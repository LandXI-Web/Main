# 이원화 구조 — LX 가 AI 서비스를 양산하고, 행정서비스로 분기해 지자체에 준다 (확정)

발주자(2026-09-20) 최종 정리:
> "Geo-AI 플랫폼이고 핵심은 **AI 서비스를 생산 양산하는 게 LX 몫**. 이걸 **행정서비스로 분기화하여 지자체에 제공하는 이원화된 구조**. 다만 이 과정에서 **AI는 연계 연결 고리가 있어야 한다**."
> "노선 구간화 등 특수 기능은 **지자체에서** 해야 한다. **LX에 모든 걸 다 구현하면 복잡도가 상당해지고 정체성이 떨어진다**."

## 1. 두 층과 그 사이의 연결 고리

```
┌─ 1층 · LX — AI 서비스 생산·양산 ────────────────────────────────┐
│  데이터 관리 → 프로젝트(라벨링·학습·검증) → 결과 품질(수정·삭제)   │
│  → 카드 발행 관리                                               │
│  정체성: 무엇을 어떻게 세고 나누는가 = 판독의 정확도             │
└───────────────────────┬─────────────────────────────────────────┘
                        │  ◆ 연결 고리 = AI 모델(카드)
                        │    모델이 오르면 행정서비스가 같이 오른다
┌───────────────────────┴─────────────────────────────────────────┐
│  2층 · 지자체/글로벌 — 행정서비스                                 │
│  로그인 → 내 서비스 카드 → 작업공간(현황·분석결과·지도·통계·보고서) │
│  + 그 기관의 행정 가공(노선 구간화·우선순위·대장 대조·민원 연계)   │
│  정체성: 받은 결과로 행정 업무를 끝내는가                        │
└─────────────────────────────────────────────────────────────────┘
```

## 2. 경계선 — 어디까지가 LX 인가

**LX 는 판독까지다.** 그 뒤 행정 가공은 기관이 한다. 기관마다 업무 규칙이 달라 표준화할 수 없고, LX 가 다 떠안으면 복잡도가 폭발하며 "AI 서비스 생산자"라는 정체성이 흐려진다.

| | LX (판독) | 기관 (행정 가공) |
|---|---|---|
| 하는 일 | 무엇을 어떻게 세고 나누는가 | 받은 결과를 업무 규칙으로 바꾸는 일 |
| 예 | 영농 주기 판정 · 비닐하우스 동수 집계 · 쓰레기 종류 분류 · 사람 탐지·계수 · 인파 밀도 격자 · 교통 혼잡도 · 변화 유형 분류 · 다시점 대조 | **노선 구간화** · 포장 등급 · 보수 우선순위 · 필지 대장 대조 · 직불금 검토 · 민원 연계 · 점검 동선 · 해안선 구간화 · 수거 계획 · 행사 구역 · 혼잡 임계 |
| 지금 | 12개 | 12개 |
| 화면 | 프로젝트 · 카드 발행 관리 | 지자체 작업공간(포털) |

데이터에서는 전용 모듈마다 `owner: 'lx' | 'local'` 로 표시한다(`cards.js` `EXT_MODULES`, `extByOwner()`).
**LX 화면에는 `lx` 모듈만, 지자체 작업공간에는 `local` 모듈이 붙는다.**

## 3. 연결 고리 — AI 가 두 층을 잇는 방식

연결 고리가 없으면 이원화는 그냥 분리다. 다섯 갈래로 잇는다.

| 고리 | 무엇이 흐르나 | 화면 |
|---|---|---|
| **발행** | LX 가 양산한 모델 → 서비스 카드가 되어 기관 홈에 놓인다 | 카드 발행 관리 → 포털 |
| **갱신** | 모델 버전이 오르면 배포본에 알림 — major/minor/patch 에 따라 할 일이 다르다 | `updateState()` · 포털 카드 배지 |
| **피드백** | 기관이 찾은 오탐·누락이 LX 로 올라가 다음 학습에 들어간다 | 지도 결과 → 오류 신고 → 프로젝트 |
| **품질 책임** | 결과의 수정·삭제 권한은 LX 가 가진다(기관은 요청) | 프로젝트 분석 탭 |
| **이식** | 검증된 카드를 다른 기관에 심는다 — 라벨·모델은 따라가고 영상은 현지 확보 | 이식 마법사 |

**정사영상**: 원본(TB)은 **LX 가 보관**하고 밖으로 내보내지 않는다. 기관에는 **영상 이미지(타일)만** 권한으로 공유한다.

## 4. 두 '카드' 를 혼동하지 않는다

| | 발행 카드 (`CARDS`) | 서비스 카드 (`portal.js serviceCards()`) |
|---|---|---|
| 누구 눈 | LX — 만드는 쪽 | 지자체 — 쓰는 쪽 |
| 뜻 | 잘 만든 AI 모델을 상품으로 내보내는 단위 | **내 지역에 깔린 서비스의 진입점** |
| 실체 | 카드 대장 한 줄 | 배포본(`DEPLOYS`) 한 줄 |
| 화면 | `admin-publish.html` | `portal.html` — 누르면 작업공간이 펼쳐진다 |

## 5. 튀는 구조를 흡수하는 장치 — 종류 선언

카드마다 **입력 · 출력 · 표현**을 선언하고, 화면은 카드 이름을 모른 채 그 선언만 보고 장치를 켠다(`needsOf()`).

| 서비스 | 입력 | 출력 | 켜지는 장치 |
|---|---|---|---|
| 영농관리 | 정사영상 | 면 | 필지 표 |
| 생활환경 | 정사영상 + 드론 영상 | 점 · 면 | 영상 플레이어 · 필지 표 |
| 도로안전 | 차량 카메라 + 정사영상 | 점 · 구간 | 구간 등급 범례 |
| **인파관리** | **드론 영상** | **점 · 밀도 · 시계열** | **영상 플레이어 · 타임라인 · 히트맵** |
| 변화탐지 | 정사영상 | 면 · 시계열 | 타임라인 · 필지 표 |
| 해양쓰레기 | 정사영상 + 드론 영상 | 점 · 구간 | 영상 플레이어 · 구간 등급 |
| 산림·탄소 | 위성 + 정사영상 | 면 · 밀도 | 히트맵 · 필지 표 |

새 종류가 나오면 `INPUT_KINDS`/`OUTPUT_KINDS`/`VIZ_KINDS` 에 한 줄 + 렌더러 하나를 더한다. **화면 코드는 고치지 않는다.**

## 6. 양산이라는 말의 뜻

한 번 만드는 것이 아니라 **계속 찍어내는 생산 라인**이다. 그래서 LX 화면은 다음을 보여야 한다.
- 지금 몇 개를 만들고 있나(프로젝트 진행 · 학습 대기열)
- 무엇이 발행 대기인가(카드 발행 큐)
- 만든 것이 어디에 깔렸나(배포본 · 지역 수)
- 다음에 무엇을 만들 것인가(공통 승격 후보 · 준비 중 카드)

지자체 화면은 반대로 **내 업무가 끝나는가**만 본다. 현황 → 결과 → 지도 → 통계 → 보고서.
