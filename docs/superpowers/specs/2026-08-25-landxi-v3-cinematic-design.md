## 1. 목적과 판정 기준

### 1.1 왜 v3인가

v2 스펙과 그 실행 계획(`plans/2026-08-25-landxi-plan1-foundation-home-dashboard.md`)은 기능 목록과 토큰 체계로는 옳았으나, 클라이언트는 결과물을 다음 문장으로 반려했다.

> **"딱딱한 클로드 구조, 시네마틱/인터랙티브 없음, 인간성 없음, 목업 수준 불가"**

자체 비평(`self-critique.md` §0)은 이 문장을 은유가 아니라 관찰로 읽었다. 리포 안에 27MB의 실촬영 정사영상 타일 9세트와 5,000건의 실제 AI 검출 폴리곤이 있는데도, 홈·로그인·대시보드 어디에서도 **사람이 사는 장소의 사진이 한 장도 화면에 나오지 않았다.** 회색 벡터 지구본, 하드코딩된 별 10개, 지구를 관통하는 점선 타원 3개, 그리고 "이 자리에 들어갑니다"라는 스텁 4개가 그 자리를 채웠다.

v3는 기능을 더하거나 빼지 않는다. v2 §6의 "유지되는 기능" 인벤토리는 **한 줄도 삭제되지 않고 한 줄도 추가되지 않는다.** 바꾸는 것은 그 기능들이 놓이는 **무대와 문법**이다. 구체적으로 셋을 바꾼다.

1. **페이지를 없앤다.** 화면 전환이 아니라 카메라 이동으로 이동한다(§2).
2. **베이스맵을 영상으로 바꾼다.** 벡터 스타일은 라벨·경계 오버레이로 강등한다(§3).
3. **모든 패널이 서로를 안다.** 브러싱-링킹·감쇠 필터·실시간 임계값이 기본값이 된다(§5).

### 1.2 클라이언트의 서사 — 이 문서의 최상위 요구사항

클라이언트 발언 원문. 이 문단이 §2 전체의 근거다.

> **"위성에서 바라보는 지구 궤도가 돌다가 성층운을 돌파하면서 한국 지형이 나온다. 그럼 우리 Land-XI 서비스 지역이 지도상 표출되고 그걸 클릭하면 실제 분석 결과가 지도 레이어와 겹쳐서 입체적인 Geo-AI 서비스임을 강조하는 게 핵심."**

여기에는 네 개의 요구가 들어 있다. (a) 궤도 → 성층운 돌파 → 한국 지형이라는 **연속 하강**, (b) 서비스 지역의 **지도상 표출**, (c) 클릭 시 **실제 분석 결과가 지도 레이어와 겹침**, (d) 결과적으로 **입체적**이라는 인상. v3의 홈은 이 넷을 순서대로 만족시키는 것 외에 다른 목적을 갖지 않는다. 마케팅 카피 섹션이 아니라 **작동하는 시스템의 창**이다.

### 1.3 합격 판정 — 4중 게이트

각 화면은 아래 게이트를 **모두** 통과해야 한다. 하나라도 미달이면 그 화면은 미완성이며 다음 단계로 진행하지 않는다.

**게이트 A — Palantir 18항목 ≥ 28/36.**
`benchmark-palantir.md` §4의 18항목을 화면당 0(없음)/1(부분)/2(완전)로 채점한다. 만점 36점, **28점 미만은 반려.** 항목: ①객체가 1급 시민 ②모든 숫자가 클릭 가능 ③뷰 상호연동(cross-filter) ④필터가 삭제가 아니라 감쇠 ⑤관계 탐색(Search Around) ⑥시간이 1급 축 ⑦시간 기반 시각 감쇠 ⑧지도가 입력 장치 ⑨레이어 통제 가능 ⑩심볼로지가 의미를 가짐 ⑪AI가 사고 과정을 보여줌 ⑫AI 신뢰도의 정직한 처리 ⑬사람의 흔적 ⑭아이콘 3단 상태 ⑮충분한 밀도 ⑯상태 전환 100ms ⑰승격 경로 ⑱화면이 이야기를 함.
빠른 자가진단: 정지 스크린샷을 놓고 **"무엇을 클릭할 수 있고 클릭하면 무엇이 변하는가"를 5개 이상 말할 수 없으면 그 화면은 여전히 뻣뻣하다.**

**게이트 B — Roboflow 18항목 중 ≥ 12개 충족.**
`benchmark-roboflow.md` §4. **12개 미만이면 "정적"이라는 지적을 다시 받는다.** 분석·모델·워크플로우 계열 화면(프로젝트 캔버스, 데이터 관리, 분석 실행, XI맵, 모델 카드)에 전면 적용하고, 게시판 계열에는 해당 항목(①결과 썸네일 ⑭클래스 고정색 ⑰모노 수치 ⑱공유 링크 실행)만 적용한다.

**게이트 C — 안티패턴 27개 제로.**
`awwwards-interaction-grammar.md` §2의 20개 + `cinematic-geo-references.md` §4의 7개. **단 하나도 발견되지 않아야 한다.** 1차 구현에서 실제로 위반된 것들을 명시 금지 목록으로 둔다.

| 금지 | v2에서 위반한 위치 | v3의 대응 |

### 1.4 범위

**대상 (v2와 동일, 축소 없음).** 홈, 로그인, 대시보드, 프로젝트(목록·워크플로우 캔버스·하위 페이지 전부), 데이터 관리, 분석 실행(+과제별 결과), XI 맵(+`map-*` 파생), 카드 발행 관리, 서비스 지원(공지·FAQ·문의·활용사례·매뉴얼), 서비스 관리(공지·문의·FAQ·사용자·지도 속성), 마이페이지.

**비대상.** 남원시(`namwon3`)·하천(`river`) 변형, 백엔드 연동, 실제 인증, 신규 기능 추가. **기존 기능 제거도 없다.**

**비전 문안 (v2 §1에서 그대로 승계, 화면에 그대로 사용).**
- 모토: **"LX 전 직원이 Geo-AI 전문가입니다"**
- 축: 노코드 · 워크플로우 기반 AI 모델 개발 · 전국단위 AI 실태조사
- 비전: **범부처 AI 기반 국토정보 통합조사** — 부처마다 개별·단일 목적으로, 대부분 인력 현장조사로 수행하던 실태조사들을 드론·항공·위성 인프라와 AI로 부분 대체하고, 통합·일괄 조사하여 효율적으로 관리하는 것이 사업의 코어다.

단, `self-critique` #16("카피가 명찰이다")을 반영해 **문안은 그대로 두되 항상 증거 숫자를 옆에 붙인다.** 모토 아래 한 줄이 "전남 해안 38,057건을 사람이 가지 않고 찾았습니다 · 2025-06 · 신뢰도 0.51–1.00"가 된다. 주장 → 증거 → 초대의 순서이며, 이것이 "AI 기반 배지"류 상투구(안티패턴 #11)를 대체한다.

## 2. 서사 골격 — 「글로벌 캔버스 앱 셸」

### 2.1 핵심 결정: 지도는 한 번만 만들고 절대 파괴하지 않는다

수상작과 1차 구현을 가르는 단 하나의 구조적 차이는 효과의 양이 아니라 **연속성**이다. San Rita Project는 3D 캔버스를 라우터 바깥에 마운트해 페이지 전환 대신 카메라를 이동시킨다(`awwwards` §0-1). v3는 이 구조를 그대로 채택한다.

```
                    ┌───────────────────────────────────────────┐
                    │           #globe-canvas  (영구)            │
                    │   MapLibre 인스턴스 1개 · 앱 수명 = 지도 수명 │
                    └───────────────────────────────────────────┘
                                        ▲
                    ┌───────────────────┴───────────────────────┐
                    │        Director  (씬 = 카메라 상태 기계)    │
                    │  {id, camera, layers[], hud, theme, mode}  │
                    └───────────────────┬───────────────────────┘
     ┌──────────────┬──────────────┬────┴─────────┬──────────────┬──────────────┐
   홈 챕터1–4      로그인        대시보드        XI맵        워크플로우      게시판
 (스크롤 p 구동)  (카메라 정박)  (물러선 카메라) (작업 카메라)  (다크 ops)   (배경 문맥)
```

- **페이지 = 카메라 상태.** 각 화면은 `Director`가 아는 씬 프리셋 하나다: `{center, zoom, pitch, bearing, layers[], hudDensity, theme}`.
- **내비게이션 = 카메라 이동.** 레일에서 XI맵을 누르면 URL이 바뀌되(딥링크 유지) 지도는 파괴되지 않고 카메라만 이동한다.
- **역방향도 카메라 이동.** "개요로" 클릭 시 완전 역경로. 단 이징을 바꾼다(`awwwards` M08: 갈 때 `cinematicSilk`, 올 때 `expo.inOut`) — 같은 시간·같은 곡선의 역재생은 되감기처럼 보인다.

**금지.** 지도 인스턴스 재생성 라우팅, 챕터 전환 시 `setStyle()` 전체 교체, 문서형 화면에서 지도를 `<img>` 스냅샷으로 대체하는 것.

### 2.2 두 개의 운전대 — 스크롤 구동 p, 클릭 구동 자유 경로

**(A) 대국민 서사 — 정규화 진행값 `p ∈ [0,1]` 하나.**
홈(로그인 이전)은 Lenis + GSAP ScrollTrigger가 만드는 **단일 정규화 값 p**가 카메라·조명·레이어 투명도·타이포·HUD를 전부 구동한다(Trionn 방식). 시스템 간 통신이 필요 없다는 것이 이 설계의 이점이다.

```
p          0        0.25            0.50            0.80          1.00
           │─ 챕터1 ─│──── 챕터2 ────│──── 챕터3 ────│── 챕터4 ──│
             궤도       전국 점등        남원 강하        증명
zoom      1.4────────4.5─────────────6.8──8.5──11──13.5──16──18.2──18.2
pitch     0──────────30──────────────30───45───68──62───40───0─────0
bearing   +25 ────── -10 드리프트 ──── -15 ── -35 ── -20 ── 0 ─────0
투영      globe ──────────[보간 전환 z4~7]──────── mercator ────────
지형      OFF ─────────────OFF───────── ON(3~4초) ──OFF ───────────OFF
베이스    EOX ────[크로스페이드]── V-World ────[크로스페이드]── 우리 정사영상
조명      새벽 5600K ─────────────────────────────────────── 정오
```

- 매 프레임 `map.jumpTo(lerp(keyframes, p))`. **스크럽에 `flyTo`/`easeTo`를 쓰지 않는다** — 스크롤을 멈추면 카메라도 즉시 멈춰야 하기 때문(`awwwards` M03 난이도 노트).
- 구간마다 **다른 이징**을 갖는다(안티패턴 #5 대응). 챕터1→2 `power2.out`, 능선 진입 `expo.inOut`, 착지 `power4.out`.
- bearing은 전 구간 미세 드리프트. 완전히 고정된 bearing은 정지 화면으로 읽힌다.
- 스크롤 공간 600vh. 상단에 **"건너뛰고 지도 열기"를 상시 노출**해 스크롤 하이재킹 피로를 막는다.
- 스크롤 방향 전환 시 자연스럽게 역재생되도록 **상태 기반으로만** 구현한다(트윈 누적 금지).

**(B) 도구 사용 — 클릭 구동 자유 경로.**
로그인 이후에는 p가 사라지고 클릭이 카메라를 움직인다. `easeTo`/`flyTo`를 쓰되 **시간 축을 UI와 엄격히 분리**한다.

| 축 | 대상 | 시간 | 이징 |
|---|---|---|---|
| **UI 축** | 버튼·칩·토글·패널 상태·호버·체크 | **100ms** (최대 150ms) | `cubic-bezier(0.4, 1, 0.75, 0.9)` — Blueprint 원본값 |
| **카메라 축** | 씬 이동·객체 진입·승격 | **1,200–2,400ms** | `cinematicSilk(0.45,0.05,0.55,0.95)` / `power4.out` |
| **시네마 축** | 홈 챕터·스토리↔툴 핸드오프 | **1,600–3,500ms** | `expo.inOut` |

Palantir가 100ms를 쓰는 이유는 부드러움이 아니라 **즉답성**이다. 400ms 페이드는 고급스러움이 아니라 렉으로 읽힌다. 반대로 카메라를 100ms로 움직이면 순간이동이 되어 공간 감각이 무너진다. **이 분리를 어기는 것이 1차 구현이 "딱딱하다"고 읽힌 원인 중 하나다.**

### 2.3 서비스 표출과 결과 겹침의 공통 문법 (클라이언트 요구 b·c·d)

**표출 문법 (b).** `services.js`의 13개 서비스를 `lastRun` 순으로 **스태거 점등**한다. deck.gl `ScatterplotLayer` 반경 애니메이션 + 링 1회 확산 후 정지. 실데이터 4종만 링이 한 번 더 뛴다. 라벨은 **최근 4개만** 점 옆에 mono로(13개 동시 라벨은 `self-critique` §1.3에서 "표처럼 읽힌다"고 진단됨). 나머지 9개는 호버 시에만 라벨이 뜬다.

**겹침 문법 (c·d).** 서비스 포인트 클릭 시 일어나는 일은 **앱 전체에서 항상 동일한 4단계**다. 이것이 공통 어휘가 된다 — 홈에서 배운 동작이 XI맵·분석 실행·대시보드에서 그대로 통한다.

```
① 카메라 이동   해당 AOI로 2.2s flyTo. pitch는 데이터 성격에 따라
                (면 데이터 0~20° / 3D 맥락 필요 45~62°)
② 베이스 교체   V-World 위성 → 우리 정사영상 raster-opacity 크로스페이드 0.6s
③ 결과 적층     탐지 폴리곤이 0.04s 간격 스태거 pop-in
                (scale 0.94→1 + alpha, easeOutBack 소량)
                클래스색 외곽 2px / 채움 22% — Roboflow supervision 문법
④ 패널 착지     우측 유리 패널 1장 슬라이드 인 1.0s power4.out.
                신뢰도 슬라이더 · 클래스 토글 · 검출 상세가 실려 있다
```

**"입체적"의 정의 (d).** 클라이언트가 말한 입체감을 세 층위로 구현한다. ⓐ **공간적 입체** — pitch와 지형이 만드는 실제 3D. ⓑ **정보적 입체** — 같은 좌표 위에 영상·경계·검출·시간이 겹쳐 쌓이는 것. ⓒ **시간적 입체** — 4시점 정사영상이 같은 자리에서 갈아 끼워지는 것. ⓐ만 있으면 관광 앱이고, ⓑⓒ만 있으면 차트다. **셋이 다 있어야 "Geo-AI 서비스"로 읽힌다.**

### 2.4 스토리 ↔ 툴 핸드오프 (M08) — 가장 중요한 전환

`awwwards` §5 결론: **M03(다이브)과 M08(핸드오프)이 "Web3GL feel"의 90%를 결정한다.** M08은 로그인 성공 순간의 처리이며, 여기서 지도가 파괴되면 v3 전체가 무너진다.

```
t=0.00  로그인 성공. 화면이 전환되지 않는다. 커튼이 좌측으로 회수 0.9s expo.inOut
t=0.20  같은 지도, 같은 카메라. 목표점만 바뀐다:
        pitch 46→18, zoom 13.5→9.2, 1.6s cinematicSilk
        → "다른 페이지"가 아니라 "카메라가 물러선 것"
t=0.35  시네마 HUD(큰 타이포·카피)가 밀도 높은 툴 HUD로 교체.
        좌측 레일 아이콘 8개 stagger 0.04, y:-8→0, 0.35s power3.out
t=0.90  우측 패널(이 화면의 유일한 유리 1장)이 슬라이드 인 1.0s power4.out.
        backdrop-filter blur 고정 10px — 블러 애니메이션 금지
t=1.60  카메라 정착. 그레인 opacity .05 → .03 (툴 모드는 조금 더 선명하게)
```

목적지별 차이는 카메라 목표와 HUD 밀도뿐이다.

| 목적지 | 카메라 | HUD 밀도 | 지도의 역할 |
|---|---|---|---|
| 대시보드 | z6.2 전국, pitch 0, 라벨 최소 | 높음(패널 4~5) | 코로플레스 + 큐 호버 연동 하이라이트 |
| XI맵 | 마지막 본 AOI 유지, pitch 45 | 최고(패널 6~7) | 작업 대상 그 자체 |
| 프로젝트 캔버스 | 카메라 정지, 캔버스가 지도를 88% 덮음 | 중간 | 배경 문맥(프로젝트 범위만 발광) |
| 게시판·마이페이지 | 직전 카메라 유지, blur 1.2px + 라벨 OFF | 낮음(문서 1열) | 조용한 배경. 그러나 **같은 지도** |

### 2.5 정적 사이트에서 글로벌 캔버스를 구현하는 방법 — **프로토 판정 후 확정**

빌드 도구가 없고 페이지가 별도 HTML 파일인 상태에서 지도 인스턴스를 살려두는 방법은 둘이다.

**옵션 1 — 앱 셸 SPA (권장 후보).** `landxi/index.html` 하나를 셸로 삼고 각 화면은 `pages/*.html` 조각을 `fetch` → 주입한다. 지도는 셸에 있으므로 절대 파괴되지 않는다. URL은 History API로 유지.
- 장점: M08이 문자 그대로 구현된다. 카메라 연속성 100%.
- 단점: 기존 딥링크(`?tab=`, `?pid=`, `?embed=1`) 재배선 필요. `?embed=1` iframe 보고서는 셸을 우회하는 경량 진입점이 따로 필요.

**옵션 2 — 페이지 유지 + View Transitions cross-document.** 각 HTML을 그대로 두고 `@view-transition{navigation:auto}` + `view-transition-name`으로 지도 캔버스를 모프시킨다. 지도는 실제로 재생성되지만 **시각적 연속성**은 유지된다.
- 장점: 파일 구조·딥링크 그대로. 리스크 최소.
- 단점: 타일 재로드 깜빡임 가능. 카메라 상태를 `sessionStorage`로 이월해야 한다. Chrome/Edge 전용(공공기관 표준 범위 내이므로 허용 가능).

**판정.** 프로토에서 옵션 2 방식 이월 전환을 1회 시험해 **타일 깜빡임이 200ms 이내로 억제되면 옵션 2**, 아니면 옵션 1. **P1 착수 전 확정 — 프로토 판정 후 확정.**

### 2.6 딥링크

v2에서 전부 승계: `?tab=`, `?domain=`, `?status=`, `?pid=`, `?job=`, `?region=`, `?embed=1`. `?embed=1`은 레일·컨텍스트 바·푸터를 숨기고 **시네마 연출도 전부 끈다**(보고서 iframe용 정지 모드).
추가 3개: `?scene=`(홈 챕터 직접 진입 — 프로토의 `__dive.seek(p)`를 제품화), `?conf=`(신뢰도 임계 공유), `?epoch=`(시점 공유). 이 셋이 Roboflow 체크 ⑱ "공유 링크가 그 자리에서 실행된다"를 만족시키며, 발주처 시연에서 특정 장면을 바로 여는 수단이 된다.

### 3.2 영상 베이스맵 합성 — 3단 크로스페이드

**원칙: 베이스맵은 위성/항공 영상이다. 벡터 스타일은 라벨·도로·경계 오버레이로만 쓴다.**

```
z0 ───────── z7 ─── z9 ────────────────── z12 ─ z13.5 ───────────── z19
 ├ EOX Sentinel-2 cloudless (전지구, 구름 없음, 글로브 연출용)
 │            ╲─ 페이드아웃 (7→9)
 │      ┌ V-World Satellite (한국 z5–19) ────────────────────────────┤
 │      ╱─ 페이드인 (6→8)              ╲─ AOI 밖에서는 계속 유지
 │                              ┌ 우리 정사영상 (AOI 내부, z12–19) ──┤
 │                              ╱─ 페이드인 (12→13.5)
 ├ OpenFreeMap 벡터 라벨/경계 (name:ko, halo 필수, KR 필터) ─────────┤
```

```js
  vhyb: { type:'raster', tiles:[SRC.vworldHybrid], tileSize:256, minzoom:5, maxzoom:19 },
  ofm:  { type:'vector', url:'https://tiles.openfreemap.org/planet' },
  dem:  { type:'raster-dem', tiles:['https://tiles.mapterhorn.com/{z}/{x}/{y}.webp'],

  // + IMAGERY 9세트를 각각 raster 소스로 등록 (bounds·minzoom·maxzoom은 imagery.js에서)
```

paint 규칙:
- `eox` `raster-opacity: ['interpolate',['linear'],['zoom'], 7,1, 9,0]`
- `vsat` `['interpolate',['linear'],['zoom'], 6,0, 8,1]` + `raster-saturation:0.08` + `raster-contrast:0.05` — 이 미세한 등급 조정이 "시네마틱 색보정"을 만든다
- 우리 정사영상 `['interpolate',['linear'],['zoom'], 12,0, 13.5,1]`
- 전 raster에 `raster-fade-duration: 250~300`
- 경계선(`ofm` boundary): `line-blur:0.6` 글로우. 색은 시안이 아니라 **`--lx` 계열**(브랜드 일관성)
- 라벨(`ofm` place): `['coalesce',['get','name:ko'],['get','name']]` + **`['==',['get','iso_a2'],'KR']` 필터 필수.** 1차 구현에서 화면 우측 1/3이 일본 지명으로 도배된 문제(`self-critique` §1.3)의 직접 처방. 국외는 별도 저대비 레이어로 분리하고 챕터별 라벨 밀도를 3단계로 조절
- **영상 위 라벨은 halo 필수**(`text-halo-width:1.4`). halo 색은 영상 밝기에 따라 어두운 쪽. `maplibre-cartography` 스킬 준수
- **한반도 실루엣**: 미사용 상태인 `korea-outline.geojson`을 로드해 2px 잉크 라인 + 바깥 8px 소프트 글로우. 국토가 주인공의 실루엣을 갖는다(`self-critique` #6)

### 3.3 V-World 키 취급

`.env.local`의 `VWORLD_KEY`를 쓴다. **소스에 하드코딩 금지.**

```
1순위  키 발급형 WMTS   https://api.vworld.kr/req/wmts/1.0.0/{KEY}/Satellite/{z}/{y}/{x}.jpeg
                        (도메인 인증 필요. localhost 개발 시 별도 등록,
                         비 HTTPS·비 웹뷰어 환경은 &domain= 파라미터 추가)
2순위  keyless xdworld  https://xdworld.vworld.kr/2d/Satellite/service/{z}/{x}/{y}.jpeg
                        (CORS `*` 실측, z5–19, 키 불필요 — 데모·GitHub Pages 기본값)
```

- 키 주입은 `tools/serve.mjs`가 생성하는 `env.js` → `window.VWORLD_KEY`. 파일이 없으면 자동 2순위 폴백.
- **URL 상수는 `assets/js/map/sources.js` 한 곳에만 존재한다.** 정식 서비스 전환 시 이 파일 한 줄만 바꾼다.
- 표기 의무: `© V-World / 국토교통부`, `Sentinel-2 cloudless © EOX`, `© Mapterhorn`, `OpenFreeMap © OpenMapTiles / OpenStreetMap`을 `attributionControl`에 전부 노출. 이것은 라이선스 준수인 동시에 **데이터가 진짜라는 증거**이기도 하다.

### 3.4 지형 정책 — 「연출 전용, 상시 금지」

**v3에서 가장 엄격한 성능 규칙이다.** 실측: 소프트웨어 렌더러 기준 지형 OFF 66fps → ON **2.4fps(27배)**. GPU가 있어도 지형은 다른 모든 요소를 합친 것보다 비싸다(558.7 → 92.3, 6배).

| 상황 | 지형 | 근거 |
|---|---|---|
| 홈 챕터 3 능선 진입 (p 0.55~0.68, **3~4초**) | **ON** `exaggeration:1.4` | 유일한 허용 구간. 지리산 능선이 솟는 그 순간만 |
| 착지 후 1.5초 | **자동 OFF** `setTerrain(null)` | 정지 상태에서 지형은 시각 기여가 거의 없으면서 프레임만 먹는다 |
| 그 외 전부 (대시보드·XI맵·분석·캔버스·게시판) | **OFF** | 예외 없음 |
| `lite`·`still` 티어 | **항상 OFF** | pitch만 준다 |

- `encoding:'terrarium'` 명시 필수. Mapbox RGB와 혼동하면 지형이 폭발한다.
- Mapterhorn은 **maxzoom 12(512px)**, z13+ 404. 고줌 지형이 필요하면 AWS terrarium(maxzoom 14, 256px)으로 스위치. 남원 AOI는 z13.5부터 정사영상이 덮으므로 실질 문제 없음.
- **MapLibre v5에서 globe + terrain 동시 사용 시 fog가 비활성화된다.** 글로브 씬(챕터 1~2)과 지형 씬(챕터 3)을 분리 설계한 것이 이 제약의 결과다.
- ON/OFF는 시각 튐 없이: 켜기 직전 카메라 pitch가 이미 높은 상태여야 하고, 끄기는 착지 후 opacity 크로스페이드와 동시에.
- `queryTerrainElevation`으로 읽은 **실제 표고(m)**를 HUD에 카운트업으로 표시한다(가짜 HUD 금지 원칙의 실천).

### 3.5 성능 티어 — full / lite / still

```js
const gl = document.createElement('canvas').getContext('webgl2');
const dbg = gl && gl.getExtension('WEBGL_debug_renderer_info');
const renderer = dbg ? gl.getParameter(dbg.UNMASKED_RENDERER_WEBGL) : '';
const soft   = /SwiftShader|Software|llvmpipe|Microsoft Basic/i.test(renderer);
const weak   = /Intel.*(HD|UHD) Graphics (5|6)\d\d/i.test(renderer);
const reduce = matchMedia('(prefers-reduced-motion: reduce)').matches;
const lowMem = (navigator.deviceMemory || 8) <= 4;
const TIER = (!gl || soft) ? 'still' : (reduce || weak || lowMem) ? 'lite' : 'full';
```

| 티어 | 글로브 | 지형 | deck.gl | three.js | 그레인·파티클 | 카메라 |
|---|---|---|---|---|---|---|
| `full` | ✅ 대기광 | 연출 3~4초만 | 인터리브드 전부 | ✅ 궤도 + glTF | ✅ | 스크럽 + flyTo |
| `lite` | ✅ 대기광 유지 | **OFF** | 오버레이드, Arc/Trips 1/3 | 궤도만, 블룸 OFF | 그레인만 | `duration:0` 즉시 |
| `still` | 절차 캔버스 폴백(`map/fallback.js` 유지) | — | — | — | — | 각 챕터 최종 프레임 정지 |

**적응형 강등.** 최근 60프레임 평균이 예산 초과 시 자동으로 한 단계 낮춘다(San Rita/ZERO/Shopify 공통). 측정은 median이 아니라 **p95 프레임타임**, 스파이크 목표 < 50ms. 현재 티어를 개발 모드에서 우하단 mono로 표시한다.

**`still` 티어는 기능 손실이 아니다.** 오프라인·아티팩트·타일 차단 환경에서도 화면이 살아 있어야 하며, 기존 `map/shell.js`의 2엔진 추상화(MapLibre 실패 → 절차 캔버스, 동일 API `flyTo/project/addRaster/addGeoJSON/on`)는 **재작성하지 않고 그대로 유지한다**(`self-critique` §2-2).

### 3.7 감소 모션 (`prefers-reduced-motion`)

- 카메라 자동 비행 → `map.jumpTo()` 즉시 도착
- **`AnimationOptions.essential: true`를 쓰지 않는다.** 이 플래그는 reduced-motion을 무시시키므로 접근성 위반이다
- GSAP: ScrollTrigger `scrub:false`. CSS: `@media (prefers-reduced-motion: reduce){ *,*::before,*::after{ animation-duration:.01ms!important; transition-duration:.01ms!important } }`
- 앰비언트(자전·펄스·타임라인 자동재생) 정지. **단 정보는 하나도 사라지지 않는다** — 애니메이션의 최종 상태를 즉시 보여준다
- 예외: 앰비언트 1개에 한해 정지 대신 **감속**을 허용한다(Trionn 실제 구현: 0.0042 → 0.0015). 완전 정지가 오히려 "고장난 화면"으로 읽히는 경우가 있다

### 3.8 빌드·배포 (v2 승계)

빌드 도구 없는 정적 사이트. HTML + CSS 커스텀 프로퍼티 + ES Module. GitHub Pages/로컬 실행. 상태는 `localStorage`(로그인 플래그·사용자 심볼·최근 검색). CSP 사용 시 `worker-src 'self' blob:` 필요(MapLibre 워커). 브라우저 Chrome/Edge 최신, 1280px 이상 데스크톱 우선, 1024px 이하에서 패널이 시트로 전환.

## 4. 디자인 시스템 v3

### 4.1 기본 방침 — 토큰은 유지하고 값과 규칙을 얹는다

`landxi/assets/css/tokens.css`의 배선은 **재작성하지 않는다.** 29줄이 색·서체·형태·모션·쉘 치수를 단일 출처로 잡고 `tokens.js`의 `cssVar()`를 통해 지도 스타일과 인라인 SVG stop-color까지 같은 값을 읽는다. 팔레트를 바꾸면 지도까지 따라오는 이 구조는 유지 가치가 크다(`self-critique` §2-4). v3는 여기에 **다크 ops 세트·모션 사전·검출 팔레트·아이콘 상태 규칙**을 추가한다.

유지되는 라이트 토큰: `--mist:#E9EEF1` `--surface:#FFFFFF` `--glass:rgba(255,255,255,.82)` `--ink:#111C2D` `--lx:#006DF7`(LX CI 블루) `--lx-deep:#0052B9` `--ai:#0FA9A0`, 상태 6색 `--s-found:#F2622A` `--s-doing:#E3A008` `--s-done:#1E9E6A` `--s-hold:#6B7A8C` `--s-error:#D93025` `--s-info:var(--lx)`.

**Palantir에서 가져오는 것은 색이 아니라 구조다.** 그레이 램프 11단, 인텐트 4색과 범주형 10색의 분리, 아이콘 3단 상태, 4px 그리드, 30px 컨트롤, 100ms 전환. 헥스값을 그대로 베끼면 LX 브랜드가 사라진다.

### 4.2 슬레이트 그레이 램프 (신규)

Blueprint 그레이는 완전 중성이 아니라 **청록 쪽으로 기운 슬레이트**다(`#5f6b7c`는 R<G<B). 이 미세한 한기(寒氣)가 "계기판" 느낌의 8할을 만든다. `--ink:#111C2D`는 이미 그보다 더 파랗다 — 방향은 맞다. 이제 중간 단계를 채운다.

```css
--sl-1:#1C2127; --sl-2:#252A31; --sl-3:#2F343C; --sl-4:#383E47; --sl-5:#404854;
--sl-6:#5F6B7C; --sl-7:#738091; --sl-8:#8F99A8; --sl-9:#ABB3BF; --sl-10:#C5CBD3;
--sl-11:#D3D8DE; --sl-12:#DCE0E5; --sl-13:#E5E8EB; --sl-14:#EDEFF2; --sl-15:#F6F7F9;
```

용도: 표 구분선·비활성 텍스트·차트 축·아이콘 기본색. 상태색·브랜드색과 절대 섞지 않는다.

### 4.3 다크 "ops" 세트 (신규 — 챕터 1과 판독 모드 전용)

**다크는 멋이 아니라 용도다.** Palantir가 다크인 이유는 상황실 조도와 포지셔닝 때문이며, 그들조차 Map 앱에 라이트/다크 사용자 설정을 둔다. Land-XI는 **밝은 정사영상을 판독하는 플랫폼**이므로 라이트가 기본이다. 다크를 쓰는 곳은 정확히 셋뿐이다.

1. 홈 챕터 1(궤도 — 우주는 실제로 어둡다)
2. XI맵 "야간/판독 모드"(영상 대비 극대화, 사용자가 명시적으로 켬)
3. 프로젝트 캔버스 실행 모니터링(실행 중에만)

```css
[data-ops="dark"]{
  --bg:var(--sl-1);            /* app 배경 */
  --bg-2:var(--sl-1);          /* 보조 배경 = 배경과 동일 (핵심) */
  --bg-elevated:var(--sl-3);
  --ink:#F6F7F9; --ink-2:rgba(246,247,249,.68); --ink-3:rgba(246,247,249,.46);
  --line:rgba(255,255,255,.20);   /* 면 분리는 배경색이 아니라 1px 흰 반투명 보더 */
  --glass:rgba(16,26,44,.62); --glass-border:rgba(230,236,245,.14);
  --sh-card:0 1px 2px rgba(0,0,0,.20); --sh-float:0 10px 30px rgba(0,0,0,.40);
}
```

**결정적 규칙 2개.**
- **다크에서 배경과 보조 배경은 같은 색이다.** 면 분리는 배경색 차이가 아니라 **1px 흰색 반투명 보더**로 한다. 카드마다 다른 회색을 쓰면 즉시 아마추어처럼 보인다.
- **다크는 색 반전이 아니다.** 지도 스타일 자체를 라이트/다크 2종으로 준비하고, 유리 패널 대비비를 각각 재계산한다(안티패턴 #19).

전환은 챕터 2 진입 시 '일출' 크로스페이드로 일어난다. **단 1차 구현처럼 검은 판 하나가 투명해지는 것이 아니라**(`self-critique` §1.2), 색온도 이행(5600K → 정오) + 터미네이터 통과 + 노출 적응이 함께 일어난다.

### 4.4 모션 토큰 (신규 — 이징 사전)

안티패턴 #5("모든 곳에 동일 이징 = 위계 없음 = 연출 없음")의 직접 처방. 무게별로 이징과 시간을 분리한다.

```css
/* 시간 */
--t-ui:100ms;        /* Palantir 즉답성 — 버튼·칩·토글·호버·체크 */
--t-ui-max:150ms;    /* UI 축 상한. 이걸 넘으면 렉으로 읽힌다 */
--t-panel:340ms;     /* 패널·드로어·카드 */
--t-cam:1200ms;      /* 카메라 기본 */
--t-cam-long:2400ms; /* 원거리 카메라·승격 */
--t-cinema:1600ms;   /* 챕터 전환·핸드오프 */

/* 이징 — awwwards 쿡북에서 채집 */
--e-ui:cubic-bezier(0.4, 1, 0.75, 0.9);        /* Blueprint 원본 */
--e-bounce:cubic-bezier(0.54, 1.12, 0.38, 1.11);
--e-silk:cubic-bezier(0.45, 0.05, 0.55, 0.95);  /* 카메라용 미묘한 가감속 */
--e-smooth:cubic-bezier(0.25, 0.10, 0.25, 1.00);/* 텍스트 상승 */
--e-flow:cubic-bezier(0.33, 0.00, 0.20, 1.00);  /* 반응적 UI */
--e-expo:cubic-bezier(0.16, 1.00, 0.30, 1.00);  /* power4.out 근사 */
--e-power4:cubic-bezier(0.22, 1.00, 0.36, 1.00);
--e-inout:cubic-bezier(0.65, 0.00, 0.35, 1.00); /* power3.inOut 근사 */
```

**무게 규칙.** 가벼움(툴팁·모달) `power1~2.out` 0.2–0.3s / 중간(카드·섹션) `power2~3.out` 0.4–0.6s / 무거움(히어로·페이지) `power3~4.out` 0.9–1.4s. `power3.out`의 스위트 스팟은 **0.4초 부근** — 0.1초는 이징이 안 보이고 2초 이상은 늘어진다.

**스태거 사전.**

```
문자 단위 리빌   duration 0.8  stagger {each:0.06~0.08, from:"random"}  power2.out
단어 스태거      stagger 0.03
라인 스태거      stagger 0.1
아이콘 열        stagger 0.04, y:-8→0, 0.35s power3.out
탐지 pop-in      stagger 0.04, scale 0.94→1, easeOutBack 소량
지도 포인트 점등  거리순 stagger 0.06
공유요소 Flip    1.3s power3.inOut (닫힘은 1.1s — 늘 조금 빠르게)
카드 밀침        out 0.34s → back 0.52s 스프링백
호버 커서 추종   0.2s power2.out, lerp 0.12 (스냅 금지)
스크램블 티커    40ms 공유 인터벌
```

**불규칙성의 의도적 주입.** `from:"random"` 스태거, 경로별 위상 오프셋 `random(0, 2π)`, 속도 `random(0.7, 1.3)`, 펄스 간격 `random(1.4s, 3.2s)`. **균일함 = AI가 만든 티**라는 것이 이미 업계 담론이다. 완벽하게 동기화된 모션은 반드시 어긋뜨린다.

### 4.5 아이콘 — muted → hover → selected 3단 상태

**"뻣뻣함을 없애는 가장 저렴하고 효과 큰 한 수"**(Palantir P12). 1차 구현의 흔한 원인이 "모든 아이콘이 처음부터 진하게 켜져 있음"이다.

```css
.icon           { color: var(--ink-3); transition: color var(--t-ui) var(--e-ui); }
.icon:hover     { color: var(--ink); }
.icon[aria-pressed="true"], .icon.is-selected { color: var(--lx); }
```

- 아이콘 기본색 = **뮤티드 텍스트색**. 툴바에 아이콘 20개가 있어도 조용하다가 손끝을 따라 깨어난다.
- 크기는 **16px·20px 두 벌의 별도 SVG**로 관리한다(벡터 스케일이 아니라 옵티컬 사이즈). 스프라이트 `assets/icons.svg`에 `-16`/`-20` 접미로 둔다.
- **이모지 아이콘 금지.** 도메인 고유 픽토그램(필지·지적선·드론 궤적·해양쓰레기·정사영상 타일)을 직접 그리고, 스트로크 두께는 본문 텍스트와 같게 맞춘다(안티패턴 #10).

### 4.6 검출 팔레트 (신규 — 클래스 고정색)

Roboflow가 `ColorLookup.CLASS`로 클래스 고정색을 쓰듯, **클래스 → 색 고정 매핑을 토큰화**한다. 브랜드 블루를 검출색으로 쓰면 지도 UI와 충돌하므로 **별도 네임스페이스**로 둔다.

```css
--det-1:#F2622A; /* 비닐하우스 */   --det-6:#00C4FF; /* 선박(OBB) */
--det-2:#0FA9A0; /* 해양쓰레기 */   --det-7:#FF97CA; /* 탱크(OBB) */
--det-3:#863AFF; /* 불법건축물 */   --det-8:#94CF1A; /* 도로(seg) */
--det-4:#FFB633; /* 차량 */         --det-9:#CD3AFF; /* 토지형질(seg) */
--det-5:#40DE8A; /* 건물 */         --det-0:#6675FF; /* 기타 */
/* 신뢰도 연속 램프 — LX 블루 계열로 치환 */

--conf-3:#006DF7; --conf-4:#0052B9; --conf-5:#003B85;
```

규칙 4개:
1. **채도 높은 클래스색은 오직 검출에만.** 지도 크롬·패널·버튼은 `--lx`/`--ink`/슬레이트 계열만.
2. **화면이 바뀌어도 같은 클래스는 같은 색.** 홈 스토리·XI맵·분석 실행·모델 카드가 전부 같은 매핑을 읽는다.
3. **범주형(차트 계열)은 별도 10색 팔레트**를 쓰고 상태 6색과 절대 섞지 않는다. 이 분리가 차트가 촌스러워지지 않는 이유다.
4. **신뢰도 색농도**는 `['interpolate',['linear'],['get','confidence'],0.5,'var(--conf-0)',1.0,'var(--conf-5)']`로 연속 표현한다.

### 4.7 타이포그래피

- **Display: Gothic A1 900.** 히어로 모토·챕터 타이틀·KPI 대형 수치. `letter-spacing:-.035em`. 단 1차 구현의 지적("무명 서체")을 반영해 **워드마크는 CI PNG를 SVG 아웃라인으로 벡터화해 옵티컬 커닝을 수동 조정**한다. 대제목은 가변 축을 써 스크롤 0→1 구간에서 `wght 700→400`으로 연속 감소시킨다(`animation-timeline: scroll()`, JS 0줄).

### 4.8 유리 패널 규칙

1차 구현의 가장 흔한 오독이 "backdrop-filter를 디자인으로 착각"하는 것이다(안티패턴 #3).

- **동시 3개 이하.** 실질 목표는 **화면당 1~2개**이며, 지도 위에서 실제 기능이 있는 곳에만 쓴다. 나머지 패널은 불투명 종이(`--surface`) 또는 단색.
- `blur ≤ 12px` **고정.** 블러 반경 애니메이션은 매 프레임 전체 재블러 → iGPU 킬러. 절대 금지.
- 유리 위 본문은 항상 `--ink`(대비 확보). 유리에 미세 노이즈 텍스처를 넣어 완벽한 균질을 깬다.
- 캔버스형 화면(워크플로우)에서는 **하단 실행 바만 유리**, 노드 카드는 불투명. 유리를 남발하면 데이터가 읽히지 않는다.

### 4.9 밀도·형태

- 컨트롤 높이 **30px**(small 24 / large 40), 인풋 30/24/40, 네비바 50px, **간격 4px 배수**, 라운드 6(컨트롤)/10(카드)/14(플로팅).

## 5. 화면별 설계

각 화면은 **「유지되는 기능(v2 인벤토리 그대로)」 → 「배치(ASCII)」 → 「살아있음(사용자가 하면 → 시스템이 보여준다)」** 순으로 적는다. 기능 인벤토리는 v2 §6에서 한 줄도 빠지지 않고 승계되며, 바뀌는 것은 그 기능이 놓이는 방식뿐이다.

### 5.1 홈 — 4챕터 연속 다이브

**유지되는 기능.** 상단 내비(플랫폼 소개·활용 사례·문의하기·로그인), 히어로 CTA 2개, 4개 지표, 4단계 파이프라인, 전/후 비교, 3개 기능 소개, 서비스 라인업 13종, 활용 사례 2건(모달), 문의 폼(모달·검증·토스트), 정책 모달. **전부 유지된다.** 다만 "섹션"이 아니라 **챕터 안의 계기**로 재배치된다: 4개 지표 → 챕터 2 HUD 타일, 서비스 라인업 13 → 챕터 2 점등 + 부처 칩, 전/후 비교 → 챕터 4 스와이프, 4단계 파이프라인 + 기능 소개 3 → 챕터 4 하단 워크플로우 미리보기, 활용 사례·문의·정책 → 챕터 4 종료 후 푸터 영역.

### 5.2 로그인 — "관문이 아니라 도킹"

| 히스토그램 막대 클릭 | 그 값으로 필터 적용/제외. 지도·표·선택 패널이 동시 반응 |
| 클래스 토글 | 체크박스 옆 숫자가 **현재 임계값 기준으로** 실시간 갱신 — 슬라이더와 토글이 연결되어 있다는 증거 |
| 줌 아웃 | 폴리곤 → 격자(`marine-debris-grid` 9,032셀)로 자동 전환. 줌 인하면 다시 폴리곤(전국 스케일에서 5,000건을 보여줄 때 필수) |
| 탐지 폴리곤 클릭 | 카메라 pitch 45° + 우측 드로어에 **256px 타일 크롭**. `←/→`로 검출 간 이동 |
| "연결된 객체" 펼침 | 클릭 **전에** 각 타입별 개수가 표시된다("연결된 필지 3", "이전 탐지 4"). 탐색이 도박이 아니라 항법이 된다 |
| 재생 버튼 | 4시점이 흐르다가 **사건이 있는 시각에서 스스로 멈춘다**(자동 정지). 시스템이 "여기를 보라"고 말한다 |
| 스와이프 핸들 드래그 | 좌우가 시점별 정사영상. 차이 강조 모드에서 초록=2504만/빨강=2510만/흰=양쪽 |
| 레이어 토글 | 체크박스 페이드가 아니라 **칩 위치를 원점으로 노이즈 threshold 파문**이 퍼지며 덮인다(0.9s power2.inOut, 끄기는 0.6s). 프론트 엣지에만 미세 밝기 부스트 — 경계가 살아있어야 물질처럼 보인다 |
| 폴리곤을 그린다 | 즉시 "교차 선택 / 영역 내 검색 / 궤적 필터 / 수정" + 둘레·면적 측정값. **지도가 배경 그림이 아니라 입력 장치** |
| 판독 모드 토글 | 다크 ops 세트로 전환. 정사영상 대비 극대화, HUD 십자선·좌표 리드아웃 표시. **지도 스타일 자체가 교체**되며 색 반전이 아니다 |
| 오탐 신고 / 현장 확인 요청 | 검출에 사람 피드백이 기록되고 재학습 큐에 쌓인다. 누적된 오탐 수가 모델 카드에 표시된다 |
| 보고서 발급 | `?embed=1` iframe. 시네마 연출 전부 OFF, 현재 필터·시점·선택 그대로 |

**심볼로지 규칙 (Palantir 체크 ⑩).** 일반 핀 금지. 탐지 = 클래스색 폴리곤(외곽 2px/채움 22%), 행정 케이스 = 상태색 도메인 글리프, **검수 상태는 stroke style로 구분**(대기 dashed / 승인 solid / 반려 dotted). AI 예측과 사람 확정이 절대 섞이지 않는다(Roboflow P9). OBB 모델(`yolo11x-obb` 15클래스)은 축 정렬 사각형이 아니라 **회전 폴리곤** 4점으로 그린다.

### 5.9 카드 발행 관리

**유지되는 기능.** 상태 칩(전체·대기·검토중·승인·반려), 목록·검색, 요청 상세(개요·구성원·라벨링·학습 결과·분석 결과 탭), 발행 처리(승인/반려·사유·이미지), 클래스 일괄 변경, 발행 카드 목록. **전부 유지.**

**배치.** 지도 캔버스형. 지도에는 요청 프로젝트의 분석 범위와 배포 대상 기관(`orgs.geojson`: LX 전주·남원시청·전남도청·신안·완도) 위치.

**살아있음.** 요청 호버 → 범위 강조 + 리더선 / 승인 확정 → 카드 썸네일이 목록에서 떠올라 지도 위 권한 기관으로 **deck.gl ArcLayer 궤적을 그리며 날아가 착지**하고 기관 핀이 켜진다(1.6s) / 반려 → 카드가 흔들리며 회색으로, 사유가 Action Log에 기록 / 상태 스테퍼는 각 단계에 **누가 언제** 처리했는지 표시 / 발행된 카드는 읽기 전용 공유 링크를 갖고, 그 링크에서 **결과가 실제로 렌더된다**(Roboflow 체크 ⑱).

**유지되는 기능.** 각 탭과 게시판(검색·기간 버튼·표·페이지네이터·상세·등록/수정 RTE·첨부), 사용자 관리(승인/거부·로그인 이력·비밀번호 이력), 지도 속성 관리, 마이페이지(회원 정보·비밀번호 변경·디스크 사용량·증량 신청 이력·브랜드 심볼 업로드·정보 수정). **전부 유지.**

## 6. 데이터 · 실자산 매핑

### 6.1 원칙

1. **모든 픽셀과 모든 숫자는 실제 파일에서 온다.** 실자산이 없는 항목은 **예시임을 화면에 명시**한다. "그럴듯하게 채우기"가 목업 판정의 직접 원인이었다.
2. **없는 데이터를 꾸미지 않는다.** 남원 4시점에는 AI 탐지 결과가 없다 → 순수 영상 비교만 한다. 제주 불법건축물은 2건뿐이다 → 2건이라고 쓰고 "학습 데이터 부족" 경고를 단다.
3. **값이 없으면 `0`이 아니라 "값 없음"**으로 표시하고 집계에서 제외한다.
4. **비지도(unsupervised) 결과는 반드시 그렇게 라벨링한다.** 지도학습 탐지와 같은 색·같은 문법으로 그리면 안 된다.

### 6.3 신규 산출물 — `namwon-change.geojson` (비지도 변화지수)

남원 4시점에는 지도학습 탐지 결과가 없다. 그러나 **4시점이 있다는 사실 자체가 자산**이므로, 시점 간 픽셀 통계로 **비지도 변화지수**를 산출해 별도 파일로 만든다.

- 산출: `tools/prepare-assets.py`(conda env `yolo`의 GDAL 3.12) — 2504↔2510 격자(예: 20m) 단위 변화 강도 정규화 0~1
- 파일: `assets/data/geo/namwon-change.geojson`, 속성 `cell_id`, `change_index`(0~1), `epoch_a`, `epoch_b`, `method`
- **표기 규칙(엄수).** 이 레이어는 UI에서 항상 **"변화지수(비지도)"**로 표기한다. 클래스 고정색(`--det-*`)을 쓰지 않고 **중성 단색 램프**로 그리며, 범례에 "AI 탐지가 아님 · 시점 간 통계 지표 · 검수 대상"을 명시한다. 검출 개수·신뢰도·mAP 같은 지도학습 지표를 붙이지 않는다.
- 용도: XI맵 "변화지수" 레이어 토글, 챕터 4 스와이프의 보조 오버레이(선택), 대시보드 변화 감지 큐의 후보 목록.
- **상태: 프로토 판정 후 확정** — 프로토에서 4시점 순수 영상 비교만으로 충분한 임팩트가 나오면 P3로 미룬다.

### 6.4 실결과 없는 서비스의 정직한 처리

`services.js` 13종 중 `real:true`는 **4종**(해양쓰레기 전남 / 농지이용·불법건축물 제주 / 도로안전 남원 / 드론 변화탐지 국산리)이다. 나머지 9종(비닐하우스·개발제한구역·방치쓰레기·불법소각장·차량/교통량·도로망·건물·토지형질·토지이용 등)은 라인업 소개용이다.

**처리 규칙.**

| 구분 | 지도 표현 | 라벨 | 패널 |
|---|---|---|---|
| 실데이터 4종 | 실제 폴리곤/격자 + 정사영상 | `실데이터` 배지(눈에 띄게 — 10px 민트 알약 금지, 12px 아웃라인 칩) | 신뢰도 슬라이더·히스토그램·상세 전부 활성 |

**금지.** 예시 서비스에 그럴듯한 검출 폴리곤을 생성해 얹는 것, 예시 건수를 실데이터와 같은 서식으로 표기하는 것, "AI 신뢰도 94%" 같은 근거 없는 게이지(Palantir 문법의 정반대다 — 근거를 보여줘라).

## 7. 성능 · 접근성 · 테스트 전략

### 7.1 fps 예산과 측정

| 장면 | 목표(iGPU 추정) | 측정 방법 | 실패 시 |
|---|---|---|---|
| 홈 챕터 1–2 (글로브 + 위성 + deck + three, 지형 OFF) | **45–60fps** | Playwright + 풀 크롬 `executablePath`, rAF 프레임타임 수집 | `lite` 강등 |
| 홈 챕터 3 (지형 ON, pitch ≤ 68, 3–4초) | **25–40fps 허용** | 같은 방법, 구간 한정 측정 | 지형 생략, pitch만 |
| 대시보드·XI맵 (mercator + 위성 + 벡터, 지형 OFF) | **60fps+** | 상시 | 레이어 축소 |
| 5,000 폴리곤 신뢰도 슬라이더 드래그 | **드래그 중 프레임 드랍 0** | mousemove 이벤트 → 다음 페인트까지 시간 | `maxzoom` 조정, 격자 모드 조기 전환 |

**측정 규칙.** median이 아니라 **p95 프레임타임**, 프레임 스파이크 목표 < 50ms. **Playwright 기본 headless shell은 GPU가 안 붙어 SwiftShader로 떨어지므로 성능 측정이 무의미하다** — `chromium-1223/chrome-win64/chrome.exe`를 `executablePath`로 직접 지정한다(이번 조사에서 실제로 겪은 함정).

**전송 예산.** 홈 초기 로드 ≤ 1.2MB(wire, 라이브러리) + 타일. LCP 목표 2.5s(로컬). 라이브러리는 화면별 분할 로드(§3.1).

### 7.2 접근성

- **키보드.** 레일·탭·다이얼로그·팔레트·슬라이더·타임라인 전부 포커스 가능. `:focus-visible` 링 2px `--lx`. 홈은 `←/→`로 챕터 이동. 라벨링 화면은 `B/P/D/S/N`, `←/→`, `⌘Z`, `Enter/Esc`, `↑/↓`, `a/r` 전부 동작 + 상시 힌트 바(Roboflow 체크 ⑯).
- **대비.** 잉크/미스트 12:1. 유리 패널 위 본문은 항상 `--ink`. **영상 위 텍스트는 halo 또는 불투명 배지 필수** — 위성 영상은 밝기가 예측 불가하므로 반투명 스크림에 의존하지 않는다.
- **색맹.** 상태색은 항상 필(pill) + 라벨 병기. 검출 클래스는 색 + 라벨 + stroke style 3중 인코딩.
- **모션.** §3.7 준수. 자동 재생 사운드 금지(옵트인 토글만).
- **스크린리더.** 지도의 상태 변화(필터 적용, 시점 변경, 검출 개수)를 `aria-live="polite"`로 알린다. 시네마 연출은 `aria-hidden`.

### 7.3 테스트

**(a) 씬 스크린샷 회귀.** `?scene=` / `window.__director.seek()`로 각 씬을 강제 세팅하고 1440×900 스크린샷. 홈 4챕터 + 각 화면 기본/필터적용/선택 상태 = 약 30컷. 기존 페이지와 나란히 비교해 **기능 누락**을 점검한다(체크리스트는 §5의 "유지되는 기능"에서 생성).

**(b) 비디오 회귀.** `playwright.config.mjs`에 `use:{ video:'on', trace:'on' }`. 홈 30초 스크롤 자동 재생을 `shots/*/dive.webm`으로 남긴다. **시네마틱 연출은 정지 이미지로 검증할 수 없다.** ffmpeg는 이미 설치되어 있다(`ms-playwright/ffmpeg-1011`).

**(c) 데이터 계약 단위 테스트.** 목업이 슬쩍 들어오는 것을 막는 방어선.
- `marine-debris.geojson`의 모든 feature가 `confidence ∈ [0,1]`을 가진다
- `detections-sample.geojson`이 `conf`를 가진다(P3 이후)
- `services.js`의 `real:true` 항목은 대응하는 geojson/타일이 실제로 존재한다
- `sigungu.geojson` feature 수 > 200이고 모든 `coverage ∈ [0,1]`
- `models.js` 10종 각각에 대응 파일 메타가 있다
- **문자열 검사**: 소스 전체에 `"이 자리에 들어갑니다"`, `TODO(`, `lorem`, `placeholder` 0건
- `namwon-change.geojson`을 쓰는 레이어의 legend 텍스트에 `비지도`가 포함된다

**(d) 판정 게이트 자동화.** §1.3 게이트 C(안티패턴 27개) 중 기계 검사 가능한 것을 린트로 만든다: `antialias:true` 사용 0건 / `essential:true` 0건 / 동시 `backdrop-filter` 요소 ≤ 3 / 이모지 문자 클래스가 아이콘 위치에 0건 / `--ease` 단일 토큰만 쓰는 파일 0건.

**(e) 오프라인 폴백.** 타일 도메인을 전부 차단한 상태에서 페이지가 살아야 한다. `still` 티어 + 절차 캔버스 폴백으로 **콘솔 오류 0, 레이아웃 붕괴 0, 기능 접근 가능**. 발주처 시연장 네트워크가 막히는 상황을 가정한 필수 시나리오다.

**(f) 콘솔 오류 0.** 전 페이지. `calculateFogMatrix` 경고만 화이트리스트.
