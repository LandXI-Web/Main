# 지도 기반 대시보드 — 인터랙티브 구현 방안 재검토 (3안)

- 작성일: 2026-08-26 · 브랜치 `plan1-foundation`
- 발주 요구: *"우리 자원조사 항목 중에서 지도 기반 대시보드의 인터랙티브한 자료들을 살펴보고 구현 방안을 다시 검토하자."*
- 이 문서는 **설계 검토서**다. 코드는 한 줄도 건드리지 않았다.

## 0. 전제 세 가지 (모든 안이 지켜야 하는 것)

1. **기능은 원본과 1:1이다.** 원본 <https://mini531.github.io/namwon-smart-village/landxi7/dashboard.html> 을
   Playwright(1440×900, `networkidle`)로 다시 열어 DOM·스크립트·ECharts 시드를 전량 덤프했고,
   기존 인벤토리 `docs/superpowers/proto/2026-08-26-dashboard-parity.md`(A1–A11 / B1–B16)와 **완전히 일치**함을 확인했다.
   §1이 그 확정 목록이다. **표에 없는 기능은 어느 안에서도 만들지 않는다.**
2. **디자인 시스템은 `docs/superpowers/specs/2026-08-25-client-taste-profile.md` §2.2 / §4 / §5 / §7이다.**
   흰 종이가 바탕(§2.2) · 어두움은 오직 사진 판(plate) 안에서만 · 라운드 0 · 그림자 0 · 유리는 화면당 1개 ·
   액센트 1개(LX 블루 `#006DF7`, 탐지 순간만 앰버 `#FFB633` 380ms) · 명명 레이아웃 5종
   (`PLATE-FULL` `SPLIT-5050` `LEDGER` `EVIDENCE-PAIR` `CHIP-RAIL`)의 조합으로만 짠다(§7).
   **콘티 원칙**(§7): 이 산출물은 신규 개발 콘티이지 운영 현황이 아니다. 지어낸 운영 서사
   (대기 일수 · 담당자 활동 기록 · KPI 추세 · 운영 리포트 문구) 금지.
3. **현재 Ops Atlas 빌드는 반려됐다**(`shots/proto-dash/01-infer.png` — "마음에 안 든다").
   반려 사유를 이 문서가 정면으로 다룬다:
   (a) 밝은 위성 위에 **불투명 격자 사각형**을 깐 것 → §5-1(사진이 화면의 60%)·§4(선택적 채도) 위반,
   (b) **앱 크롬 탭**(01/02/03 레지스터)이 첫인상 → §3-5(관리자 SaaS 크롬) 위반,
   (c) **지어낸 레지스터**(처리 대기 큐 7건 등) → 원본에 없는 기능 + §7 콘티 원칙 위반.

### 1.3 원본에 **없는** 것 — Playwright로 확인한 사실

발주 메모에 "차트 탭, 커버리지"가 언급됐으나 실측 결과 **원본에는 없다.** 지어내지 않는다.

| 항목 | 실측 |
|---|---|
| 탭 UI | `[role=tab]` · `.tab` · `[data-tab]` **0개**. 차트 3개는 탭이 아니라 **나란한 3열**이다 |
| 커버리지 위젯 | 없다. `<table>` **0개**, 본문 링크 목록 없음 |
| 지도 | **없다.** 원본 대시보드에 지도 요소는 존재하지 않는다 |
| 처리 대기 큐 | 없다. 대기 목록은 **카드 발행 승인 2건뿐**이다. 사용자·문의 건수는 KPI 부제(B4·B8)로만 존재한다 |

> **따라서 세 안 모두에서 지도는 "새 위젯"이 아니라 B1–B16을 조판하는 바탕이거나,
> B10(프로젝트 현황 Top5)을 지도 위에 놓은 같은 값의 다른 표현이다.**
> "전국 커버리지"라는 이름의 새 위젯은 만들지 않는다.
