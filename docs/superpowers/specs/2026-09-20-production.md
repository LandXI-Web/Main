# 생산화 — 분기·CI·화면·HW 를 모두 LX 의 기능으로 (2026-09-20 발주자 구술)

이원화 구조(`2026-09-20-two-tier.md`)가 "누가 무엇을 하는가"를 정했다면, 이 문서는 **"그 일을 사람이 하는가, 기능이 하는가"**를 정한다.

발주자 네 마디:
1. "기관이 찾은 오탐 재학습도 있겠지만, **LX가 적극적으로 이 임무와 역할을 해야** 이 플랫폼은 **비즈니스 사업화**할 수 있다."
2. "결국 LX에서는 이런 **지자체 분기화도 기능화** 해야만 나중에는 **인프라 HW도 잘 관리**할 수 있다."
3. "지자체 포털의 **CI 등 기본 틀은 LX가 만들어 낼 수 있고 생산화** 할 수 있도록 하는 거지."
4. "지자체 **서비스 카드별로 디자인을 LX에서 클로드 코드로 만들어냈으면** 좋겠다. 그래야만 적극적으로 지자체에서 **요구사항을 수시로 피드백 보완** 할 수 있거든."

## 0. 한 줄로

> **손으로 하면 용역이고, 기능으로 하면 사업이다.**

네 마디는 모두 같은 말이다 — 운영도·분기도·CI도·화면도 사람 손에서 빼내 기능으로 만든다. 그래야 50곳이 되어도 LX 한 팀이 감당하고, 고칠 때 한 번 고쳐 전부에 내린다.

| 손으로 하면 | 기능으로 하면 | 파일 |
|---|---|---|
| 기관이 신고해야 고친다 | LX 가 먼저 찾아 고쳐 올린다 | `ops.js` |
| 몇 대가 더 필요한지 아무도 모른다 | 배포본 한 줄에서 HW 가 계산된다 | `infra.js` |
| 기관마다 포털을 따로 발주한다 | 골격은 한 벌, 기관은 CI 한 벌만 낸다 | `brand.js` |
| 화면 수정은 다음 사업 때 | 명세 한 줄 고쳐 같은 주에 다시 찍는다 | `studio.js` + `tools/gen/portal-gen.mjs` |

## 1. 능동 운영 — 사업이 되는 자리 (`ops.js`)

```
납품형(수동)  모델 배포 → 기관이 쓴다 → 문제를 신고하면 → 고친다
사업형(능동)  모델 배포 → LX 가 성능을 지켜본다 → 떨어지면 먼저 재학습 →
              새 버전 배포 → 기관은 좋아진 것을 받는다 → 다음 계약이 이어진다
```

다섯 임무 **전부 LX 몫**이다: 성능 감시 · 선제 재학습 · 표본 검수 · 갱신 배포 · 적용 확대.
기관 임무는 **오류 신고 하나뿐**이며, 그것은 보조 신호다 — 그것만으로는 품질이 유지되지 않는다.

기준(`THRESHOLDS`): 신뢰도 0.60 · IoU 0.70 · 마지막 학습 365일 · 표본 100건.
`actionsFor(배포본)` 이 규칙만으로 "지금 무엇을 해야 하나"를 뽑는다. 사람이 판단하기 전에 기계가 먼저 든다.
`businessView().능동비율` 이 낮으면 납품형에 가깝다는 뜻이다.

## 2. 분기화의 기능화 → HW 관리 (`infra.js`)

분기(이식·배포)가 사람 손으로 도는 일이면 자원 소요를 아무도 모른다.
**배포본 한 줄이 시스템의 정식 기록이 되는 순간, 그 줄에서 HW 가 계산된다.**

```
배포본(DEPLOYS) × 지역 프로파일(면적) × 카드 선언(kind) × 대상 범위(COVER_RATIO)
     → 저장 · GPU · 트래픽 → 증설 시점
```

- **대상 범위를 지역 면적으로 잡지 않는다.** 영농은 농경지(0.20), 도로는 노선 버퍼(0.05), 해양쓰레기는 해안 버퍼(0.015), 인파는 행사 구역(0.01), 국토 변화만 전역(1.00). 이것을 빼면 자원이 몇 배로 부풀려져 판단을 망친다.
- 단가는 실측에서 뽑았다: 남원 전역 1시점 ≈ 2.1 TB / 752 km² → **2.8 GB/km²**, 타일은 원본의 1.5 %, 추론 0.9 GPU·h/km².

현재(배포본 7 · 지역 3): **저장 16 TB / 120 TB (13 %) · GPU 2,517 / 28,800 h·년 (9 %) · 타일 68 GB/월** — 예정 사업 2건을 넣어도 여유.
`costOfNewRegion(카드, 지역)` 이 **한 곳 더 받는 데 드는 값**을 즉시 내놓는다(영업·계약의 근거). 광주전남에 해양쓰레기 한 벌 = 2.31 TB · 611 GPU·h/년.

## 3. 포털 기본 틀 — LX 가 찍어 파는 생산품 (`brand.js`)

지자체가 포털을 따로 발주하면 기관마다 화면이 다르고, 고칠 때마다 그 기관 용역을 다시 돌려야 한다. 그러면 **LX 는 모델만 넣는 하청이 된다.**

| | 누가 | 무엇 |
|---|---|---|
| **골격** | LX 가 한 벌 | 레일 72 · 마스트헤드 64 · 카드 홈 · 작업공간 5탭 · 지도 · 보고서 서식 · 로그인 · 서비스 지원 (8부위) |
| **CI** | 기관이 한 벌 | 명칭 · 약칭 · 마크 · 상징색 · 연한 바탕 · 행정단위 말 · 좌표계 · 문의처 · 직인 (`CI_KEYS` 9개) |

`LOCKED` — 타이포(Paperlogy/Pretendard/Inter) · 바닥 14px · 라운드 0 · 그림자 0 · 레일 72 · 마진 56 · 채운 파란 버튼 없음. **기관이 못 바꾼다.** 그래야 50곳이 한 벌로 유지되고, 개선이 전부에 퍼진다.

`cssVars()` 는 **새 변수를 만들지 않는다** — `shell.css` 가 이미 쓰는 `--accent` · `--tint-1` · `--tint-2` 를 덮어쓸 뿐이다. 그래서 골격 CSS 한 벌이 모든 기관에 그대로 돈다.
`brandGuard()` 가 흰 바탕 대비 4.5 미만, 너무 짙은 연한 바탕, 허용 밖 토큰을 막는다. 남원 6.12 · 광주전남 6.57 — 통과.

화면에서 CI 교체가 닿는 곳: 레일 마크(`남원/XI` · `光全/XI`) · 창 제목 · 상징색 · 보고서 발급 기관.
**동시에 메뉴 경계도 화면이 지킨다** — 기관 레일에서 데이터 관리 · 프로젝트 · 카드 발행 관리는 제거된다(`TENANTS.menus`). LX 전용 메뉴가 기관 포털에 뜨면 이원화 경계가 무너진다.

`PRODUCE` — 새 기관 포털을 세우는 6단계 중 **4단계가 자동**(CI 등록 · 프로파일 등록 · 배포본 심기 · 화면 생성), 수동은 2개(현지 영상 수급 · 검수 개통)뿐이다. 이 비율이 생산화의 척도다.

## 4. 화면 생성 — 명세에서 찍는다 (`studio.js` + `tools/gen/portal-gen.mjs`)

화면을 용역으로 만들면 한 번 납품하고 끝난다. 기관이 "여기 이 칸을 바꿔 달라" 해도 다음 사업까지 못 고친다.

```
요구 접수 → 명세 한 줄 수정 → 생성기가 화면을 다시 찍음 → 배포 → 기관이 확인
     (몇 주가 아니라 같은 날 안에 도는 고리)
```

명세는 두 겹이다.
- **기본 명세** — 카드 선언(`kind`)에서 **자동으로 나온다.** 사람이 쓰지 않는다. 드론 영상이면 플레이어가, 밀도 출력이면 히트맵이, 구간 출력이면 등급 범례가 켜진다.
- **기관 보완** — 그 기관이 요구한 것만 얹는다(`REQUESTS`). 연산은 다섯 가지: `add` · `drop` · `order` · `label` · `opt`.

검증된 고리:

| 요구 | 연산 | 결과 |
|---|---|---|
| 광주전남 "해안선 구간 등급을 지도 첫 화면에 바로" | `order` | 지도탭이 `구간 등급 → 지도` 순으로 다시 찍힘 |
| 남원 건설과 "'분석 결과'를 '점검 대상'으로 부르고 싶다" | `label` | 그 배포본만 탭 이름 교체 |
| 남원 농정과 "필지 표에서 대장 불일치만 먼저" | `opt` | 필지 블록에 필터 옵션 전달 |
| 남원 환경과 "현황에 읍·면별 막대를" | `add` | 현황탭에 추이 차트 추가 |

평균 반영 **1.3일**(최장 3일). 접수 5 · 배포 3 · 반영중 1 · 대기 1.

규모: **배포본 7 × 5탭 = 35개 화면을 블록 12종으로 찍는다. 손으로 짠 화면 0.**

생성기 출력: `landxi/proto/portal.html`(기관 홈) · `portal-<배포본>.html` 7장 · `portal-gen.json`(무엇을 언제 찍었나 — 감사 기록).
`node tools/gen/portal-gen.mjs --queue` 는 요구가 반영된 것만 다시 찍는다.

**생성기는 CSS 를 만들지 않는다.** 골격(`shell.css` · `parts.css` · `portal.css`)은 LX 가 손으로 만들어 둔 생산품이고, 생성기는 그 부품을 카드 명세대로 배치할 뿐이다. 컨트롤러(`portal-ui.js`)도 블록 한 종류를 어떻게 그리는지만 알고 **카드 이름을 모른다** — 새 서비스가 생겨도 고치지 않는다(성장 규칙 R5).

## 5. 성장 규칙에 더하는 것

- **R8** 기관은 CI 한 벌만 낸다. 골격·타이포·간격은 LX 가 잠근다(`LOCKED`).
- **R9** 화면은 손으로 짜지 않는다. 명세를 고치고 다시 찍는다.
- **R10** 기관 요구는 기본 명세를 건드리지 않는다 — 그 배포본에만 얹는다.
- **R11** 배포본 한 줄은 자원 한 몫이다. 범위 없는 배포본을 만들지 않는다.
- **R12** LX 전용 메뉴는 기관 레일에 뜨지 않는다(`TENANTS.menus`).
