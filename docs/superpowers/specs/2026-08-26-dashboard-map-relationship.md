## 0. 이 문서가 답하는 한 문장

> **판(plate)은 위젯의 배경이 아니라 원장(ledger)의 대답이다.**
> 현황 숫자가 지도 위에 "얹히는" 게 아니라, **위치를 가진 현황만** 지도에서 스스로 자기 모양으로 서고,
> 위치가 없는 현황은 지도에 올리지 않는 것이 곧 "자연스럽게 어울리는" 것이다.

## 2. 관계 등급 3단

| 등급 | 정의 | 판(plate)의 역할 | 개수 |
|---|---|---|---|
| **Ⅰ 지도에 직접 표현** | 그 현황 **자체가 위치를 가진 것** | 첫 프레임부터 **아무 조작 없이** 판 위에 서 있다 | **4** |
| **Ⅱ 지도와 연동** | 값은 위치가 없지만 **가리키는 대상이 위치를 가진 것** | 원장 행 호버·클릭 때만 판이 **카메라·감쇠로 응답** | **4** |
| **Ⅲ 원장 전용** | 위치가 없는 것 | **판은 반응하지 않는다.** 무반응이 곧 정직성의 증명 | **8** |

기본 규칙 셋:

1. **Ⅰ만 상시 그린다.** Ⅱ는 사용자가 원장을 만졌을 때만 판에 나타나고, 손을 떼면 사라진다.
2. **감쇠하되 삭제하지 않는다**(Palantir P1). 필터·선택은 비매칭을 흐리고 클릭 불가로 만들 뿐이다.
3. **선 종류가 정직성이다**(`yt-iyRYc9sVRsw` §5-2 D5 → `측정 = 실선 + 채움` / `추정 = 점선 고스트` / `미확정 = 무채 파선 + 이유 한 줄`).
   색으로 신뢰도를 말하지 않는다. 범례에 정의문 1줄을 반드시 노출한다(`benchmark-vwlab` §5-5).

### 3.2 유휴 — 무엇이 움직이나

취향 프로필 §5-10: **화면당 움직이는 요소는 1개 + LIVE 스탬프.** 따라서:

| 상태 | 움직이는 것 | 정지한 것 |
|---|---|---|
| **유휴(기본)** | **실행 중 작업 1건(JOB-2026-039 주천면)의 스윕선 하나.** AOI 안쪽을 한 방향으로 6s 주기로 훑고, 테두리 진행 호가 5스텝 중 3번째에서 정지해 있다 | 시간 스트립 재생헤드 · D08 도트 · KPI 숫자 · 나머지 전부 |
| **스크러버 재생 중** | **시간 스트립 재생헤드 + 유리 창** (초당 전 범위 4%) | **스윕이 멈춘다** — 두 개가 동시에 움직이지 않는다 |

- D08은 **펄스하지 않는 정적 스탬프**다(`● 2025-10 기준`). 움직임 예산 1개를 스윕이 이미 썼다.
- KPI 숫자는 앰비언트 tick으로 흔들지 않는다 — **원본에 시계열이 없으므로 값이 바뀌는 척하면 그것이 지어낸 운영 서사**다(§7 콘티 원칙).
  진입 시 D13 카운트업 1회만 하고 그 뒤로 정지한다.
- 실행 중 작업이 0건이면 **유휴에 움직이는 것이 없다.** 그때는 스트립 재생헤드가 유일한 운동으로 승계된다. 가짜 활동을 만들지 않는다.

| **8** | **D01 스트립의 앰버 틱(변화 급변) 클릭** | 재생이 그 시점에서 멈추고(자동 정지), 유리 창이 `2025-08 → 2025-10`으로 750ms 이동하며 판의 밑그림이 그 시점 영상으로 교체된다. 변화 폴리곤이 스캔선 통과 뒤에만 남고 `0 → 112`가 900ms 카운트업. **동시에 판이 자백한다: `작업 상태는 시점 축이 없다 — AOI 10건 값 고정`.** 시점에 따라 변하는 것은 영상과 변화 지수뿐이며, 작업 건수·KPI는 **연출만 하고 값은 바뀌지 않는다** |

**보조**: 레일 A3–A9 클릭은 페이지 점프가 아니라 **원장 해당 블록 스크롤 + 판 카메라 `easeTo` 1,250ms**(§5-4).
A11 로그아웃만 원본과 동일하게 `lx_logged_in` 삭제 후 `home.html`.

### 3.4 상태 변화 — 대기 → 실행 → 완료가 지도에서 어떻게 바뀌나

한 AOI(예: 금지면)를 두고 세 상태가 **같은 자리에서 선의 종류만 바꾼다.** 위치는 절대 움직이지 않는다.

```
대기      무채 파선  1px   채움 0    라벨: 금지면 · 대기 · 예약 영상 namwon_2510
          정지. 스윕 없음.
   │
   │  실행 시작 (사용자가 A5에서 실행하거나, 콘티에서는 모의 실행 라벨)
   ▼
실행중    LX 블루   1px 실선  채움 0
          + AOI 안쪽 스윕선 1개  (6s 주기, 화면 유일한 운동)
          + 테두리 진행 호 5스텝  대기 ● 전처리 ● 분석 ◐ 후처리 ○ 완료 ○
          라벨: 금지면 · 분석중 3/5 · 시작 09:30
   │
   │  마지막 스텝 통과
   ▼
완료      스윕이 마지막 1회를 끝까지 통과한 뒤 → 380ms 락온 3비트
          → 잉크 실선 1px 확정 + 건수 0 → 397 카운트업 900ms (easeOutQuart, tabular-nums)
          라벨: 금지면 · 완료 · 397건 · 측정
          이후 정지. 스윕은 다음 실행 작업으로 넘어간다.
   │
   └─ (실패)  무채 파선 + 채도 0 + 라벨: 아영면 · 실패 · GPU 자원 부족
              삭제하지 않는다. 감쇠만 한다(P1).
```

세 가지 불변 규칙:

1. **상태 전이는 색이 아니라 선 종류 + 운동의 유무로 표현한다.** 파선(대기) → 실선+스윕(실행) → 실선+정지(완료).
2. **완료의 숫자는 실측에서만 나온다.** `results.js`의 `emd` 값(금지면 397 · 운봉읍 275 …)이 없는 AOI는 완료로 만들 수 없다.
3. **동시에 실행 중일 수 있는 작업은 화면에서 1건이다.** 2건 이상이면 스윕은 가장 최근 시작 건에만 붙고,
   나머지는 실선 + 정지 + `대기열 n` 배지로 표시한다(움직이는 요소 1개 규칙).

### 5.2 모의 실행 라벨

- A5에서 채록한 작업 10건(JOB-2026-035 ~ 044)은 **원본의 데모 시드**다.
  판 위에 그리되 **`모의 실행 · 원본 시드 10건`** 을 판 우하단에 상시 노출한다.
- 실제로 우리 `results.js`에서 나온 건수(운봉읍 237 · 금지면 397 …)로 완료 라벨을 채울 때는
  **AOI(읍면동)와 건수는 `측정`, 작업 자체는 `모의 실행`** 으로 두 태그가 함께 붙는다.
  이 두 겹을 한 겹으로 뭉개면 "실제로 그 작업이 돌아간 것"처럼 읽힌다.

### 5.4 남은 리스크 3가지

1. **"내가 알던 화면이 아니다"** — 원본을 아는 담당자에게 배치가 낯설다.
   완화: 원장이 **원본 순서 B1→B15를 그대로** 지키고, §1 표가 곧 e2e 검수 체크리스트가 된다(위젯 16 · 레일 11 존재·값·딥링크 자동 검사).
2. **Ⅲ등급 8개의 무반응이 "미완성"으로 오해될 수 있다.**
   완화: 등급 눈금(E8)을 원장에 시각화하고, 판 하단 범례에 `눈금이 붙은 블록만 지도에 선다` 한 줄을 둔다.
   담당자 설명에서도 이 문장을 먼저 말한다 — **무반응은 설계이지 결함이 아니다.**
3. **작업 AOI 레이어(E6)가 "새 위젯 추가"로 감사될 수 있다.**
   완화: 이것은 **B9의 `연결된 분석 과제 14개`라는 원본 숫자의 지도 표현**이며, 원장에 새 블록을 만들지 않는다.
   판 위 표현은 위젯이 아니라 조판이다 — `options.md` §1.3의 "지도는 새 위젯이 아니라 B1–B16을 조판하는 바탕" 원칙과 동일.
