# §1. 대상별 해부 (실측)

각 항목은 **① 캡처 · ② 그리드 실측 · ③ 타입 스케일 실측 · ④ 밀도 · ⑤ 상태 표기 문법 · ⑥ 수치/KPI 조판 ·
⑦ 지도의 위치와 크기 · ⑧ 목록·큐 조판 · ⑨ 빈 상태/대기 상태 · ⑩ 색 규율 · ⑪ 첫 900px(첫인상) ·
⑫ 훌륭한 점 / 우리가 가져올 것** 순서다. 숫자는 별도 표기가 없으면 **1440×900 기준 실측 px**이다.

## 1.1 NASA Earthdata Search — `search.earthdata.nasa.gov` 〔L〕

**캡처** `earthdata-1.jpg` `earthdata-2.jpg` `earthdata-3.jpg` `earthdata-hd-4.jpg`

지오 도메인에서 **"좌측 필터 레일 + 가운데 결과 목록 + 우측 지도"** 3단을 가장 성숙하게 조판한 실물이다.
로그인 없이 전 기능이 열리고, 데이터가 진짜다(11,131개 컬렉션).

**② 그리드.** 좌 필터 레일 `0–327`(327px, 안쪽 패딩 16). 결과 목록 컬럼 `328–928`(**600px**).
지도 `928–1440`(**512px = 화면폭의 35.6%**, 높이 100%). 세로로는 상단 브랜드바 32px → 검색바 44px →
패싯 툴바 50px → 본문. 하단에 28px **프로비넌스 바**가 상주한다(`v26.1.9-2 · Search Time: 2.9s ·
NASA Official: Doug Newman · FOIA · NASA Privacy Policy`). 즉 화면의 위아래를 얇은 시스템 밴드가 물고,
가운데를 3단이 채운다. 컬럼 사이 거터는 **0**이고 대신 **1px 헤어라인**이 경계다 — 카드 사이 여백으로
구획하지 않는다.

**③ 타입.** 결과 제목 15px/600, 메타 라인 13px/400 회색, 설명 13px/400, 프로비넌스 라인 11px/400,
목록 헤더 `11,131 Matching Collections` 17px/600, 툴바 12px/400. **네 단계뿐**이고 굵기는 400·600 둘뿐이다.

**④ 밀도.** 결과 행 1개 높이 ≈ **135px**(제목 1–2줄 + 메타 1줄 + 설명 2줄 + 프로비넌스 1줄 + 썸네일 68×64).
900px 안에 약 **5.5행**. 좌 레일 아코디언 행은 40px → 900px에 약 **20행**. 즉 같은 화면에서
**"20행짜리 얇은 목록"과 "5.5행짜리 두꺼운 목록"을 동시에** 쓴다. 밀도를 한 값으로 통일하지 않는 것이 요령이다.

**⑤ 상태 표기.** 세 층으로 나뉜다.
(a) **무채 아웃라인 아이콘 줄** — 구름 사용 가능/불가, 지도 이미지 유무 등. 색을 쓰지 않는다.
(b) **알약 칩 1개** — `1 to 3 hours`(지연 시간). 회색 채움, 높이 20px, radius 10px, 12px/400.
(c) **밑줄 링크** — `GEOSS`(출처 계보). 칩을 남발하지 않고 **행당 컬러 칩은 0–1개**로 묶는다.

**⑥ 수치.** KPI 카드가 **없다.** 큰 수(11,131)는 목록 헤더의 한 줄로 존재하고, 행마다의 수
(`4,058 Granules`)는 메타 라인의 첫 토큰이다. **숫자를 위한 별도 박스를 만들지 않는다**는 것이 이 화면의 결론이다.

**⑦ 지도.** 우측 512px. 지도는 목록의 **결과가 아니라 짝**이다 — 목록 행에 마우스를 올리면 지도에 풋프린트가 뜬다.
지도가 화면을 지배하지 않고, 폭의 1/3만 갖는다. 우리 요구("대시보드는 축소하되 첫 화면이니 잘 보이게")와
직접 맞물리는 비율이다.

**⑧ 목록.** 행 = `제목 / 메타 / 설명 / 프로비넌스 / 썸네일 / (i)정보 + (+)담기` 6요소. 우측 하단에 액션 2개
(원형 `i`, 원형 `+`)가 **항상 보인다**(호버에서 나타나지 않는다). 우리 B13의 `검토` 버튼 자리와 같은 문법이다.

**⑨ 빈 상태.** 썸네일이 없으면 68×64 무채 박스에 9px `No image available`을 중앙 정렬한다. **자리를 비우지 않고,
없다고 말한다.** 우리 §5-10(결손은 무채 + 이유 한 줄)과 같은 원리를 실제로 구현한 사례다.

**⑩ 색.** 배경 흰색, 텍스트 `#2C2C2C`/`#5A5A5A`, 상단·하단 밴드 `#111`, **액센트는 빨강 하나**(검색 버튼)
+ 파랑(링크). 지도는 컬러지만 UI는 사실상 무채다.

**⑪ 첫 900px.** 이미지(지도 타일)가 첫 화면의 **약 36%**, 나머지는 목록. 최대 폰트 17px. 즉 **"큰 글자로 놀래키지
않고, 데이터 개수와 실제 목록으로 첫인상을 만든다."** 첫 화면에서 사용자가 얻는 정보량이 가장 큰 축에 든다.

**⑫ 훌륭한 점.** 밀도를 두 종류로 쓴 것, 컬러 칩을 행당 1개로 제한한 것, 없는 것을 말하는 썸네일,
하단 프로비넌스 밴드(버전·검색 소요시간·담당자 실명). **우리가 가져올 것**: 3단 그리드 비율(327 / 600 / 512),
행의 6요소 구성, 결손 썸네일 문구, 하단 프로비넌스 밴드.

## 1.2 Esri ArcGIS Online — 콘텐츠 브라우저 / 검색 〔L, DOM 실측〕

**캡처** `arcgis-gallery-1.jpg` `-2` `-3` `arcgis-gallery-hd-4.jpg` · 실측 `_measure-arcgis-gallery.json`

이번 조사에서 **우리 취향 프로필 §4와 가장 정확히 겹치는 실물**이다. 이유는 하나 —
**border-radius가 페이지 전체에 0개, box-shadow는 헤어라인 대용 2개뿐**이기 때문이다.

**② 그리드(DOM 실측).** 좌 필터 레일 `arcgis-item-browser-filters` **w=261**(내부 콘텐츠 237, 좌우 12씩).
레일 시작 x=24. 콘텐츠 컬럼 `arcgis-item-browser-content` **x=316, w=1104**. 따라서
**거터 = 316 − (24+261) = 31px**, 우측 마진 20px. 상단 검색 인풋은 `x=24, w=1416, h=48`로
**두 컬럼을 가로질러 폭 전체를 먹는다** — 검색이 이 화면의 주인공임을 조판으로 선언한다.

**③ 타입(DOM 실측).** 실제 사용된 조합은 **네 개뿐**이다.

| 크기/굵기/행간 | 등장 수 | 쓰임 |
|---|---|---|
| `12px / 400 / lh16` | **120회** | 메타·칩 라벨·`View details` |
| `14px / 400 / lh16` | **82회** | 본문·필터 항목·설명 |
| `16px / 400 / lh20~24` | 9회 | 탭(`Content`/`Groups`), 헤더 메뉴 |
| `20px / 400 / lh30` | 1회 | 페이지 제목 `Search` |

폰트는 Avenir Next 단일, **굵기는 400 하나뿐이다.** 위계를 굵기가 아니라 **크기와 색으로** 만든다
(`#141414` 528회 / `#595959` 25회 / `#6B6B6B` 8회). 우리 §4의 "SUIT Medium 단일 굵기" 규칙과 정확히 같은 전략이다.

**④ 밀도.** 행 높이 중앙값 **56px → 900px당 16.1행**. 단 이 56px는 필터 트리 행이고, **아이템 카드는 158–190px**
(제목 20px + 설명 1–2줄 + 메타/칩 라인 + 1px 구분선 + 소유자 스트립). 900px에 **약 4.7개**. Earthdata와 같은
"두 밀도 병용" 구조다.

**⑤ 상태 표기 — 이번 조사에서 본 최고의 칩 문법.** 아이템 카드 메타 라인은
`[타입 아이콘] Feature layer │ Item updated: Sep 23, 2025 │ ✓Authoritative │ ⓐLiving Atlas │ ⛨Subscriber`
순서다. 규칙이 뚜렷하다.
1. **칩은 사실(fact)만 담는다** — 상태가 아니라 *속성*이다. `Authoritative`(검증됨), `Retired item type`(폐기 유형),
   `Has replacement`(대체본 있음), `OAuth 2.0 Credentials`.
2. **칩마다 14px 아이콘 + 12px 라벨**, 높이 24px, 좌우 패딩 10, 알약형. 배경은 **파스텔 채움**(연녹/연청/연보라),
   테두리 없음, 그림자 없음.
3. **부정적 사실도 같은 무게로 쓴다** — `Retired item type`을 빨강 경고로 만들지 않는다. 경고색을 아끼는 것이
   신뢰를 만든다.
4. 카드당 칩은 **최대 4개**, 그 이상은 잘라낸다.

**⑥ 수치.** KPI 카드가 **없다.** 총계는 `1-60 of 8,147` 한 줄(12px)로 목록 상단 좌측에 붙고, 우측에는
정렬 드롭다운(`Relevance`)이 온다. 숫자를 위해 면적을 쓰지 않는다.

**⑦ 지도.** 이 화면에는 **지도가 없다.** 대신 각 행 우측에 **128×72 썸네일**로 지도를 축소해 둔다 —
"지도는 목록의 삽화"라는 결정. 지도 크기 0인 대안(§2-C)의 실물 근거다.

**⑧ 목록.** 카드 하나 = `제목(20px) / 설명(14px, 최대 2줄) / 메타+칩 라인 / ─1px─ / 소유자 스트립`.
소유자 스트립은 좌측에 24px 아바타 + 소유자명(14px), 우측에 `Open in Map Viewer` + `⋯`. **행의 액션을
행 안쪽 아래에 따로 띠로 분리**한 것이 특징 — 우리 B13의 `검토` 버튼을 여기에 두면 그대로 맞는다.

**⑨ 빈 상태.** 썸네일이 없는 아이템은 회색 톤 아이콘 플레이스홀더로 채우고, 검색 0건일 때는
"필터를 조정해 보라"는 문장 + 적용된 필터 칩을 나열한다(제거 가능). §2-D05(dim-not-delete)의 온건판.

**⑩ 색.** 배경 `#FFFFFF` + 섹션 구분 `#F7F7F7`. **radius 0 · shadow 0**(실측: `radii` 목록이 비었고,
shadow는 `rgb(224,224,224) 0 1px 0`과 `1px 0 0 inset` 둘뿐 = 전부 헤어라인 대용). 테두리 `1px #D4D4D4`.
액센트는 `#007AC2` 하나.

**⑪ 첫 900px.** 이미지 점유율 **0%**, 최대 폰트 **20px**, 텍스트 노드 94개. 첫인상이 **완전히 텍스트**다.
정보 밀도로 승부하는 극단. 우리 클라이언트 취향(§3-5 "관리자 SaaS 크롬이 첫인상인 화면" 거부)과는
정면으로 충돌하는 지점이므로 **이 화면의 조판은 가져오되 첫 밴드는 반드시 다르게 처리해야 한다**(§3에서 다룸).

**⑫ 훌륭한 점.** 라운드 0 · 그림자 0 · 단일 굵기 · 헤어라인 구획 · 칩은 사실만. **우리가 가져올 것**:
261 / 31 / 1104 그리드, 12·14·16·20 4단 타입, 칩 규격(h24 · 12px 라벨 · 파스텔 채움 · 카드당 ≤4),
행 하단 액션 스트립, 총계를 `1-60 of 8,147` 한 줄로 쓰는 어법.

## 1.3 kepler.gl — 사이드 패널 〔L, DOM 실측〕

**캡처** `keplergl-1.jpg` `keplergl-data-1.jpg` `-2` `-3` `keplergl-data-hd-4.jpg` · 실측 `_measure-keplergl-data.json`

**② 그리드.** `side-panel--container` **w=324**, 그 안의 `side-bar` **w=292**(상하 12씩 인셋 → h=876),
다시 `side-panel__content__inner` **w=260**. 즉 **324 → 292 → 260**의 3중 인셋이고, 실제 콘텐츠 폭은 260px다.
패널은 화면에 붙지 않고 **16px 떠 있다**. 지도는 `1440×900 = 100%`로 패널 **밑을 지나간다**(패널이 지도를 자르지 않는다).

**③ 타입.** `11px/500/ls0.3px`(버튼·라벨) · `11px/400/ls1.25px`(섹션 라벨 `Datasets`) ·

`MP Service Territory` 파란 폴리곤). **색의 의미를 화면 안에서 정의한다.**
우리 §5-9("HUD의 모든 숫자가 해설인가")의 색 버전이다.

**⑨ 탭.** 좌 컬럼 하단에 `Outage Summary | Location Summary` 2탭 — **탭은 목록 컬럼에만 걸리고

→ **"지도를 줄이되 지도가 화면의 바닥이게 하는" 방법**의 실물. 우리가 찾던 절충안이다.

제3의 형식이며, **시작/끝처럼 짝을 이루는 값**에 최적이다.
→ 우리 B13 행의 `제출 2026.06.10 14:30` 같은 값에 쓸 수 있다.

**⑧ 하단 시간 스트립.** 화면 맨 아래 어두운 밴드(h≈60)에 `YEAR ▲▼` 스케일 셀렉터 + 데이터셋 이름 +

배경 흰 + `#F6F6F6`. 액센트는 **빨강 `#F64137`(검색 버튼)** 하나 + 포커스 링 `#1C67E3`.

동시에 원본은 **기능 배치가 이미 합리적**이다 — 공지 → KPI 5 → 백본 → 차트 3 → 큐 → 바로가기의 순서는
Esri 상황판의 `요약 → 지표 → 큐` 순서와 사실상 같다. **바꿔야 할 것은 순서가 아니라 조판·타이포·첫 밴드다.**

# §2. 후보 3안 — 우리 12위젯을 그들의 슬롯에 1:1로 넣는다

## 2.0 대입 규칙

1. **기능을 더하지 않는다.** 새 위젯·새 탭·새 큐·새 지표를 만들지 않는다.
   원본에 없는 것(탭 UI, 커버리지 위젯, 처리 대기 큐)은 어느 안에도 없다.
2. **지도는 출처에 지도가 있을 때만, 출처의 크기 그대로 쓴다.**
   지도에 올리는 것은 **위치를 가진 4위젯**뿐이다 —
   **B5**(발행 분석 카드 8건의 대상 지역) · **B9**(백본 모델이 적용된 지역) ·

   나머지 8위젯은 지도에 아무것도 올리지 않는다.
3. **ASCII는 1440×900 첫 화면**이다. 접힘 아래로 내려가는 것은 표 아래에 따로 적는다.
4. 표기: `[Bn]` = 원본 위젯 번호, `[A1–A11]` = 좌측 레일 11항목, `〔출처〕` = 그 슬롯의 원 소유자.

# §3. 권고 — **안 B `ESRI-STATUS` 하나를 그대로 이식한다**

## 3.1 왜 이것인가 (네 줄)

1. **같은 업종의 실물이다.** ArcGIS Dashboards는 지오 상황판의 산업 표준이고, 우리가 캡처한 세 인스턴스
   (오리건 화재 · Hanover 카운티 · Outage Center)는 **지금 이 순간 운영 중**이다. "임의 구현"이 아니라
   "잘 만든 걸 따온 것"이라는 발주 요구를 문자 그대로 만족한다.
2. **취향 프로필 §4와 충돌이 없다.** 실측상 **border-radius 0, box-shadow 0, 위젯 간격 8px 균일**이다.
   우리가 지켜야 할 "라운드 0 · 그림자 0"이 이미 이 제품의 기본값이다.
3. **첫인상이 가장 강하다.** 박스 없이 흰 바탕에 놓인 **52px 숫자**, 화면의 **58%를 차지하는 지도**,
   그 옆에 실제로 5행 이상 보이는 큐. `arcgis-dash-oregon-2.jpg` 를 보면 세 안 중 어느 것이 첫 화면으로
   더 강한지 논쟁의 여지가 없다.
4. **0과 결손을 다루는 법이 이미 들어 있다.** `ⓘ No data` 위젯과 **큰 0**은 우리 B6·B7·B8·B13이
   0건이 되는 날을 위한 완성된 답이다. 다른 두 안에는 이만한 답이 없다.

**안 A(Earthdata)는 버리지 않는다.** §3.4에 적은 **세 가지 부품**(칩 규격 · 하단 프로비넌스 밴드 ·
하단 시간 스트립)만 부품으로 가져온다. 조판은 안 B 하나만 따른다.

## 3.4 상태 문법 — 그대로 옮길 규약

1. **상태는 아이콘이 말하고, 범례가 그 아이콘을 정의한다.**〔Outage〕
   우 범례 패널이 일급 위젯이므로, 큐 행의 아이콘(`⚠ 검토 대기` / `◔ 처리 중` / `✓ 완료`)은
   **반드시 범례에 정의가 있어야 한다.** 화면 안에서 정의되지 않는 색·기호를 쓰지 않는다(§5-9).
2. **큰 수는 박스가 없다.**〔Oregon〕 채움·테두리·그림자 없이 흰 바탕에 놓는다.
   **라벨은 값 아래가 아니라 다음 줄의 좌·우 끝**에 교차 배치한다(B4 좌 / B5 우).
3. **큐의 제목이 곧 KPI다.**〔Outage〕 → **B6과 B13을 하나로 합친다.**
   `카드 발행 승인 대기 2건 / 검토 필요` 요약 블록 바로 아래에 그 2건이 온다.
   **같은 숫자를 화면에서 두 번 말하지 않는다.** (기능은 그대로 — 딥링크 `admin-publish.html?status=대기`는 유지)
4. **0은 큰 수로 쓴다.**〔Hanover〕 `가입 승인 대기 0건`도 40px다. 회색으로 죽이지 않는다.

## 3.6 검수 체크리스트 (이식 완료 판정)

1. 위젯 간격이 8 이외의 값이 **하나도** 없는가.
2. `border-radius`와 `box-shadow`가 **0회** 등장하는가.
3. 화면에 액센트 색이 **LX 블루 하나**인가(앰버는 380ms 동안만).
4. B4–B8·B13의 숫자가 **원본 값과 1:1**인가.
5. B6의 숫자와 B13의 건수가 **한 번만** 나오는가.
6. 어떤 값이 0일 때 위젯이 사라지지 않고 **큰 0 또는 `ⓘ 자료 없음`** 이 오는가.
7. 지도 위 모든 기호가 **범례에 정의**돼 있는가.
8. 첫 900px에서 정사영상이 **58% 이상**인가.
9. 첫 900px의 최대 글자가 **52px**인가.
10. 라벨이 **잘리지 않는가**(1440과 1920 둘 다에서).
11. 크레딧 스트립의 날짜가 `imagery.js`의 **실제 값**인가.
12. 좌 레일 항목이 **정확히 11개**이고 링크가 원본과 같은가.

# §4. 이번 조사에서 본 안티패턴

번호마다 **어느 캡처에서 봤는지**를 적는다. 전부 실물이다.

**A1. 색 채움 블록으로 심각도를 말하기** — `arcgis-dash-wildfire-1.jpg`
`5` `13` `17` `483.45` `5` `2` `1,369` `795,488` 이 전부 크림슨/앰버/회색 **면 채움 블록**에 담긴다.
문제 셋: (a) 값보다 **배경이 먼저 읽힌다**, (b) 색이 세 개라 액센트 규율이 무너진다,
(c) 색맹 사용자에게 심각도가 전달되지 않는다. 같은 제품의 `arcgis-dash-oregon-2.jpg` 는
**채움 없이 흰 바탕에 크림슨 숫자**만으로 같은 일을 더 잘 해낸다 — 그래서 §3은 오리건 쪽을 택했다.

**A2. 값은 자동 축소하는데 라벨은 자르기** — `arcgis-dash-hanover-1.jpg` `-hd-3.jpg`
1440에서 `Motor Vehicle Crashes` 가 `Motor Vehicle Crashe…` 로 잘리고,
1920에서도 `Air Temperature at Hanover County Airport` 의 `Airport` 가 잘린다.
**숫자를 살리려고 라벨을 죽인 것**인데, 라벨 없는 숫자는 §5-9 위반(해설이 아닌 장식 숫자)이다.

**A3. 축척에 따라 무너지는 심볼 — 같은 화면이 1440에서는 실패하고 1920에서는 성공한다** —
`arcgis-dash-oregon-2.jpg`(1440) vs `arcgis-dash-oregon-hd-4.jpg`(1920)
**1440에서는** 불꽃 아이콘이 40–70px로 렌더되어 서로 겹치고, 워싱턴·오리건·캘리포니아의 **지형이 사라진다.**
"많다"는 전달되지만 "어디"가 사라졌다.
**1920에서는** 같은 레이어가 **빨간 헤어라인 화재 경계 폴리곤**으로 바뀌어, 지형·행정경계·화재 범위가 모두 읽힌다.
즉 **아이콘/폴리곤 전환 임계 축척이 1440 데스크톱을 고려하지 않은 것**이다.
교훈: 심볼 밀도는 화면 폭과 축척 둘 다에 걸어야 한다. 우리 §4의 정답은 **헤어라인 풋프린트 + 코너 브래킷**이고,
**밀도→개체 크로스페이드**(취향 §6)를 화면 폭 기준으로도 한 번 더 걸어야 한다.

**A4. 죽은 대시보드를 그대로 두기** — `arcgis-dashboard-jhu-1.jpg` `arcgis-dashboard-county-2.jpg`
한때 세계에서 가장 많이 본 지오 대시보드(누적 5.7억 조회)가 지금은
`Sign in — Please sign in to ArcGIS Online.` 모달과 `⊗ Data source does not exist or is inaccessible.`,
그리고 `Fatal errors / ABORTED` 만 남았다. **폐기 계획 없는 대시보드는 신뢰를 역으로 갉아먹는다.**
우리 문서에 **데이터 기준시점 스트립**(C11·C16)을 필수로 넣는 이유다.

**A5. 폐기 안내를 모달 하나로 대체하기** — `eobrowser-1.jpg`
Sentinel Hub EO Browser는 앱 전체가 사라지고 `See. Decide. Act.` + 버튼 두 개짜리 검은 모달만 남았다.
**리다이렉트도 아니고 아카이브도 아니다.** 사용자는 자기 워크플로가 어디로 갔는지 화면에서 알 수 없다.

**A6. 첫 클릭을 콘텐츠가 아니라 동의로 만들기** — `copernicus-browser-1.jpg` `-2` `-3`
익명 열람이 가능한데도 `Log in / Anonymously` 모달이 지도를 덮는다. 우리 자동화가 세 번 재시도하고도
못 뚫었다는 것은 **사람도 매번 뚫어야 한다**는 뜻이다.

**A7. 일러스트로 제품을 암시하기** — `cloudflare-2.jpg`
"Get actionable insights into your web performance" 옆에 **실제 대시보드가 아니라 대시보드 그림**이 있다.
막대·도넛·표를 흉내 낸 벡터 일러스트다. 우리 §3-3("이 자리에 들어갑니다" 금지)이 거부한 그것.

**A8. GIS/결제 제품인데 첫 화면에 제품 UI가 0** — `felt-1.jpg` `toss-business-1.jpg`
Felt는 `Make maps, apps, and dashboards in seconds` 아래 **지도 실루엣 워터마크**만 보여주고,
토스 비즈니스는 **노트북을 치는 사람 사진**만 보여준다. 둘 다 로그인해야 제품이 나온다.
**우리는 이 분리를 할 수 없다 — 대시보드가 곧 첫 화면이다.**

**A9. 큰 라운드 + 그림자 + 액센트 2개** — `vworld-portal-1.jpg` `ncloud-2.jpg` `tosspayments-3.jpg`
V-World는 radius 4/8/100px + `0 2px 4px rgba(0,0,0,.1)` 그림자 11회 + 인디고·오렌지 2액센트,
네이버 클라우드는 radius **20/22px** 33+16회, 토스는 radius **24px** 19회.
**국내 관례이지만 우리 §4(라운드 0 · 그림자 0 · 액센트 1)의 정면 위반**이다.
"국내에서 다들 이렇게 한다"는 근거로 이 셋을 따라가면 취향 프로필이 무너진다.

**A10. 균일 카드 그리드** — `ZZ-original-landxi7-1.jpg` `foursquare-studio-2.jpg`
원본 대시보드의 KPI 5 + 차트 3 + 목록 1은 **전부 같은 radius 10px 흰 카드**다.
Foursquare 문서도 3열 동일 카드다. 형태가 같으면 **위계가 사라지고 전부 같은 무게로 읽힌다.**
§3의 답은 **형태를 다르게 하는 것**이다 — 큰 수(박스 없음) / 요약 블록(연한 밴드) / 큐 행 / 범례 행.

**A11. 툴팁 안에 조작 버튼 두기** — `vercel-obs-3.jpg`
차트 툴팁 안에 검은 `Zoom In` 버튼이 있다. 마우스가 조금만 움직이면 사라지는 표면에 액션을 둔 것.
**호버로 나타나는 것에 클릭을 요구하지 않는다.**

**A12. 액센트를 3개 이상 쓰기** — `cesium-ion-2.jpg` `cesium-ion-4.jpg`
Cesium은 청록 셸 + **연두 `#D8DF4F` 버튼** + 파랑 링크를 동시에 쓴다.
`LEARN MORE` 연두 버튼과 `BACK TO HOME` 연두 버튼이 청록 배경 위에서 진동한다.

**A13. 내부 컨테이너 스크롤** — `stripe-2.jpg`~`stripe-4.jpg`, `foursquare-studio-*`
`window.scrollTo()` 가 아무 효과가 없다. 문서 본문이 별도 스크롤 컨테이너 안에 있어서,
자동화·딥링크·`Ctrl+F`·접근성이 모두 어긋난다. (우리 캡처도 이것 때문에 한 번 실패해 휠 스크롤로 다시 찍었다.)

**A14. 문서 셸을 제품 근거로 삼기** — 이 조사 자체의 한계
Stripe·Cloudflare·Cesium·Mapbox·Foursquare는 **대시보드를 못 봤다.**
문서 셸의 그리드·타입은 실측했지만 **그것은 대시보드가 아니다.**
§3에 이들의 조판을 넣지 않은 이유가 이것이다 — **본 것만 옮긴다.**

**A15. 검색 없는 화면에 검색을 남겨두기** — 안 A·안 C 설계 시 실제로 마주친 함정
Earthdata와 Esri 브라우저 모두 **검색이 화면의 주인공**이다(전폭 인풋 1416×48).
우리 원본 대시보드에는 검색이 **없다.** 이 슬롯을 "빈 자리라서" 검색으로 채우면 **기능 추가**가 된다.
그래서 안 A는 그 자리를 B2로, 안 C는 B3으로 **대체**했다. 조판을 베낄 때 가장 흔한 사고 지점이다.

**A16. 같은 숫자를 두 번 말하기** — `ZZ-original-landxi7-1.jpg`
원본은 `카드 발행 승인 대기 2건`(B6 KPI)과 `카드 발행 승인 대기` 목록 2행(B13)을 **따로** 그린다.
`Outage Center` 는 `9 Active Outage(s)` 제목 아래 그 9건을 바로 놓아 **한 번만** 말한다.
숫자를 두 번 말하면 둘이 어긋나는 날이 반드시 오고, 그날 화면 전체의 신뢰가 무너진다.

**A17. 히어로 500px 뒤에 제품을 숨기기** — `roboflow-1.jpg` `up42-5.jpg` vs `linear-3.jpg`
Roboflow와 UP42는 첫 화면이 문장과 로고 띠뿐이고 제품은 한참 아래에 있다.

**"헤드라인 → 제품이 반쯤 올라온다"** 가 이 공식의 유일한 성공형이다.

# §6. 보강 — V-World 지도조회(`map.vworld.kr`)가 권고안을 국내 사례로 뒷받침한다

**캡처** `vworld-map-1.jpg` `-2` `-3`

§1.13에서 다룬 것은 V-World **포털 첫 화면**이었다. 실제 **앱**(지도조회)은 다른 화면이고,
**권고안 `ESRI-STATUS`와 사실상 같은 조판**이다. 국내 국토교통부 서비스가 이미 이 구조를 쓴다는 점은
"임의 구현이 아니라 잘 만든 걸 따왔다"는 근거로 그대로 쓸 수 있다.

**② 그리드(1440×900 실측).**

| 영역 | x | 폭 | 비율 |
|---|---|---|---|
| 상단 GNB (남색 `#1B3A6B`) | 0–1440 | 1440 | h **46** |
| 서브 바 (`📌 주제도 0 건 ‹`) | 0–1440 | 1440 | h **34** |
| **좌 패널** | 0–360 | **360** | **25%** |
| **지도** | 360–1390 | **1030** | **71.5%** |
| **우 도구 레일** | 1390–1435 | **45** | 3% |
| 하단 상태 밴드 | 0–1440 | 1440 | h **32** |

→ Esri `Outage Center`(좌 344 / 지도 830 / 우 235)와 **같은 3단**이고,
Esri `Oregon`(지도 70%)과 **지도 비율이 거의 같다**(71.5%). 우리 권고 그리드(57.6%)보다 지도가 더 크다.

**⑤/⑧ 좌 패널의 구조 — 우리 좌 큐 컬럼과 1:1 대응.**
`주제도 ⓘ` 제목(20px) + `✕` → **2탭 50:50**(`검색어로 찾기` / `분류별 찾기`, Copernicus의 `VISUALISE`/`SEARCH`와
같은 규격) → **총계 줄** `총 402 건` + 우측 `모두열기 ✛`(Esri의 `1-60 of 8,147` + `Relevance ▾`와 같은 자리) →
**아코디언 행 h=41**(`3D지도` `지도` `새만금개발사업` `국토관리/지역개발` `농림/해양/수산` `도로/교통/물류`
`문화/체육/관광` `사회복지` `산업/중소기업` `일반공공행정` `공공안전` `환경/자연/기후` `기타` = 13행) +
행 우측 `✛` 확장. 900px에 **13행이 정확히 들어간다.**

**⑦ 우 도구 레일 45px — 아이콘 + 한글 2글자 라벨.**
`3D지도 / 화질 / 거리 / 면적 / 높이 / KML / 둘러보기 / 초기화 / 측정`. Copernicus의 40px 도구 레일과 같은 문법인데
**한글 라벨을 아이콘 아래 10px로 붙였다** — 한국어에서 아이콘만으로는 의미가 안 서기 때문이다.
**우리 좌 레일(76px, 아이콘 24 + 라벨 11px 2줄)이 같은 판단을 이미 하고 있다.**

**⑨ 하단 상태 밴드 h=32 — 세 가지를 한 줄에.**
좌: 기관 로고 2개(`국토교통부` `브이월드`), 중: **빨간 고지 문구**
`※ 연속지적도 등 모든 주제도와 3D 가시화 및 분석결과는 참고용으로만 사용하시기 바랍니다.`,
우: **카메라 상태 판독** `내려다보는 높이 1700.7 km · 각도 90°`.
→ 우리 C11(지도 하단 크레딧 스트립)과 C16(프로비넌스)이 국내에서 어떻게 쓰이는지의 실물.
**빨간 고지 문구는 국내 공공 지오 서비스의 사실상 의무**이므로, 우리도 이 자리를 비워 두면 안 된다.

**⑩ 색.** GNB 남색, 액센트 파랑, 고지 문구만 빨강. 지도는 위성영상(컬러). **UI는 사실상 무채**다.

**⑪ 첫 900px.** 위성영상 **71.5%**, 최대 폰트 20px. 큰 수는 없다(`총 402 건`이 14px).
→ 즉 **국내 실물은 "지도 큼 + 목록 촘촘 + 큰 수 없음"** 이다. 우리 권고안은 여기에
Esri 오리건의 **박스 없는 52px 큰 수**를 더한 것이고, 발주자의 *"첫 화면이니 잘 보이게"* 가
그 추가분을 정당화한다.
