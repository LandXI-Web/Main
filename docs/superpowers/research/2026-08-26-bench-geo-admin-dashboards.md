## 0. 수집 방법과 접근 한계 (정직 기록)

캡처는 전부 이 저장소에서 **Playwright(Chromium, headed)** 로 직접 찍었다. 두 해상도(1440×900 / 1920×1080)를
쓰고, 쿠키 배너는 자동 제거했다. 각 캡처마다 `page.evaluate()` 로 **DOM 실측 JSON**(`shots/bench/dash/_measure-*.json`)
을 함께 남겼다 — 타입 스케일(사이즈/굵기/행간/자간/폰트패밀리 + 등장 횟수), 레일 폭, 콘텐츠 컬럼 x·폭,
그리드 `grid-template-columns`·`gap`, 행 높이 중앙값(→ 900px당 행 수), border-radius/box-shadow/border 사용 분포,
색 사용 빈도, 그리고 **첫 900px(above the fold)** 의 노드 수·최대 폰트·이미지 점유율.

# §1. 대상별 해부 (실측)

각 항목은 **① 캡처 · ② 그리드 실측 · ③ 타입 스케일 실측 · ④ 밀도 · ⑤ 상태 표기 문법 · ⑥ 수치/KPI 조판 ·
⑦ 지도의 위치와 크기 · ⑧ 목록·큐 조판 · ⑨ 빈 상태/대기 상태 · ⑩ 색 규율 · ⑪ 첫 900px(첫인상) ·
⑫ 훌륭한 점 / 우리가 가져올 것** 순서다. 숫자는 별도 표기가 없으면 **1440×900 기준 실측 px**이다.

## 1.1 NASA Earthdata Search — `search.earthdata.nasa.gov` 〔L〕

**캡처** `earthdata-1.jpg` `earthdata-2.jpg` `earthdata-3.jpg` `earthdata-hd-4.jpg`

지오 도메인에서 **"좌측 필터 레일 + 가운데 결과 목록 + 우측 지도"** 3단을 가장 성숙하게 조판한 실물이다.
로그인 없이 전 기능이 열리고, 데이터가 진짜다(11,131개 컬렉션).

**② 그리드.** 좌 필터 레일 `0–327`(327px, 안쪽 패딩 16). 결과 목록 컬럼 `328–928`(**600px**).
지도 `928–1440`(**512px = 화면폭의 35.6%**, 높이 100%). 세로로는 상단 브랜드바 32px → 검색바 44px →
패싯 툴바 50px → 본문. 하단에 28px **프로비넌스 바**가 상주한다(`v26.1.9-2 · Search Time: 2.9s ·
NASA Official: Doug Newman · FOIA · NASA Privacy Policy`). 즉 화면의 위아래를 얇은 시스템 밴드가 물고,
가운데를 3단이 채운다. 컬럼 사이 거터는 **0**이고 대신 **1px 헤어라인**이 경계다 — 카드 사이 여백으로
구획하지 않는다.

**③ 타입.** 결과 제목 15px/600, 메타 라인 13px/400 회색, 설명 13px/400, 프로비넌스 라인 11px/400,
목록 헤더 `11,131 Matching Collections` 17px/600, 툴바 12px/400. **네 단계뿐**이고 굵기는 400·600 둘뿐이다.

**④ 밀도.** 결과 행 1개 높이 ≈ **135px**(제목 1–2줄 + 메타 1줄 + 설명 2줄 + 프로비넌스 1줄 + 썸네일 68×64).
900px 안에 약 **5.5행**. 좌 레일 아코디언 행은 40px → 900px에 약 **20행**. 즉 같은 화면에서
**"20행짜리 얇은 목록"과 "5.5행짜리 두꺼운 목록"을 동시에** 쓴다. 밀도를 한 값으로 통일하지 않는 것이 요령이다.

**⑤ 상태 표기.** 세 층으로 나뉜다.
(a) **무채 아웃라인 아이콘 줄** — 구름 사용 가능/불가, 지도 이미지 유무 등. 색을 쓰지 않는다.
(b) **알약 칩 1개** — `1 to 3 hours`(지연 시간). 회색 채움, 높이 20px, radius 10px, 12px/400.
(c) **밑줄 링크** — `GEOSS`(출처 계보). 칩을 남발하지 않고 **행당 컬러 칩은 0–1개**로 묶는다.

**⑥ 수치.** KPI 카드가 **없다.** 큰 수(11,131)는 목록 헤더의 한 줄로 존재하고, 행마다의 수
(`4,058 Granules`)는 메타 라인의 첫 토큰이다. **숫자를 위한 별도 박스를 만들지 않는다**는 것이 이 화면의 결론이다.

**⑦ 지도.** 우측 512px. 지도는 목록의 **결과가 아니라 짝**이다 — 목록 행에 마우스를 올리면 지도에 풋프린트가 뜬다.
지도가 화면을 지배하지 않고, 폭의 1/3만 갖는다. 우리 요구("대시보드는 축소하되 첫 화면이니 잘 보이게")와
직접 맞물리는 비율이다.

**⑧ 목록.** 행 = `제목 / 메타 / 설명 / 프로비넌스 / 썸네일 / (i)정보 + (+)담기` 6요소. 우측 하단에 액션 2개
(원형 `i`, 원형 `+`)가 **항상 보인다**(호버에서 나타나지 않는다). 우리 B13의 `검토` 버튼 자리와 같은 문법이다.

**⑨ 빈 상태.** 썸네일이 없으면 68×64 무채 박스에 9px `No image available`을 중앙 정렬한다. **자리를 비우지 않고,
없다고 말한다.** 우리 §5-10(결손은 무채 + 이유 한 줄)과 같은 원리를 실제로 구현한 사례다.

**⑩ 색.** 배경 흰색, 텍스트 `#2C2C2C`/`#5A5A5A`, 상단·하단 밴드 `#111`, **액센트는 빨강 하나**(검색 버튼)
+ 파랑(링크). 지도는 컬러지만 UI는 사실상 무채다.

**⑪ 첫 900px.** 이미지(지도 타일)가 첫 화면의 **약 36%**, 나머지는 목록. 최대 폰트 17px. 즉 **"큰 글자로 놀래키지
않고, 데이터 개수와 실제 목록으로 첫인상을 만든다."** 첫 화면에서 사용자가 얻는 정보량이 가장 큰 축에 든다.

**⑫ 훌륭한 점.** 밀도를 두 종류로 쓴 것, 컬러 칩을 행당 1개로 제한한 것, 없는 것을 말하는 썸네일,
하단 프로비넌스 밴드(버전·검색 소요시간·담당자 실명). **우리가 가져올 것**: 3단 그리드 비율(327 / 600 / 512),
행의 6요소 구성, 결손 썸네일 문구, 하단 프로비넌스 밴드.

## 1.2 Esri ArcGIS Online — 콘텐츠 브라우저 / 검색 〔L, DOM 실측〕

**캡처** `arcgis-gallery-1.jpg` `-2` `-3` `arcgis-gallery-hd-4.jpg` · 실측 `_measure-arcgis-gallery.json`

이번 조사에서 **우리 취향 프로필 §4와 가장 정확히 겹치는 실물**이다. 이유는 하나 —
**border-radius가 페이지 전체에 0개, box-shadow는 헤어라인 대용 2개뿐**이기 때문이다.

**② 그리드(DOM 실측).** 좌 필터 레일 `arcgis-item-browser-filters` **w=261**(내부 콘텐츠 237, 좌우 12씩).
레일 시작 x=24. 콘텐츠 컬럼 `arcgis-item-browser-content` **x=316, w=1104**. 따라서
**거터 = 316 − (24+261) = 31px**, 우측 마진 20px. 상단 검색 인풋은 `x=24, w=1416, h=48`로
**두 컬럼을 가로질러 폭 전체를 먹는다** — 검색이 이 화면의 주인공임을 조판으로 선언한다.

**③ 타입(DOM 실측).** 실제 사용된 조합은 **네 개뿐**이다.

| 크기/굵기/행간 | 등장 수 | 쓰임 |
|---|---|---|
| `12px / 400 / lh16` | **120회** | 메타·칩 라벨·`View details` |
| `14px / 400 / lh16` | **82회** | 본문·필터 항목·설명 |
| `16px / 400 / lh20~24` | 9회 | 탭(`Content`/`Groups`), 헤더 메뉴 |
| `20px / 400 / lh30` | 1회 | 페이지 제목 `Search` |

폰트는 Avenir Next 단일, **굵기는 400 하나뿐이다.** 위계를 굵기가 아니라 **크기와 색으로** 만든다
(`#141414` 528회 / `#595959` 25회 / `#6B6B6B` 8회). 우리 §4의 "SUIT Medium 단일 굵기" 규칙과 정확히 같은 전략이다.

**④ 밀도.** 행 높이 중앙값 **56px → 900px당 16.1행**. 단 이 56px는 필터 트리 행이고, **아이템 카드는 158–190px**
(제목 20px + 설명 1–2줄 + 메타/칩 라인 + 1px 구분선 + 소유자 스트립). 900px에 **약 4.7개**. Earthdata와 같은
"두 밀도 병용" 구조다.

**⑤ 상태 표기 — 이번 조사에서 본 최고의 칩 문법.** 아이템 카드 메타 라인은
`[타입 아이콘] Feature layer │ Item updated: Sep 23, 2025 │ ✓Authoritative │ ⓐLiving Atlas │ ⛨Subscriber`
순서다. 규칙이 뚜렷하다.
1. **칩은 사실(fact)만 담는다** — 상태가 아니라 *속성*이다. `Authoritative`(검증됨), `Retired item type`(폐기 유형),
   `Has replacement`(대체본 있음), `OAuth 2.0 Credentials`.
2. **칩마다 14px 아이콘 + 12px 라벨**, 높이 24px, 좌우 패딩 10, 알약형. 배경은 **파스텔 채움**(연녹/연청/연보라),
   테두리 없음, 그림자 없음.
3. **부정적 사실도 같은 무게로 쓴다** — `Retired item type`을 빨강 경고로 만들지 않는다. 경고색을 아끼는 것이
   신뢰를 만든다.
4. 카드당 칩은 **최대 4개**, 그 이상은 잘라낸다.

**⑥ 수치.** KPI 카드가 **없다.** 총계는 `1-60 of 8,147` 한 줄(12px)로 목록 상단 좌측에 붙고, 우측에는
정렬 드롭다운(`Relevance`)이 온다. 숫자를 위해 면적을 쓰지 않는다.

**⑦ 지도.** 이 화면에는 **지도가 없다.** 대신 각 행 우측에 **128×72 썸네일**로 지도를 축소해 둔다 —
"지도는 목록의 삽화"라는 결정. 지도 크기 0인 대안(§2-C)의 실물 근거다.

**⑧ 목록.** 카드 하나 = `제목(20px) / 설명(14px, 최대 2줄) / 메타+칩 라인 / ─1px─ / 소유자 스트립`.
소유자 스트립은 좌측에 24px 아바타 + 소유자명(14px), 우측에 `Open in Map Viewer` + `⋯`. **행의 액션을
행 안쪽 아래에 따로 띠로 분리**한 것이 특징 — 우리 B13의 `검토` 버튼을 여기에 두면 그대로 맞는다.

**⑨ 빈 상태.** 썸네일이 없는 아이템은 회색 톤 아이콘 플레이스홀더로 채우고, 검색 0건일 때는
"필터를 조정해 보라"는 문장 + 적용된 필터 칩을 나열한다(제거 가능). §2-D05(dim-not-delete)의 온건판.

**⑩ 색.** 배경 `#FFFFFF` + 섹션 구분 `#F7F7F7`. **radius 0 · shadow 0**(실측: `radii` 목록이 비었고,
shadow는 `rgb(224,224,224) 0 1px 0`과 `1px 0 0 inset` 둘뿐 = 전부 헤어라인 대용). 테두리 `1px #D4D4D4`.
액센트는 `#007AC2` 하나.

**⑪ 첫 900px.** 이미지 점유율 **0%**, 최대 폰트 **20px**, 텍스트 노드 94개. 첫인상이 **완전히 텍스트**다.
정보 밀도로 승부하는 극단. 우리 클라이언트 취향(§3-5 "관리자 SaaS 크롬이 첫인상인 화면" 거부)과는
정면으로 충돌하는 지점이므로 **이 화면의 조판은 가져오되 첫 밴드는 반드시 다르게 처리해야 한다**(§3에서 다룸).

**⑫ 훌륭한 점.** 라운드 0 · 그림자 0 · 단일 굵기 · 헤어라인 구획 · 칩은 사실만. **우리가 가져올 것**:
261 / 31 / 1104 그리드, 12·14·16·20 4단 타입, 칩 규격(h24 · 12px 라벨 · 파스텔 채움 · 카드당 ≤4),
행 하단 액션 스트립, 총계를 `1-60 of 8,147` 한 줄로 쓰는 어법.

## 1.3 kepler.gl — 사이드 패널 〔L, DOM 실측〕

**캡처** `keplergl-1.jpg` `keplergl-data-1.jpg` `-2` `-3` `keplergl-data-hd-4.jpg` · 실측 `_measure-keplergl-data.json`

**② 그리드.** `side-panel--container` **w=324**, 그 안의 `side-bar` **w=292**(상하 12씩 인셋 → h=876),
다시 `side-panel__content__inner` **w=260**. 즉 **324 → 292 → 260**의 3중 인셋이고, 실제 콘텐츠 폭은 260px다.
패널은 화면에 붙지 않고 **16px 떠 있다**. 지도는 `1440×900 = 100%`로 패널 **밑을 지나간다**(패널이 지도를 자르지 않는다).
하단 시간 위젯은 `x≈380, w≈1020, h≈242`, 우측 아이콘 레일은 `x=1396, w=32, h=420`.

**③ 타입.** `11px/500/ls0.3px`(버튼·라벨) · `11px/400/ls1.25px`(섹션 라벨 `Datasets`) ·
`20px/400/ls1.25px`(`Layers`) · `11px/400`(`54,936 rows`) · `14px/500`(`01/05/1991`) · 차트 축은 `10px/400`.
**본문 폰트가 11px**다. 지도 위 패널이므로 극단적으로 작게 간다.

**④ 밀도.** 행 높이 중앙값 **38px → 900px당 23.7행**. 레이어 카드는 62px.

**⑤ 상태 표기.** 색 점(dot)과 칩이 거의 없다. 대신 **레이어 카드 좌측 3px 컬러 바**(레이어 색)와
**눈 아이콘(표시/숨김)** 으로 상태를 말한다. 필터가 걸리면 하단 히스토그램의 **선택 구간만 시안으로 켜지고
나머지는 회색으로 남는다** — 삭제가 아니라 감쇠(우리 D05와 동일).

**⑥ 수치.** `54,936 rows` 11px 한 줄. **거대 숫자 없음.** 대신 시간 범위를 `01/05/1991 — 03/30/2011`
14px/500로 지도 한가운데 떠 있는 알약에 띄운다 — **지금 보고 있는 범위**를 화면 중앙에 말한다.

**⑦ 지도.** 100%. 패널은 지도 위에 뜬 유리다(`#242730`, 실측 `rgb(36,39,48)`). 이 값은 우리 취향 프로필
§2.1에 이미 "유일하게 허용되는 유리"로 적혀 있는 바로 그 색이다 — **출처가 kepler.gl임이 실측으로 확인됐다.**

**⑨ 빈 상태.** 데이터 0건일 때 `Datasets` 섹션은 사라지지 않고 `+ Add Data` 버튼만 남는다(캡처 `keplergl-1.jpg`).
**빈 상태 = 다음 행동 버튼 하나.**

**⑩ 색.** radius `2px`(11회) 지배, 4px·9px 소수. shadow `0 6px 12px rgba(0,0,0,.16)`(11회).
액센트는 초록 `#0F9668`(Add Layer) / 파랑 `#2E7CF6` / 시안 `#1FBAD6`. UI 무채는 `#6A7485`·`#A0A7B4`.
