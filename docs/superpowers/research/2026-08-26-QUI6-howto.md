### 5단계 — 스크럽용 인코딩 (일반 웹 인코딩으로 하면 100% 실패)
13. 핵심: **일반 웹 인코딩은 키프레임이 2~5초에 하나**. 스크럽은 임의 지점 seek이라 디코더가 직전 키프레임부터 걸어와야 하고, 그래서 "재생은 완벽한데 스크럽은 진흙"이 된다. **GOP를 조밀하게** 만드는 것이 이 기법의 전부다.
```bash
# 데스크톱 마스터: 1080p, GOP 8, crf 20 / 모바일: 720p, GOP 4, crf 24
ffmpeg -y -i in.mp4 -an \
  -vf "scale=-2:1080:flags=lanczos,format=yuv420p" \
  -c:v libx264 -profile:v high -preset slow -crf 20 \
  -g 8 -keyint_min 8 -sc_threshold 0 \
  -movflags +faststart out.mp4
```
14. 오디오는 **제거**(스크럽 전용이라 죽은 용량 + autoplay 정책 위험).
15. **포스터는 그 클립의 첫 프레임**을 ffmpeg로 뽑는다(따로 생성한 비슷한 그림 금지 — 영상이 페인트되는 순간 점프한다).
```bash
ffmpeg -sseof -0.15 -i legN.mp4 -frames:v 1 -q:v 2 chainN.png   # 다음 leg의 시작 이미지
ffmpeg -i legN.mp4 -frames:v 1 -q:v 3 pN.webp                    # 이 leg의 포스터
```
16. 용량 기대치: 5초 1080p ≈ **3MB**, 720p 모바일 ≈ 1.5MB. 그레인이 많은 월드는 약 2배(→ `-crf 22~23`).

### 6단계 — 페이지 조립 (worldflight 마크업)
17. **문서 흐름(document flow)에 있는 것은 빈 spacer 하나뿐.** 스테이지는 `position: fixed` **단 하나**, 모든 leg가 처음부터 끝까지 **동시에 마운트된 채** 있는다. 섹션도, 핀도, 언핀도 없다 → **이음매가 생길 경계 자체가 없다.**
```html
<div data-sc-mode="worldflight" data-sc-seam="0.16">
  <div data-sc-world>
    <div data-sc-segment data-sc-w="0.95" data-sc-linger="0.3" data-sc-waypoint="Surface">
      <img class="sc-world__poster" src="assets/p1.webp" alt="" decoding="async">
      <video data-sc-src="assets/leg1.mp4" data-sc-src-mobile="assets/leg1-m.mp4"></video>
    </div>
    <!-- leg를 비행 순서대로, 있는 만큼 -->
  </div>
  <div data-sc-world-copy>
    <div class="sc-world__scrim sc-scrim sc-scrim--band"></div>
    <div class="sc-copy sc-copy--lead"  data-sc-copy data-sc-window="hero">…</div>
    <div class="sc-copy sc-copy--trail" data-sc-copy data-sc-window="0.38 0.66">…</div>
    <div class="sc-copy sc-copy--lead"  data-sc-copy data-sc-window="finale">…</div>
  </div>
  <div data-sc-spacer aria-hidden="true"></div>
</div>
```
18. spacer 높이 = **(leg 가중치 총합 + 1) × innerHeight** 픽셀. `+1`은 여백이 아니라 **마지막 클립의 마지막 1초에 독자가 멈춰 설 자리**다.
19. **크로스페이드는 반드시 한쪽만(one-sided).** 씸 구간에서 들어오는 leg가 0→1로 올라오는 동안 나가는 leg는 **밑에서 풀 강도로 버티고**, 완전히 덮인 뒤에야 0으로 떨어진다. 양쪽을 동시에 페이드하면 매 이음매마다 페이지 배경이 비쳐 **번쩍임**이 된다(그게 자연스러운 구현이라 다들 이걸로 망한다). z-index는 현재 leg 120, 나머지 `100 + opacity×10`.
20. **`src`를 절대 교체하지 않는다.** src 교체 = 검은 프레임 = 이 모드가 없애려던 바로 그 컷.
21. 카피 레이어의 유일한 변형은 `translateY`이고 **전 구간 합계 4vh 상한**(+2vh → −2vh). 그 이상이면 "다른 속도로 스크롤하는 두 번째 페이지"로 읽혀서 싸구려가 된다. opacity 0.5 넘을 때만 포인터 이벤트 반환.
22. **route rail은 엔진이 안 그려준다.** 엔진은 `--sc-seg`(현재 leg 인덱스)/`--sc-segp`(진행도) CSS 변수와 `sc:waypoint` 이벤트만 발행. 좌측 KYOTO/PATAGONIA/ERG CHEBBI 점등은 페이지가 직접 구현:
```js
addEventListener('sc:waypoint', (e) => {
  document.querySelectorAll('.rail__leg').forEach((el) => {
    el.setAttribute('aria-current', String(+el.dataset.leg === e.detail.index));
  });
});
```
23. **로딩**: leg는 `±1.6vh` 안에 들어와야 fetch. 전부 미리 받으면 첫 프레임 전에 수십 MB. 아직 실제 프레임이 안 그려졌으면 포스터가 `scale(1.03 + local × 0.14)`로 **밀고 들어가며** 대신 움직인다(완전히 정지한 스틸은 즉시 "플레이스홀더"로 들킨다).
24. **reduced-motion에서는 클립을 아예 fetch하지 않는다.** 포스터들이 같은 스크롤 위치에서 같은 씸으로 디졸브되고 카피 윈도우도 그대로 열리고 닫혀서 **스토리는 전부 읽힌다.**

### 7단계 — 스크럽 재생 로직 (이게 "부드러움"의 정체)
25. **스크롤은 `currentTime`을 절대 직접 쓰지 않는다.** 목표값만 쓰고, 별도 rAF 루프가 프레임당 고정 비율로 걸어간다. 휠 이벤트는 등간격으로 안 오기 때문에 1:1로 쓰면 그 틈이 전부 스터터로 재현된다.
    - **lerp 0.18** 기본, `data-sc-lerp`로 오버라이드. **worldflight는 0.12가 더 낫다**(leg와 씸이 많아 감쇠가 더 필요). reduced-motion에서는 1.0(무보정).
    - **deadband** 데스크톱 8ms / 모바일 20ms 미만의 쓰기는 무시(seek 비용만 들고 보이는 게 없음).
    - **seek coalescing**: 디코더가 직전 seek을 처리 중이면 새 seek을 큐에 넣지 않는다(빠른 플릭에서 seek이 쌓여 클립이 얼어붙음).
26. **페이스가 부드러움보다 중요하다.** `rate = weight / clip_seconds`를 **전 leg에서 몇 % 이내로 유지.** ORRERY 초안은 10 leg에서 36% 편차였고 클라이언트 표현이 "not smooth"였다. **6% 편차로 균일화하니 같은 소재가 하나의 연속 이동으로 읽혔다.**
27. 그리고 **생각보다 느리게.** 필름 1초당 **0.21–0.22vh**가 날아다니는 월드의 하한. 0.14–0.19는 눈에 띄게 빠르다. `data-sc-seam`도 0.12 → **0.16**으로 넓힌다.
28. 가중치를 바꾸면 모든 leg 경계가 이동하므로 **`data-sc-window`를 전부 재계산하고 화면에서 다시 확인.** 카피 윈도우는 숫자가 아니라 **필름의 한 프레임**에 맞추는 것이다.

### 8단계 — 자체 검증 (영상 8:15–9:11의 "Zooming into key frames")
29. 로컬 서버 띄우고 헤드리스 크롬으로 **자기 스크롤을 스크린샷**한 뒤 **그 이미지를 다시 읽는다.**
```bash
node scripts/serve.mjs --root builds/<name> --port 4513
node scripts/shoot.mjs --url http://localhost:4513 --out lab/<name>-shots --per-act 8
node scripts/shoot.mjs --url http://localhost:4513 --out lab/<name>-reduced --reduced-motion
node scripts/worldflight-assert.mjs --url http://localhost:4513
```
30. 검출 항목: **dead scroll**(0.12vh 이상 떨어진 두 샘플 사이에 `currentTime` 변화도, 크로스페이드도, 카피 opacity 변화도 없음) / **끝내 full opacity에 도달 못하는 leg**(영원히 디졸브만 보임) / **포스터에 갇힌 leg**(클립이 로드/디코드 안 됨 — 다른 모든 검사를 통과한다, 포스터는 일시정지된 영상과 똑같아 보이니까) / **행별 대비**(합성된 페이지 위에서, 각 줄이 놓이는 최악의 프레임 기준으로).
31. `worldflight-assert.mjs`가 기계적으로 확인: spacer 높이, fixed 스테이지, 문서 흐름 비어있음, lerp 수렴/오버슈트 없음, 씸 단조성, 카피 transform 상한, reduced-motion 계약.
32. **영상에서 실제로 잡아낸 결함(8:50 화면 그대로)**:
    > *"Found real defects. Fixing: a `white-space: nowrap` that broke prose, a transparent margin rail that let the pan run through it, an empty first screen on the peak, and dead space after the cover."*

### 9단계 — 흔한 침묵 실패 하나
33. `layout()`이 spacer 높이를 `(total + 1) * innerHeight`로 **마운트 시 1회** 쓴다. 그 순간 `innerHeight`가 0이면 spacer가 **0px**이 되고 스크롤 트랙이 없어서 비행이 영영 진행되지 않는다. **콘솔에 아무것도 안 뜨고 성공처럼 보인다.** 임베드 프리뷰/이른 로드에서 실제로 발생.
```js
function relayout() { dispatchEvent(new Event('resize')); }
addEventListener('load', relayout);
if (document.fonts && document.fonts.ready) document.fonts.ready.then(relayout);
// 확인 한 줄:
document.documentElement.scrollHeight   // ≈ (가중치합 + 1) * innerHeight 여야 함
```

## E. 그대로 가져올 것 vs 우리 제약에 맞게 바꿀 것

### E-1. 그대로 가져올 수 있는 것 (엔진 없이도 성립)

1. **worldflight의 구조적 발명 자체.** "고정 스테이지 1개 + 문서 흐름엔 spacer만 + 전 leg 상시 마운트 + 한쪽만 크로스페이드." 이건 라이브러리가 아니라 **레이아웃 계약**이라 바닐라 JS로 100줄이면 된다. 번들러 불필요.
2. **스크럽 재생 로직 3종**: lerp 0.12–0.18, deadband 8/20ms, seek coalescing. 우리 `landxi/proto/spikes/scrollcam/scrollcam.js`에 그대로 이식 가능.
3. **`rate = weight / clip_seconds` 균일화**와 **0.21–0.22vh/필름초** 하한. 우리 필름 히어로(`tools/film/`, 23초 궤도→남원→여수)가 지금 정확히 이 함정에 있다 — 구간별 속도가 다르면 "안 부드럽다"는 피드백이 나온다.
4. **인코딩 사양**: `-g 8 / -keyint_min 8 / -sc_threshold 0 / -movflags +faststart / -an`. 우리 ffmpeg는 gyan full build 9.0이라 그대로 실행된다(확인함).
5. **씸 프레임을 인코딩 산출물에서 뽑기**(`-sseof -0.15`). 원본 렌더에서 뽑으면 1프레임 팝.
6. **포스터 = 클립 자신의 첫 프레임**, WebP.
7. **reduced-motion에서 클립을 fetch하지 않고 포스터만으로 같은 스토리를 읽게 하기.** 정적 사이트에서 특히 저렴하고 접근성 점수를 그냥 얻는다.
8. **자체 검증 루프**(스크린샷 → 그 이미지를 다시 읽기 → 결함 수정). 우리는 이미 `tools/_shots.mjs`, `tools/_smoke.mjs`가 있으니 **dead scroll / poster-stuck / 행별 대비** 세 검사만 추가하면 된다.
9. **인터뷰 8문항 + BRIEF.md + feeling curve + peak.** 도구와 무관하게 그대로 쓸 수 있는 프로세스.
10. **카피 transform 4vh 상한**, **plateau 윈도우**(순수 삼각형은 opacity 1을 한 순간만 스쳐서 모든 헤드라인이 살짝 흐려 보인다).
11. **카피 앵커를 인접 반복 없이 순환**(ORRERY: BL→BR→C→BR→BL→TL→ML→TL). 같은 자리에 계속 글이 뜨면 영상이 아니라 슬라이드로 읽힌다.
12. **"실제 값에 고정된 아날로그 계기" 아이디어.** ORRERY의 방위 다이얼은 목적지의 **실제 경도**에 핍이 박혀 있어서 비행이 도착할 때 핍이 바늘 아래로 들어온다. 우리는 **진짜 좌표를 갖고 있으므로 이걸 꾸며낼 필요조차 없다** — 남원(127.4°E) / 여수(127.7°E) / 제주(126.5°E)를 실제 경도로 찍으면 된다. 다만 세 곳이 1.2° 안에 모여 있어 회전 다이얼로는 구분이 안 되므로, **위도 축(35.4 / 34.7 / 33.5°N)이나 축척 축**으로 바꾸는 편이 맞다.
13. **"the elsewhere field" 발상의 이식.** "선택하지 않은 것들이 화면에 계속 있고, 가리키면 **멈춘다**(색이 바뀌는 게 아니라)"는 규칙. 우리 버전 = **아직 촬영/탐지되지 않은 필지**를 배경에 상주시키고, 포인터를 올리면 그것만 정지하며 지번과 한 줄이 도착. 단 `EXAMPLES.md`가 이 무브를 `orrery`가 **선점**했다고 명시하므로, 그대로가 아니라 **정지 대신 다른 반응**으로 바꿔야 예의에 맞다.

### E-3. 즉시 적용 가능한 3가지 (우선순위)

1. **`rate = weight / clip_seconds` 감사.** 현재 필름 히어로 각 구간의 이 값을 재서 **0.212–0.225 vh/필름초** 대역에, **편차 6% 이내**로 맞춘다. 5초 구간 = 1.08vh, 10초 클라이맥스 = 2.25vh가 검증된 배분이다. 36% → 6%가 "not smooth"를 실제로 고쳤다는 근거가 있다. `data-sc-seam` 0.16, `data-sc-lerp` 0.12를 함께 적용.
2. **인코딩을 `-g 8`로 재실행.** 지금 클립이 일반 GOP면 스크럽 반응이 무조건 늦다. 파일이 커지는 건 의도된 거래다.
3. **한쪽만 크로스페이드 + 상시 마운트**로 구간 전환 재구성. 지금 구조가 src 교체나 양방향 페이드면 이음매마다 번쩍인다.
