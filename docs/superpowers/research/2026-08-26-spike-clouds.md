# SPIKE — 움직이는 구름 & 대기 (지구 안에서 구름이 움직인다)

- 일자: 2026-08-26
- 브랜치: `plan1-foundation`
- 비교 페이지: `landxi/proto/spikes/clouds/index.html` (정적 · CDN · `window.__spike.seek(p)`)
- 스크린샷: `shots/spikes/clouds/` (`t{1..4}-p{...}.png`, `film/`)
- 측정 GPU: **NVIDIA RTX 4090 / ANGLE D3D11**, 1440×900 @ DPR 1.5 (실렌더 2160×1350)

> 한 줄 결론: **고도대별 하이브리드**가 답이다. 250km 위는 ① 구름 구, 170km~8km 는
> ② 빌보드 데크, 지상 8km 아래에서 카메라가 구름 *속*에 머무는 컷에서만 ③ 볼류메트릭.
> ④ 실사 GIBS 는 "오늘의 하늘"이라는 서사가 필요할 때만 ①을 대체한다.

## 1. 무엇을 만들었나

한 페이지에서 같은 하강(`seek(p)`, p 0→1)을 네 기법으로 갈아끼우며 본다.
배경은 고도로 갈린다 — **>500km: three.js EOX 글로브**, **<380km: MapLibre 위성 지도**.
크로스페이드 기준을 `p` 가 아니라 **고도(km)** 로 잡은 것이 중요하다. 그래야 스크럽과
필름 타임라인이 같은 규칙을 공유한다.

### 고도 곡선 (`altitudeKm(p)`)

| p | 0.00 | 0.10 | 0.22 | 0.28 | 0.30 | 0.32 | 0.60 | 1.00 |
|---|---|---|---|---|---|---|---|---|
| 고도 | 40,800 km | 6,000 km | 600 km | 27.8 km | 10 km | 9.1 km | 2.4 km | 350 m |

세 구간 지수 보간(`BANDS = [[0,40800],[0.22,600],[0.30,10],[1,0.35]]`).
`p=0.30` 이 대류권계면이고, 구름 데크 관통은 `p 0.30–0.45` 사이에서 일어난다.

### 공통 대기 요소 (기법과 무관하게 항상 켜짐)

- **프레넬 대기림** — 뒷면을 그린 `R×1.052` 구. `pow(1-|N·V|, 3.1)`, 레일리 근사색
  `mix(#3D78EB, #D9DBFF, (N·L)²)` + 태양 쪽 `pow(N·L,6)×0.55` 의 따뜻한 가산.
- **태양** — SunCalc `getPosition(WHEN, lat, lon)`. 방위각(남 기준)을 앵커 로컬
  `(east, up, -north)` 로 옮겨 월드 벡터로 만든다. HUD 슬라이더로 4–20시 조절 가능.
- **지평선 헤이즈** — 화면 위쪽으로 갈수록 짙어지는 `pow(h,1.7)` 그라디언트.
  고도 60km→3km 구간에서 차오르고, 태양 고도가 낮을수록 따뜻한 쪽(#FADCBD)으로 간다.

## 2. 네 기법

### ① 구름 구 (cloud sphere) — `t1-sphere.js`

지구보다 살짝 큰 구(`R×1.008`)에 등장방형 구름맵을 입히고 천천히 자전. 지표 바로 위
`R×1.0012` 에 **그림자 구**를 한 겹 더 깔고 UV 를 태양 반대로 밀어 구름 그림자를 만든다.

- 알파는 그레이스케일 밀도에서 `clamp((d-0.20)×1.55)` 로 뽑고 smoothstep.
- 시선각이 얕을수록 광학두께가 길어지는 것을 `rim = 1 + 1.9·pow(1-|N·V|, 2.2)` 로 근사.
- 전방산란(실버라이닝) `pow(clamp(V·-L),6)×0.55`.
- 자전 0.0035 회전/초 ≈ 0.21 회전/분 (지구 자전 ×300 과장 — 5초 레그에서 눈에 보이려면 필요).

**평가.** 궤도 프레임의 완성도는 네 기법 중 압도적이다(`shots/spikes/clouds/film/t2-0.png`).
지구가 "한 알"로 읽히는 순간엔 이것 말고 대안이 없다. 대신 셸이 실질 510km 고도라
**250km 아래로 내려가면 구가 카메라 위로 사라진다.** 셸을 실제 12km(`R×1.00188`)로
낮춰도 8k 텍스처가 4.9km/px 라 27km 상공에서 완전히 뭉갠다 — 고도 하한은 텍스처
해상도가 정한다. 궤도 전용으로 못 박는 게 맞다.

### ② 빌보드 데크 — `t2-decks.js` ★ 돌파 구간의 주력

실제 고도의 수평 평면 4장(10.6 / 8.0 / 5.4 / 1.7 km)을 앵커 로컬에 깔고 카메라가
관통한다. 시차는 원근에서 공짜로 나온다.

이 기법에서 **결과를 갈랐던 두 가지**:

1. **`tileKm` — 텍스처 한 장이 덮는 지상 거리.** 처음엔 820km 평면에 repeat 3.4 를
   줘서 한 타일이 241km 를 덮었다. 9km 상공에서 보이는 지상 폭은 8.8km — 타일의
   1/27 이라 화면이 그냥 회색 얼룩이 됐다. `tileKm` 을 **70/34/16/6.5 km** 로 잡으니
   (2048px 기준 34/17/8/3 m/px) 비로소 구름 알갱이가 생겼다.
2. **고도별 게이팅(`from`).** 네 장을 늘 켜두면 스택 커버리지가 99% 가 되어
   불투명한 회색 안개가 된다. 각 데크는 `from`(70/26/15/6.5 km) 아래로 들어와야
   나타난다: `far = 1 - smoothstep(alt, from, from×2.4)`.

그리고 초기에 실제 있었던 버그: 셰이딩의 `N·L` 을 **월드 Y축**(자전축)으로 재고 있었다.
북위 35.5°에서는 그 내적이 늘 0.2~0.4 라 한낮에도 구름이 회색으로 죽는다. 판의 실제
법선(`mat3(modelMatrix)*normal` = 앵커의 up)으로 바꾸자 흰 구름이 나왔다.

- 통과 직전 1.8km 안에서만 한가운데가 갈라진다(`uHole`).
- 관통 정점에 `haze.webp` 를 카메라 앞 스크린 스페이스 판으로 붙여 화이트아웃
  (additive, `flash × 0.88`).
- 지평선 쪽 `smoothstep(1.02, 0.34, rad)` 로 에어리얼 퍼스펙티브.

**평가.** 32km(`film/t2-0_5.png`)와 11km(`film/t2-0_6.png`) 프레임 모두 "실제로 구름
사이로 내려가는" 느낌이 난다. 구멍으로 지상이 비치고, 가장자리가 부드럽고, 흰색이
납작하지 않다. **비용은 사실상 0**(0.4–0.6ms). 지금 우리 자산(`cloud_*.webp`)을
그대로 쓴다는 점도 크다.
한계: 카메라와 데크가 1km 이내로 가까워지면 텍스처가 8배 이상 확대되어 뭉갠다.
그래서 화이트아웃이 필수다 — 흰 섬광이 그 순간을 덮는다.

### ③ 볼류메트릭 레이마치 — `t3-volumetric.js`

반해상도 RT 에 슬래브(1.6–8.2 km)를 24–48 스텝으로 행진. 밀도는 타일러블 3D 값노이즈
64³(R=저주파 형상, G=고주파 디테일)의 remap fbm, 조명은 6스텝 라이트마치
(Beer–Lambert) + powder + Henyey-Greenstein(g=0.62) 위상함수.

주의점 두 가지를 기록해 둔다.

- `RawShaderMaterial` + `GLSL3` 에서는 `position`/`uv` 어트리뷰트를 **직접 선언**해야
  한다(`ShaderMaterial` 과 달리 three.js 가 주입하지 않는다).
- 밀도 상수를 처음에 너무 낮게 잡아 화면에 아무것도 안 나왔다. `(n-(1-coverage))×3`
  → `×6.5`, 소광 `×0.5` → `×2.4`, 라이트마치 `×0.62` → `×1.5` 로 올려야 구름이 섰다.

**평가.** 물리적으로는 가장 정직하다 — 시선이 슬래브를 비스듬히 지날 때 두께가 길어지고,
태양 쪽 가장자리가 실제로 탄다. 하지만 **우리 서사에서 카메라가 구름 속에 머무는
시간이 1초도 안 된다.** 데크 대비 3–7배 비용(2.1–3.6ms)을 그 한 순간에 쓰는 셈이다.
저사양 티어에서는 반해상도로도 부담이다. **저고도 정지/체류 컷이 생기면 그때 켠다.**

### ④ 실사 NASA GIBS — `t4-gibs.js`

어제자 MODIS Terra / VIIRS SNPP CorrectedReflectance TrueColor.

- **글로브**: EPSG:4326 `250m` 타일매트릭스를 이어붙여 등장방형 캔버스로 굽고,
  트루컬러에서 "밝고(V↑) 채도 낮은(S↓)" 화소만 알파로 키잉해 구름만 남긴다.
- **지도**: EPSG:3857 `GoogleMapsCompatible_Level9` 를 MapLibre raster 로 반투명 적층
  (여기서는 알파 키잉이 불가 — 그냥 반투명이라 지상이 뿌옇게 죽는다).

**격자 함정(실측).** GIBS EPSG:4326 은 정사각 격자가 아니다. 레벨 z 의 타일 한 변은
`288/2^z` 도이고, 격자 밖 좌표는 404 가 아니라 **400** 을 돌려준다.

| z | 타일 크기 | 격자 | 결과 |
|---|---|---|---|
| 2 | 72° | 5×3 | 아래 한 줄이 잘림 (2560×1280 로 크롭 필요) |
| **3** | **36°** | **10×5** | **5120×2560 = 정확히 2:1 등장방형 ← 이걸 쓴다** |

처음에 8×4 로 가정해 절반이 400 을 맞았다. 굽고 나서 4096×2048 로 줄여 GPU 52MB→33MB.

**평가.** "지금 한반도 위에 있는 진짜 구름"이라는 서사적 가치가 유일하고 강하다.
다만 (a) 트루컬러 키잉은 눈·사막·갯벌을 구름으로 오인하고, (b) 하루 늦은 데이터이며,
(c) 저고도로 내려가면 250m/px 라 완전히 무너진다. **궤도 오프닝의 대안 카드**로 남긴다.

## 3. 성능 (frame cost, RTX 4090 · 2160×1350)

측정 방법을 먼저 적어 둔다. **이 환경에서 `requestAnimationFrame` 은 30Hz 로 묶이고,
ANGLE/D3D11 의 `gl.finish()` 는 실제로 동기화하지 않는다**(0.0ms 가 나온다).
그래서 `benchFrames(n)` 이 rAF 밖에서 n 프레임을 연속으로 그리고 매 프레임
**1픽셀 `readPixels`** 로 GPU 왕복을 강제한 뒤 중앙값/95분위를 낸다.

| 기법 | p=0.10 (6,000km) | p=0.28 (27.8km) | p=0.32 (9.1km) | p=0.60 (2.4km) |
|---|---|---|---|---|
| ① 구름 구 | **1.0 ms** | 0.5 ms† | 0.7 ms† | 0.5 ms† |
| ② 빌보드 데크 | 1.5 ms‡ | **0.5 ms** | **0.4 ms** | **0.6 ms** |
| ③ 볼류메트릭 | 0.3 ms† | **3.6 ms** | **2.1 ms** | **3.1 ms** |
| ④ 실사 GIBS | **0.9 ms** | 0.7 ms | 0.7 ms | 0.7 ms |

† 해당 고도에서 그 기법이 꺼져 있음(배경만의 비용) · ‡ 배경 글로브 + EOX 타일 업로드 포함
전체 표: `shots/spikes/clouds/fps.json`

**읽는 법.** 4090 에서 절대값은 의미가 적다. 중요한 건 **비율**이다 — 볼류메트릭은
데크의 **5–7배**다. 프레임 예산 16.7ms 를 기준으로 대략 20배 느린 내장 GPU 를 가정하면
데크는 8–12ms(여유 있음), 볼류메트릭은 42–72ms(60fps 불가, 반해상도로도 30fps 경계)다.
`dive.js` 의 `TIER` 판정을 그대로 재사용해 `full` 에서만 볼류메트릭을 켜야 한다.

## 6. 드롭인 모듈 스펙 — `clouds.js`

```js
import { createClouds } from './clouds.js';

// scene: THREE.Scene | map: maplibregl.Map (④ 실사 레이어를 얹을 때만 필요)
// anchor: THREE.Object3D — X=동 / Y=상 / Y=고도. 없으면 내부에서 만든다.
const clouds = createClouds(sceneOrMap, {
  tier: 'full',            // 'full' | 'lite' | 'still'  (dive.js detectTier() 결과를 그대로)
  anchor,                  // 대상 지점의 로컬 프레임
  lonlat: [127.35, 35.53],
  when: new Date(),        // SunCalc 기준 시각
  techniques: ['sphere', 'decks'],   // 기본값. tier==='full' 이면 'volumetric' 자동 추가
  cloudMap: './tex/earth_clouds_8k.jpg',
  deckTextures: '../assets/proto/clouds/',
  gibs: false,             // true 면 ④ 실사(글로브 구 + 지도 raster)로 ①을 대체
});

// 매 프레임 — 고도(km)와 dt(초)만 주면 된다. 기법 선택·페이드·화이트아웃은 내부에서.
clouds.update(altitudeKm, dt);

// 결정론적 렌더(필름 프레임)에서는 절대 시각을 준다 — 누적 dt 금지
clouds.updateAt(altitudeKm, seconds);

clouds.setSun(date);       // 시간대 변경
clouds.dispose();
```

**계약**

- `update(altKm, dt)` 는 **고도만** 받는다. `p`(스크롤 진행도)를 알 필요가 없어야
  스크럽 프로토와 필름 렌더가 같은 모듈을 쓴다.
- 기법 전환은 호출자가 하지 않는다. `altKm` 하나로 `sphere`(>250km) → `decks`(<170km)
  → `volumetric`(<8km, tier=full) 이 각자 페이드 인/아웃한다.
- 볼류메트릭은 반해상도 RT 를 쓰므로 `clouds.render(w, h)` 를 **본 렌더 직전**에
  불러야 한다. 나머지 기법은 씬 그래프에 붙어 있어 별도 호출이 없다.
- `tier: 'lite'` → 볼류메트릭 제외, 데크 4장 → 3장(1.7km 데크 생략), 구름 구 8k → 2k.
- `tier: 'still'` (prefers-reduced-motion) → 바람·자전 0, 화이트아웃 0.4 로 감쇠.

## 8. 남은 함정 메모

- `THREE.MathUtils.smoothstep(x, min, max)` 는 `min > max` 를 넘겨도 예외를 던지지 않고
  **역방향으로 동작**한다. 의도한 것이면 괜찮지만 오타면 조용히 1 이 나온다 — 실제로
  볼류메트릭 밀도 게이팅에서 이 실수를 했다.
- EOX z3 64타일을 한 번에 쏘면 몇 장이 떨어져 지구에 **검은 사각형**이 남는다.
  동시 8장 + 3회 재시도로 해결.
- Sentinel-2 cloudless 의 바다는 거의 검다. 그대로 두면 한낮인데 밤처럼 읽힌다.
  어두운 화소(`lum < 0.16`)를 심해 블루로 끌어올리고 `pow(c, 0.80)×1.18` 감마 리프트 +
  좁은 글린트(`pow(N·H, 900)×0.85`)를 넣었다. 이 세 줄이 "지구가 살아 있는 물체"로
  읽히게 하는 값싼 지점이다.
