### 0.2 가장 중요한 사실 — 이것은 3D 엔진이 아니다

**지구·구름·주택은 실시간 3D 렌더링이 아니다.** three.js도, CesiumJS도, Google Photorealistic
3D Tiles도, deck.gl도 쓰이지 않았다. 실제 구조는:

> **AI로 생성한 5초짜리 실사 영상 클립 10개**를 이어붙일 수 있게 씨앗 프레임을 물려 만들고,
> **GOP 8로 조밀하게 재인코딩**한 뒤, 브라우저에서 `<video>` 10개를 **한 장의 `position: fixed`
> 무대에 전부 마운트한 채** 스크롤 값으로 `video.currentTime`을 **스크럽**하고,
> 클립 경계는 **한쪽만 페이드하는 크로스페이드**로 지운다.

즉 **"영상 스크러빙 + 무이음 크로스페이드 + 고정 무대"**가 전부다. 화면에 보이는 "지구"는
실제로는 **손으로 만든 물리 축소모형 스타일의 AI 생성 영상**이고(놋쇠 링, 이끼, 부은 레진, 체로 친
모래, 광섬유 조명 — `EXAMPLES.md`의 world 열에 그렇게 적혀 있다), 그 위에 얹힌 마커·다이얼·카피만
DOM/CSS다.

이 점이 우리에게 결정적인데, **가장 무거워 보이는 부분이 사실 가장 싼 부분**이기 때문이다.
WebGL 지구본을 만들 필요가 없다. 우리에게는 이미 **진짜 정사영상과 진짜 탐지 결과**가 있으므로,
AI 생성 대신 **우리 데이터로 카메라 무빙을 오프라인 렌더 → mp4로 구워** 같은 자리에 끼우면 된다.

### 0.4 화면 크롬(비영상 요소) 목록 — 전부 DOM/CSS

0:05–0:22 사이 영상 위에 얹힌 요소는 정확히 다음 넷뿐이다.

1. **카피 블록** — `<h1>`/`<p>`. 고정 오버레이 레이어 `[data-sc-world-copy]` 안에 있고, 트랙 전체
   대비 자기 창(window)에서만 불투명해진다. **변형은 `translateY`뿐이고 전 구간 총 4vh로 제한**된다
   (그 이상이면 "다른 속도로 스크롤되는 두 번째 페이지"로 읽혀 싸구려가 된다 — 명세 원문).
2. **ORRERY 방위 다이얼** — 좌하단 고정. 원반에 궤도선, 허브에 워드마크, 위쪽에 삼각 니들,
   가장자리에 세 목적지의 **실제 경도**(135.8E / 73W / 4W) 위치의 핍. 원반은 페이지 전체에 걸쳐
   **정확히 한 바퀴** 돈다. 그래서 니들 아래로 핍이 오는 순간과 비행이 그곳에 도착하는 순간이 일치한다.
   **페이지 어디에도 숫자가 없다** — 이전 빌드들이 다 쓴 수치 판독을 일부러 안 쓴 것이 이 빌드의 차별점.
3. **elsewhere field 마커** — 60개. 자기 깊이만큼 패럴랙스. 하강 구간에서는 `--sc-seg`/`--sc-segp`를
   페이지가 직접 읽어 **방사형으로 흩뿌려지듯 스트리크**한다. **마우스를 하나에 올리면 그것만 멈춘다**
   (그 마커에만 값을 안 쓰면 나머지가 계속 움직이므로 홀로 정지한 것처럼 보인다). 클릭/탭으로 고정,
   Escape로 해제.
4. **스크림** — 카피가 앉는 자리에만 얹는 국소 스크림(`.sc-world__scrim`). 전면 어둠 오버레이 금지.

### 0.5 스크롤–카메라 대응의 실제 수치 (`orrery` 실측값)

`EXAMPLES.md`에 이 빌드의 실제 파라미터가 기록되어 있다. 그대로 옮기면:

- **레그 10개, 필름 총 11.97vh, 스페이서 12.97vh** (모드가 마지막 착지용으로 1뷰포트를 더한다).
- **페이스 통일**: 5초 클립은 각각 **1.08vh**, 정점의 10초 클립은 **2.25vh**.
  → 필름 진행 속도가 전 구간 **0.212–0.225 vh/초**로, 편차 6%.
  (첫 컷에서는 편차가 36%였고 소유자의 평가는 "부드럽지 않다"였다. **편차를 없애는 것이
  스무딩보다 중요하다**는 것이 이 빌드가 남긴 가장 값진 교훈이다.)
- `data-sc-seam` = **0.16**(기본 0.12보다 넓게 — 이음매가 사라질 방을 더 준다).
- `data-sc-lerp` = **0.12**(기본 0.18보다 강한 감쇠 — 월드플라이트는 레그가 많아 휠 저더가 더 잘 보인다).
- 정점(peak)은 **페이지 유일의 10초 클립 한 레그**가 가져간다. 다른 방식(두 레그를 붙여 정점을
  만드는 방식)은 이미 `descent` 빌드가 썼기 때문에 **핑거프린트 규칙상 재사용이 금지**된다.
- 카피 앵커 순서: BL → BR → C → BR → BL → TL → ML → TL. 인접 반복 없음.
  이 중 TL/ML 두 개는 스킬 기본 킷에 없는 앵커다(빌드가 직접 만든 것).

**속도 감각의 결론**: `0.21–0.22 vh/초`가 "날아서 통과하는 세계"의 하한선이다. 8초 클립당 1.5vh는
"죽은 스크롤 방지선"이지 목표치가 아니다. **본능이 시키는 것보다 훨씬 느리게 가야 한다.**

### 1.5 에셋 생성 (영상 4:39–5:27)

**kie.ai** — Nate의 표현으로 "**이미지·영상 모델판 OpenRouter**". 로그 화면(5:00)에서 실제
생성 이력(캔, 향수병, 컵)을 보여준다. API 키를 프로젝트 환경변수에 넣으면 스킬이 알아서 호출한다.

```bash
node <skill>/scripts/kie.mjs probe                       # 크레딧 확인 먼저
node <skill>/scripts/kie.mjs still "<스타일 프리앰블>\n\n<장면>" out/01.png --ar 16:9 [--ref brand.png]
node <skill>/scripts/kie.mjs shot  "<카메라 무빙>" out/01.png out/01.mp4 --dur 5 [--tail end.png]
bash  <skill>/scripts/encode.sh out/01.mp4 assets/01.mp4          # 데스크톱 1080p g=8 crf20
bash  <skill>/scripts/encode.sh out/01.mp4 assets/01-m.mp4 mobile # 모바일 720p g=4 crf24
```

- 엔드포인트: `POST https://api.kie.ai/api/v1/jobs/createTask` / `GET …/jobs/recordInfo?taskId=`
  업로드: `https://kieai.redpandaai.co/api/file-base64-upload`
- 모델: 스틸 `seedream/5-pro-text-to-image`(`--ref` 있으면 `-image-to-image`),
  영상 `kling/v2-1-pro`(image-to-video).
- **`--ar`은 `16:9`(2736×1520) / `9:16`(1520×2736) / `3:4`(1776×2352)만 검증됨. `4:5`는 거부된다.**
- 포스터는 **반드시 클립의 첫 프레임을 ffmpeg로 뽑아** 쓴다(따로 생성하면 영상이 뜨는 순간 점프한다).

**품질을 결정하는 3가지**
1. **스타일 프리앰블 한 개를 모든 프롬프트에 토씨 하나 안 바꾸고 재사용.** 이것이 따로 생성한 여섯 장을
   한 번의 촬영처럼 보이게 만든다. 의역하면 여섯 개의 프롬프트처럼 보인다.
   프리앰블은 반드시 다섯 가지를 명시한다: **매체·렌즈 / 광원 개수와 위치 / 그레이드(색 이야기 세 단어) /
   질감(그레인·헐레이션·물방울·불완전함) / 네거티브 목록**("NOT 3D render, NOT clay, NOT illustration,
   no digital glow, no plastic sheen"). 다섯 중 하나만 빠져도 세트가 흐트러진다.
2. **모든 에셋을 눈으로 보고 나서 쓴다.** 생성은 싸고 리롤은 더 싸다.
3. **재생용이 아니라 스크럽용으로 인코딩한다.** 일반 웹 인코딩은 키프레임이 2–5초에 하나여서
   임의 시각으로 seek하면 디코더가 직전 키프레임부터 걸어와야 한다 → **재생은 완벽한데 스크럽은 진창**.

**"장면마다 빈 공간이 어디인지"를 프롬프트에 매번 쓴다.** 이건 조언이 아니라 요구사항이다.
(세 종횡비 7장이 리롤 0회로 통과한 빌드가 매번 이걸 썼다.) 예: "프레임 좌상단에 넓은 그림자 여백",
"피사체는 낮고 오른쪽에, 위쪽에 네거티브 스페이스". **크롭하지 말고 여백을 생성한다.**
그리고 **이미지 안에 글자를 넣으라고 절대 요청하지 않는다** — 마크업 텍스트만 선택·번역·확대 가능하다.

### 1.6 이음매 법칙 (월드플라이트 전용 — orrery의 심장)

두 가지 아키텍처만 작동한다.

- **A(권장): 시작 이미지로만 체인.** 각 레그는 시작 이미지에서 출발해 끝은 자유. 다음 레그의 시작
  이미지는 **직전 레그의 인코딩된 mp4에서 뽑은 프레임**. 끝 이미지를 강제하면(양끝 고정) 모델이
  갈등을 "카메라를 뒤로 빼서" 해결해 버려 **모든 레그가 똑같은 와이드 설정샷**이 된다.
- **B: 커넥터 레그.** 기존 클립 둘을 이어야 할 때, 앞 레그의 끝 프레임에서 시작해 다음 레그의 실제
  첫 프레임으로 끝나는 짧은 연결 클립을 만든다.

```bash
# 직전 레그의 마지막 프레임 → 다음 레그의 시작 이미지
ffmpeg -sseof -0.15 -i legN.mp4 -frames:v 1 -q:v 2 chainN.png
# 각 레그의 첫 프레임 → 포스터
ffmpeg -i legN.mp4 -frames:v 1 -q:v 3 pN.webp
```
**반드시 인코딩된 mp4에서 뽑는다.** 인코딩이 픽셀을 바꾸므로, 인코딩 전 마스터에서 뽑은 프레임은
브라우저가 실제로 디코드할 프레임과 다르다.

**병렬화 팁(orrery가 실제로 쓴 것)**: 앵커 스틸을 **먼저 전부** 만들고, 레그 N에 앵커 N을 head로,
앵커 N+1을 `--tail`로 준다. 그러면 10개 클립을 동시에 생성할 수 있다(직렬이면 10레그에 45분).
orrery는 9개 이음매 전부에서 **PSNR 28.5–39.8 dB**를 기록했다.

### 1.7 페이지 작성

엔진 두 파일(`scrollcraft.js`, `scrollcraft.css`)을 빌드 폴더에 **복사만 하고 절대 수정하지 않는다.**
테마는 토큰 6개 + 폰트 2개 오버라이드로 끝낸다.

```css
:root{
  --sc-canvas:#0A0806; --sc-surface:#16110E;
  --sc-ink:#F5EBDD;    --sc-ink-soft:#A2968A;
  --sc-accent:#FF5A3D; --sc-accent-ink:#15110F;
  --sc-font-display:"Archivo",system-ui,sans-serif;
  --sc-font-text:"Geist",system-ui,sans-serif;
}
```

월드플라이트 마크업(실제 구조):

```html
<div data-sc-mode="worldflight" data-sc-seam="0.16" data-sc-lerp="0.12">
  <div data-sc-world>
    <div data-sc-segment data-sc-w="1.08" data-sc-linger="0.3" data-sc-waypoint="Kyoto">
      <img class="sc-world__poster" src="assets/p1.webp" alt="" decoding="async">
      <video data-sc-src="assets/leg1.mp4" data-sc-src-mobile="assets/leg1-m.mp4"></video>
    </div>
    <!-- … 비행 순서대로 레그 10개 … -->
  </div>
  <div data-sc-world-copy>
    <div class="sc-world__scrim sc-scrim sc-scrim--band"></div>
    <div class="sc-copy" data-sc-copy data-sc-window="hero">…</div>
    <div class="sc-copy" data-sc-copy data-sc-window="0.38 0.66">…</div>
    <div class="sc-copy" data-sc-copy data-sc-window="finale">…</div>
  </div>
  <div data-sc-spacer aria-hidden="true"></div>
</div>
<script>ScrollCraft.mount(document)</script>
```

**절대 규칙 6개**
1. 문서 플로우에 스페이서 말고 아무것도 두지 않는다(하나라도 두면 이음매가 생기고 모드가 무의미해진다).
2. 카피의 `translateY` 총량 ≤ 4vh.
3. lerp는 reduced-motion 외에는 절대 끄지 않는다.
4. 페이지 전체가 한 페이스, 그리고 필요하다 싶은 것보다 느리게.
5. **모든 클립은 끝까지 마운트된 채로 있고 `src`를 절대 바꾸지 않는다**(src 교체 = 검은 프레임 = 이 모드가
   없애려던 바로 그 컷).
6. 이음매 프레임은 인코딩된 mp4에서.

**스페이서 높이 함정**: `layout()`이 `(가중치 합 + 1) × innerHeight`로 스페이서를 잡는데, 그 순간
`innerHeight`가 0이면 스페이서가 **0px**가 되어 페이지에 스크롤 트랙이 없어진다. **콘솔에 아무것도
안 뜨고 성공처럼 보인다.** 폰트·윈도가 정착한 뒤 resize를 한 번 보내면 해결된다:

```js
function relayout(){ dispatchEvent(new Event('resize')); }
addEventListener('load', relayout);
if (document.fonts?.ready) document.fonts.ready.then(relayout);
// 확인: document.documentElement.scrollHeight ≈ (가중치합+1) × innerHeight
```

### B.2 스크롤 → 카메라: 정확한 메커니즘

**(a) 스크롤 트랙**
스페이서 높이 = `(레그 가중치 합 + 1) × innerHeight` **px 단위로** 기록한다(무대는 `svh`로 잡히는데
폰에서 `vh`와 `svh`가 다른 숫자이므로 같은 자를 써야 한다). `+1`은 패딩이 아니라 **마지막 비행이
착륙할 방**이다. 없으면 마지막 클립의 마지막 1초가 독자가 절대 머물 수 없는 지점이 된다.

레그 i는 `[c_i, c_i + w_i)`를 소유하고, 로컬 진행도는 `(t − c_i) / w_i`를 `lingerEase`로 리맵한다.

**(b) 재생헤드 lerp — 스크롤은 절대 `currentTime`을 직접 쓰지 않는다**

```js
function tick() {
  var eps = isMobile() ? 0.02 : 0.008;                 // 데드밴드
  for (var i = 0; i < playheads.length; i++) {
    var V = playheads[i];
    if (!V.ready) continue;
    if (V.el.seeking) {                                 // 시크 병합
      var nw = performance.now();
      if (!V.stuckAt) V.stuckAt = nw;
      else if (nw - V.stuckAt > 700) {                  // 700ms 넘게 막히면 재발행
        V.stuckAt = nw;
        try { V.el.currentTime = V.el.currentTime + 0.001; } catch (e) {}
      }
      continue;
    }
    V.stuckAt = 0;
    if (!V.live && Math.abs(V.cur - V.target) < 0.002) continue;   // 화면 밖 + 도착 = 무비용
    V.cur += (V.target - V.cur) * (reduce ? 1 : V.lerp);           // 프레임당 고정 비율
    var dur = V.el.duration || 1;
    var t = clamp(V.cur, 0, 0.999) * dur;
    if (Math.abs(V.el.currentTime - t) > eps) { try { V.el.currentTime = t; } catch (e) {} }
  }
  requestAnimationFrame(tick);
}
```

세 장치가 전부 기본 활성:
- **프레임당 lerp 0.18**(월드플라이트는 **0.12**가 더 낫다). reduced-motion에서는 1.0(스무딩 없음).
- **데드밴드** 데스크톱 8ms / 모바일 20ms. 그보다 작은 쓰기는 시크 비용만 들고 보이는 게 없다.
- **시크 병합**: 디코더가 직전 시크를 해결 중이면 새 시크를 큐에 넣지 않는다. 빠른 플릭 때
  시크가 쌓여 클립이 얼어붙는 것을 막는다.

**왜 필요한가**: 휠 이벤트는 일정한 간격으로 오지 않는다. 1:1로 쓰면 이벤트 스트림의 모든 틈이
그대로 스터터로 재생된다.

**(c) 클립 로딩 — Blob**
`src`가 아니라 `data-sc-src`를 쓴다. 엔진이 `fetch()`로 **Blob을 받아 `URL.createObjectURL()`**로
물린다. HTTP Range 지원 없이도 seek이 되게 하려는 것이고, reduced-motion에서는 아예 fetch하지 않는다.

레그는 독자가 **±1.6vh 안에 들어왔을 때만** 가져온다. 전부 미리 받으면 첫 프레임 전에 수십 MB다.

**(d) 포스터가 무빙을 대신한다**
클립의 첫 실프레임이 그려지기 전까지 포스터가 `scale(1.03 + local × 0.14)` 푸시인으로 움직인다.
페이지가 스크롤되는데 정지 이미지가 완전히 가만히 있으면 그건 자기가 플레이스홀더라고 광고하는 것이고,
느린 푸시는 "카메라가 이미 날고 있다"로 읽힌다.

**(e) 이음매 = 한쪽만 페이드하는 크로스페이드**
이음매 밴드에서 **들어오는 레그가 0→1로 올라오는 동안 나가는 레그는 밑에서 최대 강도를 유지**하고,
완전히 덮인 뒤에야 0으로 떨어진다. 양쪽을 동시에 페이드하면(= 명백해 보이는 구현) 이음매 한가운데로
페이지 바닥이 비쳐 **플래시로 읽힌다.** z-index는 현재 레그 120, 나머지 `100 + opacity × 10`.

밴드의 각 면은 이음매 폭의 절반이라 각 레그가 자기 이음매 프레임을 약 0.06vh 동안 붙잡는다.
그 프레임이 바로 이음매 법칙으로 맞춘 프레임이므로 **구조적으로 보이지 않는다.**

### B.3 "주택이 나타나는" 기법의 정확한 정체

세 겹이 겹쳐서 만들어진다.

1. **스케일 점프를 카메라가 한다.** 지구본 전체 → 곡면 스침 → 계곡 → 안뜰까지 **한 대의 카메라가
   연속으로 내려간다.** 페이지 전환이 아니다. 이것이 "안에서 나온다"는 인상의 90%.
2. **구름/어둠이 컷을 삼킨다.** 실제 클립 경계는 t≈9.2(구름) / t≈11.5(어둠)에 있다. 클립을 바꾸는
   순간을 **화면이 거의 단색이 되는 순간**으로 잡아 두면 크로스페이드가 물리적으로 안 보인다.
3. **디오라마 미학이 축척 모순을 해소한다.** 실제 위성 스케일이라면 지구 곡률과 기와 지붕이 같은
   샷에 있을 수 없다. "작업대 위 손으로 만든 축소모형"이라는 세계관을 선언해 버렸기 때문에
   **비율이 틀려도 거짓말이 아니게** 된다. 이건 미술 결정이 기술 문제를 없앤 사례다.

### B.4 카피 계약

각 블록은 **레그가 아니라 트랙 전체**에 대해 창을 선언한다.
- `hero`: 첫 픽셀부터 존재하고 첫 레그의 0.62에서 사라진다. **히어로가 페이드인하면 안 된다** —
  화면에 볼 게 아무것도 없는 유일한 순간에 빈 화면 위로 글자가 떠오르게 되기 때문.
- `finale`: 마지막 레그의 0.4부터 들어와 끝까지 유지.
- `"0.38 0.66"`: 플래토 창 — 앞 30% 램프인, 유지, 뒤 30% 램프아웃. **순수 삼각형이면 불투명도 1을
  한 순간만 스치므로 모든 헤딩이 약간 흐리게 읽힌다.** 플래토는 장식이 아니라 필수.
- 포인터 이벤트는 불투명도 0.5 위에서만 돌려준다.

### B.5 성능

- 클립 2개 ≈ 9MB(데스크톱 5초 1080p 약 3MB, 모바일 720p 약 1.5MB). 그레인 많은 세계는 약 2배
  (`-crf 22`로 되사올 수 있다).
- 화면 밖에서 목표에 도달한 클립은 아예 건드리지 않는다.
- 모바일 변형(`data-sc-src-mobile`)을 **모든 레그마다** 낸다. 엔진이 coarse pointer/좁은 뷰포트에서 고른다.
- reduced-motion: **클립을 한 개도 받지 않는다.** 포스터가 필름이 되어 같은 이음매·같은 카피 창으로
  교차 디졸브한다. 이야기가 통째로 남는다.

### D.2 우리 버전의 필름 만들기 — kie.ai 대체 파이프라인

**핵심 아이디어: 카메라 무빙을 브라우저에서 오프라인 렌더해 mp4로 굽고, 그 mp4를 스크럽한다.**

```
[레그 정의]  각 레그의 시작/끝 카메라 상태(center, zoom, pitch, bearing, 고도)
     ↓
[오프라인 렌더]  headless Chrome에서 MapLibre + deck.gl을 1920×1080으로 띄우고,
                 프레임마다 map.jumpTo(보간된 카메라) → map.once('idle') → screenshot
                 5초 클립 = 30fps × 150프레임
     ↓
[PNG 시퀀스 → mp4]  ffmpeg -framerate 30 -i f_%04d.png ...
     ↓
[스크럽 인코딩]  encode.sh (g=8 crf20 데스크톱 / g=4 crf24 720p 모바일)
     ↓
[포스터]  ffmpeg -i legN.mp4 -frames:v 1 -q:v 3 pN.webp
     ↓
[worldflight 마크업에 끼움]
```

**이 방식의 장점 5가지**
1. **이음매가 수학적으로 정확하다.** 레그 N의 끝 카메라 = 레그 N+1의 시작 카메라로 두면 프레임이
   동일하다. AI 체인의 PSNR 28–40dB 같은 근사가 필요 없다. **이음매 법칙 전체가 사라진다.**
2. **타일 로딩 지연이 사라진다.** 실시간이면 z18 타일이 늦게 와서 화면이 뭉개지지만, 오프라인
   렌더는 `idle` 이벤트를 기다렸다 찍는다. **모든 프레임이 완전히 로드된 상태**다.
3. **V-World 쿼터를 한 번만 쓴다.** 방문자마다 타일을 때리지 않는다.
4. **모바일에서도 60fps.** 폰에서 deck.gl 9,664동 발광 레이어를 실시간으로 돌릴 필요가 없다.
5. **비용 0.** kie.ai 크레딧이 필요 없다.

**단점과 대응**
- 카메라 경로가 고정된다 → 탐사 모드(자유 조작)는 **필름이 끝난 뒤 실시간 MapLibre로 인수인계**한다.
  마지막 레그의 카메라 상태를 그대로 실지도에 `jumpTo`하면 필름→실시간 전환이 이음매가 된다.
  (이것이 우리 signature move의 후보다 — §D.4)
- 데이터가 바뀌면 다시 구워야 한다 → 렌더 스크립트를 `tools/film/`에 두고 CI화. **이미 `tools/film/`
  디렉터리가 작업 트리에 있다**(다른 세션 산출물로 보임) — 합류 지점이다.

### D.3 우리 악장 → 레그 매핑 (초안)

취향 프로필 §2.2 확정: **메인은 흰 바탕, 옵서버토리(어두운 무대)는 메인에서 제외.**
그러면 궤도의 검정은 어떻게 되는가? → **"어두움은 오직 위성/정사영상 사진 판(plate) 안에서만"**이라는
규정을 따른다. 즉 **우주는 필름 안에 있고, 종이는 그 필름을 담는 판**이다.

| 레그 | 카메라 | 가중치 | 클립 길이 | 웨이포인트 | 카피 앵커 |
|---|---|---|---|---|---|
| 1 | 궤도 786km, 한반도가 지구 곡률 위에 | 1.08 | 5s | `ORBIT` | BL (hero) |
| 2 | 성층운 돌파 — 구름이 화면을 채운다 | 1.08 | 5s | `STRATUS` | — (이음매) |
| 3 | 한반도 전경, 13개 서비스 지역 점등 | 1.08 | 5s | `KOREA` | C |
| 4 | 전라북도 → 남원 접근 | 1.08 | 5s | `NAMWON` | BR |
| **5** | **남원 z18 강하 — 비닐하우스 9,664동이 이름을 얻는 순간** | **2.25** | **10s** | `DETECT` | TL (**정점**) |
| 6 | 여수 해양쓰레기 | 1.08 | 5s | `YEOSU` | ML |
| 7 | 제주 | 1.08 | 5s | `JEJU` | BL |

### D.4 우리 signature move 후보 (핑거프린트 게이트를 통과해야 함)

기존 10개 빌드가 이미 쓴 것: 램프 콘(descent) / 마커 정지(orrery) / 스플릿플랩(airfield) /
포인터 안료(pigment) / 향 토큰(maison) / 글자 물리(showcase) / 열지문(phase) / 레일 병합(lane) /
스크롤=재생헤드(vesper).

**LX 후보 ①: "필름이 지도가 되는 순간(The handoff)."**
마지막 레그가 끝나는 정확한 프레임에서, 사전 렌더 mp4가 **같은 카메라 상태의 실시간 MapLibre로
교대**한다. 관객은 자기가 보던 영화가 갑자기 조작 가능한 지도가 되었다는 것을 마우스를 움직여서
발견한다. **어느 빌드도 이걸 안 했다** — 그들에겐 진짜 지도가 없었기 때문이다. 우리만 할 수 있다.

**LX 후보 ②: "영수증(The receipt)."**
페이지의 모든 숫자 옆에 눈에 안 띄는 각주 표식이 있고, 스크롤이 그 숫자를 지날 때
`sourced 4 of 13`이 올라간다. 클릭하면 그 숫자를 만든 **실제 타일과 실제 탐지 폴리곤 크롭**이
Acquired 인셋으로 뜬다. Nate의 AIS 빌드가 쓴 아이디어와 겹치므로 **①과 결합해 차별화**해야 한다.

**LX 후보 ③: "채도 복원."**
전 화면 −45% 저채도인데, **AI가 탐지한 폴리곤 안에서만 원본 채도가 살아난다.** 필름을 오프라인
렌더하므로 **이번엔 진짜 마스킹이 가능하다**(§13.3의 갭 1이 여기서 해소된다 — MapLibre가 실시간에
못 하던 것을 렌더 타임에는 할 수 있다).

→ 권고: **①을 주 signature, ③을 그 안의 장치로.** ②는 페이지 크롬(룰러)에 흡수.

### D.5 흰 캔버스 대응 체크리스트 (worlds.md §"If the canvas is light")

1. 스크림은 **어둡게가 아니라 캔버스 쪽으로 밀도를 올린다.** 종이 위 영상에 검은 스크림을 얹으면 실패.
2. 미디어 위 활자는 **잉크색을 유지**한다. 밝은 페이지 + 밝은 프레임 위의 흰 글자는 회복 불가.
3. `--sc-edge`(잉크 톤 인셋 하이라이트)는 종이 위에서 **윗입술의 때**처럼 보인다 → 흰색으로 반전하거나
   버리고 헤어라인으로 대체. **우리 v3는 이미 헤어라인 체계**라 자연스럽다.
4. `--sc-e1/2/3` 그림자 알파는 **절반**으로, `--sc-shadow-color`는 캔버스 색조 쪽으로.
   → 우리 취향 프로필은 **그림자 0**이므로 그냥 전부 제거한다.
5. 대비 방향이 뒤집힌다: **어두운 활자는 아래 가장 어두운 패치에서 실패**한다(밝은 패치가 아니라).
   하네스가 줄마다 방향을 판정하므로 밝은 페이지도 올바르게 채점된다.

| **E9** | 죽은 스크롤 검사가 없다 | Playwright 2 tests(스크린샷·규칙 확인) | 0.12vh 간격 샘플에서 **어떤 것도 안 움직이는 구간**을 기계적으로 검출 | 중 |

| **E11** | §13.3 갭 1 — "폴리곤 안만 원본 채도"가 부분 구현 | MapLibre 실시간 마스킹 불가 → 전역 저채도 + Acquired 크롭으로 우회 | 오프라인 렌더로 가면 **진짜로 가능해진다** | 낮음(해법 확보) |
| **E12** | §13.3 갭 3 — 1장 실영상 비중 미달(궤도 25%) | EOX 지구본이 화면 1/4 | 필름 레그 1을 궤도 실영상 풀블리드로 구우면 **해소** | 낮음(해법 확보) |
| **E13** | 룰러가 두 축(챕터/시간)을 교대로 쓴다 | §13.3 갭 2 | `sc:waypoint` 이벤트로 **웨이포인트 레일**을 따로 그리면 축 하나에 의미 하나 | 낮음 |

**요약**: E1·E2·E3가 클라이언트가 말한 "이거다"와 우리 프로토 사이의 실제 거리다. 나머지는 파생.
그리고 **셋 다 `scrollcraft.js`를 그대로 붙이면 코드 한 줄 안 짜고 해결된다.**

## F. 단계별 계획과 먼저 찔러볼 것

### F.0 먼저 스파이크할 것 (반나절, 이게 되면 나머지는 실행)

> **스파이크: "레그 2개짜리 남원 월드플라이트"**
>
> 1. `build/scroll-craft/plugins/nateherk-design/skills/scrollcraft/engine/` 두 파일을
>    `landxi/proto/vendor/scrollcraft/`에 복사(MIT 고지 유지).
> 2. `tools/film/render-leg.mjs` — Playwright로 MapLibre를 1920×1080 헤드리스로 띄우고,
>    시작/끝 카메라를 보간해 150프레임 PNG를 뽑는다. **프레임마다 `map.once('idle')`을 기다린다.**
> 3. 레그 A = 한반도 전경 → 남원 접근(5초), 레그 B = 남원 z18 강하(5초).
>    레그 A의 끝 카메라 = 레그 B의 시작 카메라.
> 4. `encode.sh`로 각각 g=8 crf20 데스크톱 + g=4 crf24 720p 모바일.
> 5. `landxi/proto/film.html` — worldflight 마크업 최소본, 카피 3블록(hero/plateau/finale),
>    `data-sc-seam="0.16"`, `data-sc-lerp="0.12"`, 가중치 1.08/1.08.
> 6. `node vendor/scrollcraft/scripts/worldflight-assert.mjs --url http://localhost:4510`
>    + `shoot.mjs`로 컨택트시트.
>
> **성공 판정**: (a) 이음매가 안 보인다, (b) 휠을 아무 데서나 멈춰도 프레임이 완성되어 있다,
> (c) 되감으면 정확히 되감긴다, (d) `scrollHeight ≈ (2.16+1) × innerHeight`,
> (e) 죽은 스크롤 0, (f) 폰에서 720p 변형이 실제로 잡힌다.
>
> **실패 시 조기 경보**: 프레임당 `idle` 대기가 너무 느려 150프레임에 10분 이상 걸리면,
> 타일 프리캐시 후 `idle` 없이 고정 지연으로 전환한다.

### F.1 단계 계획

**Phase 1 — 엔진 이식과 필름 파이프라인 (스파이크 포함, 1주)**
- ScrollCraft 엔진 vendoring + MIT 고지.
- `tools/film/` 렌더러 확립: 카메라 키프레임 JSON → PNG 시퀀스 → mp4(데스크톱/모바일) → 포스터.
- 레그 2개 스파이크 통과.
- 산출: `landxi/proto/film.html`, `tools/film/render-leg.mjs`, `tools/film/legs.json`.

**Phase 2 — 8레그 전편과 흰 캔버스 이식 (1–2주)**
- §D.3 표대로 8레그(총 50초 필름, 11.81vh) 렌더.
- 흰 캔버스 대응 5개 항목 적용(§D.5). 그림자·유리·라운드 전부 0 유지.
- 카피 8블록, 앵커 순서 BL→C→BR→TL→ML→BL→TL(인접 반복 없음), 전부 플래토 창.
- 정점 = 레그 5(남원 z18, 10초/2.25vh), 그 직전 레그 4는 authored silence.
- **페이스 편차 목표 ≤ 3%**(orrery는 6%).
- 검증: `worldflight-assert` 통과, 죽은 스크롤 0, 대비 통과, reduced-motion 포스터 필름 확인.

**Phase 3 — signature move: The handoff (1주)**
- 마지막 레그가 끝나는 프레임에서 실시간 MapLibre로 교대. 필름의 마지막 카메라 상태를 그대로
  `jumpTo`. 관객이 마우스를 움직이는 순간 조작 가능해진다.
- 그 위에 §D.4 후보 ③(폴리곤 안만 원본 채도)를 필름 렌더 단계에서 진짜 마스킹으로 구현.
- 핑거프린트 6차원 기록: 문법=Continuous world / 내비=전폭 헤어라인 룰러 + 웨이포인트 레일 /
  히어로=궤도 실영상 greet / 시퀀스=8레그 단일 트랙 / 닫기=필름→실지도 인수인계 /
  signature=The handoff. **기존 10행 대비 4차원 이상 상이함을 확인.**

**Phase 4 — 증거 층 (1주)**
- Acquired z18 크롭 인셋(이미 구현됨)을 필름 위 오버레이로 이식.
- 결과 패널 400px 컬럼, 임계값 슬라이더, 히스토그램 스윕 — 인수인계 이후 실시간 지도 위에서.
- `sourced N of 13` 룰러 흡수.

**Phase 5 — 기기·접근성·성능 마감 (0.5주)**
- 실제 iPhone에서 확인(헤드리스가 재현 못 하는 것: 디코더·자동재생 정책·저전력 모드·터치 스크롤).
  결함이 보고되면 첫 라운드에 `references/device-diag.html`을 사이트 옆에 배포해 기기가 답하게 한다.
- 총 영상 용량 목표: 데스크톱 8레그 × 3MB ≈ 24MB(±1.6vh 지연 로딩이므로 초기 로드는 3MB).
  넘으면 `-crf 22`로 되사온다.
- 탭 포커스 순서, 대비, reduced-motion 최종 확인.

### F.2 리스크

| 리스크 | 대응 |
|---|---|
| 오프라인 렌더가 너무 느리다 | 타일 프리캐시 + 고정 지연. 또는 레그 길이를 5초→4초로 |
| 24MB 영상이 무겁다 | ±1.6vh 지연 로딩이 이미 해결. 초기 페인트는 포스터(WebP 수백 KB) |
| 데이터가 바뀔 때마다 재렌더 | `tools/film/`을 CI 잡으로. 데이터 갱신 주기가 분기 단위라 문제되지 않음 |
| 클라이언트가 "실시간이 아니네"라고 볼 위험 | **The handoff가 정확히 그 답이다.** 필름은 도입부일 뿐이고 끝나면 진짜 지도가 손에 들어온다 |
| 엔진이 우리 케이스를 못 버틴다 | **엔진을 절대 수정하지 않는다.** 필요한 건 페이지 로컬 JS로 `--sc-p`/`--sc-seg`/`--sc-segp`를 읽어 만든다(스킬의 하드 규칙) |
