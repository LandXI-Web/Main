## 0. 결론 먼저

**Path A 는 한국에서 목표 경험을 만들지 못한다. 채택하지 않는다.**

기술적으로는 완전히 작동한다. API 도 붙고, Cesium 통합도 한 줄이고, 스크롤 레일 · 구름 · 우리 탐지
결과 드레이프는 이미 이 스파이크에서 다 돌아간다. 문제는 오직 하나, **데이터가 없다**는 것이다.
한국 영토에는 Google 의 포토리얼리스틱 **메시(집 모양)** 가 존재하지 않는다. 정사영상을 지형에
덮은 2.5D 뿐이다. "지구 안으로 들어가 주택·마을이 3D 로 서는" 장면은 도쿄에서는 되고 남원에서는
안 된다. 서울 코엑스에서조차 안 된다.

우회로는 하나뿐이다 — **지구·대기·구름·카메라 레일은 그대로 쓰고, 한국 지표만 우리 정사영상 +
자체 3D 로 채운다.** (§7)

## 1. 접근 가능성 · 키

`root.json` 엔드포인트를 직접 두드려 확인했다.

| 요청 | 응답 |
|---|---|
| `GET https://tile.googleapis.com/v1/3dtiles/root.json` (키 없음) | `403 PERMISSION_DENIED` — *"Method doesn't allow unregistered callers"* |
| `…?key=INVALID_KEY_PROBE` | `400 INVALID_ARGUMENT` — `API_KEY_INVALID` |

즉 **API 키는 필수이고, 무료 익명 접근은 없다.** 리포지토리에는 Google 키가 없다
(`.env.local` 에는 `VWORLD_KEY` 하나뿐). 스파이크는 키 없이도 돌도록 만들었고,
키가 주입되면 자동으로 Google 타일셋으로 전환한다.

### 키 발급 절차 (클라이언트 작업)

1. Google Cloud Console → 프로젝트 생성 → **결제 계정 연결** (필수. 무료 등급도 카드가 있어야 열린다)
2. API 및 서비스 → 라이브러리 → **Map Tiles API** 사용 설정
3. 사용자 인증 정보 → API 키 만들기
4. **키 제한을 반드시 건다** — 애플리케이션 제한 `HTTP 리퍼러`(우리 도메인만),
   API 제한 `Map Tiles API` 만 선택. 3D 타일 키는 클라이언트에 노출될 수밖에 없으므로
   리퍼러 제한이 유일한 방어선이다.
5. 키는 소스에 넣지 않는다. `tools/serve.mjs` 가 `VWORLD_KEY` 를 주입하는 방식
   (`/landxi/proto/env.js`)을 그대로 확장하는 게 맞다.

스파이크 주입 경로: `?key=…` → `localStorage.GOOGLE_MAPS_KEY` → `window.GOOGLE_MAPS_KEY`.

## 2. 한국 커버리지 — 이 스파이크의 핵심

키가 없어 타일을 직접 받아보지는 못했으므로, **두 갈래의 독립 증거**로 판정했다.

### 2.1 시각 증거 — Google Earth 웹 대조 촬영

Photorealistic 3D Tiles 는 Google Earth 의 3D 메시와 같은 계열 자산이며, Cesium 측 설명에
따르면 **Tiles API 쪽이 Earth 보다 좁다**. 따라서 *Earth 에 메시가 없으면 Tiles API 에도 없다.*
같은 카메라 고도(약 200 m)에서 찍었다.

| 지점 | 파일 | 관측 |
|---|---|---|
| 남원 (127.3900, 35.4103) | `shots/spikes/google3d/earth-namwon-600d.jpeg` | 카메라 215 m. 지형 기복은 있으나 **건물이 하나도 서지 않는다.** 마을 전체가 지형에 칠해진 그림 |
| 서울 코엑스 (127.0587, 37.5126) | `earth-seoul-coex-700d.jpeg` | 카메라 210 m. **완전히 평평.** 무역센터·아셈타워가 전혀 없다. 해상도도 뭉개짐 |
| 제주시 (126.5312, 33.4996) | `earth-jeju-700d.jpeg` | 평평. 하단 크레딧에 **`2015. 12. 14.`** — 영상 자체가 10년 전 |
| **도쿄 (139.7454, 35.6586) — 대조군** | `earth-tokyo-control-700d.jpeg` | 카메라 186 m. **완전한 포토그래메트리 메시.** 도쿄타워가 서 있고 개별 주택 지붕 형상까지 보인다 |

같은 뷰어 · 같은 고도 · 같은 시각에서 도쿄는 되고 한국은 안 된다. 렌더러 문제도, 로딩 문제도 아니다.

### 2.2 문서 · 커뮤니티 증거

- Cesium 스태프(azrogers)는 한국 코엑스 문의에 대해 Photorealistic 3D Tiles 데이터셋에
  해당 지역은 **"only the top down view"** 만 있으며, Earth 의 3D 건물은 *다른 데이터셋*이라고 답변.
  대안으로 Cesium OSM Buildings 나 자체 타일셋 업로드를 권고했다.
- Google 공식 커버리지 문서: **3D terrain(지형)은 전 세계**, **3D surface(건물·나무)는 표시된 영역 한정**.
  한국은 그 영역 밖이다.

### 2.3 왜 없는가 — 규제 배경

한국은 「공간정보의 구축 및 관리 등에 관한 법률」에 따라 정밀 측량성과의 국외 반출을 통제한다.
Google 은 2007년 이후 반복 신청했고 두 차례 불허됐다. 2025년 2월 세 번째 신청(1:5000 축척)은
5·8·11월 세 차례 유보를 거쳐 **2026년 2월 27일 "엄격한 보안 조건 준수 전제 조건부 허가"** 로 결론났다.

**중요 — 이 허가는 이번 스파이크의 문제를 풀어주지 않는다.**
허가 대상은 **1:5000 벡터 지도 데이터**(내비게이션·자율주행·위치 AI 용)이지,
**항공사진 기반 포토그래메트리 메시**가 아니다. 항공촬영 성과의 반출은 별도 심의 사안이다.
설령 파급되더라도 메시 구축 → 타일링 → 배포까지는 별개의 리드타임이 붙는다.
**2026-08-26 현재 한국에는 집 스케일 메시가 없고, 언제 생길지 약속된 바 없다.**

### 2.4 재검증 도구

`probe.html` 을 같이 만들어 뒀다. 키를 넣고 `프로브 실행` 을 누르면 남원·여수·제주·전주·서울과
대조군(도쿄·샌프란시스코)에 대해 **목표 좌표를 포함하는 자식 타일만 따라 내려가며 최심
`geometricError` 를 측정**한다.

- `geometricError ≤ 4 m` → 메시, 집 스케일 가능
- `≤ 15 m` → 거친 메시, 건물 덩어리만
- 그 이상 / 데이터 없음 → 2.5D 정사영상

키가 생기는 즉시 이 표 하나로 판정이 끝난다. 실행 비용은 지점당 루트 요청 1건이다.

## 3. 만든 것 — 무엇이 실제로 돌아가는가

`index.html` 은 Cesium + Lenis + GSAP, 전부 CDN, 정적 파일이다. 키가 없으면
**Esri World Imagery 폴백**(토큰 불필요)으로 붙는다. Cesium Ion 은 쓰지 않는다.

| 요소 | 상태 | 비고 |
|---|---|---|
| 스크롤 카메라 레일 | 동작 | 7 키프레임(지구 14,000 km → 거리 궤도 320 m). **고도는 로그 보간** — 선형이면 마지막 5%에서 전부 일어난다 |
| Lenis 관성 스크롤 | 동작 | `lerp 0.075`. 자동 촬영 중엔 `locked` 플래그로 레일을 잠근다 |
| 지구 + 대기 | 동작 | `skyAtmosphere` + `showGroundAtmosphere` + `fog` |
| 조준 앵커 이동 | 동작 | 진행도 0.50→0.76 구간에서 **군 중심(127.39, 35.41) → 탐지 밀집지(127.3065, 35.3165)** 로 스르르 옮겨탄다 |
| 구름 스프라이트 덱 | 동작 | 130장, 고도 6.8–9.4 km, **`sizeInMeters` 실측 폭 1.4–4.0 km**, 서→동 표류 |
| 우리 탐지 결과 드레이프 | 동작 | 남원 비닐하우스 + 농지 **1,411개** 폴리곤, `clampToGround` + `ClassificationType.BOTH` |
| 지점 전환 | 동작 | 남원 · 여수 · 제주 · 전주 · 서울(코엑스) |
| Google 타일셋 부착 | 코드 완성 · 미검증 | 키가 없어 실행 경로를 타지 못함. `Cesium3DTileset.fromUrl` + `showCreditsOnScreen:true` |

### 구름에서 배운 것 (재사용 가치 있음)

1. **`scale` + `scaleByDistance` 는 쓰지 말 것.** 처음 그렇게 했더니 고도에 따라 거대한
   회색 원반이 되어 화면을 덮었다 (`rail-3` 이전 시도). `sizeInMeters: true` + 실제 폭(m)으로
   바꾸니 원근이 저절로 맞는다.
2. **스프라이트 가장자리를 `destination-in` 원형 마스크로 완전히 0 까지 떨어뜨려야** 사각 경계가
   안 보인다.
3. **8 km 구름층은 카메라가 그 위에 있을 때만 보인다.** 피치 −46° 로 내려다보면 카메라와 같은
   고도의 구름은 프레임 밖(수평선 쪽)이다. 실측: 진행도 0.585(카메라 고도 ≈ 20 km)에서
   화면 안 구름 **26장**, 진행도 0.66(카메라 고도 ≈ 8.7 km)에서 **0장**.
   → 구름 통과 연출은 **레일 상 30 km → 12 km 구간**에 배치해야 한다.

### 스크린샷

| 파일 | 장면 |
|---|---|
| `rail-1-orbit.jpeg` | 지구 궤도 13,887 km — 한반도가 림에 걸린 상태 |
| `rail-2-national.jpeg` | 국토 415 km — 호남권 |

## 4. 성능

| 항목 | 값 |
|---|---|
| 측정 fps 중앙값 | 30 (전 구간) |
| **환경 rAF 상한** | **30 fps** (`requestAnimationFrame` 간격 중앙값 33.4 ms) |
| 드레이프 엔티티 | 1,411 (clampToGround ground primitive) |
| 콘솔 오류 | 0 |

**fps 30 은 렌더 병목이 아니라 헤드리스 브라우저의 천장이다.** rAF 자체가 33.4 ms 로 고정돼
있어 그 이상은 측정 불가다. 즉 이 씬은 *최소한* 30 fps 이며 실제 상한은 알 수 없다.
드레이프 1,411개를 얹고도 상한에 붙어 있다는 점만 유의미하다.

타일 로딩 시간 · 메모리는 **키가 없어 측정하지 못했다** (`tilesLoaded 0`, `tilesMemMB 0`).
이 항목은 미해결이며, 키 확보 시 `__spikeStats()` 로 바로 나온다.

## 5. 비용

Map Tiles API — Photorealistic 3D Tiles (SKU `C6E1-98B2-DBD0`, **Enterprise** 등급)

| 구간 (요청/월) | 단가 (1,000건당) |
|---|---|
| 무료 제공량 | **1,000건/월** |
| 0 – 100,000 | **$6.00** |
| 100,001 – 500,000 | $5.10 |
| 500,001 – 1,000,000 | $4.20 |
| 1,000,001 – 5,000,000 | $3.30 |
| 5,000,000+ | $2.40 |

과금 단위는 **루트 타일셋 요청 1건 = 1 이벤트**(맵 '세션' 개념). 하위 타일 요청은
별도 과금·쿼터에 잡히지 않는다. 일일 상한은 **루트 타일셋 쿼리 10,000건/일**.

### 월 10,000 방문 시나리오

| 케이스 | 계산 | 월 비용 |
|---|---|---|
| **정상 — 방문당 타일셋 1회 인스턴스화** | (10,000 − 1,000) × $6.00/1,000 | **$54** (약 7.5만원) |
| 지점 전환마다 새 타일셋 생성 (5지점) | (50,000 − 1,000) × $6.00/1,000 | $294 |
| 월 100,000 방문 | (100,000 − 1,000) × $6.00/1,000 | $594 |

$54/월 자체는 감당 가능한 수준이다. **비용은 이 결정의 걸림돌이 아니다.**
다만 구현상 함정이 하나 있다 — 타일셋은 전 지구를 덮으므로 **앱 생애 동안 단 하나만 만들고
재사용해야 한다.** 지점 전환마다 `Cesium3DTileset.fromUrl` 을 다시 부르면 비용이 5배가 된다.
(이번 스파이크 코드는 부팅 시 1회만 부른다.)

참고로 2D Map Tiles 는 무료 100,000건 + 이후 $0.60/1,000 로 **10배 저렴**하다.
3D 는 명백히 프리미엄 SKU다.

| **공공 조달** | 공공기관 납품 시 국내 공간정보(브이월드·국토정보플랫폼) 사용과 CSAP 를 요구하는 경우가 많다 | **높음** — 미국 호스팅 3D 베이스맵이 조달 요건에서 탈락 사유가 될 수 있다 |

가장 무거운 두 개는 **파생 데이터셋 금지**와 **공공 조달**이다. 둘 다 Land-XI 의 사업 핵심에
정면으로 닿는다. 커버리지가 있었더라도 재고해야 할 항목이다.

## 7. 우리 정사영상과의 품질 비교 — 그리고 대안

| | Google (한국) | 우리 자산 |
|---|---|---|
| 형태 | 지형 + 정사영상 (2.5D) | 지형 + 정사영상 (2.5D) — 현재 동일 |
| 해상도 | 위성급, 뭉개짐 | **z19 ≈ 0.24 m/px** (`landxi/assets/tiles/namwon_2510` 등) |
| 시점 | 갱신 시점 통제 불가. 제주는 **2015년** | **2025년 4·6·8·10월 4시점** (`namwon_2504/2506/2508/2510`) |
| 변화 분석 | 불가 | **가능** — `namwon_change_2504_2510` 이미 존재 |
| 메시(집 형상) | **없음** | 없음 — 만들어야 함 |
| 비용 | $54/월~ | 0 (자체 호스팅) |
| 법적 제약 | 파생 금지 · 캐시 금지 · 크레딧 강제 | 없음 |

**즉 Google 을 붙여도 한국 지표의 품질은 우리 것보다 나빠진다.** 해상도도 낮고 시점도 낡았고
제약만 생긴다. 얻는 것은 "지구 전체가 매끄럽게 이어진다"는 원경 연출 하나뿐이다.

### 권고 — 하이브리드 B안

1. **원경(지구 · 대륙 · 국토)**: Cesium 기본 지구 + 대기 + 우리 구름 덱. Google 불필요.
   필요하면 무료 위성 베이스맵(Esri)으로 충분하다. 이번 스파이크가 이미 그렇게 돌아간다.
2. **근경(지역 · 마을 · 거리)**: **우리 정사영상 z19** + Terrarium DEM
   (`landxi/assets/data/3d/terrain-namwon`, z9–14) 로 교체.
3. **주택·마을 3D**: 건물 풋프린트를 **압출(extrude)** 한다.
   `landxi/assets/data/3d/_raw-namwon-overture.geojson` 에 **남원 5,231동**이 이미 있다.
   - 단, **높이 속성이 전부 비어 있다** (`height` 0건, `num_floors` 1건, 분류도 5,115동이 null).
   - 높이는 우리가 만들어야 한다 → **드론/항공 DSM − DTM** 이 가장 정확하고,
     차선은 용도·면적 기반 휴리스틱(농촌 주택 1–2층, 비닐하우스는 곡면 프로파일).
   - 비닐하우스는 압출이 아니라 **아치 프로파일 메시**로 세워야 남원이 남원처럼 보인다.
     이건 우리만 할 수 있는 차별화이기도 하다.
4. **탐지 결과 드레이프**: 이번 스파이크 코드 그대로 재사용 가능
   (`clampToGround` + `ClassificationType.BOTH`, 1,411개에서 성능 문제 없음).

이 경로는 Google 대비 **비용 0, 법적 제약 0, 해상도 우위, 시계열 우위**이고,
무엇보다 "우리가 직접 만든 남원"이라는 서사가 선다. 추가 작업은 **건물 높이 산출**
하나로 수렴한다.
