## 4. 기술 해부 — worldflight 모드가 실제로 하는 일

### 4.1 DOM 구조 (문서 흐름에 있는 건 스페이서 단 하나)

```html
<div data-sc-mode="worldflight" data-sc-seam="0.16" data-sc-lerp="0.12">
  <div data-sc-world>                          <!-- position:fixed 스테이지 1개 -->
    <div data-sc-segment data-sc-w="1.08" data-sc-linger="0.3" data-sc-waypoint="Kyoto">
      <img class="sc-world__poster" src="assets/p1.webp" decoding="async">
      <video data-sc-src="assets/leg1.mp4" data-sc-src-mobile="assets/leg1-m.mp4"></video>
    </div>
    <!-- ... 총 10개 leg, 전부 동시 마운트 상태 유지 -->
  </div>
  <div data-sc-world-copy> ... 고정 오버레이 카피 레이어 ... </div>
  <div data-sc-spacer aria-hidden="true"></div>   <!-- 유일한 문서 흐름 요소 -->
</div>
```

### 4.2 핵심 규칙 (원문 "Hard rules")

1. **스페이서 외에는 문서 흐름에 아무것도 두지 않는다.** 블록이 흐르는 순간 씸이 생긴다.
2. **`src`를 절대 교체하지 않는다.** src 스왑 = 검은 프레임 = 이 모드가 없애려는 바로 그 컷.
3. **크로스페이드는 한쪽만.** 들어오는 leg가 0→1로 올라오는 동안 나가는 leg는 **밑에서 풀 강도 유지**,
   완전히 가려진 뒤에야 0으로 떨어진다. 양쪽 동시 페이드는 씸마다 페이지 바탕이 비쳐 **플래시**로 읽힌다.
   z-index는 현재 leg 120, 나머지 `100 + opacity×10`.
4. **lerp는 절대 끄지 않는다**(reduced-motion 제외). 1:1 플레이헤드는 휠 이벤트의 빈틈을 그대로 스터터로 재생한다.
5. **전체 비행 페이스 1개.** `rate = weight / clip_seconds`를 수 % 이내로 유지. orrery는 초판 36% 편차 → 6%로 수정.
6. **씸 프레임은 인코딩된 mp4에서 추출.** 인코딩이 픽셀을 바꾸므로 프리인코드 마스터에서 뽑으면 안 맞는다.
7. **카피의 유일한 transform은 `translateY`, 창 전체에서 4vh 상한.**

### 4.3 플레이헤드 수학 (`engine/scrollcraft.js`)

```js
// 1) 스페이서 높이 = (Σ leg weight + 1) × innerHeight
// 2) t = 스크롤 위치(vh 단위). leg i는 [c_i, c_i + w_i) 소유.
//    local = (t - c_i) / w_i  ->  lingerEase(local, linger)
function lingerEase(x, L) {                 // 단조 dwell 리맵
  if (!L) return x;
  L = clamp(L, 0, 0.6);                     // 0.6 초과 시 중앙에서 카메라가 죽어버림
  var c = x - 0.5;
  return (1 - L) * x + L * (4*c*c*c + 0.5); // f(0)=0, f(1)=1 고정 -> 씸 프레임 불변
}

// 3) rAF 루프에서 감쇠 후 seek (read()와 분리: seek은 비동기·디코더 율속)
V.cur += (V.target - V.cur) * (reduce ? 1 : V.lerp);   // lerp 0.12
var dur = V.el.duration || 1;
var t   = clamp(V.cur, 0, 0.999) * dur;
var eps = isMobile() ? 0.02 : 0.008;                   // 데드밴드
if (Math.abs(V.el.currentTime - t) > eps) V.el.currentTime = t;
```

부가 방어 로직: `V.el.seeking` 중에는 seek을 큐에 쌓지 않되 **700ms 이상 걸린 seek은 재발행**,
오프스크린 클립은 `|cur-target| < 0.002`면 비용 0으로 스킵,
iOS는 muted 비디오에 제스처를 주기 전엔 페인트하지 않으므로 **클립마다 1회 `play()`→`pause()` 프라이밍**.

### 4.4 에셋 파이프라인

- **생성**: kie.ai 경유 image→video (Veo 3.1 / Kling 3.0 / Seedance 등). 이미지 먼저, 그다음 영상.
- **씸 법칙 A(권장)**: leg는 **시작 이미지로만 체인**한다. 다음 leg의 시작 이미지 =
  이전 leg **인코딩된 mp4의 마지막 프레임**. 끝 이미지까지 강제하면 모델이 카메라를 뒤로 빼서
  모든 leg가 똑같은 와이드 설정샷이 된다.
  ```bash
  ffmpeg -sseof -0.15 -i legN.mp4 -frames:v 1 -q:v 2 chainN.png   # 다음 leg 시작 이미지
  ffmpeg -i legN.mp4 -frames:v 1 -q:v 3 pN.webp                   # 포스터
  ```
- **인코딩(`encode.sh`)**: **스크럽 전용 조밀 GOP.**
  - 데스크톱 `scale=-2:1080 -g 8 -crf 20`, 모바일 `scale=-2:720 -g 4 -crf 24`
  - 오디오 제거(`-an`), `-movflags +faststart`, `-pix_fmt yuv420p`
  - 일반 웹 인코딩은 키프레임 간격 2–5초 → seek마다 디코더가 앞 키프레임부터 걸어와서 휠 밑이 진흙이 된다.
  - 실측 용량: 데스크톱 클립당 **5–6MB**(crf 20). 그레인 많은 소재는 22–23으로.
- **로딩**: leg는 **±1.6vh 이내일 때만** fetch. 첫 실프레임 전까지는 포스터가
  `scale(1.03 + local × 0.14)` push-in으로 카메라 무브를 대신한다.
- **reduced-motion**: **클립을 아예 받지 않는다.** 포스터들이 동일 씸·동일 카피창으로 크로스디졸브하며
  이야기 전체가 그대로 읽힌다.

### 4.5 레일/HUD는 엔진이 안 만든다

엔진은 `--sc-seg`(현재 leg 인덱스)와 `--sc-segp`(leg 내 진행도)를 모드 루트와 `:root`에 쓰고,
leg가 바뀌면 `sc:waypoint` CustomEvent(`detail: {index, count, label, el, progress}`)를 발화할 뿐이다.
좌하단 베어링 다이얼도, elsewhere field 60개 마커도 **전부 페이지 자체 코드**다.

### 4.6 검증 하니스

- `scripts/shoot.mjs` — 스페이서 트랙 전체 샘플링 + 씸마다 4포인트 추가, lerp 수렴 대기 후 촬영.
  **dead scroll**(0.12vh 이상 이동했는데 currentTime·크로스페이드·카피 opacity 전부 불변),
  **full opacity에 도달 못하는 leg**, **포스터에 갇힌 leg**, 카피 대비 검사를 보고.
- `scripts/worldflight-assert.mjs` — 스페이서 높이, fixed 스테이지, 문서 흐름 비었는지,
  lerp 수렴·비오버슛, 씸 단조성, 카피 transform 상한, reduced-motion 계약을 기계적으로 단언.

## 6. 100% 재현 계획 (우리 정적 사이트 제약 위에서)

### 6.0 결정적 사실: 이건 우리 스택으로 **완전 재현 가능**하다

MapLibre도 deck.gl도 three도 Cesium도 **필요 없다.** 필요한 것은
`<video>` + `position:fixed` + rAF 하나다. GPU 부담이 사실상 없고 정적 호스팅과 완벽히 맞는다.
(역설적으로 우리가 준비한 WebGL 스택은 이 화면에 **전혀 쓰이지 않는다.**)

### Top 5 실행 항목

**1. 스크럽 엔진을 먼저 이식한다 (반나절).**
`scroll-craft`는 MIT 라이선스이므로 `engine/scrollcraft.js`의 worldflight 경로를 그대로 쓰거나
150줄 규모로 재작성한다. 필수 불변식 7가지(§4.2)를 그대로 지킬 것.
특히 **한쪽만 크로스페이드**와 **src 절대 미교체**는 타협 불가 — 어기면 씸마다 검은 플래시가 난다.
`data-sc-seam="0.16"`, `data-sc-lerp="0.12"`부터 시작.

**2. 필름을 먼저 만들고 페이지를 나중에 만든다 (여기가 전체 공수의 90%).**
10 leg × 5초(피크 1개만 10초) ≈ **60초 분량**. 아트디렉션 프리앰블을 **한 글자도 바꾸지 말고**
모든 프롬프트 맨 위에 붙여넣는 것이 여러 에셋을 한 촬영처럼 보이게 하는 유일한 방법이다.
우리 버전 프리앰블(예: 남원 실경 기반):

> 수제 물리 스케일모형, 매크로 틸트시프트. 밀링 황동, 채색 석고, 진짜 이끼, 주조 레진,
> 체질한 모래, 광섬유 실연 조명. 저조도 단일 웜 키, 딥 폴오프. NOT 3D render, NOT clay, NOT CGI.

**씸 법칙 A 준수**: leg N+1의 시작 이미지 = leg N **인코딩된** mp4의 마지막 프레임(`-sseof -0.15`).
끝 이미지를 강제하지 말 것.

**3. 페이스를 숫자로 고정한다.**
`rate = weight / clip_seconds`를 **0.212–0.225 vh/초**로 전 leg 통일(편차 6% 이내).
5초 클립 → `data-sc-w="1.08"`, 10초 피크 → `2.25`. 스페이서 = (Σw + 1) × innerHeight.
이 한 줄이 "부드럽다/안 부드럽다"를 가르는 지점이다(초판 36% 편차 = "not smooth").

**4. 인코딩은 스크럽 전용으로.**
`-g 8 -crf 20 scale=-2:1080` 데스크톱 / `-g 4 -crf 24 scale=-2:720` 모바일, `-an -movflags +faststart`.
**일반 웹 인코딩을 쓰면 재현 실패한다.** 포스터는 인코딩된 mp4의 첫 프레임에서 webp로.
예산: 데스크톱 10클립 × 5–6MB ≈ **55MB**, 모바일 별도. ±1.6vh 지연 로딩 필수.

**5. HUD와 elsewhere field는 우리가 직접 만든다.**
엔진은 `--sc-seg` / `--sc-segp` / `sc:waypoint`만 준다.
- 베어링 다이얼: SVG 원 + 워드마크 허브, 디스크가 페이지 전체에 정확히 1회전,
  각 목적지 실제 경도에 핍. 우리 버전은 남원 127.4E 등 실좌표 사용.
- 현재 목적지는 **악센트 사각 마커로만** 표시(색 변경 금지). **페이지에 숫자 0개** 원칙 유지.
- elsewhere field: 마커 60개 깊이별 패럴랙스, 낙하 구간에 `--sc-segp` 기반 방사형 스트리크,
  포인터 올리면 그 마커만 갱신 중단(=freeze) + 이름/한 줄 노출, 클릭/탭으로 고정, Esc 해제.
- 마감: "도착이 아니라 귀환" — 마지막 프레임이 첫 프레임과 운을 맞추게.
