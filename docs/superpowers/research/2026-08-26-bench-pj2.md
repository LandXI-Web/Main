### 1-2. 원본 골격의 문제(우리가 고칠 것)
- 레일이 **3겹(75+200+392=667px)** — 라벨링/학습/분석에서 지도가 773px만 남는다. 지도는 우리 1급 자산인데 절반도 안 된다.
- 그룹 목차 8항목 중 **3개(파일/데이터셋/모델등록)는 표 1장짜리 페이지**, 3개(라벨링/학습/분석)는 **지도 작업공간** — 같은 사이드바에 성격이 다른 두 종류가 섞여 있다.
- 개요 페이지의 "작업 공간 3버튼"은 사이드바와 **중복 진입**.
- 초성 타일(도/사/곤/비/농/방…)이 실사 썸네일을 대체 — 남원 정사영상이 있는데 글자 타일을 쓴다.
- 카드 발행 요청 → 발행 폼이 프로젝트 사이드바 밖(별 페이지)으로 빠져 컨텍스트가 끊김.

## 2. 대상별 해부 (흰 바탕에서 빌릴 것만)

### 2.1 Roboflow Universe — `universe.roboflow.com/roboflow-universe-projects/construction-site-safety` 〔LIVE〕 `roboflow-universe-1,2,4.jpg` `roboflow-images-1.jpg`
정체: CV 프로젝트 공개 허브. 우리와 가장 가까운 **"프로젝트 = 이미지 + 데이터셋 버전 + 모델"** 구조.
- **셸 `56 | 1384`**: 아이콘 레일 56px(남색 `#141c2e`)만 두고 나머지는 흰 종이. 프로젝트 이름 30px/600 Inter 2줄 + 실사 히어로 **420×240**(우상단, 박스 표시된 실제 추론 이미지) — 첫 화면 이미지 15.4%.

| **T1 고정 헤더 + 상단 탭** | 프로젝트 헤더(제목·썸네일·CTA) 고정, 아래 탭으로 본문 교체 | Kaggle 7탭(헤더 320 고정) · HF 3탭 · Roboflow 3탭 | 5–7 | 프로젝트 정체성이 항상 보임, URL `?tab=` 1단 | 8개 넘으면 탭이 밀림, 작업공간(지도)엔 헤더가 낭비 |
| **T2 탭 × 좌측 목차 2단** | 탭 안에서 다시 좌 레일로 세분 | Roboflow Dataset 탭(`Versions` 272px 레일 + 상세) | 3×n | 탭 수를 억제하면서 n을 무한히 | 레일 2겹(원본의 문제 재현 위험) |
| **T3 좌측 목차 1단(그룹형)** | 그룹 헤더 + 항목 목차 하나, 본문 전폭 | 원본 `project-sidebar` 4그룹 8항목 · Vercel/Supabase/ncloud 문서 목차 | 8–20 | 전부 한눈에, 깊이 2단 표현 | 항목 성격(표 vs 작업공간) 섞임, 레일 200–360 고정 소모 |
| **T4 한 장 롱페이지(세그먼트 + 아코디언/앵커)** | 하위 화면을 페이지 섹션으로 펴고 우측 "On this page" 앵커 | AI허브 상세(2세그먼트 × 9아코디언) · Airflow/Encord 우측 목차 | 6–12 | URL 하나, 스크롤로 전체 파악, 인쇄 가능 | 작업공간(지도·폼)은 섹션에 못 넣음, 닫힌 아코디언은 첫 화면 0 |
| **T5 상태 열 보드/이력 스트림** | 하위 항목을 상태별 열(칸반) 또는 시간 스트림으로 | GitHub Projects 4열 · Airflow 상태 막대 · Prefect 상태 도식 | 상태 4–5 | 진행 상황이 화면 구조 그 자체 | 정적 설정(개요·파일)은 못 담음 |
| **T6 드로어/작업공간 전환** | 목록 → 클릭 시 우측 드로어(원본 학습 결과) 또는 캔버스 전체 전환(원본 라벨링 `&did=`) | 원본 training-run 드로어 392+392 · Label Studio 캔버스+우측 툴바 | 무제한 | 컨텍스트 유지, 뒤로가기 명확 | 드로어가 겹치면 캔버스 실종(원본 1-2) |

관찰: 실서비스(Kaggle·HF·Roboflow)는 예외 없이 **T1을 뼈대로 두고 필요한 탭에서만 T2/T6로 판다.** 문서형(T3/T4)은 읽기용이지 작업용이 아니다. 원본은 T3 단독이라 작업공간에서 레일이 3겹이 됐다.

## 4. Land-XI 프로젝트 적용 골격 후보 5 (순위)

우리 하위 메뉴 12개: ① 목록 ② 만들기 ③ 개요(수정·초대) ④ 파일 ⑤ 라벨링 ⑥ 데이터셋 ⑦ 학습 ⑧ 분석 ⑨ 모델 등록 ⑩ 발행 요청 ⑪ 발행 폼 ⑫ (공통) 사이드바. 아래 각 후보에 12개를 모두 배치했다.

### 후보 1 ★ "헤더 고정 + 5탭 + 작업공간 풀블리드" (T1 + T6) — Kaggle × Roboflow × 원본 라벨링
- 프로젝트 헤더(높이 200): 프로젝트명 **48px** + 남원 정사영상 실사 썸네일 320×180(초성 타일 폐기) + kv 4(탐지유형·데이터유형·GSD·최근 학습) + 검정 CTA 1개(다음 할 일: "라벨링 이어하기" 등 상태에 따라 바뀜) + `수정 · 구성원 초대`(텍스트 버튼).
- **탭 5**: `개요 · 데이터 (파일 12·데이터셋 2) · 라벨링 · 학습 5 · 분석 · 배포` → 실제로는 6이지만 원본 8항목을 **Data/Models/Deploy 그룹 = 탭**으로 접어 `개요 · 데이터 · 라벨링 · 학습 · 분석 · 배포` 6탭, 배지에 개수.
- 매핑: ③→개요 탭(kv+구성원+최근 활동 스트림) · ④⑥→데이터 탭 안 **세그먼트 2(파일 | 데이터셋)** · ⑤→라벨링 탭 = **헤더 접고 지도 풀블리드**(1440−56 레일 = 1384px), 영상 목록은 좌측 320 드로어(접힘 가능), 라벨 목록은 우측 320 드로어 · ⑦→학습 탭 = 이력 카드 목록 + 클릭 시 결과 **드로어 480**(지도 불필요, 흰 바탕) · ⑧→분석 탭 = 지도 풀블리드 + 좌 픽커 드로어(원본 3탭은 세그먼트로) · ⑨⑩⑪→배포 탭 안 세그먼트 2(모델 등록 | 발행 요청) + 발행 폼은 같은 탭 안 우측 드로어 720 · ①→목록은 상위(레일 아이콘) · ②→목록 우상단 CTA → 폼 드로어.
- 왜 1위: 실서비스 3곳이 검증한 뼈대, 레일 1겹(56px)으로 원본의 667px 문제를 해결, 지도 1384px 확보, URL `?pid=&tab=` 1단 유지.
- 리스크: 라벨링/분석 탭에서 헤더가 접히는 전환 애니메이션 필요.

### 후보 2 "좌측 그룹 목차 1단 + 본문 전폭" (T3 개선) — 원본 골격 유지, 레일 다이어트
- 원본 `project-sidebar` 4그룹 8항목을 그대로 두되 **아이콘 레일 75 + 그룹 목차 200 → 하나의 240px 레일로 합침**(글로벌 메뉴는 레일 하단 아이콘 5개로 축소). 본문 1200px.
- 매핑: 원본 1:1(③~⑩). ⑤⑧은 본문 안에서 **목록 패널을 240px 오버레이 드로어**로 바꿔 지도 1200 확보. ⑪은 ⑩ 페이지 안 드로어.
- 왜 2위: 구현 최소, 이해관계자가 이미 아는 구조. 단 "표 페이지 vs 작업공간" 혼재는 그대로.

### 후보 3 "개요 한 장 롱페이지 + 작업공간은 별도 모드" (T4 + T6) — AI허브 × Airflow 우측 목차
- 프로젝트 = 한 장 스크롤: `개요 → 구성원 → 파일 → 데이터셋 → 학습 이력(상태 막대) → 분석 이력 → 모델 → 발행 이력` 8섹션, 우측 "이 페이지에서" 앵커 목차 8. 각 섹션은 요약 표 5행 + "전체 보기".
- 작업(라벨링/분석/학습 새로)은 섹션의 CTA로 **풀스크린 모드** 진입(레일 56만).
- 매핑: ③④⑥⑦⑧⑨⑩→섹션, ⑤→풀스크린, ⑪→섹션 내 드로어, ②→목록 CTA.
- 왜 3위: 프로젝트 상태를 한 번에 읽는 데 최고(발주자 검토용). 그러나 표 8개를 한 장에 두면 첫 화면 이후 정보 밀도가 균질해져 위계가 죽는다(AI허브 안티패턴).

### 후보 4 "상태 보드가 곧 프로젝트" (T5 + T1) — GitHub Projects × Prefect
- 개요 탭 대신 **파이프라인 보드**: 열 = `파일 → 라벨링 → 데이터셋 → 학습 → 분석 → 발행` 6열, 각 열에 해당 항목 카드(영상 3장, 데이터셋 2, 학습 5…) 상태칩. 카드 클릭 = 드로어.
- 나머지 탭은 후보 1과 같음(설정·구성원은 "설정" 탭).
- 매핑: ④⑤⑥⑦⑧⑩→열, ③→설정 탭, ⑨→발행 열 카드, ⑪→드로어, ②→목록.
- 왜 4위: 진행 상황 가시성 최고, 남원 사업 보고에 강함. 하지만 열 6개 × 카드는 1440에서 열 폭 220 — 실사 썸네일이 작아지고, 지도 작업은 어차피 별도 모드.

### 후보 5 "탭 × 좌측 목차 2단" (T2) — Roboflow Dataset 탭형
- 탭 3(`데이터 · 모델 · 배포`) + 각 탭 안에서 좌 272px 목차(데이터: 파일/라벨링/데이터셋, 모델: 학습/분석, 배포: 모델 등록/발행 요청).
- 매핑: 원본 그룹 = 탭, 항목 = 목차. ③은 탭 밖 헤더에 흡수.
- 왜 5위: 원본 그룹 구조를 가장 충실히 옮기지만 **레일이 다시 2겹(56+272)**, 라벨링에서 원본 문제 재발.

**추천**: 후보 1을 기본으로, 개요 탭의 내용을 후보 3의 "요약 섹션 + 앵커" 방식으로 채우고, 학습 탭의 이력은 후보 4의 상태 열(대기/진행/완료/실패, Prefect 색 어휘)로 보여준다.
