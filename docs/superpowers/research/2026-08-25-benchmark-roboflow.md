# Roboflow 벤치마크 심층 리포트 — Land-XI 개편을 위한 UX 해부와 이식 설계

작성일: 2026-08-25
대상: Land-XI(LX 국토정보공사) Geo-AI 플랫폼 개편 — 노코드 워크플로우 기반 AI 모델 개발 + 전국 AI 국토조사
전제: 발주처가 Roboflow를 벤치마크로 지정했고, 1차 시안을 "딱딱하고 정적이며 목업 수준"이라고 반려함.

---

## 0. 이 리포트의 결론을 먼저

Roboflow가 "살아있다"고 느껴지는 이유는 화려한 애니메이션 때문이 아니다. **모든 화면이 "지금 이 순간 진짜 모델이 돌고 있다"는 증거를 화면 안에 상주시키기 때문**이다.
구체적으로는 다음 세 가지가 전부다.

1. **결과 이미지가 UI의 1급 시민이다.** 노드 카드 안에, 미리보기 패널 안에, 데이터셋 카드 썸네일 안에, 혼동행렬 셀 안에 — 어디를 눌러도 "박스가 그려진 실제 이미지"가 나온다. 텍스트/표만 있는 화면이 거의 없다.
2. **파라미터는 즉시 그림을 바꾼다.** confidence 슬라이더를 끌면 박스가 사라지고, 혼동행렬 숫자가 갱신되고, 클래스별 성능 막대가 다시 그려진다. "설정 → 저장 → 재실행"이라는 3단 지연이 없다.
3. **모든 중간 단계가 열람 가능하다.** 워크플로우의 각 블록은 자기 출력을 JSON/Visual 두 탭으로 보여주고, 캐시 배지("Cached"/"Not Cached")로 자기 계산 상태까지 노출한다. 블랙박스가 없다.

Land-XI 1차 시안이 "정적"이라고 반려된 이유는 정확히 이 세 가지의 부재다. 워크플로우 캔버스가 **다이어그램**이지 **실행 가능한 파이프라인**이 아니었고, 결과 지도가 **완성된 사진**이지 **조작 가능한 레이어**가 아니었다.

이 리포트는 (1) Roboflow의 실제 UI를 화면 단위로 해부하고, (2) 그것을 "살아있게" 만드는 인터랙션 패턴 14개를 추출하고, (3) Land-XI의 5개 핵심 화면에 ASCII 와이어프레임과 함께 이식안을 제시하고, (4) 18항목 "Roboflow-ness 체크리스트"로 마감한다.

## 1. Roboflow 제품 UX 해부

### 1.1 Workflows — 노드 캔버스

출처:
- 제품 페이지 https://roboflow.com/workflows
- 블록 라이브러리 https://roboflow.com/workflows/build
- 빌더 문서 https://docs.roboflow.com/workflows/build/build-a-workflow
- 테스트 문서 https://docs.roboflow.com/workflows/build/test-a-workflow
- Hello World https://docs.roboflow.com/workflows/tutorials-1/hello-world
- 모델 비교 https://docs.roboflow.com/workflows/tutorials-1/compare-models
- 소객체 SAHI https://docs.roboflow.com/workflows/tutorials-1/detect-small-objects
- Builder 2.0 런칭 https://blog.roboflow.com/launch-workflows-builder-2-0/
- 최초 런칭 https://blog.roboflow.com/workflows/
- 블록 카탈로그 https://docs.roboflow.com/workflows/blocks/blocks

**핵심 개념.** 워크플로우는 "블록(Block)"의 그래프다. 현재 카탈로그는 **177개 블록**이며 문서상 9개 카테고리로 묶인다: `Run a Model`, `Visualize Predictions`, `Logic and Branching`, `Data Storage`, `Notifications`, `Transformations`, `Classical Computer Vision`, `Video Processing`, `Advanced Blocks`. 마케팅 페이지는 이를 Model / Transformation / Flow Control / Fusion / Tracker / Sink / Notifications / Utility 로 다르게 라벨링해 필터 칩으로 제공한다. 헤드라인 카피는 "Building Blocks for Custom Pipelines. Blocks receive inputs, execute code, and send outputs to the next block in your Workflow."

**노드 카드의 구조.** 각 블록은 카드다. 카드 상단에 블록 고유 아이콘 + 이름, 본문에 핵심 파라미터 요약, 하단에 **출력 포트 옆의 `+` 버튼**이 붙는다. Hello World 문서는 "Object Detection Model 블록 하단의 `+` 버튼을 눌러 시각화 블록을 추가한다"고 명시한다 — 즉 **다음 블록 추가가 포트에서 시작한다.** 또 모델 비교 튜토리얼은 블록 옆의 **"Fork" 버튼**을 눌러 병렬 브랜치를 만든다고 설명한다. 이 두 개(`+`, `Fork`)가 캔버스의 주 동사다. 드롭다운을 뒤지는 대신 **포트에서 끌어다 연결**하는 Drag-to-Connect가 Builder 2.0의 간판 기능이다("Instead of searching through drop downs to find available outputs, you drag a connection from one block to another, making the data flow through your workflow instantly clear").

**연결 규칙이 곧 레이아웃이다.** 문서는 "블록은 이전 블록의 출력을 입력으로 써야 배치될 수 있다"고 못박는다. 서로 의존하지 않는 블록은 **좌우로 나란히** 놓이고 런타임에 병렬 실행된다. 즉 **캔버스의 x축은 의존성 깊이, y축은 병렬 분기**라는 읽기 규칙이 존재한다. 사용자가 그래프를 보면 "무엇이 동시에 도는지"를 알 수 있다.

**Builder Assist (3단 자동화 강도).** 우상단 토글로 `Auto` / `Quick` / `Manual`을 고른다.
- Auto(기본): 호환 필드를 자동 배선하고, 블록을 지우면 **하류 참조를 자동 복구**한다.
- Quick: 제안만 하고, 사용자가 수락해야 적용.
- Manual: 제안 없음.
선택은 브라우저에 저장되어 세션을 넘어 유지된다.

**Auto Layout.** 툴바의 sitemap 아이콘으로 현재 블록을 자동 정렬 + 화면 맞춤. 옆의 chevron은 "Arrange now"(1회) / "Arrange automatically"(블록 추가·연결 변경 때마다 재정렬) 메뉴를 연다. **블록을 손으로 드래그하면 자동 정렬이 일시 정지**되어 수동 배치가 보존된다. 이 "손을 대면 자동이 물러난다"는 예의가 캔버스를 짜증나지 않게 만든다.

**설정 사이드바.** 블록을 선택하면 우측 사이드바에서 파라미터를 편집한다. Object Detection 블록의 파라미터는 문서에 명시되어 있다: `Image`(필수), `Class Filter`, `Confidence`, `IoU threshold`, `Max Detections`, `Class Agnostic NMS`. 시각화 블록은 색상/두께/텍스트(class name / confidence / class+confidence) 옵션을 갖는다.

**테스트/디버그 = Test Workflow 패널.** 에디터 상단 "Test Workflow" 버튼 → 우측(또는 하단)에서 테스트 페인이 열린다.
- 입력: Image 탭(JPG/PNG/WEBP 드래그앤드롭, GIF 불가) 또는 Video 탭(웹캠·RTSP; Dedicated Deployment 또는 self-hosted 필요).
- 실행: "Run".
- 출력: 기본 **JSON 탭**(Outputs 블록에 설정된 값 전부), 시각화 블록이 있으면 **Visual 탭**으로 렌더 이미지. 썸네일을 클릭하면 확대.
- **Use Block Cache**(기어 아이콘): 켜면 변경 없는 블록의 결과를 재사용하고, 각 블록에 **"Cached" / "Not Cached" 배지**가 붙는다. 특정 블록만 "Uncache"로 매번 재계산 지정 가능. 크레딧과 시간을 아끼는 장치이자 **그래프 위에 실행 상태를 시각화하는 장치**이기도 하다.
- **Enable Sinks**: 외부에 쓰는 Sink 블록은 테스트 중 기본 비활성. 체크해야 실제로 실행된다 → "테스트가 데이터를 망치지 않는다"는 안전 계약.

**출력 블록(Outputs).** 별도 블록으로 존재하며, 필드를 **삭제**하거나 **Move Up/Down으로 순서 변경**할 수 있다. Hello World 튜토리얼은 "시각화를 JSON 위로 올려라"라고 가르친다 — 즉 **응답 스키마 자체가 캔버스에서 편집되는 대상**이다.

**버전/공유.** 저장할 때마다 버전이 쌓인다. 우측 사이드바 **시계 아이콘** → 버전 히스토리 패널, 최신 버전에 **"Live" 배지**, 3점 메뉴로 Rename / Restore. Share Workflow 버튼 → Copy Share Link → **읽기 전용 + 프리뷰 실행 가능한 공개 URL**. 기본적으로 공유본은 소유자 API 키로 돌지 않으며(크레딧 비소모), "Run access" 드롭다운으로 자기 키로 돌게 허용할 수 있다. 문서 페이지 안에 워크플로우가 **iframe 임베드로 삽입되어 독자가 그 자리에서 실행**한다(가위바위보 예제).

**AI Assistant / Roboflow Agent.** 사이드바의 "Agent"는 자연어로 워크플로우를 **만들고, 실행하고, 실패를 자동 수정**한다. 이미지·영상을 채팅에 드래그하면 내용을 이해해 워크플로우를 만들고 **같은 미디어로 재실행해 검증**한다. 실행 오류가 나면 채팅 입력창 위에 **"Investigate" 프롬프트**가 뜬다. 장기 작업(학습, 오토라벨링, 버전 생성, 프로젝트 병합)은 백그라운드로 돌고 채팅 위 **알약(pill) 카운터**가 개수를 표시한다. 웹캠·RTSP 프리뷰는 **최근 2.5분 결과를 기억**해서 스트림을 멈추지 않고도 "방금 뭘 봤냐"고 물을 수 있다. (https://docs.roboflow.com/agents/roboflow-agent)

**대형 이미지 대응 — SAHI.** `Image Slicer` → 모델 → `Detections Stitch` 3블록으로 슬라이싱 추론을 구성한다. "Image Slicer와 Stitch 사이의 모든 것은 슬라이스 집합에 대해 element-wise로 동작하고, Workflows가 가능한 곳에서 자동 병렬화한다." **정사영상 타일 추론과 개념이 1:1로 대응**하는 대목이라 Land-XI에 그대로 옮길 수 있다.

**모델 비교 블록.** `Model Comparison Visualization`은 두 모델의 예측을 한 이미지에 겹쳐 그린다. 판독 규칙이 명시적이다 — **어두움 = 둘 다 미검출, 밝음 = 둘 다 검출, 초록 = A만, 빨강 = B만.** 남원 4시점 정사영상의 **시점 간 변화 탐지**에 그대로 쓸 수 있는 시각 문법이다.

### 1.2 Annotate — 라벨링

출처:
- 제품 페이지 https://roboflow.com/annotate
- 라벨링 인터페이스 https://docs.roboflow.com/datasets/annotate/annotate/use-roboflow-annotate
- 단축키 https://docs.roboflow.com/datasets/annotate/annotate/use-roboflow-annotate/keyboard-shortcuts
- Smart Select(SAM) https://docs.roboflow.com/datasets/annotate/annotate/ai-labeling/smart-select
- Label Assist https://docs.roboflow.com/datasets/annotate/annotate/ai-labeling/model-assisted-labeling
- Box Prompting https://docs.roboflow.com/datasets/annotate/annotate/ai-labeling/box-prompting-ai-labeling
- Auto Label https://docs.roboflow.com/datasets/annotate/annotate/ai-labeling/auto-label

제품 페이지 카피: "The Fastest Way to Label Computer Vision Datasets", 75만+ 데이터셋 / 5억 7,500만+ 이미지 라벨링. Label Assist는 "reduce human labeling time by 95%"를 주장한다.

**툴바는 오른쪽.** 도구는 Drag/Select(손 아이콘, D), Bounding Box(B), Polygon(P), Brush(U), Smart Polygon(S), Label Assist(마법봉), Mark Null(N). 좌하단에 Zoom 도구(+ / − / 0=fit / 1=100%, **Zoom Lock**으로 모든 이미지에 동일 배율 고정).

**단축키가 진짜 워크플로우다.** 한 손은 마우스, 한 손은 키보드라는 전제가 설계 전반에 깔려 있다.
- `meta`(⌘/Ctrl) **누르고 있는 동안만** Drag/Select로 임시 전환 → 박스 그리다가 기존 박스 잡고 놓으면 다시 그리기 모드. 모드 전환 비용이 0에 수렴한다.
- `b/p/d/n/s` 도구 전환, `+/−/0/1` 줌, `←/→` 이전/다음 이미지, `shift+a` 데이터셋에 추가(리뷰 활성 시 "Submit for Review" 다이얼로그), `⌘Z / ⌘⇧Z` undo/redo.
- **선택 상태 단축키**: `↑/↓`로 클래스 후보 이동, `enter`로 확정(활성 후보는 **보라색 하이라이트**), `esc` 취소, `backspace` 삭제.
- **리뷰 모드**: `a` 승인 / `r` 반려.

**Class Selector.** 박스를 그리면 즉시 뜨는 콤보. 텍스트 필드(필터 + 신규 클래스 생성), 저장/취소 버튼, 기존 클래스 리스트(활성 항목 보라 하이라이트, 매칭 없으면 "Create class"). 즉 **그리기와 라벨링이 하나의 제스처로 붙어 있다.**

**Smart Polygon / Smart Select (SAM).** SAM을 **브라우저에서** 돌린다. 문서 표현이 결정적이다 — "you can hover over objects and see a **preview of the mask** that will be generated with your initial click." 즉 **클릭하기 전에 결과가 보인다.** 클릭 후에는 폴리곤 복잡도(Convex Hull / Smooth / Complex)를 토글하며 비교하고 `Enter`로 확정. 마스크 밖 클릭 = 확장(**녹색 점**), 마스크 안 클릭 = 축소(**빨간 점**). 큰 객체는 드래그로 박스 프롬프트.

**Label Assist.** 마법봉 → 모델 선택 팝업(`Your Models` / `Public Models` 탭, Universe 모델은 star해야 노출) → 클래스 선택 및 **클래스명 리매핑** → 이미지 열 때마다 자동 예측이 얹힌다. 앞뒤 화살표로 넘겨도 **계속 따라온다.**

**Box Prompting — 가장 "살아있는" 부분.** 클래스당 박스 하나만 그리면 **그 예제로 즉석 미세조정된 모델**이 유사 객체를 찾아 **점선 박스**로 예측을 뿌린다. 그 다음이 핵심이다.
- **confidence 슬라이더**로 표시 개수를 실시간 조절.
- 틀린 예측은 우클릭 → **"Convert to Negative"**, 음성 예제는 **음영 처리**되어 표시되고 모델이 다음부터 그 유형을 피한다.
- 예제를 더 그리고 "Predict"를 누르면 재예측.
- 만족하면 **"Approve Predictions"**로 일괄 확정(그 전까지 예측은 저장되지 않음 — 예측과 라벨의 경계가 명확).
문서의 팁까지 실전적이다: "confidence를 높이기보다 **낮춰놓고 초과분을 negative로 바꾸는 편이 쉽다**."

**멀티 선택 + 컨텍스트 메뉴.** Shift+클릭 또는 드래그 사각형으로 다중 선택 → 우클릭 메뉴에서 **Convert to Box / Polygon / Mask / Smart Mask**, **Merge Masks**(선택 마스크 합집합, 주 선택의 라벨·색 상속), **Bring to Front / Forward / Send to Back / Backward**. 조건부 노출까지 정교하다 — Merge Masks는 **선택이 전부 마스크일 때만** 나타난다.

**보조 패널.** 우측 Annots 드로어(클래스 존재 여부, 박스 색, 레이어 순서, Tags), Attributes 사이드바(치수, 최종 수정 시각, train/valid/test 소속). Display Options의 **"Mask Boxes" 스위치**로 마스크 외곽 박스 표시 토글. `H` 키로 주석 전체 숨김. 주석 이력(Annotation History)과 이미지 코멘트, 유사 이미지 검색까지 라벨링 화면 안에 있다.

- Rapid 리뷰 https://docs.roboflow.com/models/rapid/rapid/review-a-rapid-model

**모델 크기 카드.** Nano / Small / Medium / Large / Extra Large 5단, 각 카드에 **예상 학습 시간**(예 "약 2시간 5분")이 붙는다. 카피는 "fast iteration and low compute" ↔ "highest level of accuracy"의 트레이드오프로 프레이밍한다. 제품 페이지는 "175,000+ models trained"와 예시 지표("93.4% mAP", "95.7% precision", "89.4% recall")를 큰 숫자로 박아둔다.

**학습 중 = 라이브 차트.** 학습을 시작하면 데이터셋 버전 페이지에 메시지가 뜨고("training machine is starting"), 이어서 **"training graphs appear live as your model trains."** loss / precision / recall이 실시간으로 흐른다. 조기 종료(가중치 보존)와 취소(폐기)가 분리되어 있다. 한 버전에 학습이 여러 개면 버전 페이지에서 학습을 골라 각각의 그래프를 본다.

**NAS 전용 차트 — 이 부분이 특히 인상적이다.**
- **Training Progress Band**: 에폭에 따른 성능 상·하한을 그라디언트 밴드로 채우고, 임의 에폭에 **호버하면 그 시점 지표**를 보여준다. 라이브 학습 중에는 **맥동(pulsing)하는 인디케이터**가 현재 학습 전선을 표시한다.
- **Epoch Snapshot**: 각 에폭에서 평가된 아키텍처들의 **latency ↔ accuracy 파레토 곡선**. 그라디언트가 "빠름(밝음) → 정확함(어두움)"으로 흐른다.
- API 응답에는 `recommendedByHardware: {"jetson-orin-nano": "...", "t4": "..."}` 처럼 **하드웨어별 추천 모델**과 `paretoOptimalFor` 플래그가 담긴다.

**학습 후 = Model Evaluation 창.** "View Evaluation" 버튼으로 열리며 5개 패널로 구성된다.
1. **Production Metrics Explorer** — 모든 confidence 임계값에 대한 Precision/Recall/F1 곡선. "optimal confidence"를 추천하고, **평가가 끝나면 그 값이 추론 요청의 기본값으로 자동 적용**된다(클래스별 임계값이 있으면 그것까지, 없는 클래스는 전역값 폴백). **슬라이더를 끌면 세 지표가 그 자리에서 갱신된다.**
2. **Model Improvement Recommendations** — 혼동행렬 기반 자연어 조언(FN 과다, FP 과다, 자주 혼동되는 클래스 쌍, 데이터가 더 필요한 클래스, test/valid가 너무 작음 등).
3. **Performance by Class** — 클래스별 정답/오분류/FN/FP 스택 차트. "All Classes" 드롭다운으로 클래스 포커스, **Confidence Threshold 슬라이더로 차트 전체가 재계산**된다.
4. **Confusion Matrix** — 기본은 optimal threshold 기준. **슬라이더를 움직이면 행렬·정밀도·재현율이 같이 갱신**된다. **각 셀을 클릭하면 그 범주에 속한 이미지 목록**이 뜨고, 이미지를 클릭하면 **Ground Truth ↔ Model Predictions 토글**이 가능한 인터랙티브 뷰로 들어간다. 클래스가 많으면 스크롤바가 생긴다. Semantic Segmentation은 헤드라인 지표가 **mIoU**이고 행렬 값이 **픽셀 수**다.
5. **Vector Explorer** — 이미지 임베딩 클러스터링. 모델이 잘/못하는 이미지 군집을 찾는다. 제품 페이지 표현으로는 "find patterns in model failures".

**Test 페이지.** 우측 사이드바 "Test" → 테스트셋 이미지 몇 장이 즉시 제공되고, **직접 이미지·영상 업로드 또는 웹캠**으로도 시험한다. "Try on My Machine"이 배포 코드로, "Deploy on Workflows"가 워크플로우로 이어진다. 즉 **평가 화면이 곧 배포 진입점**이다.

**Rapid 모델 리뷰.** 텍스트 프롬프트로 만든 few-shot 모델을 리뷰하는 화면. **영상을 올렸으면 전 프레임에 추론이 돌아 재생하며 확인**한다. **confidence 슬라이더**로 예측 수 조절, "Edit Model"로 리뷰 단계에서 곧장 프롬프트·박스를 고치고 **"Update"로 재추론**, 만족하면 "Publish and Use Model"로 API 엔드포인트를 받는다. "Relabel Objects"로 빌드 단계로 되돌아갈 수도 있다.

### 1.4 Deploy / Inference / Monitoring

출처:
- 제품 페이지 https://roboflow.com/deploy
- 워크플로우 웹캠 프리뷰 https://blog.roboflow.com/workflows-webcam/
- Model Monitoring https://docs.roboflow.com/deployment/monitoring-and-analytics/model-monitoring
- Vision Events https://blog.roboflow.com/get-better-models-and-insights-with-vision-events/
- 서버리스 비디오 스트리밍 https://docs.roboflow.com/deployment/roboflow-cloud/serverless-api/serverless-video-streaming-api

헤드라인은 "Deploy Vision AI in Minutes — Integrate custom or foundation models into your toolset and codebase". 배포 타깃을 **하드웨어 칩(Enterprise GPU / NVIDIA Jetson / Hosted API / Raspberry Pi / ARM·x86 CPU)**으로 보여주고, 각각에 **복사 가능한 코드 스니펫**을 붙인다. 스니펫은 몇 줄짜리 `from inference_sdk import InferenceHTTPClient` 예제다 — **"이걸 붙이면 끝"이라는 인상**이 카피보다 강하다.

**웹캠 라이브 프리뷰.** 워크플로우 프리뷰의 입력 탭에서 "Video"를 고르면 브라우저가 카메라 권한을 묻고, **주석이 얹힌 라이브 피드**가 그 자리에서 돈다(자체 인프라 또는 Dedicated Deployment 필요). Serverless Video Streaming API는 WebRTC로 웹캠·RTSP·비디오 파일을 클라우드 모델에 흘린다.

**Model Monitoring 대시보드.** 상단에 3개 큰 숫자 — **Total requests / Average confidence / Average inference time** — 각각에 **전기간 대비 % 변화**가 붙고, 상단 버튼으로 기간(기본 1주)을 바꾼다. 아래에 모델 테이블(클릭 → 모델 대시보드), Recent Inferences 탭, Alerts 탭. 모델 대시보드에는 **클래스별 검출 수 분포**가 추가된다.

**Inferences Table + Inference Details.** 개별 추론으로 드릴다운하면 5개 영역이 나온다: (1) **추론된 이미지 자체**, (2) 추론 상세 패널(기어 아이콘으로 필드 숨김, 설정은 브라우저에 유지), (3) 일부 필드는 **그 값으로 재검색**하는 링크, (4) **Detections 접이식 표**(Class/Confidence 헤더 클릭으로 정렬), (5) 이미지 다운로드 + 이 상세로 오는 **딥링크 복사**.

**Vision Events(차세대).** 이벤트 피드를 device / time / detection class / 임의 metadata로 질의한다. 각 이벤트는 **입력·출력 이미지, 예측, 소스 장비, 커스텀 메타데이터**를 함께 보관한다. **Operator Feedback**으로 현장 담당자가 correct/incorrect/inconclusive를 찍고, 플래그된 이벤트를 모아 **다음 학습 데이터셋으로 직행**시킨다. Agent에게 자연어로 물으면("지난주 실패 몇 건?", "어느 카메라가 불량을 가장 많이 내나?") 집계해 답한다. 주간 요약 리포트를 실제 데이터 프리뷰와 함께 초안 잡아 이메일 예약까지 한다.

**Asset Library.** 워크스페이스 전체 이미지·영상 통합 검색. **의미 검색**(`boxes`), **유사 이미지 검색**(`like-image:<id>`), **필터 질의**(`class:helmet AND NOT (tag:v1 OR tag:v2)`), **메타데이터 질의**(`metadata:author=John`)가 한 입력창에 섞인다. 선택하면 **하단에 sticky 액션 바**가 올라오고 태그 부여, 새 프로젝트 생성, **선택 이미지에 워크플로우 일괄 실행(Batch Processing)**, 내보내기, 삭제가 가능하다. "Select All"은 현재 화면이 아니라 **질의 전체**에 적용된다. 배치 실행 모달은 CPU/GPU 머신 타입까지 고르게 하고, 워크플로우가 GPU를 요구하면 자동 선택한다.

### 1.5 Universe / Dataset Health Check

출처:
- https://docs.roboflow.com/datasets/universe/universe/what-is-roboflow-universe
- https://docs.roboflow.com/datasets/universe/universe/find-a-dataset-on-universe

100만+ 데이터셋, 5만+ 학습 모델. 검색은 기본이 **CLIP 기반 의미 검색**이고 토글로 Metadata 키워드 검색으로 바꾼다. **이미지로 검색**도 된다 — 좌측 필터 패널의 드롭존에 이미지를 넣으면 별점순이 아니라 **시각적 유사도순으로 결과가 재정렬**된다(JPEG/PNG/HEIC/GIF, 20MB 이하; 텍스트 질의와 병용 가능). 필터: 모델 보유 여부, 프로젝트 타입(detection/classification/segmentation/keypoint/multimodal), 학습된 모델 종류(예 YOLOv12), 이미지 수, star 수. 인라인 필터 문법도 지원한다(`images>100`, `dog+stars>=5`, `class:cat`, `model:yolov8`).

**카드에 이미지가 두 장 붙는다.** API 응답에 `thumbnail`(프로젝트 아이콘)과 **`annotationThumbnail`(주석이 그려진 샘플 이미지)**가 따로 있다. 카드에서부터 "이 데이터가 어떻게 라벨링돼 있는지"를 보여준다. 상세 페이지에는 Classes 목록, 라이선스가 명시된 "Cite this Project" 블록, star/조회/다운로드 애널리틱스가 붙는다.

**Dataset Health Check 탭.** 통계 나열이 아니라 **클릭 가능한 진단 도구**다.
- 이미지 수 / 주석 수 / 평균 이미지 크기 / 중앙 종횡비 / **missing annotations** / **null annotations**
- **train·test·valid별 클래스 분포**
- **Dimension Insights**(원본 크기·종횡비 분포)
- **Annotation Heat Map** — 주석이 이미지 어디에 몰려 있는지. **히트맵 위를 드래그하면 그 영역에 해당하는 이미지들이 뜬다.**
- **Object Count Histogram** — 이미지당 객체 수 분포. **막대를 클릭하면 그 개수를 가진 이미지들이 뜬다.**
차트가 **필터 컨트롤을 겸한다**는 점이 핵심이다. 문서는 한 걸음 더 나아가 "null 주석이 하나도 없다면 몇 개 추가를 고려하라", "주석이 한 곳에 몰려 있으면 과적합 위험" 같은 **해석까지 제공**한다.

## 2. 무엇이 이것을 "살아있게" 만드는가 — 인터랙션 패턴 14

각 항목: **사용자가 하는 것 → 시스템이 보여주는 것 → 왜 기쁜가**

**P1. 클릭 전 미리보기 (Smart Select 호버)**
사용자: 객체 위에 마우스를 올린다 → 시스템: 그 클릭이 만들 **마스크를 반투명으로 미리 그려준다** → 왜: 실행 취소가 필요 없다. 실패의 비용이 0이 되면 사람은 과감해지고, 과감해지면 빨라진다.

**P2. 임계값 슬라이더 = 실시간 필터**
사용자: confidence 슬라이더를 끈다 → 시스템: 박스가 **사라지고 나타나며**, 동시에 혼동행렬 셀·정밀도·재현율·클래스별 막대가 **같은 프레임에 갱신**된다 → 왜: 추상적인 숫자(0.45)가 눈앞의 그림으로 번역된다. 사용자가 모델을 "이해"하는 유일한 순간이다.

**P3. 차트가 곧 필터 (Health Check 히스토그램·히트맵)**
사용자: 히스토그램 막대를 클릭하거나 히트맵을 드래그한다 → 시스템: **그 조건에 해당하는 실제 이미지 그리드**가 나온다 → 왜: 통계가 "보고서"에서 "탐색 도구"로 승격된다. 이상치를 눈으로 확인하는 경로가 한 클릭이다.

**P4. 혼동행렬 셀 → 이미지 → GT/예측 토글**
사용자: False Positive 열의 셀을 누른다 → 시스템: 해당 이미지 목록 → 이미지 클릭 → **Ground Truth ↔ Model Predictions 토글 뷰** → 왜: "왜 틀렸나"를 3클릭 안에 눈으로 본다. 모델 디버깅이 데이터 디버깅으로 자연스럽게 이어진다.

**P5. 학습 곡선 스트리밍 + 맥동 인디케이터**
사용자: 학습을 시작하고 탭을 연 채 둔다 → 시스템: loss/precision/recall이 **에폭마다 자라나고**, NAS는 성능 밴드 위에서 **현재 전선이 맥동**한다 → 왜: 진행률 바는 시간을 알려주지만 학습 곡선은 **결과의 질**을 알려준다. 기다림이 관찰로 바뀐다.

**P6. 포트에서 시작하는 그래프 편집 (`+`, `Fork`, drag-to-connect)**
사용자: 블록 하단 `+`를 누르거나 포트에서 선을 끌어 놓는다 → 시스템: **그 포트와 호환되는 블록만** 추천 목록에 뜨고, 놓는 순간 자동 배선된다 → 왜: "무엇을 연결할 수 있는가"를 시스템이 알고 있다. 사용자는 가능한 것 중에서만 고르므로 틀릴 수 없다.

**P7. 자동 정렬의 예의 (드래그하면 물러남)**
사용자: 자동 정렬을 켜둔 채 블록 하나를 손으로 옮긴다 → 시스템: **자동 정렬을 일시 정지**하고 수동 배치를 존중한다 → 왜: 자동화가 사람과 싸우지 않는다. "내가 통제하고 있다"는 감각이 유지된다.

**P8. 블록 단위 캐시 배지**
사용자: 한 블록의 파라미터만 고치고 Run → 시스템: 나머지 블록에 **"Cached" 배지**가 붙고 그 블록만 재계산된다 → 왜: 그래프가 자기 계산 상태를 자백한다. 빠르기도 하지만, **왜 빠른지 보이는 것**이 신뢰를 만든다.

**P9. 예측과 라벨의 시각적 분리 (점선 vs 실선, 승인 게이트)**
사용자: Box Prompting으로 예측을 띄운다 → 시스템: 예측은 **점선**, 확정 라벨은 실선. "Approve Predictions" 전까지 저장되지 않는다 → 왜: AI가 만든 것과 사람이 확정한 것이 절대 섞이지 않는다. 공공 데이터 품질 책임 소재가 UI 레벨에서 갈린다.

**P10. 부정 예제로 가르치기 (Convert to Negative)**
사용자: 틀린 예측을 우클릭해 negative로 바꾼다 → 시스템: 그 박스가 **음영 처리**되고 재예측 결과가 달라진다 → 왜: 사용자가 모델을 "고쳤다"는 인과를 직접 체험한다. 라벨링이 노동이 아니라 대화가 된다.

**P11. 손이 키보드를 떠나지 않는 라벨링**
사용자: `b`로 그리고 `↓`로 클래스 고르고 `enter`, `→`로 다음 장. 필요하면 `meta`를 **누르고 있는 동안만** 선택 모드 → 시스템: 모드 전환에 클릭이 0회 → 왜: 100장이 아니라 10,000장을 처리하는 사람의 리듬이 유지된다.

**P12. "당신 이미지로 바로 해보기"**
사용자: 평가 화면에서 이미지를 드래그하거나 웹캠을 켠다 → 시스템: **박스가 얹힌 결과**가 즉시 나온다 → 왜: 벤치마크 숫자(mAP 93.4%)는 남의 이야기지만, 내 사진 위의 박스는 내 이야기다. 신뢰는 여기서 생긴다.

**P13. 두 모델 겹쳐 보기 (초록=A만, 빨강=B만, 밝음=둘 다)**
사용자: Model Comparison 블록을 꽂고 Run → 시스템: 한 장의 이미지에 **차집합이 색으로** 드러난다 → 왜: 표로는 "0.81 vs 0.84"지만 그림으로는 "얘가 사람 발을 놓쳤다"가 보인다.

**P14. 문서·공유 링크가 그 자리에서 실행된다**
사용자: 블로그나 공유 링크를 연다 → 시스템: **임베드된 워크플로우가 읽기 전용으로 뜨고, 이미지를 넣어 실제로 돌릴 수 있다**(기본은 소유자 크레딧 비소모) → 왜: 설득의 마지막 1cm를 없앤다. 발주처 시연에 이보다 강한 장치가 없다.

보조 패턴 3가지도 기록해 둔다. **(a) 안전한 테스트** — Sink 블록은 테스트 중 기본 비활성이라 "돌려봐도 아무것도 망가지지 않는다"는 계약이 있다. **(b) 백그라운드 작업 알약** — 장기 작업이 몇 개 도는지 상시 카운터로 보인다. **(c) 실행 위치 셀렉터** — 상단 좌측 "Running on"에서 클라우드/로컬 서버를 바꾸고, 어디서 도는지가 항상 화면에 있다.

이식 포인트:
- **노드 카드 안에 결과 썸네일.** 실행 후 각 노드는 자기 출력 이미지를 64~120px 썸네일로 물고 있는다. 호버하면 400px 팝오버. 이것 하나가 "다이어그램 → 파이프라인" 전환의 90%다.
- **포트 `●`와 `+`, `⑂ 분기`.** 포트에서 드래그해 연결, 포트 옆 `+`로 호환 블록만 추천. 분기 버튼으로 병렬 브랜치(예: **남원 2504 vs 2510 두 시점을 같은 모델에 병렬 투입**).
- **노드 상태 3종**: `대기` / `계산중 ▓▓░ 68%` / `캐시됨`. Roboflow의 Cached 배지 그대로.
- **실행위치 셀렉터**(상단 좌측): `LX-GPU-01 ● 연결됨 12ms`. Roboflow의 "Running on" 셀렉터 대응. 공공기관 온프레미스 GPU를 노출하는 것이 오히려 신뢰 요소다.
- **Builder Assist 자동/제안/수동 3단**과 **자동정렬(손대면 정지)**을 그대로 채택.
- **버전 히스토리(⏱)** + `Live` 배지 + 복원. 공공사업 감사 대응에도 유리하다.
- **Sink 실행 체크박스**를 우리 맥락으로 번역하면 "결과를 국토조사 DB에 실제로 반영" 스위치다. 기본 꺼짐 = 시험 실행은 안전.
- **글래스 적용**: 캔버스 배경은 `--mist:#E9EEF1` 위에 미세 그리드, 노드 카드는 `--surface` 불투명(가독성), **하단 실행 바만 `--glass` + backdrop-blur**로 띄운다. 유리를 남발하면 데이터가 읽히지 않는다.

구현 메모(실제로 살아있게 만드는 방법):
- **신뢰도 슬라이더는 MapLibre 필터로 즉시 반영.** `map.setFilter('det-fill', ['>=', ['get','confidence'], v])`. 5,000 폴리곤은 `geojson` 소스로 60fps 유지 가능. `marine-debris.geojson`에 이미 `confidence`가 있으므로 **오늘 바로 된다.**
- **`detections-sample.geojson`에 `conf` 속성 추가가 선행 과제.** 현재 `cls/status/capturedAt`만 있어 슬라이더를 붙일 수 없다.
- **신뢰도 색농도**: `['interpolate',['linear'],['get','confidence'],0.5,'#BFD9FF',1.0,'#003B85']` — Roboflow의 퍼플 램프를 LX 블루 램프로 치환.
- **슬라이더 위에 신뢰도 히스토그램을 얹는다.** 실제 분포(0.5대 1,713 / 0.6대 2,375 / 0.7대 781 / 0.8대 99 / 0.9대 15 / 1.0 17)를 스파크라인으로 그려두면 사용자가 "어디를 잘라야 하는지"를 즉시 안다. Roboflow의 Production Metrics Explorer를 지도에 이식한 형태.
- **히트맵/격자 모드**는 `marine-debris-grid.geojson`(9,032셀, `count`/`mean_conf`)을 그대로 쓴다. 줌 아웃하면 자동으로 격자, 줌 인하면 폴리곤으로 전환(`zoom` 기반 레이어 토글) — 5,000건을 전국 스케일에서 보여줄 때 필수.
- **클래스 토글은 개수와 함께.** `☑ ■ 해양쓰레기 3,412` — 체크박스 옆 숫자가 현재 임계값 기준으로 실시간 갱신되어야 한다. 이것이 슬라이더와 토글이 서로 연결되어 있다는 증거가 된다.
- **검출 칩 / 상세 드로어**: 폴리곤 클릭 → 우측 드로어. **검출 중심 256px 타일 크롭 이미지**를 반드시 넣는다(Inference Details의 (1)번). `←/→`로 검출 간 이동.
- **오탐 신고 / 현장 확인 요청** 버튼 = Vision Events의 Operator Feedback. 공공 국토조사 맥락에서 **현장 검증 루프**로 자연스럽게 번역되며, 누적된 오탐은 재학습 데이터가 된다. 이것이 Land-XI만의 서사가 될 수 있다.
- **남원 4시점 비교 모드**는 Model Comparison Visualization의 색 문법(초록=A만/빨강=B만/흰=양쪽)을 **시점 간 변화 탐지**로 전용한다. 발주처가 가장 좋아할 화면이다.
- **OBB 렌더링**: `yolo11x-obb`(선박/항만/탱크 등 15클래스)는 축 정렬 사각형이 아니라 **회전 폴리곤**으로 그린다. supervision의 `OrientedBoxAnnotator` 대응이며, 지도 위에서는 GeoJSON Polygon 4점으로 표현하면 그대로 된다.

## 5. 경쟁사 대조 — 왜 Roboflow가 유일한 벤치마크인가

2026년 현재 경쟁 지형이 크게 이동했다. 이 사실 자체가 발주처 설득 논리가 된다.

- **Labelbox** (https://labelbox.com/) — 포지션이 **"The RL data engine for AI teams"**로 바뀌었다. Horizon(post-training 환경/선호 신호), Terra(로보틱스 파운데이션 모델 데이터), Alignerr(260만+ 전문가 피드백), Recursion(엔터프라이즈 플랫폼). 과거의 Model Diagnostics(실패 모드 분석)는 여전히 강점으로 언급되지만, **제품의 무게중심이 CV 어노테이션에서 LLM/RL 데이터로 이동**했다. Land-XI가 참고할 것은 "모델 진단을 데이터 큐레이션으로 되먹이는 루프" 개념뿐이다.
- **V7** (https://www.v7labs.com/) — **V7 Go로 완전히 피벗**해 사모펀드·보험·부동산 문서 자동화 회사가 되었다. "Operational AI for the investment lifecycle". 이미지 어노테이션 UI의 깔끔함은 여전히 회자되지만 **더 이상 CV 플랫폼 벤치마크가 아니다.**
- **Scale AI** (https://scale.com/) — Data Engine + 생성형 AI 데이터 서비스(RLHF, red teaming, 평가). Nucleus는 공개 제품 페이지 전면에 없다. **서비스 회사이지 셀프서브 도구가 아니다.**
- **Encord** (https://encord.com/) — 비디오·의료영상(DICOM)·멀티모달에서 가장 강하고, 합의 점수 자동화와 중첩 태스크 구조 등 **품질 워크플로우가 best-in-class**. Land-XI가 참고할 것은 **검수(리뷰) 워크플로우의 엄밀함** — 공공사업의 품질 감사 요건에 직결된다.
- **Picsellia** (https://www.picsellia.com/) — 데이터/라벨링/실험추적(AI Laboratory)/배포/모니터링 5단 MLOps. API-first, Python SDK 중심, 50+ 툴 연동. **UI가 아니라 SDK가 주인공**이라 "살아있는 화면" 벤치마크로는 약하다.
- **Ultralytics Platform** (https://platform.ultralytics.com/, 구 hub.ultralytics.com) — **가장 직접적인 경쟁자.** "Annotate, train, and deploy vision AI in one workflow", SAM 기반 원클릭 스마트 어노테이션("Masks and bounding boxes in one click"), **Detection/Instance Seg/Semantic Seg/Classification/Pose/OBB 전 태스크 지원**(우리 모델 구성과 정확히 일치), 26종 클라우드 GPU, **실험 나란히 비교**, 드래그앤드롭 추론 시험, 20종 포맷 익스포트 + 42개 리전 배포. **다만 노드 캔버스가 없다** — 파이프라인을 시각적으로 조립하는 개념이 부재하다.

**결론:** *"노드 캔버스로 파이프라인을 조립하고, 각 노드가 자기 결과 이미지를 보여주며, 그것을 그대로 배포한다"*는 조합을 온전히 갖춘 곳은 현재 Roboflow뿐이다. 발주처의 벤치마크 지정은 타당하며, Land-XI는 여기에 **"국토 스케일 지도 + 정사영상 타일 + 필지/행정경계 연계"**라는 Roboflow에 없는 축을 얹어 차별화할 수 있다. 즉 **Roboflow의 상호작용 문법 × MapLibre의 공간 문맥**이 Land-XI의 고유 포지션이다.

## 6. 우선순위 실행 제안 (반려 대응)

발주처가 "정적"이라고 지적한 것을 뒤집는 데 필요한 최소 작업을 효과/비용 순으로 정렬한다.

1. **[최우선·즉시 가능] 결과 지도에 신뢰도 슬라이더 + 히스토그램.** `marine-debris.geojson`에 `confidence`가 이미 있다. MapLibre `setFilter` 한 줄. 5,000건이 실시간으로 사라지고 나타나는 장면이 반려를 뒤집는 단일 최강 데모다.
2. **[최우선] 워크플로우 노드에 실결과 썸네일 + 실행 상태 배지.** 남원/제주 타일에 각 모델을 미리 돌려 이미지 몇 장만 캐시해두면 정적 목업이 즉시 파이프라인으로 보인다.
3. **[상] 분석 실행 화면의 라이브 3종 차트 + 검출 스트림.** 실제 배치가 없어도 저장된 결과를 타임라인으로 재생하면 동일한 인상을 준다.
4. **[상] `detections-sample.geojson`에 `conf` 속성 추가.** 없으면 슬라이더를 붙일 수 없다.
5. **[중] 남원 4시점 비교 모드**(초록/빨강/흰 차이 강조). 우리만 가진 자산이고 시연 임팩트가 크다.
6. **[중] 검출 색 팔레트 토큰화**(클래스 고정색 + 신뢰도 램프).
7. **[중] 라벨링 에디터의 어두운 캔버스 + 단축키 힌트 바 + 점선/실선 문법.**
8. **[하] 모델 카드 10종에 샘플 오버레이 + mAP 스파크라인.**
9. **[하] 데이터 건강도 탭**(클래스 분포·히트맵·히스토그램, 전부 클릭 가능).
10. **[하] 워크플로우 버전 히스토리 + 읽기전용 공유 링크.**
