## 0. 첫 문장부터 정정해야 할 전제

의뢰서에는 VW-LAB이 "3D/GIS/데이터 시각화로 알려진 국내 스튜디오"이고 그 **사이트**를 해부하라고 되어 있었다. 실측 결과 이 전제는 절반만 맞다.

`www.vw-lab.com`은 **스튜디오 포트폴리오 사이트가 아니라 티스토리 블로그**다. 실측 근거:

- 모든 정적 자원이 `tistory1.daumcdn.net/tistory/1789156/skin/...`에서 내려온다(블로그 ID 1789156).
- 스킨 스크립트: `skin/images/script.js?_version_=1644850871` — 2022년 2월 빌드에서 멈춰 있다.
- 푸터에 `Designed by 어포스트`, `관리자`, `글쓰기` 링크가 그대로 노출된다.
- `masonry-layout@4.2.2`, `imagesloaded@4.1.4`를 unpkg에서 로드하는 4열 매스너리 그리드.
- 카테고리는 `ALL(100) / About(1) / Content(44) / Function(54)`, 페이지네이션 4페이지. 총 100편.
- 방문자 카운터(736,135), 방명록, 구독 버튼, 9개 국어 Google Translate 위젯, Kakao SDK 공유 — 전형적인 개인 기술 블로그 구성.

즉 **웹사이트의 시각 언어를 벤치마크할 대상이 아니다.** 사이트 크롬(내비·카드·타이포·모션)은 우리 프로토타입보다 오히려 뒤처진다. 카드 호버 시 픽셀 변화가 **0**이다(`main-hover-1~5.jpg`를 `main-02-5s.jpg`와 비교하면 완전히 동일). `box-shadow: none`, `transition: all`이지만 duration이 없어 실질적으로 트랜지션이 없다. 유일한 동적 요소는 상단 2px 스크롤 진행바(`div#progressbar.progressbar [1425x2]`)와 우하단 top 버튼이다.

**그럼에도 이 조사가 값어치 있는 이유**는 두 가지다.

1. 그리드에 깔린 100장의 썸네일이 곧 **국내 지오·데이터 시각화 표현 사전(辭典)**이다. 3D 도시 익스트루전, 지형 음영, 해류·풍속 벡터필드, OD 플로우, 등시선, 격자 인구, 코로플레스, 방사형 차트, 레이마칭 렌더링이 한 화면에 나열되어 있다. 우리가 남원·여수 실데이터에 얹을 표현의 후보군이 여기 다 있다.
2. 이 블로그의 저자(vuski / VWL Inc.)가 만든 **실제 프로덕션 앱**이 외부에 살아 있다. `https://www.dokdo.re.kr/currentVis/index.htm` — 한국해양과학기술원(KIOST) 독도 종합정보시스템. deck.gl 기반 실시간 해류 벡터필드다. **이것이 이번 벤치마크의 진짜 본체이고, 우리 해양쓰레기·여수 서비스와 1:1로 대응한다.**

그래서 이 문서는 "사이트 해부"가 아니라 "**작업물 해부**"로 축을 옮겨 쓴다.

| 데이터 타일 | **자체 바이너리 스킴** `data/current/{epoch}/{z}/{x}/{xy}.bin` (예: `1787659200/5/130/130216.bin`) |

| 번들 | `main.js` **단일 파일**. 프레임워크 없음 |
| 스크립트 총 3개 | gtag, fontawesome, main.js |

**핵심 설계 판단 3가지가 우리에게 직결된다:**

1. **시간축을 URL 경로에 넣었다.** `{epoch}/{z}/{x}/{y}.bin` — 시점이 타일 경로의 최상위 세그먼트다. 브라우저 HTTP 캐시가 시점별로 자동 분리되고, 재생 버튼을 누르면 다음 epoch을 프리페치하기만 하면 된다. 서버 로직 0줄. 우리 남원 4시점 정사영상·탐지 결과에 **그대로** 복제 가능하다.
2. **결측을 데이터로 관리한다.** `missingList.csv`가 별도로 존재한다. 즉 "이 시점 이 타일은 없다"를 클라이언트가 사전에 알고, 요청하지 않고, UI에서 회색 처리한다. 우리 4시점 커버리지 불균형(시점별 촬영 범위 차이)에 필요한 바로 그 장치다.
3. **지명을 TSV로 분리했다.** 벡터타일 라벨이 아니라 별도 TSV → 줌별 필터 → deck.gl TextLayer. 라벨 스타일을 100% 통제할 수 있고, 베이스맵을 갈아끼워도 라벨은 유지된다. `maplibre-cartography` 스킬이 말하는 "위성영상 위 라벨 가독성" 문제의 실전 해법이다.

## 3. Frame-by-frame 해부

### 3.1 메인 페이지 히어로 — **없다**

정직하게 기록한다. `main-00-load.jpg`(load 직후), `main-01-2s.jpg`, `main-02-5s.jpg` 3장은 **픽셀 단위로 동일**하다. 히어로 섹션 자체가 없고, 로드 즉시 매스너리 그리드가 첫 화면을 채운다. 인트로 애니메이션·페이드인·스태거 없음. `main-hover-0~5.jpg`도 기준 프레임과 동일 — **카드 호버 반응 0**.

배울 점은 역설적으로 하나 있다: **첫 화면에서 곧바로 "이 사람들이 만든 그림"이 12장 보인다.** 로고와 슬로건에 화면을 낭비하지 않는다. 우리 `ch3.png`는 상단 좌측 로고, 좌측 부처 칩 5개, 우측 HUD, 하단 좌측 대형 타이포로 **주변을 다 채우고 가운데는 비어 있다.** VWL 그리드는 정반대로 가운데가 꽉 차 있다.

### 3.2 독도 해류 앱 — 프레임 단위 (총 20개 타임드 프레임)

캡처 파일: `demo-current-00-load` → `01-2s` → `02-5s` → `03-8s` → `04-pan` → `05-zoomin` → `06-zoomin2` → `07-hover` → `08-zoomout` → `09-anim0/4/8` → `10-regional` → `11-wide` → `12-layer0~5` → `13-play-a/b/c` → `14-info` (`shots/bench/vwlab/demo-current-*.jpg`)

**t=0s (`00-load`)** — 상단 72px 안내 배너(딥네이비 계열)와 좌측 아이콘 레일만. 캔버스는 비어 있다.

**t=2s (`01-2s`)** — 배경 스칼라 필드가 **먼저** 칠해진다. 왼쪽 아래에서 오른쪽 위로 남색(#3A5A9B계) → 보라(#5A3A6B계) 그라디언트. 이건 지도가 아니라 **유속 스칼라장을 그대로 화면에 깐 것**이다. 파티클보다 배경이 먼저 뜨는 순서가 중요하다 — 로딩 중에도 화면이 이미 "정보"다.

**t=5s (`02-5s`)** — 파티클 수천 개가 시딩되어 전 화면을 덮는다. 형태는 **혜성(comet)**: 머리는 밝은 라벤더(#E0C8F0계), 꼬리는 진행 반대 방향으로 6~14px 페이드아웃, 길이가 유속에 비례한다. 화면 어느 지점을 봐도 최소 3~4개의 파티클이 시야에 있다. **픽셀당 정보 밀도가 이 앱의 "살아있음"의 정체다.**

**t=5s 오버레이 계층 (같은 프레임)**

- 지명 라벨 13개: `서도`, `동도`, `물개바위`, `북항초`, `강치초`, `가제초`, `삼봉초`, `괭이초`, `서도초`, `군함초`, `넙덕초`, `부채초`, `동도초`. 섬 이름은 **흰색**, 수중 암초는 **연하늘(#A8C8FF계)** — 두 색으로 대상 종류를 구분한다. 12~13px Pretendard, 얇은 다크 halo.
- 하단 레전드 `.gradientBar [549,808,342×17]`: `border: 1px solid rgb(122,122,122)`, `border-radius: 10px`. 눈금 `0.0m/s / 0.4 / 0.8 / 1.2 / 1.6`, 눈금 텍스트 **12.8px #fff**. 램프는 파랑 → 청록 → 연두 → 흰색.

- **`backdrop-filter: none`.** 유리 효과를 전혀 쓰지 않는다. 순수 90% 불투명 검정이다.

**t=hover (`12-layer0~5`)** — 레일에 마우스를 올리면 **폭 45px → 120px로 확장**하며 라벨이 나타난다: `해류 / 파랑 / 조위 / 수온 / 염분`. 별도 pill로 `부이`. 아이콘만 있던 레일이 텍스트 메뉴로 변신하는 이 한 동작이, 이 앱에서 유일하면서 가장 세련된 마이크로 인터랙션이다.

**줌 인 (`05-zoomin`, `06-zoomin2`)** — z15 도달 시 VWorld 위성 타일이 나타나고 서도·동도의 실제 텍스처가 드러난다. 파티클은 **밀도를 유지한 채 길이만 늘어난다**(화면 좌표계 스케일). 근접에서는 파티클이 성기게 흩어져 보이고 섬이 주인공이 된다.

**줌 아웃 (`10-regional`, `11-wide`)** — 이 앱의 클라이맥스. 위성 타일이 사라지고 스칼라 배경 + 파티클만 남는데, **에디(eddy, 소용돌이) 구조가 화면 전체에 드러난다.** 좌하단→우상단 주류(main flow)와 독도 남쪽 반시계 와류가 눈으로 읽힌다. **넓게 볼수록 정보가 늘어나는 구조** — 우리 프로토는 정반대로 전국 뷰가 가장 비어 있다.

**재생 (`13-play-a/b/c`)** — 재생 버튼을 누르면 시간이 자동 진행되고, 다음 epoch의 `.bin` 타일이 프리페치되면서 벡터장이 **크로스페이드 없이 즉시 교체**된다. 파티클 자체는 계속 흐르고 있으므로 교체 순간의 점프가 눈에 띄지 않는다. 영리한 트릭이다: **연속적인 파티클 모션이 이산적인 데이터 교체를 가려준다.**

> 주: `recordVideo`로 webm 2건을 확보했으나(`shots/bench/vwlab/_video/`), Playwright 번들 ffmpeg(`ffmpeg-win64.exe`)에 이미지 인코더가 없어(`Error selecting an encoder`) ffmpeg 키프레임 추출은 실패했다. 대신 Playwright로 직접 타임드 캡처한 위 20개 프레임이 동일 역할을 한다.

### 3.3 프로젝트별 표현 해부

**① `/131` 수도권 지하철 접근성** (`p131-metro2-00~12.jpg`)
표현: 검은 배경 위 **다중 등시선 링**. 중심역에서 10/20/30분 등시선을 채도가 다른 색으로 겹치고, 지하철 노선을 노선색 그대로 얹는다. 좌측에 컨트롤 패널(히스토그램 + 순위 리스트), 우측 상단에 랭킹 테이블. 썸네일만으로 **"지도 + 컨트롤 + 순위표" 3분할 대시보드** 구조가 읽힌다.

**③ `/127` Urban Density Profiler** (`p127-udp-00~12.jpg`)

## 4. 왜 저건 살아 있고 우리 건 죽어 있는가 — 잔인하게

### 4.1 `shots/proto/ch3.png` (전국 히어로)

- **화면의 65%가 무정보 영역이다.** 위성영상 위에 부처 칩 5개(좌상), 펄스 노드 5개, 곡선 2개, HUD 1개(우상), 타임라인 1개(우하), 대형 타이포(좌하). 가운데 한반도 본체는 **그냥 위성 사진**이다. 데이터가 얹혀 있지 않다. 독도 앱은 같은 1440×900에서 어느 100×100px을 잘라도 파티클 3~4개가 들어 있다.
- **펄스 노드 5개 = 초당 갱신되는 정보량 0.** 노드는 위치만 알려주고 값을 말하지 않는다. VWL의 파티클은 위치·방향·속도 3개를 동시에 말한다.
- **HUD가 "우주 컨셉"이다.** `SENTINEL-2 / 고도 786km / 한반도까지 9,300km / 태양 직하점 10.9°, 40.5°` — 이 숫자들은 **국토조사 업무와 아무 관계가 없다.** 멋있어 보이려고 넣은 장식이다. VWL의 HUD(`0.0m/s ~ 1.6m/s`, `2026-08-25 화 21:00`)는 화면에 보이는 것을 그대로 해설한다. 이 대비가 "2%"라는 평가의 핵심이다. **우리는 장식을 넣었고, 그들은 해설을 넣었다.**
- 타이포 대비는 좋다(대형 굵은 산세리프 + 얇은 메타 라인). 문제는 **타이포가 화면에서 가장 강한 요소라는 것** — 지도가 조연이다.

### 4.2 `shots/proto/svc-marine-close.png` (여수 해양쓰레기)

- 우측 패널에 `객체 1,860건`, `1,857 / 1,857 객체표시`라고 써 있는데 **화면에는 주황 폴리곤 20~30개만 보인다.** 나머지는 z15.40 / 100m 스케일에서 서브픽셀이라 사라졌다. **숫자와 그림이 서로를 배신한다.** VWL은 정확히 이 문제를 격자 집계로 해결한다(셀에 숫자를 직접 찍거나 밀도를 색으로).
- **배경이 균질한 파랑 한 장이다.** 바다 위성영상이지만 텍스처가 없어 사실상 단색. 여기에 작은 주황 점을 뿌리면 "빈 화면에 먼지" 인상이 된다. 독도 앱은 같은 바다를 **유속 스칼라 그라디언트**로 칠해 배경 자체를 데이터로 만들었다.
- 좌하단 미니맵이 본 지도와 같은 희소 패턴을 반복한다 → **정보 중복.** 미니맵은 전국 맥락(여수가 어디인지)을 줘야 하는데 같은 축척의 축소판이다.
- 우측 히스토그램은 좋다. 다만 주황 단색 막대 + 회색 배경이라 지도의 주황과 같은 색 — 연결은 되지만 계층이 없다.
- 결정적으로 **움직이는 것이 아무것도 없다.** 스크린샷과 실행 화면이 구분되지 않는다.

### 4.3 `shots/proto-wf/slider-090.png` (워크플로 캔버스)

- 정보량은 오히려 과잉이다. 워크플로 노드 6개 + 지도 + 5개 차트 패널. 그런데 **전부 정지 UI**다.
- **컬러가 무너졌다.** 한 화면에 파랑·청록·주황·노랑·보라·자홍이 동시에 있고, 각각 서로 다른 의미 체계에 속한다(클래스 색 / 상태 색 / 차트 색 / 브랜드 색). 독도 앱은 **액센트 1색 + 램프 1개**로 끝낸다.
- 노드 썸네일 5장이 전부 **저해상도 미리보기**라 실제로 무엇이 탐지됐는지 안 보인다. 04 탐지 노드의 보라·주황 마스크는 예쁘지만 128px에서는 노이즈다.
- 우측 지도가 **VWorld 일반 지도(도로·지명 풀 라벨)** 위에 청록 점 몇 개다. 라벨이 데이터보다 강하다. `maplibre-cartography` 원칙 위반 — 데이터 레이어가 주인공이어야 한다.
- 하단 좌측 컬러 블록 5개(파랑/청록/주황/노랑/초록)는 정체불명의 장식이다.

### 4.4 한 문장 진단

> **VWL은 "데이터가 화면을 채우고 UI가 물러난다". 우리 프로토는 "UI가 화면을 채우고 데이터가 물러난다".**

우리 3장 모두 크롬(패널·칩·HUD·타이포)이 훌륭하다. 하지만 그 크롬이 감싸고 있는 지도 안에 **볼 것이 없다.** 이것이 "단조롭고 딱딱하다"의 정확한 기술적 정체다. 유리 패널을 더 다듬어도 해결되지 않는다. **지도 안의 픽셀 밀도를 올려야 한다.**

## 6. 피해야 할 것

1. **블로그 스킨 자체를 참고하지 말 것.** 호버 반응 0, `box-shadow: none`, 매스너리 재배치 점프, `letter-spacing: -1px` 전역. 우리 카드 시스템이 이미 더 낫다.
2. **`backdrop-filter` 없는 `rgba(0,0,0,0.9)` 패널을 그대로 베끼지 말 것.** 독도 앱은 어두운 바다 위라 성립한다. 우리는 "밝은 지도 바탕 + 유리 패널"이 정해진 방향이다. **훔칠 것은 색이 아니라 "UI는 무채색 + 액센트 1색, 색은 데이터가 쓴다"는 원칙**이다.
3. **상단 고정 안내 배너(72px)로 지도를 잘라먹지 말 것.** 독도 앱은 화면 상단 8%를 기관 설명문에 쓴다. 지도 앱에서 가장 아까운 낭비다.
4. **라벨 겹침 방치 금지.** 광역 뷰(`11-wide`)에서 `서도`/`동도`/`독도`가 겹쳐 읽히지 않는다. 줌별 라벨 우선순위·충돌 회피가 필요하다.
5. **파티클이 베이스맵을 잡아먹게 두지 말 것.** `06-zoomin2`에서 섬 위성 텍스처가 파티클에 가려진다. 줌 임계값 이상에서는 파티클 밀도·불투명도를 낮춰야 한다.
6. **GIF·YouTube 임베드로 인터랙션을 대체하지 말 것.** VWL 블로그가 그렇게 한다 — 100편 중 인터랙티브 데모는 외부 링크 몇 개뿐이다. 우리 클라이언트는 "동작하는 화면으로 판단"한다.
7. **의미 없는 우주·위성 HUD 수치 금지.** `태양 직하점 10.9°, 40.5°`는 삭제 대상. 화면에 보이는 것을 해설하는 숫자만 남긴다.
8. **6색 이상 동시 사용 금지.** `slider-090.png`의 컬러 혼재를 정리. 클래스 색 램프 1개 + 상태 액센트 1개로 축소.
9. **초장문 페이지 금지.** VWL 포스트는 40,381px(`/115`)까지 간다. 기술 블로그니까 성립하는 것이고, 플랫폼 UI에서는 재앙이다.
10. **성능 수치를 개발자 언어로 노출하지 말 것.** `tier full · 75 fps`는 사용자에게 의미 없다. `9,664동 · 0.4초 로드`로 번역하라.
