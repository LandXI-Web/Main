## 명세와 다른 점 (제안)
- 명세의 .docx 경로는 `GET /agent/runs/{id}/draft.docx`(서버 서식)다. 서버 서식은 아직 개발 정보가 많고 장 구성(① 개요 ~ ⑥ 조치 제안)이 화면 세 문단과 다르다. 그래서 공무원이 화면에서 본 것과 내려받은 파일이 같도록 화면이 직접 조립한다. 서버 서식을 고쳐 화면 문단을 같은 제목 아래 넣게 되면 서버 파일로 되돌릴 수 있다(`armDocx` 한 곳).

## 서버 요청(서버 팀)
1. **담당 재지정**: `POST /survey/findings/{fid}/state{state: 지금 상태, assignee}` 로 같은 상태 안에서 담당만 바꾸기를 허용하고, 상세의 `allowed_next` 에 지금 상태를 넣어 주면 화면 버튼이 바로 열린다(이벤트 · SSE 도 같은 경로).
2. **조치 종류**: 서버 kind 는 `notice · correction · revisit · referral · other`, 화면 종류는 `안내 · 시정명령 · 이행강제금 · 원상복구 · 없음`. 지금은 가까운 kind 로 저장하고 사용자 말(종류 · 근거 조문)을 `note` 에 그대로 담는다. `law`(근거 조문) 열과 화면 5종 kind 가 있으면 note 파싱을 없앨 수 있다.
3. **목록의 판정**: `GET /survey/findings` 항목에 `verdict · verdict_code` 가 빠져 있다(상세에만 있음). 화면은 `reason` 과 상세로 보완한다.
4. **초안 글(server/agent/report.py)**: LLM 사용자 메시지가 `대상: 남원시 {읍면동}` 으로 기관 이름을 고정한다. 규칙 코드(`R1`)가 문장에 섞여 나온다(화면은 표시에서 지운다). 서버 .docx 의 개발 문자열(`PostGIS survey_findings (emd_cd …)` · `survey_finding_events` · `README §5` · `[법령 확인 · 2차 RAG]` · `inspected/closed/dismissed` · `건축HUB API 키 대기` · `서술: llm(인용 검사 통과)`)도 남아 있다. 화면 다운로드는 이제 이 파일을 쓰지 않지만 다른 경로로 받으면 그대로 나온다.
