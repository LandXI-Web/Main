## 명세와 다르게 한 곳 · 어댑터(서버 S-9 전)
1. **`power_budget` 없음**: 서버 `/ops/gpus` 에 `power_budget` 필드가 아직 없음. 서버 값이 있으면 그것을 쓰고, 없으면 ops-core 와 같은 규칙으로 계산함(이동평균 부하 50% 이상이면 고부하, 동시 한도 1 = `pools.yaml max_hot_gpus`). 두 화면의 숫자는 같게 나옴.
2. **관제 스트림 Origin**: `/events/ops` 가 아직 :8702 만 받음. 그래서 SSE 대신 2.5초 조회로 갱신함. 응답에 `power_budget` 이 생기면(S-9 반영 신호) SSE 를 자동으로 엶. 거절 응답이 콘솔에 찍히지 않게 하려는 처리임.
3. **시드 정리 전**: 시험용 복제 배포본 `…-test-n` 17건은 한 칸으로 접어서 보여 줌. 체험 계정 `lx-demo` 는 뺌.
4. **결재 요청**: `결재 요청` 은 `PUT /tenants/{id}/quota` 를 부름. 지금 서버는 이 호출을 받으면 결재 행을 **승인 상태로 바로** 적음. 대기 중인 결재로 쌓는 기능(S-9 `/approvals`)은 서버에 없음. 또 이 PUT 은 한도의 `note` 를 사유로 덮어써서 `[추정 기반 초기값]` 표기가 사라짐. 그래서 이번 점검에서는 제출까지는 하지 않고 시트와 입력 검증만 확인함.
5. **배포 시트 쓰기 동작**(단계 올리기 · 롤백 · 모듈 · 모델 교체 · GPU 배치): 버튼과 API 연결은 끝냄. 실데이터 상태를 바꾸지 않으려고 영상에서는 누르지 않음. 동작 규칙은 이렇게 넣음: 운영 단계면 `단계 올리기` 를 끔. 이전 버전이 없거나 단계가 시범·운영이 아니면 `롤백` 을 끔. 서버가 `approval_required` 로 거절하면 `결재 후 올릴 수 있습니다` 토스트를 띄우고 `결재`(ops-core 결재함) 링크를 붙임.
