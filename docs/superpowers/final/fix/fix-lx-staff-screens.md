# fix-lx-staff-screens — LX 직원 화면 5종: 용어 · 숫자 한 출처 · 완성형 버그

**배경(평가 P0/P1):** LX 직원 대시보드 '확인 대기 1,101' vs XI맵·서비스 상세 1,079 vs 결과 확인 745 · 기관 신고 24(대시보드) vs 16+6=22(서비스 관리 표). 데이터 올리기(lx-ingest) 남원 패널 '필지 결합률'이 4초 넘게 회색 스켈레톤. 학습(lx-train) 네 카드 정밀도가 모두 0.86 으로 같고, 해양쓰레기를 '첫 학습 전'이라 하면서 다른 화면은 운영이라 함. 서비스 관리 표 대부분 '0건 · —'.

## 소유 파일
- `landxi/v3/lx-console/**` · `landxi/v3/lx-ingest/**` · `landxi/v3/lx-train/**` · `landxi/v3/lx-review/**` · `landxi/v3/lx-deploy/**`

## 할 일
1. **용어:** 다섯 앱의 보이는 글자(html·js 문구·json)에서 생산 콘솔→`LX 직원 대시보드`, 반입→`데이터 올리기`/`영상 등록`, 조립·카드 만들기→`서비스 만들기`, 검수→`결과 확인`, 이식·심기→`다른 지역에 적용`/`배포`, 판독→`AI 분석`, 발행→`서비스 공개`, 운영(단계)→`서비스 관리`, 착지·봉투·계보 제거. 공정 레일 단 이름도 포함.
2. **숫자 한 출처:** 대표 수치(확인 대기·현장 확인 필요·기관 신고·탐지)를 `GET /api/v1/summary`(계약 `fix-server-summary.md`)에서 읽는다. 서비스 관리 표 합계와 대시보드 숫자가 같은 label 이면 같은 값이 되도록 표도 summary(`?card=`·`?region=`) 기준으로. 서버가 아직 없으면 계약 형식 목(`server/mock` 이 아닌 앱 내부 fetch 실패 처리)으로 개발하되 합격은 실서버로.
3. **lx-ingest 결합률 스켈레톤:** `app.js` 의 `D.joinRate` · 결합률 캐시 경로에서 응답이 늦거나 실패할 때 스켈레톤이 영원히 남는 원인 규명 → 응답 시 값, 실패 시 `—`+사유, 계산 중이면 진행 표시. 1440·390 둘 다.
4. **lx-train 정밀도:** 카드별 실제 모델 평가값을 registry/모델 기록에서 읽는다. 같은 값이 복사돼 있으면 제거하고 없는 값은 `—`. 해양쓰레기 학습 상태는 실제 모델·결과 보유 기준(summary 의 stage 와 모순 없게).
5. **썸네일 중복**(공유재산·하천·무허가 같은 이미지): 카드별 실제 결과 crop(`crop_url`)이 있으면 그것으로. 없으면 교체하지 말고 `Fable 에게 넘길 것`.
6. 로딩 중 '아직 결과가 없습니다' 오표시가 있으면 `불러오는 중`으로.
