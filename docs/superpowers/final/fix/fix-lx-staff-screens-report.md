## 원인과 조치
- **lx-ingest 결합률 스켈레톤:** 결합률 분자(`GET /results/{set}/parcels?emd_cd=…`)가 서버에서 남원 전체 필지 × AI 결과(토지피복 12.9만 탐지) 공간 결합을 매번 새로 계산해 **22–32초** 걸린다. 화면은 응답이 올 때까지 `is-loading` 스켈레톤만 두었고, 키트 bignum 의 20초 '불러오는 중→아직 결과가 없습니다' 전환이 응답(22s+)보다 먼저 와서 '결과 없음'이 잠깐 비치기도 했다. 또 지역 경계가 없을 때(`!geo.bbox`)는 스켈레톤을 끄는 경로가 없었다.
  → 서랍이 열린 뒤 1.5초에도 값이 없으면 '—' + `계산 중` + 진행 막대(bignum 타이머는 empty() 로 끔), 값이 오면 그 자리에서 숫자, 실패면 '—' + `결합률을 불러오지 못했습니다`, 경계 없음·결과 없음은 '아직 결과가 없습니다'. 두 번째 방문부터는 기존 1시간 캐시로 즉시 값.
  - 측정(로그인 폼 · 캐시 비움): 1440 = 서랍 1.19s → 사유 표시 2.75s → 값 32.3s · 390 = 1.14s → 2.60s → 27.6s. 실패 모의(응답 503) = 2.46s 에 사유. `after/ingest-timing-{1440,390}.json`

- **해양쓰레기 '첫 학습 전' vs 운영:** 등록된 모델 목록(/registry/models)에 해양쓰레기 모델이 없어 '첫 학습 전'으로 그렸다. summary 는 card-marine = 운영(실결과 1,857 탐지). → `tasks.json` 에 이 업무 전용 카드(`card: card-marine`)를 적고, 모델 기록이 없어도 summary stage 가 운영·시범이면 '학습 기록 없음'(서랍: '이 업무의 AI 결과는 있지만 모델 학습 기록이 아직 등록되지 않았습니다') + 그 카드의 실제 결과 크롭(crop_url). summary 가 없을 때만 카드 기록 단계로 대체.
