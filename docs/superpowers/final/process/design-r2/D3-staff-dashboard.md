# D3. LX 직원 대시보드 — 답해야 할 질문과 첫 화면 (FR-5)

> 지위: 사용자 확인 전 제안(FR-5 "다시 기획"). 코드는 고치지 않았다.
> 사용자 원문(09-30): "정말 대시보드의 중요한 역할인지, 메인에 뭐가 표출되어야 LX 직원에게 도움될지 고민 필요. 지금은 의미가 크게 없다." · (09-27) "LX 직원 관점에서 도통 이해가 안 된다 — 이게 뭐야? 우리는 뭘 해야 하지? 어떤 서비스를 만들 수 있지? 어떻게 지자체에 제공하지?"

## 1. 원래 의도(근거)
- 옛 대시보드(LX 직원 첫 화면): "AI 분석 결과와 학습데이터가 어디에 쌓였는지 한눈에" — 큰 숫자 3(발행 서비스 · AI 분석 결과 · 학습데이터 영상) + 전국 판(결과 / 학습데이터 토글) + 프로젝트별 저장 용량. 즉 **'우리가 만든 것이 전국 어디에 얼마나 있나'** 를 답하는 판이었다.
- 09-20 명세 "양산이라는 말의 뜻": LX 화면은 네 가지를 보여야 한다 — 지금 몇 개를 만들고 있나 · 무엇이 공개 대기인가 · 만든 것이 어디에 깔렸나 · 다음에 무엇을 만들 것인가.
- 최종 명세: "오늘 할 일 · 만들 수 있는 것 · 깔린 곳이 전국 지도 한 화면에."
- 지금 v3: '오늘' 4칸(결과 확인 대기 2,878 · 재학습 3 · 적용 요청 3 · 기관 신고 96) + 지도 위 단계 6개. 첫 항목 열기는 눌러도 반응 없음. '만들 수 있는 것·깔린 곳'은 서랍 안에 숨어 있음.

## 2. 왜 지금 의미가 약한가
- 4칸이 **전국 합계**라 '내가 오늘 할 일'로 읽히지 않는다(결과 확인 대기 2,878건은 아무도 오늘 처리하지 못한다).
- 4칸 중 둘(재학습·기관 신고)은 계산 방식이 화면마다 달라 신뢰가 안 간다(D5 §2).
- '우리가 만든 서비스가 어디서 돌고 있나'와 '다음에 무엇을 만들 수 있나'가 첫 화면에 없다 — 사용자 09-27 세 질문에 답하지 못한다.
- 지도가 배경인데 지도 위 점이 무엇인지(배포·영상·결과) 설명이 없다.

## 3. 설계 — LX 직원이 아침에 열었을 때 답할 질문 3개
| # | 질문 | 첫 화면 칸 | 숫자 한 출처 |
|---|---|---|---|
| Q1 | **오늘 내가 처리할 것은?** | '오늘 할 일' — 결과 확인(내 표본 몫) · 적용 요청(내가 낸 것의 결재 상태) · 오탐 신고(내 서비스에 온 것) · 공개 대기(내 서비스) — 각 칸 클릭 = 그 목록 첫 항목 | 요약 API 한 곳(D5 §5 재계산 규칙 적용) |
| Q2 | **우리 서비스가 어디서 돌고 있나?** | '돌고 있는 서비스' — 서비스 n개 · 운영 지역 n곳 · 이번 달 새로 적용 n곳 + 전국 지도의 점(서비스별 색, 점 클릭 = 그 지역 결과) | 서비스 목록·배포본 API |
| Q3 | **다음에 무엇을 만들 수 있나 / 만드는 중인가?** | '만드는 것' — 만드는 중 n(학습 중·공개 대기) · 만들 수 있는 업무 n/10 · 재학습 필요 n — 클릭 = ③ 서비스 만들기 / ② 학습 / ⑥ 서비스 관리 | D2 서비스 목록 · D5 재학습 신호 |

### 3-1. 첫 화면 구성(글 예산 300자 · 큰 숫자 3개 이하)
- 위 띠: 인사 한 줄 없음. 세 카드(Q1·Q2·Q3)를 가로로. 각 카드 = 제목 + 큰 숫자 1 + 작은 줄 2–3.
- 가운데: 전국 지도(밝은 바탕) + 서비스별 점. 오른쪽 위 작은 범례(서비스 이름 · 색). 지도 위 단계 레일(① 데이터 올리기 ~ ⑥ 서비스 관리)은 유지 — 단계는 일의 순서를 알려 주는 길잡이.
- 아래 띠: 최근 일어난 일 3줄(예: "구례군 농지이용 전역 분석 끝남 · 어제", "광주전남 오탐 신고 4건 · 오늘") — 클릭하면 그 화면. 운영 서사 금지, 실제 이벤트만.
- 없애는 것: 전국 합계만 있는 '결과 확인 대기 2,878' 같은 큰 숫자. 개발 정보·내부 지표.

### 3-2. '내 것'의 뜻
- LX 직원에게 **담당 서비스·담당 지역**을 둘 수 있다(관리자가 지정, 없으면 전체). Q1은 담당 기준, Q2·Q3은 전체. 담당이 없으면 Q1도 전체를 보여 주되 '전체' 표시.

### 3-3. 각 칸의 클릭 도착지(작동 안 됨 → 됨)
| 칸 | 도착 |
|---|---|
| 결과 확인 n | ④ 결과 확인, 1순위 지역·필지가 열린 상태 |
| 적용 요청 n | ⑤ 배포, 내 요청 행 강조 |
| 오탐 신고 n | ⑥ 서비스 관리 → 신고함(D5) |
| 공개 대기 n | ③ 서비스 만들기 목록, 해당 서비스 |
| 운영 지역 n곳 | ⑤ 배포 한눈표(서비스 × 지역) |
| 만들 수 있는 업무 n/10 | ③ 만들 수 있는 업무 표 |
| 재학습 필요 n | ⑥ 서비스 관리, 재학습 신호 열 |

## 4. 구현 계획
1. **서버**: 요약 API에 세 묶음(오늘 할 일 · 돌고 있는 서비스 · 만드는 것)을 한 번에 — 계산 규칙은 D5 §5(오탐 신고 = 오탐만, 재학습 = 한 규칙). 담당 지정(직원 ↔ 서비스·지역) 필드 추가. 최근 일어난 일 = 실제 이벤트 기록에서.
2. **화면**: 4칸 → 세 카드 + 지도 범례 + 최근 일 3줄. 모든 칸 클릭 도착지 연결(FR-5). 글 예산 검사.
3. **실증**: 두 직원 계정(담당 있음/없음) · 두 지역.

## 5. 완료 기준
- 첫 화면 글 300자 이하, 큰 숫자 3개 이하, 지어낸 숫자 0.
- 카드 7개 칸 클릭 → 7곳 모두 도착·강조(첫 항목 열기 포함).
- 첫 화면 숫자와 ③·⑤·⑥ 화면·관리자 화면의 같은 이름 숫자가 같은 값.
- 담당을 지정한 직원과 지정하지 않은 직원의 Q1 숫자가 다르게(담당 있으면 그 범위만) 나온다.

## 6. 확인받을 선택지
1. **세 질문(Q1 오늘 할 일 · Q2 돌고 있는 서비스 · Q3 만드는 것)과 첫 화면 구성** — 확인 / 보류 / 반려.
2. **'오늘 할 일'의 범위** — ⓐ 관리자가 직원마다 담당 서비스·지역을 지정, 없으면 전체 / ⓑ 담당 개념 없이 항상 전체(지금처럼).
3. 지도 유지 여부 — ⓐ 전국 지도 + 서비스 점 유지 / ⓑ 지도 없이 카드·목록만(08-26 초기 결정과 같은 방향).
