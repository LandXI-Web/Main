**한 줄 정의: 서비스 만들기 = 학습·결과 확인이 끝난 AI 모델을 '행정 업무 하나 = AI 분석 서비스 한 벌'로 묶어(모델 + 판정 규칙 + 대장 형식 + 영상 조건 + 결과 보여 주는 방법 + 전용 기능 목록) 이름을 붙이고 공개하는 일. 만들어진 서비스는 '다른 지역에 적용'을 거쳐 기관 플랫폼에 서비스 카드로 나타난다.**

## 2. 옛 자산이 정의한 서비스(카드)의 구성과 순서
- 카드 = 행정 업무명 + 근거 업무 + 묶은 모델(여러 개 가능) + 공통 기능 7(영상 → AI 분석 → 결과 확인 → 지도 → 행정구역 통계 → 보고서 → 권한) + 전용 기능(LX 몫/기관 몫 표시) + 결과 종류 선언(입력·출력·표현) + 이식 가능 여부 + 필요한 것(필지 레이어·영상 시점 등) + 버전(큰 변경/작은 변경/수정).
- 발행 흐름: LX 직원이 **발행 요청**(신규 / 고도화 · 대상 사업(국내/해외) · 권한) → **LX 관리자 검토·승인** → 발행 카드 목록에 '공개'. 반려 사유 예: "정확도 기준 미달".
- 만들어져 기관에 닿기까지: 영상·라벨·학습 → 결과 품질 → **서비스 만들기(발행)** → 매칭(기관 업무 접점) → 이식 점검(지역 프로파일 × 필요한 것) → 기관 표지 등록 → 배포본 심기 → 화면 생성 → 현지 영상 연결 → 검수·개통 → 기관 서비스 카드 → 서비스 관리(재학습·갱신·확대).
- 옛 관리자 '생산 관리' 화면은 이 순서를 5단으로 보여 줬다(고정 Geo-AI 생산 → 산출 표준 → 매칭 → 화면 생성 → 기관 전달).

## 4. 설계
### 4-1. 두 낱말을 분명히
| 화면 말 | 뜻 | 누가 |
|---|---|---|
| **서비스 만들기** | 모델을 행정 업무 서비스로 묶어 이름 붙이고 **서비스 공개**(관리자 결재)까지 | LX 직원 → LX 관리자 승인 |
| **다른 지역에 적용** | 공개된 서비스를 특정 기관·지역에 심는 것(배포본) → 기관 플랫폼에 '서비스 카드' | LX 직원 요청 → LX 관리자 승인 → 자동 분석 |
- 첫 화면 ③ 표의 버튼은 '서비스 만들기'만 한다. '적용'은 ⑤ 배포에서만.

### 4-2. 서비스 만들기 화면(LX 직원 대시보드 ③)
1. **서비스 목록** — 우리가 만든 서비스 전부: 이름 · 버전 · 상태(만드는 중 / 공개 대기 / 공개 / 보류) · 모델 · 규칙 수 · 대장 형식 · 적용된 지역 수 · 재학습 필요 표시. 한 줄을 열면 서비스 상세(구성 · 적용 지역 · 이력 · 새 버전 만들기).
2. **만들 수 있는 업무** — 지금 표(업무 × 모델·대장 형식·영상·규칙 있음/없음)는 '다음에 무엇을 만들 수 있나' 안내로 유지. 네 칸이 찬 행에만 `이 업무로 서비스 만들기`.
3. **새 서비스 만들기(4단 시트)**
   - ① 업무: 행정 업무명(직접 입력 또는 표에서) · 근거 업무 한 줄 · 대상(국내 / 해외).
   - ② 분석: 모델(여러 개 선택 가능) · 판정 규칙(체크) · 기준값 · 영상 조건(해상도·시점 수).
   - ③ 행정 자료·결과: 대장 형식(있으면) · 결과 보여 주는 방법(지도 층 / 필지 목록 / 행정구역 통계 / 시점 비교 / 보고서 서식) · 기관 전용 기능 목록(이름만, 예: '노선 구간화' — 기관 몫으로 표시).
   - ④ 확인: 요약 + `공개 요청` → LX 관리자 결재함에 '서비스 공개' 항목.
4. **공개 뒤** — 목록 상태 '공개' · 배포 화면 '다른 지역에 적용' 목록에 뜸 · 영업 화면 서비스 목록에 뜸.
5. **새 버전** — 재학습 뒤 '새 버전 만들기'(큰 변경: 다시 분석 필요 / 작은 변경: 다음 주기부터 / 수정: 바로 반영) → 적용된 지역마다 갱신 알림(FR-27).

### 4-3. 기관 쪽(서비스 카드)
- 기관 첫 화면의 서비스 카드 = 그 기관에 적용된 배포본 한 줄. 카드에는 서비스 이름·연도·상태(운영/준비)·결과 요약 숫자·버전·새 버전 알림. 카드를 열면 그 서비스의 작업 공간(D4 §4-3).
- 기관은 서비스를 만들지 않는다. 기관이 낼 수 있는 것은 오탐 신고(D5)와 '이 기능이 필요하다' 요청(다음 차수).

### 4-4. 첫 화면 세 질문과의 연결(D3)
"어떤 서비스를 만들 수 있지?" → 만들 수 있는 업무 n/10 · "우리는 뭘 해야 하지?" → 공개 대기·재학습 필요 · "어떻게 제공하지?" → 적용된 지역 수 → ⑤ 배포.

## 5. 구현 계획
1. **서버**: 서비스(카드) 생성 API를 한 곳으로(업무명·대상·모델 여러 개·규칙·기준값·영상 조건·대장 형식·결과 표현·전용 기능 목록) · 상태 '공개 대기' → 결재 항목 '서비스 공개' → 승인 시 '공개' · 서비스 목록 API(적용 지역 수·재학습 표시 포함) · 새 버전 규칙(큰/작은/수정) 저장.
2. **화면**: 첫 화면 ③ = 서비스 목록 + 만들 수 있는 업무 + 4단 시트. 학습 화면 원스톱의 마지막 단은 같은 시트를 연다(호출 하나). 배포 화면은 '공개' 서비스만 고르게.
3. **관리자**: 결재함에 '서비스 공개' 종류 추가(FR-3 과 함께).
4. **실증**: 갖춰진 업무 1개(예: 농지이용)로 새 서비스 → 관리자 승인 → 배포에서 서로 다른 시도 두 지역에 적용 → 기관 플랫폼 서비스 카드 확인.

## 6. 완료 기준
- 첫 화면 ③ 에서 새 서비스 1건 만들기 → 관리자 결재함 '서비스 공개' 1건 → 승인 → 목록 상태 '공개'.
- 배포 화면 '다른 지역에 적용'에 그 서비스가 뜨고, 적용 요청 → 승인 → 기관 첫 화면 서비스 카드 1장.
- 학습 화면 원스톱의 '서비스 만들기'와 첫 화면의 버튼이 같은 시트·같은 결과.
- 서비스 목록 숫자(서비스 수·적용 지역 수)가 첫 화면·관리자 화면·영업 화면에서 같은 값(숫자 한 출처).

## 7. 확인받을 선택지
1. **서비스 공개에 관리자 결재** — ⓐ 옛 자산처럼 LX 관리자 승인 뒤 공개(적용 결재와 별개) / ⓑ 직원이 바로 공개하고 결재는 '다른 지역에 적용' 때만.
2. 정의(서비스 만들기 = 모델을 행정 업무 서비스로 묶어 공개 · 적용은 별도 단계 · 서비스 목록 + 4단 시트) — 확인 / 보류 / 반려.
