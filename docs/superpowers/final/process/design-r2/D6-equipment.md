## 1. 지금 상태(실측)
| 항목 | 지금 |
|---|---|
| 장비 | 노드 1대(작업용 PC · GPU 2장). 확장용 GPU 서버 2대는 '등록 대기' 자리만 |
| GPU 통제 | 동시 고부하 GPU ≤ 1장(작업기가 임대를 잡아야 분석 시작) · 장당 전력 상한 200W(부팅 때 자동 적용) · 언어 모델은 다른 GPU가 바쁘면 기동 거부 · 기동 스크립트의 전력 검사는 경고만 |
| 작업 대기열 | 풀별 대기열, 취소·재큐·우선순위 API는 있으나 관리자 화면에 버튼 없음 |
| 저장 공간 | 드라이브 3개 사용량 측정·표시(C: 여유 68GB · D: 364GB · E: 1.9TB). 기관별 사용량 계산은 두 방식이 서로 다름. **기관 저장 한도는 알림뿐, 실제로 막지 않음** |
| 장비 추가 | '가입 토큰 발급'까지만 있고, 토큰을 받아 노드를 붙이는 쪽이 없음 |
| 증설 계산 | 옛 화면에 있었으나 지금 화면에는 없음 |

## 2. 방향(순서대로, 구현은 사용자가 정하는 때에)
### 2-1. 원칙
- **전력 예산이 1급 제약.** 노드마다 '동시 고부하 GPU 수'와 '장당 전력 상한'을 갖고, 대기열은 이 안에서만 배정한다. 지금 PC는 1장. 새 서버는 그 서버의 전원 용량으로 따로 정한다(두 장 동시 금지 규칙은 이 PC의 규칙이고, 새 서버에는 그 서버의 값).
- **관리자 화면 안에서 끝난다**(원스톱). 명령줄·설정 파일 수정 0.
- **숫자 한 출처**: 장비·대기열·저장·기관 사용량은 측정 한 곳에서, 화면·경보·기관 화면이 같은 값.
- 화면에 GPU 모델명·ms 같은 개발 정보는 쓰지 않는다. 관리자에게 필요한 말은 '고부하 n/m · 대기 n · 여유 n TB'.

### 2-2. 네 묶음
| 묶음 | 무엇을 | 왜 · 전력 규칙과의 관계 |
|---|---|---|
| ① 장비 등록 | '장비 추가'(이름 · 주소 · GPU 수 · 이 장비의 동시 고부하 한도 · 전력 상한) → 가입 토큰 → 새 장비가 토큰으로 붙으면 대기열 풀에 합류 · 상태(연결됨/끊김) · 빼기(작업 비운 뒤) | 확장(A100 서버)이 화면에서 끝나야 완전체. 한도는 장비별 |
| ② GPU 통제 | 장비 표(부하 · 메모리 · 전력 · 지금 작업) · 대기열 조작(취소 · 다시 넣기 · 우선순위) · 언어 모델 켜기/끄기 · 모델 상주 고정 · 전력 규칙 위반 시도 기록(겹침 횟수) | 지금 서버 규칙을 화면에서 보고 조작. 규칙 값 변경은 결재 |
| ③ 저장 공간 배분 | 드라이브별 여유 · 자료 등급별(원본 영상 / 타일 / 결과 / 기관 올린 것) · **기관별 사용량과 한도** · 한도 초과 정책(알림 / 저부하 / 거부)을 실제로 적용 · 증량 신청(기관 → 결재) · 여유 200GB 아래 경보 · 원본 영상은 어느 드라이브에 두는지 지정 | 사용자 "SSD 자원 배분". 지금은 알림뿐 |
| ④ 증설 계산 | 적용 지역 × 서비스 종류 × 면적 → 저장 · GPU 시간 · 타일 트래픽 예상 → "이 지역을 더 하면 저장 +n TB · GPU +n시간" · 여유가 n개월 남음 | 옛 화면의 기능. 관리자가 "언제 서버를 더 사야 하나"에 답 |

### 2-3. 하지 않을 것
- 기관에 물리 SSD를 나눠 주는 방식(기관별 폴더·한도로 나눈다). 관리자가 GPU를 손으로 골라 작업을 배정하는 화면(대기열이 한다).

## 3. 구현 순서 제안(나중)
1. ③ 저장 한도 실제 적용 + 기관별 사용량 계산 한 방식으로 통일(작은 일, 효과 큼).
2. ② 대기열 조작 버튼 + 전력 규칙 표시(API는 있음).
3. ① 장비 등록(토큰 받는 쪽 구현 = 새 서버가 왔을 때).
4. ④ 증설 계산.

## 4. 완료 기준(그때 판정)
- 관리자 화면에서 장비 1대 추가 → 대기열 표에 나타남 → 작업이 그 장비에도 배정 → 전력 규칙 위반 0.
- 기관 한도 초과 → 정책대로 막힘/알림 · 증량 신청 → 결재 → 반영. 명령줄 0.
