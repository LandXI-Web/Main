# D4. 기관 분기 플랫폼의 위계 (FR-12 · FR-4 · FR-13 · FR-14 반영)

> 지위: 사용자 확인 전 제안(FR-12 "반려 → 다시 기획" · FR-4 "확인, D4와 함께" · FR-13 "확인(보완)" · FR-14 "반려, 위계는 D4에"). 코드는 고치지 않았다.
> 사용자 원문(09-30): "남원시도 엄밀히 보면 관리자-사용자가 분명 있다. 농정과는 농지이용 전수조사 기능들에 대한 서비스만 볼 것이고… 부서별로 다르다. 그런데 이 또한 공통 기능화할 수 있는 범위만 한정해서 메인 화면이어야. 자유도가 높을수록 복잡도가 높아지고 통제 관리가 어려움" · "Land-XI 플랫폼은 LX 직원이, 분기화된 남원 GeoVision 플랫폼은 남원시 직원이 보는 용도" · "광역은 광역 전체나 세부적으로 시군구 단위로 보고 싶어 할 것" · "다른 지역 정보는 호출도, 보지도, 열리지도 않는다."

## 1. 원래 의도(근거)
- 옛 기관 포털은 **'남원시 GeoVision 플랫폼'·'전남광주 AI 플랫폼'** 처럼 기관 이름·표지를 가진 **다른 사이트**였다(사용자 09-21: "지자체에서는 나만의 AI 시스템인 것처럼 보여야 한다. LX에 위탁은 하지만"). 메뉴는 `내 서비스`뿐, 서비스 카드를 열면 작업 공간(현황·분석 결과·지도·통계·보고서).
- 옛 사용자 관리 화면(원본은 남원시청 사이트)은 **기관 안 위계**를 갖고 있었다: 시청 직원이 부서·직위를 적어 가입 → **기관 관리자('남원시청 관리자')가 승인** → 권한 1개 부여(사료작물 분석 / 농지 활용 분석 / 영농 정보 분석 / 일반). 즉 권한이 **서비스 단위**였다 — 사용자의 "농정과는 농지이용 전수조사만"과 같은 개념. 비밀번호 5회 실패 잠금·초기화·3개월 변경 정책·로그인 이력도 있었다.
- 09-24 결정("기관 계정은 LX와 완전 별도") 뒤 기관 쪽 계정·역할 화면이 사라졌고, 지금 서버에는 기관 역할이 `담당자 / 열람자` 둘뿐, 부서·서비스 권한 칸이 없고, 계정을 만드는 기능도 없다.
- 광역: 옛 자산은 '행정단위 말'만 바꿨고(시·군·구별 집계) 시군구를 고르는 화면이 없었다. 지금 서버는 광역 관할을 시도 단위로 준다.

| 관할 밖 지역이 검색 제안에 뜬다 | S3-16 |

## 3. 설계 — 위계
```
Land-XI 플랫폼 (LX)                    기관 플랫폼 (예: 남원시 GeoVision — 같은 서버의 분기)
  LX 관리자 ── 기관 만들기·승인 ──▶  기관 관리자 ── 부서·사용자 만들기 ──▶ 부서 사용자
  LX 직원   ── 서비스 적용 ────────▶  (기관 서비스 카드)                    (배정된 서비스만)
```
| 역할 | 누가 | 무엇을 본다 | 무엇을 한다 |
|---|---|---|---|
| **LX 관리자** | LX 운영 책임자 | 전국·모든 기관 | 기관 만들기(이름·관할·국내/해외·언어·표지) · 첫 기관 관리자 계정 발급 · 기관 한도 · 서비스 적용 승인 |
| **기관 관리자** | 기관의 관리 부서 담당(예: 정보통신·기획) | 자기 기관 관할 전체 · 모든 서비스 · 모든 부서 할 일·보고서 | 부서 만들기 · 부서 ↔ 서비스 연결 · 사용자 만들기·승인·비밀번호 재설정·잠금 해제 · 기관 표지 · 한도 조정 요청 · 영상 등록 요청 |
| **부서 사용자** | 업무 부서 담당(예: 농정과) | 자기 부서에 연결된 서비스만 · 그 서비스의 관할 결과·할 일·보고서 | 대장 올리기 · 결과 보기 · 필지 판정·조치 기록 · 보고서 · 오탐 신고 · 말로 묻기(자기 서비스 범위) |
| (선택) 열람자 | 부서 안 열람만 하는 사람 | 부서 사용자와 같은 범위 | 보기만(올리기·판정 없음) |
- 계정 범위 = **기관 관할 ∩ 부서 관할(선택) ∩ 부서 서비스.** 서버가 이 범위 밖은 검색 제안·지도·영상·필지·AI 도우미 모두 내주지 않는다(원칙 39). 화면에서 숨기는 것이 아니다.

### 3-1. 부서 ↔ 서비스 연결
- 기관 관리자가 '부서'를 만들고(이름 · 관할 시군구 선택(광역만) · 담당 서비스 체크). 사용자는 부서 하나에 속한다. 부서 사용자가 로그인하면 그 부서 서비스 카드만 보인다(예: 농정과 = 농지이용 전수조사 1장, 도로과 = 도로 안전 1장).
- 한 부서에 서비스 여러 개 가능(예: 환경과 = 생활환경 위험요소 + 하천 점용). 기관 관리자는 모든 카드.
- 옛 자산의 '권한 = 서비스 1개'보다 한 단계 위(부서)에 묶는다 — 사용자 원문이 부서 단위.

### 3-2. 기관 메인 = 부서 공통 기능만(자유도 최소)
| 기관 메인(공통) | 서비스 카드 안(부서·서비스별) |
|---|---|
| 내 서비스 카드(부서에 연결된 것만) · 관할 지도(XI맵, 관할만) · 할 일 n · 보고서 목록 · 알림(새 버전·신고 처리 결과) · 도움말·내 계정 · (기관 관리자만) 부서·사용자 관리 | 결과 지도·필지 목록 · 대장 올리기·결합 · 말로 묻기 · 필지 판정·조치 · 보고서 초안 · 오탐 신고 · 서비스별 도구(시점 비교·밀도 지도 등, 서비스가 선언) |
- 메인에 서비스 전용 기능을 올리지 않는다. 기관마다 메인이 달라지는 것은 표지(이름·마크·색·행정단위 말·문의처)뿐.
- 첫 화면 도착: **서비스 카드부터**(카드 1장이면 바로 그 서비스 작업 공간으로). '최근 대장'은 서비스 안의 목록으로 내려간다(누가·언제 올렸는지와 함께, 내가 올린 것 먼저).

### 3-3. 기관·계정 만들기 흐름
| 단계 | 누가 | 어디서 | 내용 |
|---|---|---|---|
| 1 | LX 관리자 | LX 관리자 대시보드 → 기관 | 기관 만들기: 이름 · 국내/해외 · 관할(시군구 여러 개 또는 시도 전체) · 언어 · 표지(이름·마크·색·행정단위 말·문의처) · 한도 초기값 |
| 2 | LX 관리자 | 같은 곳 | 첫 기관 관리자 계정 발급(아이디 · 임시 비밀번호 · 첫 로그인 때 변경 강제) |
| 3 | 기관 관리자 | 기관 플랫폼 → 부서·사용자 관리 | 부서 만들기 · 부서 ↔ 서비스 연결(적용된 서비스 중에서) |
| 4 | 기관 관리자 | 같은 곳 | 사용자 만들기(이름·부서·역할) → 임시 비밀번호 / 또는 직원 가입 신청 승인(갈림길 §6 ①) |
| 5 | 기관 관리자 | 같은 곳 | 비밀번호 재설정 · 잠금 해제(5회 실패) · 사용 중지 · 로그인 이력 |
| 6 | LX 관리자 | LX 관리자 대시보드 | 기관 사용 중지·재개 · 기관 관리자 교체 · 기관별 계정 수·마지막 로그인 |
- LX 직원은 기관 계정을 만들지 않는다. LX 관리자는 기관 사용자 개개인을 만들지 않는다(기관 관리자 몫) — 통제선이 분명해진다.

### 3-4. 광역 기관 보기
- 관할이 시군구 여러 개(광역·도)인 기관: 메인 도착 = **광역 전체 집계**(서비스 카드 숫자는 관할 합계) + 지도 위 시군구 경계. 시군구를 고르면 그 시군구로 좁혀지고(주소에 남음), '전체로' 버튼으로 돌아온다. **화면이 대신 고르지 않는다**(최근 선택은 기억만, 표시로 알림).
- 부서를 시군구 단위로 만들 수도 있다(예: 도 농정과는 전체, 시군 파견 부서는 그 시군만) — 부서 관할 선택.
- 결과 확인·보고서 화면도 같은 규칙: 전체(시군구별 표) ↔ 시군구.

### 3-5. 해외 기관
- 같은 위계(기관 관리자·부서 사용자). 관할은 현지 행정단위(District). 표지·언어만 다르다.

## 4. 구현 계획
1. **서버**: 기관 사용자에 `부서 · 역할(기관 관리자/부서 사용자/열람자)` · 부서 표(이름·관할·서비스 목록) · 기관·부서·사용자 만들기/승인/비밀번호 재설정/잠금 API(활동 기록 남김) · 관할 판정을 '기관 관할 ∩ 부서 관할', 서비스 접근을 '부서 서비스'로 — 검색 제안·지도·타일·필지·AI 도우미·보고서 모두 같은 판정 함수.
2. **LX 관리자 화면**: 기관 탭에 '기관 만들기 · 첫 관리자 발급 · 사용 중지' (FR-4).
3. **기관 플랫폼**: 메인 = 서비스 카드(부서 것만) + 공통 기능. 기관 관리자 전용 '부서·사용자 관리'. 광역 전체/시군구 전환. 최근 대장은 서비스 안으로.
4. **실증**: 기관 2곳(기초 1 · 광역 1) × 계정 3종(기관 관리자 · 부서 사용자 2개 부서) — 부서 사용자가 다른 부서 서비스·관할 밖 시군구를 어떤 경로로도 못 여는지(주소 직접 입력 포함) 확인.

## 5. 완료 기준
- LX 관리자 화면만으로 새 기관 + 첫 기관 관리자 → 그 계정으로 기관 플랫폼 로그인 → 부서 2개·사용자 2명 만들기 → 각 사용자가 자기 부서 서비스 카드만 봄.
- 부서 사용자가 주소를 직접 쳐서 다른 서비스·관할 밖 시군구를 열면 서버가 거부(데이터 0) · 검색 제안에 관할 밖 0.
- 광역 기관 관리자: 도착 = 전체 집계, 시군구 고르기 → 좁힘 → 전체로 복귀. 화면 자동 선택 0.
- 잠금(5회 실패) → 기관 관리자가 해제 → 로그인 됨. 모든 계정 작업이 활동 기록에 남음. DB 손작업 0.

## 6. 확인받을 선택지
1. **기관 사용자 계정 발급 방식** — ⓐ 기관 관리자가 만들어 준다(임시 비밀번호) / ⓑ 옛 자산처럼 직원이 가입 신청하고 기관 관리자가 승인 / ⓒ 둘 다(기관 관리자가 켜고 끔).
2. **부서 단위 연결**(부서 ↔ 서비스, 사용자는 부서 하나) — 확인 / 옛 자산처럼 사용자마다 서비스 1개 권한 / 보류.
3. **광역 보기**(도착 = 전체 집계, 시군구 고르기, 자동 선택 0, 부서 관할 선택 가능) — 확인 / 보류 / 반려.
