# D5. 오탐 신고(FR-9) · 재학습 판단(FR-10)

> 지위: 사용자 확인 전 제안(FR-9·FR-10 "더 구체적으로 설계"). 코드는 고치지 않았다.
> 사용자 원문(09-30): 오탐 신고는 "LX 직원과 기관 이용자가 주로 쓸 기능", 재학습 판단은 "LX 직원이 주로 쓸 기능 — 더 구체적으로 설계".

## 1. 원래 의도(근거)
- 09-20 명세 '생산화': "다섯 임무(성능 감시 · 선제 재학습 · 표본 검수 · 갱신 배포 · 적용 확대) **전부 LX 몫**이다. 기관 임무는 **오류 신고 하나뿐**이며, 그것은 보조 신호다." 사용자 원문: "기관이 찾은 오탐 재학습도 있겠지만, LX가 적극적으로 이 임무와 역할을 해야 이 플랫폼은 비즈니스 사업화할 수 있다."
- 재학습 기준(옛 명세): 신뢰도 0.60 · 겹침 정확도 0.70 · 마지막 학습 365일 · 표본 100건. **기관 신고 5건 이상은 '표본 검수' 신호**였지 재학습 신호가 아니었다.
- 실태조사 명세: 오탐 원인 4분류(AI가 잘못 봄 · 대장이 오래됨 · 기준값이 엄함 · 계절 요인) → 'AI가 잘못 봄'만 재학습 표본으로, '기준값'은 임계 재교정 제안으로. "판독 오류 비율이 높은 종류·지역이 곧 다음 학습 데이터 수집 지역이다."
- 옛 화면에는 기관이 신고를 보내는 기능이 실제로는 없었다(문구만). 자산 대장의 '오류 신고' 항목은 실제로는 보고서 발급 요청 화면(이름이 잘못 붙음).

## 3. 설계 — 오탐 신고(기관 · LX 양쪽)

### 3-1. 기관 쪽 신고 흐름(부서 사용자·기관 관리자)
1. **어디서**: ① 필지 판정 화면에서 '대장과 같음(AI가 잘못 봄)'을 고를 때 ② 결과 지도의 필지 카드 `오탐 신고` ③ XI맵 필지 카드 `오탐 신고`.
2. **무엇을 적나**(30초 안에): 이유 4택(AI가 잘못 봤어요 / 대장이 오래됐어요 / 기준이 너무 엄해요 / 계절·일시적이에요) · 메모 한 줄(선택) · 현장 사진(선택). 필지·AI 근거·영상 조각은 자동으로 붙는다.
3. **접수**: 신고 번호 · '접수됨'. 기관 메인 알림과 서비스 안 `내 신고` 목록에 상태가 보인다: 접수 → 확인 중 → 처리 결과(맞는 탐지였어요 / 오탐 — 다음 학습에 반영 / 기준값 조정 예정 / 대장 확인 요청).
4. **되돌아옴**: LX가 처리하면 기관 `내 신고` 상태가 바뀌고 알림 한 줄. '오탐'으로 처리된 필지는 기관 할 일에서 빠진다(다시 조사 안 하게).
- 신고는 그 서비스·그 기관 범위 안에서만(원칙 39). 판정 '대장과 같음'은 신고로 자동 접수되되, 화면에 "오탐 신고로 접수됩니다" 한 줄을 보여 준다.

### 3-2. LX 직원 쪽 처리 흐름(⑥ 서비스 관리)
1. **신고함**: 서비스 관리 표의 `신고 n건`(오탐만 센다) → 신고함. 묶음 = 서비스 × 기관. 각 묶음에 미처리 n · 30일 추이 · 이유 분포(4택).
2. **건별 처리**: 목록(필지 · 이유 · 기관 메모 · 사진 · 접수일) → 한 건 열면: 영상 조각(시점 비교) · AI 근거(종류·신뢰도·면적) · 대장 값 · 기관 의견. 판정 3택: `맞음(탐지 맞음)` / `오탐` / `모름`. 오탐이면 원인 4분류 확인(기관이 고른 값이 기본).
3. **판정 뒤 자동으로**: 오탐(AI가 잘못 봄) → **재학습 표본에 넣기**(라벨 큐) · 오탐(기준값) → **임계 조정 제안**(결재) · 오탐(대장 오래됨) → 기관에 '대장 확인 요청' · 계절 → 다음 시점 재분석 표시. 맞음 → 기관에 '맞는 탐지' 회신 + 정밀도 통계에 반영.
4. **한 번에 여러 건**: 같은 필지 묶음·같은 이유는 체크해서 한꺼번에 판정.
5. LX 직원의 결과 확인(④) 표본 판정 '오탐'도 같은 표본 큐·같은 통계로 들어간다(경로 하나).

## 4. 설계 — 재학습 판단(LX 직원)
### 4-1. 신호 5개와 '다음 할 일'
| 신호 | 기준(초기값, 조정은 결재) | 근거 |
|---|---|---|
| 표본 정밀도 | 확인 표본 ≥ 20건이고 정밀도 < 80% → 재학습 후보 (표본 < 20이면 '표본 확인' 먼저) | 옛 명세 표본·정밀도 |
| 오탐 신고 | 30일 · 서비스 × 기관 · 'AI가 잘못 봄' ≥ 5건 → 재학습 후보 (다른 이유는 세지 않음) | 옛 명세(보조 신호) |
| 마지막 학습 경과 | > 365일 → 재학습 후보(조용한 지역의 낡은 모델) | 옛 명세 |
| 새 영상 시점 | 적용 지역에 새 영상이 등록됨 → '재분석'(재학습 아님) | 옛 명세 '새 도엽' |
| 신뢰도 흐름 | 최근 분석의 평균 신뢰도가 이전보다 0.05 이상 떨어짐 → 재학습 후보 | 옛 명세 drop 0.05 |
- **다음 할 일은 하나만** 정한다(우선순위): 재학습 > 임계 조정 제안 > 표본 확인 > 재분석 > 갱신 배포 > 없음. 첫 화면(D3)·서비스 관리·관리자 화면이 **같은 계산 한 곳**을 쓴다.

### 4-2. 화면(⑥ 서비스 관리)
- 표: 서비스 · 기관 · 버전 · 정밀도(표본 n) · 신고(30일, 오탐만) · 마지막 학습 · **다음 할 일** — 신호 열에는 기준을 넘긴 것만 작은 표시.
- 서비스 행을 열면 '왜 이 할 일인지' 근거 판(신호 5줄 · 값 · 기준) + 버튼 하나(`재학습 시작` / `임계 조정 제안` / `표본 확인` / `재분석`).
- `재학습 시작` → 학습 화면(②)으로 이동, 표본 = 기존 학습 표본 + 오탐 신고 표본 + 맞음 표본이 이미 담긴 상태. 학습은 작업 대기열(GPU 한 장 규칙). 끝나면 결과 확인 → **새 버전 만들기**(D2) → 적용 지역 갱신 배포(결재) → 기관 알림.
- 재학습 시작 자체는 직원이 한다(GPU 작업이라 대기열이 통제). 새 버전 공개·갱신 배포는 결재.

## 5. 숫자 한 출처 규칙(이 설계로 바뀌는 계산)
- '기관 신고' = 열린 **오탐 신고**만(영상 등록 요청 등 제외).
- '재학습 필요' = §4-1 계산 한 곳. 첫 화면·서비스 관리·관리자 요약이 같은 값.
- 정밀도 = 필지당 마지막 판정 기준, LX 표본 판정과 신고 처리 판정을 합산. 표본 20건 미만이면 '—'(UX-19).

## 6. 구현 계획
1. **서버**: 신고에 이유 4택·사진·상태(접수/확인 중/처리 결과)·처리 판정·원인 필드 · 기관 회신 알림 · 신고 처리 → 표본 큐/임계 제안/대장 확인 요청 자동 분기 · 재학습 신호 계산 한 곳(요약 API) · '기관 신고' 집계를 오탐만으로.
2. **기관 화면**: 판정·필지 카드·XI맵의 신고 입력(4택+메모+사진) · `내 신고` 목록·알림.
3. **LX 화면**: 서비스 관리 신고함·건별 처리·신호 판·다음 할 일 버튼 · 학습 화면이 표본을 받아 열림.
4. **실증**: 기관 계정으로 신고 3건(이유 다르게) → LX 직원이 처리 → 기관 화면 상태 변화 · 재학습 표본 큐에 1건 · 임계 제안 결재 1건. 두 지역.

## 7. 완료 기준
- 기관에서 신고 1건 → 30초 안에 LX 신고함에 보임 → LX 판정 → 기관 `내 신고` 상태 변경 + 알림. 기관 할 일에서 그 필지 제외.
- 신고 이유 '기준이 엄함' 1건 처리 → 관리자 결재함에 임계 조정 제안 1건. '잘못 봄' 1건 → 학습 화면 표본에 포함.
- 첫 화면·서비스 관리·관리자 요약의 '재학습 필요'·'기관 신고'가 같은 값. 학습 뒤 새 버전 → 갱신 배포 → 기관 알림 1줄.
- GPU 두 장 동시 고부하 0(대기열 로그).

## 8. 확인받을 선택지
1. **기관 신고 입력**(이유 4택 + 메모 + 사진, 판정 '대장과 같음'도 자동 접수, `내 신고`로 회신) — 확인 / 보류 / 반려.
2. **재학습 판단 신호 5개 + 다음 할 일 하나 + 재학습 시작은 직원, 새 버전 공개는 결재** — 확인 / 보류 / 반려.
