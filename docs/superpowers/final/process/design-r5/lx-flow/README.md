# 설계 5차(design-r5/lx-flow) — LX 직원 원스톱 흐름 먼저, 화면은 그 칸

> 2026-09-30 · Fable 5.1(기획·UI/UX). 지위: **사용자 확인 전 제안**(코드 수정 0 · GPU 실행 0 · 서버 호출 0). 확인 요청 4차 답 — "영상 올리는 이유가 있을 것, 앞뒤 과정을 원스톱으로" · "미달의 판단 근거가 뭐지, 분석 결과도 직접 보고 승인·반려" · "담당 직원도 매칭되어야" · "AXIS-Label 은 실험, 다시 만든다 가정" · "대장 맞추기는 프로젝트 만들기에서, 필지 번호 기준 출력" — 를 받아, **흐름 한 장을 먼저 그리고 화면 네 가지를 그 흐름의 칸으로** 만들었다(원칙 61–64). 확정된 것(P1 관계 그림 · 프로젝트는 직원이 바로 · 입력 가볍게 · 미달은 표시만 · 발행 전 프로젝트장 / 발행 후 관리자)은 그대로 두었다.
> 방법: 4차와 같이 실제 키트(`landxi/v3/kit/kit.css` · 토큰 · 서체)를 불러 HTML 시안을 만들고 기존 자산 이미지를 지도 바탕으로 깔았다. 숫자·이름·지번은 흐름을 보이기 위한 **예시**이며 서버 값이 아니다(각 문서 '확인 못 한 것').

## 1. 흐름 13단계 — 한 줄씩(`flow.md` · 그림 `shots/flow-lx-13.png`)
| # | 단계 | 누가 | 한 줄 |
|---|---|---|---|
| 1 | 사업 · 목적 | 영업 · 기관 · LX 관리자 → 맡을 직원 | 기관 업무 하나 — 무엇을 · 어디 · 결과를 어떻게 쓸지(필지 기준 표) |
| 2 | 프로젝트 만들기 | LX 직원(= 프로젝트장) · 승인 없음 | 이름 · 무엇을 · 어디 + '무엇과 대조하나'(지목 기본) |
| 3 | 데이터 올리기 | 구성원 | 파일만 + **쓸모 하나**(학습용 영상 / 분석 대상 영상 / 라벨 원천) → 올린 뒤 다음 단계 버튼 |
| 4 | 학습데이터 구축 | 구성원 | 조각 보기 · 그리기 · AI 제안 · 사람이 확인 → 확인한 라벨 |
| 5 | 학습 | 프로젝트장이 시작 · 대기열 | 모델 판 · 학습 정확도(참고) |
| 6 | 결과 확인 ★ | 구성원 판정 · 프로젝트장 확인 완료 | 필지 기준 표 → 표본 뽑기 → **표본 확인 기록(몇 건 · 맞음/틀림 · 정밀도) = 판단 근거** |
| 7 | 서비스 카드 발행 요청 | 프로젝트장 | 이름 · 한 줄 설명만 · 기준 표는 자동 · 미달은 표시만 |
| 8 | 판단 | LX 관리자 | 지도 위 결과 + 표본 기록 + 기준 넷을 **직접 보고** 승인 / 반려(사유 필수 → 프로젝트장에게) |
| 9 | 공개 | 저절로 | 카드 1판 · 담당 프로젝트장 기록 · 관리는 관리자로 |
| 10 | 기관 제공 | LX 관리자 → 기관 관리자 → 부서 | 기관 홈에 카드 · 같은 필지 표 + 기관 판정 열 |
| 11 | 'AI가 잘못 봤어요' | 부서 사용자 | 필지 누르고 메모 한 줄 → **담당 프로젝트장** |
| 12 | 담당 프로젝트장이 받음 | 프로젝트장 · **없으면 LX 관리자** | 맞음 / AI 오류 / 모름 → 기관에 답 · AI 오류는 재학습 표본 |
| 13 | 보완 · 재학습 | 공개 뒤엔 관리자 지시 → 프로젝트장 | 같은 프로젝트의 4 · 5 · 6 다시 → 7 새 판 |

## 2. 관리자 판단 기준(`admin-judge.md` · 시안 `judge-1/2/3`)
| 기준 | 어디서 | 누가 만든 값 | 기준값은 누가 | 기본값(제안) |
|---|---|---|---|---|
| 표본 확인 정밀도 | 6단계 표본 확인 기록 | 구성원 판정 → 서버 계산 | LX 관리자('공개 기준' 한 장 · 서비스 종류별 가능) | 0.85 |
| 확인한 표본 수 | 같은 기록 | 구성원 | LX 관리자 | 20건 |
| 실증 지역 | 같은 기록의 지역 | 자동 | LX 관리자 | 1곳 |
| 겹치는 서비스 | 공개 카드 목록 | 자동 | — (표시만) | — |
결재 한 건 = 지도 위 결과(표본 24건 점 · 틀린 것은 조각) + 표본 확인 기록 + 기준 표(값 · 기준값 · 출처 한 줄) + 승인 / 반려(사유 필수 · 틀린 표본과 함께 프로젝트장에게).

## 3. 학습데이터 구축 도구 1차 범위(`label-tool.md` · 시안 `label-1/2`)
조각 보기 · 사각형/다각형 그리기(지우기 · 실행 취소) · 클래스 자동 채움 + 추가 · AI 제안(기존 모델 결과) · 맞음/아님/고치기(키보드 Y/N · 덜 확신하는 것부터) · 클래스별 진행률 · '학습으로 보내기' · 기록. 2차: 비슷한 조각 찾기 · 자석 그리기 · 교차 확인 · 새 클래스 제안 · 외부 데이터셋 검증. AXIS-Label 은 아이디어만(어두운 화면 · 코드 안 씀).

## 4. 필지 기준 출력 표(`ledger-output.md` · 시안 `ledger-1/2`)
한 줄 = 한 필지: **지번 · 필지 번호 · 지목(공개) · AI 결과 · 대조(같음 / 다름 / 대조 못 함) · 까닭 · 영상 조각 · 확인**(기관 화면은 + 기관 판정). 큰 숫자 = '다름 n필지'(현장 확인 후보). 대조 기준은 프로젝트 만들기 넷째 칸에서 공개 기준만(지목 기본 · 용도지역 · 개발제한구역 경계 · 건축물 정보 · 개발행위허가 · 대조 없음) — 기관 대장은 사업 협의 뒤 커스텀. 필지가 단위가 아닌 대상(해안 · 섬)은 같은 표를 구역 기준으로.

## 5. 알림 받는 사람(F1 다시)
카드 공개 때 담당 프로젝트장이 기록됨 → 기관 알림은 그 프로젝트장 받은함 → 없으면 LX 관리자가 받아 담당 지정. 흐름 그림 11 → 12 화살표에 표시.

## 8. 확인 못 한 것(정직)
- 시안의 숫자(표본 24 · 맞음 20 · 틀림 4 · 정밀도 0.83 · 조각 620 · 라벨 212/96 · 다름 462 등) · 이름(김도윤 · 이하늘) · 지번 · 필지 번호는 **예시**다. AI 탐지 132,310건만 4차 시안이 쓴 기존 화면 값.
- 기준값(0.85 · 20건 · 1곳 · 클래스당 300)은 **제안 기본값** — 사용자 확인 뒤 시작값이 된다.
- 표본 뽑기 방식 · AI 제안의 정확도·속도 · 대조 규칙의 세부(대 위 비닐하우스를 다름/참고)는 실증에서 다듬을 것.
- 옛 라벨링 화면은 코드에서 기능만 읽었고 원판 그림은 보지 않았다. AXIS-Label 은 문서만 읽었다.
- 확인 요청 페이지 생성은 하지 않았다(오케스트레이터 몫 · `LX_CONFIRM_ITEMS=design-r5/lx-flow/confirm-items.json LX_CONFIRM_EXTRA=design-r5/lx-flow/shots`).
- 기관 분기 흐름(`design-r5/gov-flow/`)은 다른 에이전트 몫 — 이 문서는 10·11 단계에서 기관 쪽을 카드 두 장으로만 그렸다.
