## 2. 도구 기능 목록(사용자 말로)
| # | 기능 | 무엇 | 1차 | 비고 |
|---|---|---|---|---|

## 3. 쉬운 흐름(직원이 하는 순서)
1. 프로젝트 → 2단계 '학습데이터 구축' 열기. 클래스는 이미 채워져 있고, 조각은 첫 장이 열려 있다.
2. 사각형으로 몇 개 그린다(단동 5개 정도).
3. 'AI 제안 받기'를 누른다 → 점선 제안이 조각마다 뜬다.
4. 제안을 Y / N 으로 넘기고, 모양이 어긋나면 꼭짓점을 끌어 고친다. 몰아서 할 때는 '확인 대기'에서 덜 확신하는 것부터.
5. 오른쪽 진행률이 목표에 닿으면 '학습으로 보내기'가 열린다 → 누르면 5단계.
6. 학습 뒤 6단계에서 틀린 표본이 나오면 같은 화면으로 돌아와 그 유형을 더 그린다(13단계 재학습도 같은 길).

입력 칸은 없다(원칙 49). 저장 버튼도 없다 — 그릴 때마다 저절로 저장되고 기록에 남는다.

## 6. 1차에 만들 최소 범위(한 줄)
**조각 보기 · 사각형/다각형 그리기 · 클래스 자동 채움 + 추가 · AI 제안(기존 모델 결과) · 맞음/아님/고치기(키보드) · 클래스별 진행률 · 학습으로 보내기 · 기록.** 2차: 비슷한 조각 찾기(모델 없이 제안) · 자석 그리기 · 두 사람 교차 확인 · 새 클래스 제안 · 외부 데이터셋 검증 · 자료 설명서 · 되돌리기 화면.

## 7. 사용자가 고를 것
1. 1차 범위(6절)로 시작할까 — 확인 / 범위 조정 / 보류.
2. AI 제안 방식 — ⓐ 1차는 기존 모델 결과로만(빠르고 GPU 한 장 규칙에 맞음) / ⓑ 처음부터 비슷한 조각 찾기까지(모델이 없는 새 대상도 제안 — 만드는 데 오래 걸림).

## 8. 확인 못 한 것(정직)
- 조각 수(620) · 라벨 수(212 · 96) · 목표(300) · 제안 47건은 **예시**다. 실제 학습용 영상으로 잘라 보지 않았다.
- AI 제안의 정확도 · 속도는 실증 전이다. 제안을 만드는 일은 작업 대기열(GPU 한 장 규칙)로만 돌린다.
- 옛 작업공간의 원판 그림(B5·B7)은 보지 않았다 — 코드에서 기능만 읽었다(사용자 지시: 디자인은 참고하지 않음).
- AXIS-Label 은 문서(README · CLAUDE.md)만 읽었다. 코드 · 모델 · 화면은 쓰지 않는다.
- GPU 실행 · 코드 수정 없음.
