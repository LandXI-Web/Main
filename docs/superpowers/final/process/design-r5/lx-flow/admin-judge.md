## 1. '기준 미달'은 무엇을 근거로 하나 — 기준 넷
| 기준 | 무엇을 재나 | 어떤 자료에서 | 누가 만든 값인가 | 기준값은 누가 정하나 | 기본값(제안) |
|---|---|---|---|---|---|
| **표본 확인 정밀도** | 사람이 확인한 표본 가운데 AI가 맞은 비율 | 6단계 결과 확인의 **표본 확인 기록**(필지 · AI 결과 · 사람 판정 · 누가 · 언제) | 구성원이 표본을 보고 맞음/틀림 판정 → 서버가 계산(맞음 ÷ 확인 수) | **LX 관리자**가 '공개 기준' 가이드에서 · 서비스 종류별로 다르게 둘 수 있음 | 0.85 이상(해양쓰레기처럼 작은 조각은 0.80 — 예시) |
| **확인한 표본 수** | 사람이 직접 본 필지·조각 수 | 같은 기록 | 구성원 판정 건수 | LX 관리자 | 20건 이상(UX-19 와 같은 값 — 20건 미만이면 정밀도는 '—') |
| **실증 지역** | 표본을 확인한 시군구 수 | 같은 기록의 지역 | 자동 | LX 관리자 | 1곳 이상(첫 발행) · 다른 지역 적용은 따로 결재 |
| **겹치는 서비스** | 같은 대상 · 같은 지역에 이미 공개된 카드가 있나 | 공개된 서비스 카드 목록 | 자동 | — (기준값 없음, 표시만) | 있으면 이름을 보여 주고 관리자가 합칠지 따로 낼지 판단 |
| (참고) 학습 정확도 | 학습에 안 쓴 라벨로 잰 값 | 5단계 학습 | 자동 | — (기준값 없음) | 참고 표시만 — 학습 지역 안 값이라 후하다 |
| (참고) 클래스별 라벨 수 | 확인한 라벨 수 | 4단계 학습데이터 구축 | 구성원 확인 → 자동 셈 | LX 관리자(목표) | 클래스당 300(예시) — 4단계의 '학습으로 보내기' 조건이지 발행 기준은 아님 |

- **판단 근거는 사람이 본 표본에서만 나온다.** AI 스스로 매긴 확신도(신뢰도)는 기준에 넣지 않는다(믿을 만한 정도 표시 반려 — 제안 S-5).
- **미달은 막지 않는다.** 결재 화면에 빨간 글자로 표시만 하고, 관리자가 결과를 직접 본 뒤 정한다. 요청 메모("틀린 4건은 모두 차광막입니다")가 함께 오므로 관리자는 미달의 까닭을 안다.
- 기준값을 바꾸면 **누가 · 언제 · 왜**가 남고 다음 요청부터 적용된다. 프로젝트장은 기준값을 바꿀 수 없고 조정 요청만 할 수 있다(R&R 3-2).

## 2. 결재 한 건 — 관리자가 보는 것과 누르는 것(시안 1·2)
| 자리 | 무엇이 보이나 | 왜 |
|---|---|---|
| 머리 | 무엇을(비닐하우스 서비스 발행 요청) · 누가(프로젝트장 · 프로젝트 · 날짜) | 누가 · 무엇을 |
| **지도(왼쪽 위)** | 분석 대상 영상 위에 AI가 찾은 결과(청록) · 표본 24건이 점으로(맞음 검정 · 틀림 빨강) · 틀린 표본을 누르면 영상 조각 + AI 분석 + 사람 확인 + 판정한 사람 | **분석 결과를 직접 본다**(원칙 62). 관리자는 표본이 아닌 필지도 눌러 볼 수 있다(자기 확인 — 정밀도에는 안 들어가고 기록만 남음) |
| **표본 확인 기록(왼쪽 아래)** | 확인 24건 · 맞음 20 · 틀림 4 · 누가 · 언제 · 틀린 것부터 조각과 함께 | 정밀도 0.83 이 어디서 나온 숫자인지 그 자리에서 |
| **판단 서랍(오른쪽)** | 카드 미리 보기 → **공개 기준 표**(기준 · 값 · 기준값 · 어디서 온 값인지 한 줄 · 미달은 빨간 글자) → 요청 메모 → **승인 / 반려** | 기준 표시는 한눈에, 누를 것은 둘뿐(4차 A1 확정 그대로) |
| 반려 | '반려'를 누르면 사유 칸(비우면 보낼 수 없음) + '함께 돌아가는 것: 틀린 표본 4건 · 기준 표' | **사유가 프로젝트장에게 그대로 돌아간다**. 프로젝트장은 7단계 화면에서 사유와 틀린 표본을 보고 4·6단계로 되돌아간다 |
| 승인 | 카드 공개 · 담당 프로젝트장 기록 · 이후 갱신·재학습은 관리자 관리 | 원칙 51 |

승인·반려 어느 쪽이든 관리자가 본 것(지도 · 표본 · 기준)과 결정 · 사유가 결재 기록에 남는다.

## 3. 공개 기준 가이드 — 기준값을 정하는 한 장(시안 3)
- 자리: LX 관리자 → 결재 → **'공개 기준' 탭**(새 메뉴 없음).
- 내용: 기준 넷의 기준값 · 서비스 종류별로 다르게 둔 것(예: 해양쓰레기 0.80) · 값은 어디서 오나 한 줄 · 저장 · 오른쪽에 바꾼 기록(누가 · 언제 · 왜).
- 기준값을 정하는 사람은 **LX 관리자**다. 처음 값은 이 문서의 기본값(제안)으로 넣고, 사용자가 확인하면 그 값으로 시작한다.
- 재학습 신호의 기준값(AI 오류 몇 건 · 정밀도 얼마 하락 · 며칠 지남)도 같은 장에 같은 모양으로 넣을 것을 제안(13단계).

## 4. 결재 목록(대기)의 한 줄
종류(서비스 발행 · 다른 지역 적용 · 재학습 실행 · 기준값 조정) · 무엇을 · 어디 · 누가 · 언제 · **기준 표시**(미달 n · 표시 n · —). 4차 A1 목록 그대로, '기준' 열에 미달 개수만.

## 5. 다른 결재에도 같은 모양
| 결재 | 근거 자료 | 직접 보는 것 |
|---|---|---|
| 다른 지역 적용 | 그 지역 분석 대상 영상 유무 · 카드의 대조 규칙이 그 지역에도 맞나 | 그 지역 첫 결과(전역 분석 표본) |
| 재학습 실행(공개 뒤) | AI 오류 건수 · 정밀도 하락 · 지난 날 · GPU 대기열 | 알린 필지 목록과 조각 |
| 기준값 조정 요청 | 프로젝트장의 까닭 · 지금 값 | 표본 확인 기록 |

## 6. 사용자가 고를 것
1. 기준 넷과 기본값(0.85 · 20건 · 1곳 · 겹침 표시만)으로 시작할까 — 확인 / 값 조정 / 보류.
2. 기준값은 ⓐ 서비스 종류별로 다르게 둘 수 있게(추천 — 해안 조각처럼 사람도 헷갈리는 대상이 있음) / ⓑ 모든 서비스 하나로.

## 7. 확인 못 한 것(정직)
- 시안의 숫자(표본 24 · 맞음 20 · 틀림 4 · 0.83 · AI 탐지 132,310건)는 흐름을 보이기 위한 **예시**다. 132,310 은 4차 시안에 쓴 기존 화면 값이고, 나머지는 실제 표본 확인 기록이 아직 없어 지어낸 예시(서버에 없는 값 — 화면에 그대로 옮기지 않는다).
- 담당자 이름(김도윤 · 이하늘)과 지번(이백면 남계리 312 등)은 예시 표기.
- 관리자가 표본이 아닌 필지를 직접 눌러 보는 '자기 확인'을 기록에 남기되 정밀도에 넣지 않는 것은 제안 — 사용자 확인 필요.
- GPU 실행 · 코드 수정 없음.
