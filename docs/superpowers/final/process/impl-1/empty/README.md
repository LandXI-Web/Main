# 기다림 · 빈 화면 · 문제 표시 — 그림 없애고 세 모양으로 통일

확인 대장: 확인 요청 4차 **S1 ⓐ "그림 3장 모두 없앰(글과 막대만)"** · 원칙 42 "대기 화면의 드론 사진처럼 뜻 없는 그림·장식을 넣지 않는다"
(3차 FR-3 "불러오는 중이라는 이미지가 왜 저 드론이지?? 의미 없는 사진")

## 결과 한눈에

| 모양 | 이렇게 보입니다 |
|---|---|
| 기다리는 중 | 가는 막대 1개 + '불러오는 중' 한 줄. 6초 넘게 응답이 없으면 '서버 응답이 늦습니다' + '다시 시도' |
| 비었을 때 | 회백 카드 + 문장 1 + (있으면) 행동 버튼 1 |
| 문제가 생겼을 때 | 그 자리에 경고색 한 줄 + '다시 시도' |

- 그림이 나오던 곳: 기다림·빈 화면·문제 호출 **53곳**(내가 고친 화면 33 · 다른 갈래 폴더 20) + 서비스 카드의 '대표 영상 없음' 자리 1부품(메인·영업·서비스 상세가 씀).
- **공통 부품 한 곳(`kit/empty.js`)을 고쳐 53곳이 한 번에** 그림이 사라졌고, 화면이 그림을 직접 고르던 곳만 따로 고쳤습니다.
- 그림 파일(위성·드론·항공기 3장, `landxi/v3/kit/img/`)은 **지우지 않았습니다.** 쓰는 곳만 없앴습니다.
- 확인: 로그인 폼으로 들어가 v3 화면 17개를 정상 · 응답 늦춤(3초·8초) · 연결 끊김 상태로 열어 68번 점검 → 기다림·빈 상태·문제 자리의 **그림(img·배경 그림) 0개**, 옛 대표 영상 그림 자리 0개, 화면 오류 0.

## 그림을 쓰던 곳 전수 목록

### 공통 부품(한 곳에서 해결)
| 곳 | 무엇을 했나 |
|---|---|
| `landxi/v3/kit/empty.js` | 종류에 따라 위성·드론·항공기 그림을 자동으로 넣던 것을 없애고 세 모양(기다림·빈 화면·문제)으로 다시 만듦. 문제 모양(`error`) 신설. 6초 넘게 기다리면 '서버 응답이 늦습니다' + '다시 시도'. 옛 `char:` 옵션은 받아도 그리지 않음. 그림 목록 내보내기(`CHARS`) 삭제 |
| `landxi/v3/kit/kit.css` · `landxi/v3/shared/tokens-v2.2.css` | 그림을 앉히던 스타일 삭제 · 세 모양 스타일 신설 |
| `landxi/v3/kit/service-card.js` (+ `index.js`) | 대표 영상이 없는 서비스 카드에 위성 그림이 들어가던 것 → 회백 판(그림 없음) |
| `landxi/v3/kit/i18n/ko.json` · `en.json` | '불러오지 못했습니다' · '다시 시도' · '서버 응답이 늦습니다' 문구 추가 |
| `landxi/v3/kit/gallery.js` · `index.html` · `README.md` | 부품 갤러리·설명을 새 모양으로. '문제' 예시 1개 추가 |

### 화면이 직접 그림을 고르던 곳(내가 고침)
| 화면 | 곳 | 전 → 후 |
|---|---|---|
| 서비스 상세 | `service-detail/app.js` 5곳(세션 확인 실패 · 첫 결과 전 · 지도 실패 · 이 지역에 없음 · 없는 주소) + 관련 서비스 카드 1곳 | 드론·항공기 그림 → 글. 세션 확인 실패와 지도 실패는 '문제' 모양 |
| 서비스 상세 | `service-detail/service-detail.css` 그림 배치 규칙 | 삭제. 첫 결과 전 큰 판(680px) → 회백(흰) 카드 + 문장 1 |
| LX 관리자 배포 | `lx-deploy/app.js` 2곳(깔린 기관 없음) + 점검 기록 실패 1곳 | 항공기 그림 → 글. 점검 기록 실패는 '문제' 모양 + 다시 시도(그 자리에서 다시 불러옴) |
| 영상 등록 | `lx-ingest/app.js` 1곳(영상 등록 필요) + `ingest.css` 그림 배치 2줄 | 드론 그림 → 글 |
| 영업 | `sales/app.js` 1곳(대표 영상이 안 열릴 때) | 위성 그림 → 회백 판 |
| 학습 | `lx-train/app.js` 1곳(모델 목록 실패) + `train.css` 정렬 1줄 | 항공기 그림 → '문제' 모양(제목과 왼쪽 줄 맞춤) |
| 영문 지도 | `global/app.js` 1곳(지도 실패) + `global.css` 1줄 | 그림 → '문제' 모양 |

(그림을 직접 고르지 않고 부품 기본값에 기대던 나머지 호출 — 메인 · 영업 · 학습 서랍 · 영상 등록 · 검토 · 인프라 · 영문 지도 등 — 은 부품 수정으로 자동으로 고쳐졌습니다.)

### 다른 갈래가 고치는 폴더(건드리지 않음 — 공통 부품을 쓰므로 그림은 이미 사라짐)
옛 `char:` 옵션이 코드에 남아 있는 곳입니다. 그림은 그려지지 않아 화면에는 영향이 없고, 그 갈래가 정리할 때 옵션만 지우면 됩니다.

| 폴더 | 곳 |
|---|---|
| `gov-report` | `app.js` 보고서 초안 빈 화면(항공기) |
| `gov-fusion` | `app.js` 이어 붙이는 중(드론) · 내 대장 × AI(위성) · 영상 등록 필요(드론) · `gov-fusion.css` 그림 배치 규칙 |
| `ops-core` | `js/app.js` 결재할 것이 없습니다(위성) |
| `xi-clean` | 그림 옵션 없이 부품 기본값에 기대는 호출(기다림 · 관할 밖 · 첫 결과 전 · 영상 등록 필요) — 부품 수정으로 자동 해결 |
| `login` | 그림 쓰는 곳 없음 |

'문제' 모양(`kind: 'error'`)으로 바꾸면 더 좋은 곳(그 갈래 몫): `xi-clean` 현황 실패 카드(지금은 회백 카드 + 다시 시도 버튼), `gov-fusion` 대장을 다시 여는 중(다시 시도 붙은 기다림).

## 확인 방법(다시 해 볼 수 있게)
1. 서버 켜기: `server/start-landxi.ps1`(이미 켜져 있으면 그대로).
2. 로그인 폼으로 들어가기(세션 주입 없음): `landxi/v3/kit/lint/forbidden.mjs` 의 `frontDoor` 로 LX 관리자 계정(`lx-admin`) · 기관 계정으로 입력. 비밀번호는 `server/.env` 에서 자동으로 읽음.
3. 각 화면을 열고 세 상태를 만들기 — 기다림은 API 응답을 늦추고(playwright `route` 로 9초 지연 · 세션 확인 제외), 문제는 API 연결을 끊고, 빈 상태는 자연 상태로 확인. 서버·GPU 는 건드리지 않음.
4. 화면의 모든 `img` 와 빈 상태·서비스 카드의 배경 그림 중 위성·드론·항공기 그림(`kit/img/…`)이 0개인지 세기.
5. `npm run test:unit` — 108개 통과 · 실패 0 · 건너뜀 1(원래부터).

## 새 모양이 하는 일(부품 시험 결과)
- 기다림 → 6.3초 뒤 '서버 응답이 늦습니다' + '다시 시도' 로 바뀜. 진행 값이 들어오면 원래 '불러오는 중' 으로 되돌아옴.
- 늦기 전에 그 자리가 다른 내용으로 바뀌면 타이머가 남지 않음(뒤늦게 글자를 덮어쓰지 않음).
- '~하는 중' 처럼 제목을 따로 준 오래 걸리는 작업 줄은 늦음 표시를 하지 않음(정상적으로 오래 걸리는 것이므로).
- 문제 모양 '다시 시도' 는 기본이 화면 다시 열기이고, 화면이 그 자리에서 다시 불러오게 바꿀 수도 있음.
