## ECW 를 올리면 어떻게 되나
**기관(분석 의뢰)** — 지금 이 화면은 다른 갈래가 '쉬운 판'(영상 넣기 → 분석 카드 고르기 → 요청하기)으로 바꿨고, 그 위에서 그대로 동작합니다.
1. 파일을 고르는 순간: 파일 머리(처음 몇 바이트)가 정말 그 형식인지 · 서버가 지금 그 형식을 바꿀 수 있는지 봅니다. 안 맞으면 그 줄에 쉬운 말 한 줄, 올리지 않습니다.
2. 다 올리면: 서버가 파일에서 위치 · 해상도 · 촬영일을 읽고(ECW 는 그 형식을 읽는 GDAL 로) 미리 보기를 지도에 얹습니다. 드론 영상의 흰 · 검은 테두리는 미리 보기에서 투명하게 보입니다. "순천시 와룡동·상사면 등 3곳 일대 드론영상 · 1장 — 분석할 수 있습니다 ✓"
3. 바로 표준본으로: 작은 파일(64MB 이하)은 서버가 그 자리에서 몇 초 만에, 큰 파일은 CPU 작업기 대기열에서 바꿉니다. 큰 파일 변환은 한 번에 하나, 디스크 여유를 먼저 봅니다.
4. 의뢰를 승인하면: 분석은 **표준본으로** 합니다(아직 바꾸는 중이면 끝날 때까지 기다림 · 표준본을 못 만들었으면 원본으로 · 원본도 못 읽으면 "영상 파일을 읽을 수 없습니다 — LX 담당자가 확인합니다").

**LX 직원(데이터 올리기 → 영상 등록)** — 서버 경로를 넣고 등록하면 영상 등록 작업(CPU)이 메타를 읽고 표준본을 만든 뒤, 지도 · 분석이 표준본을 읽게 바꿉니다(원본 경로는 따로 남김). 좌표계 기록이 없는 도엽(TFW 만)은 등록한 지역 안에 떨어지는 좌표계 번호를 붙입니다(다시 그리지 않음).

**ECW 를 읽는 GDAL 이 없는 서버라면** — ECW 를 고르는 순간 기관에는 "지금은 이 파일을 받을 수 없습니다 — TIF 로 저장해 올려 주세요", LX 쪽(영상 등록 · 관리자)에는 "**ECW 변환기가 이 서버에 없습니다**" 한 줄. 이 PC 는 QGIS 3.28.3 의 GDAL(ECW SDK 5.5)이 있어 받습니다.

## 원본 지울 날짜
- **언제**: 표준본을 확인한 날 + 90일(예: 10월 1일 확인 → **2026.12.30**). 그 전에는 원본과 표준본이 함께 있습니다.
- **누가**: 정해진 작업 — CPU 작업기가 하루 한 번 지울 날짜가 지난 원본을 지웁니다. 지운 것마다 감사 기록(무엇을 · 크기 · 표준본 · 보관 날 수)을 남깁니다.
- **무엇을**: 플랫폼이 받은 원본만(기관이 올린 영상 · LX 가 올린 영상 칸). 서버 경로로 등록한 LX 보관 영상(다른 드라이브의 원본)은 표준본만 만들고 원본은 지우지 않습니다(관리자 목록에 '원본 보관(지우지 않음)'). 지우기 직전에 한 번 더 봅니다: 그 칸 안의 파일인가 · 표준본이 있나.
- **보기만**: `config/imagery.yaml` 의 `original.delete: false` 로 바꾸면 지울 목록만 남깁니다. 이번 시험은 시험 칸(02. 데이터/tenants/_imagery_std_test)의 사본으로 '보기만 → 지우기'를 확인했고, 실제 자산은 지우지 않았습니다. 오늘 기준 지울 대상은 0건입니다(가장 이른 날이 2026.12.30).
- **어디서 보나**: LX 관리자 → 기관 → '공유 영상' 목록의 영상 줄 · 결재 → 분석 의뢰 → 판단 근거. 기관 화면에는 내지 않았습니다(아래 제안 ①).

- ECW 를 읽는 구성요소는 Hexagon(옛 ERDAS)의 ECW SDK 뿐입니다. 이 PC 는 QGIS 3.28.3 에 함께 든 SDK 5.5 로 읽습니다. 공식 설명상 **데스크톱에서 읽기는 무료, 서버에서 읽기는 유료** 입니다("To compress, deploy on a Server platform … a license must be purchased from Hexagon Geospatial" — GDAL ECW 드라이버 설명).
- 지금 Land-XI 서버가 이 구성요소로 ECW 를 자동 변환하는 것은 **서버 사용** 에 해당할 수 있습니다. 사용자 결정(영상-1)대로 구현은 진행했고, **정식 오픈 전에 Hexagon 서버 읽기 라이선스(서버 CPU 코어 수 기준 견적 · 공공기관 조건)를 확인** 해야 합니다. 그때 정하는 것: ① 라이선스를 사서 지금 길 그대로 ② 사지 않으면 `LX_ECW_GDAL_BIN` 을 비우기만 하면 ECW 는 고르는 순간 "TIF 로 저장해 올려 주세요"로 바뀜(코드 수정 0).
- A100 서버로 옮길 때도 같은 확인이 필요합니다(코어 수가 바뀜).

## 남은 것 · 먼저 드리는 제안(원칙 57)
- **남은 것**: ① 쌓인 LX 보관 영상(5.9TB)의 밤 변환은 사용자 결정 뒤(설계 policy.md 4절 — 이번 범위 아님). 서버 경로로 50GB 가 넘는 영상을 등록하면 지금처럼 원본 옆 축소판만 만들고 '밤 변환 대상'으로 남깁니다. ② 관리자 설정 화면('영상 표준' 칸)은 만들지 않았습니다(새 화면 금지) — 값은 설정 파일 한 곳. ③ 표준본으로 한 AI 분석이 원본과 얼마나 같은지(GPU 차례에 도엽 10장 비교)는 아직.
- **제안 ① 기관에 한 줄 알리기** — 누가: 기관 담당자. 왜: 올린 원본이 90일 뒤 지워지는 것을 모르면 다시 올려 달라는 요청에 당황할 수 있음. 분석 의뢰 '영상 넣기' 아래 작은 글 "올린 원본은 90일 뒤 지워집니다 · 지도와 분석은 서버가 정리한 영상으로 합니다"(설계 policy.md 3절 문구).
- **제안 ② 관리자 현황에 '이번 달 줄인 용량'** — 누가: LX 관리자(하드웨어 담당). 왜: 표준화 효과를 숫자 한 출처(변환 기록)로 보고 저장 공간 계획에 씀. 인프라 '저장 공간' 칸 아래 한 줄(변환 기다림 n건 · 줄인 용량 · 지울 원본 n개).
- **제안 ③ 화질 기준 0.97 의 끝자리** — 누가: 사용자(결정). 왜: 남원 숲 도엽 159장 중 2장이 SSIM 0.969 로 0.97 에 0.001 모자라 원본(330MB)을 그대로 둡니다. ⓐ 지금대로(원본 보관 · 저장 조금 더) ⓑ 기준을 0.96 으로(설계 표본 최저 0.980 · 이번 최저 0.969) ⓒ 미달 영상만 JPEG 95 로 한 번 더 — 고르시면 설정 한 곳에서 바꿉니다.
- **제안 ④ ECW 횟수 세기** — 누가: 사용자(라이선스 결정). 왜: 설계 추천대로 석 달 동안 ECW 가 얼마나 들어오는지 세면 서버 라이선스를 살지 판단할 근거가 됨. 변환 기록에 형식이 남아 있어 세기만 하면 됨.
