## 정직
- '데이터' 메뉴는 지금 '데이터 올리기' 화면(지역별 영상 · 행정 자산 · 올리기)으로 간다. 1안 설명의 '영상 · 학습데이터 보관소(내 것 · 공유된 것)' 한 장은 아직 없다 — 아래 제안 1.
- '분석하기' · '서비스 카드' 메뉴는 그 화면을 만드는 다른 갈래(lx-analyze · lx-cards)로 잇기만 했다. 대시보드 '바로 분석하기'는 고른 지역을 `?region=시군구코드` 로 넘긴다.
- 대시보드 '우리 서비스' 장면 · 상태 · 어디는 서비스 카드 한 벌의 서버 덱이 있으면 그것을 쓰고(지금 있음), 없으면 서비스 소개의 실제 결과 장면 · 서버 크롭으로 그린다(지어낸 그림 0).
- '내 프로젝트'의 다음 할 일 글은 서버 판정 그대로다(지금 네 프로젝트 모두 '시범 n곳'). 시안의 '결과 확인 대기 60필지' 같은 숫자는 서버가 그 단계에서 주는 말이 바뀌어야 나온다 — 제안 2.
- 옛 대시보드의 '서비스 만들기' 표(업무 × 모델 · 규칙 · 영상)는 1안에 없어 대시보드에서 뺐다(코드는 남김). 서비스 카드 발행 요청은 프로젝트 안 '발행 요청' 단계(학습 화면 원스톱)로 한다.
- LX 관리자 계정으로 app 주소에 들어오면 LX 직원 메뉴를 쓰지만, 요청함 화면만은 관리자 메뉴(검토 요청)로 보인다 — 입구별 메뉴 정리는 제안 3.
- 기존 서버 시험 `test_r3_train.py::test_screen_name_rules_one_source` 1건은 이번 변경 전부터 실패(LX 관리자 결재함 종류에 '분석 의뢰'가 더해진 뒤 시험이 안 바뀜 · 이 갈래 파일 아님).

## 이런 것도 필요하지 않을까요?(원칙 57 — 채택은 사용자)
1. **데이터 보관소 한 장** — LX 직원이 "내가 올린 영상 · 학습데이터가 어디 있고 어느 프로젝트가 쓰나 · 다른 프로젝트 것을 불러올 수 있나"를 한 곳에서. 지금 '데이터'는 지역별 올리기 화면이라 프로젝트 단위로 보이지 않는다(원칙 66 · 74).
2. **다음 할 일에 업무 숫자** — 프로젝트장이 줄만 보고 무엇이 남았는지 알게(예: 결과 확인 대기 60필지 · 표본 확인 18/20). 서버 판정의 다음 할 일 글에 그 단계 숫자를 함께 싣는 일.
3. **입구별 메뉴** — LX 관리자가 app 주소로 오면 LX 직원 메뉴, admin 주소면 관리자 메뉴로 모든 화면을 맞추기(지금은 요청함 화면만 계정 기준).
4. **요청함 '알림' 칸** — 분석 끝남 · 결재 결과 · 기관 메모를 요청함 안에 한 줄씩(1안 정의의 '알림'). 지금은 끝난 분석을 대시보드 '최근 활동'에서만 본다.
