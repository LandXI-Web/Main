## 1 · 학습단위-저절로: 고친 자리 한 칸 → 학습 데이터 1장

| 단계 | 서버가 하는 일 |
|---|---|
| 칸 | XI맵 그 자리 고치기로 고친 객체의 가운데가 든 **격자 한 칸**. 격자는 그 자리의 UTM 좌표(어느 나라든 미터 · 지역 고정 없음), 한 변 = 512화소 × 모델이 배운 해상도(경작지 모델 25cm → 128m) |
| 기다림 | 그 칸을 마지막으로 고친 뒤 **30분 조용하면**(설계 25차 값 · 관리자 설정 `tile_quiet_min`) 1장이 된다. 5분마다 도는 재학습 스케줄러가 칸을 맞춘다 |
| 영상 | 그 결과를 만든 **영상 원천에서 그 칸만 다시 잘라** 쓴다(지리원 API 타일 · 기관 영상 같은 imagery 한 곳으로). 영상 파일은 쌓지 않고 학습 데이터 조각(512화소 그림 + 테두리 줄)만 `02. 데이터/training/xi-tiles/{서비스}/` 에 둔다 |
| 테두리 | 그 칸에 드는 **지금 결과 객체 전부**(지운 것 빼고 · 고친 모양 · 새로 그린 것 포함)를 칸 경계로 잘라 학습 테두리로. 분류 순서는 모델 머리 순서 |
| 빼기 | **같은 객체를 두 사람이 다르게 고친 칸은 뺀다**(사람마다 마지막으로 고친 결과를 비교). 칸 안 고친 것을 모두 되돌리면 그 칸도 뺀다. 같은 칸을 또 고치면 기다림으로 돌아가 다시 만든다(1장 그대로) |

| 켜기 | 대기열 넣기를 켰다(설정 `core.retrain.submit = true` · 환경 `LX_RETRAIN_SUBMIT=1` 도 됨). 지금 1장이 된 칸은 0장이라 실제로 들어가는 학습은 없다 |

1. LX 직원이 실제 작업 결과(경작지 모델)에서 가까운 경작지 객체 셋을 **시험으로** 고침(분류 바꾸기 둘 · 지우기 하나). 영상은 그 결과의 영상 원천에서 다시 잘림.

3. LX 관리자가 같은 객체를 다르게 고침 → 그 칸은 **'둘이 다르게 고침'으로 빠짐**(1장 → 1장 줄어듦). 관리자 것을 되돌리면 다시 1장.
4. 스케줄러: 기준 200장에 2장 → **기준 미달 · 대기열에 안 넣음**. 기준을 1장으로 낮춘 시험 환경 → **대기열에 들어감**(학습 작업 queued 확인) → 바로 취소(학습 0 · 워커는 취소된 작업을 건너뜀).
5. 시험 고친 기록(되돌린 뒤 지움) · 칸 · 조각 파일 · 재학습 기록 · 시험 작업 줄 모두 정리 — 남은 것 0.

## 남은 것
1. **학습 끝 · 같은 검증 묶음 비교** — 무인 실행기(`02. 데이터/training/farm-v2/run_farm_v2.py`)가 학습이 끝나면 새 모델을 같은 두 묶음으로 재고 `progress.json` 에 남긴다. 등록 · 배포 신청은 하지 않는다(사람 몫). 끝나면 이 README 의 비교 표를 채워야 한다.
2. 학습 화면의 '같은 검증 묶음' 칸은 새 묶음(farm-api-v1)으로 잰 지금 모델 값이 있어 학습이 끝나면 함께 보인다.
3. 1장이 된 XI맵 칸은 아직 0장 — 실제 직원 고치기가 쌓여야 저절로 학습이 돈다.
4. 사용자 NAS 자료(9_crop_항공_농경지 · 남원 경작/비경작)가 오면 자리 폴더에 두고 v3 학습.

## 제안 — 이런 것도 필요하지 않을까요?
1. **사용자 AI 분석이 오면 학습도 잠깐 비키기** — 누가 · 왜: 기관 사용자 · LX 직원. 지금은 10시간 학습 중에 들어온 분석이 학습 끝까지 기다린다. 반복 사이(또는 몇백 배치마다)에 대기열을 보고 사용자 분석 칸이 있으면 학습을 멈추고 분석을 먼저 돌린 뒤 이어 가면(전국 작업기와 같은 비킴), 체감 속도를 지키면서 학습도 계속된다.
2. **'남원 API 검증 묶음' 만들기** — 누가 · 왜: LX 직원 · 관리자. 지금 같은 검증 묶음은 경기 2021 칸뿐이다. 사용자 남원 경작/비경작 라벨이 오면 같은 방식(자리 → 같은 해 API 층 다시 자르기)으로 서비스 지역 검증 묶음을 만들어, 실제 쓰는 곳에서 나아졌는지 본다.
