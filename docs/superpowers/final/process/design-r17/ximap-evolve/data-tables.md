## 1. 새로 만드는 표

### 1-1. 고치기 기록 `result_edits` — 지우지 않고 쌓는다
| 열 | 뜻 |
|---|---|
| id | ed_… |
| tenant_id | 결과의 주인(행 단위 보안 — 지금 detections 와 같은 규칙) |
| job_id · det_id · fid | 어느 결과의 어느 도형(놓친 것 그리기면 새로 만든 도형) |
| action | delete(지우기) · reshape(모양 고치기) · reclass(분류 바꾸기) · add(놓친 것 그리기) · undo(되돌리기) |
| cls_before · cls_after | 분류 전 · 후('해당 없음' = 이 서비스 대상 아님) |
| geom_before · geom_after | 고치기 전 · 후 모양 — **원래 모양을 잃지 않는다**(지금 PATCH 는 덮어써서 원래 모양이 사라짐) |
| conf_before | 고치기 전 신뢰도(신뢰도 낮은 것부터 보기 · 다시 보기 표본에 씀) |
| model_id · card_id · card_version | 어느 모델 · 어느 서비스 몇 판의 결과였나 |
| imagery_id · imagery_src | 어느 영상(원천 · 연도 · 해상도 — 등록 영상 · 국토지리정보원 연도별 · 브이월드 최신 · 올린 영상 · Sentinel-2) |
| cell_id | 이 고치기가 속한 칸(1-2) |
| source | ximap(XI맵) · result_check(프로젝트 결과 확인) · gov_report(기관 신고 → 'AI 오류' 판정) |
| report_id | 기관 신고에서 왔으면 그 신고 |
| by · at | 고친 사람 · 때 |
| undone_by · undone_at · test | 되돌림 · 시험 표시 |

detections 는 그대로 두고 '지금 보이는 모양'만 바꾼다(edit_state 에 added 를 더함). 결과 화면 · API 내보내기 · 집계는 지금처럼 deleted 를 뺀 값.

| id | lc_… |

| imagery_src | 원천 · 연도 · 해상도 · 이용 조건 |

| labels | 다 봤음 순간의 칸 안 도형 전부 [{분류, 칸 좌표 다각형, 출처: 모델 그대로 · 고침}] |
| classes_complete | 빠짐없이 확인된 분류(다 봤음 = 그 서비스 분류 전부) — 조합 ⓑ '빠진 분류는 무시'와 같은 표시 |

### 1-3. 학습 데이터 자산 `train_assets` — 질문 11 ⓐ와 같은 표, 종류 하나를 더함
질문 11 ⓐ(서버 · 가진 자료 전부 등록부터)로 만드는 자산 표에 **kind = edits('고친 것' 층)** 를 더한다. 한 건 = 서비스 × 분류 × 영상 종류 · 해상도(예: '비닐하우스 · 항공 25cm · 고친 것'). 수량 · 출처(시군구 수) · 이용 조건 · 쓰인 모델 · 판이 칸 표에서 저절로 센다. 관리자가 관리(원칙 133) — 빼기 · 표준으로 흡수(자산-3 ⓐ 수시) · 내려받기 승인.

### 1-4. 학습 묶음 판 `train_sets`
| 열 | 뜻 |
|---|---|
| id · card_id · project_id · round | 어느 서비스 · 프로젝트 · 회차 |
| version | 묶음 판(1, 2, …) — 만든 뒤 잠김 |
| parts | [{자산 · 자산 판 · 몇 장 · 규칙(전부 · 무작위 k장 씨앗)}] — 고친 칸(train 쪽 전부) + **되풀이 자료**(같은 분류 표준 층에서 무작위 — 새 지역에 맞추다 원래 잘하던 것을 잊지 않게) |
| cells_cutoff | 이때까지 ready 가 된 칸만 |
| manifest_sha · n_images | 그림 목록 지문 · 장 수 |
| per_editor_max | 한 사람 몫 최대 비율(설정값 — 1-7) |

### 1-5. 검증 묶음 `eval_sets` — 고정
| id | 종류 | 무엇 |
|---|---|---|
| aerial25-v1 | 기준(fixed) | 이미 있는 AI 허브 시험 칸 3,000장 · 4분류 · 잠금. DB 에 등록만(그림 목록 지문 · 설정 = 입력 1280) |
| holdout-{서비스}-v{n} | 고친 곳(holdout) | 고친 칸 중 검증 쪽(20%). 판이 오를 때 더하기만(빼지 않음) · 같은 판 비교는 같은 v |

설정(입력 크기 · 신뢰도 기준)은 묶음에 묶어 둔다 — 설정이 다르면 비교하지 않는다(실제로 같은 모델이 62% · 68%로 갈림).

### 1-6. 비교 기록 `model_evals`
model_id · eval_set_id · settings_sha · 분류마다 값 · acc(서비스 분류 마스크 기준 — 분석하기 카드 · 배포 신청서와 같은 출처) · job_id · at. 지금 models/eval/*.json 10건을 옮겨 시작한다.

## 4. 서버 기능 — 재사용 / 고침 / 새로
| 기능 | 지금 있는 것(재사용) | 고침 · 새로 |
|---|---|---|
| 결과 고치기 | PATCH /results/{작업}/features/{도형} — LX 직원 · 관리자 · 감사 기록 | **고침**: 기록 먼저(원래 모양 보존) · 칸 연결. **새로**: POST 놓친 것 그리기 · POST 되돌리기 · POST 칸 '다 봤음' |
| 결과 조회 범위 거르기 | GET /results/{세트}/features | **고장(이번에 발견)**: bbox 를 주면 500. 고치기 화면이 칸 안 도형을 받으려면 먼저 고쳐야 함 — 기록만(XI맵 고장 오퍼스 몫) |
| 칸 그림 | 칸 나누기(tiling) · 등록 영상 열기(imagery_src) · CPU 작업기 | **새로**: CPU 작업 '칸 그림' — 다 봤음 순간 그 칸을 잘라 작은 그림(JPEG)으로. 영상 API 칸은 16차 ① 영상 원천이 생긴 뒤 같은 길 |
| 기관 신고 → 고칠 거리 | 검토 요청(POST /reviews · LX 판정 맞음 · AI 오류 · 모름) · feedback | **새로**: 'AI 오류' 판정만 XI맵 고칠 거리 핀으로 · 고친 뒤 기관에 '고쳤습니다 — 다음 판에 반영' 한 줄. 옛 신고 109건은 판정 칸을 채우는 한 번 정리(AI 결과 6건만 고칠 거리) |
| 학습 데이터 자산 | (질문 11 ⓐ 로 만드는 자산 표) | **더함**: '고친 것' 층 종류 · 칸 표에서 수량 저절로 |
| 다시 학습 | 작업 대기열 kind train · 학습 어댑터 · 전력 임대 · 배치마다 다른 GPU 고부하면 멈춤 · 프로젝트 재학습 회차(POST /projects/{프로젝트}/rounds) | **고침**: 학습 어댑터가 표본 한 개만 받음 → 학습 묶음 판(여러 자산 합침 · 되풀이) · 메모리 한도(건축물 10-08 멈춤) → 배치 저절로 줄이기. **새로**: 밤 시간 창(작업 '시작 가능 시각') |
| 비교 | 학습 어댑터 '검증만' 모드(같은 묶음으로 모델 하나 재기) · 명령줄 실행기의 판정 | **새로**: 비교 기록 표 · 서버가 판정(기준 묶음 떨어지지 않음 + 고친 곳 나아짐) · 결과 한 줄 |
| 배포 신청 | release 신청서(서버 값 · 낮은 정확도 경고 — 질문 9 ⓑ) · 판 기록 | **더함**: 비교 값을 신청서에 붙임 · 나아진 판이면 신청서를 미리 채워 둠(누르기는 사람) |
| 승인 · 새 판 · 알림 | 승인(모델 등록 · 서비스 공개) · 공유 기관 새 판 알림(나중 19) | 재사용 |
| XI맵 장부 다시 분석 | 작업 우선순위 · 배포 흐름의 분석 시작 | **새로**: 새 판이 공개되면 그 서비스 결과가 있는 시군구를 밤에 낮은 순위로 다시 분석 · 지난 판 결과는 이력으로 |
| 감사 | audit_log | 재사용(모든 고치기 · 판정 · 시작 · 신청 · 승인) |
