**막는 자리는 하나 — 5 비교.** 자동으로 하는 것은 '신청서 채우기'까지다. 신청 · 승인은 늘 사람이 누른다. 실제 사례: 10-08 비닐하우스 다시 학습(33,485장 · 20회 · 약 25시간)이 같은 검증 묶음 3,000장에서 원판 91% → 87%로 떨어져 후보로 남았다(명령줄 실행기가 막음 — 이것을 서버 기능으로 옮긴다).

### 2-1. 비교 — 무엇을 '나아졌다'고 하나(결정 5)
- **기준 묶음**: AI 허브 토지피복 시험 칸 3,000장(10-07 잠금 · 학습 · 표본과 겹침 0). 지금 판 이상이어야(떨어지지 않음).
- **고친 곳 묶음**: 고친 칸의 20%를 처음부터 학습에서 떼어 둔 것(칸 자리로 정해 늘 같은 쪽). 여기서 나아져야.
- 설정 고정: 같은 모델 · 같은 묶음이라도 입력 크기 1280 → 62%, 640 → 68%(10-07 실제 기록). 묶음마다 설정을 묶어 두고 다르면 비교하지 않는다.
- 화면 숫자: '91% → 92%'(기준 묶음) 한 줄 + '고친 곳 n% → m%' 한 줄. '재학습 필요' 같은 꼬리표 없음(원칙 172).

### 2-2. XI맵 고치기 · 기관 '틀렸어요' · 결과 확인 — 한 줄로 잇기
| 들어오는 길 | 지금 | 이 틀에서 |
|---|---|---|
| **XI맵 고치기** | 없음 | 2단계 그대로(source XI맵) |
| **기관 '틀렸어요'(검토 요청)** | 기관 → 담당 LX 직원 대화 · LX 판정(맞음 · AI 오류 · 모름) — 대화 0건. 옛 신고 109건은 점만 쌓임 | LX 판정이 **'AI 오류'일 때만** XI맵 '고칠 거리' 핀이 됨 → 직원이 고치면 기록에 그 신고가 이어지고 기관에 '고쳤습니다 — 다음 판에 반영' 한 줄이 저절로 감. '맞음'(AI는 맞고 대장상 적법 등)은 학습 자료가 아님 |
| **프로젝트 결과 확인**(원칙 164 재정리 대기 · 질문 7 · 8) | 표본 20 · 100건 맞음/틀림 판정 · 고칠 수 없음 | 제안(결정 4 ⓐ): 결과 확인 = **같은 고치기 화면을 프로젝트 결과에 쓰는 곳.** 표본 수 세기는 없애고, 정확도는 5단계 비교 숫자 하나 |

**실데이터가 보여 주는 것(시안 e3):** 남원시 신고 109건 중 AI 결과 자체에 대한 신고는 6건이고 103건은 업무 판정(건축물대장 확인 — 적법 43 · 농업용 창고 현장 사진 43 · 대장과 같음 13 · 결과 확인 판정 4)이다. 이 103건은 AI가 건물을 맞게 찾은 경우가 대부분이라, '틀렸다'로 학습하면 모델이 나빠진다 → 판정 단계 없이 신고를 학습에 넣지 않는다.

### 2-3. 프로젝트 · 서비스와의 관계
- 고친 칸은 **서비스(카드)** 에 붙는다. 서비스의 담당 = 그 서비스를 만든 프로젝트의 프로젝트장(지금 규칙). 다시 학습은 그 프로젝트의 다음 회차(지금 있는 재학습 회차 — 사유 칸에 'XI맵에서 고친 칸 n · 시군구 m곳'이 저절로).
- 한 결과에 여러 서비스가 섞인 경우(예: 구례 2023 원판 결과 = 건물 · 주차장 · 경작지 · 비닐하우스 4분류 한 모델): 고친 분류가 속한 서비스로 간다. 같은 모델을 쓰는 서비스들은 고친 것 층을 함께 보고, 다시 학습은 그 모델을 쓰는 서비스 하나(대표)에서 한 번 — 나머지 서비스는 같은 새 판을 함께 신청.
- 원칙 158(배포 안 한 내 모델): 후보로 남은 판도 그 프로젝트의 '추론' 탭에서는 쓸 수 있다(지금 길 그대로).

## 4. 위험과 막기
| 위험 | 어떻게 막나 |
|---|---|
| **잘못 고친 라벨** | 칸 '다 봤음'(칸 단위로 확인) · 고치기 전 모양 보존 · 되돌리기 · 프로젝트장의 무작위 다시 보기(제안 10%) · 같은 칸을 두 사람이 다르게 고치면 '다툼' — 학습 제외 · 정리 뒤 사용 |

| **검증 묶음 오염** | 기준 묶음은 잠금(그림 목록 지문) · 학습 묶음을 만들 때 기준 묶음 그림과 같은 이름 · 같은 자리를 저절로 뺌 · 고친 곳 검증 쪽은 칸 자리로 한 번 정하면 영원히 검증 쪽 · 판이 오를 때 더하기만 |
| **성능 떨어진 판 승격** | 자동은 '신청서 채우기'까지 · 나빠진 판은 신청서를 채우지 않음(후보로 남음) · 그래도 사람이 신청하면 질문 9 ⓑ 경고가 신청서 · 승인 화면에 그대로 · 승인은 관리자 |
| **업무 판정이 학습에 섞임** | 기관 신고는 'AI 오류' 판정만 고칠 거리(실데이터: 109건 중 6건) |
| **잊어버림**(새 지역에 맞추다 원래 잘하던 것을 잃음) | 되풀이 자료 섞기(제안 5,000장) · 기준 묶음에서 떨어지면 막힘 |

## 먼저 드리는 제안(원칙 57)
1. **먼저 볼 곳 줄 세우기** — 누가 왜: LX 직원. 결과 130만 개를 다 볼 수 없다. 신뢰도가 낮은 결과 · 두 해 결과가 크게 다른 곳 · 기관 신고가 몰린 곳을 '먼저 볼 칸'으로 고치기 도구 맨 위에. 같은 시간에 고친 칸이 학습에 더 쓸모 있다.
