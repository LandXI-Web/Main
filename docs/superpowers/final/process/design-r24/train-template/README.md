## 서식이 무엇인가 — 한 줄
**서식 = 프로젝트의 학습 화면을 처음 열면 이미 놓여 있는 기본 흐름**(학습 데이터 → 기반 모델 → 학습 설정 → 학습 → 평가 → 배포 신청). 빈 판에서 시작하지 않게 하는 출발점이고, 직원은 그 위에서 고친 뒤 '밤에 돌리기'를 누른다.

## 직원이 바꿀 수 있는 것 · 없는 것(그림 ②)
| 블록 | 바꿀 수 있는 것(블록을 누르면 서랍에서) | 바꿀 수 없는 것(관리자 영역 · 서버) |
|---|---|---|
| 학습 데이터 | 어느 묶음을 쓸지 · 묶음 더 보태기 · 분류 고르기 | 검증 묶음은 학습에 못 넣음 |
| 기반 모델 | 원판 · 지난 판 중 고르기 | 새 모델 등록 |
| 학습 설정 | 반복 횟수 · 이미지 크기 · 한 번에 몇 장 | 상한(반복 · 크기 · 장수) · GPU 메모리 한도 |
| 학습 | 이름 · 지금 또는 밤에 | GPU 배정(프로젝트 하나에 한 장) · 밤 시간대 · 전력 규칙 |
| 평가 | 없음 — 재는 법은 늘 같음 | 검증 묶음 · 비교 기준 |
| 배포 신청 | 사유 적고 신청 | 승인(LX 관리자) |
**그리고 흐름 자체** — 블록 넣고 빼기 · 순서 잇기 · 같은 블록 여러 개(설정 A · B 나란히 · 데이터 묶음 둘 합치기). 이것을 직원이 해도 되는지가 이번 결정.

## 결정 — 다시 쓴 선택지 둘
| | ⓐ 관리자가 흐름을 정해 두고 직원은 값만 바꿈 | ⓑ 기본 흐름은 놓여 있고 직원이 블록까지 바꿈 |
|---|---|---|
| 처음 연 모양 | 같음(블록 여섯 놓여 있음) | 같음 |
| 직원이 하는 일 | 서랍에서 값만(묶음 · 모델 · 반복 · 크기 · 장수 · 사유) | 값 + 블록 더 놓기 · 빼기 · 잇기 |
| 좋은 점 | 누가 열어도 같은 모양 · 실수 적음 · 관리자가 업무별 서식 한두 개만 관리 | 설정 둘 · 묶음 둘을 한 판에서(10-11 에 말씀한 자유도) · 잘못 잇기는 규칙 넷이 그 자리에서 막음 |
| 못 하는 것 · 조심할 것 | 설정 둘 나란히 · 묶음 둘 합치기는 관리자에게 서식을 늘려 달라고 해야 함 | 판이 복잡해질 수 있음 → '기본 흐름으로 되돌리기' 단추 |
| GPU · 상한 · 승인 | 관리자 | 관리자 |
**추천 ⓑ.** 처음 연 모양은 둘이 같고, 10-11 에 말씀한 '블록 여러 개 · 학습 데이터 더 붙이기 · 다른 설정'(원칙 200)은 ⓑ에서만 된다. 지난 ⓐ(관리자 서식 + 직원 자유 편집)는 이번 ⓑ와 같은 뜻이고, 지난 ⓑ(서식 없이 빈 판)는 뺐다.

## 제안 — 이런 것도 필요하지 않을까요?
1. **'기본 흐름으로 되돌리기' 단추** — LX 직원. ⓑ를 고르면 블록을 흐트러뜨린 뒤 한 번에 처음 모양으로.
