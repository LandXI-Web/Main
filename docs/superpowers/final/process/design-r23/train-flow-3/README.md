## 필요한 서버 기능(2차 ⑨~⑭ 그대로 · 더한 것 없음)
회차 지표 실시간 흘려보내기(어댑터 `train.epoch` 이벤트는 이미 있음) · 끝난 학습의 회차 목록 조회(`/registry/models?with=train` 이 이미 `train_log` 를 줌 — 그래프 재료는 있음) · 흐름 안 블록 여러 개(묶음 합치기 · 학습 블록마다 작업 한 건) · 평가 블록 · 추론 시험 · GPU 배정은 관리자 설정만. 3차에서 **줄어든 것**: 지난 판 겹쳐 그리기(⑩의 '겹치기')는 필요 없음 — 이력은 목록 한 번 조회로 끝.

## 결정 1 · 서식(기본 흐름)은 누가 관리하나 — 다시 묻기
| | ⓐ LX 관리자가 기본 흐름 서식 관리 + 직원은 프로젝트에서 자유 편집 | ⓑ 서식 없이 자유 |
|---|---|---|
| 처음 연 화면 | 기본 흐름(학습 데이터 → 기반 모델 · 학습 설정 → 학습 → 평가 → 배포 신청)이 놓여 있고 학습 데이터만 고르면 됨 | 빈 판 → 블록을 직접 놓고 이어야 함 |
| 자유도 | 같음(서식은 출발점일 뿐 잠그지 않음) | 같음 |
| GPU · 전력 규칙 | 관리자가 서식에 상한(반복 · 크기 · 한 번에)을 둠 → '관리자 영역'과 맞음 | 상한이 코드 기본값에 숨음 |
| 부담 | 관리자가 업무별 서식 한두 개 관리 | 없음 |
**추천 ⓐ.** 쉬움은 놓여 있는 기본 흐름에서, 자유도는 그 위 편집에서. ⓑ는 결국 코드 안 기본값이 관리자가 손댈 수 없는 숨은 서식이 된다.

## 제안 — 이런 것도 필요하지 않을까요?
1. **이력 줄을 누르면 그 판의 반복마다 그래프로 바꿔 보기** — LX 직원. 비교가 아니라 '그때 어땠나'를 같은 자리에서 보는 길(겹치지 않고 바꿔 그림).
2. **학습 설정에 '지난 설정 불러오기'** — LX 직원. 한 값만 바꿔 다시 돌리는 일이 가장 흔함(2차 제안 유지).
3. **관리자 대시보드에 'GPU 배정' 칸** — LX 관리자. 프로젝트별 한 장 · 밤 시간 창 · 오늘 밤 대기열(2차 제안 유지).
