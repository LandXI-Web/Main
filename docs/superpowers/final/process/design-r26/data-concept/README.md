## 진단 핵심 3줄
1. **같은 영상 목록을 세 이름으로 부른다** — 데이터하우스 '영상' · 추론 · 분석하기의 '공유 데이터셋 / 공유 영상' · 새 프로젝트 창 '데이터하우스에서 고르기'. 프로젝트 안 '데이터 올리기' 화면과 데이터하우스 '영상 · 행정 자료' 탭은 같은 화면이다(프로젝트 안 · 밖 두 이름). 이것이 "프로젝트 내 공유 데이터와 데이터하우스가 겹친다"의 실체.
2. **학습 데이터는 두 화면에 다른 축으로 보이지만, 데이터하우스에서 가져다 쓰는 길이 없다** — 학습 화면 블록(묶음별) · 데이터하우스 탭(클래스별). 원칙 133 '프로젝트 안 공유 데이터 불러오기'는 영상에만 있다. 데이터하우스 머리 문구가 "XI맵에서 고친 것 0건 · 승인 대기 0개"만 말해 고친 것만 있는 것처럼 읽힌다(올린 장 수는 표 안) — "왜 고친 것만?"은 **문구와 셈 단위(건 ↔ 장)의 문제**.
3. **고친 것 = 라벨과 같은 것인데 이름 · 단위 · 자리가 다르다.** 그리고 결과 확인 화면에는 고치기가 없다(코드 lx-review 에 고치기 0) — 고친 것이 학습으로 돌아오는 길은 XI맵 하나뿐.

## 원천 기능 한 줄
**영상 위에 라벨을 붙이거나 고친다 → 학습 데이터가 된다 → 재학습 → 새 판 → 결과를 보고 다시 고친다.**
꼭 필요한 화면은 셋: ① 라벨 붙이기 · 고치기(프로젝트 학습데이터 구축 = XI맵 고치기와 같은 동작 · 새 클래스는 이름을 새로 쓰면 그뿐) ② 학습(이 프로젝트 학습 데이터 한 묶음으로 · 쉬는 시간 자동) ③ 새 판 배포 신청 · 승인(관리자는 여기서 한 번 · 새 클래스도 이때). 데이터하우스 탭 셋 · 승인 대기 목록 · '비슷한 클래스 먼저' · '공유 데이터셋' 이름은 고리 밖의 덧붙임.

## 방향 둘(복잡도 줄이는 쪽 · 덧붙임은 빼는 전제)
| | **ⓐ 데이터하우스를 없앤다** — 프로젝트 안 학습 데이터 + 관리자 공유 데이터 둘로 | **ⓑ 데이터하우스 하나로 합친다** — 프로젝트는 거기서 고르기만 |
|---|---|---|
| 뜻 | 학습 데이터는 프로젝트 안에만. XI맵에서 고친 것은 그 서비스를 만든 프로젝트의 학습 데이터로. 영상 · 행정 자료는 관리자가 관리하는 '공유 데이터' 한 이름 | 영상 · 행정 자료 · 학습 데이터 · 고친 것이 모두 데이터하우스 한 곳. 프로젝트의 데이터 올리기 · 학습데이터 구축 단계 = '데이터하우스에서 고르기' |
| 사라지는 화면 · 단추 | 직원 메뉴 '데이터하우스' · 탭 셋 · 승인 대기 목록 · '고친 것' 탭 · '비슷한 클래스 먼저' · '공유 데이터셋' 이름 | '공유 데이터셋' · '프로젝트 영상' 구분 · 학습 데이터 블록 세 선택지(→ 하나) · 데이터 올리기 서랍 · '비슷한 클래스 먼저' |
| 바뀌는 것 | 새 프로젝트 창 · 추론 · 분석하기의 영상 고르기 → '공유 데이터에서 고르기' 하나 | 라벨 붙이기 · 고치기도 데이터하우스 안에서(프로젝트는 묶음을 가리키기만) |
| 새 클래스 | 라벨 붙일 때 이름을 새로 쓰면 새 클래스 · 관리자는 배포 신청 때 본다 | 같음 |
| 무거운 점 | 전 프로젝트 학습 데이터를 한눈에 보는 표가 없어짐(관리자는 XI 재학습 탭에서 서비스별로 봄) | 직원이 프로젝트와 데이터하우스를 오감 · 학습 데이터가 프로젝트 밖에 있어 '내 것'이 흐려짐 |

**추천: ⓐ.** 직원 일이 프로젝트 안에서 끝나고(원칙 133 '관리자가 관리하는 공유 데이터'와 같은 그림), 화면 · 단추가 가장 많이 줄며, "왜 고친 것만 데이터하우스에?"라는 질문 자체가 사라진다.

## 이런 것도 필요하지 않을까요
- 결과 확인 화면에서도 XI맵과 같은 '그 자리에서 고치기' — 직원이 결과를 확인하며 고친 것이 바로 그 프로젝트 학습 데이터가 되어야 고리가 닫힙니다(지금은 XI맵에서만).
- 고친 것을 '건'이 아니라 학습 데이터 '장'으로 세는 규칙(결정 3) — ⓐ로 가면 '고친 것 = 이 프로젝트 학습 데이터 n장'으로 한 단위가 됩니다.
