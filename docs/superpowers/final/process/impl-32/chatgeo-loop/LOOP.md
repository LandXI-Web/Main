# XI ChatGEO 정기 개선 바퀴 — 모은다 · 나눈다 · 고친다 · 잰다 · 내보낸다

> 2026-10-14 사용자: "그럼 모아둔걸 ChatGEO가 알아 듣게 서비스를 만들려면 어떻게 개선해야 해?" → "응 진행하자. 이 부분도 정기적인 개선 방향을 잡고 시작해야될 것 같다." (원칙 249)

XI ChatGEO 가 답하지 못한 질문은 서버가 저절로 모은다. 이 문서는 모은 질문을 **정해진 주기로** 고치고, 고친 것이 정말 나아졌는지 재고, 관리자 승인을 받아 내보내는 방법이다.

## 1. 주기

| 언제 | 무엇이 |
|---|---|
| **매주 월요일 새벽 2시**(사용자가 없는 쉬는 시간) | 한 바퀴를 돈다 |
| 그 전이라도 **새로 모인 개선 후보가 10건**이 되면 | 다음 쉬는 시간에 한 바퀴를 앞당긴다 |
| 같은 질문을 **3명 이상**이 물었으면 | 그 질문 하나만 먼저 한 바퀴(작은 판) |

한 바퀴는 언어 모델을 질문 하나씩 차례로 부른다(동시에 여러 개 부르지 않음). 분석 작업이 학습 장비를 쓰고 있으면 끝날 때까지 기다린다.

## 2. 다섯 단계 — 누가 · 무엇을

| 단계 | 누가 | 무엇을 | 남는 것 |
|---|---|---|---|
| **모은다** | 서버(저절로) | 답하지 못한 질문 · 3분 안에 다시 물은 질문 · '도움 안 됐어요' · 확인 카드 취소 · 지도 못 그림. 지명 · 지번 · 사람 이름은 ○○ 로 가린 요지만 | 개선 후보(관리자 대시보드 → 배포 → 개선 후보) |
| **나눈다** | 서버(제안) | 후보마다 원인 넷 가운데 하나와 고치는 방법(아래 3절)을 정한다 | 원인 · 방법 표 |
| **고친다** | 서버(시스템) | 바로 되는 것을 고치고 **새 판**에 묶는다. 새 판은 승인 전까지 **시험 질문에만** 적용 — 실제 사용자 답은 그대로 | 판(만드는 중) |

## 3. 고치는 방법 네 갈래

| 갈래 | 언제 | 어떻게 | 이번 바퀴 |
|---|---|---|---|
| **(a) 규칙** | 못 알아들음 · 다음 할 일이 없는 거절 | 관리자 화면 '이대로 반영'과 같은 길로 표 한 줄 — 다른 이름 더하기 · 질문 뜻 연결 · 답 문구 | 3건 |
| **(b) 예시 질문 붙이기** | 모델이 도구는 아는데 고르기를 자주 틀릴 때 | 확인된 '질문 → 도구 호출' 짝을 쌓아 두고, 비슷한 질문이 오면 가까운 예 셋까지 길잡이 앞에 붙인다(낱말이 3분의 1 이상 겹칠 때) | 0건 — 이번 후보 가운데 모델이 도구를 잘못 고른 질문이 없었다(장치는 넣어 둠) |
| **(c) 길잡이 모델 추가 학습** | 같은 종류의 못 알아들음이 많이 쌓였을 때 | 모아 둔 '질문 → 도구 호출' 짝으로 작은 추가 학습(적은 수의 덧붙임 가중치) · 학습 장비 한 장 · 쉬는 시간 · 한 번에 한 시간 상한 · 분석 작업 대기열과 같은 줄에 선다 | **지금은 하지 않음** — 아래 판단 |
| **(d) 새 도구** | 도구 없음 | 기존 도구 방식 — 모델 앞 직행 우선 · 모델 호출 최소 · 숫자는 서버 실제 값 · 새 도구는 판이 승인되기 전 시험 질문에만 열림 | 2개 |

**(c) 지금 할 만큼 데이터가 되는가 — 아니다.**
- 실제 사용자에게서 모인 신호 23번 · 개선 후보 38건 가운데 '못 알아들음'은 8건(이번 바퀴에 다시 물어 보니 지금도 못 알아듣는 것은 1건 — 프로젝트 이름).
- 이번에 다시 물어 본 55개 질문 가운데 모델이 도구를 잘못 고른 것은 0개였다('비닐하우스만 보기'는 도구는 맞게 골랐는데 답 검사가 그 문장을 지웠다 — 남은 것). 막힌 까닭은 대부분 도구 없음 · 결과 없음이라 추가 학습으로 풀리지 않는다.
- **시작 조건: 확인된 '질문 → 도구 호출' 짝 300개 이상, 그 가운데 '못 알아들음'에서 온 것 50개 이상.** 그 전까지는 (a) · (b)로 고친다.
- 판 바꿈: 지금 언어 모델 서버는 추가 학습 가중치를 끼우는 설정이 꺼져 있다. 서비스를 멈추지 않고 갈아 끼우려면 언어 모델 서버 설정을 바꿔야 한다(덧붙임 가중치 켜기 · 실행 중 갈아 끼우기 허용) — **보고만 하고 바꾸지 않았다.** 지금 쓰는 4비트 압축 모델에 덧붙임 가중치가 붙는지도 바꾸기 전에 시험해야 한다.

## 4. 판정 기준(잰다)

평가 질문 하나를 실제 XI ChatGEO 에 물어 끝난 답을 셋으로 나눈다. 서버가 개선 후보를 모으는 규칙과 **같은 기준**이다.

| 판정 | 뜻 |
|---|---|
| 답함 | 막힘이 없음 — 도구 답 · 지도 동작 · 확인 카드까지 감(확인 카드는 곧바로 '취소' — 분석을 돌리지 않음) |
| 안내함 | 할 수 없는 일이 맞고(권한 밖 · 결과 없음 등) 다음 할 일(버튼 · 안내 한 줄)이 붙음 |
| 못 함 | 막힘이 있고 다음 할 일도 없음 · 서버가 답하지 않음 · 2분 30초 안에 끝나지 않음 |

- 평가 질문 = 개선 후보 전부(상태와 관계없이 · 시험으로만 모인 줄 포함) + **되던 질문 14개**(지도 이동 · 확대 · 업무 거르기 · 법령 · 요약 · 대기열 · 영어 등 늘 쓰는 말).
- 가린 지명(○○)은 그 역할이 볼 수 있는 예시 지역으로 채운다(LX 계정 = 남원시 · 구례군, 기관 = 남원 기관의 남원시). 질문은 시험 질문으로 보내 개선 후보에 다시 쌓이지 않는다.
- 모델 답은 매번 조금씩 다르다. 나빠진 듯한 질문은 두 번 더 물어 한 번이라도 전과 같으면 '흔들림'으로 따로 센다.

## 5. 통과 기준(내보낸다)

**평가 질문 전체에서 답한 수(답함 + 안내함)가 늘고, 전에 답하던 질문이 하나도 나빠지지 않으면** 승인 요청을 올린다.
나빠진 질문이 하나라도 있거나 답한 수가 늘지 않으면 서버가 승인 요청을 만들지 않는다(판은 만드는 중으로 남고, 고친 것은 실제 사용자에게 적용되지 않는다).

## 6. 판 번호 · 승인 · 되돌리기 · '이제 됩니다'

- 판 번호는 1부터 차례로. 화면: LX 관리자 대시보드 → 배포 → 개선 후보 맨 위 한 줄 **'새 판 n · 질문 n개 개선 · 승인 요청'** + 답한 질문 전 → 후 · 나빠진 질문 수 + [승인] [거절].
- **승인** — 그 판의 규칙 · 새 도구가 모든 질문에 적용된다. 나아진 질문을 처음 물었던 사람(90일 안 · 시험 제외)에게 다음에 XI ChatGEO 를 열 때 맨 위에 '지난번에 물으신 ○○가 이제 됩니다' 한 줄(누르면 그 질문을 다시 보냄).
- **거절** — 그 판의 규칙을 끄고 새 도구를 닫는다. 묶였던 후보는 '새로 옴'으로 돌아간다.
- **되돌리기**(승인 뒤) — 거절과 같게 되돌린다. 다음 질문부터 예전처럼 답한다.
- 기록: 판마다 누가(시스템 · LX 관리자) · 언제 · 전/후 점수 · 나아진 질문이 남는다.
