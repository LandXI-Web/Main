# 구현 22 · 전국 작업기 — 학습 장비가 놀 때면 언제든 · GPU 한 장 · 풀로드 금지 (원칙 221 · 10-12)

브리핑 확인: (1) **GPU 한 장만 · 두 장 동시 고부하 금지 · 추론은 게이트웨이 대기열로만**: 전국 작업은 GPU0 한 장에서만 돈다. vLLM 이 쓰는 GPU1 에는 손대지 않았다. 시스템 전력 상한(nvidia-smi)도 바꾸지 않았다. (2) **숫자는 한 출처에서**: 진행률·하루 예상·남은 날은 진행 장부 하나(GET /national/progress)에서 나온다. 시험 칸은 숫자에 들어가지 않는다. (3) **설정은 그대로 두고 재시작은 정해진 방식으로만**: national.run 의 assets 는 건드리지 않았다(오케스트레이터가 농지만으로 바꿔 둠). 재시작은 start-landxi.ps1 -Restart(전후 health), 예약 작업은 register-task.ps1 로만 했다.

## 남은 것
1. **영상 읽기가 속도를 정한다.** 지금은 워커 안에서 한 창씩 읽는다(fetch_max 4 · 설정값이라 건드리지 않음). 국토지리정보원 호출 한도를 정식으로 확인한 뒤 동시에 읽는 수를 올리면 전국 예상이 크게 준다.
2. 하천은 사용자 자료가 오면 범위를 다시 만든다(`python -m national.targets --asset river --force`) → 설정 assets 에 river 를 다시 넣는다(사용자 결정).
3. 도심의 작은 칸(0.1㎢ 미만)은 칸마다 15–30초씩 고정 시간이 든다. 작은 칸을 묶어 한 작업으로 넣으면 빨라진다(아래 제안).

## 제안 — 이런 것도 필요하지 않을까요?
1. **작은 칸 묶어 넣기** — 누가·왜: LX 관리자. 도심 읍면동은 범위가 0.1㎢ 남짓이어서, 분석보다 작업 하나를 시작하고 마무리하는 데 시간이 더 든다. 같은 시군구의 작은 칸을 10㎢ 까지 묶으면 전국 예상이 줄어든다.
2. **영상 동시 읽기 수 정식 확인 후 올리기** — 누가·왜: LX 관리자(전국 일정). 병목이 영상 읽기다. 국토지리정보원 이용 범위를 확인한 뒤 동시 읽기 수를 올리면 하루 처리량이 크게 는다(사용자·관리자 결정).
3. **관리자 한 줄에 '남은 약 n일'** — 누가·왜: LX 관리자. 진행 %만으로는 언제 끝나는지 알기 어렵다. 같은 장부의 남은 날(학습 장비가 놀 때 기준)을 함께 보이면 일정을 판단할 수 있다.
