## 지도 제어 속도(재서 보고)
바깥 주소에서 채팅창에 질문을 보낸(Enter) 순간 → 지도 서비스가 조건을 건 순간 / 지도가 다시 그려져 멈춘 순간:

| 질문 | 조건 반영 | 다 그림 |
|---|---|---|
| 면적 1,000㎡ 넘는 것만 보여 줘 (152건) | 0.69초 | 0.72초 |
| 운봉읍만 (241건) | 0.90초 | 0.93초 |
| 조건 풀어 줘 | 0.68초 | 0.72초 |

서버 안 거르기 계산(값 확인 + 맞는 수) 12–14ms · 지도에 거는 시간 11ms(XI맵 결과 층 21개). 나머지는 질문 → 답 연결(게이트웨이 · 답 받기) 시간. 1초 안 목표 통과.

## 자동진화-관리 설계 한 장
- **모으기(이미 있음 · 재사용)**: XI ChatGEO 답이 끝날 때 개선 고리(improve.record_run)가 '못 한 요청'을 분류(지도 동작 없음 · 이 화면에 없음 · 자료 없음 …)해 요지 한 줄(지명 ○○)로 모은다. 시험 질문(run_test…)은 빼고, 3분 안 다시 물음 · '도움 안 됐어요' · 지도 동작 못 그림도 함께.
- **이번에 더한 것**: 거르기에서 없는 값('단동' · 없는 읍면동) → '자료 없음', 켜진 층 없음 → '이 화면에 없음', 보고서 지역 못 정함 → '그 밖'. 화면 이름 '지도 서비스'.
- **LX 관리자가 보는 곳**: LX 관리자 대시보드 → 서비스 관리 → '개선 후보'(새 메뉴 없음). 줄마다 몇 번 막혔는지 · 어느 화면 · 예시 요지 · 채택 / 보류 / 이미 됨. 채택해 만들어지면 '이제 됩니다'를 물었던 사람에게.
- **나아지는 길**: 예) '단동만'이 자주 쌓이면 → 단동 · 연동을 따로 찾는 모델(이미 프로젝트 추론 결과에 '비닐하우스_단동 · _다동' 분류가 있음)을 서비스로 올리는 일을 채택 → 그 서비스 결과가 켜지면 같은 질문이 바로 거름.
- **남긴 것**: 목록 이름을 '개선할 질문'으로 바꾸는 것은 확인 대장 16차 개선-1 에서 정한 이름('개선 후보')이라 바꾸지 않았습니다 — 바꿀지 확인 부탁드립니다.

## 이런 것도 필요하지 않을까요? (원칙 57)
1. **조건 그대로 내려받기** — 거른 상태(예: 운봉읍 1,000㎡ 넘음 152건)만 GeoJSON · 엑셀로. 담당자가 '보이는 것만' 받고 싶어함.
2. **보고서에 지금 조건 반영** — 거른 상태에서 '보고서 초안'을 청하면 그 조건의 읍면동 표로. 회의 자료를 바로 만드는 직원용.
3. **LX 관리자 '내려받기 기록' 칸** — 지금은 기록 API만(LX 계정 전부). 관리자 대시보드에 한 줄 목록이 있으면 감사 대응이 쉬움.
