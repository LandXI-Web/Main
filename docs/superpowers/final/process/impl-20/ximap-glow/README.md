# 구현 20 · XI맵 바퀴 6 — 빛나는 밀도 → 실제 객체 (원칙 204 · 199 · 196 · 162)

브리핑 확인: (1) **확인받고 만든다** — 10-12 대화 답 'XI맵 = 빛나는 밀도 → 실제 객체'(확인 대장 10-12 08:39)만 구현했다. 같은 주소(landxi/v3/xi-clean)를 바꿨고, 사용자가 직접 싫다고 한 시군구 칠하기 · 알약 · 점만 걷었다(원칙 199 — 다른 이미 쓰던 것은 그대로). (2) **숫자 한 출처 · 지어낸 숫자 0** — 빛은 서버가 전국 결과 객체를 센 칸이고, 올렸을 때 수는 그 시군구의 전국 결과 수(HUD와 같은 값). (3) **밝은 톤 · 움직임 줄이기** — 어두운 바탕 · 네온 없음, prefers-reduced-motion 이면 빛 켜짐 · 날아가기 · 요약 칸 움직임을 끈다.

## 한 줄
**XI맵을 열면 전국에서 AI가 찾은 객체가 서비스 색으로 은은히 빛난다. 확대하면(줌 10~12) 빛이 옅어지며 같은 색의 실제 객체 모양이 진해지고, 빛에 올리면 그 시군구의 서비스별 수 · 영상이 작은 칸에, 누르면 그 자리로 부드럽게 날아간다.**

주소: https://app.land-xi.dev/landxi/v3/xi-clean/ (LX 직원 · 관리자)

## 밀도 데이터(서버 · 지어내지 않음)
- `GET /ximap/density?g=0|1` (`server/landxi_api/ximap.py`) — 전국 결과(`/ximap/board` 와 같은 결과 묶음: 서비스 결과 장부 + 시군구 전역 분석)의 객체(detections · 지운 것 빼고 새로 그린 것 포함)의 중심(경계 상자 가운데)을 격자로 센다. g=0 = 0.02°(약 2km · 1,832칸 · 첫 화면과 함께 받음), g=1 = 0.004°(약 400m · 18,350칸 · 첫 화면 뒤에 받음).
- 칸 = [x, y, 묶음 번호, 수] 를 이어 붙인 한 줄 + 묶음 목록(서비스 · 시군구 · 영상) · 받는 쪽이 gzip 을 받으면 압축해서 보냄.
- 묶음마다 다시 세는 것은 그 묶음 수가 바뀌었을 때만(고치기 · 새 결과) · 기동 때 미리 셈(warm) · 한 번 세는 데 약 0.6초(전국 60만여 객체).
- **칸 합 = 그 결과 수**(서버 시험으로 확인 — 27묶음 모두 같음 · 서비스별 합 = 전국 결과 서비스 수). 빛 세기(가중치)는 서비스마다 상위 10% 칸 수로 나눈 값(객체가 적은 서비스도 보이게) — 화면 숫자에는 쓰지 않는다.

## 남긴 것
1. **바깥 연결에서 객체 조각이 늦게 옴** — 날아간 뒤 객체가 다 그려지기까지 바깥 주소에서 약 10~13초(이 PC 에서는 1~2초). 빛을 붙들어 두는 장치를 넣었지만 조각 일부가 먼저 오면 빛이 먼저 빠져 잠깐 빈 지도가 보인다. 공개 관문의 결과 조각 보관(다른 오퍼스 작업 중)과 함께 다시 볼 일.
2. 휴대폰 폭에서는 왼쪽 위 칸이 지도 위쪽을 많이 덮는다(이전과 같음) — 빛은 아래쪽에서 보임.
3. 토지피복은 객체가 많아(남원 13만여) 확대하면 지도를 넓게 덮는다 — 칩으로 끄면 다른 서비스가 잘 보인다.

## 제안 — 이런 것도 필요하지 않을까요?
1. **'이 서비스만' 길게 누르기** — 누가 왜: LX 직원. 여덟 서비스 중 하나만 빛나게 보고 싶은 일이 잦다(토지피복이 다른 빛을 덮을 때).
2. **새 결과가 들어온 자리 잠깐 반짝** — 누가 왜: LX 관리자 · 직원. 수시 갱신(원칙 182)이 눈에 보이면 '지금 돌아가는 서비스'가 체감된다(움직임 줄이기면 끔).
3. **결과 조각을 공개 관문에서 보관** — 누가 왜: 바깥에서 쓰는 모든 사람. 날아간 뒤 객체가 바로 보이게(위 남긴 것 1).
