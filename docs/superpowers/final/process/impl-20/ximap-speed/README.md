## 한 줄
**바깥 주소에서 전국 빛을 눌러 날아가면, 내려앉는 순간 객체가 이미 다 그려져 있다(남원 · 보령 · 원주 모두 누른 뒤 2.1~2.4초 = 날아가는 시간). 다시 열면 결과 조각을 다시 받지 않는다(받은 양 0). 빈 지도 0초.**

## 고친 것
1. **결과 조각 = 한 요청 · 판 번호 주소 · 1년 보관** — 서버가 조각을 꺼내 하나씩 내준다(`/tiles/mvt/{결과}/{z}/{x}/{y}.pbf?v=판`). 판 = 결과 파일 지문(크기 · 고친 시각). 판이 맞으면 브라우저가 1년 보관, 옛 판 주소는 보관 없이(no-cache) 지금 내용을 준다. 전국 결과(board)가 내줄 때마다 판을 다시 잰다 — 파일을 다시 구우면 주소가 바뀌고, 이미 그린 층도 새 주소로 바꾼다.
2. **조각 줄이기** — 얕은 줌(≤12)은 화면이 쓰는 속성(객체 번호 · 분류)만 남김(도형 · 객체 수 그대로 · 누르면 서버가 원래 속성을 줌). 가장 큰 조각 480 → 317KB. 첫 요청은 원래 조각을 바로 주고 뒤에서 줄여 디스크에 둔다(기다림 0).
3. **날아가기 전 미리 부르기** — 누르는 순간 내려앉을 화면 전체(가장자리 시군구 포함)의 결과 층을 붙이고, 그 화면을 덮는 조각을 바로 받아 둔다. 서명 · 주소는 한꺼번에(차례로 기다리지 않음).
4. **빛 붙들기 강화** — 화면 안 결과 조각이 **모두** 올 때까지 빛을 붙든다(일부만 와도 빛이 빠지던 것 고침).
5. **관문** — 서버 연결 이어 쓰기를 명시(동시 수 제한 없음) · 바깥 연결의 close 를 서버로 넘기지 않음. **서명 주소**는 6시간 칸에 맞춰 같은 칸 안에서는 같은 주소(보관이 이어짐).
6. **그 자리 고치기**는 조각을 바꾸지 않고 '고친 자리' 층으로 보인다 — 그 층은 보관하지 않음(no-store)을 명시.

## 남은 것
1. **'고친 자리' 층 응답이 느림** — 결과 묶음 하나에 약 4초(서버 질의). 고친 자리 표시가 객체보다 늦게 붙는다(이번 고장과 별개 · 고치지 않음).
2. **바탕 영상 조각**은 이번 범위 밖 — 내려앉은 뒤 영상이 선명해지기까지는 여전히 터널 시간이 걸린다(녹화에서 보임).
3. 지역 하나만 여는 화면(전국 결과 아님)의 결과 층은 아직 예전 길(PMTiles). 전국 결과 화면(XI맵 기본)만 바꿨다.
4. 시험 중 실패한 실행이 남긴 시험 고치기를 모두 되돌림(남아 있던 시험 고치기 9건 — 다른 날 실행분 포함 · 모두 '시험' 표시였음).

## 제안 — 이런 것도 필요하지 않을까요?
1. **바탕 영상도 날아가기 전에 미리 받기** — 누가 왜: 바깥에서 쓰는 모든 사람. 객체는 바로 보이지만 영상이 1~2초 흐리게 남는다.
2. **줄인 조각 미리 굽기(밤에 한 번)** — 누가 왜: 기관 첫 사용자. 새 결과가 들어온 뒤 첫 사람도 작은 조각을 받게.
3. **'고친 자리' 질의 빠르게** — 누가 왜: LX 직원. 고친 직후 다시 열었을 때 빨간 표시가 4초 늦게 붙는다.
