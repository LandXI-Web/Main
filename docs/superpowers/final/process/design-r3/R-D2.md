# R-D2. 서비스 만들기 — 단계별 처리 방식 · 승인/반려 흐름 · 서비스 버전 (다시 기획)

> 지위: 사용자 확인 전 제안(확인 요청 2차 D2 "보류 → 다시 기획"). 코드는 고치지 않았다.
> 사용자 원문(09-30): "복잡한 업무인데 구체적으로 어떻게 처리할지 신중히 검토. UI/UX 통일성." · 갈림길 답 **ⓐ 관리자 승인 뒤 공개** — "반려 사유도 기능적으로 필요."
> 확정된 전제: 서비스 만들기 = 학습·결과 확인이 끝난 모델을 '행정 업무 하나 = AI 분석 서비스 한 벌'로 묶는 일(2차 설계 정의는 유지) · 공개는 LX 관리자 승인 뒤 · 반려에는 사유가 남는다(원칙 46) · LX 직원의 일 단위는 프로젝트(R-D3) — **서비스 만들기는 프로젝트의 5번째 단계**다.

## 1. 한 눈에 — 누가 · 무엇을 입력 · 무엇이 자동
```
프로젝트(R-D3)  영상 올리기 → 라벨링 → 학습 → 결과 확인 → [서비스 만들기] → 적용
                                                            │
  ① 업무 정하기 ─ ② 분석 구성 ─ ③ 행정 자료·결과 ─ ④ 시험(자동) ─ ⑤ 공개 요청 ─ ⑥ 관리자 승인/반려
  직원 입력       자동+직원 확인  직원 입력·선택    플랫폼      직원 한 번 누름   LX 관리자
```

## 2. 시작 조건(이 조건이 안 되면 '서비스 만들기' 버튼이 비활성 + 이유 한 줄)
| 조건 | 왜 | 안 되면 보이는 말 |
|---|---|---|
| 프로젝트에 '쓸 수 있음' 상태 모델 1개 이상 | 서비스는 모델 위에 선다 | "학습을 마친 모델이 아직 없습니다 — 학습 단계로" |
| 결과 확인 표본 20건 이상 판정, 정밀도 값 있음 | 기준 없이 공개 요청 불가(UX-19: 20건 미만은 '—') | "표본을 20건 이상 확인해야 합니다(지금 n건)" |
| 실증 지역(프로젝트 대상 지역) 1곳 이상에 분석 결과 있음 | ④ 시험이 이 결과로 미리 보기를 만든다 | "분석 결과가 있는 지역이 없습니다" |

## 3. 단계표
| 단 | 직원이 입력하는 것 | 자동으로 채워지는 것 | 화면 부품(P-patterns) | 넘어가는 조건 |
|---|---|---|---|---|
| ① 업무 정하기 | 행정 업무명(실태조사 목록 10개에서 고르거나 직접 입력) · 근거 한 줄(법령·지침, 선택) · 대상(국내 / 해외) | 프로젝트 이름·지역·모델에서 업무 후보를 먼저 골라 둠 | 시트 4단 스텝퍼(공통 H) · 입력 | 업무명 있음 |
| ② 분석 구성 | 모델 확인(프로젝트 모델이 기본, 다른 프로젝트 모델 추가 가능) · 판정 규칙 체크(규칙 묶음에서) · 기준값(초기값 그대로 또는 조정 — 조정하면 '조정됨' 표시) | 영상 조건(해상도·시점 수)을 학습 데이터에서 제안 | 체크 목록 · 표 | 모델 1 · 규칙 1 이상 |
| ③ 행정 자료·결과 | 대장 가이드(없음 / 종류 선택 → 필수 열·양식·변형 처리 — R-D7 §4) · 결과 보여 주는 방법 체크(지도 층 · 필지 목록 · 행정구역 통계 · 시점 비교 · 보고서 서식) · 기관 전용 기능 이름(선택) | 대장 종류를 고르면 필수 열·규칙이 가이드 틀에서 채워짐 | 체크 목록 · 가이드 카드 | 결과 방법 1 이상 |
| ④ 시험(자동) | 보고 '확인'만 | 플랫폼이 실증 지역의 **이미 있는 결과**로 미리 보기를 만든다: 서비스 카드 모양 · 의심 필지 수 · 표본 정밀도 · 대장 가이드가 있으면 표본 대장 결합률. **GPU 실행 없음**(기존 결과만 씀) | 서비스 카드(공통 K7) + 숫자 3 | 미리 보기 생성됨 |
| ⑤ 공개 요청 | 요청 메모 한 줄(선택) · '공개 요청' 누름 | 요약(①~④) + 승인 기준 자동 검사 결과가 붙어 결재함으로 | 확인 대화(공통 P-9) → 토스트 "공개를 요청했습니다" | 승인 기준 자동 검사 통과(§4 · 갈림길) |
| ⑥ 승인/반려 | (LX 관리자) 승인 / 반려 + 사유 | 승인 → 상태 '공개' · 배포 화면 '다른 지역에 적용' 목록에 뜸 · 영업 화면 목록에 뜸 · 직원 알림. 반려 → 상태 '반려됨' + 사유 · 직원 알림 · 프로젝트 '다음 할 일' = "반려 사유 반영" | 승인/반려 시트(공통 P-2) | — |
- 시트는 중간에 닫아도 '만드는 중'으로 남아 이어서 쓴다(프로젝트 안에 보관).
- 학습 화면 원스톱의 마지막 단과 첫 화면 ③의 버튼은 **같은 시트 하나**를 연다(지금은 둘이 다른 일을 함 — 2차 설계 §3).

## 4. 승인 기준(가이드 초안) — 관리자가 보는 것과 자동 검사
| 기준 | 값(초기, 조정은 관리자 설정) | 자동 검사 | 관리자 결재함에 보이는 것 |
|---|---|---|---|
| 표본 정밀도 | ≥ 80%(표본 ≥ 20건) | 미달이면 표시 | 정밀도 · 표본 수 · 판정한 사람 |
| 실증 결과 | 지역 1곳 이상 결과 있음 | 없으면 표시 | 지역 이름 · 의심 필지 수 · 미리 보기 카드 |
| 대장 가이드 | 대장을 쓰는 서비스면 가이드 완성(필수 열 · 양식) | 없으면 표시 | 가이드 요약 |
| 표기 | 업무명 · 근거 · 대상 채움 · 화면 금지어 0(개발 정보·지어낸 말) | 자동 | 요약 |
| 중복 | 같은 업무명·같은 대상의 공개 서비스가 이미 있으면 '새 버전'으로 가야 함 | 자동 | 기존 서비스 이름 |
- **반려 사유는 필수**: 고르기 5개(정밀도 미달 / 실증 부족 / 대장 가이드 미완 / 표기·설명 부족 / 기존 서비스와 중복) + 자유 입력 한 줄. 사유는 직원 화면의 서비스 행과 프로젝트 이력에 그대로 남는다.
- 반려 뒤: 같은 서비스를 고쳐 **다시 요청**(요청 회차 +1, 이전 사유가 시트 위에 보임). 새 서비스로 다시 만들지 않는다.
- 승인 뒤 되돌림: 관리자가 '공개 중지'(사유 필수) → 적용된 지역의 기관 카드는 '중지됨' 표시, 새 적용 불가. 삭제는 없다(이력 보존).

## 5. 서비스 버전
| 변경 | 버전 | 언제 | 승인 | 적용된 지역에 |
|---|---|---|---|---|
| 첫 공개 | 1.0 | ⑥ 승인 | 관리자 | — |
| 큰 변경(모델 교체·규칙 추가로 결과가 달라짐) | 2.0 | 재학습 뒤 '새 버전 만들기' → ④ 시험 → ⑤ 요청 | 관리자 | '새 버전 있음' 알림 · 갱신은 배포 결재(지역마다) · 갱신 전까지 옛 버전 유지 |
| 작은 변경(기준값 조정·결과 방법 추가) | 1.1 | 같은 흐름 | 관리자 | 다음 분석부터 · 알림 한 줄 |
| 수정(문구·가이드·양식) | 1.0.1 | 시트에서 저장 | 없음(기록만) | 즉시 · 알림 없음 |
- 기관 서비스 카드에는 버전과 '달라진 점 한 줄'(직원이 ⑤에서 적음)이 보인다(FR-27).
- 재학습 뒤 새 버전을 만드는 판단은 R-D5-2(프로젝트장 판단 · 관리자 실행 승인).

## 6. 상태와 화면(공통 패턴)
| 상태 칩(잉크 농도 3단 · 색 0) | 뜻 | 누가 바꾸나 |
|---|---|---|
| 만드는 중 | 시트 ①~④ 진행 중 | 직원 |
| 공개 대기 | ⑤ 요청함 | 직원 → 관리자 결재함 |
| 반려됨 | 사유 있음 · 다시 요청 가능 | 관리자 |
| 공개 | 적용 가능 | 관리자 |
| 중지됨 | 사유 있음 | 관리자 |
- **서비스 목록**(첫 화면 ③ = 프로젝트의 서비스 단계에서 열림): 표(이름 · 버전 · 상태 · 모델 · 규칙 수 · 대장 가이드 · 적용 지역 수 · 재학습 필요) → 행을 누르면 우측 서랍(구성 · 적용 지역 · 이력(요청·승인·반려 사유) · 새 버전 만들기).
- **관리자 결재함**: 종류 칩 '서비스 공개' · 행 → 승인/반려 시트(누가·무엇을·왜 + 시험 결과 + 자동 검사 표시 + 승인 1차 버튼 · 반려 2차 버튼 → 사유 필수).
- 기관 화면: 적용된 뒤에만 서비스 카드(버전·달라진 점) — 기관은 서비스를 만들지 않는다.

## 7. 구현 계획(확인 뒤)
1. 서버: 서비스 만들기 저장(①~③ 항목 + 대장 가이드) · ④ 미리 보기(기존 결과 집계만) · 승인 기준 자동 검사 · 결재 항목 '서비스 공개'(승인/반려·사유·회차) · 버전 규칙 · 공개 중지 · 서비스 목록(적용 지역 수·재학습 표시).
2. 화면: 첫 화면 ③·학습 화면 원스톱 → 같은 시트 · 서비스 목록 표 + 서랍 · 결재함 '서비스 공개' + 승인/반려 시트(공통 부품) · 기관 카드 버전·달라진 점.
3. 실증: 프로젝트 1개(농지이용, 표본 20건 이상) → 시트 ①~⑤ → 결재함 → **반려(사유)** → 고쳐 다시 요청 → 승인 → 배포에서 두 시도 지역 적용 → 기관 카드 · 새 버전 1.1 흐름 1회.

## 8. 완료 기준
- 시작 조건 미달이면 버튼 비활성 + 이유 · 충족이면 시트 열림. 두 입구(③·학습 화면)가 같은 시트.
- ④ 시험이 GPU 없이 3초 안에 미리 보기 · 숫자가 결과 확인 화면과 같은 값.
- 반려 1회 → 사유가 직원 서비스 행·프로젝트 이력·다시 요청 시트에 보임 → 다시 요청 → 승인 → '공개'.
- 서비스 수·적용 지역 수가 첫 화면·관리자·영업 화면에서 같은 값.

## 9. 확인받을 것
1. **R-D2** — 시작 조건 · 단계표 ①~⑥ · 승인 기준 가이드 · 반려 사유 필수·다시 요청 · 버전 규칙 — 확인 / 보류 / 반려.
2. **R-D2-갈림길** — 승인 기준 자동 검사의 힘: ⓐ 기준 미달이면 '공개 요청'을 못 누르게 막는다(관리자는 기준 충족 건만 본다) / ⓑ 요청은 언제나 되고 미달 표시만 붙여 관리자가 판단한다.
