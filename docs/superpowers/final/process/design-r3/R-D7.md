# R-D7. 대장 결합 — 누가, 어떤 업무에서, 왜 대장을 AI 결과와 맞춰 보나 (다시 기획)

> 지위: 사용자 확인 전 제안(확인 요청 2차 D7 "보류 → 다시 기획"). 코드는 고치지 않았다.
> 사용자 원문(09-30): "어떤 대장이어야 하는지 등 변수가 많은데 가이드 없이 대장으로 통일하는 건 너무 쉽게 판단. **AI 분석이 우선**이고 대장 매칭 행정서비스는 Land-XI 에서는 필요도가 낮고 기관(지자체)에 높다. LX 도 필요 없는 건 아님. 신중히." · 갈림길에 대해 "용도를 정확히 파악 못 했다. 어떤 기능인지 더 구체적으로 설명."
> 2차 설계(design-r2/D7-ledger-join.md)의 정리표(열 사전·매칭 순서·실패 안내)는 **버리지 않고 이 설계의 부록**으로 내려간다. 이 문서는 그 앞에 있어야 했던 '누가·왜·어떤 대장'을 세운다.

## 1. 한 줄
**AI 분석 결과(필지마다 '무엇이 보이나')는 그 자체로 서비스다. 대장 결합은 기관이 "우리 대장과 다른 필지"를 골라내려 할 때 붙이는 선택 단계이며, 대장 종류마다 '가이드'를 두고 서비스 단위로 켜고 끈다. LX 는 가이드를 만들고 결과를 검증하는 쪽, 기관은 대장을 올리고 결과를 쓰는 쪽이다.**

## 2. 실제 업무 예 — 대장이 왜 필요한가(그림)

### 예 1. 남원시 농정과 — 농지이용 전수조사(대장이 꼭 필요한 경우)
```
[AI 분석만]                         [AI 분석 × 농지대장]
남원시 농지 필지 41,000            대장 "경작 중" 인데 AI "건물·야적"  →  현장 확인 필요 759필지
 ├ 경작 중   35,200                대장 "휴경" 인데 AI "경작 중"      →  대장 갱신 확인 412필지
 ├ 휴경       3,900                대장에 없는 필지에 AI "비닐하우스" →  신고 안 된 시설 96필지
 ├ 시설(비닐하우스) 1,300          대장·AI 같음                       →  현장 안 감(39,700필지)
 └ 전용(건물·주차장) 600
"무엇이 어디에 있나"까지           "대장과 다른 곳만 가서 본다" — 농정과가 원하는 것
```
- 담당자가 들고 있는 것: 농지대장(농지정보시스템에서 내려받은 엑셀 — 소재지·지번·지목·면적·경작 여부·경영체).
- 결합이 없으면 41,000필지 결과를 눈으로 대장과 대조해야 한다. 결합이 있으면 '다른 필지'만 남는다.
- 근거: 실태조사 명세의 농지이용 실태조사(농지법 제54조, 시군 농정과) · 09-20 남원 농정과 요구 "필지 표에서 대장 불일치만 먼저".

### 예 2. 도시과 — 개발행위 허가 확인(대장 + 구역 도형)
```
AI 변화 탐지(신규 건물·절토·포장)  ×  개발행위 허가대장(허가번호·필지·기간) + 허가 구역 도형
 → 허가 없는 변화 필지   → 현장 확인
 → 허가 범위 밖 변화     → 현장 확인
 → 허가 안 변화          → 정상(안 감)
```
### 예 3. 하천과 — 하천 점용 확인
```
AI 하천구역 안 시설·경작 탐지  ×  점용허가 대장(허가 위치·기간)
 → 허가 없는 점용 · 기간 지난 점용 → 현장 확인
```
### 대장이 필요 없는 예(AI 결과만으로 서비스가 되는 것)
- 비닐하우스 동수·면적 집계 · 태양광 설비 현황 · 도로 파손 · 해안 쓰레기 · 국토 변화 시점 비교 — 대장과 대조할 것이 없거나(현황 집계) 대장이 없다.
- **따라서 '대장 결합'은 모든 서비스의 기본이 아니라, 서비스 만들기(R-D2 ③단)에서 "이 서비스는 어떤 대장과 맞춰 보나(없음 / 농지대장 / 허가대장 …)"를 고를 때만 켜진다.**

## 3. 누가 어디서 무엇을 하나

| 누가 | 어디서 | 대장과 관련해 하는 일 | 필요도 |
|---|---|---|---|
| **기관 부서 사용자**(예: 농정과 담당) | 기관 플랫폼(예: 남원 GeoVision) → 자기 서비스 안 '대장 올리기' | 대장 파일 올리기 → 열 확인 → 결합 결과(맞음·못 맞춘 행) 보기 → 대장과 다른 필지 목록 → 판정·보고서 | **높음** — 이 사람의 업무가 곧 대조 |
| **기관 관리자** | 기관 플랫폼 → 부서·사용자 관리 | 어느 부서가 어느 대장을 올릴 수 있는지(부서 ↔ 서비스) · 대장 보관 한도 | 중간 |
| **LX 직원** | Land-XI 서비스 만들기(③) · 결과 확인(④) · 서비스 관리(⑥) | ① 서비스마다 **대장 가이드** 작성(어떤 대장·필수 열·양식) ② 표본 대장으로 규칙(예: '대장 경작 × AI 건물')이 제대로 도는지 검증 ③ 오탐 신고 처리 때 대장 값을 근거로 봄 | 중간 — 만들고 검증할 때 |
| **LX 관리자** | LX 관리자 대시보드 | 대장 자체는 다루지 않음. 기관별 저장 사용량·한도만 | 낮음 |
- 대장은 **기관 것**이다. LX 서버는 기관별로 분리해 보관하고 개인정보 열은 받자마자 버린다. LX 직원이 기관 대장 원본을 열어 보는 화면은 없다(표본은 기관이 검증용으로 준 것만).

## 4. '가이드' 방식 — 대장을 한 형식으로 통일하지 않는다

### 4-1. 대장 가이드 한 장의 구성(서비스마다 1장, LX 직원이 서비스 만들기 ③단에서 작성)
| 칸 | 내용 | 농지이용 전수조사 예 |
|---|---|---|
| 대장 이름 | 기관이 부르는 이름 | 농지대장(농지 목록) |
| 어디서 받나 | 어느 시스템·부서에서 내려받는지 | 농지정보시스템 → 엑셀 내려받기(읍면 단위) |
| **꼭 있어야 하는 열** | 필지를 찾는 열 1묶음 + 대조에 쓰는 열 1개 이상 | 필지 찾기: 소재지 + 지번(또는 필지 번호) · 대조: 지목, 경작 여부 |
| 있으면 좋은 열 | 결과를 더 나누는 열 | 면적 · 작물 · 용도지역 · 농업진흥 |
| 빼야 하는 열 | 개인정보 | 성명 · 연락처 · 경영체 대표자 |
| 양식 파일 | 열 이름이 맞춰진 빈 엑셀(내려받기) | 농지대장-양식.xlsx |
| 흔한 변형과 처리 | 표본에서 본 변형 | 지번 뒤 지목('1답') 자동 분리 · 주소가 네 열로 나뉨 자동으로 이어 붙임 · '법정동' 열 인식 · 소재지에 시군 이름 접두 제거 |
| 결합 뒤 규칙 | 어떤 어긋남을 '다른 필지'로 보나 | 대장 경작 × AI 건물·야적 · 대장 휴경 × AI 경작 · 대장 없음 × AI 시설 |
- 가이드가 있는 대장 종류는 기관 화면에서 **올리기 전에 먼저 보인다**: "이 서비스에 필요한 대장: 농지대장 · 꼭 있어야 하는 열 4개 · 양식 내려받기". 기관은 가이드대로 준비하면 열 확인 표가 접힌 채 한 번에 결합된다.
- 가이드가 없는 대장(예: 아직 표본을 받지 못한 공유재산 대장)은 **'일반 표'로 올릴 수 있되 필지를 찾는 열만 확인**하고, 대조 규칙은 없이 '대장에 있는 필지 / 없는 필지'만 나눈다. 대조 규칙은 LX 직원이 표본을 받은 뒤 가이드로 만든다.

### 4-2. 대장 종류별 가이드 상태(첫 목표)
| 대장 | 가이드 | 근거 |
|---|---|---|
| 농지대장(농지 목록) | **1차에 완성** — 표본 11개(남원·여수·강진·목포·구례)로 변형 4가지 확인됨 | 2차 설계 §1 표본 |
| 개발행위 허가대장(+ 구역 도형) | 틀만(필수 열 정의) — 기관 표본을 받은 뒤 완성 | 실태조사 명세 §1.2 '기관 파일로 올림' |
| 하천 점용허가 대장 | 틀만 | 〃 |
| 공유재산 대장 | 틀만 | 〃 |
| 시설원예 등록 | 틀만 | 〃 |
| 건축물대장 | 가이드 없음 — 공개 조회로 붙이는 것이라 기관이 올리지 않음(키 확보 뒤) | 〃 |
- **사용자 조치가 필요한 것**: 농지대장 밖 네 종류의 실제 표본 파일(각 1개면 됨). 표본 없이는 '틀'까지만 만든다(지어내지 않음).

### 4-3. LX 쪽 쓰임새(사용자: "LX 도 필요 없는 건 아님")
1. **서비스를 만들 때** — 대장 가이드를 작성하고, 표본 대장으로 결합률(90% 이상)과 규칙 결과(다른 필지 수가 말이 되는지)를 확인한 뒤 공개 요청(R-D2 ④단 시험).
2. **결과 확인·오탐 처리 때** — 필지 카드에 대장 값이 나란히 보여야 '대장이 오래됨' 원인을 가릴 수 있다(R-D5-1 답변 종류 중 하나).
3. **다른 지역에 적용할 때** — 그 지역 기관이 같은 대장을 준비할 수 있는지 가이드로 미리 안내(적용 요청 화면에 '필요한 대장' 한 줄).
4. LX 직원이 기관 대신 대장을 올리는 일은 없다(기관 것 · 원칙 38 위계).

## 5. 결합 계산은 어디서 하나 — 갈림길을 비전문가 말로

### 지금(ⓑ)
```
[기관 담당자 PC 의 화면]                         [Land-XI 서버]
엑셀 읽기 → 열 뜻 맞추기 → 지번 정리            네 열만 받아 필지 찾기 → 결과
 (규칙 한 벌이 여기)                             (규칙 또 한 벌이 여기)
```
- 비유: 민원 서류를 **창구 직원 각자가 해석**해서 핵심만 적어 넘기는 방식. 창구마다 해석이 다르고(화면마다 규칙이 다름), 넘기지 않은 칸(지목·면적)은 뒤에서 쓸 수 없다.
- 실제로 생긴 문제: 규칙이 두 곳 · 지목·면적 열이 서버에 안 닿음 · 새로 고침하면 결과가 사라짐(코어 C4 막힌 것) · AI 도우미와 XI맵이 같은 대장을 다르게 봄.

### 제안(ⓐ) 서버 한 곳
```
[기관 담당자 PC 의 화면]                         [Land-XI 서버]
파일 고르기 · 미리 보기(첫 5행) · 열 확인 표     파일을 그대로 받음 → 개인정보 열 즉시 삭제
· 진행 막대 · 결과 세 숫자 · 못 맞춘 행 고치기   → 열 뜻 맞추기 → 지번 정리 → 필지 찾기
                                                 → 대조 규칙 → 결과 저장(기관별 분리 · 이력)
                                                 (규칙 한 벌만 여기)
```
- 비유: 서류를 **접수만 하고 한 부서가 표준 절차로 처리**하는 방식. 어느 창구(기관 화면·XI맵·AI 도우미·보고서)에서 물어도 같은 답이 나온다.
- 장점: 규칙 한 벌 · 새로 고침·다른 화면에서도 같은 결과 · 누가 언제 올렸는지 이력 · 가이드(§4)를 서버가 그대로 적용.
- 단점: 원본 파일이 서버에 잠깐 올라간다 → 개인정보 열은 받자마자 버리고 기관별로 분리 보관, 원본은 결합이 끝나면 지운다(보관은 결합 결과만). 화면이 하던 일을 서버로 옮기는 개발이 필요하다.
- 사용자 PC 에 남는 것은 없다(브라우저는 파일을 읽지 않는다).

## 6. 화면(공통 패턴 적용 — P-patterns.md)
| 장면 | 어디 | 패턴 |
|---|---|---|
| 올리기 전 안내 | 기관 서비스 작업 공간 → '대장 올리기' | 빈 상태 카드(가이드 요약 3줄 + '양식 내려받기' + 끌어 놓기 칸) — P-1 올리기 |
| 올리는 중 | 같은 곳 | 파일 줄 + 진행 막대 + 취소 — P-1 |
| 열 확인 | 같은 곳(자동 인식이 확실하면 접힘) | 표(열 이름 · 자동 인식한 뜻 · 바꾸기) + '확인' 1차 버튼 — P-3 목록 |
| 결과 | 같은 곳 | 세 숫자(올린 행 · 맞은 필지 · 못 맞춘 행) + 못 맞춘 행 표(유형별) → 행 고쳐 다시 결합 — P-3·P-4 |
| 다른 필지 | 결과 지도·필지 목록 | 규칙별 칩(현장 확인 필요 · 대장 갱신 확인 · 신고 안 된 시설) — P-4 상태 |
| 실패 | 같은 곳 | 인라인 오류 한 줄 + 할 수 있는 일 1개(2차 설계 §5 문구 표) — P-7 오류 |

## 7. 구현 계획(확인 뒤)
1. 서비스 정의에 '대장 가이드' 항목(없음 / 종류 선택 + 필수 열 + 양식 + 변형 처리 + 규칙) — R-D2 ③단.
2. 서버 한 곳 결합(ⓐ 확인 시): 원본 받기 → 개인정보 열 삭제 → 사전·순서·실패 유형(2차 설계 §3–5) → 결과·이력 저장 → 행 단위 재결합.
3. 기관 화면: 가이드 안내 → 올리기 → 열 확인 → 세 숫자 → 못 맞춘 행. '마쳤습니다'는 세 숫자가 온 뒤에만.
4. 실증: 농지대장 표본 5개(변형 4가지) × 기관 2곳(남원·목포) → 결합률 90% 이상 · 새로 고침 뒤 유지 · AI 도우미 답과 화면 숫자 동일.

## 8. 완료 기준
- 농지이용 전수조사 서비스에 가이드 1장이 붙고, 기관 화면에서 올리기 전에 가이드가 보인다.
- 표본 5개 결합률 ≥ 90% · 못 맞춘 행은 유형별 표 · 행 1건 고쳐 다시 결합 → 맞음.
- 대장 없는 서비스(비닐하우스 집계)에는 '대장 올리기'가 나타나지 않는다.
- 같은 대장의 '다른 필지 n' 이 기관 화면·XI맵·AI 도우미·보고서에서 같은 값.
