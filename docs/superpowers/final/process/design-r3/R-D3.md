# R-D3. LX 직원의 일 단위 = 프로젝트·사업 — '오늘 할 일' 대신 (다시 기획)

> 지위: 사용자 확인 전 제안(확인 요청 2차 D3-갈림길 "보류 → 개념 다시"). D3 카드 셋 중 Q2(우리 서비스가 어디서 돌고 있나)·Q3(다음에 무엇을 만들 수 있나)는 **확인됨** — 이 문서는 Q1 '오늘 할 일' 칸을 무엇으로 바꾸는지만 정한다. 코드는 고치지 않았다.
> 사용자 원문(09-30): "LX 담당자에게 오늘 할 일이 있을까. 프로젝트나 사업에 의해 영상 업로드·라벨링·학습해서 모델 개발·보완, 최종 완성되면 서비스 카드 발행 — 생산이 우선. '오늘'은 개념이 아닌 것 같다."

## 1. 근거 — 옛 자산에 이미 있던 '프로젝트'
- 옛 화면 **프로젝트 = LX 의 AI 모델 개발 작업실**: 프로젝트 만들기(이름 · 탐지 유형 · 영상은 선택 · 구성원 초대) → 탭 5(데이터 · 라벨링 · 학습 · 분석 · 배포) → 끝에 **카드 발행 요청**. 프로젝트 목록 · 조회 · 구성원(소유자 + 편집자) · 카드 역추적(이 프로젝트 모델이 어느 서비스로 갔나).
- 09-20 명세: "프로젝트 = LX 의 모델 개발 작업실. 끝에 카드 발행 요청으로 나간다" · 발행 때 **대상 사업(지자체 / 글로벌)** 을 고른다 · LX 화면이 답할 것 = "지금 몇 개를 만들고 있나(프로젝트 진행·학습 대기열)".
- 지금 v3: 프로젝트가 없다. 레일 6단(데이터 올리기 → 학습 → 서비스 만들기 → 결과 확인 → 배포 → 서비스 관리)은 있지만 **어느 일의 6단인지**(무엇을·어디·누가) 없이 전국 합계만 보인다. 그래서 '오늘' 칸이 2,878건 같은 남의 숫자가 된다.

## 2. 한 줄
**LX 직원의 일은 프로젝트 단위로 생기고 끝난다. 프로젝트 = 무엇을(업무·탐지 대상) · 어디(대상 지역, 국내·해외) · 언제까지 · 누가(프로젝트장 + 구성원) · 지금 어느 단계. 첫 화면의 '오늘 할 일' 칸은 '내 프로젝트'(진행 중 · 현재 단계 · 다음 할 일 1개)로 바뀐다. 사업은 프로젝트를 묶는 이름표일 뿐(예산·발주 문서는 다루지 않는다 — 원칙 19).**

## 3. 프로젝트 모델
### 3-1. 프로젝트 한 장
| 칸 | 내용 | 예 |
|---|---|---|
| 이름 | 직원이 짓는다 | 남원·구례 농지이용 2026 |
| 무엇을 | 행정 업무(실태조사 목록에서) + 탐지 대상 | 농지이용 전수조사 · 경작/휴경/시설/전용 |
| 어디 | 대상 지역 여러 곳(시군구 · 시도 전체 · 해외 행정단위) — **직원이 정한다.** 영상을 올리면 파일에서 읽은 지역이 후보로 뜨고 직원이 확인 | 남원시 · 구례군 |
| 사업 | 어느 사업에 속하나(선택 · 국내/해외 구분 포함) | 2026 농지이용 실태조사 지원(국내) |
| 기간 | 시작일 · 목표일 | 2026-09-01 ~ 2026-12-31 |
| 누가 | 프로젝트장 1(만든 사람이 기본, 바꿀 수 있음) + 구성원 | 김도윤(장) · 이서연 |
| 단계 | 6단 중 현재(§3-2) + 단계별 완료 조건 | 3 학습 |
| 다음 할 일 | 현재 단계에서 막힌 것 1개(자동) | "표본 20건 확인 필요(지금 2건)" |
| 회차 | 보완(재학습) 회차 | 1차 → 2차(재학습) |

### 3-2. 단계 6 = 지금 레일 6단(이름 그대로) + 완료 조건
| 단 | 이름(지금 레일) | 완료 조건(자동 판정) | 다음 할 일 예 |
|---|---|---|---|
| 1 | 데이터 올리기 | 대상 지역마다 영상 1개 이상 '지도에 올림' | "구례군 영상 없음 — 올리기" |
| 2 | 학습 | 라벨 표본 n건 이상 · 학습 1회 끝 · 모델 '쓸 수 있음' | "라벨링 120/300" · "학습 대기열 2번째" |
| 3 | 서비스 만들기 | 서비스 '공개'(R-D2 ⑥ 승인) | "공개 대기(관리자)" · "반려 사유 반영" |
| 4 | 결과 확인 | 대상 지역 분석 결과 + 표본 ≥ 20건 · 정밀도 있음 | "표본 확인 2/20" |
| 5 | 배포 | 대상 지역 1곳 이상 적용 승인 · 기관 카드 생김 | "적용 요청 결재 대기" |
| 6 | 서비스 관리 | (끝이 없는 단계) 오탐 신고 · 재학습 신호 → 보완 회차 | "오탐 신고 4건 처리" · "재학습 권장(신호 2)" |
- 순서는 길잡이일 뿐 **막지 않는다**(옛 자산: "영상은 나중에 넣어도 프로젝트는 만들어진다"). 다만 서비스 만들기·배포는 시작 조건(R-D2 §2)이 있다.
- 결과 확인(4)은 학습(2) 직후에도 할 수 있다(모델 시험) — 레일 순서는 지금 화면대로 두되 단계 판정은 조건으로 한다.
- **보완 회차**: 서비스 관리에서 재학습이 정해지면(R-D5-2) 같은 프로젝트가 '2차'로 학습 단계로 돌아간다. 새 프로젝트를 만들지 않는다 — 이력이 한 줄로 이어진다.

### 3-3. 사업
- 사업 = 이름 · 구분(국내 지자체 / 해외) · 기간 · 담당 부서(LX) · 프로젝트 목록. 만들기는 LX 관리자(또는 직원이 만들고 관리자가 이름만 정리).
- 사업이 없는 프로젝트도 된다(사업 칸 '없음'). 사업은 관리자 화면의 묶음 보기(사업별 진행·자원)에만 쓴다.

### 3-4. 누가 무엇을
| 누가 | 프로젝트에서 하는 일 |
|---|---|
| LX 직원(구성원) | 프로젝트 만들기 · 6단 작업 · 다른 직원 초대 |
| 프로젝트장 | 대상 지역·기간 변경 · 구성원 관리 · 공개 요청·적용 요청·재학습 요청을 낸다(R-D5-2) |
| LX 관리자 | 전체 프로젝트 목록·사업별 묶음 보기 · 승인(공개·적용·재학습 실행) · 프로젝트장 교체 · 보관(종료) |
- 프로젝트 만들기에 관리자 승인은 두지 않는다(가볍게 시작, §7 갈림길).

## 4. LX 직원 첫 화면 — '오늘 할 일' 칸을 대신할 것
```
┌ 내 프로젝트 ────────────────────────┐ ┌ 돌고 있는 서비스(Q2 · 확인됨) ┐ ┌ 만들 수 있는 것(Q3 · 확인됨) ┐
│ 남원·구례 농지이용 2026   3 학습     │ │ 서비스 4 · 운영 지역 9곳       │ │ 만드는 중 2 · 업무 5/10      │
│   → 표본 확인 2/20                   │ │ 이번 달 새로 적용 2곳          │ │ 재학습 권장 1                │
│ 여수 해안 쓰레기 2026     5 배포     │ └────────────────────────────────┘ └──────────────────────────────┘
│   → 적용 요청 결재 대기              │
│ + 새 프로젝트                        │
└──────────────────────────────────────┘
      전국 지도(서비스별 점 · 확인됨) · 최근 일어난 일 3줄(확인됨)
```
- '내 프로젝트' = 내가 구성원인 프로젝트, 진행 중만(끝난 것은 목록에서). 줄마다 **이름 · 현재 단계 · 다음 할 일 1개**, 누르면 그 프로젝트의 그 단계 화면이 열린다(레일이 그 프로젝트로 맞춰짐).
- 구성원인 프로젝트가 없으면 빈 상태 카드 한 장: "진행 중인 프로젝트가 없습니다 — 새 프로젝트" (공통 P-5).
- 관리자 지정 '담당 서비스·지역'(2차 갈림길 ⓐ)은 두지 않는다 — 프로젝트 구성원이 곧 담당이다.
- 옛 '오늘' 4칸의 숫자는 어디로 가나: 결과 확인 대기 → 각 프로젝트 '다음 할 일' · 적용 요청 → 프로젝트 5단 · 오탐 신고·재학습 → 프로젝트 6단 + Q3 '재학습 권장' · 공개 대기 → 프로젝트 3단. 전국 합계 큰 숫자는 첫 화면에서 사라진다.

## 5. 프로젝트 화면(공통 패턴)
| 장면 | 패턴 |
|---|---|
| 프로젝트 목록(첫 화면 '내 프로젝트' 더 보기 · 관리자 전체) | 표(이름 · 무엇을 · 어디 · 사업 · 단계 · 다음 할 일 · 프로젝트장 · 목표일) → 행 = 우측 서랍(요약 · 구성원 · 이력) — P-3 |
| 새 프로젝트 | 시트 1장(이름 · 업무 · 대상 지역 고르기(검색·지도) · 사업 · 기간 · 구성원) · '만들기' 1차 버튼 — 지역을 화면이 고르지 않음(원칙 33) |
| 프로젝트 안 | 지금 레일 6단이 **이 프로젝트의 단계**가 된다(레일 위에 프로젝트 이름 · 지역 칩). 단계 원 = 완료(잉크) · 현재(액센트) · 대기(헤어라인) — 공통 스텝퍼 |
| 지역 표시 | 마스트 아래 프로젝트 이름 + 지역 칩(여러 곳이면 '남원시 외 1') — P-8 |
| 끝내기 | 프로젝트장이 '보관' → 확인 대화(P-9) · 이력 유지 · 서비스는 그대로 |

## 6. 구현 계획(확인 뒤)
1. 서버: 프로젝트(이름·업무·지역 여러 개·사업·기간·장·구성원·단계·회차) · 사업 · 단계 완료 조건 자동 판정 · '다음 할 일' 계산 한 곳 · 기존 영상·모델·서비스·배포본에 프로젝트 연결(지금 데이터는 '이름 없는 프로젝트'로 묶어 이관).
2. 화면: 첫 화면 '오늘' → '내 프로젝트' · 프로젝트 목록·시트 · 레일이 프로젝트 문맥을 가짐 · 관리자 사업별 보기.
3. 실증: 직원 2명 · 프로젝트 2개(국내 2지역 · 해외 1) · 한 프로젝트를 6단 끝까지 + 보완 회차 1회.

## 7. 완료 기준
- 첫 화면에 전국 합계 큰 숫자 0 · '내 프로젝트' 줄을 누르면 그 단계 화면에 그 지역으로 도착(화면이 지역을 바꾸지 않음).
- 단계 완료 조건이 자동으로 바뀌고, '다음 할 일' 이 프로젝트·서비스 관리·관리자 화면에서 같은 값.
- 재학습이 정해지면 새 프로젝트가 아니라 회차 +1.

## 8. 확인받을 것
1. **R-D3** — 프로젝트 정의(무엇·어디·기간·담당·단계 6·회차) · 사업은 이름표 · 첫 화면 '오늘 할 일' → '내 프로젝트' — 확인 / 보류 / 반려.
2. **R-D3-갈림길** — 프로젝트 만들기: ⓐ 직원이 바로 만들고 관리자는 목록·사업 묶음만 본다 / ⓑ 관리자 승인 뒤 시작.
