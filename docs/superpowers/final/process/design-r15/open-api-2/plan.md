## 0. 한 줄 정의
**기관에 공유된 분석 서비스 하나 = 그 기관이 API로 쓸 수 있는 서비스 하나 = 키 하나.** 키를 든 기관의 다른 시스템은 그 서비스의 결과를 가져가고(지난 결과까지), 영상을 올려 분석을 맡긴다(관리자 승인 뒤). 화면보다 넓게 열리는 것은 없다 — 같은 관할 · 같은 서비스 · 같은 한도 · 같은 기록.

## 3. API가 하는 일 — 새 구조에서
| # | 일 | 바깥 주소(키 머리글 `Authorization: Bearer lxk_…`) | 지금 서버에서 |
|---|---|---|---|
| 1 | **키 확인** | `GET /v1/me` → 기관 · 서비스 이름 · 판 · 관할(공유한 시군구) · 한도 남은 양 · 끝나는 날 | 공유 판정 · 한도 |
| 2 | **결과 시점** | `GET /v1/timepoints` → 서비스 결과 + 분석 요청으로 더해진 시점 | `/requests/timepoints` |
| 3 | **결과 가져오기(지난 결과 포함)** | `GET /v1/results?timepoint=&since=&cursor=&limit=&crs=&bbox=&class=` → GeoJSON 한 쪽 최대 1,000개 | 결과 조회 · 내려받기 자르기 |
| 4 | **요약** | `GET /v1/summary?timepoint=` → 종류별 개수 · 면적 · 읍면동별 · 확인 전/확인됨 | 대표 수치 한 출처 |
| 5 | **파일 내보내기** | `GET /v1/exports/{geojson|shp|parcels}?timepoint=&crs=` | 내려받기(GeoJSON · 필지 엑셀 있음 · SHP 새로) |
| 6 | **영상 올리기** | `POST /v1/uploads` → `PUT …?offset=` → `POST …/finish` → `POST /v1/drafts/{id}/read`(파일에서 읽은 값 · 관할 안인가) | 분석 요청 조각 올리기 그대로 |
| 7 | **분석 맡기기** | `POST /v1/analyses {source: upload|shared, draft_id|imagery_id, memo}` + `Idempotency-Key` → 요청 번호 · '승인 대기' | `POST /requests` 그대로(들어온 곳 = API) |
| 8 | **상태** | `GET /v1/analyses` · `/v1/analyses/{id}` → 승인 대기 · 보류 · 승인됨 · 분석 중 · 끝 · 반려(사유) · 실패(사유) | 분석 요청 상태 |
| 9 | **알림(웹훅)** | 승인 · 반려 · 분석 끝 · 실패 · 새 결과 시점 공유됨 | 작업 이벤트(ops_event) 위에 발송기 새로 |

- **서비스는 요청에 적지 않는다** — 키에 이미 묶여 있다(틀릴 자리 하나 줄임).
- **분석 맡기기는 곧바로 돌지 않는다** — 화면의 분석 요청과 같은 결재함 한 줄(원칙 69 · API-3 ⓐ 한도 안 비용 없음). 승인되면 같은 대기열(게이트웨이 · 전력 규칙), 결과는 그 서비스의 새 시점으로 기관 화면과 API 양쪽에 같은 번호로 쌓인다(C7).
- **사용 현황에 합산**(원칙 160): 배포 → 사용 현황 표에 열 둘 — 'API 호출(이번 달)' · '기관이 요청한 분석' 안에 'API로 n'. 기관 합계 · 기관 한도는 화면과 같은 장부.
- **기관 한도**: 분석 시간 · 면적 · 저장은 지금 칸 그대로 합산. 새 칸 'API 호출(하루)'(초기값 제안 — 키당 1분 60회 · 기관 하루 20,000회 · 관리자가 기관별로 바꿈). 넘으면 잠시 멈춤(다시 해도 되는 때를 알려 줌).
- **감사 기록**: 모든 호출 = 시각 · 키 끝 네 자리 · 쓰는 시스템 이름 · 기관 · 서비스 · 무엇을 · 몇 건 · 크기 · 결과 코드 · 접속 주소(1년). 키 만들기 · 폐기 · 교체 · 분석 승인/반려는 audit_log. 기관 관리자와 LX 관리자가 같은 기록을 본다.
- **인증(원칙 173 — 섞지 않음)**: 사람은 화면 로그인(아이디 · 비밀번호 · 나중에 OTP — 기관 = 정부 OTP · LX = 사내 OTP). 시스템은 키. 키로는 화면 API(`/api/v1`)를 못 부르고, 세션 토큰으로는 `/api/ext/v1`을 못 부른다. **키를 만들고 폐기하는 화면 동작은 사람의 로그인(OTP가 붙으면 OTP 뒤)** 에서만.
- **알림 비밀**: 키마다 알림 서명 비밀을 서버 기본 비밀에서 만들어 낸다(따로 저장하지 않음 · 키와 함께 한 번 보임).

## 4. 구현 계획
공정: 평가(1 · 2절) → 기획(이 문서 · 확인 항목) → 개발(단계별) → 실증(바깥 주소 · 남원 + 광주전남 + 확인자가 고른 한 곳 · 로그인 폼 · 명령줄 없이 화면 · GPU 한 장) → 서비스(안내 페이지 · 운영 기록).
**API-정리가 '맞음'이고 결정 항목이 정해진 뒤에만** 시작한다. 다른 오퍼스가 고치는 직원 · 관리자 화면(release · approvals · gov-accounts 등)과 겹치는 파일은 그 작업이 끝난 뒤.

## 7. 확인 못 한 것(정직하게)
- 코드 읽기와 문서만 했다 — API를 부르지도, 바깥 주소에 새 이름을 붙여 보지도 않았다.
- 터널에 `api.land-xi.dev` 이름을 더하려면 터널 설정과 DNS 연결이 필요하다(이 PC의 cloudflared 인증서로 될 것으로 보이나 확인 전).
- 공유 표 · 사용 현황 · 기관 관리자 화면은 지금 다른 오퍼스가 고치는 중 — 칸 자리는 그 작업이 끝난 화면에 맞춘다.
- 초기 한도 값(호출 수)은 제안이다. 결과 크기(시군구 전역 GeoJSON 약 160–225MB)는 6차에 잰 값 그대로다.
