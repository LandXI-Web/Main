### A. 지도 서비스 (질문 1 ⓑ · 원칙 163 · 154 · 147 · 123)
- 화면 가득 실제 지도. 왼쪽 372 = 내가 돌린 분석 결과가 **분석서비스별 묶음**으로 쌓임(비닐하우스 3 · 건축물 2 · 주차장 2 · **프로젝트 추론 1** — 원칙 158 배포 전 모델로 돌린 것도 내 결과). **여러 묶음을 동시에** 켤 수 있고(캡처 = 남원 비닐하우스 703동 + 덕과면 프로젝트 추론 144건), 줄을 켜면 그 결과 세트가 지도에 그려지고 그 범위로 간다.
- 도형(또는 줄)을 누르면 **오른쪽 속성 칸**이 펼쳐진다 — 결과 값은 PMTiles 속성 그대로(분류 · 신뢰도 · AI가 그린 면적 · 읍면동), 영상 시점 · 분석한 날은 작업 기록, **필지 정보**는 그 자리의 연속지적 API(`/parcels?lng&lat` — 지번 · 지목 · 필지 면적 · 공시지가) + 필지 가운데 결과가 차지한 비율. 캡처의 값은 전부 실제 응답(운봉읍 준향리 824-9답 · 1,653㎡ · 비닐하우스 780㎡ 37% 등).
- 바탕 = 영상 시점(2023 항공 · 2025 드론 넷) · LX맵(편집지적도 — V-World WMS 프록시가 아직 흰 그림 1,313B 를 돌려줘 '연결 확인 중') · 연속지적 선. 범례는 결과 분류 넷 + 필지 경계. XI맵 실시간 · 전역 · 성능 요소 0.
- 이 세트는 `GET /regions/{sgg}/results`가 주는 것과 같은 PMTiles(결과 세트 `results/lx/{job}`) — 프로젝트 추론 세트는 regions 목록에는 없지만 같은 길(`/tiles/pmtiles/…`)로 열린다.

### C. 분야 관리 (질문 5 · 원칙 165 · 156)
- ① 배포 신청서에 **분야 고르기(여러 개)** · **서비스 설명 한 문장**(카드 소개로 그대로) · **쓸 수 있는 영상**(드론 · 항공 · 위성 — 영상별 거르기의 출처). 새 분야는 '요청'만 — 만드는 것은 관리자.

- ③ 분석하기 거르기 칩이 그 목록(순서)을 따르고(서비스가 0인 분야는 숨김), 카드 소개는 서비스 설명 말투(원칙 156 예문), 그림 위 분야 표시, 영상별 거르기(드론 3 · 항공 5 · 위성 0).

## 4. 판정 근거(짧게)
- 질문 1: 사용자 말 그대로 — 왼쪽 쌓임 · 누르면 지도 · 오른쪽 속성. 실제 데이터로 렌더해 보니 **두 묶음이 같은 지역에 겹칠 때(남원 703동 + 덕과면 추론)** 색만으로는 어느 묶음인지 구분이 안 됨 → 속성 칸 머리줄에 묶음 이름을 적고, 왼쪽 줄에서 '이 묶음만 보기'가 있으면 좋겠다(제안 1).
- 질문 3: 브이월드 분석은 **된다(실증)** — 단 서비스마다 다르다. 원천마다 적합도 표시가 핵심이고, 연도 이력은 국토지리정보원 층이 바탕.
- 질문 5: 분야는 서버 상수 → 관리 표. 신청서에서 고르고 관리자가 만든다. 거르기 · 카드 · 기관 공유가 한 목록을 따른다.

## 5. 제안 — 이런 것도 필요하지 않을까요?
1. **왼쪽 줄마다 '이 묶음만 보기'(다른 묶음 잠시 끄기)** — 누가 왜: LX 직원. 같은 지역에 두 묶음이 겹치면(배포 모델 결과 vs 내 프로젝트 모델 결과) 어느 쪽 도형인지 바로 구분해야 비교가 된다.
2. **영상 원천으로 돌린 결과에는 '원천 · 연도' 꼬리표를 결과 세트에 붙이고, 같은 범위를 다른 연도로 다시 돌리면 지도 서비스에서 두 해를 나란히** — 누가 왜: LX 직원 · 기관 담당자. 영상 저장 없이 결과만 쌓는 구조(원칙 136)가 지도 서비스에서 '변화'로 보이는 첫걸음.
