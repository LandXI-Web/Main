### 알려진 것 — ChatGEO '운봉읍 무허가 건축 의심 필지'가 '해당 지역 데이터가 없습니다'
- 원인: AI가 '운봉읍'을 지역 칸에 넣어 부르면, 서버는 **지금 화면의 지역(시군구)** 안에서만 그 읍면동을 찾습니다. 화면이 남원시(또는 '남원시'라는 이름)일 때는 남원시 운봉읍으로 읽어 답하고(같은 질문 07:37 성공), 화면이 전국 · 함양군 · 옛 남원 코드(45190)일 때는 '지역을 찾지 못했습니다' → '해당 지역 데이터가 없습니다'로 끝납니다(07:38 실패 · 비교 대시보드 뒤).
- 고칠 곳: 읍면동 이름만 왔을 때 화면 지역에 없으면 전국 읍면동에서 한 곳으로 정해지는지 더 찾기 · 옛 시군구 코드도 새 코드로 읽기. 이 파일(서버 ChatGEO 지역 판정)은 지금 관리자 · 기관 쪽 에이전트가 '농지 위 건물' 이름 통일로 고치는 중이라 손대지 않았습니다(겹침 보고).

### 느린 곳 상위 다섯과 고친 것
1. **분석하기 지역 고르기 → 영상 · 조건** 3.8초 → 1.8초. 서버가 요청마다 등록 영상 83장의 범위 도형을 처음부터 다시 풀고 고쳤음(0.6초 · 영상 목록과 조건 둘 다) → 같은 범위는 한 번 풀어 두고 다시 씀(0.65 → 0.05초). 전국 분석 · XI맵 영상 고르기도 같은 길이라 함께 빨라짐.
2. **학습데이터 구축** 처음 5.2초 → 3.5초. 라벨 그림 아홉 장을 동시에 부르면 한 장마다 학습 데이터 폴더 전체(200장)를 다시 훑었음(그림 한 장 1.6초) → 묶음이 바뀌지 않았으면 목록을 다시 씀(0.25초 · 다시 0.02초).
3. **데이터 올리기** 4.5 · 3.7초 → 3.3 · 2.4초. 지역을 열기 전에 일부러 0.7초를 기다리던 것을 없앰 · 영상 목록과 지역 목록을 지도 준비와 같이 받음(순서대로 기다리지 않게).
4. **지도 서비스 · 결과 확인의 '불러오는 중'** 3.1 · 2.3초 → 2.0 · 1.5초. 지도 준비가 끝난 뒤에 바탕 층 목록 → 행정 자료 목록을 차례로 받던 것을 결과 목록과 함께 받게 함.
5. **대시보드** 2.4 · 2.1초 → 1.6 · 1.6초('불러오는 중' 1.2초 → 0.4 · 0). 화면 자료를 다 받은 뒤 서버 경로 목록 → 카드 덱을 차례로 받던 두 바퀴를 없앰(서버 경로 목록은 화면이 열릴 때 바로 · 카드 덱은 프로젝트 목록과 같이). 이 한 바퀴(약 0.3초)는 프로젝트 목록 · 분석하기 · 데이터 올리기 · 학습데이터 구축에서도 같이 줄었습니다.

## 남은 것
- XI맵 첫 화면 2.0 ~ 2.9초: 전국 읍면동 집계(내려받는 크기 1.5 MB · 서버 0.4초)가 가장 큼 — 필요한 칸만 받거나 미리 계산해 두면 줄어듦(구조 변경이라 이번엔 안 함).
- 학습데이터 구축 3초대: 묶음 목록 → 묶음 하나 → 그림 순서로 세 번 기다림(화면 흐름을 바꿔야 줄어듦).

## 이런 것도 필요하지 않을까요? (원칙 57)
