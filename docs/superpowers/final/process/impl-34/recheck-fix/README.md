## 3. 로그인 직후 `/auth/session` 이 30초 넘게 응답 없음
- **다시 재 봤지만 일어나지 않았습니다.** 로그인 폼 → 첫 화면을 직원 · 관리자 · 기관 × 여러 번, 크롬과 크로미움으로 했고 모두 0.3~1.3초였습니다.
- 지난 기록 두 번은 모두 'gov' 묶음의 첫 화면이었습니다. 측정 도구가 앱 주소로 로그인한 뒤 기관 주소로 넘어간 경우라서, 측정 도구가 요청 끝을 놓쳤을 수도 있습니다. 확정은 못 했습니다.
- **관문 쪽에서 원인이 될 수 있는 것 하나를 막았습니다.**
  - 관문은 게이트웨이와의 연결을 이어 씁니다. 게이트웨이(uvicorn)는 75초 쉬면 연결을 닫습니다.
  - 그래서 쉬던 연결이 닫히는 순간에 그 연결로 보낸 요청이 걸릴 수 있었습니다.
  - 이제 관문이 60초에 먼저 닫습니다(`agent timeout 60s`).
- **다음에 또 나면 바로 가를 수 있게 기록을 남깁니다**(`server/logs/public-gate.err`).
  - 게이트웨이 답이 5초를 넘으면 `slow` 줄.
  - 게이트웨이 답 전에 바깥 연결이 10초 넘게 기다리다 끊기면 `gone` 줄.
  - `slow` 가 있으면 게이트웨이 쪽이고, 둘 다 없는데 화면이 기다렸다면 터널 · Cloudflare 쪽입니다.
- **고치는 중 실수 하나:** 관문 수정 중 응답 머리를 넘기는 줄이 빠졌습니다. 약 17:39–17:46 동안 바깥 주소 응답에 형식 머리가 없어 관리자 대시보드의 실시간 알림 연결이 끊겼습니다(콘솔 오류 1). 곧바로 되살렸고 지금은 정상입니다(event-stream · json 확인).

## 이런 것도 필요하지 않을까요?
1. **시험용 계정 · 시험용 배포 하나** — 시험 DB 를 나누기 전이라도, 배포 흐름 시험이 운영 중인 남원 배포 대신 시험 표시 배포를 쓰게 하면 이력 흔적이 바로 멈춥니다. 누가: LX 관리자 — 배포 이력에 실제 일만 남습니다.
2. **관문을 따로 다시 켜는 단추** — `start-public.ps1 -Restart gate` 처럼 관문만 다시 켜면 터널까지 끊지 않습니다. 누가: 운영 담당 — 배포할 때 바깥 주소 끊김이 짧아집니다.
3. **시험 흔적 점검 한 줄** — 관리자 처리 기록에서 '시험'·'test' 사유를 하루 한 번 세어 보이기. 누가: LX 관리자 — 4(a) 같은 엇갈린 기록을 사용자가 보기 전에 압니다.
