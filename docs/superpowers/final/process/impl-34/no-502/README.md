# 502 고침 · 502 에 로그아웃하지 않기 · XI맵 콘솔 'pt' (구현 34 · 전수 재검수 첫 일 · 원칙 251)

## 1. 502 원인
- 화면이 받은 502 는 **공개 관문(:4180)이 게이트웨이(:8700)에 닿지 못해 돌려준 502**(본문 `gateway_down`)였습니다. 터널 로그(tunnel.err)에는 오늘 'Unable to reach' 가 없고 브라우저가 끊은 요청(context canceled)만 있습니다.
- 게이트웨이에 닿지 못한 까닭은 두 가지가 겹쳤습니다.
  1. **이벤트 루프 막힘.** 게이트웨이는 작업자 하나(uvicorn 1개)입니다. 응답 본문 만들기(FastAPI 의 반환값 변환 → 직렬화 → 다시 읽기 → 봉투 검사)가 전부 이벤트 루프 위에서 돌았습니다. 큰 응답(실태조사 집계 1.5 MB · 작업 목록 0.6 MB · 배포 목록 0.3 MB)이 몰리면 루프가 1~7초씩 막혔습니다. 막힌 동안에는 health 도 다른 요청도 못 받습니다.
     - 실측(부하 30초 · 동시 12 · 바깥 주소): 루프 스레드가 89% 바빴고(표본 1,555/1,750) 그 가운데 응답 만들기가 약 60%였습니다. 이어서 GPU 칸의 동시 고부하 집계(`/ops/gpus` — 캐시가 끝난 순간 몰린 요청마다 표본 3,600개를 루프 위에서 다시 읽음) 약 11%, XI ChatGEO 스트림이 닫힐 때마다 없는 모듈(sniffio)을 파일에서 찾는 일 약 4%였습니다(lag.log · py-spy).
     - 감시(gateway-watch.log)는 health 가 20초 안에 오지 않으면 실패로 셉니다. 오늘 1/3 실패가 21번, 14:00 에는 3번 연속이어서 **감시가 게이트웨이를 다시 켰습니다**(14:01:17). 다시 켜지는 동안 관문은 연결이 거절되어(ECONNREFUSED) 그 틈의 모든 요청에 502 를 돌려줬습니다.
  2. **재시작 틈.** 감시 재기동과 배포 재시작(오늘 다른 재검수 에이전트가 16:09 · 16:13 · 16:22 · 16:48 에 다시 켬)마다 2~10초 동안 연결이 거절되어 그 틈에 열린 화면이 502 를 받았습니다.
- DB 연결 풀(16개)은 원인이 아니었습니다(부하 중 쓰는 연결 1개 · 나머지 대기). hwpx 만들기 · 지도 조각 · 영상 그리기는 이미 스레드에서 돌고 있었습니다.

## 2. 고친 것
- **게이트웨이(server/landxi_api)**
  - `main.py` · `envelope.py`: 반환값 변환 · 직렬화 · 봉투 검사를 전용 스레드 4개(lx-json)에서 미리 만들고, 루프에서는 만든 바이트만 보냅니다. 결과(본문 바이트 · 봉투 없는 숫자면 500)는 예전과 같습니다(같은 jsonable_encoder 결과를 검사 — 다시 읽기만 뺌). 지도 조각이 쓰는 공용 스레드와 줄을 나눴습니다.
  - `ops.py`: 동시 고부하 집계는 한 번에 하나만 계산하고(기다린 요청은 방금 값을 씀) 표본 읽기는 스레드에서 합니다.
  - `main.py`: sniffio 가 없으면 '없음'을 한 번 적어 두어 매번 파일을 뒤지지 않습니다(뜻은 같음 = asyncio).
- **관문(tools/public-gate.mjs)**: 게이트웨이가 다시 켜지는 동안(연결 거절) 온 읽기 요청(GET · HEAD)은 0.5초 간격으로 12초까지 기다렸다 보냅니다. 쓰기 요청은 다시 보내지 않습니다. 502 를 돌려줄 때는 원인(오류 코드 · 주소 · 걸린 시간)을 `server/logs/public-gate.err` 에 한 줄 남깁니다(바깥 연결이 먼저 끊긴 것은 빼고).
- 감시 기준(20초 × 3번) · 작업자 수 · 풀 크기 · 전국 작업기 설정은 바꾸지 않았습니다. 검사 도구도 그대로입니다.

## 4. 502 · 503 · 연결 끊김에 로그아웃하지 않기
- 규칙: **로그인 화면으로 보내는 것은 401(세션 없음 · 끝남)뿐.** 502 · 503 · 504 · 연결 끊김은 '다시 시도'.
- `landxi/shared/api-v1.js`: 읽기 요청은 502 · 503 · 504 · 연결 끊김에 0.7초 · 1.8초 뒤 두 번 다시 묻습니다(모든 화면 공용 호출부).
- `landxi/v3/kit/auth-gate.js`: 세션 확인(/me)이 서버 끊김으로 실패하면 세션을 지우지 않고 로그인 화면으로 보내지 않습니다. 가운데 '불러오는 중 · 서버 응답이 늦습니다 · 다시 시도'(기존 loader 모양 · 새 문구 0)를 띄우고 몇 초마다 다시 묻다가, 서버가 돌아오면 그 화면을 그대로 엽니다. `loader.js` 에 '처음부터 늦음 줄 함께' 선택(slowNow)만 더했습니다.
- `gov-report` · `lx-train`: 403 에도 로그인으로 보내던 것을 401 만으로. `help-my`(서랍 안): 서버 끊김이면 다시 묻습니다.
- 확인(sim502.mjs · sim502-result.json · shots/): 바깥 주소 로그인 폼으로 들어간 뒤, 브라우저 안에서만 /api/v1 을 7초 동안 502 로 돌려주고(운영 영향 0) 화면을 다시 엶 —

## 5. XI맵 콘솔 'pt'
- 'pt' 는 지도 엔진(MapLibre 5.6 압축본)의 **AJAXError 클래스 이름**입니다. 결과 지도 조각(/tiles/mvt/…)이 502 를 받으면 지도 엔진은 '오류' 듣는 이가 없을 때 오류 객체를 콘솔에 그대로 찍어 'pt' 로 보였습니다(재현 두 번 74건 · 120건 — ximap-console-before.json: `AJAXError (502): …/tiles/mvt/results/lx/namwon-farmland-2025/13/6994/3232.pbf`). 즉 1의 502 가 지도 조각에서 보인 모습입니다.
- 고친 것(`landxi/v3/kit/stage.js` — 지도 무대를 쓰는 모든 화면): 502 · 503 · 504 · 연결 끊김으로 못 온 조각은 그 조각만 1.5초 · 4초 뒤 다시 받습니다(조각마다 2번). 그 밖의 오류와 다시 받기를 다 쓴 경우는 경고 한 줄로 남깁니다.
- 확인: XI맵 여덟 곳 날아가기(전국 · 남원 11 · 14 · 16 · 전주 · 종로 · 대구 · 제주) — 고친 뒤 콘솔 오류 0(ximap-console-after.json · 부하 동시). 지도 조각 첫 요청을 **모두** 502 로 흉내 낸 시험(2,703건)에서도 콘솔 오류 · 경고 0, 조각은 다시 받아 그려짐(ximap-console-fake502.json).
- TypeError(classList): 이번 재현 세 번에서는 나지 않았습니다. 502 로 로그인으로 떨어지며 화면이 지워지는 중에 남은 코드가 칸을 찾다 난 것으로 보입니다(로그아웃이 없어져 같은 길이 없어짐). 다시 나면 관문 502 기록과 시각을 맞춰 보겠습니다.
