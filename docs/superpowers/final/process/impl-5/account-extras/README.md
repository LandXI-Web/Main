- **할당은 사람마다 한 칸 → 비어 있으면 기본 할당 → 기본 할당도 없으면 '할당 없음'.** 기본 할당은 관리자 '저장 용량 요청' 탭 위의 한 줄(설정 한 곳)이고 처음 값은 '할당 없음'입니다.
- **쓴 양은 한 곳에서 셉니다** — 내가 프로젝트장인 프로젝트의 저장 공간 합(이은 학습데이터 파일 + 올린 파일). 프로젝트 한 장의 '저장 공간', 내 정보, 관리자 계정 목록, 요청 서랍이 모두 같은 계산입니다(위 캡처 모두 29.8 MB).
- **내 정보** — 할당이 있으면 '할당 n GB 중 m 사용' + 막대 + '용량 늘리기 요청'(원하는 할당 · 이유 한 줄). 대기 중 요청은 한 사람에 하나('늘리기 요청 중 · 보낸 날 · LX 관리자 확인 전'), 처리되면 '지난 요청 · 승인 / 반려 · 사유'. 할당이 없으면 지금처럼 '할당 없음 · 지금 쓴 양'만(늘릴 것이 없으니 요청 버튼 없음).
- **관리자** — 승인하면 그 사람의 할당이 원하는 값이 되고, 반려는 사유가 있어야 합니다. 어느 쪽이든 요청한 사람의 대시보드 '내 프로젝트' 맨 위와 프로젝트 목록 맨 위에 알림 한 줄('처리한 사람 · 시각 · 사유', '내 정보' · '확인')이 뜹니다. 처리 기록 탭에 '저장 용량 할당 · 늘리기 요청 · 승인 · 반려 · 기본 할당 바꿈'이 전 → 후와 함께 남습니다. 관리자 자신의 요청 · 할당은 다른 관리자가 하고, 관리자 계정이 하나뿐이면 스스로 합니다(결재함과 같은 규칙).
- **90% 를 넘으면(막지 않고 알리기만)** — 내 정보에 빨간 한 줄 '할당의 99%를 썼습니다. 더 필요하면 늘리기 요청을 보내 주세요', 파일 올리는 자리(프로젝트 기록 칸)에 '내 저장 용량 할당의 99%를 썼습니다. 올리기는 그대로 됩니다 · 늘리기 요청', 그리고 파일을 올린 뒤 창 하나(원칙 109 — 이 창을 연 동안 한 번만). 프로젝트 구성원이 올리면 '프로젝트장 저장 용량 …'으로 보이고 요청 버튼은 프로젝트장에게만.

### 여쭐 것 — 할당을 넘었을 때 막을까요? (S-19-넘을 때)
지금은 **ⓐ 알리기만**입니다(원칙 91 '한도는 하드웨어에만' · 기본값). 예시 장면: 할당 50 GB 인 직원이 49 GB 를 썼고 2 GB 학습 표본을 더 올리려 합니다.
- **ⓐ 알리기만(지금)** — 올라갑니다. 51 GB(102%)가 되고 내 정보 · 올리는 자리에 빨간 한 줄 + 창으로 늘리기 요청을 권합니다. 관리자는 계정 목록에서 빨간 칸으로 봅니다. 일은 멈추지 않지만, 여럿이 넘으면 서버 디스크가 먼저 찰 수 있습니다(그때는 지금처럼 서버 전체 디스크 선에서만 막힙니다).
- **ⓑ 올리기 막음** — 올리기 전에 '할당을 넘습니다 — 늘리기 요청을 보내 주세요' 창으로 멈춥니다. 디스크는 지켜지지만, 관리자가 승인할 때까지 그 직원의 데이터 올리기가 멈춥니다.
- 예외(어느 쪽이든): 할당이 없는 사람(할당 없음)은 막지 않습니다. 서버 전체 디스크가 모자라면 지금처럼 누구든 막힙니다. 이미 올린 데이터를 지우거나 줄이지는 않습니다.

- 쓴 양은 **프로젝트에 이어진 학습데이터 파일과 올린 파일**만 사람(프로젝트장) 몫으로 셉니다. 영상 원본 · 분석 결과처럼 프로젝트에 이어지지 않은 저장은 사람에게 나누지 않았습니다(지난 구현과 같음).
- 부서 목록은 로그인 전 가입 신청 창이 써야 해서 **로그인 없이 부서 이름만** 내줍니다(누리집 조직도와 같은 정보 · 계정 · 출처 · 바꾼 사람은 관리자에게만).
- 같은 계정 화면 파일에 기관 갈래가 '볼 수 있는 서비스'(기관 관리자의 부서 사용자 배정) 줄을 동시에 넣는 중이었고, LX 계정 서랍에 'null' 글자가 찍히는 것을 봐서 그 줄을 비어 있으면 넣지 않게 막아 두었습니다(그 갈래의 변경이라 이번 커밋에는 넣지 않았습니다 — 그 갈래가 함께 올립니다).

## 먼저 드리는 제안(원칙 57)
| 제안 | 누가 · 왜 |
|---|---|
| 할당 합계와 서버 디스크를 한 줄로(인프라 화면 '저장 공간' 옆에 '나눠 준 할당 합 n GB / 디스크 m GB') | LX 관리자 — 할당은 막지 않는 약속이라, 나눠 준 합이 실제 디스크를 넘는지 한눈에 봐야 증설 시점을 잡습니다 |
| 90% 를 넘은 사람만 계정 관리 위에 모아 보기(이름 · 쓴 비율 · 마지막 올린 날) | LX 관리자 — 요청이 오기 전에 먼저 늘려 주거나 정리를 권할 수 있게 |
| 지운 파일을 7일 동안 되살리는 휴지통(지금은 지우면 바로 사라짐) | 프로젝트장 — 잘못 지운 근거 파일을 되찾게. 대신 그동안은 저장 공간에서 빠지지 않습니다(어느 쪽이 좋은지 여쭘) |
| 사내 인사 시스템과 이을 때 부서 이동을 저절로 반영 + 지사 명단 | LX 직원 — 전보 때마다 본인이 고치지 않게, 지사도 목록에서 고르게(정식 오픈 때 사내 계정 · OTP 연동과 함께) |
