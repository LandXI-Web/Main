# 구현 5차 · 기관 화면 완성 디자인 — 메인 · 내 서비스 · 서비스 대시보드 · 분석 요청 · 요청함의 보낸 사람 (2026-10-01)

브리핑 확인: (1) 확인된 것만 만든다 — 기관 화면 확인(10-01) 기관-1 ⓐ(공통 틀 · 메뉴는 지금 다섯 통일만) · 기관-2 ⓐ · 기관-3 ⓐ · 기관-4 ⓐ · 기관-5 ⓐ(+ 이름 '분석 요청' · 원칙 113) · 기관-8 ⓐ. 기관-7 · 9 · 10 · N-1~3 은 손대지 않았다(서비스별 우리 담당자 표 · '우리 공간' 정리 없음). (2) 숫자는 서버 값 한 출처 · 큰 숫자 자리엔 업무 결과만 · 지역 하드코딩 0 — 남원시 · 광주전남 둘 다로 확인. (3) 로그인 전 그림은 저해상 크롭만 · 제한 영상 0 · 연락처는 받은 LX 담당 직원과 LX 관리자에게만(서버가 자른다).

캡처는 모두 바깥 주소에서 로그인 폼으로 들어간 화면이다(1440×900 · 휴대폰 390×844 · `-full` = 아래까지 한 장). '전'은 같은 바깥 주소에서 이번에 고친 화면 파일만 지난 판(커밋된 판)으로 바꿔 끼워 찍었다(메인 · 로그인 전도 같은 방법). 계정: 기관(남원시 · 광주전남) `lxadmin@lx.or.kr` · LX 직원 `test@lx.or.kr` · LX 관리자 `lxadmin@lx.or.kr`. 비밀번호는 임시 비밀번호(대화로만). 시안은 설계 8차 `design-r8/gov-design/`(오른쪽 칸).

- 탭 = 현황 · **결과 지도**(XI맵 · 그 시군구) · 필지 목록 · **행정정보와 비교**(지금의 대장 × AI 화면) · 보고서. 필지 목록 · 보고서는 필지 대조가 있는 서비스만.
- 현황(왼쪽): **결과 장면 위 큰 숫자 하나**(현장 확인 필요 1,035필지 · 서버 값 / 광주전남 = AI 탐지 1,857건) + '결과 지도 열기' · '필지 목록'. 장면은 그 기관 관할 장면만(시점이 있는 서비스는 가장 최근 시점 장면).
- **읍면별 현장 확인 필요** 막대(많은 곳부터 다섯 + 그 밖 n곳) — 실태조사 집계에 읍면별 '현장 확인 필요'를 더했다(큰 숫자와 같은 식 · 칸 합 = 1,035). 읍면을 누르면 그 읍면의 결과 지도(가장 먼저 볼 필지)로. 광역 전체에서는 시·군·구별 막대(한 곳뿐이면 막대 없음).
- **영상과 결과 — 시점**: 서비스 카드의 고를 수 있는 장면 가운데 날짜가 적힌 것(관할 것만 · 서버가 거른다) — 남원 2025.04 · 06 · 08 · 10. 날짜 없는 장면은 넣지 않는다.
- 오른쪽: **이 결과는**(무엇이 · 언제 · 믿을 만한 정도 세 줄 + 판 · 공개한 날) · '이 결과 설명 자세히' 서랍(바뀐 점 + 여섯 칸) · 내려받기 셋(지도 파일 · 필지 엑셀 · 요약 — 분기 공간 1단 서버 그대로 · 처음 한 번 이용 약속). **내가 확인할 필지** 셋(결과 확인 대기 1,038건 — 서버 값). **LX와 주고받은 검토 요청**(이 서비스로 보낸 검토 요청 · 분석 요청 · 상태) + LX 담당(요청을 받는 사람 · 없으면 'LX 관리자가 대신 답합니다') + '결과 지도에서 검토 요청 보내기'(필지 카드에서 보낸다).
- 새 결과 한 줄: 이 서비스의 읽지 않은 새 판이 있으면 탭 아래 한 줄(설명서를 열면 읽음).

## 6. 요청함의 보낸 사람(기관-8 ⓐ)
| 전 | 후 — LX 관리자 | 후 — LX 직원(받은 사람) |
|---|---|---|
| ![](img/before-admin-inbox-1440.png) | ![](img/after-admin-inbox-1440.png) | ![](img/after-staff-inbox-1440.png) |

- 기관 검토 요청을 열면 **보낸 사람** 칸: 이름 · 기관 부서 / 역할 · 연락처. 목록 줄도 '남원시 농정과 이름'. 분석 요청 목록(요청함 숫자 '분석 요청')에도 보낸 사람 한 줄.
- 연락처는 그 사람이 스스로 적은 경우만 있다 — 기관 가입 신청에 **'연락처(선택)'** 칸을 더했고(동의 항목에도 '연락처(선택 — 적은 경우만)'), 승인되면 그 계정에 옮겨진다. 관리자가 대신 적지 않는다(원칙 105).
- 보는 사람: 그 요청을 받은 LX 담당 직원과 LX 관리자만(새 길 `GET /api/v1/accounts/senders` — 다른 직원의 요청은 빈 칸 · 기관 계정 403).

## 이런 것도 필요하지 않을까요?
- **부서 사용자 첫 로그인 때 '맡은 서비스' 안내** — 누가: 부서 사용자. 왜: 정해 준 서비스가 없으면 빈 화면이다. '기관 관리자 ○○에게 서비스를 요청하세요' 한 줄과 기관 관리자 이름을 보여 주면 막히지 않는다.
- **읍면 막대에서 바로 필지 목록 거르기** — 누가: 담당 공무원. 왜: 읍면별로 현장 계획을 세운다. 막대를 누르면 지도 대신 그 읍면만 거른 필지 목록(내려받기 포함)으로 가는 길을 하나 더.
- **메인 업무 결과 숫자를 보일지 기관이 고르기** — 누가: 기관 관리자. 왜: 로그인 전에도 보이는 숫자라 기관마다 공개 여부 판단이 다를 수 있다(지금은 시안대로 보임 · LX 메인은 게스트에게 기관 자료 숫자를 '로그인 후 확인'으로 가린다).

- **부서 배정** = 계정 화면 → 부서 사용자 한 줄 → **볼 수 있는 서비스**(체크 · 저장) — 우리 공간의 배정과 같은 기록이라 내 서비스 · 이력 · 통계가 바로 그대로 거른다.
- '우리 공간' 메뉴는 없다. 옛 주소(gov-space)는 그 서비스의 통계·보고서 탭(없으면 내 서비스)으로 보낸다. 내 서비스 오늘 띠 = 새 알림 · 보낸 요청 · 요청하기.

## 2묶음 — 시안과 다른 점
- **결과 지도는 서비스 안 탭이 아니라 XI맵 화면으로 연다**(시안 A안은 탭 안 지도). 탭 구조를 새로 짜는 일(기관-1 다시 그리기)이 '다시'라 지금 XI맵에 '보고 있는 결과' 카드 · 단추만 붙였다. XI맵의 기관 왼쪽 칸은 지도 도구라 '내 서비스'로는 머리의 마크로 돌아간다.
- 통계의 **기간 칩은 월별 확인 기록에만** 건다 — 다섯 숫자는 지금 상태(기준일)라 기간으로 자르면 같은 이름의 숫자가 둘이 된다(사용자 규칙 3). 숫자 이름도 짧게(의심 필지 · 확인 전 / 현장 확인 필요 / 확인 끝 / 오탐 · AI가 잘못 봄 / 현장 확인 예정).
- 이력 탭의 촬영 · 분석 · 검토 요청 줄은 실제 기록만(시안의 '예시' 줄 없음). 확인 기록은 지금 남원시에 쌓인 그대로.
- 촬영 요청의 대략 비용은 **화면에 보이는 넓이(소수 둘째 자리)로 셈**한다 — 보이는 넓이 × 고시 금액 = 보이는 금액이 되게.
- 메일 알림 '계정에서 끄기'는 아직 없다(메일 서버 설정 뒤 함께).

## 2묶음 — 이런 것도 필요하지 않을까요?
- **다음 확인 날짜가 되면 종 · 메일 한 줄** — 누가: 담당 공무원. 왜: 적어 둔 '다음 확인 10.06'이 지나도 아무도 모른다. 새 결과 알림과 같은 길(종 다른 할 일)로 그날 아침에 한 줄.
- **부서 사용자도 맡은 서비스 필지에 메모** — 누가: 현장에 나가는 부서 담당자. 왜: 지금 서버 규칙은 기관 관리자만 적을 수 있어, 실제로 다녀온 사람이 관리자에게 전해 적어야 한다. 배정된 서비스의 필지에만 적게 열면 기록이 바로 남는다.
- **촬영 요청 확정 금액의 근거 한 줄** — 누가: 기관 예산 담당. 왜: 대략 값과 확정 값이 다를 때(끝수 · 부가세 · 분석 대가) 무엇이 더해졌는지 줄로 보이면 기관 안 문서에 바로 붙일 수 있다.
