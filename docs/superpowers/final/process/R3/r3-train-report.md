## 알려진 한계 · 남은 것
1. **보령시 곤포사일리지 배포본의 결과·실태조사가 남아 있다.** 이 배포본은 3차 실증 때 기본 모델로 분석됐다. 이제 두 화면(직원·관리자)이 모두 '서비스 모델로 분석하지 않음 · 분석 모델 건물·주차장·경작지'로 정직하게 보인다. 하지만 보령 실태조사(의심 필지 14,432 · 규칙 6개)는 시군구 실태조사로 DB 에 남아 있고, 전국 합계에도 들어간다. 지우거나 되돌릴지는 **사용자·관리자 판단**이다. 이번에는 지우지 않았다.
2. 실태조사는 시군구마다 하나다. 같은 시군구에 규칙이 다른 서비스 두 개를 적용하면, 나중 것이 그 시군구 실태조사를 다시 만든다. 서비스별 실태조사는 구조 결정이 필요하다(C3).
3. 관리자 모델 교체 목록이 해상도가 맞지 않는 모델(예: 주차장 서비스에 곤포사일리지)도 후보로 보인다. 서버가 교체를 막는다(409 · 이유 문장). 목록에서 빼는 것은 r3-ops 화면 몫이다.
4. 관리자 결재함 대상이 '서북구 주차장'처럼 구 이름만 나온다(천안시 서북구). r3-ops 표기 규칙.
5. 배포 서랍·서비스 관리의 빈 상태에 비행기 그림, XI맵 불러오는 중에 드론 사진이 나온다. 공통 키트 그림이다. 원칙 42(의미 없는 장식 금지)와 어긋날 수 있다. Fable·공통 키트 판단 몫이다.
6. 로그인 화면의 역할 탭(원칙 27 '탭 없음')은 입구 셋 정리(r3-ops·UI/UX) 전이라 남아 있다. 이번에는 탭이 있을 때의 착지만 맞췄다.
7. 백그라운드 탭에서는 지도·서랍 애니메이션이 느리게 그려져 화면이 뜨는 데 10–20초 걸렸다(서버 응답은 0.2초 안). 확인 도구 환경 탓이며, 실제 사용자 체감은 따로 재야 한다.
8. 새 주차장 모델 성능은 0.404 다(작은 표본·3회차). 서비스 품질은 표본·회차를 늘려 재학습해야 한다. 이번 목적은 원스톱 동작 확인이다.
9. 기관 결과: 두 지역 모두 계약 기관이 없어(LX 보관) 기관 화면 대신 XI맵·배포 화면으로 확인했다.
