# 메일 2차 인증 — 보안성 검토

> 2026-10-01 · Opus 5.5 · 지위: **사용자 확인 전 제안**(코드 수정 0). 그림: `shots/mfa-4-compare.png`(원본 `fig/04-compare.html`).
> 사용자 원문(10-01): "메일 2차 인증 이런 것도 보안성 검토 필요하다."

## 1. 판단 한 줄
**메일로 코드를 보내는 방식은 2차 인증으로 쓰지 않습니다.** 메일은 **알림과 비밀번호 재설정 보조**로만 씁니다. 문자(SMS)도 2차 인증으로 쓰지 않습니다. 2차 인증은 OTP 앱(기관 · LX) 또는 회사 OTP(LX, 연결되면)입니다.

## 2. 메일 코드의 약점
| 약점 | 무슨 뜻 | 근거 |
|---|---|---|
| 두 번째 문이 되기 어렵다 | 메일은 비밀번호 하나로 열리는 경우가 많아, 메일 비밀번호를 가진 사람은 코드도 받습니다. 사람들이 같은 비밀번호를 여러 곳에 쓰면 사실상 한 겹 | 미국 국립표준기술연구소 디지털 신원 지침(2025년 8월판) 3.1.3.1 — 메일은 "비밀번호만으로 접근 · 전송 중·중간 메일 서버에서 가로채기 · 경로 바꾸기"에 약해 **2차 인증 수단으로 쓰지 말 것** ([원문](https://pages.nist.gov/800-63-4/sp800-63b.html)) |
| 메일 계정이 먼저 노려진다 | 업무 메일을 노린 가짜 로그인 메일(피싱)이 흔합니다 | 한국인터넷진흥원 보호나라 2024-11-26 "ERP, 그룹웨어, 웹메일 대상 피싱 공격 주의" — 외부에서 접속 가능한 웹메일은 "반드시 2차 인증(OTP 등)을 설정" ([공지](https://www.boho.or.kr/kr/bbs/view.do?searchCnd=&bbsId=B0000133&searchWrd=&menuNo=205020&pageIndex=1&categoryCode=&nttId=71596)) |
| 늦게 오거나 안 온다 | 기관 메일 필터 · 스팸함 · 외부 발송 차단에 걸리면 코드 유효 시간(보통 5–10분) 안에 못 받아 로그인이 막힙니다 | 운영 경험 일반 — 기관별 필터 설정은 확인 못 함 |
| 공무원 메일은 또 로그인해야 연다 | 공직자통합메일 등 업무 메일은 밖에서 열 때 인증서·모바일 공무원증 같은 로그인을 한 번 더 거치는 경우가 많습니다. 코드 하나 받으려고 로그인을 두 번 하는 셈 | 모바일 공무원증으로 공직자통합메일 등에 로그인([전자신문 2022-09-28](https://www.etnews.com/20220928000178)) |
| 우리 쪽 준비가 필요 | 보내는 메일 서버 · 발신 도메인 인증(받는 쪽 필터 통과) · 보낸 기록 · 실패 재시도 | — |

## 4. 메일이 쓸 만한 자리 — 보조로만
| 자리 | 보내는 것 | 왜 |
|---|---|---|
| 비밀번호 재설정 | 한 번만 쓰는 링크 · 15분 · 링크로 바꾼 뒤에도 **2차 인증을 거쳐야** 입장 | 메일만으로 계정이 넘어가지 않게 |
| 새 기기 · 새 나라 로그인 알림 | "처음 보는 환경에서 로그인했습니다. 내가 아니면 비밀번호를 바꾸세요" | 본인이 먼저 알아채게 |
| 2차 인증 초기화 · 복구 코드 사용 | "2차 인증이 초기화되었습니다(누가 · 언제)" | 본인 모르게 풀리는 것을 막음 |
| 계정 잠김 | "틀린 비밀번호 5번으로 10분 잠겼습니다" | 누가 대입하고 있음을 알림 |
| 가입 신청 승인 · 반려 | 기관 가입 흐름에서 이미 쓰기로 한 알림(가입 신청 시안의 '업무 메일' 칸) | 새로 받는 정보 없음 |
메일 주소는 가입 때 받는 **업무 메일** 하나만 쓰고, 휴대폰 번호는 받지 않습니다(원칙 50 — 사용자에게 짐을 넘기지 않음).
