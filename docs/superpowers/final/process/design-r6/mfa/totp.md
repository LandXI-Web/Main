# 기관(남원 · 전남 · 해외) — 구글 OTP 같은 표준 OTP 앱으로 2차 인증

> 2026-10-01 · Opus 5.5 · 지위: **사용자 확인 전 제안**(코드 수정 0 · GPU 0). 그림: `shots/mfa-3-totp.png`(등록 · 로그인 · 분실) · `shots/mfa-5-login.png`(지금 / 바뀐 뒤) · 지금 화면 `shots/now-gov-login.png`.
> 사용자 원문(10-01): "반대로 남원이나 전남에서 접속할 때 구글 OTP? 이런 걸 활용할 수 있는지."

## 1. 한 줄 답
**활용할 수 있고, 기관 쪽 기본으로 권합니다.** 구글 OTP · 마이크로소프트 인증 앱처럼 **국제 표준 시간 방식**(30초마다 바뀌는 6자리)을 쓰는 앱이면 무엇이든 됩니다. Land-XI 서버 안에서 끝나므로 업체 계약·문자 비용·기관 전산실 연동이 필요 없고, 해외 기관도 똑같이 씁니다. LX 직원도 회사 OTP 가 연결되기 전까지 같은 모양으로 씁니다.

## 2. 흐름
### 처음 한 번(약 2분) — 관리자가 켜 두면 다음 로그인 때 저절로 나옵니다
1. **앱 설치** — 휴대폰에 OTP 앱(무료). 이미 있으면 건너뜀.
2. **QR 비추기** — 앱으로 화면의 QR 을 비춤. QR 이 안 되면 '글자로 넣기'.
3. **6자리 확인** — 앱에 생긴 'Land-XI 남원시' 줄의 번호를 넣어 맞아야 등록.
4. **복구 코드 10개 보관** — 휴대폰을 잃었을 때 하나씩 한 번만 쓰는 코드. 내려받기 · 인쇄. 이 화면이 지나면 다시 보여 주지 않음.

### 로그인 때
아이디 · 비밀번호(지금과 같음) → **6자리 한 장** → 입장. 로그인이 하루 유지되므로 **하루 한 번꼴**입니다(관리자 권한 계정은 로그인마다). 틀리면 다시, 5번이면 10분 잠금 + 본인 메일로 알림.

### 휴대폰을 잃거나 바꿀 때(원칙 72 — LX 관리자는 다 보고 돕는다)
| 복구 코드 | 이렇게 |
|---|---|
| 있다 | '복구 코드로 들어가기' → 코드 하나로 입장(그 코드는 다시 못 씀) → 새 휴대폰으로 다시 등록. 혼자 끝, 본인 메일로 알림 |
| 없다 | '휴대폰을 잃어버렸어요' → 가까운 관리자에게 초기화 요청 → 관리자가 **본인 확인**(전화 등) 뒤 '2차 인증 초기화'(사유 한 줄 · 기록) → 본인 메일로 알림 → 다음 로그인 때 다시 등록 |

| 누가 잃었나 | 누가 풀어 주나 |
|---|---|
| 기관 부서 사용자 | 그 기관 관리자 — LX 관리자도 할 수 있고, 그때는 기관 관리자에게 알림 |
| 기관 관리자 | LX 관리자 |
| LX 직원 · 영업 | LX 관리자 |
| LX 관리자 | 다른 LX 관리자 — 관리자가 한 명뿐이면 복구 코드가 유일한 길이므로 **관리자를 두 명 이상** 둡니다 |

LX 는 기관 가입 승인에는 관여하지 않지만(원칙 72), 초기화·잠금 풀기 같은 **지원**은 할 수 있게 합니다. 모든 초기화는 누가 · 누구를 · 왜 · 언제로 남고 LX 관리자가 봅니다.

### 휴대폰을 미리 바꿀 때 · 사람이 떠날 때
- 새 휴대폰: '내 계정 → 2차 인증 다시 등록'(지금 번호 한 번 확인 뒤 새 QR).
- 퇴직·전보: 기관 관리자가 계정을 잠그면 2차 인증도 함께 무효.

## 3. 누가 켜나
- **정식 오픈**: 모든 사람 계정 필수. LX 관리자가 기관을 만들 때 기본으로 켜져 있고, 기관 관리자는 끌 수 없습니다(보안 기준 — `public-sector.md`).
- **지금(시범)**: 관리자 권한 계정(lxadmin 등)만 켭니다 — 사용자 혼자 쓰므로 부담이 작고, 가장 위험한 계정부터 지킵니다.

## 4. 장단점
| 좋은 점 | 아쉬운 점 |
|---|---|
| 무료 · 업체 계약 없음 · Land-XI 안에서 끝남 | 휴대폰이 필요함(업무용이 없으면 개인 휴대폰) |
| 인터넷·문자·전화번호가 필요 없음(번호는 휴대폰 안에서 만들어짐) | 휴대폰을 잃으면 초기화 업무가 생김(복구 코드로 줄임) |
| 문자보다 안전 — 유심 복제·번호 가로채기와 무관 | 가짜 로그인 사이트에 번호를 넣으면 뚫림(피싱에 강하지는 않음) |
| 해외 기관도 같은 방식 · 앱은 사용자가 고름 | 휴대폰 시계가 많이 틀리면 실패(앞뒤 30초까지는 받아 줌) |
| 휴대폰에 개인정보를 요구하지 않음(번호·위치 없음) | 구글 OTP 의 '구글 계정 백업'을 켜면 그 계정이 털릴 때 함께 위험 — 2023년 4월 생긴 기능([The Hacker News](https://thehackernews.com/2023/04/google-authenticator-app-gets-cloud.html)) · 안내 한 줄로 알림 |

## 5. 공무원 업무 환경에서 현실적인가
- **PC 망**: 지자체는 업무망 PC 와 인터넷 PC 를 나눈 곳이 많습니다. Land-XI 기관 입구는 인터넷 주소라 **인터넷 PC 에서** 엽니다. OTP 앱은 휴대폰에 있어 PC 망과 상관이 없습니다 — 맞습니다.
- **개인 휴대폰 사용**: 공무원이 개인 휴대폰으로 업무 인증을 하는 선례가 이미 있습니다 — 모바일 공무원증(2022년 9월부터 희망한 227개 지자체로 확대, 공직자통합메일·정부원격근무서비스 로그인 지원 — [전자신문 2022-09-28](https://www.etnews.com/20220928000178)) · 정부원격근무서비스의 스마트폰 앱 인증([복합인증 안내](https://auth.gvpn.go.kr/app/usr/certiCenter/all/authInfo)). OTP 앱은 전화번호·위치·연락처를 받지 않아 거부감이 적은 편입니다.
- **휴대폰을 못 쓰는 사람**: 같은 표준 방식의 **실물 OTP 토큰**을 기관이 사서 등록하면 됩니다(등록 흐름 같음, QR 대신 토큰 번호).
- **기관 보안 규정**: 기관에 따라 업무용 앱 설치를 제한할 수 있습니다 — 남원 · 전남 정보보안 담당에게 확인할 것(확인 못 함).
- **해외(키르기스 등)**: 표준 OTP 앱이 가장 현실적입니다. 아래 7절의 공무원 인증은 국내 전용입니다. 안내는 영문.

## 6. 쉽게(원칙 49 · 50)
- 입력 칸은 **번호 하나만** — 6칸은 숫자를 넣으면 저절로 다음 칸, 붙여넣기 됨, 휴대폰에서는 숫자 자판.
- '처음 한 번'은 네 칸 그대로, 설명은 칸마다 한 줄.
- 하루 한 번꼴 — 같은 날 다시 묻지 않음(관리자 권한만 로그인마다).
- 복구 코드로 혼자 해결되는 길을 먼저 둠 — 관리자에게 짐이 덜 감.
- 기관 사용자에게 추가 입력(휴대폰 번호 등)을 받지 않음.

## 7. 공무원이 이미 가진 인증을 쓰는 길(대안 — 갈림길 2)
공무원은 이미 **정부 OTP** · **모바일 공무원증** · **행정전자서명 인증서**를 씁니다. 이것을 Land-XI 에 붙이면 새 앱이 필요 없습니다. 다만 **LX(공공기관)가 운영하는 Land-XI 가 신청할 수 있는지 확인이 먼저**입니다.
| 수단 | 붙이려면 | 걸림돌 |
|---|---|---|
| 정부 OTP | 정부OTP인증센터에 기관 연계 신청 — 행정전자서명 연동 라이선스 + 정부 OTP 연동 키 · 국가정보자원관리원에 연결망 허용 신청(인터넷망 연결 창구 있음) | LX 가 신청 대상인지 · 해외 불가 · 문의 1661-9088 |
| 모바일 공무원증 | 민간 서비스는 '민간 SaaS 연계공통기반'(2024년 6월 개통, 모바일 공무원증 로그인 · 조직도 · 행정표준코드 연계)을 거침 | 클라우드 보안 인증을 받은 **민간** 서비스 대상 — 공공기관 LX 가 운영하는 Land-XI 가 이 길인지, 다른 길이 있는지 행정안전부 확인 필요 |
| 행정전자서명 인증서 | 인증서 검증 표준 창구 신청 · 서버용 인증서 | 인증서가 업무망 PC 에 있어 인터넷 PC 로 옮겨야 하는 불편 · 해외 불가 |
출처와 자세한 내용은 `public-sector.md` 3절.

**권하는 순서**: 표준 OTP 앱으로 먼저 열고(국내·해외 한 가지 모양), 정부 OTP · 모바일 공무원증은 행정안전부 답을 받은 뒤 **국내 공무원의 선택 수단**으로 더합니다.

## 8. 개발 메모(구현 에이전트용 — 확인된 뒤에만)
- 표준: 국제 표준 시간 방식(RFC 6238) · 30초 · 6자리 · 앞뒤 한 칸 허용 · 같은 칸 번호 재사용 거절(마지막으로 받은 칸을 계정에 저장).
- 비밀값은 서버 설정 파일(`server/.env`)의 키로 **암호화해 저장**하고, 화면에는 등록 때 QR 로 한 번만. 기록·오류 메시지에 비밀값 0.
- 복구 코드 10개는 비밀번호처럼 **한 방향 저장**(지금 쓰는 argon2) · 하나 쓰면 지움.
- 계정마다 5번 실패 → 10분 잠금. 성공 · 실패 · 잠금 · 초기화 · 복구 코드 사용을 모두 기록하고 LX 관리자 화면에서 봄.
- 초기화 권한: 기관 관리자 = 자기 기관 부서 사용자만(관할 밖 0 — 원칙 39) · LX 관리자 = 모두. 자기 자신은 초기화 못 함.
- 구현은 표준 라이브러리(HMAC)로 스무 줄 안팎이면 되고, 외부 라이브러리를 쓰면 라이선스를 확인합니다. QR 은 서버가 만들어 한 번 내줌.
- 로그인 화면 두 번째 장은 지금 로그인 카드 안에서 바뀝니다(새 창 없음). 기관 분기 화면은 기관 마크·색만 다름.
