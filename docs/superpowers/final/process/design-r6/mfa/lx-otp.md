# LX 직원 · LX 관리자 — 회사 OTP 를 Land-XI 로그인에 붙이기

> 2026-10-01 · Opus 5.5 · 지위: **사용자 확인 전 제안**(코드 수정 0 · GPU 0). 그림: `shots/mfa-2-lx-otp.png`(원본 `fig/02-lx-otp.html`).
> 사용자 원문(10-01): "우리 직원이 사용하는 OTP 가 따로 있는데 이걸 반영할 수 있는지? 어떻게 해야 하는지? 어떤 정보가 필요한지?"

## 1. 한 줄 답
**반영할 수 있습니다.** 다만 방법은 그 OTP 가 **무엇인지**(휴대폰 앱 · 실물 토큰 · 회사 통합 로그인)와 **그 인증 서버가 회사 밖에서 닿는지**에 따라 네 길로 갈립니다. 어느 길이든 직원이 하는 일은 같습니다 — 로그인 때 회사 OTP 번호 한 번. 회사 쪽 정보가 오기 전에는 Land-XI 가 **표준 OTP 앱**(구글 OTP 등)으로 먼저 지키고, 연결되면 바꿉니다.

## 2. 지금 Land-XI 로그인
- 세 입구(메인 · 관리자 · 기관) 모두 **아이디 · 비밀번호 한 번**이면 들어갑니다. 로그인은 하루 유지됩니다.
- 틀린 비밀번호는 **접속한 곳(인터넷 주소)마다 10분에 20번**까지만 받습니다. **계정마다 잠그는 장치는 없습니다.**
- 성공한 로그인은 기록되지만 **실패한 로그인은 기록되지 않습니다.**
- 관리자 계정(lxadmin)은 관리자 입구뿐 아니라 메인 입구로 들어와도 **관리자 권한**을 받습니다. 그래서 2차 인증은 입구가 아니라 **계정에 걸어야** 합니다.
- 시범 단계라 모든 계정이 임시 공통 비밀번호를 씁니다(원칙 30 · 10-01 비밀번호는 그대로 두기로 결정).

## 3. LX 가 직원에게 쓰게 하는 OTP 는 무엇일까 — 조사 결과
**공개 자료로는 확인하지 못했습니다.** 'LX OTP · 통합인증 · 원격근무 · 입찰 공고'로 찾았지만 LX 의 제품 이름·방식을 밝힌 공개 글은 없었습니다. 공공기관에서 흔히 쓰는 형태는 다음 다섯입니다 — LX 도 이 중 하나일 가능성이 큽니다.

## 4. 붙이는 네 길
| | A. 회사 통합 로그인으로 들어가기 | B. 인증 서버에 번호만 물어보기 | C. 회사 OTP 앱에 Land-XI 추가 | D. 연결 전까지 Land-XI OTP 앱 |
|---|---|---|---|---|
| 기술 이름(정보보안 부서용) | 통합 로그인(SSO) — SAML 또는 OIDC | RADIUS 또는 업체 확인 API | 표준 시간 방식 OTP(TOTP) 등록 | 표준 시간 방식 OTP(TOTP) |
| 직원이 보는 것 | Land-XI 로그인의 'LX 통합 로그인' 버튼 → 회사 로그인 화면(회사 비밀번호 + 회사 OTP) → Land-XI 로 돌아와 입장 | Land-XI 아이디·비밀번호 → 회사 OTP 6자리 → 입장 | 처음 한 번 회사 앱으로 Land-XI QR 비추기 → 로그인 때 그 줄의 6자리 | 처음 한 번 OTP 앱 등록 → 로그인 때 6자리(기관 입구와 같은 모양) |

| 받아야 할 것 | 통합 로그인 연결 정보(주소 · 서명 인증서) · Land-XI 돌아올 주소 두 곳 등록(메인 · 관리자 입구) · 넘겨받을 항목(사번 · 이름 · 부서 · 메일) · 시험 계정 2개 · 정보보안 부서 승인 | 인증 서버 주소 · 포트 · 방식 · 공유 비밀값 또는 확인용 키 · 연동 규격 문서 · 아이디 맞추는 규칙 · **방화벽 허용**(Land-XI 서버 → 인증 서버) · 시험 계정 2개 · 승인 | 회사 앱이 'QR 로 다른 서비스 추가'를 허용하는지 · 업무 외 등록을 규정이 허용하는지 | 없음 |

| 좋은 점 | 비밀번호도 회사 것 하나 · 퇴사·전보가 저절로 반영 | 흔한 방식(VPN 과 같음) · Land-XI 화면 모양 그대로 | 준비가 거의 없음 | 지금 바로 · 기관과 같은 모양·같은 말 |
| 아쉬운 점 | 회사에 통합 로그인이 있어야 함 · 설정이 가장 많음 | 연결망(방화벽) 협조 필요 | 퇴사해도 자동으로 안 막힘(Land-XI 계정을 따로 잠가야) | 직원이 앱을 하나 더 씀 |

**추천 순서**: 지금 D(관리자 계정부터) → 여쭐 것의 답을 받아 A 또는 B → 연결되면 LX 계정은 회사 OTP 로 바꾸고, 회사 인증 서버가 멈출 때만 D 를 비상용으로 남김(아래 7절).

## 5. 회사 OTP 서버가 사내망에서만 닿는다면
지금 Land-XI 서버는 이 PC 에서 인터넷 주소(app · admin · gov)로 열려 있습니다. 회사 인증 서버가 사내망 전용이면 B 는 곧바로는 안 됩니다. 길은 넷입니다.
1. **D 로 시작** — 표준 OTP 앱으로 지금 바로 지킵니다(회사 정보 없이 가능).
2. **운영 서버를 LX 전산센터로 옮길 때 연결** — 같은 망 안이 되면 B 가 가장 쉬워집니다(국내 운영은 LX 전산센터가 기본 방향).
3. **정보보안 부서에 한 줄 허용 요청** — 'Land-XI 서버 주소 → 인증 서버 포트' 하나만 여는 방식. 보안성 검토가 따릅니다.
4. **A(통합 로그인)를 먼저 확인** — 통합 로그인은 직원 브라우저가 오가며 확인서를 옮기는 방식이라, 서버끼리 직접 닿지 않아도 되는 경우가 있습니다(회사 설정에 따라 다름 — 여쭐 것 3·4).

## 6. 사용자께 여쭐 것(짧게)
1. **OTP 이름과 모습** — 휴대폰 앱인가요, 실물 토큰인가요? 앱 화면 사진 한 장이면 충분합니다.
2. **어디에 쓰나요** — 재택근무 VPN · 그룹웨어 · 메일 · 업무 포털 중 어디서 번호를 넣나요?
3. 한 번 로그인하면 여러 사내 시스템이 열리는 **통합 로그인**이 있나요?
4. **집·출장지에서도** 그 OTP 로 로그인되는 시스템이 있나요? (회사 밖에서 닿는지)
5. **관리 부서**와 담당자 — 정보보안 또는 정보화 담당 부서 이름.
6. 다른 사내·외부 시스템이 이 OTP 를 **붙인 사례**와 그때 받은 연동 문서가 있나요?
7. 직원 **아이디 체계** — 사번인가요, 메일 아이디인가요? Land-XI 아이디를 그것에 맞춰도 되나요?

## 8. 연결되면 달라지는 것
- 퇴사·휴직·전보가 회사 쪽에서 막히면 Land-XI 도 함께 막힙니다(A 는 바로, B 는 다음 로그인부터).
- Land-XI 의 LX 계정 비밀번호를 따로 관리하지 않아도 됩니다(A).
- 회사 인증 서버가 멈추면 LX 직원이 못 들어옵니다 → **관리자만** 복구 코드나 Land-XI OTP 앱으로 들어오는 비상 길을 남기고, 몇 시간 동안 열지 정보보안 부서와 정합니다.

## 9. 개발 메모(구현 에이전트용 — 확인된 뒤에만)
- 로그인을 두 단계로: 비밀번호가 맞으면 세션 대신 **5분짜리 확인표**를 주고, 2차 확인이 맞을 때 세션을 줍니다. 관리자 입구의 '관리자 계정만' 확인은 2차 확인 뒤에도 그대로.
- 계정마다 2차 인증 종류(없음 · OTP 앱 · 회사 번호 확인 · 회사 통합 로그인)를 둡니다 — 입구가 아니라 계정 기준.
- 공개 관문의 로그인 시도 제한은 지금 로그인 경로 하나만 셉니다 → 2차 확인 경로도 함께 셉니다. 계정마다 5번 실패 잠금은 서버가 합니다.
- 실패도 기록(비밀번호 실패 · 2차 실패 · 잠금 · 초기화)합니다.
- 고칠 곳: 서버 로그인(`server/landxi_api/auth.py`) · 공개 관문(`tools/public-gate.mjs`) · 로그인 화면(`landxi/v3/login/auth.js` · `index.html`) · 계정 표에 2차 인증 칸. 관리자 화면(:8702)으로 넘기는 인계도 2차 확인 뒤 세션만.
