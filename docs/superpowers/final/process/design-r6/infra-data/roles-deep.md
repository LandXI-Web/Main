## 0. 한 줄
**사람 역할은 9개로 충분하다.** 빠진 것은 새 사람이 아니라 **"보관소 · 장비 · 기관 데이터를 누가 책임지나"라는 책임 셋**이고, 이는 LX 관리자 · 프로젝트장 · 기관 관리자의 일로 붙인다. 9 역할 가운데 **화면 권한 묶음으로 실제 만들 것은 계정 역할 5(+ 선택 1) · 프로젝트 안 역할 2 · 키 1**이고, 해외 기관 · 게스트는 문서로 정한다. 반대로 **서버가 지금 아는 기관 역할(담당자 · 열람자)은 R&R 과 맞지 않아** 다시 맞춰야 한다.

## 1. 역할 = 화면 권한 묶음(구현) / 문서로만 정할 것
| 9 역할 | 무엇으로 만드나 | 이유 |
|---|---|---|
| LX 관리자 | **구현 — 계정 역할** | 결재 · 기관 만들기 · 자원 · 보관소 · 장비 · 기관 검토 요청과 의뢰를 함께 봄 · 기관 사용자 확인 · 통제 · 지원(가입 승인은 기관 관리자 — 원칙 72). 결재는 요청자와 다른 사람이 해야 해서(구현됨) 최소 두 사람(지금 관리자 계정 2) |
| LX 직원 | **구현 — 계정 역할** | 프로젝트를 만들고 생산한다 |
| └ 프로젝트장 · 구성원 | **구현 — 프로젝트 안 역할**(계정 역할 아님) | 한 직원이 A 프로젝트에선 장, B 에선 구성원. 프로젝트마다 붙는 표시. 소유 · 판단(공개 요청 · 재학습 시작 — 역할-3 확정)과 프로젝트 몫 요청이 여기에 걸린다 |
| LX 영업 | **구현 — 계정 역할**(읽기 전용) | 있음 |
| 기관 관리자 | **구현 — 계정 역할(새로)** | 부서 · 사용자 · 가입 승인 · 기관 데이터 책임. 지금 서버에 없다 |
| 부서 사용자 | **구현 — 계정 역할(새로) + 부서 칸** | 자기 부서 서비스만(원칙 38). 지금 서버에 부서 칸 없다 |
| (선택) 열람자 | 구현 — 계정 역할(있음) | 보기만. 쓸 기관이 있을 때만 |
| 외부 시스템 | **구현 — 키 권한 묶음**(사람 아님) | 서비스별 API 키 한 개 = 기관 · 서비스 · 결과 보기/분석 맡기기 · 기한(원칙 69) |
| 해외 기관 | **문서로만** | 기관 관리자 · 부서 사용자와 권한이 같다. 다른 것은 기관의 언어 · 관할 종류(해외 구역)뿐 — 기관 한 줄의 속성. 따로 역할을 만들면 권한이 두 벌이 된다 |
| 게스트 | **문서로만** | 계정이 없다. 로그인 전 공개 화면 규칙(소개 · 서비스 · 문의 · 가입 신청) |

**서버가 지금 아는 역할과의 차이**
| 지금 서버 | 바뀐 뒤 |
|---|---|
| LX: 관리자 · 직원 · 영업 | 그대로 |
| 기관: 담당자 · 열람자(기관 계정 9개가 모두 '담당자') | 기관 관리자 · 부서 사용자(+ 부서) · 열람자. 지금 '담당자' 계정은 기관 관리자로 옮기고 부서 사용자는 가입 신청 · 승인으로 새로 |
| 프로젝트 역할 없음(프로젝트가 없음) | 프로젝트장 · 구성원 |
| 키 없음 | 서비스별 API 키 |

## 2. 기관 만들기 · 데이터를 하려면 빠진 것 — 후보를 하나씩
| 후보 | 해야 하는 일 | 판단 | 어디에 붙이나 |
|---|---|---|---|
| **데이터(보관소) 관리 담당** | 보관소 여유 보기 · 1TB 넘는 원본 승인 · 두는 기간이 된 것 정리 · 중복 합치기 · 기관에 영상 공유 고르기 | 일은 **빠져 있다**(지금 아무도 안 함 — 2.1TB 사본 · 결과 1,133 폴더). 그러나 **새 로그인 역할은 만들지 않는다** | **LX 관리자**의 화면 칸 '저장 · 보관소'. 지우기는 두 사람 결재. 관리자가 여럿이면 문서로 담당을 정함 |
| **인프라 운영 담당** | 장비 등록 · 전력 규칙 값 · 저장 위치 · 언어 모델 켜기 | 화면 안의 일은 **LX 관리자** 일로 충분. 값을 바꾸면 두 사람 결재(한도 변경과 같은 방식) | LX 관리자 화면 '장비 · 저장 설정'(`infra-flex.md`) |
| └ 화면 밖 장비 일 | 디스크 교체 · 전원 · 드라이버 · IDC 설치 · 보관 장치 연결 | 플랫폼 계정이 아니다 — **사람(장비 담당)** | **문서로만**: 누가 하는지 · 끝나면 관리자 화면에 무엇을 등록하는지 |
| **기관 관리자의 부서 관리** | 부서 만들기 · 부서 ↔ 서비스 연결 · 가입 승인 · 광역의 부서 관할(도 전체 / 시군만) | R&R 에 이미 있으나 **서버 · 화면 모두 없다** — 구현이 빠져 있음. 6차 답에서 "부서는 누가 만드나"를 다시 물음 | 제안: 기관 관리자 권한 묶음(부서는 기관 안 조직이라 기관이 가장 잘 앎) · LX 관리자는 보고 도움(원칙 72). **부서장 역할은 두지 않는다**(원칙 38 — 자유도를 늘리지 않음) |
| **기관의 데이터 책임** | 기관이 올린 영상 · 대장 지우기 · 기관 영상의 LX 학습 동의 · 해지 때 내려받기 | 주인이 없었다 | 기관 관리자 |
| **프로젝트 몫 책임** | 프로젝트 저장 몫 안에서 쓰기 · 넘으면 요청 · 프로젝트 보관 때 학습용 조각 정리 | 주인이 없었다(LX 무제한) | 프로젝트장(요청) → LX 관리자(승인) |
| **영상 공유를 누가** | LX 영상을 어느 기관에 열까 | 확정(역할-4): LX 관리자가 기관마다 | LX 관리자. 프로젝트장은 '이 기관에 공유하면 좋겠다' 추천만(제안) |

→ **결론**: 새로 만들 사람 역할 0. 새로 붙일 책임 셋 — ① 보관소 · 장비 = LX 관리자(두 사람 결재) ② 기관 데이터 = 기관 관리자 ③ 프로젝트 몫 = 프로젝트장. 그리고 **화면 밖 장비 담당(사람)**을 문서에 적는다.

## 3. 겹치는 곳 — 정리
| 겹침 | 정리 |
|---|---|
| 해외 기관 ↔ 기관 관리자 · 부서 사용자 | 합친다(1절) |
| 서버의 '기관 담당자' ↔ R&R 의 '기관 관리자' | 이름 · 권한을 R&R 에 맞춘다 |
| LX 관리자의 결재 ↔ 인프라 · 보관소 운영 | 같은 사람이 해도 되지만 **요청과 승인은 다른 사람**(지금 한도 변경 규칙을 장비 · 보관소 · 기관 지우기에 그대로) |
| 프로젝트장의 재학습 시작(역할-3) ↔ 관리자의 GPU 예약 | 재학습 시작은 프로젝트장, 드론 전역 분석의 시간대 예약은 관리자 — 둘 다 같은 대기열 · 같은 전력 규칙 |
| 프로젝트장의 영상 소유 ↔ 관리자의 영상 공유 | 영상은 LX 보관소 것(프로젝트 것 아님). 공유는 관리자, 프로젝트장은 추천만 |
| 기관 관리자의 한도 조정 요청 ↔ LX 관리자의 한도 결재 | 요청은 기관, 결정은 LX(지금 그대로) |

## 5. 확인 못 한 것
- LX 관리자 실제 인원(두 사람 결재가 늘 돌 만큼인지). 한 사람뿐인 시기에는 결재가 멈춘다 — 그때의 대리 규칙이 필요하다.
- 광역 기관에서 시군 파견 부서의 관할(제안 S-11)을 이번 기관 만들기 시트에 넣을지 — 부서는 기관 관리자 몫이라 여기서는 넣지 않았다.
- 부서 사용자 · 열람자 계정이 서버에 없어 실제로 눌러 보지 못했다(5차 R&R 과 같은 한계).
