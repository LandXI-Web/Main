# 기관 만들기 — 어디까지 정하고, 무엇이 저절로 붙고, 무엇이 사람 손인가 (2026-10-01)

> 사용자(10-01, 확인 요청 5차 답)
> - 역할-1: "단순 표로 고정하는 형태인지? 기능이 없는 건지. 한 예로 기관 만들기는 어디까지? 도메인 생성까지? 도메인 생성되면 다 붙는 기능인지? 등등 복잡도가 높은데 이런 것까지 고민하는 건지..?"
> - 체계-5: "기관 만들기에 기능과 서비스는 모두 LX 관리자 역할이다. 거기서 정해서 서비스 체계를 정리하는 거다."
> - 역할-4 확정: "LX 가 찍은 영상을 어느 기관에 열어 줄지 — 관리자가 기관마다 고름."
>
> 지위: **사용자 확인 전 설계.** 코드 수정 0 · GPU 실행 0. 숫자는 이 PC 실측(10-01 오전)과 서버 기록에서만 가져왔다.
> 어느 플랫폼: **둘 다** — 만드는 곳은 Land-XI(LX 관리자 화면), 만들어진 결과는 기관 분기 플랫폼.
> 종류: 기관 만들기 시트 · 영상 공유 고르기 · 끄기는 **[화면]**, 저절로 붙는 규칙 · 보관 규칙은 **[문서]**(원칙 65).
> 그림: `shots/org-1-create.png`(한 장) · `shots/org-2-address.png`(주소 세 갈래) · `shots/now-admin-tenants.png`(지금 관리자 화면 기관 칸).

## 0. 한 줄
**LX 관리자가 한 장(여덟 칸)을 채우면 로그인 · 관할 · 한도 · 사용량 계산 · 기관 모습 · 첫 기관 관리자 계정은 저절로 붙는다. 그러나 "기관을 만들면 서비스가 다 된다"는 아니다** — 서비스 결과는 영상과 AI 분석(GPU 시간)이 있어야 생기고, 결과 확인 표본 · 기관 대장 맞추기 · 기관 자체 도메인은 사람 손이다. 주소(도메인)는 문일 뿐이고, 무엇이 붙는지는 주소가 아니라 **기관 한 줄(기관 대장)**이 정한다.

## 1. 지금은 어떤가 (실측)
| 항목 | 지금 |
|---|---|
| 기관 수 | 서버에 기관 4곳(남원시 · 광주전남특별시 · 키르기스 두 기관) + LX · 영업 계량용 자리 |
| 기관 만들기 화면 | **없음.** LX 관리자 화면의 '기관' 칸은 기관별 사용량 고리와 '한도 조정'뿐(`shots/now-admin-tenants.png`) |
| 새 기관을 넣으려면 | 손으로 다섯 군데: ① 서버 기관 표에 한 줄 ② 관할(시군구)을 **설정 파일**에 적기 ③ 한도 줄 넣기 ④ 첫 계정을 스크립트로 만들기 ⑤ AI 결과 저장 칸이 기관 이름 목록으로 박혀 있어 새 기관은 공용 칸으로 들어감 |
| 한도 없는 기관 | 한도 줄이 없으면 서버는 **'한도 없음' = 무제한**으로 처리한다. 새 기관을 만들고 한도를 잊으면 GPU·저장을 제한 없이 쓴다 |
| 기관 계정 역할 | 서버가 아는 기관 역할은 '담당자 · 열람자' 둘. 기관 관리자 · 부서 · 부서 서비스 칸 없음(지금 기관 계정 9개가 모두 '담당자') |
| 기관 모습(마크 · 색 · 이름) | 저장할 곳 없음. 기관 화면은 Land-XI 모양 그대로 |
| LX 영상 공유 | 영상마다 '모든 기관에 열기 / 닫기' 둘뿐. **기관마다 고르는 칸이 없다**(역할-4 확정을 담을 자리 없음) |
| 입구 | 기관은 모두 `gov.land-xi.dev` 한 주소 → 로그인에서 기관 고르기. 기관 목록은 서버 기관 표에서 자동으로 뜬다 |

## 2. 기관 만들기 한 장 — LX 관리자가 정하는 여덟 칸 [화면 · Land-XI]
LX 관리자 대시보드 → 기관 → **새 기관**. 오른쪽 시트 한 장, 위에서 아래로. 칸마다 기본값이 먼저 채워져 있고 관리자는 확인만 하는 것이 목표다(원칙 49).

| # | 칸 | 무엇을 정하나 | 저절로 채워지는 것 · 기본값 | 관리자 입력 |
|---|---|---|---|---|
| 1 | **기관 정보** | 기관 이름 · 약칭 · 종류(시군구 / 광역 / 정부 부처 / 해외 기관) · 관할 · 언어 | 관할은 **시군구 이름을 치면 목록에서 고름**(광역은 시도 하나로 전체). 종류와 관할에서 행정단위 말(읍·면·동 / 시·군·구)·좌표계·언어(국내 한국어 · 해외 영어)가 자동 | 이름 · 종류 · 관할 |
| 2 | **입구(주소)** | 기관 사용자가 들어오는 주소 | 기본 = 지금처럼 기관 공용 주소 + 기관 고르기(할 일 0). 기관별 주소는 5절 갈림길 | 없음(기본) |
| 3 | **기관 모습** | 마크 · 플랫폼 이름 · 기관색 · 메인 소개 두 줄 · 문의처 | 틀(배치 · 메뉴 · 부품)은 잠김, 이 다섯만 바뀜. 색은 흰 바탕 대비 검사를 통과해야 저장. 소개 글은 서비스 목록에서 초안. **만들 때는 LX 관리자가 첫 값을 넣고, 그 뒤엔 기관 관리자가 직접 고친다**(LX 관리자도 고칠 수 있음 — 6차 답) | 마크 파일 · 문의처 |
| 4 | **켜는 서비스(카드)** | 공개된 서비스 카드 중 이 기관에 줄 것 | 고르면 그 기관 관할로 **'다른 지역에 적용' 요청이 자동으로 만들어진다** — 지금 LX 직원 적용 → 관리자 승인과 같은 길. 카드마다 상태: 결과 있음 / 분석 대기(영상 있음) / 영상 필요 | 카드 고르기 |
| 5 | **첫 기관 관리자** | 기관 관리자 한 사람 | **아이디 = 업무 메일 주소**(원칙 77) · 임시 비밀번호는 한 번만 보이고 첫 로그인 때 바꾸기. 그다음 사용자는 가입 신청 + 기관 관리자 승인(확정). LX 는 가입 승인에 관여하지 않지만 사용자 확인 · 잠금 · 지원은 할 수 있다(원칙 72) | 이름 · 업무 메일 |
| 6 | **한도** | 저장 · GPU 시간(월) · 분석 면적(월) · AI 도우미 사용량(월) · 동시 작업 | **종류별 기본값 틀에서 자동**(지금 초기값: 남원형 저장 500GB · GPU 월 10시간 · 광역형 300GB · 6시간 · 해외형 200GB · 5시간 — 모두 '추정 초기값'). **한도 없이는 만들 수 없게** 한다 | 고칠 때만(고치면 다른 관리자 결재 — 이미 구현) |
| 7 | **LX 영상 공유** | LX 가 보관한 영상 중 이 기관에 열어 줄 것(역할-4) | 관할과 겹치는 LX 영상이 **목록으로 자동으로 뜬다**(촬영 연도 · 종류 · 관할에 겹치는 비율). 기본은 아무것도 안 켬 — 관리자가 고른다. 공유는 **지도 이미지 보기 · 분석 의뢰에 쓰기**까지이고 원본 파일은 나가지 않는다. 복사도 없다(권한 한 줄) | 체크 |
| 8 | **끄기 · 보관** | 사용 중지 · 해지 뒤 데이터를 얼마나 두나 | 기본: 사용 중지 = 로그인만 막힘(데이터 그대로) · 해지 = 90일 내려받기 기간 뒤 기관 데이터 정리(제안 — `data-governance.md` 5절) | 필요할 때만 |

**누르면 끝나는 것(만들기 한 번)**: 기관 한 줄 · 관할 · 한도 · 기관 모습 · 첫 관리자 계정 · 공유 권한 · 적용 요청이 **한꺼번에** 만들어지고, 감사 기록 한 줄이 남는다. 기관 만들기 자체는 결재가 없다(관리자가 정한다 — 체계-5). 단 한도를 기본값보다 올리면 결재.

## 3. 저절로 붙는 것 — 기관 한 줄이 생기는 순간
| 무엇이 | 지금 | 바뀐 뒤 |
|---|---|---|
| 기관 로그인 목록에 뜸 | 자동(서버 기관 표) | 자동 |
| 관할 밖 0(검색 · 지도 · 영상 · 필지 · AI 도우미) | 관할을 **설정 파일**에 손으로 적어야 작동 | 관할이 기관 한 줄에 있어 자동 |
| 광역 기관: 광역 전체 + 시군구 고르기 | 관할이 시도면 자동 | 자동 |
| 사용량 계산(GPU · 면적 · AI 도우미 · 저장) | 자동(작업을 맡긴 기관 몫으로) | 자동 |
| 한도 판정(넘으면 새 작업을 받지 않음) | 한도 줄이 있을 때만 · 없으면 무제한 | 기본값 틀로 **항상** |
| 기관 사이 데이터 분리 | 자동(서버 규칙) | 자동 |
| AI 결과 저장 칸 | 기관 이름 목록에 없으면 공용 칸 | 기관이 생길 때 기관 칸도 생김 |
| 기관 메인 · 로그인 · 모든 기관 화면의 모습 | 없음(Land-XI 모양) | 기관 모습 한 벌이 모든 화면에 |
| 기관 검토 요청 · 의뢰 · 메시지를 받는 사람 | — | 그 서비스를 담당하는 프로젝트장 + LX 관리자도 함께 봄(6차 답 · 원칙 72) |
| 결재 흐름(한도 · 적용 · 공개) | 있음 | 그대로 |
| 기관 관리자의 사용자 관리(가입 승인) · 부서 | 없음 | 첫 관리자 계정과 함께 열림. 부서를 누가 만드나는 6차 답에서 다시 물은 것 — 제안: 기관 관리자가 만들고 LX 관리자도 봄(`roles-deep.md` 2절) |

## 4. 저절로 붙지 않는 것 — 사람 손 · GPU · 협의 (정직하게)
| 무엇 | 왜 저절로 안 되나 | 누가 · 무엇으로 |
|---|---|---|
| 서비스 결과(첫 숫자) | 결과는 그 관할의 영상 × 모델 × **AI 분석 시간(GPU)** 이 있어야 생긴다. 등록 항공 영상이 있는 64개 시군구는 적용 승인 뒤 분석 한 번으로 첫 결과(시군구 한 곳 25cm 항공 기준 수십 분 — 추정). 그 밖은 영상부터 | LX 직원(적용 요청) → LX 관리자(승인) → 대기열 |
| 드론 영상 기반 서비스 | 드론 전역 분석은 시군 한 곳 수십 시간(추정) — 지금 장비로는 예약제(체계-4, A100 뒤 다듬기) | LX 관리자가 시간대 예약 |
| 결과 확인 표본 | 정확도를 말하려면 그 지역 표본을 사람이 봐야 한다(병목 1 — 역량 조사) | LX 직원(프로젝트장) |
| 기관 대장 맞추기 | 부서 대장은 너무 다양 — 요구사항을 들어 만드는 커스텀(원칙 58 · 64) | LX 직원 · 기관 협의 |
| 드론 촬영 의뢰 | 촬영은 LX 수수료 체계(원칙 60 — 10-01 고침). 기관 영상의 AI 분석 의뢰는 무상이지만 LX 관리자 승인 · 반려를 거치고 기관 GPU 한도에서 센다 | LX 영업 · 관리자 |
| 기관 자체 도메인 | 기관 전산 담당이 기관 쪽 이름 설정을 바꿔야 한다(5절) | 기관 전산 담당 + LX 관리자 |
| 새 언어(한국어 · 영어 밖) | 화면 번역 | LX |
| 해외 기관의 행정구역 · 필지 자료 | 나라마다 자료를 구해야 한다(지금 해외는 구역 단위까지) | LX 직원 |
| 기존 시스템 연결 | 그 시스템 주체와 형식 · 계정 협의(체계 ⓑ) | LX 관리자 · 상대 기관 |
| 서비스 계약 · 첫 관리자 본인 확인 | 화면 밖 행정 | LX 영업 · 관리자 |

## 5. 기관 주소(도메인) — 실제로 따져 보기
지금 바깥 주소 셋(app · admin · gov)은 이 PC 의 **Cloudflare 터널 하나**가 받아 공개 관문으로 넘긴다. 주소 이름은 세 곳에 같이 적혀 있다: 화면의 주소 이름 표 · 서버의 허용 주소 목록 · 터널 설정(사용자 폴더). 인증서는 Cloudflare 가 자동으로 붙인다(무료 인증서는 `land-xi.dev` 와 **한 단계 아래 주소**까지만 — 예: `namwon.land-xi.dev` 는 되고 `namwon.gov.land-xi.dev` 는 유료 인증서가 필요).

| | ⓐ 지금처럼 한 주소 + 기관 고르기 | ⓑ 기관별 주소(`기관.land-xi.dev`) | ⓒ 기관 자체 주소(기관 누리집 아래 이름) |
|---|---|---|---|
| 기관 사용자가 보는 것 | `gov.land-xi.dev` → 로그인에서 기관 고르기. 기관별 메인(원칙 64)은 **주소 뒤 기관 이름**(`gov.land-xi.dev/namwon`)으로 가를 수 있음 | `namwon.land-xi.dev` → 처음부터 남원 메인 · 기관 고르기 없음 | 기관 누리집 아래 주소 → 남원 메인 |
| 한 번만 할 일 | 기관 이름 경로를 관문이 알아듣게(구현 한 번) | 사람 손 한 번: 이름 설정에 `*.land-xi.dev` 한 줄(Cloudflare 계정) · 터널 규칙 `*.land-xi.dev` 한 줄 · 관문 · 서버가 '주소 → 기관'을 기관 표에서 읽게(구현) · app/admin/gov 는 예약 이름 | ⓑ 와 같음 + 사용자 지정 주소 기능 켜기(Cloudflare — 무료 100개, 그 뒤 주소마다 소액) |
| 새 기관마다 할 일 | **0** — 기관 한 줄이 생기면 목록에 뜸 | **0** — 기관 만들기 2칸에서 주소 이름만 정함, 인증서 자동 | **사람 손**: 기관 전산 담당이 기관 이름 설정에 한 줄 추가 → Cloudflare 가 확인 뒤 인증서 자동. 공공기관 주소는 기관 보안 검토가 걸릴 수 있음(확인 못 함) |
| 주소가 바뀌면 붙는 것 | — | 기관 메인 · 로그인 모습이 주소만으로 결정. 서버 · 데이터 · 흐름은 같다 | ⓑ 와 같다 |
| 맞는 때 | 지금(기관 4곳) | 기관이 늘고 기관별 메인을 주소로 알리고 싶을 때 | 기관이 요청할 때만 |

→ **"도메인이 생기면 다 붙나"의 답**: 주소는 문이다. ⓑ 로 한 번 설정해 두면 새 기관의 주소는 저절로 생기지만, 그 주소 뒤에 붙는 것(관할 · 서비스 · 한도 · 모습)은 2절의 기관 한 줄이 정한다. ⓒ 는 기관마다 기관 쪽 손이 필요해 LX 가 자동으로 할 수 없다. → 갈림길 1(`confirm-items.json` 기관-주소).

## 6. 끄기 · 보관 · 되살리기
| 단계 | 무엇이 일어나나 | 누가 |
|---|---|---|
| 사용 중지 | 기관 사용자 로그인 · API 키 막힘. 데이터 · 결과 · 공유 권한 그대로 · 한도 계산 멈춤 | LX 관리자(사유 한 줄) |
| 다시 켜기 | 그대로 돌아옴 | LX 관리자 |
| 해지 | 기관 관리자에게 내려받기 기간(제안 90일) 안내 → 기간 뒤 기관 결과 · 기관 대장 · 기관이 올린 영상 정리. LX 가 만든 모델 · LX 영상은 LX 것이라 남음. 기관 한 줄은 이름만 남김(기록용) | LX 관리자 · 두 사람 결재(지우기는 되돌릴 수 없음) |

## 7. 만드는 순서(제안 — 확인 뒤)
1. 기관 한 줄에 관할 · 한도 · 모습 칸(설정 파일 → 서버 표) · **한도 없는 기관 금지** · 기관이 생기면 AI 결과 칸도 생김 — 화면 없이도 무제한 사용을 먼저 막는다.
2. 기관 만들기 시트(여덟 칸) + 첫 기관 관리자 계정 — 완전체 기준 '계정 · 기관(손작업 0)'.
3. LX 영상 공유 고르기(역할-4) — 기관 서랍 안 한 칸.
4. 끄기 · 해지.
5. 주소 — 갈림길 1 결과대로(ⓐ 면 경로만).
