# API 키 흐름 — 키는 서비스마다 하나, 키로 하는 일은 셋

> 2026-10-01 · 지위: **사용자 확인 전 설계**(코드 수정 0 · GPU 실행 0). 어느 플랫폼: **둘 다** — 신청은 기관 분기 화면(기관 관리자), 승인은 Land-XI(LX 관리자 결재함), 키를 쓰는 쪽은 기관의 다른 시스템.
> 사용자 원문(10-01, 확인 요청 5차 API-1): "분석 서비스마다 API 키가 발급되고 API 키는 접속 - 분석하기 - 분석결과 가져오기(기존 결과도 마찬가지)이다."
> 그림: `shots/api-key-flow.png` · 시안 `shots/new-gov-api-apply.png`(기관 관리자 신청) · `shots/new-admin-key-issue.png`(LX 관리자 승인) · `shots/new-gov-api-once.png`(키 한 번 보기)

## 0. 한 줄
**키 한 개 = 기관 하나 × 분석 서비스 하나.** 기관 관리자가 신청하고, LX 관리자가 결재함에서 승인하면, 키는 기관 관리자 화면에 **딱 한 번** 보인다. 그 키로 할 수 있는 일은 셋 — **접속 확인 · 분석 맡기기 요청 · 결과 가져오기(지난 결과 포함)**. 그 밖은 없다.

## 1. 발급 단위 — 왜 '기관 × 서비스'인가
| | 이전 설계(5차 확인 요청) | 이번(사용자 답 반영) |
|---|---|---|
| 키 단위 | 기관(또는 부서) 하나에 키 하나, 할 수 있는 일·서비스를 골라 묶음 | **기관 × 분석 서비스**마다 키 하나 |
| 할 수 있는 일 | 결과 보기 / 분석 맡기기 중 고름 | 셋 모두(접속 · 요청 · 가져오기) — 분석은 어차피 관리자 승인을 거치므로 고를 칸이 없다 |
| 발급 | LX 관리자가 기관 서랍에서 바로(결재 없음) | 기관 관리자 **신청** → LX 관리자 **결재함에서 승인** |

- 서비스가 곧 부서 업무다(원칙 38: 농정과 = 영농관리 행정서비스). 그래서 서비스별 키는 부서별 키와 거의 같고, 부서가 바뀌어도 키 규칙은 그대로다.
- 한 키로 다른 서비스 결과를 부르면 **없음**(404)으로 답한다 — 계정 범위 밖 0(원칙 39)과 같은 결.
- 키 주소에 서비스가 이미 묶여 있으므로 **요청마다 서비스를 적지 않는다.** 외부 개발자가 틀릴 자리가 하나 줄어든다.
- 공개(서비스 공개 결재를 마친) 서비스이고 그 기관에 적용된 것만 신청할 수 있다. 공개 전·적용 전 서비스는 신청 칸이 흐리게 보인다.

## 2. 누가 무엇을 하나
| 누가 | 하는 일 | 어디서 |
|---|---|---|
| **기관 관리자** | 서비스를 골라 **키 신청**(쓰는 시스템 이름 · 이용 약속 동의) · 승인되면 **키 한 번 보기·복사** · 급할 때 **폐기** · 요청·내려받기 기록 보기 | 기관 분기 화면 → 기관 관리 → 'API 연동' 칸(6차 시안의 기관 관리 화면에 칸 하나 더) |
| **LX 관리자** | 키 신청 **승인 / 반려(사유 필수)** · 분석 맡기기 요청 **승인 / 반려** · 폐기 · 한도 | Land-XI → LX 관리자 대시보드 → 왼쪽 '결재'(지금 결재함과 같은 곳·같은 모양) |
| **그 서비스 담당 프로젝트장**(LX 직원) | 키로 들어온 분석 결과의 결과 확인 · 'AI가 잘못 봤어요' 처리(원칙 63) — 승인은 하지 않는다 | LX 직원 대시보드(기존 흐름) |
| **기관의 다른 시스템**(개발자) | 키로 세 가지 | API |

- LX 관리자는 **키를 보지 않는다.** 승인만 하고, 키는 신청한 기관 관리자 화면에서 한 번 나온다(메일·메신저로 오가지 않음 → 새는 길이 줄어든다).
- 기관을 만들 때(원칙 67 — 기관 만들기는 LX 관리자) 관리자가 서비스와 함께 키를 바로 만들 수도 있다. 이때도 키는 그 기관 관리자 화면에서만 한 번 나온다(요청자 칸은 비움 — 지금 결재함 규칙과 같음).
- 기관이 일을 맡긴 사업자·개발사의 시스템도 **그 기관의 키**를 쓴다. 책임은 기관에 있다(누구에게 여나는 [README 5절](README.md) · API-2).

## 3. 키 신청 — 입력은 세 칸
| 칸 | 내용 | 왜 |
|---|---|---|
| 서비스 | 우리 기관에 적용된 공개 서비스 중 하나(고르기) | 키 단위 |
| 쓰는 시스템 이름 | 예: '남원 영농관리 시스템' · '도청 GIS' | 요청 기록·결재함에서 누가 불렀는지 사람 말로 보이게 |
| 이용 약속 동의 | 결과에 개인정보를 붙이지 않음 · 기관 밖 재배포는 기관 책임 · 요청·내려받기는 모두 기록됨 | 원칙 59(내려받기는 정책과 함께 — 동의·범위·기록) |
| (접힌 '더 보기') | 허용 주소(그 시스템 서버 주소만 받기) · 알림 받을 주소 | 선택 — 비워 두어도 된다 |

- 끝나는 날은 기본 **1년**(입력 칸 없음 — 관리자가 승인할 때 바꿀 수 있음). 끝나기 30일 전 기관 관리자 화면에 한 줄.
- 한 서비스를 두 시스템이 쓰면(예: 영농관리 시스템 + 시청 GIS) 이름이 다른 키를 하나 더 신청한다. 기본은 하나.

## 4. 키로 하는 세 가지
| # | 일 | 무엇을 받나 | 얼마나 걸리나 |
|---|---|---|---|
| 1 | **접속 확인** | 이 키가 살아 있나 · 기관 · 서비스 이름과 버전 · 관할(시군구 목록) · 이번 달 한도 남은 양(분석 시간 · 분석 넓이 · 저장 · 내보낸 양) · 키 끝나는 날 | 바로 |
| 2 | **분석 맡기기 요청** | 범위 + 영상(보내는 방법 넷 중 하나) → 요청 번호. 곧바로 돌지 않고 **LX 관리자 결재함**으로 → 승인되면 분석, 반려되면 사유. 자세한 흐름은 [request-approve.md](request-approve.md), 영상 보내는 법은 [imagery-in.md](imagery-in.md) | 승인까지 사람 시간(기본 5 업무일 안) + 분석 몇 분~몇 시간 |
| 3 | **결과 가져오기** | 이번 요청의 결과 **+ 이 서비스로 이 기관 관할에서 나온 지난 결과 전부**(시점별). '지난번 이후 바뀐 것만' 받기 가능. 형식은 [export-formats.md](export-formats.md) | 쪽 나눠 받기는 바로 · 큰 파일은 준비되면 알림 |

- 지난 결과란 — 기관 화면에서 볼 수 있는 그 서비스의 모든 시점이다(예: 남원 영농관리의 2023년 · 2025년 결과). 화면에서 볼 수 없는 것은 API 로도 없다.
- 결과는 분석이 끝나면 **'결과 확인 전'** 표시로 바로 내준다(5차 답 API-4 ⓐ). LX 가 결과 확인을 마치면 표시가 **'확인됨'**으로 바뀌고, '바뀐 것만' 받기에 다시 나온다. 사람이 지운 조각은 '지운 목록'으로 알려 준다(외부 시스템도 따라 지우게).
- 1차 결과가 바뀌면 2차 서비스도 바뀌어야 한다(원칙 68 — 예: 해양쓰레기 탐지 → 해류 모델 예측 지도). 결과마다 **시점 · 서비스 버전**이 붙고 '결과가 바뀌었어요' 알림이 가므로, 기관의 2차 모델은 알림을 받으면 다시 계산하면 된다.

## 5. 키로 못 하는 것
| 못 하는 것 | 까닭 |
|---|---|
| 다른 서비스 · 다른 기관 · 관할 밖 결과 | 계정 범위 밖 0(원칙 39). 읽기는 '없음', 분석 범위가 관할을 조금이라도 벗어나면 거절 |
| 영상 내려받기(원본 · 잘라낸 그림 · 영상 지도 조각) | 내보내는 것은 AI 분석 결과(원칙 69). 보낸 영상도 되돌려 주지 않는다 |
| 학습 · 모델 바꾸기 · 설정(임계값 등) 바꾸기 | LX 생산(프로젝트장 → 결과 확인 → 서비스 공개 → 관리자 승인)의 몫 |
| 개인정보(대장에서 온 소유자 이름 · 연락처 등) | 원칙 59 · 개인정보 자동 가림(채택) |
| 결과 판정 바꾸기 · 처분 문서 | 판정은 기관 화면에서, 문서는 보고서까지(원칙 40) |
| AI 도우미(말로 묻기) | 지금은 닫는다 — 같은 AI 서버를 쓰고 말 이해 개선이 진행 중. 열 때는 읽기 질문만, 같은 기관 한도 장부 |

## 6. 키의 일생
**쓰는 중 → 끝남(1년) / 폐기됨.** 상태 말은 공통 사전 그대로.
- **폐기**: 기관 관리자(급할 때, 한 번 확인) 또는 LX 관리자. 폐기하면 **5초 안에** 모든 요청이 거절된다. 진행 중인 분석은 그대로 끝나고 결과는 기관 화면에 남는다.
- **교체**: 유출이 의심되면 '새 키로 바꾸기' → 새 키가 한 번 보이고, 옛 키는 **7일 겹친 뒤** 저절로 폐기(시스템을 멈추지 않고 갈아 끼우게).
- **저장**: 키는 한 방향 암호로만 저장한다(다시 꺼낼 수 없음 — 잃어버리면 교체). 화면에는 끝 네 자리만.
- **기록**: 모든 요청은 누가(키 · 쓰는 시스템 이름) · 무엇을 · 언제 · 몇 건으로 남는다(열람·내려받기 기록 채택). 기관 관리자와 LX 관리자가 같은 기록을 본다.

## 8. 개발자에게 보이는 모양(요약 — 자세한 것은 3단의 안내 페이지)
- 바깥 주소 하나(주소 이름은 한 곳에서 바꿈), 화면용 내부 경로와 분리. 키는 요청 머리글에만.
- 접속 확인 1개 · 분석 요청 4개(요청 · 상태 · 취소 · 영상 올리기) · 결과 5개(결과 · 요약 · 파일 내보내기 · 파일 받기 · 지도 조각) · 알림 6종(승인 · 반려 · 분석 끝 · 분석 실패 · 결과 바뀜 · 파일 준비).
- 모르는 필드는 무시하게 안내하고, 같은 버전 안에서는 더하기만 한다. 빼거나 바꾸면 새 버전, 옛 버전은 최소 12개월 유지.
