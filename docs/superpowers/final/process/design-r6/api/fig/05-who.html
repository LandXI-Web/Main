API 는 누구에게 여나 — 선택지 셋

키를 받을 수 있는 쪽을 정합니다. 어느 쪽이든 키는 LX 관리자가 결재로 내주고, 그 기관 · 그 서비스 · 그 관할 밖은 없습니다.

추천

ⓐ 서비스를 받는 기관만 — 서비스별로

누가 계약 · 협약으로 서비스를 받는 기관(지자체 · 해외 기관). 그 기관이 일을 맡긴 사업자 · 개발사도 그 기관 키로(쓰는 시스템 이름에 업체 표시 · 책임은 기관)

예 남원시 영농관리 시스템 · 광주전남이 맡긴 해양쓰레기 수거 사업자 시스템

좋은 점

  • 계정 범위 밖 0 이 그대로 지켜짐
  • 책임이 분명(기관) · 한도 장부 하나
  • 지금 구조(기관 · 서비스 · 관할)에 바로 얹힘 — 가장 빠름

아쉬운 점

  • 계약 없는 중앙부처 · 연구기관은 못 씀 → 필요하면 기관으로 등록

추천 — 개발사는 따로 키 대신 그 기관 키 + 시험 키(읽기만 · 30일)

나중 후보

ⓑ ⓐ + 다른 공공기관에 요약만

누가 중앙부처 · 광역 · 공공 연구기관이 신청 → 관리자 승인으로 시군구 단위 요약 숫자만(모양 · 필지 없음)

예 부처가 전국 해양쓰레기 탐지 현황을 정책 통계로

좋은 점

  • LX 공공 역할 · 전국 현황에 쓰임

아쉬운 점

  • 결과 확인 전 숫자가 공식 통계처럼 쓰일 위험
  • 지자체 결과를 다른 기관이 보는 것 — 원래 기관 동의 필요
  • 관할 원칙에 예외가 생김

결과 확인 체계('확인됨')가 선 뒤, 원래 기관 동의 + 확인된 숫자만으로

열지 않음

ⓒ ⓐ + 개발사에 직접 키

누가 GIS · 시스템 개발사가 자기 이름으로 키를 받아 여러 기관 시스템을 붙임

예 한 업체가 여러 시군구 영농 시스템을 한 키로

좋은 점

  • 연동 개발이 빨라짐 · 여러 기관을 한 번에

아쉬운 점

  • 한 키가 여러 기관을 넘나듦 — 계정 범위 밖 0 이 깨짐
  • 책임이 흐려짐(기관 · 업체)
  • 개인정보 · 재배포 통제가 어려움

ⓐ 의 '기관 키 · 쓰는 시스템 이름'으로 같은 효과

누구나 쓰는 공개 API열지 않음계정 범위 밖 0 · 개인정보 · 결과 확인 전 결과 — 공개 소개 화면의 숫자로 충분합니다.

시안 그림 · 예는 지금 등록된 기관과 서비스입니다.
