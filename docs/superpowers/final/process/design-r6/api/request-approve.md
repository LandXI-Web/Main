## 0. 한 줄
외부 시스템이 분석을 요청하면 **곧바로 돌지 않는다.** 서버가 기계적으로 가를 수 있는 것(관할 · 한도 · 넓이)은 그 자리에서 거르고, 통과한 요청만 **LX 관리자 결재함에 한 줄**로 들어간다. 관리자가 근거 넷을 보고 **승인하면 대기열로, 반려하면 사유가 API 응답 · 알림 · 기관 관리자 화면으로** 돌아간다.

## 1. 흐름 — 누가 · 무엇을 · 근거
| # | 누가 | 칸 | 무엇을 | 상태(기관 · API 가 보는 말) |
|---|---|---|---|---|
| 1 | 기관 시스템 | 요청 | 범위(읍면동 이름·코드 또는 도형) + 영상(보내는 방법 넷 중 하나 — [imagery-in.md](imagery-in.md)) + 메모 한 줄(선택) + 같은 요청 막는 열쇠 | — |
| 2 | 서버(자동) | 자동 검사 | 아래 2절 일곱 가지. 하나라도 걸리면 **그 자리에서 반려 + 사유**(사람을 거치지 않음 · AI 서버 사용 0) | 반려(자동) |
| 3 | 서버 | 결재함에 한 줄 | 요청 번호를 돌려주고, 결재함에 종류 **'API 분석 요청'** 한 줄 · 담당 프로젝트장에게 알림(참고) | 승인 대기 |
| 4 | **LX 관리자** | 판단 | 결재 한 건을 열어 **근거 넷**(3절)을 보고 승인 / 반려(사유 필수) | 승인됨 / 반려 |
| 5 | 서버 | 영상 받기 | 영상을 보내는 요청이면 **승인 뒤에** 받는다(반려된 요청의 영상은 저장 0). 받은 뒤 검사: 위치 정보가 있나 · 범위가 관할 안인가 · 요청 때 적은 촬영일·범위와 같은가 | 영상 받는 중 |
| 6 | 서버 | 대기열 | 화면에서 기다리는 사람의 분석 **뒤** 순서 · Land-XI 전체에서 API 분석은 한 번에 1건 · 동시 작업 한도는 화면과 합산 | 분석 대기 |
| 7 | AI 서버 | 분석 | LX 직원이 올린 영상과 같은 길(같은 대기열 · 같은 전력 규칙 — 한 번에 한 장) | 분석 중 |
| 8 | 서버 | 결과 | 결과는 '결과 확인 전' 표시로 바로 열리고, 기관 화면에도 같은 요청 번호로 새 시점이 쌓인다(관리-생산-서비스 한 흐름) · 알림 | 분석 끝 |
| 9 | 담당 프로젝트장 | 결과 확인 | 표본을 보고 확인을 마치면 표시가 '확인됨'으로 바뀌고 '결과가 바뀌었어요' 알림 | (분석 끝) |

상태는 다섯 + 넷: **승인 대기 → 영상 받는 중 → 분석 대기 → 분석 중 → 분석 끝** · 또는 **반려(사유) · 취소 · 실패(사유) · 기한 지남.** 기관 화면과 API 가 같은 말을 쓴다(기계용 이름은 따로 한 벌).

## 2. 자동 검사 — 사람이 볼 필요 없는 것은 서버가 먼저 거른다
| # | 검사 | 걸리면 돌려주는 사유(예) | 지금 서버 |
|---|---|---|---|
| 1 | 범위가 관할 안인가 | "관할 밖 지역은 분석할 수 없습니다" | **있음** — 구현 1차 관할 확인(경계 오차 약 10m 넘게 벗어나면 거절) |
| 2 | 이 서비스가 그 지역에 적용돼 있나 | "이 지역에는 이 서비스가 아직 적용되지 않았습니다" | 적용 기록 있음 · 검사 새로 |
| 3 | 한 번 넓이 한도 | "한 번에 드론 5㎢ 까지입니다 — 범위를 나눠 요청해 주세요" | 화면 천장(150㎢) 있음 · 드론 따로 새로 |
| 4 | 이번 달 한도(분석 시간 · 분석 넓이 · 저장) | "이번 달 분석 시간 한도를 넘습니다 — 범위를 나누거나 LX 관리자에게 한도 변경을 요청하세요" | **있음** — 구현 1차 한도 넘으면 새 작업 거절 |
| 5 | 영상 | LX 영상 범위만 쓰면: 그 범위를 덮는 영상이 이 기관에 열려 있나(관리자가 기관마다 고름 — 5차 확정) · 주소로 보내면: 허용된 저장소인가, 받을 수 있나(크기·형식만 확인) · 올리면: 한 건 크기 한도 안인가 | 영상 범위 · 기관 공유 규칙 있음 · 주소 확인 새로 |
| 6 | 같은 요청 | 같은 열쇠로 다시 보내면 새로 만들지 않고 처음 요청 번호를 돌려줌 | 새로 |
| 7 | 쌓인 승인 대기 | "승인 대기가 5건입니다 — 결정된 뒤 다시 요청해 주세요"(한 기관 요청이 결재함을 덮지 않게) | 새로 |

- 예상 분석 시간은 **지금 견적 계산을 그대로** 쓴다(넓이 · 조각 수 · 모델의 지난 처리 속도). 화면 견적이 하는 '모델 미리 올리기'는 하지 않는다 — 요청만으로 AI 서버를 건드리지 않는다.
- 사유는 **사람이 읽는 한 줄 + 기계용 사유 이름** 두 벌(한국어 · 영어). 무엇을 고치면 되는지 한 마디를 붙인다.

## 3. 결재 한 건 — 지금 결재함과 같은 곳 · 같은 모양
**어디서**: LX 관리자 대시보드 → 왼쪽 '결재' → 표에 한 줄(종류 'API 분석 요청' · 대상 '남원시 · 영농관리 행정서비스' · 요청자 '남원 영농관리 시스템' · 요청일) → 오른쪽 서랍. 새 메뉴를 만들지 않는다. 서랍의 틀(요청한 곳 · 요청 사유 · 요청일 · 바뀌는 것 상자 · 사유 칸 · 반려 / 승인)은 구현 1차 결재함 그대로, **'바뀌는 것' 상자 자리에 근거 넷**이 들어간다.

![결재 한 건(시안)](shots/new-admin-api-request.png)

| 근거 | 보이는 것 | 기준(초기값 · 관리자가 바꿈) | 어디서 온 값인가 |
|---|---|---|---|
| ① 범위 | 표 아래 지도: 요청 범위 · 관할 경계 · 영상 범위를 겹쳐 보기 + 읍면동 이름 | 관할 안 · 적용 지역 안 | 자동 검사 1·2 결과(통과한 요청만 여기에 옴) |
| ② 넓이 | 4.2㎢ · 한 번 한도 5㎢(드론) | 드론 5㎢ · 항공·위성 150㎢ | 범위 도형에서 서버가 계산(국내 평면 좌표계) |
| ③ 예상 분석 시간 | 약 4–5분 · '추정' 표시 | 한 번 2시간 넘으면 빨간 글자 | 영상 해상도 × 넓이 × 이 서비스 모델의 지난 처리 속도 |
| ④ 한도 남은 양 | 이번 달 분석 시간 남음 → 승인 뒤 남음(막대) · 저장(영상을 보내는 요청만) 남음 → 승인 뒤 | 승인 뒤 0 아래로 가면 자동 검사에서 이미 걸림 · 20% 아래면 빨간 글자 | 기관 한도 표 + 사용량 장부(화면과 같은 값) |
| 참고 | 지금 대기열 앞 n건 · 이 기관 지난 API 요청(승인 · 반려 수) · 담당 프로젝트장 이름 · 요청 메모 | — | 대기열 · 결재 기록 |

- **기준을 넘는 값은 빨간 글자로 표시만 한다. 판단은 관리자**(3차 답 '표시만, 관리자 판단' · 6차 '결재 한 건 — 근거 넷'과 같은 결).
- **판단하는 사람이 직접 본다**(원칙 62): 결과가 아직 없는 요청이므로 대신 **범위와 영상을 지도에서** 본다. LX 영상 범위만 쓰는 요청은 그 영상이 바탕으로 바로 보이고, 주소로 보내는 요청은 상대 영상이 클라우드용 GeoTIFF(COG)이면 **작은 미리 보기 한 장(몇 MB)** 만 읽어 보여 준다. 올리기 · 직접 전달은 승인 뒤에 영상이 오므로 요청 때 적은 범위만 보인다.
- **누를 것은 둘**: 승인 / 반려. 반려는 사유를 적어야 보낼 수 있다(구현 1차 규칙 그대로).

## 4. 반려 사유가 돌아가는 곳
| 어디로 | 어떻게 | 누가 본다 |
|---|---|---|
| API 상태 조회 | 요청 번호로 물으면 상태 '반려' + 사유 한 줄 + 사유 종류 + 결정한 날 | 기관 시스템 |
| 알림 | 키에 알림 받을 주소가 있으면 '요청 반려' 알림(서명 · 받는 쪽이 꺼져 있으면 6번 다시 보냄) | 기관 시스템 |
| 기관 관리자 화면 | 기관 관리 → 'API 연동' → 분석 요청 목록에 '반려 · 사유' + 기관 알림 한 줄 | 기관 관리자(사람) |

- 사유 종류(기계용): 범위 · 영상 품질 · 촬영 시기 · 한도 · 중복 · 그 밖. 관리자는 글만 적고 종류는 한 번 고른다(고르지 않으면 '그 밖').
- 승인도 같은 세 곳으로 알린다('요청 승인' → 영상을 보내는 요청이면 "이제 영상을 보내 주세요" + 받을 곳).

## 5. 기한 · 취소 · 실패
- **기한**: 승인 대기로 **5 업무일** 동안 결정이 없으면 '기한 지남'으로 닫고 세 곳에 알린다. **저절로 승인하지 않는다.** LX 관리자 대시보드 할 일 칸에 '승인 대기 n건 · 가장 오래된 것 n일'.
- **취소**: 요청한 키가 승인 대기 · 영상 받는 중 · 분석 대기에서 취소할 수 있다. 분석 중이면 그 자리에서 멈추고 쓴 분석 시간만 한도에 적힌다.
- **실패**: 영상 검사 실패(위치 정보 없음 · 범위가 요청과 다름 · 관할 밖) · 분석 실패는 사유를 붙여 '실패'. 받은 영상은 바로 지운다.

## 6. 맞춰야 할 것 — 기관 화면의 '우리 영상으로 분석 의뢰'(6차 확인 대기)와
6차 확인 요청의 기관 화면 의뢰는 **"그 서비스 담당 프로젝트장이 접수 · 수수료 안내"**, 이번 API 요청은 **"LX 관리자 결재 · 한도 안 비용 없음"**(5차 확정)이다. 같은 일이 길 두 개로 규칙이 다르면 기관은 비용 없는 API 쪽으로 돌아가고, LX 는 같은 요청을 두 곳에서 본다.
- **추천**: 요청 한 건의 모양을 하나로 — 결재함 종류 **'분석 요청'** 하나에 '들어온 곳(기관 화면 / API)' 표시. 규칙도 하나 — **기관 한도 안이면 비용 없이 LX 관리자 결재**, **한도를 넘거나 새 촬영이 필요하면 수수료 의뢰**(원칙 60)로 담당 프로젝트장이 수수료·기간을 적고 관리자가 결재.
- 이 문서는 API 쪽만 설계했다. 합칠지는 6차 '우리 영상으로 분석 의뢰' 답과 함께 정한다(확인 요청 항목 2 에 한 줄로 적음).

## 7. 먼저 드리는 제안(원칙 57)
- **정기 요청** — 매달 같은 범위를 같은 방법으로 분석하는 기관(예: 도로안전 매달 점검)은 관리자가 **한 번 승인하면 12개월 동안 매달 저절로** 대기열에 들어가게. 그 달 한도를 넘으면 그 달만 멈추고 알림. 결재함이 같은 요청으로 차는 것을 막는다.
- **밤에 돌리기** — 드론 전역처럼 오래 걸리는 요청은 관리자가 승인할 때 '밤에 돌리기'를 고를 수 있게(낮 화면 작업과 부딪히지 않게). A100 이 붙으면 필요 없어질 수 있다 — 지금은 후보로만.

## 8. 코어와의 관계
| 코어 | 이 설계에서 |
|---|---|
| XI맵 전역 AI 추론 | 같은 대기열 · 같은 영상 고르기 규칙 · 화면 분석이 먼저 |
| vLLM 기반 GeoAI 서비스(AI 도우미) | API 로 열지 않음. 관리자 운영 요약이 '승인 대기 n건'을 결재 기록에서 읽을 수 있음(같은 표) |
| 필지 실태조사 | 결과가 나오면 그 서비스의 실태조사 규칙이 같은 길로 돈다 |
| LX 관리자(인프라 · 기관 · 배포) | 결재함 한 곳 · 한도 장부 한 곳 · 대기열 표에 'API' 표시 |
| 관리-생산-서비스 한 흐름 | 요청 번호 = 작업 번호로 기관 화면 · 관리자 대기열 · 사용량에 같이 보임 |
| 기관 AI 서비스 제공 체계 | API 는 제공 방식 가운데 하나 — 분기 화면과 같은 서비스 · 같은 관할 · 같은 한도 |
