## 0. 한 줄
**추천 — 크기와 있는 곳으로 고른다.** LX 가 이미 가진 영상이면 영상 없이 범위만(④), 상대가 저장소를 가지고 있으면 **주소만 알려 주고 LX 가 가져간다(①, 기본)**, 작은 영상만 조각으로 올리고(②), 수백 GB 넘는 영상은 디스크로 직접 전달한다(③). 어느 방법이든 **승인 먼저, 받기 나중** · **분석 끝 30일 뒤 지움 · 결과는 남음.**

## 1. 왜 고민인가 — 실제 크기
| 무엇 | 크기 | 출처 |
|---|---|---|
| 남원 전역 드론 정사영상(1.5cm) 한 시점 | **1.1–2.1TB** | LX 보유 자산 4시점(320GB–2.1TB) |
| 밀양 정사영상 | 457GB | LX 보유 자산 |
| 읍면 하나 일부(약 4㎢) 드론 3cm | 약 3–13GB(압축 방식에 따라) | 넓이 × 해상도 계산 |
| 이 서버의 영상 보관 디스크 **남은 공간** | 약 1.9TB(2026-10-01) | 디스크 확인 |
| 기관 저장 한도 | 남원시 500GB · 광주전남 300GB | 기관 한도 표 |

→ 드론 전역 한 시점이 **서버 남은 공간을 다 먹고, 기관 저장 한도의 네 배**다. 받는 방법보다 먼저 **얼마까지 · 얼마나 오래 두나**를 정해야 한다(원칙 66).

보내는 시간(이론값 — 실제는 더 걸림 · 이 PC 회선 속도는 재지 않음):
| 크기 | 100Mbps | 1Gbps |
|---|---|---|
| 10GB | 약 13분 | 약 1분 20초 |
| 100GB | 약 2시간 13분 | 약 13분 |
| 1TB | 약 22시간 | 약 2시간 13분 |
| 2TB | 약 44시간 | 약 4시간 30분 |

또 하나: 바깥 주소 앞단(지금 쓰는 무료 연결)은 **요청 한 번에 100MB · 100초**까지만 받는다. 그래서 바깥에서 **밀어 넣는** 방법(②)은 반드시 작은 조각으로 나눠야 하고, LX 서버가 **당겨 오는** 방법(①)은 이 앞단을 지나지 않는다.

## 2. 네 가지 비교
| | ① 주소 알려 주기 — LX 가 가져감 | ② 조각 올리기 — 이어 올리기 | ③ 디스크로 직접 전달 | ④ LX 가 가진 영상 범위만 |
|---|---|---|---|---|
| **어떻게** | 요청에 영상 주소(기한 있는 서명 주소 · 공공 클라우드 저장소)를 적으면, **승인 뒤** LX 서버가 받아 온다. 끊기면 받은 곳부터 | 승인 뒤 8–64MB 조각으로 올림. 끊기면 받은 곳부터(학습 표본 올리기와 같은 방식) | 요청에 '직접 전달' 표시 → 디스크를 LX 에 전달 → LX 직원이 영상 등록 화면에서 **그 요청에 붙여** 등록 | 영상 없이 범위 · 시점만. LX 가 그 기관에 열어 준 영상 안에서만 |
| **큰 영상(수백 GB–TB)** | 좋음 — 앞단 한도와 무관, 받을 쪽 회선만큼 | 어려움 — 수십 GB 부터 몇 시간~하루, 조각 수만 개 | **가장 확실** — TB 도 하루 안. 복사 없이 연결한 채 분석하고 돌려줄 수도 | 보낼 것 없음 |
| **보안** | 상대의 저장소 비밀번호를 받지 않고 **기한 있는 서명 주소만**. 서버가 남의 주소를 부르는 기능이라 내부망을 부르게 악용될 수 있음 → **키마다 등록한 저장소 주소만** · 내부 주소 금지 · 넘겨주기 안 따라감 | 키로만 받음 · 조각마다 크기 확인 · 끝나면 파일 지문 대조 | 사람 손 — 인수인계 기록(받은 날 · 받은 사람 · 디스크 · 파일 지문 · 돌려준 날/지운 날). 공공기관 보안 규정에는 오히려 맞을 수 있음 | 새로 오가는 영상 0 |
| **저장 공간** | 승인 뒤에만 받으므로 **반려분 0** · 원본은 상대 저장소에 그대로 → 다시 필요하면 다시 받음 | 승인 뒤에만 열리지만, 끊긴 조각이 남을 수 있음(7일 뒤 지움) | 복사하면 크다 · **연결한 채 분석하면 0** | **0** |
| **보관** | 분석 끝 30일 뒤 지움 | 같음 | 복사본은 같음 · 디스크는 돌려주거나 파기 기록 | 해당 없음(LX 영상 규칙대로) |
| **상대가 할 일** | 저장소에 올려 두고 주소 한 줄(승인 알림을 받은 뒤 보내도 됨 — 서명 주소 기한 걱정 없음) | 올리기 프로그램(가이드의 예제 그대로) | 디스크 보내기 | 범위만 |
| **LX 가 할 일** | 없음(자동) | 없음(자동) | **사람 일** — 받기 · 등록 · 돌려주기 | 없음 |
| **API 로 끝까지?** | 예 | 예 | 등록 이후만(받는 칸은 사람) | 예 |
| **지금 서버** | 없음 — 새로 | **있음(학습 표본용)** — 8MB · 이어 올리기 · 400MB 한도 → 영상용으로 넓힘 | 영상 등록 · 파일에서 촬영일·해상도·범위 자동으로 읽기 **있음** → '요청에 붙이기' 새로 | 영상 범위 · 기관 공유 규칙 · 견적 **있음** |

## 3. 추천 — 크기와 있는 곳으로 고른다
| 영상이 | 방법 | 한 건 한도(초기값) |
|---|---|---|
| LX 가 이미 가지고 그 기관에 열어 준 범위 | **④ 범위만** | 한 번 넓이 한도(항공·위성 150㎢ · 드론 5㎢) |
| 상대 저장소에 있다(공공 클라우드 · 기관 파일 서버의 https 주소) | **① 주소 알려 주기(기본)** | 100GB |
| 저장소가 없고 작다 | **② 조각 올리기** | 20GB |
| 100GB 를 넘거나, 내부망 밖으로 내보낼 수 없다 | **③ 디스크로 직접 전달** | 사람이 조율(맡긴 영상 칸이 모자라면 연결한 채 분석) |

- **만드는 순서**: 분석 맡기기를 여는 날은 **④만**(보낼 것 · 저장할 것 0 — 지금 서버로 바로 된다). 그다음 ① → ② → ③ 연결(plan.md 3단).
- 영상은 **파일에서 읽는다**(원칙 49): 위치 정보 · 좌표계 · 촬영일(파일에 있으면) · 해상도 · 범위. 상대가 요청에 적는 것은 범위와 촬영일 정도이고, 받은 뒤 서버가 파일 값과 대조해 다르면 '실패(사유)'.
- 이 서비스가 요구하는 해상도보다 거친 영상이면(예: 드론 서비스에 50cm 영상) 받은 뒤 검사에서 '실패 · 영상 해상도가 이 서비스 기준보다 거칩니다'.

## 4. 얼마나 · 얼마나 오래 두나(원칙 66 — 설정 한 곳)
| 설정 | 초기값(제안) | 까닭 |
|---|---|---|
| **맡긴 영상 칸** 전체 | 400GB | 영상 보관 디스크 남은 공간(약 1.9TB)의 약 5분의 1 — LX 영상 등록 · 결과 · 학습이 쓸 자리를 남긴다 |
| 기관당 동시에 두는 양 | 200GB — **기관 저장 한도 안에 포함**, '맡긴 영상'으로 따로 표시 | 한 기관이 칸을 다 쓰지 않게 · 한 장부(화면과 API 같은 한도) |
| 한 건 크기 | ② 20GB · ① 100GB · ③ 사람 조율 | 위 3절 |
| **보관 기간** | **분석 끝 뒤 30일 → 저절로 지움** | 결과 확인 · 'AI가 잘못 봤어요' 처리 · 다시 분석할 여유 한 달. 원본은 기관에 있다 |
| 반려 · 취소 · 실패 | 받은 것 24시간 안 지움 | 쓰지 않을 영상 |
| 끊긴 올리기 | 7일 뒤 지움 | 이어 올릴 여유 |
| 보관 연장 | 기관 관리자 요청 → LX 관리자 결재, 한 번 최대 60일(저장 한도 안) | 기관 화면에서 결과와 영상을 같이 보고 싶을 때 |
| 지운 뒤 남는 것 | 결과 · 요청 기록 · 영상 정보(촬영일 · 해상도 · 범위 · 크기 · 파일 지문) | 같은 영상을 다시 보내면 지문으로 알아봄 |

- **모든 값은 LX 관리자 화면의 설정 한 곳**에서 바꾼다. A100 · 새 저장 장치가 붙으면 코드가 아니라 설정만 바꾼다.
- 맡긴 영상은 **그 요청의 분석에만** 쓴다. LX 가 학습 등 다른 곳에 쓰려면 기관 동의 + LX 관리자 결재(따로 절차) — 기본은 쓰지 않는다. 영상의 권리는 기관에 있다.
- 지우는 일도 기록한다(무엇을 · 언제 · 왜 — 기간 끝 / 반려 / 기관 요청). 기관 관리자 화면에서 보인다.

## 5. 남는 질문(사용자 결정 또는 다음 차수)
- 기관 화면에서 **결과 옆에 자기 영상을 바탕으로** 보고 싶다는 요구가 오면 30일 보관이 짧다. 그때는 '보관 연장'으로 풀고, 길게 둘 영상은 LX 영상 등록(기관에 공유)으로 옮기는 것이 맞다.
- 공공 클라우드 저장소 종류(국내 공공 클라우드 업체 몇 곳)마다 주소 모양이 다르다. 1차는 'https 로 열리는 기한 있는 주소'만 받는다.
