# 기관 한도 — 일상어로 (2026-10-01)

> 사용자(10-01, 구현 확인 1차) — I-10 다시: "한도는 무엇인지???" · Q-1(광주전남이 한도 초과로 새 작업 거절) ⓒ 그대로 + "지금 선택지가 ABC 만 있는데 이런 건 검토도 추가한다. 분석 면적이 넓어 GPU 용량이 수용을 못한다고 이해를 하면 되나?? 이런 건 타일링/스케줄링 분석 기능으로 처리해야 되지 않나??"
>
> **같은 날 7차 답이 방향을 정했습니다** — "기관은 한도에 관심 없고, 유지관리 수수료를 주기 때문에 한도가 있으면 불만이 있을 거다. 우리 인프라를 얼마만큼 쓰고 있는지 보여 '잘 쓰고 있구나' 관점. LX 관리자는 하드 자원을 관리. GPU 한도는 아닌 것 같다. 다만 분석의 순번이나 승인 · 반려 등 정책은 있겠지." 그래서 이 문서는 **지금 구현된 한도가 무엇이었는지**를 풀어 쓰고, 바꾸는 구체안은 `redesign.md` 1절에 둡니다.
>
> 어느 플랫폼: **둘 다**(LX 관리자가 정하고, 기관 화면에서 거절이 보였음). 종류: **[문서]**. 코드 수정 0 · GPU 실행 0(광주전남 전역 계획은 GPU 없이 계획만 세워 봄). 숫자는 10월 1일 오전 서버 기록 · 코드 · 이 PC 실측에서만.

## 1. 한도는 무엇이었나 — 기관마다 정해 둔 한 달 사용 허용량(장부)
**한도 = LX 관리자가 기관마다 정해 둔 사용량 상한.** LX 서버(GPU · 저장 공간 · AI 도우미)를 여러 기관이 나눠 쓰니, 한 기관이 다 쓰지 않게 두었던 장부입니다.

| 무엇을 세나(화면 이름) | 어떻게 세나 | 언제 0 으로 | 광주전남 한도(지금 값) |
|---|---|---|---|
| **분석 면적** | 분석이 끝날 때 그 분석 범위의 넓이(㎢) | 매달 1일 0시 | 1,000㎢ |
| **GPU 사용 시간** | 분석 조각을 GPU 가 실제로 처리한 시간 | 매달 1일 0시 | 6시간 |
| **저장 공간** | 그 기관 결과 파일 + 기관 자료(대장 · 실태조사 · 탐지 결과) | 쌓임(0 이 되지 않음) | 300GB |
| **AI 도우미 사용량** | AI 도우미가 읽고 쓴 글자 양(단위 토큰) | 매달 1일 0시 | 1,800,000 |
| 동시 작업 수 | 지금 돌고 있는 분석 수 | — | 1 |
| 나라 지도 자료 호출 | 하루 몇 번 불렀나 | 매일 0시 | 하루 3,000 |
| 내려보낸 양 | (아직 세지 않음) | — | 30GB |

- **누가 정하나**: LX 관리자(관리자 화면 '기관' → '한도 조정'). 바꿀 때는 결재(요청한 관리자가 아닌 다른 관리자 — `approvals.md`).
- **값은 어디서 왔나**: 9월 서버를 만들 때 넣은 **'추정 기반 초기값'**이고, 사용자 확인을 받은 적이 없습니다(9월 26일부터 미결 장부 '쿼터 초기값 · 2인 승인 정책'). 예를 들어 광주전남 전역을 한 번 분석하면 8,418㎢ 라 한 달 면적 한도(1,000㎢)의 8배입니다 — 실제 서비스와 맞지 않는 값이었습니다.
- **칸 셋의 뜻**: '소프트'(화면 이름 '임박 기준') = 넘으면 관리자 화면 카드에 '임박' · '하드' = 한도 · '정책' = 알림 / 우선순위 낮춤 / 거절.

### 넘으면 지금 무엇이 되나(코드 그대로)
| 상황 | 지금 동작 |
|---|---|
| 하드 한도에 이미 닿은 기관이 **새 AI 분석**을 내면 | GPU 시간 · 분석 면적 · 저장 공간 중 하나라도 닿았으면 **견적 단계에서 거절** — "이번 달 분석 면적 한도를 넘어 새 분석을 시작할 수 없습니다. 한도 변경은 LX 관리자에게 요청하세요." GPU 는 쓰지도 않음(정책 칸과 상관없이) |
| 하드 한도에 닿은 기관이 **AI 도우미에 질문 · 보고서 초안**을 청하면 | 언어 모델을 부르지 않고 한 줄로 닫음 — "이번 달 AI 도우미 사용 한도를 넘어 새 질문을 받을 수 없습니다…" |
| 이번 분석으로 GPU 시간이 한도를 **넘게 될** 때 | 정책 '우선순위 낮춤'이면 가장 뒤 순서(3)로, '거절'이면 거절 |
| 동시 작업 수를 넘을 때 | 거절 없이 **줄에서 기다림**(앞 작업이 끝나면 시작) |
| '소프트' · 정책 '알림'에 닿을 때 | **아무에게도 알리지 않음** — 관리자 '기관' 카드의 '임박' 표시와 관리자 대시보드 할 일 '한도 임박' 한 줄뿐 |
| LX(직원 · 관리자) | 한도가 없어 막지 않음 |

## 2. 한도와 GPU 용량은 다르다
사용자 질문 "분석 면적이 넓어 GPU 용량이 수용을 못한다고 이해하면 되나?" — **아닙니다.**

| | 한도(장부) | 한 번 작업 크기 천장 | GPU 용량(대기열) |
|---|---|---|---|
| 무엇 | 기관별 **한 달 허용량** | 작업 **한 건**의 최대 크기 | 서버가 **얼마나 빨리** 처리하나 |
| 넘으면 | 새 작업을 문 앞에서 **거절**(지금) | 해상도를 한 단계 낮추거나 "범위를 나눠 주세요" | 줄에서 **기다림** — 거절 없음 |
| 광주전남 9월 거절의 원인인가 | **예** | 아니오 | 아니오 |

넓은 범위는 **이미 조각(타일)으로 나눠 대기열에서 차례로 돕니다**(작업자 코드로 확인):

- **조각 크기** — 모델에 들어가는 한 장이 1024×1024 화소입니다. 25cm 영상이면 **약 256m 네모**, 이웃과 32m 겹칩니다(경계에서 물체가 잘리지 않게). 9월 시군구 전역 분석 기록으로 **1㎢에 약 21조각**(섬이 많은 여수는 31).
- **한 작업의 천장** — 시군구 하나가 한 작업이고 조각 2만 개까지입니다. 넘으면 해상도를 한 단계 낮춰 다시 계획합니다(광주전남에서는 해남군만 0.75 배). 화면에서 바로 보는 읍면동 · 그린 범위 분석은 한 번에 150㎢까지입니다.
- **순서** — 화면에서 보고 있는 곳과 가까운 읍면동부터, 읍면동 안에서도 가까운 조각부터 내보냅니다(지도가 보는 곳부터 차오름). 대기열은 ① 읍면동 · 그린 범위 같은 짧은 분석 ② 시군구 전역 · 다시 분석 ③ GPU 몫을 넘긴 기관 순이고, 같은 순서 안에서는 새 작업의 첫 16조각을 먼저 끼워 넣은 뒤 적게 받은 기관 · 적게 받은 작업 · 먼저 온 것 순입니다. 한 번에 32조각씩 얕게 채워(대기 24조각 아래) 큰 작업이 돌고 있어도 새 작업이 몇 초 안에 시작합니다.
- **전력 규칙** — GPU 두 장이 **동시에 무거운 일을 하지 않습니다**(9월 26일 전력 부족 셧다운 뒤 규칙). 분석 작업자는 '전력 칸'을 잡아야 조각을 가져가고(칸은 1개), 장당 전력 상한은 200W 입니다. AI 도우미 쪽 GPU 가 100W 를 넘으면 분석은 새 묶음을 읽지 않고, 읽은 묶음도 8조각마다 멈춰 기다렸다가 20초 조용하면 이어 갑니다.
- **속도(9월 기록)** — 끝까지 돈 시군구 전역 분석 21건: 1초에 가운데값 **약 7.6조각**(느린 쪽 4.0 · 빠른 쪽 9.7). 예: 강진군 전역 10,242조각 약 30분.

그러니 "넓어서 GPU 가 못 받는다"가 아니라 **"기관 장부에 적힌 허용량을 넘었다"**였습니다. 넓으면 오래 걸릴 뿐입니다.

## 3. 광주전남이 넘은 이유 — 9월 실제 기록
9월 30일 관리자 화면: 분석 면적 **10,850 / 1,000㎢**, AI 도우미 **1,977,210 / 1,800,000** → 새 분석 · 새 질문 거절. GPU 시간 2.5 / 6시간 · 저장 5.5 / 300GB 는 여유.

**분석 면적 10,849.6㎢ 를 작업 하나하나 따라가 보면:**

| 몫 | 넓이 | 무엇 |
|---|---|---|
| 광주전남 땅을 실제로 분석한 넓이 | **1,176㎢** | LX 가 영농관리 행정서비스를 적용하며 돌린 시군구 전역 분석 — 여수(두 번) · 강진 · 구례 · 목포 |
| 같은 분석을 '바깥 테두리'로 잰 몫 | **7,172㎢** | 넓이를 실제 분석한 땅이 아니라 범위를 감싸는 가장 바깥 테두리로 재어, 섬 사이 바다 · 이웃 땅까지 들어감. 여수 한 번이 3,617㎢ 로 적힘(실제 146㎢) — **고장** |
| 남원(전북) 분석 | **1,979㎢** | 남원 영상의 범위가 광주전남 구례군 서비스 범위에 닿아 광주전남 몫으로 잡힘 — **고장** |
| 하동(경남) 분석 | **522㎢** | 같은 까닭 — **고장** |

- **광주전남 계정이 낸 AI 분석은 0건.** 장부의 분석 54건은 모두 LX 직원 · 관리자가 돌린 것입니다. 기관 몫을 정하는 규칙이 "LX 가 돌린 분석은 그 범위와 겹치는 기관 서비스 범위 가운데 **가장 좁은 곳**의 기관 몫"이라, 남원 · 하동 영상이 이웃 구례군 범위(남원시 범위보다 좁음)에 걸려 광주전남으로 갔습니다.
- **GPU 시간 2.5시간 중 약 4분의 3(1.9시간)도 남원 · 하동 몫**입니다. 광주전남 땅에 쓴 것은 38분.
- **저장 5.5GB 중 약 2.7GB 도 남원 · 하동 분석 결과**입니다.
- **AI 도우미 1,977,210** 은 9월 27–30일 **광주전남 담당자 시험 계정**으로 한 질문 769건입니다. 시범 기간이라 기관 계정은 사용자와 점검용뿐이므로, 실제 기관 직원의 사용이 아닙니다.
- **10월 1일 0시에 한 달 장부가 새로 시작돼 지금 광주전남은 0** 이고 거절도 없습니다(아래 10월 1일 화면). 그러나 LX 가 광주전남 전역을 한 번만 돌려도 다시 막히는 구조였습니다.

## 4. 고칠 고장 둘 — 방향과 상관없이
사용 현황으로 바꾸더라도 숫자는 맞아야 하므로, 아래 둘은 어느 선택이든 고칩니다(확인이 필요 없는 고장으로 다음 구현 차수에).
1. **다른 지역 분석이 이웃 기관 몫으로 적힘** — 시군구 전역 분석은 그 시군구를 관할하는 기관으로, 영상 전체 분석은 그 영상의 시군구 기관으로 적는다. 겹치는 범위로 짐작하는 규칙은 범위를 직접 그린 분석에만.
2. **넓이를 바깥 테두리로 잼** — 실제로 분석한 땅(시군구 읍면동 ∩ 영상)의 넓이로 적는다. 이 값은 서버가 견적 때 이미 계산해 두고 있다(같은 숫자를 확인 카드 · 진행판에서 씀).
- 덧붙여 **학습 GPU 시간이 사용 기록에 남지 않습니다**(9월 학습 7건 · 기록 0). 직원 단위 자원 관리(`redesign.md`)를 하려면 학습 시간도 적어야 합니다.
