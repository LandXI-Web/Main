# 다시 설계 — 기관 한도를 없애고, 사용 현황 · 순번 · 직원 할당으로 (2026-10-01)

> **7차 답(10-01)이 방향을 정했다 — 이 문서는 그 구체안이다.**
> 기관-1: "켜는 서비스? 한도? 이해가 안 되네... 한도는 아마 물리적인 하드웨어일 것 같은데. 쟤들(기관)은 한도에 관심 없고, 유지관리 수수료를 주기 때문에 한도가 있으면 불만이 있을 거다. 우리 인프라를 얼마만큼 사용하고 있는지를 이해해서 '아 잘 사용하고 있고 뽕뽑고 있구나' 관점이고, LX 관리자는 하드 자원을 관리하는 거지. GPU 한도는 아닌 것 같다. 다만 분석의 순번이나 승인/반려 등 정책은 있겠지."
> 데이터-1: "LX 관리자가 기본적으로 인프라를 통제하고, 개인(LX 직원)에게 자원 할당-요청-승인 개념이어야 한다. 직원이 프로젝트를 개설하더라도 개인의 허용된 정책에 한하여 가능하다."
> 그 앞의 구현 확인 1차 Q-1: "ⓒ 그대로" + "분석 면적이 넓어 GPU 용량이 수용을 못한다고 이해를 하면 되나?? 이런 건 타일링/스케줄링 분석 기능으로 처리해야 되지 않나??"
>
> 어느 플랫폼: **둘 다**(기관은 사용 현황만 보고, LX 관리자 · LX 직원 화면이 바뀜). 종류: **[화면]** + 규칙은 **[문서]**. 지위: 사용자 확인 전 설계 — 코드 수정 0 · GPU 실행 0. 숫자는 10월 1일 서버 기록 · 코드 · 이 PC 실측과 서버 계획 함수(GPU 없이)에서만.

## 1. 구체안 — 무엇을 없애고, 무엇을 남기고, 무엇을 새로 만드나

### 1-1. 세 주체가 이렇게 바뀐다
| 누구 | 지금 | 바뀐 뒤 |
|---|---|---|
| **기관**(기관 분기) | 한 달 한도에 닿으면 새 분석 · 새 AI 도우미 질문이 거절됨(9월 광주전남) | **막는 한도 없음.** '우리 기관 이용 현황'만 본다 — LX 인프라를 얼마나 잘 쓰고 있나. 큰 의뢰는 승인 뒤 순번대로(밤에 돌면 '예상 끝' 시각) |
| **LX 관리자**(Land-XI) | 기관마다 한도 일곱 칸을 정하고, 바꿀 때마다 '한도 변경' 결재 | **장비를 관리하고 차례를 정한다** — 장비 · 저장소 여유 · 전력 규칙 · 대기열, 순번 규칙, 승인 / 반려(기관 의뢰 · API 요청 · 직원 자원 요청), 기관 사용 현황 확인 |
| **LX 직원**(개인) | 제한 없음(LX 는 한도 없음). 학습 시간은 사용 기록에도 안 남음 | **개인에게 허용된 몫 안에서 자유롭게.** 프로젝트는 지금처럼 바로 만들되 쓰는 자원은 그 사람 몫에서. 넘으면 '자원 요청' → LX 관리자 승인 / 반려 |

- AI 도우미는 '토큰' 대신 **질문 수**로 보인다 — 기관이 알아듣는 말. 토큰은 개발자 서랍에만.

**(나) 분석 순번 규칙 — 거절하지 않고 차례를 정한다**

![분석 순번 규칙](shots/rq-queue-rules.png)

| 순번 | 무엇 | 언제 돌까 | 지금 |
|---|---|---|---|
| ① | **지금 화면에서 기다리는 분석** — 읍면동 · 그린 범위(한 번 150㎢까지) | 누가 냈든 가장 먼저 · 첫 결과 몇 초 안 | 있음(순서 0) |
| ② | **승인된 분석** — 기관 분석 의뢰 · API 분석 요청 · 다른 지역 적용 뒤 첫 분석 | 승인된 순서대로 | 새로(지금은 ③과 같은 칸) |
| ③ | **시군구 전역 · 다시 분석**(예상 2시간 이하) | 낮에도 돌되 ① · ② 사이사이 | 있음(순서 1) |
| ④ | **큰 분석**(예상 2시간 넘음) | **밤 예약** — 밤 10시–아침 7시에 몰아서. 요청한 사람에게 '예약됨 · 예상 끝 시각' | 새로 |

- 같은 칸 안: 새 작업의 첫 16조각을 먼저 끼워 넣고 → 적게 받은 기관 → 적게 받은 작업 → 먼저 온 것(지금 있음).
- 기관마다 한 번에 도는 분석 1–2건, 나머지는 줄(지금 있음). 학습은 한 번에 1건, GPU 두 장 동시 고부하 금지(지금 있음).
- AI 도우미: 기관마다 동시에 두 질문까지, 그 이상은 잠깐 기다림 — 거절 없음(새로).
- '2시간'과 '밤 10시–아침 7시'는 제안 기본값. 규칙 값을 바꾸면 다른 관리자 결재.
- 요청한 사람 화면: "순서 n번째 · 예상 시작 · 예상 끝" — 밤이면 "오늘 밤 10시에 시작해 내일 아침 n시쯤 끝날 예정입니다".

**(다) 승인 · 반려 정책** — 결재함 한 곳, 같은 모양
- 기관 분석 의뢰(무상 · 확인됨) · API 분석 요청(설계 중) · 직원 자원 요청(새로) 세 가지가 LX 관리자 결재함으로 온다.
- 결재 한 건에 **예상 시간과 '지금 / 밤'**이 함께 보인다(지금까지 쓰려던 '한도 남은 양' 자리). 관리자는 승인할 때 "오늘 밤에"를 고를 수 있다.

**(라) LX 직원 개인 몫 · 자원 요청 · 승인**

![직원 몫과 장비 관리](shots/rq-staff-allot.png)

| 몫(사람마다) | 제안 기본값 | 근거 |
|---|---|---|
| 저장 | **300GB** | 학습 표본 한 벌 + 결과가 들어가는 크기(설계 6차 '프로젝트 저장 몫' 제안 값을 개인 단위로). 원본 영상은 LX 보관소에 두므로 몫에 넣지 않음 |
| AI 분석 시간 | **한 달 10시간** | 광주전남 전역 한 번이 약 3.1시간 · 9월에 가장 많이 쓴 계정(시험 계정)이 3.8시간 |
| 학습 시간 | **처음엔 기록만** | 지금 학습 시간이 사용 기록에 남지 않음(9월 학습 7건 · 기록 0). 두세 달 기록 뒤 몫을 정함 |
| 큰 분석 | 예상 2시간이 넘으면 몫 안이어도 **밤 예약**으로 저절로 | 낮 시간 화면 분석을 막지 않게 |

- **세는 법**: 쓴 사람(누르거나 올린 사람)의 몫. 프로젝트를 만들 때 승인은 없고(확정), 그 프로젝트에서 쓴 자원은 쓴 사람 몫에서 센다.
- **넘을 때**: 거절이 아니라 화면이 "몫을 넘습니다 — 자원 요청"을 먼저 띄운다. 직원은 무엇을 · 얼마나 · 왜 · 언제까지 한 줄(프로젝트는 저절로) → LX 관리자 결재함 '자원 요청' → 그 직원의 이번 달 사용 · 대기열 · 저장소 여유를 보고 **승인(이번 한 번만 / 몫 늘리기)** 또는 **반려(사유)** → 결과가 직원 화면에.
- 관리자가 자기 몫을 요청하면 다른 관리자가 결재(결재 규칙 그대로).
- LX 관리자 '인프라'에 **직원별 할당 표**: 사람 · 이번 달 분석 시간 / 몫 · 저장 / 몫 · 요청 대기 · 기본값 바꾸기(다른 관리자 결재).

**(마) LX 관리자 — 장비 관리 한 곳**
- 장비: GPU 2장(동시 고부하 1장 · 장당 200W · AI 도우미 쪽 100W 넘으면 분석 대기) — A100 이 오면 줄을 더한다(설계 6차 '장비 · 저장 설정 한 판'과 같은 자리).
- 저장소: 10월 1일 남은 공간 E: 1,996GB · D: 390GB. E: 가 200GB 아래면 경보(지금 있음), 두는 기간이 된 것은 정리 목록(설계 6차 데이터 보관 규칙).
- 대기열: 기다리는 분석 · 오늘 밤 예약 목록 · 예상 끝 시각 · 순번 규칙 네 칸.
- **디스크가 실제로 차는 것만은 막아야 한다** — 기관별 벽이 아니라 장비 경보(80% · 90%)와 정리 목록, 1TB 넘는 원본 올리기 승인으로 막는다.

## 2. 큰 분석은 조각 · 예약으로 — 광주전남 전역의 실제 숫자

## 3. 앞서 검토한 선택지와의 관계
7차 답은 Q-1 을 다시 검토하며 세운 네 갈래(ⓐ 알림만 · ⓑ 면적 한도 없애고 밤 예약 · ⓒ LX 가 돌린 것 따로 · ⓓ 지금대로)보다 한 걸음 더 갔다 — **기관 쪽에는 알림선조차 두지 않는다.**

| 앞의 갈래 | 이번 구체안에서 |
|---|---|
| ⓐ 한도는 알림만 | 더 나아감 — 기관에는 한도도 알림도 없고 사용 현황만 |
| ⓑ 면적 한도 없애고 GPU 시간은 밤 예약 | **밤 예약은 순번 ④로 들어감.** 면적은 사용 현황의 한 줄(실제 분석한 땅) |
| ⓒ LX 가 돌린 분석은 기관 몫에서 빼기 | **사용 현황의 두 칸**으로 남음 — 빼서 버리지 않고 'LX 가 기관 서비스로 돌린 것'으로 보여 줌(잘 쓰고 있다는 근거) |
| ⓓ 지금대로 | 버림 |

| 이번 구체안 | 판단 |
|---|---|
| 자원 보호 | 기관별 벽 대신 **장비 관리(저장소 경보 · 1TB 원본 승인) + 순번(큰 것은 밤) + 직원 몫**. 실제로 차는 것(디스크)만 막고, GPU 는 줄로 지킨다 |
| 공정성(한 기관이 다 쓰지 않게) | 대기열이 기관별로 번갈아 주고, 기관마다 한 번에 1–2건, 큰 것은 밤 — 한 기관이 낮 시간을 차지하지 못함 |
| 관리 부담 | 기관 한도 값 · 한도 결재가 사라짐. 새로 생기는 것은 직원 자원 요청 결재 · 순번 규칙 값 · 장비 경보 — 모두 LX 안의 일 |
| 기관이 느끼는 것 | 거절 문구가 사라지고 "언제 끝나는지"와 "얼마나 쓰고 있는지"만 보임(유지관리 수수료를 내는 기관의 불만 요인 제거) |

## 4. 만드는 순서(확인되면)
1. **숫자부터** — 고장 둘(다른 지역이 이웃 기관 몫으로 · 바깥 테두리 넓이) 고침 · 학습 GPU 시간 기록 · 사용량 두 칸('기관이 요청한 것' / 'LX 가 기관 서비스로 돌린 것').
2. **거절 없애기 + 사용 현황** — 1-2 의 1–7 을 없애고, 관리자 '기관 사용 현황'과 기관 '우리 기관 이용 현황'을 같은 값으로.
3. **순번** — ②칸 · 밤 예약 · '예상 끝' 안내 · AI 도우미 동시 두 질문.
4. **직원 몫** — 개인 몫 · '자원 요청' 결재 · 직원별 할당 표(구현 2차 계정 관리 화면과 함께).
5. **장비 한 곳** — 장비 · 저장소 · 대기열을 LX 관리자 '인프라' 한 곳으로(설계 6차 장비 · 저장 설정과 같이).

## 6. 확인 못 한 것(정직)
- **실제 기관 직원의 사용이 아직 없다**(시범 기간 — 기관 계정은 사용자와 점검용). 사용 현황 항목이 기관에 와닿는지는 기관 관리자에게 보여 봐야 안다.
- **밤 예약의 실제 속도** — 밤에는 AI 도우미가 한가해 빠를 것이라는 것은 추정. 밤에 돌린 기록이 따로 없다.
- **직원 몫 기본값(300GB · 한 달 10시간)** 근거가 약하다 — 9월 기록은 시험 계정뿐. 학습 시간은 기록 자체가 0. 개인별 저장은 지금 세는 곳이 없어 실측하지 못했다.
- **'2시간' · '밤 10시–아침 7시'** 는 낮 화면 분석을 덜 막자는 제안값이다.
- '등록 대장'은 '결재할 사람 명단'으로 이해했다(`approvals.md` 5절).
- 오늘 관리자 화면 캡처(`shots/rq-now-1001-tenants.png`)는 로그인 폼으로 들어갔지만 **옛 시범 아이디**로 했다 — 메일 아이디의 비밀번호는 대화로만 전해져 서버 설정 파일에 없다.
