모델은 누구 것탐지 모델 · 학습 자료 · 재학습 — LX표준 결과 형식(위치·종류·양·시점·신뢰도·버전)해류·바람 모델은 바깥 제공자, 결합 규칙(어떻게 합쳐 예측하나)은 전남. 해류 모델 소유는 확인 필요
누가 운영하나프로젝트장(공개 전) → LX 관리자(공개 뒤 갱신·재학습 지시)카드 공개 = 1차 운영 끝, 2차 시작전남 해양수산 담당 부서 + 기관 관리자. 수행사가 있으면 그 계약 확인 필요
계산은 어디서갈림길 1탐지는 LX AI 서버(대기열)—ⓐ 전남 시스템 안(LX 는 결과·알림만) / ⓑ LX 서버의 '2차 계산 자리'(해류 자료를 받아 LX 가 계산·검증) / ⓒ 바깥 제공자가 계산, 둘은 결과만 받음
자료는 어느 쪽으로LX → 전남 한 방향(결과·알림)서비스별 키 · 폴리곤·SHP·GeoJSON · 영상 아님바깥 → 전남(해류). 전남 → LX 는 '잘못 봤어요'만
1차가 새로 갱신되면새 회차 공개 → 알림 이벤트(카드 알림 한 줄 + 키에 등록한 받는 주소로 알림)알림에는 결과 버전·기준 시점이 담김알림 받으면 결과를 다시 가져가 재계산. 자동/사람이 누르는지는 전남이 정함 · 화면에는 '다시 계산 필요' 표시가 뜸
틀리면 누구 몫탐지 위치·종류·양이 틀림 — LX(재학습·표본 확인)기준 시점·버전이 화면에 있어 어느 입력으로 계산했는지 추적됨예측(어디에 언제 쌓이나)이 틀림 — 전남 + 모델 제공자. 예측 검증(다음 촬영과 대조)은 2차 운영자가 함 · 1-ⓑ면 LX 가 검증
갱신 고리 한 줄: LX 새 촬영 회차 → 탐지 → 결과 확인 → 관리자 승인 · 공개(버전 n+1) → 알림(기관 카드 · 키 받는 주소) → 전남이 결과 가져가기 → 2차 재계산 → 예측 지도 갱신(화면에 '1차 기준 시점 n+1') → 다음 촬영 때 예측과 실제를 대조. 2차의 또 하나의 갱신 원인은 해류 예보 갱신(주기 확인 필요) — 이것은 1차와 무관하게 전남 안에서 돈다.

노란 '확인 필요'는 자료가 없어 지어내지 않은 것. 숫자는 넣지 않았다. 옛 자산 원형(광주전남 해양쓰레기 2027 화면)은 해류·바람·수심을 '밖에서 받을 것'으로, 탐지·표준·검증·전달을 LX 몫으로 적어 두었으며 해류 산출은 아직 없다고 밝혀 두었다.
