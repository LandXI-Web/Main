## 0. 한 줄
**1차 = LX 가 영상에서 보이는 것을 찾아 세고 나눈 AI 분석 결과. 2차 = 기관이 그 결과에 자기만 가진 자료·모델(해류·바람, 직불 신청 명단, 교통량)을 합쳐 만드는 업무 판단·계획.** 둘의 경계는 **표준 결과 형식 한 장**(위치·종류·양·시점·신뢰도·버전)이고, 1차가 새로 공개되면 **알림**이 2차를 다시 돌리는 신호다. 1차 정확도는 LX 몫, 2차 판단은 기관 몫이며, 2차 화면에 '입력 1차 기준 시점'이 항상 보여 둘을 가른다.

## 3. 갱신 — 1차가 새로 나오면 2차는 어떻게 알고 다시 도나
1. **이벤트는 '카드 공개'다.** LX 관리자가 새 회차를 승인·공개하는 순간 결과 버전이 n → n+1 이 되고, 서버가 알림을 만든다. 공개 전(표본 확인 중)에는 아무 알림도 나가지 않는다.
2. **알림 두 길** — ① 기관 플랫폼 알림 한 줄("해양쓰레기 탐지 새 결과 · 결과 버전 3 → 예측 지도 다시 계산 필요") ② 서비스별 키(원칙 69)에 기관 관리자가 등록한 **'새 결과 알림 받는 주소'**로 같은 내용(버전 · 기준 시점 · 가져갈 주소). 주소를 비우면 ①만.
3. **다시 도는 것은 2차 운영자가 정한다.** 도 시스템이 알림을 받아 자동으로 결과를 가져가 재계산하든, 담당자가 '다시 계산'을 누르든 전남 안의 일이다. LX 는 "새 결과가 있다"까지만 책임진다.
4. **2차의 또 하나의 갱신 원인은 해류 예보 갱신**(모델 제공자 자료 주기 — **확인 필요**). 이것은 1차와 무관하게 전남 안에서 돈다. 그래서 2차 화면에는 '1차 기준 시점'과 '해류 자료 기준 시점' 두 날짜가 따로 보여야 한다.
5. **형식이 바뀌는 갱신은 미리 알린다.** 재학습으로 종류 분류가 늘거나 열이 바뀌면 2차 입력이 어긋난다. 표준 결과 형식의 **형식 버전**을 따로 두고, 형식이 바뀌는 공개는 관리자 결재 화면에 표시(그림 3의 ③)하고 기관에 먼저 알린 뒤 공개한다.
6. **갱신 고리 한 줄**: 새 촬영 회차 → 탐지 → 결과 확인 → 관리자 승인·공개(버전 n+1) → 알림(카드 · 받는 주소) → 전남이 결과 가져가기 → 2차 재계산 → 예측 지도 갱신('1차 기준 시점 n+1') → 다음 촬영 때 예측과 실제를 대조(2차 운영자).

## 4. 책임 — 예측이 틀리면 누구 몫인가
- **1차 오류**(있는 쓰레기를 못 찾음 · 종류를 잘못 나눔 · 양이 다름) → LX. 기관은 'AI가 잘못 봤어요'로 알리고, 담당 프로젝트장의 판정이 답이 되며 'AI 오류'는 재학습 표본으로 쌓인다(기존 경로).
- **2차 오류**(어느 해안에 언제 쌓일지 예측이 다름) → 2차 운영자(전남)와 모델 제공자. 옛 자산(09-20 정의)은 검증 지표를 "예측 위치와 실제 위치의 거리 · 예보 정확도 점수 · 상륙 구간 적중"으로 적어 두었고, "이 대조 고리가 없으면 예측은 주장일 뿐"이라 했다 — 이 검증을 **누가 하나**가 갈림길 1 에 달려 있다(ⓐ 전남 · ⓑ LX).
- **가르는 열쇠 = 기준 시점·버전 표시.** 2차 화면 어디에나 '입력 1차 기준 시점 · 결과 버전 · 해류 자료 시점 · 계산 시점'이 보이면, 틀린 예측이 낡은 1차 입력 때문인지 모델 때문인지 바로 갈린다.
- 화면에 보이는 신뢰도는 1차 신뢰도(LX 결과 값)뿐이다. 2차 예측의 '믿을 만한 정도' 표시는 제안 S-5 반려("필요 없다")에 따라 넣지 않는다.

## 5. 해류 모델은 누가 가지고 있나 — 확인 필요
- **옛 자산(2026-09-20 발주자 정의)에 적힌 것**: "27년 전남 해양쓰레기는 위성영상 기반 중국 유입 괭생이모자반을 포착하면 해류모델링 기반 도착 예측 시뮬레이션 기능 구현" · "해류 수치모델은 해양 물리의 영역이고 LX 가 만들 것이 아니다 — 밖에서 받는다" · "밖에서 받는 것: 해류 수치모델 산출(격자 방향·세기 · 시간축) · 해상풍 예보 · 해저지형(수심)" · "해류 수치모델 산출은 아직 없다 — 화면의 속도장은 모의값". 즉 **2026-09 기준으로 해류 자료는 LX 손에 없고, 누가 줄지도 정해지지 않았다.**
- **확인할 것(사용자·전남에 물을 목록)**: ① 전남이 이미 쓰는 해류 예측 자료가 있는가(도 안 부서 · 수행사 · 공공 해양 예측 자료 중 어느 것) ② 그 자료의 형식·격자·갱신 주기 ③ 해상풍 예보 출처 ④ 침적 예측까지 하려는지(수심 자료 필요) ⑤ 27년 사업의 발주 형태(누가 2차를 만들고 운영하나) ⑥ 예측 검증에 쓸 후속 관측(다음 촬영)을 누가 언제 하나.
- 여기서는 후보 기관 이름을 적지 않는다 — 확인 전에 적으면 지어낸 것이 된다.

**기본값 제안 = ⓐ.** 날짜가 늦은 지시(10-01 "전남 안에서 소화")가 옛 자산(09-20)을 이기고, 계정 범위 밖 0 과 인프라 설계(데이터는 인프라와 함께 — 원칙 66)에도 부담이 없다. 다만 옛 자산의 강점(LX 가 검증 고리를 쥔다 · 카드로 다른 해안에 확대)이 사라지므로 사용자가 정한다. ⓐ 로 가더라도 LX 는 **표준 결과 형식과 알림**을 쥐고 있어 고리의 가운데에 남는다.

직불금·보수 우선순위·민원 연계·수거 계획은 옛 자산의 서비스 부품 목록에 이미 **'기관 몫(행정 가공)'**으로 적혀 있던 것이다 — 이번에 그것을 '2차'라고 이름 붙이고 경계·갱신·책임을 더했을 뿐이다.

**경계를 긋는 규칙 다섯**
1. **보이는 것까지가 1차.** 영상에서 보이는 성질(쓰레기·작물·구멍·비닐)만 1차. 소유·신청·민원·교통량처럼 안 보이는 것과 합치는 순간 2차.
2. **경계는 형식 한 장.** 1차 출구 = 2차 입구 = 표준 결과 형식. 서비스마다 열 이름은 달라도 **시점·신뢰도·버전**은 공통 — 이것이 없으면 나중에 "어느 입력으로 계산했나"가 남지 않는다.
3. **기관 자료는 기관 안에서.** 2차에 들어가는 대장·모델·기록은 LX 로 오지 않는다(계정 범위 밖 0). 예외는 갈림길 1-ⓑ 를 택했을 때만.
4. **갱신은 알림으로.** 1차 공개 = 이벤트 → 카드 알림 한 줄 + 키에 등록한 받는 주소. 2차를 자동으로 돌릴지 사람이 누를지는 기관이 정한다.
5. **책임은 기준 시점으로 가른다.** 2차 화면에 '입력 1차 기준 시점 · 버전 · 계산 시점'을 항상 표시. 1차 오류는 LX(재학습), 2차 판단은 기관.

## 8. 서비스 제공 체계(네 갈래)와의 관계
- 1차는 언제나 **분기 카드(ⓐ)** 다(LX 가 만들어 뿌린다).
- 2차는 기관이 소유하므로 기관 플랫폼에서 **'우리 시/도가 운영하는 서비스'** 묶음으로 보인다(기관에 ⓐⓑⓒⓓ 글자는 보이지 않음 — concept.md 규칙 6). 갈래로는 갈림길 1-ⓐ·ⓒ 면 **연결(ⓑ)**, 1-ⓑ 면 **맞춤(ⓒ) → 카드(ⓐ)**.
- 2차가 1차 결과를 가져가는 길은 **API(ⓓ)** 의 '결과 가져가기'와 같다 — 서비스별 키 하나, 여기에 '새 결과 알림 받는 주소' 한 칸만 더한다. 키·인증·형식·한도는 API 설계(다른 에이전트)에서 정하고, 이 문서는 자리만 적는다.
- 대장 비교 3층과의 관계: 2차에 들어가는 기관 자료(직불 신청 명단 · 농지대장 · 보수 기록)는 대부분 **③ 커스텀**(요구사항을 들어 만드는 기관 맞춤 — 4차 답 대장-2)이다. 표준 양식(위치·상태·날짜 세 칸)으로 올릴 수 있는 것만 ②.
