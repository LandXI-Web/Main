## 1. L-6 — '현장 확인' 없이 카드에 남길 숫자

### 1-1. 사용자가 처음 말한 'AI 정확도'의 뜻
"비닐하우스 n동 발견은 의미 없고, AI 정확도라든지 의미를 찾아야 된다"(3차) → "현장 확인은 필요 없다"(18차). 그러므로 **현장에서 맞음/오류를 판정한 비율(9차 ①)과 '현장 확인 n필지'(9차 ③)는 뺀다.** 남는 '믿을 만한 정도'는 **학습 때 따로 떼어 둔 검증 표본으로 잰 정확도**뿐이다 — 서버 모델 기록에 실제로 있고(mAP50 · 학습 끝 검증), 모델 등록 요청에 '성능(학습 끝 검증)'으로 이미 같은 값이 쓰인다. 화면에는 이 값을 **"AI 정확도"** 라 부르고 작은 글로 '학습 검증 n장 기준 · 날짜'를 붙여 현장 값으로 읽히지 않게 한다.

### 2-2. 순번이 실제 대기열 · 전력 규칙과 맞물리는 법
- 서버 작업에는 이미 **우선순위 0~3**(숫자 작을수록 먼저 · 관리자가 바꾸는 길 있음)과 **순번 계산**(같은 줄에서 내 앞에 선 작업 수)이 있다. 작업자는 우선순위 → 아직 시작 안 한 것 먼저 → 기관 공평 → 들어온 순으로 고른다.
- **전력 규칙(동시 고부하 한 장)** 때문에 분석은 **한 번에 한 건**씩 돈다. 화면의 '동시에 도는 분석 0 / 1건'이 그 규칙이고, 순번은 "그 한 줄에 선 차례"다 — 2번은 1번이 끝난 뒤 시작. 띠 아래 한 줄로 이것만 말한다(장비 이름 · W · 임대 같은 말 0).
- **예상 시작**: 1번은 '승인하면 바로'(지금 분석 중인 건 없음 — 서버 값) · 2번부터는 '1번 끝난 뒤'. 앞 작업의 **걸리는 시간 실측**(모델 속도)이 있으면 '약 n분 뒤 · 시:분'으로 — 이번 요청(순천 1.9cm 드론 · 2cm 모델)은 실측이 없어 '첫 분석 뒤 보입니다'(지어내지 않음).
- **급함** = 우선순위 0 으로 맨 앞(사유 필수 · 기록). **▲▼** = 같은 우선순위 안에서 순서 바꾸기(서버에 '들어온 순' 대신 '관리자가 정한 순' 칸 하나). **보류** = 새 상태(지금 서버 상태는 확인 대기 · 분석 준비 · 분석 중 · 결과 도착 · 반려 · 실패뿐) — 보류 사유가 기관 '내 요청'에 보인다. **담당** = 요청의 담당 직원(지금은 서비스 담당 프로젝트장이 자동 · 없으면 비어 있음 → 관리자가 고르는 길 추가).
- 승인 뒤의 작업도 같은 목록에 남아(상태 '분석 준비' · '분석 중') 순번 · 급함을 계속 바꿀 수 있다. 끝난 것은 '처리 기록'.
