# 외부 연동 API — 쓰는 사람과 시나리오

> 2026-09-30 · 지위: **사용자 확인 전 설계**(코드 수정 0 · GPU 실행 0). 어느 플랫폼: **둘 다**(키·한도는 Land-XI LX 관리자 화면 · 쓰는 쪽은 기관의 다른 시스템).
> 요청·응답 모양은 [표준 가이드 초안](guide-draft.md), 되는 것·안 되는 것은 [제공 범위](scope.md).

## 0. 누가 쓰나
| 쓰는 쪽 | 예 | 주로 하는 일 | 키 주인 |
|---|---|---|---|
| 기관이 이미 쓰는 업무 시스템 | 남원 도로안전 관리 화면 · 남원 영농관리 서비스 · 전남 해양쓰레기 관리 | 결과를 주기적으로 가져가 자기 화면·장부에 싣기 | 그 기관(부서) |
| 기관이 맡긴 사업자의 시스템 | 해양쓰레기 수거 사업자 · 드론 촬영 사업자 | 찍은 영상을 맡기고 탐지 결과 받기 | 맡긴 기관(책임도 기관) |
| 기관의 GIS | 시청·도청 GIS · 행정 포털 | 결과 지도 조각을 자기 지도 위에 띄우기 · 보고서 붙이기 | 그 기관 |
| 해외 기관 시스템 | 키르기스스탄 농업부 · 토지자원청 | 구역별 요약을 영어로 가져가기 | 그 해외 기관 |

**지금 되는 정도(2026-09-30 서버 기준)** — 운영 중인 서비스는 남원시 '영농관리 행정서비스'(AI 탐지 2,098건 · 2025년 드론영상) · 광주전남 여수시 '해양쓰레기 실태조사 서비스'(1,857건 · 2023년 항공영상), 시범은 남원시 '국토 변화 탐지 서비스'(456건). **'도로 안전관리 서비스'는 카드와 남원 배포본(시범 단계)만 등록돼 있고 실제 결과는 아직 없다** — 학습 자료만 있고, 운영 중인 도로안전 화면은 기존 남원 GeoVision 쪽이다. 아래 시나리오 1 은 이 서비스에 결과가 공개된 뒤의 모습이다. 해외는 키르기스 농업부에 '농지 이용 실태 분석(해외)'이 시범 단계로 있다.

## 시나리오 1 — 남원시 도로안전 시스템이 매달 포트홀 결과를 가져간다
- **누가**: 남원시 도로 담당 부서의 도로안전 관리 시스템(목록: 상태 · 종류 · 도로 주소 · 대표 지번 · 발견일 · 회차).
- **키**: 남원시 · 도로 부서 · 서비스 = 도로 안전관리 서비스(`card-road`) · 할 수 있는 일 = 결과 보기 · 알림 받을 주소 있음.
- **흐름**
  1. (처음 한 번) `GET /v1/services` → `card-road` · 분류(포트홀 · 차선 도색 불량 · 시설물 불량) 확인.
  2. 새 결과가 공개되면 Land-XI 가 `results.updated` 알림을 보낸다(촬영 → AI 분석 → LX 결과 확인 → 공개).
  3. 시스템이 `GET /v1/services/card-road/results?region=52190&since=<지난번 받은 날>` 을 끝 쪽까지 받는다(알림이 없는 1단에서는 매달 정해진 날에 이것만 해도 된다).
  4. 결과 id 로 자기 목록에 넣거나 고친다(같은 id = 같은 파손). 도로 주소·대표 지번·발견일(촬영일)·회차가 속성에 있다.
  5. 현장에서 "포트홀 아님"이면 `POST /v1/feedback` 메모 한 줄(선택).
- **왜 좋은가**: 담당자가 두 화면을 오가며 옮겨 적지 않는다. 회차가 바뀌어도 '바뀐 것만' 온다.
- **조건**: 도로 안전관리 서비스에 남원 결과가 공개돼야 한다. 도로 보수 기록과 맞추는 일(보수한 곳에 다시 생긴 파손)은 기관 시스템 쪽 몫 — 대장 테마 조사의 '가까운 점 + 날짜' 방식.

## 시나리오 2 — 영농관리 시스템이 필지별 결과를 조회한다
- **누가**: 남원시 농정과가 쓰는 영농관리 서비스(사료작물·농지 활용·비닐하우스 분석).
- **키**: 남원시 · 농정과 · 서비스 = 영농관리 행정서비스 · 결과 보기.
- **흐름**
  1. 담당자가 자기 시스템에서 필지를 누르면 → `GET /v1/parcels/{필지 번호}?service=card-farm` → AI 가 본 것(경작 흔적·시설·건물)과 확인이 필요한 까닭 한 줄 · 기준 시점.
  2. 한 달에 한 번 전체 목록: `GET /v1/services/card-farm/parcels?region=52190&flag=check` → 확인이 필요한 필지만 페이지로.
  3. 읍면동 보고서가 필요하면 `GET /v1/services/card-farm/reports/{읍면동}.docx`.
- **관할 가드**: 남원 키로 구례군 필지 번호를 물으면 `404` — 필지가 있는지도 알리지 않는다.
- **지금 되는 정도**: 필지 × AI 결과 · 실태조사 결과가 서버에 있다(남원). 부서 대장(직불금 신청 작물 등)과 맞추는 결과는 대장을 올린 뒤에만.

## 시나리오 3 — 전남 해양쓰레기 사업자가 드론 영상을 맡기고 탐지 결과를 받는다
- **누가**: 광주전남이 해안 정화를 맡긴 사업자의 관리 시스템.
- **키**: 광주전남 · 서비스 = 해양쓰레기 실태조사 · 결과 보기 + 분석 맡기기 · 알림 받을 주소.
- **흐름**(그림: [분석 맡기기 흐름](shots/api-flow-analyze.png))
  1. 드론 촬영 뒤 GeoTIFF 를 8MB 조각으로 올린다(`POST /v1/uploads` → `PUT …?offset=` → `finish`). 끊기면 받은 곳부터 이어서.
  2. Land-XI 가 파일에서 촬영일·해상도·범위를 읽는다. 범위가 관할(광주전남) 밖이면 여기서 거절.
  3. `POST /v1/analyses/quote` → 넓이 · 예상 분석 시간 · 앞에 선 작업 수 · 이번 달 한도 남은 양.
  4. `POST /v1/analyses`(중복 방지 열쇠) → `202` · 작업 번호.
  5. 대기열에 선다 — 화면에서 기다리는 사람의 분석이 먼저, API 분석은 Land-XI 전체에서 한 번에 1건.
  6. 끝나면 `analysis.done` 알림 → `GET /v1/analyses/{id}/results` → 쓰레기 조각(종류 · 면적 · 신뢰도 · 촬영일) + 요약.
  7. 결과는 광주전남 기관 화면에도 같은 작업으로 뜬다(관리-생산-서비스 한 흐름 — 같은 작업 번호가 LX 관리자 화면의 대기열·사용량에도).
- **한도**: 분석 시간은 광주전남 월 한도(화면과 합산). 드론 한 번 5㎢ 까지(초기값).
- **지금 되는 정도**: 해양쓰레기 서비스는 여수 운영 중. 기관이 영상을 올리는 흐름은 확인된 방향(기관 영상 허용)이지만 아직 구현 전 — 2단에서 같은 올리기 부품을 쓴다.

## 시나리오 4 — 도청 GIS 가 결과 지도 조각을 띄운다
- **누가**: 광주전남 도청 GIS(QGIS · 웹 지도).
- **키**: 광주전남 · 서비스 = 해양쓰레기 · 할 수 있는 일 = 결과 보기(지도 조각 포함).
- **흐름**
  1. GIS 서버가 12시간마다 `GET /v1/services/card-marine/tiles.json?region=12130` → 서명된 지도 조각 주소.
  2. 그 주소를 벡터 타일 층으로 넣는다. 서명 주소에는 키가 없어 웹 지도에 넣어도 키가 새지 않는다.
  3. 조각 하나를 누르면 GIS 가 `GET /v1/services/card-marine/results?bbox=…` 로 속성을 가져온다.
- **다른 기관이라면**: 예를 들어 해양 관련 중앙 부처가 같은 지도를 원하면, 그 기관 이름으로 따로 계약·키를 받아야 한다(광주전남 키를 빌려 쓰지 않는다). 어디까지 열지는 [갈림길 1](README.md#사용자-결정이-필요한-갈림길).

## 시나리오 5 — 기관 행정 포털이 매달 실태조사 보고서를 받아 붙인다
- **누가**: 기관 내부 행정 포털(게시판·결재 시스템에 보고서 첨부).
- **흐름**: 매달 1일 `GET /v1/services/{서비스}/reports?region=<시군구>` → 읍면동 목록 → 바뀐 읍면동만 `…/reports/{읍면동}.docx` 를 받아 붙인다.
- **범위**: 보고서까지. 공문·처분 문서는 만들지 않는다(사용자 원칙). 보고서의 숫자는 화면과 같은 값.

## 시나리오 6 — 해외 기관이 구역별 요약을 영어로 가져간다
- **누가**: 키르기스스탄 농업부(으슥아타) 농업 통계 시스템.
- **키**: 키르기스 농업부 · 결과 보기 · `Accept-Language: en`.
- **흐름**: `GET /v1/regions` → 사업 구역 → `GET /v1/services/card-global-farm/summary?region=<구역>` → 구역별 농지 면적·식생 지수(위성 · 월별) 요약을 영어 라벨로.
- **범위**: 해외는 필지 체계가 없어 구역 단위까지. 사업 구역 밖은 `404`.
