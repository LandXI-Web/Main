# 외부 연동 API — 어디까지 되나(제공 범위)

> 2026-09-30 · 지위: **사용자 확인 전 설계**(코드 수정 0 · GPU 실행 0). 어느 플랫폼: **둘 다** — 키를 만들고 한도·사용량을 보는 곳은 **Land-XI(LX 관리자 화면)**, 키를 받아 쓰는 쪽은 **기관의 다른 시스템**(기관 분기 플랫폼과 같은 관할·같은 서비스).
> 사용자 원문(09-30): "우리 서비스를 API 방식으로 호출하여 결과를 가져가거나, 실제 API 형태로 분석을 던지고 주고받는 구조도 고민이 필요하다. 표준 가이드도 필요하고, 어느 범위까지 가능한 영역인지도 정해야 한다. 그리고 구현해야 하고."

![되는 것 · 맡길 수 있는 것 · 안 되는 것](shots/api-scope.png)

## 0. 한 줄
**API 는 기관 분기 플랫폼의 '기계용 창구'다.** 사람이 화면에서 보는 것과 같은 결과를, 같은 관할·같은 서비스·같은 한도 안에서 다른 시스템이 직접 받아 간다. 화면보다 넓게 열리는 것은 없다.

세 가지 원칙이 모든 줄에 걸린다.
1. **계정 범위 밖은 없다** — 키는 한 기관(또는 그 기관의 한 부서)에 묶이고, 그 관할·그 서비스 밖 결과는 서버가 아예 내주지 않는다(검색·지도 조각·보고서·필지 조회 모두).
2. **AI 분석이 먼저, 서비스 카드만** — 분석은 LX 가 만들어 공개한 서비스(모델 + 규칙 + 결과 형식)로만 맡긴다. 모델·설정을 바깥에서 고르지 않는다.
3. **한 장부** — API 로 쓴 분석 시간·면적·저장·요청은 기관 한도와 같은 장부에 쌓인다. 화면과 API 가 따로 한도를 갖지 않는다.

## 1. 세 층

### ① 결과 보기(읽기) — 1단에서 연다
| 무엇 | 예 | 지금 서버에 있는 근거 | 비고 |
|---|---|---|---|
| 이 키로 쓸 수 있는 서비스·지역 목록 | 남원시 → 영농관리 행정서비스(운영) · 국토 변화 탐지 서비스(시범) | 서비스 카드 목록 · 배포본 · 기관 관할 설정 | 광역 기관은 광역 전체 + 시군구 둘 다 |
| 요약 숫자 | 여수시 해양쓰레기 실태조사 서비스 — AI 탐지 1,857건(2023년 항공영상 · 2026-06-08 분석) | 대표 수치 한 출처(`summary`) | **화면과 같은 값**(숫자 한 출처). 값이 없으면 빈 값 + 이유 |
| 조각·점 결과(모양 포함) | 비닐하우스 조각 · 쓰레기 조각 · 변화 지점 — 종류 · 면적 · 신뢰도 · 읍면동 · 필지 번호 · 촬영일 | 탐지 결과 표 · 결과 세트 해석 | GeoJSON · 페이지 나눠 받기 · '지난번 이후 바뀐 것만' |
| 필지별 결과 | 필지마다 AI 가 본 것(경작 흔적·시설·건물)과 확인이 필요한 까닭 한 줄 | 필지 × AI 결합 저장본 · 실태조사 결과 | 규칙 코드 대신 사람이 읽는 까닭 문장 + 기계용 까닭 이름 |
| 필지 하나 조회 | 필지 번호 하나 → 그 필지의 AI 결과·까닭·기준 시점 | 필지 조회 | 관할 밖 필지는 '없음'으로 답함 |
| 결과 지도 조각(타일) | 도청 GIS 가 자기 지도 위에 해양쓰레기 결과 층을 띄움 | 결과 지도 파일 · 서명 주소 | 벡터 지도 조각 + 12시간짜리 서명 주소 |
| 보고서 | 읍면동 실태조사 보고서(한글 문서 · Word 형식) | 보고서 초안 만들기(규칙 결과 기반 · 언어 모델 불필요) | 보고서까지만 — 공문·처분 문서 없음 |
| 이번 달 사용량 | 요청 수 · 맡긴 분석 시간 · 기관 한도 대비 | 기관 사용량 장부 | 기관이 스스로 한도를 확인 |

### ② 분석 맡기기(쓰기) — 2단에서 연다
| 무엇 | 어떻게 | 막는 것 |
|---|---|---|
| 영상 올리기 | 위치 정보가 든 영상 파일(GeoTIFF)을 8MB 조각으로 나눠 올림 — 끊겨도 받은 곳부터 이어서. 해상도·촬영일·범위·좌표계는 **파일에서 자동으로 읽음**(입력 칸 0) | 위치 정보 없는 사진 · 관할 밖 범위 · 한 파일 한도 초과 |
| 견적 | 서비스 + 범위(또는 올린 영상) → 분석 면적 · 예상 분석 시간 · 대기 순서 · 한도 남은 양 · 가능/불가와 까닭 | 견적은 분석 기계를 쓰지 않는다(미리 적재도 안 함) |
| 등록 | 견적과 같은 요청을 등록 → 작업 번호 · 대기 순서. 같은 요청을 두 번 보내도 작업은 하나(중복 방지 열쇠) | 등록된 서비스 카드만 · 서비스가 그 지역에 공개(적용)돼 있어야 |
| 상태 → 결과 | 대기 → 분석 중(진행률) → 끝남/실패/취소. 끝나면 **알림(웹훅)** 을 보내고, 결과는 ①과 같은 모양으로 가져감 | 진행 중 결과는 주지 않음(끝난 뒤 한 번에) |
| 취소 | 등록한 쪽이 대기·분석 중 작업을 취소 | 다른 키가 등록한 작업은 못 건드림 |
| AI 가 잘못 봤어요(메모 한 줄) | 결과 하나(또는 필지 번호)에 메모 한 줄 | 구조화된 입력 요구 0 — 정리는 LX 쪽이 한다 |

### ③ 안 되는 것 — 그리고 까닭
| 안 되는 것 | 까닭 |
|---|---|
| 모델 학습·재학습·모델 올리기·모델 바꾸기 | LX 생산(프로젝트장 → 결과 확인 → 서비스 공개 → 관리자 승인)의 몫이다. 바깥에서 모델이 바뀌면 같은 서비스의 결과가 기관마다 달라지고, 누가 책임지는지 끊긴다. |
| 임의 모델·임의 설정(조각 크기·임계값·해상도 배율·GPU 수·우선순위) | 서비스 카드가 이미 정한 값이다. 설정을 열면 결과 품질·분석 시간·전력 규칙을 바깥이 흔든다. |
| 다른 기관·관할 밖 데이터(조회·분석 둘 다) | 계정 범위 밖은 없다는 사용자 원칙. 화면에서 숨기는 게 아니라 서버가 내주지 않는다. 읽기는 '없음'(404), 분석 범위가 관할을 조금이라도 벗어나면 거절. |
| 원본 영상 내려받기 · 영상 보기 지도 조각 | 기관에는 원본급 영상과 동적 영상 조각을 주지 않는다는 기존 결정(2026-09-24)을 따른다. 항공·드론 영상은 보안·권리 검토 대상이다. API 가 내주는 것은 **결과**뿐. |
| 개인정보 열(소유자 이름·연락처·주민번호 등) | 결과에 사람 정보를 싣지 않는다. 기관이 올린 대장의 개인정보 열도 API 로 되돌려 주지 않는다. |
| LX 내부 운영 정보(분석 기계 상태·대기열 전체·장비·다른 기관 사용량) | 기관에 필요 없는 정보이고, 보안상 알릴 까닭이 없다. 기관은 자기 작업의 대기 순서와 자기 한도만 본다. |
| 결과 판정·상태 바꾸기(현장 확인 결과 되돌려 쓰기) | 판정·조치의 권한과 책임(누가·어떤 기준으로)을 먼저 정해야 한다. 지금은 기관 화면에서만. 나중 후보로 적어 둔다. |
| 공문·시정명령 등 처분 문서 자동 만들기 | Land-XI 의 문서 기능은 보고서까지(사용자 원칙). AI 결과는 참고자료이고 처분은 사람이 한다 — 모든 결과에 '참고자료' 표시를 싣는다. |
| 관할 전체를 한 번에 통째로 내려받기 | 페이지 나눠 받기만. 한 번에 파일로 필요하면 보고서·내보내기 파일로. 한 번에 수십만 행을 내주면 다른 사용자의 화면이 느려진다. |
| 실시간 영상 흐름 분석(CCTV·차량 영상 스트림) | 분석 기계가 한 번에 한 장만 고부하로 돈다(전력 규칙). 초 단위로 끝없이 들어오는 영상은 이 역량으로 약속할 수 없다. |
| AI 도우미(말로 묻기) API | **지금은 닫는다 — 나중 후보.** 같은 분석 기계를 쓰고(두 장 동시 고부하 금지), 말 이해 개선이 진행 중이다. 열 때는 읽기 질문만 · 지도 제어 없음 · 토큰은 같은 기관 한도 장부. |

## 2. 역량에 맞춘 한도와 순서

### 2-1. 역량의 실제 모습(지난 30일 기록에서)
- **분석 기계는 사실상 한 장만 고부하로 돈다.** 전력 규칙(동시 고부하 1장)이 모든 분석 작업과 AI 도우미 언어 모델을 하나의 줄로 세운다. API 로 맡긴 분석도 이 줄에 선다.
- 시군구 전역 분석 기록 27건(25cm 항공영상): **1㎢ 에 분석 시간 약 1.0–2.9초**(가운데 값 1.4초). 예) 557㎢ 한 번 = 분석 시간 약 16분, 실제로 끝나기까지 약 39분 · 750㎢ 급 한 번 = 분석 시간 약 21분, 실제 2시간 13분(다른 작업·전력 규칙과 나눠 씀).
- 드론 영상을 드론 해상도 그대로 보는 서비스라면 같은 넓이에 훨씬 많은 조각을 본다. 3cm 급이면 1㎢ 에 분석 시간 약 50–70초로 **추산**(모델 처리 속도 기록 × 조각 수 계산 · 실측 전). 그래서 드론 한 번의 넓이 한도를 따로 둔다.
- 지금 기관 한도(초기값): 남원시 월 분석 시간 10시간 · 광주전남 6시간 · 동시 작업 1–2건. 이번 달 남원시 사용 약 2시간 31분(2026-09-30 기준 장부).
- 바깥 주소 앞단은 요청 한 번을 100초 안에 끝내야 한다 — 큰 파일은 조각으로, 긴 작업은 비동기로만.

### 2-2. 순서(화면 사용자 대 API)
| 순서 | 무엇 | 까닭 |
|---|---|---|
| 1 | 화면에서 누른 짧은 분석(읍면동·그린 범위 · 첫 결과 10초 안) | 사람이 화면 앞에서 기다린다 |
| 2 | 화면에서 누른 시군구 전역 분석 | 사람이 진행판을 보고 있다 |
| 3 | **API 로 맡긴 분석** | 기다리는 사람이 없다 — 끝나면 알림으로 |
| 4 | 한도를 넘긴 작업(화면·API 모두) | 기존 '한도 넘으면 순서 낮춤' 규칙 그대로 |

- API 분석은 **Land-XI 전체에서 한 번에 1건만** 돌린다(기관 수와 무관). 화면 작업이 굶지 않게 하는 칸막이다.
- 기관의 '동시 작업' 한도는 화면과 API 를 **합쳐** 센다.
- 약속하는 시간: API 분석은 **등록 뒤 24시간 안에 결과**(보통은 몇십 분). 초 단위 약속은 하지 않는다.
- 증설 서버(A100)가 붙으면(LX 관리자 장비 관리 — 지금은 방향만) API 칸을 늘린다. 규칙은 그대로, 칸 수만 바뀐다.

### 2-3. 한도(초기값 제안 — LX 관리자 화면에서 기관별로 바꿈)
| 한도 | 초기값(제안) | 넘으면 | 장부 |
|---|---|---|---|
| 요청 수 | 키당 1분 60회 · 기관당 하루 20,000회 | 잠시 멈춤(429 + 다시 시도할 때) | 새 칸 '하루 API 요청' |
| 지도 조각 | 키당 1분 1,200장 | 잠시 멈춤 | 요청 수와 따로 셈 |
| 한 번에 받는 결과 | 1,000행 | 다음 쪽 열쇠로 이어 받기 | — |
| 분석 한 번의 넓이 | 항공·위성 150㎢(화면과 같은 서버 천장) · 드론 5㎢ | 등록 전 견적에서 거절(범위를 나눠 달라고 안내) | 기존 분석 면적 칸 |
| 분석 등록 수 | 기관당 하루 10건 | 거절 | 새 칸 |
| 분석 시간 | 기관 월 분석 시간 한도 안(화면과 합산) | 기존 규칙(순서 낮춤) | 기존 분석 시간 칸 |
| 올린 영상 | 파일 하나 20GB · 90일 보관 | 거절 · 90일 뒤 지움(결과는 남음) | 기존 저장 공간 칸 |
| 내보낸 양 | 월 전송량 한도(기관 한도에 이미 있음) | 알림 | **처음으로 실제 계량**(지금은 '미계량') |

## 3. 누가 무엇을 하나(권한과 책임)
| 누가 | 하는 일 | 어디서 |
|---|---|---|
| LX 관리자 | 키 만들기(기관·부서·서비스·할 수 있는 일) · 폐기 · 한도 바꾸기 · 요청 기록 보기 | LX 관리자 화면 → 기관 → 그 기관 서랍 'API 연동' |
| 기관 관리자 | 자기 기관 키 보기 · **급할 때 폐기** · 요청 기록 내려받기 · 새 키 요청 | 기관 분기 플랫폼의 기관 관리(3단) |
| 기관의 다른 시스템(개발자) | 키로 결과 보기 · 분석 맡기기 · 알림 받기 | API |
| LX 직원 | 서비스 카드를 만들고 공개 — 그 서비스가 곧 API 로 쓸 수 있는 서비스가 된다 | LX 직원 대시보드(기존 흐름) |

- 키는 **기관에 속한다**. 기관이 맡긴 사업자(예: 해양쓰레기 수거 사업자)의 시스템도 그 기관 이름의 키를 쓰고, 책임은 기관에 있다.
- 부서 사용자 구조와 같게: 부서 키는 그 부서 서비스만(예: 농정과 키 = 영농관리 행정서비스만).
