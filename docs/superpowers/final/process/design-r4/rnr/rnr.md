# 역할별 R&R — 누가 무엇을 책임지고 하는가 (2026-09-30)

> 사용자(09-30): "LX 관리자, LX 직원, 이용자(지자체, 정부부처 등) 역할별 R&R과 기능 대조를 통해 개발 범위에 누락된 부분이 있는지도 체크한다." — 바로 앞 지적: "우리 직원이 AI 학습데이터 구축하는 파트에 대해서는 전혀 안 보이네??"
>
> 지위: **사용자 확인 전 정리.** 사용자 지시 기록과 확인 요청 1–3차에서 이미 확정된 결정만으로 썼다. 새 기능·새 업무 용어를 만들지 않았다. 아직 정해지지 않은 경계는 이 문서에서 정하지 않고 확인 요청(갈림길)으로 따로 묻는다. 코드는 고치지 않았다.

## 1. 한 장 위계

```
Land-XI 플랫폼 (LX 가 쓰는 본 플랫폼)                  기관 분기 플랫폼 (예: 남원시 · 광주전남 · 키르기스 — 같은 서버의 분기)
  LX 관리자 ── 결재 · 기관 · 자원 · 배포 · 공개 뒤 관리      기관 관리자 ── 부서 · 사용자 · 가입 승인 · 관할 전체
  LX 직원                                                   부서 사용자 ── 자기 부서 서비스만
    ├ 프로젝트장 ── 프로젝트 1차 소유 · 공개 전 판단           해외 기관 ── 같은 위계 · 영어
    └ 구성원 ── 데이터 올리기 · 학습데이터 구축 · 학습 · 결과 확인
  LX 영업 ── 서비스 · 사례 소개(읽기 전용)
외부 시스템(API) ── 기관의 키로 결과 가져가기 · 분석 맡기기     게스트 ── 소개 · 사례 · 문의 · 가입 신청
```

같은 작업이 이렇게 이어진다: **프로젝트(직원) → 모델 등록 → 서비스 공개(관리자 승인) → 다른 지역 적용(관리자 승인) → 기관 분기(부서 사용자가 결과를 행정에 씀) → 'AI가 잘못 봤어요' 알림 → LX 가 정리 → 재학습(공개 전 프로젝트장 · 공개 뒤 관리자)**.

## 2. 모든 역할에 걸리는 약속 (사용자 지시에서)
| 약속 | 사용자 말(09-30) |
|---|---|
| 판단에는 주인이 있다 | 승인·반려·재학습은 누가(프로젝트장·LX 관리자·기관 관리자) 하는지와 기준을 먼저 정한다. 반려에는 사유가 남는다. |
| 소유 | 프로젝트는 만든 프로젝트장이 1차 소유·판단(재학습 포함). 서비스 카드 공개 뒤에는 LX 관리자가 갱신을 관리하고 필요하면 재학습을 지시한다. |
| 위계 | Land-XI 는 LX 직원·관리자가, 기관 분기 플랫폼은 그 기관 직원이 쓴다. 기관 안에도 기관 관리자와 부서 사용자가 있고 부서는 자기 업무 서비스만 본다. 기관 메인은 부서 공통 기능만. |
| 관할 밖은 없다 | 계정의 대상지 밖 정보는 호출·표시·열람 모두 0 — 서버가 내주지 않는다. API 에도 그대로. |
| 짐을 넘기지 않는다 | 기관 사용자에게 구조화된 입력을 요구하지 않는다. 'AI가 잘못 봤어요'는 누르고 메모 한 줄, 정리는 LX. |
| 보고서까지 | 문서 기능은 보고서 생성까지. 현장 확인 배정·공문·시정명령은 만들지 않는다. |
| 학습데이터 구축은 생산의 한가운데 | 데이터 올리기 → 학습데이터 구축(라벨링·검수·클래스 관리) → 학습 → … 을 화면에서 빠뜨리지 않는다. |
| 쉬워야 쓴다 | 입력·조건·옵션은 최대한 줄이고, 파일에서 알 수 있는 것(해상도·촬영일·범위·좌표계)은 자동으로 읽는다. |

## 3. 역할별 R&R

### 3-1. LX 관리자 — Land-XI(관리자 입구)
- **누구**: LX 운영 책임자.
- **책임 — 결정·승인·소유**
  - 결재: 서비스 공개 · 다른 지역 적용 · 운영 전환 · 규칙 기준값 · 모델 등록 · 한도 변경 — 승인 또는 반려(사유 필수).
  - 공개된 서비스의 관리: 공개 뒤 갱신을 관리하고, 필요하면 재학습을 지시한다.
  - 기관과 첫 기관 관리자 만들기 · 기관 중지·재개 · LX 직원·영업 계정.
  - 자원: GPU · 작업 대기열 · 저장 공간 · 전력 · 기관별 한도(저장·GPU 시간·분석 면적·AI 도우미 사용량) · 장비(방향만 확정, 구현은 다음).
  - 배포: 단계 올리기 · 되돌리기 · 모델 교체.
  - 프로젝트·사업 전체 보기(프로젝트장이 비면 다시 지정).
  - 외부 연동 API 키와 기관 한도의 연결(발급 방식은 외부 연동 설계에서 정함).
  - 공지 · 자주 묻는 질문 · 문의 답변.
- **하는 일(하루 흐름)**: 로그인 → 현황(결재 대기·경보) → 결재함 → 인프라(GPU·대기열·저장·언어 모델·법령 색인) → 기관(한도·사용량·계정) → 배포(단계·되돌리기) → 경보 처리 → 공개된 서비스 점검(재학습 지시).
- **하지 않는 일**: 기관 사용자 개개인 만들기(기관 관리자 몫) · 프로젝트 안 작업(올리기·라벨링·학습).

### 3-2. LX 직원 · 프로젝트장 — Land-XI
- **누구**: 프로젝트를 만든 직원(프로젝트장은 넘길 수 있다). 프로젝트 만들기에는 관리자 승인이 없다(09-30 확정).
- **책임 — 결정·소유**
  - 프로젝트 1차 소유: 무엇을 · 어디 · 기간 · 구성원.
  - 공개 전 재학습 판단.
  - 서비스 공개 요청 · 다른 지역 적용 요청 · 기준값 조정 요청 — 반려되면 사유를 반영해 다시 요청.
- **하는 일**: 프로젝트 만들기 → 구성원 초대 → (구성원과 함께 생산) → 결과 확인 표본을 보고 '확인 완료' → 서비스 만들기 → 공개 요청 → 다른 지역 적용 요청 → 공개 전 재학습 판단 → 프로젝트 끝내기(보관).
- **하지 않는 일**: 승인(LX 관리자) · 공개 뒤 재학습 결정(LX 관리자 — 누가 '시작'을 누르는지는 확인 요청 갈림길).

### 3-3. LX 직원 · 구성원 — Land-XI
- **누구**: 프로젝트에 속한 직원(프로젝트장도 구성원 일을 한다).
- **책임**: 자기가 올린 데이터·라벨·판정의 품질 · AI 결과 고치기·지우기(결과 품질 책임은 LX — 09-20 역할 정의) · 기관이 알린 'AI가 잘못 봤어요' 정리와 답.
- **하는 일(생산 순서)**
  1. 내 프로젝트 열기(첫 화면 = 내 프로젝트 · 다음 할 일)
  2. 데이터 올리기 — 위성·항공·드론 영상 파일(위치는 파일에서) · 융복합 행정 자산 · 위치 없는·맞지 않는 자산 정리
  3. **학습데이터 구축 — 라벨링 · 라벨 검수 · 클래스 관리**
  4. 학습 → 결과 → 모델 등록 요청
  5. 결과 확인(표본 판정 → 정밀도)
  6. 서비스 만들기(모델 + 규칙 + 대장 가이드)
  7. 서비스 관리 — 'AI가 잘못 봤어요' 정리·답 · 재학습 신호 보기
  - 수시로: XI맵 전역 AI 분석 · AI 도우미로 말로 지도 제어·분석
- **하지 않는 일**: 공개·적용 승인 · 계정 관리.

### 3-4. LX 영업 — Land-XI(직원과 같은 입구, 아이디로 구분)
- **책임**: 결정·승인 권한 없음. 서비스와 사례를 실제 운영 결과로 정확히 소개한다.
- **하는 일**: 서비스 목록·상세 → 활용 사례(두 지역 이상) → 지역 결과 열어 보여 주기(남지 않음) → 새 지역에 열 수 있는지·드는 자원 확인(서비스 제공 체계 기획과 연결).
- **하지 않는 일**: 쓰기 · 실행 결과 남기기 · 결재.

### 3-5. 기관 관리자 — 기관 분기(지자체 · 정부부처)
- **누구**: 기관의 관리 부서 담당(예: 정보통신·기획).
- **책임 — 자기 기관 안**
  - 부서 만들기 · 부서마다 서비스 연결.
  - 직원 가입 신청 승인 · 비밀번호 재설정 · 잠금 해제(09-30 확정: 가입 신청 + 승인).
  - 관할 전체(광역이면 전체 합계 + 시군구 고르기, 화면이 대신 고르지 않음).
  - 기관 사용량 보기 · 한도 조정 요청 · 영상 등록 요청.
- **하는 일**: 기관 입구 로그인 → 관할 전체 보기 → 부서·사용자 관리(가입 승인) → 사용량 → 영상 등록 요청 · LX 공유 영상 불러오기 · 기관 드론 영상 올리기 → (부서 사용자 일도 모두 볼 수 있다).
- **하지 않는 일**: 기관 만들기·한도 정하기(LX 관리자) · AI 결과 고치기(LX 몫 — 기관은 알린다).

### 3-6. 부서 사용자 — 기관 분기
- **누구**: 업무 부서 담당(예: 농정과 = 농지이용 실태조사만).
- **책임**: 자기 부서 업무에서 AI 결과를 행정에 쓰는 것 — 판정 · 조치 기록 · 보고서.
- **하는 일**: 로그인 → 우리 부서 서비스만 → 결과(지도·필지) → 대장 올리기·결합 → 말로 묻기 → 의심 필지 판정·조치 기록 → 보고서 초안 → 'AI가 잘못 봤어요'(누르고 메모 한 줄) → 답 받기 → 내 계정(비밀번호).
- **하지 않는 일**: 현장 확인 배정 · 공문 · 시정명령(만들지 않음) · 다른 부서 서비스 · 관할 밖.

### 3-7. 해외 기관 — 기관 분기(영어)
- 국내와 같은 위계(기관 관리자 · 사용자), 관할은 현지 행정단위.
- **하는 일**: 영어 화면 → 우리 지역 결과(계절 작황·NDVI·시가지) → 이번 계절 분석 → 영어로 묻기·말로 지도 움직이기 → 구역 대장 올리기 → 보고서(영문).

### 3-8. 외부 시스템(API) — 연동
- **주인**: 키를 받은 기관. 범위는 그 기관의 관할·서비스, 한도는 그 기관의 한도.
- **하는 일**: 기관 키로 들어오기 → 결과 가져가기(필지·구역·요약·지도 조각·보고서) → 분석 맡기기(등록된 서비스만: 등록 → 상태 → 결과·알림).
- **하지 않는 일**: 학습 · 원본 영상 · 다른 기관 자료 · 개인정보.

### 3-9. 게스트 — 로그인 전
- **하는 일**: 플랫폼 소개 → 서비스·활용 사례 → 문의 남기기 → 가입 신청(기관 직원) 또는 로그인.

## 4. 역할 사이 넘겨주기 — 누가 내고, 누가 받아 정하나
| 무엇이 | 누가 낸다 | 누가 받아 정한다 | 정한 뒤 |
|---|---|---|---|
| 모델 등록 | 구성원 | LX 관리자(승인·반려) | 서비스 만들기에 쓸 수 있음 |
| 서비스 공개 | 프로젝트장 | LX 관리자(반려는 사유) | 다른 지역 적용 목록·영업 목록에 뜸 |
| 다른 지역 적용 | 프로젝트장 | LX 관리자 | 영상 → AI 분석 → 실태조사 → 기관 결과 |
| 기준값 조정 | 프로젝트장 | LX 관리자 | 규칙이 새 기준으로 |
| 한도 변경 | 기관(요청) · LX 관리자 | LX 관리자 | 한도 반영 |
| 가입 신청 | 기관 직원(게스트) | 기관 관리자 | 부서 서비스만 보이는 계정 |
| 'AI가 잘못 봤어요' | 부서 사용자 | LX 구성원이 정리 → 답 | 재학습 신호로 쌓임 |
| 재학습 | 공개 전: 프로젝트장 · 공개 뒤: LX 관리자 지시 | (누가 '시작'을 누르나 — 갈림길) | 새 버전 → 공개 결재 → 갱신 배포 |
| 영상 등록 요청 | 기관 관리자 | LX 직원(프로젝트) | 영상 올리기 → 분석 |
| LX 영상의 기관 공유 | (기록에 없음 — 갈림길) | — | 기관이 'LX 공유 영상 불러오기' |
