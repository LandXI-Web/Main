# 새 지자체 온보딩 — 무엇을 다시 쓰고 무엇만 새로 하나

> 2026-09-30 · Fable 5.1(기획). 지위: **사용자 확인 전 제안**. 어느 플랫폼: **둘 다** — 준비는 Land-XI(LX 관리자 · LX 직원), 받는 쪽은 기관 분기 플랫폼(기관 관리자 · 부서 사용자).
> 그림: `shots/sys-3-onboarding.png`. 근거: 명세 "다른 지역에 적용할 때 카드를 복사하지 않는다 — 지역 한 줄만", 원칙 48(기관 분기는 큰 틀 통일 · CI 커스텀), 49·50(직원·기관에 짐을 넘기지 않는다), 확인된 D1(파일에서 지역 자동) · D4(기관 관리자 · 가입 승인).

## 1. 원칙 한 줄
**카드는 그대로, 그 지역의 영상 · 필지 · 대장 · CI 만 갈아 끼운다.** 다른 시군이 "영농관리"를 원하면 새로 만드는 것이 아니라 **같은 카드에 지역 한 줄을 더하는 일**이다.

## 2. 다시 쓰는 것 / 새로 하는 것
| 다시 쓰는 것(Land-XI 안에 이미 있음) | 그 지역만 새로 하는 것 |
|---|---|
| 모델(경작·비경작 · 비닐하우스 · 사료작물 · 곤포 · 항공 4종) — 새 지역 표본 확인 뒤 필요하면 미세조정 | 고해상 영상(드론·항공) — 기관이 찍거나 LX 가 찍어 공유. 원본은 LX 보관 |
| 결과 규칙 · 비교 기준(기본 비교 · 표준 양식 세 칸) | 부서 대장(선택) — 표준 양식으로 올리면 비교, 틀 밖은 맞춤(ⓒ) |
| 기관 플랫폼 골격(홈 카드 · 현황 · 결과 · 지도 · 통계 · 보고서 · 서비스 지원) — 지자체끼리 같은 틀 | 기관 CI(이름 · 약칭 · 마크 · 상징색 · 문의처 등 아홉 가지) · 기관 관리자 계정 1 |
| 전국 필지 · 행정경계(서버가 이미 가진 공개 자료) | 결과 확인 표본(그 지역 20건 이상 — 사람) |
| 25cm 항공 영상(등록된 64개 시군구) — 기관 영상 없이도 첫 결과 | 기존 시스템 연결(있으면 ⓑ) |

## 3. 절차 여섯 단(파란 테두리 = 화면 안에서 자동으로 끝나는 단계)
| 단 | 누가 | 무엇 | 자동/사람 | 걸리는 시간 |
|---|---|---|---|---|
| 1 업무 정하기 | 영업 · 기관 | 어느 서비스(카드)를 어느 범위에. 기존 시스템 유무 → 갈래 판별(ⓐ/ⓑ/ⓒ/ⓓ) | 사람 | 협의 |
| 2 기관 만들기 | LX 관리자 | 기관 · CI · 관할(시군구 또는 광역+시군구) · 한도 · 기관 관리자 계정 | 화면 안 자동(지금은 관리자 화면 미완 — 확인 대장 FR-4) | 분 |
| 3 영상 올리기 | LX 직원(또는 기관) | 파일에서 위치·촬영일·해상도 자동 판독. 영상이 없으면 **등록된 항공 영상으로 시작** | 화면 안 자동 | 올리기 시간(1TB 기준 측정 필요) |
| 4 지역에 적용 | LX 직원 → LX 관리자 승인 1회 | 카드 그대로, 지역 한 줄 추가 → 전역 분석 → 결과 | 화면 안 자동(승인 1회) | 항공 25cm: 1시간 이내(추정) · 드론 전역: 예약 |
| 5 결과 확인 | LX 직원 | 표본 20건 이상 사람이 확인 → 정확도 표시 → 공개 요청 | **사람 — 여기가 시간** | 측정 필요 |
| 6 공개 · 가입 | LX 관리자 · 기관 관리자 | 관리자 승인 → 기관 홈에 카드 → 부서 사용자 가입 신청 · 승인 | 화면 안 자동(승인 1회) | 분 |

여섯 단 중 **네 단이 자동**이어야 한다(옛 명세도 "6단계 중 4단계 자동"을 생산화의 척도로 삼았다). 지금 v3 에서 자동으로 끝나는 것은 3·4 뿐이고 2·6 은 관리자 화면이 미완이다 — 온보딩을 기능으로 만들려면 확인 대장의 FR-4(계정·기관 만들기)와 D4(가입 승인)가 먼저다.

## 4. 경우별
### 4-1. 다른 시군이 "영농관리"를 원할 때(ⓐ 그대로)
- 1: 기존 시스템 없음 → ⓐ. 2: 기관 만들기. 3: 기관 드론 영상이 있으면 올리기, 없으면 25cm 항공으로 '농지 위 건물 · 비닐하우스 · 경작지'까지 먼저(사료작물 · 곤포는 드론이 있어야). 4: 영농관리 카드에 지역 한 줄. 5: 표본 확인. 6: 공개.
- 부서 대장은 나중에 — 농정과가 원하면 표준 양식(필지 번호 · 상태 · 날짜) 안내를 보고 올린다. 농지대장 특수 열은 ⓒ.

### 4-2. 전남 해양쓰레기 확대(같은 카드 · 범위 확대)
- 이미 광주전남 기관과 해양쓰레기 카드(여수)가 있다 → 새 기관 만들기 없음. 3: 확대 대상 해안의 항공·드론 영상(간조 촬영) 올리기. 4: 같은 카드에 **해안 한 줄** 추가(지역 프로파일 = 해안 구간). 5: 해안 구역 표본 확인. 6: 기존 사용자에게 '범위가 넓어졌습니다' 알림 한 줄.
- 해안 구역 경계(행정구역 집계용)는 기관이 그려 주거나 공개 해안선을 구간으로 나눔 — 이것이 없으면 통계 탭이 서지 않는다(옛 화면도 같은 메모). 수거 기록과의 비교는 표준 양식(해안 이름 · 수거일 · 양).

### 4-3. 비슷한 신규 사업인데 카드가 없을 때(ⓒ → ⓐ)
- 예: 다른 도의 해양침적쓰레기, 관광인파. 1 뒤에 **프로젝트**가 먼저 선다(영상 올리기 → 라벨링 → 학습 → 결과 확인). 모델이 완성되고 표본을 넘기면 3단(서비스 만들기) → 카드 발행 → 그때부터 위 여섯 단.
- 사업 기간 동안 기관에는 '맞춤 결과' 카드(결과 지도 · 보고서)로 중간 결과를 준다.

### 4-4. 기존 시스템이 있는 기관(ⓑ)
- 2 까지 같음. 3·4 대신 LX 관리자가 **외부 시스템 등록**(이름 · 주소 · 받는 방식: 링크 / 임베드 / 결과 자료 · 계정 연결). 5 없음(품질은 그 시스템 주체). 6: 홈에 '연결된 서비스' 카드.
- 우리 모델을 그 시스템에 공급했으면, 재학습본이 나올 때 전달 기록을 남긴다.

### 4-5. 해외 기관
- 같은 여섯 단. 다른 것은 3(위성 영상 · 현지 행정단위)과 화면 언어(영문). 필지 체계가 없으면 비교 기준은 '구역 안 합계'까지(대장 비교 초안 참조).

## 5. 기관이 준비할 것(짐을 최소로)
- **꼭**: 기관 관리자 한 사람(이름 · 이메일) · 기관 이름 · 마크 파일 · 문의처.
- **있으면**: 고해상 영상(없어도 시작) · 부서 대장(표준 양식 세 칸) · 기존 시스템 주소(있으면 연결).
- **요구하지 않는 것**: 좌표계 · 해상도 · 촬영일(파일에서 자동) · 대장 열 이름 맞추기(자동 인식 뒤 확인만) · 영상 원본 보관(LX 가).

## 6. 확인 못 한 것
- 1TB 올리기 실제 소요 · 표본 확인 처리량(capacity.md 8절과 같음).
- 광역 기관(전남)의 관할 표시 — 광역 전체 + 시군구 둘 다(확인됨)를 해안 구간과 어떻게 겹쳐 보일지는 화면 설계에서.
