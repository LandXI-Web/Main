## 1. 한 줄
**LX 는 AI 분석까지 만들고, 기관은 결과로 행정 업무를 끝낸다.** 다만 기관에 닿는 길이 하나가 아니다 — 우리가 만들어 뿌리는 카드(ⓐ), 이미 있는 시스템에 잇는 연결(ⓑ), 사업으로 따로 하는 맞춤(ⓒ), 화면 없이 자료·분석만 주고받는 API(ⓓ). 네 갈래 모두 **같은 Land-XI 서버 · 같은 작업 흐름 · 같은 계정 범위 · 같은 기관 한도**의 분기다.

## 2. 네 갈래 — 기준 · 누가 운영·유지하나
| 갈래 | 무엇 | 이 갈래로 가는 기준 | 운영·유지 | 기관 화면에 어떻게 보이나 | 실제 예 |
|---|---|---|---|---|---|
| **ⓐ 분기 카드** | Land-XI 가 만든 모델 + 결과 규칙 + 비교 기준 + 화면 부품을 **서비스 카드** 한 장으로 발행해 기관 홈에 놓는다 | 모델이 LX 안에 있고, 다른 지자체에도 그대로 심을 수 있다(지역만 바꿔서) | **LX** — 모델 · 화면 · 갱신 · 재학습(발행 전 프로젝트장, 발행 뒤 LX 관리자) · 기관은 쓰고 '실제와 다릅니다'만 알린다 | 홈의 카드 → 현황 · 결과 · 지도 · 통계 · 보고서 · (대장 비교: 기본 · 표준 양식) | 영농관리(다른 지자체에), 해양쓰레기, 국토 변화, 도로안전의 정사영상 분석 |
| **ⓑ 연결** | 이미 돌고 있는 기관·외부 시스템을 **링크 · 임베드 · 결과 자료 받기** 중 하나로 기관 플랫폼에 잇는다 | 기존 시스템이 있고 당장 옮길 이유가 없다 · 또는 입력이 우리 흐름에 없다(차량 블랙박스 등) | **그 시스템의 주체** — LX 는 연결 등록 · 모델 공급(재학습본 전달) · 결과 자료 받아 지도에 얹기만 | 홈의 '연결된 서비스' 카드 → 누르면 그 시스템으로 가거나(링크), 그 시스템의 결과가 우리 지도·통계에 얹힘(자료 받기) | 남원 영농관리 시스템(외부 운영), 도로안전 대시보드(시안) |
| **ⓒ 맞춤** | 틀에 안 맞는 일 — **연차 사업의 맞춤 개발 · 일회성 분석 보고서 · 파트너 협업** | 모델이 없다(개발부터) · 새 입력 종류(동영상 시간축 · 음파) · 특수 대장·복잡한 규칙(대장 비교 3층의 '커스텀') | **사업 기간엔 LX 프로젝트** — 끝나면 결과만 기관에 남기거나, 완성되면 ⓐ 카드로 승격 | 홈의 '맞춤 결과' 카드(결과 지도 · 보고서) 또는 파일 | 관광인파(모델 개발 전), 해양침적쓰레기, 블랙박스 분석, 특수 대장 비교 |
| **ⓓ API** | 기관·외부 시스템이 Land-XI 를 **호출**해 결과를 가져가거나, 분석을 맡기고 결과를 받는다 | 기관이 자기 시스템(도로 관리 · 농정 · 광역 통계)에 결과를 넣고 싶다 · 화면이 필요 없다 | **LX** — 표준 안내 · 기관별 키 · 한도 · 기록 · 호출하는 쪽은 기관 | 화면 없음(기관 관리자 화면에 '연동 키 · 사용량'만) | 기관 도로 관리 시스템이 포트홀 결과 받기 · 광역 통계 시스템이 시군구 요약 받기 |

**판별 순서**(위에서 아래로 처음 맞는 것): 모델이 LX 안에 있고 다른 지역에도 심을 수 있나 → ⓐ · 이미 돌고 있는 시스템이 있나 → ⓑ · 둘 다 아니면 사업으로 → ⓒ · 화면 대신 자료·분석만 필요하면 → ⓓ(ⓐⓑⓒ 어디에나 겹칠 수 있다).
**ⓓ 의 표준 안내 · 가능 범위 · 구현 계획은 이 문서가 다루지 않는다** — `../open-api/`(오퍼스 작성 예정 · 코어 C11)에 링크만. 이 문서는 ⓓ 가 체계 그림·생애·역량에서 어디에 놓이는지만 정한다(4절 · capacity.md 6절).

### 2-1. 갈래는 고정이 아니다 — 옮겨 간다
- ⓒ → ⓐ: 사업에서 모델이 완성되고 표본 확인을 넘기면 카드로 발행해 다른 지자체에 심을 수 있다(관광인파의 예정 경로).
- ⓑ → ⓐ: 기존 시스템 계약이 끝나거나 기관이 원하면 같은 모델을 우리 분기 플랫폼 카드로 옮긴다(남원 영농관리의 선택지 — 갈림길 1).
- ⓐ + ⓓ: 카드로 뿌린 서비스의 결과를 기관 시스템이 API 로도 가져간다(같은 결과, 두 출구).

### 2-2. 대장 비교 3층과의 관계(확인 대장 '대장 비교의 기본 틀' 초안 참조 · 그 초안은 이 문서가 고치지 않는다)
| 대장 비교 층 | 어느 갈래에 속하나 | 누가 만드나 |
|---|---|---|
| ① 기본 비교(AI × 나라가 공개한 기준) | **ⓐ 카드 안**에 기본으로 들어감 — 기관 할 일 없음 | LX 한 번 |
| ② 표준 양식 비교(위치 · 상태 · 날짜 세 칸) | **ⓐ 카드 안** 선택 단계 — 카드가 '무엇과 비교 가능한가'를 담고 기관은 세 칸 표만 올림 | LX 가 서비스마다 비교 대상만 정함 |
| ③ 커스텀(특수 대장 · 복잡한 규칙) | **ⓒ 맞춤** — 연차 사업으로 | 사업 협의 → LX 프로젝트 |
비교 기준을 **정하는 곳은 Land-XI(프로젝트 · 서비스 만들기)**, 기관 대장을 **올리고 비교를 돌리는 곳은 기관 분기 플랫폼** — 기관 자료는 기관 안에서만 돈다(계정 범위 밖 0).

## 3. 서비스 생애 — 일곱 단계와 소유
그림 `shots/sys-2-lifecycle-namwon.png` 위쪽.

| 단계 | 무엇 | 누가 | 화면(어느 플랫폼) |
|---|---|---|---|
| 1 연차 사업 수주 | 기관이 원하는 업무 하나(예: 도로안전) · 기존 시스템 유무 · 갈래 판별 | 영업 · 기관 · LX 관리자 | Land-XI(영업 첫 화면 · 사례) |
| 2 프로젝트 | 영상 올리기 → 라벨링 → 학습 → 결과 확인. **프로젝트장이 1차 소유**(재학습 판단 포함) | LX 직원 | Land-XI(LX 직원 대시보드 · 내 프로젝트) |
| 3 모델 + 규칙 | 무엇을 세고 나누나 · 결과 규칙(의심 필지 등) · 비교 기준(① ②) · 영상 조건 · 화면 부품(종류 선언) | LX 직원 | Land-XI(서비스 만들기) |
| 4 서비스 카드 발행 | 공개 요청 → **LX 관리자 승인 / 반려(사유 필수)** → 버전 | LX 관리자 | Land-XI(결재함) |
| 5 기관 분기 제공 | 카드를 그 기관 홈에 놓는다(지역 한 줄 = 배포본). 부서는 자기 카드만. 가입 신청 → 기관 관리자 승인 | 기관 관리자 · 부서 사용자 | 기관 분기 플랫폼 |
| 6 유지 · 갱신 · 재학습 | 새 영상마다 다시 분석 · 정확도 지켜보기 · '실제와 다릅니다' 받기 · **발행 뒤 갱신은 LX 관리자가 관리, 필요하면 재학습 지시** → 프로젝트장이 같은 프로젝트의 다음 회차로 | LX 관리자 → 프로젝트장 | Land-XI(서비스 관리 · 배포) |
| 7 다음 해 사업 | 새 업무가 붙거나(누적) 같은 서비스가 범위를 넓힘(확대) → 1 로 | 영업 · 기관 · LX | — |

- **연결(ⓑ)의 생애**는 짧다: 1(판별) → 관리자가 외부 시스템 등록(주소 · 결과 자료 받는 방식 · 계정) → 5(기관 홈에 연결 카드) → 6(결과 자료가 오면 갱신 · 모델을 공급했으면 재학습본 전달).
- **맞춤(ⓒ)의 생애**는 2 에 머문다: 사업 기간 내내 프로젝트 · 끝나면 결과 파일·보고서를 기관에 남김 · 완성되면 3 → 4 로 승격.
- **API(ⓓ)**는 5 의 또 다른 출구: 카드 결과(또는 등록된 서비스에 분석 맡기기)를 기관 시스템이 키로 가져간다. 한도 · 기록은 기관 한도 장부와 같은 곳.

## 4. 남원 누적 — 실제 연차로 본 그릇
그림 `shots/sys-2-lifecycle-namwon.png` 아래쪽.
- 2023 생활환경(새로) → 2025 영농관리(새로) + 생활환경(이어짐 — 외부 시스템 안 '방치 쓰레기 정보 분석') → 2026 도로안전(새로) + 두 서비스 유지 → 2027 관광인파(새로 · ⓒ) + 세 서비스 유지.
- 3년차 도로안전 시안의 '분석 과제' 목록에 1·2년차 과제가 그대로 들어 있다 — **기관 플랫폼은 연차 사업이 쌓이는 그릇**이라는 것이 실제로 확인된다.
- 전남도 같은 모양: 2025 여수 해양쓰레기(ⓐ 카드 · 남원 밖 첫 적용) → 2027 대상 해안 확대(같은 카드에 지역·해안 한 줄 추가).
- **지금 남원의 두 화면(영농관리 시스템 · 도로안전 시안)은 Land-XI 분기 플랫폼이 아니다.** 그래서 갈림길 1 이 필요하다(README).

## 5. 화면에 어디에 나타나나(Land-XI / 기관 분기)
| 자리 | Land-XI(LX 직원 · 관리자) | 기관 분기 플랫폼 |
|---|---|---|
| 서비스 목록 | 만들 수 있는 업무 · 운영 중인 곳(카드 × 지역 한눈표) — 갈래 표시(ⓐⓑⓒ) | 홈 카드: 서비스 카드(ⓐ) · 연결된 서비스(ⓑ) · 맞춤 결과(ⓒ). 부서는 자기 것만 |
| 연결 등록 | LX 관리자: 외부 시스템 이름 · 주소 · 받는 방식(링크 / 임베드 / 자료) · 공급한 모델 | 연결 카드(누르면 그 시스템 · 또는 우리 지도에 얹힌 결과) |
| API | LX 관리자: 기관별 키 발급·폐기 · 사용량 · 기록(`../open-api/`) | 기관 관리자: 우리 키 · 사용량(화면 한 칸) |
| 유지 | 서비스 관리: 정확도 · 새 영상 · 신고 → 재학습 지시 · 갱신 배포 | 새 버전 알림 한 줄 · '실제와 다릅니다' · 내가 알린 것 |

## 6. 이 체계가 지켜야 할 규칙(이미 있는 원칙을 갈래에 맞춤)
1. 카드는 복사하지 않는다 — 다른 지역엔 **지역 한 줄**(배포본)만 더한다(명세 규칙). 새 지자체 온보딩(onboarding.md).
2. 원본 영상은 LX 보관, 기관엔 지도 이미지로. 다른 지역에 적용할 때 따라가는 것은 모델 · 규칙 · 라벨.
3. 기관 자료(대장 · 기관이 올린 영상)는 기관 안에서만. 계정 범위 밖은 서버가 내주지 않는다 — ⓓ API 도 같다.
4. 연결(ⓑ)한 시스템의 품질은 LX 가 책임지지 않는다 — 대신 **모델을 공급했으면 재학습본은 공급한다**. 결과를 받아 얹을 때는 출처를 작은 표시로.
5. 맞춤(ⓒ)은 사업 문서가 아니라 **프로젝트**로 관리한다(예산 · 발주 문서 없음 — 원칙 19). 끝나면 결과와 '카드로 승격 가능 여부'만 남긴다.
6. 갈래는 기관 화면에 이름표로만 보인다 — 기관 담당자에게 ⓐⓑⓒⓓ 글자를 보이지 않는다(카드 · 연결된 서비스 · 맞춤 결과라는 말로).
