## 남은 것
1. **처음 여는 3초를 늘 지키려면 터널 · 정적 파일 쪽**이 남았습니다.
   - 화면 코드 파일 약 60개를 한두 개로 묶으면 처음 1초 안팎이 줄어듭니다.
   - 지도 엔진 · 화면 코드를 오래 보관(판 번호 주소)하면 다시 열 때 확인 요청이 없어집니다.
   - 해외 영상 받기가 도는 동안 터널 대역을 나눌지도 정해야 합니다.
2. 게이트웨이를 켤 때 읍면동 경계 색인 · 결과 목록을 미리 읽어 두기. 재시작 직후 첫 사람이 3~6초 기다리지 않게 됩니다(지금은 지역 요약만 기동 때 계산).
3. 전국 읍면동 집계(LX 직원 · 60KB 압축 · 서버 0.35~0.44초)는 묶음에서 뺐습니다. 첫 화면이 기다리지 않지만, 미리 계산해 두면 직원 화면의 막대가 더 빨리 찹니다(실태조사 판정이 바뀔 때 무효화 규칙이 필요해 이번에는 손대지 않음).
4. 첫 판이 '결과 층 하나라도 보이면' 걷히므로, 걷힌 직후 1초쯤 결과 무늬가 차오르는 모습이 보입니다(`gov-ximap-shown-…`). '다 그려진 뒤 걷힘'이 낫다면 되돌릴 수 있습니다.

## 이런 것도 필요하지 않을까요? (원칙 57)
1. **서비스 대시보드에서 XI맵 묶음 미리 받기** — 누가 왜: 기관 담당자. 서비스 대시보드를 보는 동안 묶음(로그인 확인 · 지역 자료 · 결과 목록)을 받아 두면, '서비스로 열기'를 눌렀을 때 서버 요청 0으로 바로 지도가 섭니다.
2. **화면 코드 묶기(정적 파일 한 묶음)** — 누가 왜: 처음 여는 모든 사람(특히 해외 · 느린 망). 처음 1초 안팎이 줄고, 다른 화면(대시보드 · 보고서)도 같이 빨라집니다.
