## 1. 한 줄
**대시보드는 LX 직원이 아침에 여는 한 장이다. 네 질문 — ① 내 프로젝트는 어디까지 왔나 ② 기관이 나를 기다리는 것은 무엇인가 ③ 우리 서비스는 어디서 잘 돌고 무엇이 문제인가 ④ 지금 무엇을 할까 — 에 각각 한 칸이 답하고, 모든 숫자는 서버 요약 한 곳에서 온 업무 결과만 쓴다.**

| 칸 | 답하는 질문 | 보이는 것 | 누르면 | 숫자 출처(한 곳) |
|---|---|---|---|---|
| **내 프로젝트** | ① | 줄마다 이름 · 지역 · **6칸 진행 막대**(끝난 칸 검정 · 지금 칸 파랑) · 지금 단계 · 다음 할 일 한 줄(예: 결과 확인 대기 60필지 / 남원시 결과 도착) · 3줄 + '전체 보기 n' · '새 프로젝트' | 줄 → 그 프로젝트의 그 단계 | 프로젝트 목록(프로젝트 화면과 같은 값) · 다음 할 일 숫자는 서버 요약의 '결과 확인 대기' |

| **우리 서비스** | ③ | 머리에 운영 n · 시범 n · 지역 n곳 · **실제 결과 장면 썸네일 4**(상태 칩 · 이름 · 어디 · 문제 신호 빨강) · 아래 '살펴볼 것' 칩(재학습 필요 n · 영상 없는 지역 n곳) | 썸네일 → 서비스 카드 상세 · 칩 → 서비스 카드(관리) 거르기 | 서비스 카드 목록 · 배포 기록(운영·시범) · 서비스 관리의 재학습 규칙(같은 값) |

| **최근 활동** | ④ | 2–3줄: 시각 · 무엇이 어떻게(결과 갱신 · 전역 분석 끝남 · 적용) | 줄 → XI맵 결과 · 프로젝트 | 분석 작업 기록 · 배포 기록(끝난 시각) |

- 글 예산: 첫 뷰 본문 **약 300자**(위 머리 포함 · 레일 · 시안 표시 제외 · 법전 5장 ≤ 300) · 1차 버튼 1('분석하기') · 큰 숫자(80) 0 — 카드 숫자 32 만 · 마침표 문장 0.
- 내부 지표 0 — 탐지 총수 · 폴리곤 수 · 걸린 시간 · 장비 이름 없음. 큰 자리에는 결과 확인 대기 n필지 · 기관 신고 n건 같은 업무 결과만(원칙 2·3).
- 지도: 바탕 지도 없음(10차 확인). 서비스가 어디서 도는지는 썸네일의 지역 이름과 서비스 카드 · XI맵에서.
- 빈 상태: 프로젝트가 없으면 "진행 중인 프로젝트가 없습니다 · 새 프로젝트"(그림 없음 · 4차 S1 ⓐ), 요청이 없으면 숫자 0 회색, 서비스 장면이 없으면 회백 판.

## 4. 2안 — 우리 서비스 칸에 작은 지도 조각(`new-dash-b-1440.png`)
1안과 같고 **우리 서비스 칸 안**에만 300×230 지도 조각을 둔다. 점 = 운영(채움) · 시범(테두리) · 살펴볼 것(빨강 + 이름 '남원시 · 신고 103'). 썸네일은 3장으로 줄어든다. 전국 지도를 바탕으로 깔지 않고 **한 칸으로 가두는** 길 — "어디서 도나"를 지도로 보고 싶다는 요구(08-26 '지도와 어울리는 대시보드')와 "지도 없음"(10차)의 중간.
- 글은 1안보다 조금 많다(약 315자 · 지도 안 이름 때문). 지도 점 자리는 서버의 배포 중심점으로 찍는다(시안에서는 근사).

**추천: 1안.** 네 질문에 답하는 칸이 더 넓고, 서비스 '얼굴'(실제 결과 장면)이 4장 보여 "우리가 무엇을 만들었나"가 바로 읽힌다. 지도로 보는 일은 XI맵이 맡는다(위 머리에서 한 번).
