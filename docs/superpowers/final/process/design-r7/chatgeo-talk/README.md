# 설계 7차(design-r7/chatgeo-talk) — XI ChatGEO 대화 규칙 · 못 하는 요청 넓히기 · 개선 고리

> 2026-10-01 · Fable 5.1(UI/UX·대화 설계). 지위: **사용자 확인 전 제안**(코드 수정 0 · 분석 실행 0 · 영상 생성 크레딧 0). 사용자 원문(10-01, 바깥 주소에서 채팅을 써 보고): "시각화한 거 맞어? 안 보이는데?" · "'그 지도 동작은 아직 할 수 없습니다.' 이런 대화는 어떤 식으로 개선할 수 있을까? 고민이 필요하다." · "사용자가 못 하는 걸 확인했다. 이걸 개선할 수 있도록 하는 방향도 설계에 들어가야 한다." → 원칙 97.
> 같은 시간에 다른 에이전트가 채팅창 고장(보이지 않는 시각화)과 막다른 답을 급히 고치고 있다. 이 폴더는 **대화 규칙과 시안**이다 — 그쪽 구현과 겹치면 그쪽이 먼저고, 규칙은 그 뒤에 맞춘다.

## 한 장 요약
1. **실태**(`audit.md`) — 실제 로그인 폼으로 들어가 네 화면(LX 직원 첫 화면 · XI맵 · LX 관리자 대시보드 · 기관 할 일 화면)에서 **31문**을 던졌다. **막다른 답 9** · **말과 화면이 다름 5**("켰다/껐다"인데 변화 0 · "못 그렸다"인데 그려짐 · 채색을 보냈는데 화면이 못 받음) · 물은 것과 다른 일 4 · 차트가 채팅창에서 3줄만 보임 3. 지어낸 숫자 0. 사용자 원문 "안 보이는데?"는 그대로 재현됐다. '할 수 없습니다'류 문구가 나오는 서버·화면 자리 13곳과 이유를 표로.
2. **대화 규칙 일곱**(`rules.md`) — ① 그려진 것만 "그렸습니다"(끝 신호 뒤 · 이미 켜져 있으면 그렇게 · 못 그리는 화면은 XI맵 버튼) ② 못 하는 요청 = 이유 한 줄 + 가장 가까운 일 **실행** + 버튼 2–3 ③ 모호하면 되묻지 않고 지명 > 화면 지역 > 직전 지역 순으로 하고 '다른 뜻이면 ○○' 한 줄 ④ 지도 없는 화면은 채팅 안 작은 표·차트 + 'XI맵에서 크게 보기' ⑤ 숫자는 도구 결과에서만 + 비교는 같은 이름끼리 ⑥ 2문장 · 쉬운 말 · 공공 서비스 말투 · 내부 말 0 ⑦ GPU·되돌리기 어려운 일만 확인 카드(범위 문장 포함 · 기관은 '의뢰 보내기'). 규칙마다 실제 답(나쁜 예)과 고친 답(좋은 예).
3. **넓힐 동작**(`expand.md`) — 12개를 자주 막힘 × 쉬움으로. 먼저: 지명 + 동작(이동 먼저) · 켰다/껐다 신호 맞추기 · 기관 '우리 시' 관할로 · 지도 없는 화면은 XI맵 열기 버튼. 둘째: 층·채색을 모든 지도 화면에서(없는 화면은 XI맵 버튼) · 두 시점 나란히(XI맵 가르기에 시점 선택) · 범위 그리기 · 지도 그림 저장. 셋째: 차트 → 지도 색 · 리 단위 이동.
4. **개선 고리**(`improve-loop.md`) — 못 한 요청·막힌 동작·같은 뜻 재질문·'도움 안 됨'을 저절로 모아(원문 저장 0 · 요지와 분류만 · 90일) → '자주 막히는 요청' 목록(몇 번 · 역할 · 화면) → LX 관리자 대시보드 '개선 후보' 탭(담당 프로젝트장은 요청함에서 자기 것만)에서 **채택 · 보류 · 이미 됨** → 채택은 확인 대장 '확인 대기'로 올라가 사용자 확인 뒤 구현 → 만들어지면 물었던 사람 채팅창 맨 위에 "이제 됩니다 · 해 보기". 이번 실태의 막힌 것 12줄을 첫 목록으로.
5. **시안 네 장**(`mock/talk.html?s=a|b|c|d` · `shots/new-*.png`) — ⓐ 못하는 요청 → 대신 한 일 + 버튼 ⓑ 지도 없는 화면에서 표 + 크게 보기 + XI맵 열기 ⓒ 모호한 요청을 해석하고 '다른 뜻이면' ⓓ 이미 켜진 층 · 실행 전 확인 카드. 실제 키트(kit.css)와 6차 채팅 시안 틀 위에 답 블록만 더 그렸다. 휴대폰(390) 두 장.
6. **확인 요청 3**(`confirm-items.json`) — 대화-1(규칙 일곱 + 답 모양) · 대화-2(넓힐 동작 첫 묶음) · 개선-1(개선 고리). 모두 '검토 필요' 선택지 포함.

## 확인 못 한 것(정직)
- 실태는 10-01 11시 전후 이 PC 의 플랫폼 상태다. 그사이 다른 에이전트가 채팅창을 고치고 있어(한때 스크립트 오류로 세 화면이 안 열려 다시 돌림 · 기관 화면 답에 새 '다음 할 일' 블록이 보이기 시작) 지금 같은 질문을 던지면 일부 답은 이미 다를 수 있다. 다시 재는 법은 `audit.mjs` 한 줄.
- 바깥 주소(app.land-xi.dev)가 아니라 이 PC 주소로 들어갔다(같은 서버 · 같은 데이터). 바깥 주소에서만 나는 차이(답 받기 연결)는 보지 않았다.
- 시안의 숫자(현장 확인 필요 312 · 기관 요청 1,284 · 읍면동 11곳 62% 등)는 **예시**다. 실제 답은 도구 결과만 쓴다.
- 마스코트 자리는 지금 화면처럼 LX 마크로 두었다(랜디·에렉스맨 원본 파일을 받기 전).
- 대화 규칙을 서버·화면 어느 쪽이 맡을지(적용 순서 1–3)는 제안이며, 구현 갈래가 정한다.
