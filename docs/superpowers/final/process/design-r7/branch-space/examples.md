## 한 줄씩
- **광주전남 해양쓰레기** — LX 가 만든 '해양쓰레기 실태조사 서비스'(1차 · 본체)의 탐지 결과를 광주전남 공간에서 받아, 도가 맡긴 개발사가 해류·바람 자료와 합쳐 계산하는 **'해양쓰레기 예측 지도'(2차 · 코드 틀 · 상자 하나)**를 올린다. 새 탐지 회차가 공개되면 예측이 저절로 다시 계산되고, 사업이 끝나면 예측 지도 상자만 지운다.
- **남원 영농** — LX 가 만든 '영농관리 행정서비스'(1차)의 경작 판정을 남원 공간에서 받아, 농정과 담당자가 직불금 신청 명단을 올리고 화면에서 비교 방식만 골라 **'직불금 대상 검토 표'(2차 · 설정만 · 상자 없음)**를 만든다. 새 판정이나 새 명단이 오면 표가 다시 만들어지고, 그 해 검토가 끝나면 명단을 지운다.

## 1. 광주전남 해양쓰레기 — 1차 탐지 → 2차 예측 지도
| | 무엇 · 누가 · 어디 |
|---|---|
| **1차(Land-XI 본체)** | 해양쓰레기 실태조사 서비스(서비스 1.2). LX 프로젝트장이 모델·학습, LX 관리자가 승인해 공개. 지금 광주전남에 공개된 회차 = 2025 항공 · **AI 탐지 1,857건** · 2026.06.08 분석. LX 가 가진 다음 판 = 2026 드론(2,078건 · 종류 8) — 공개 전 |
| **공간 ① 받은 것** | 위 결과 중 광주전남 관할분 · 결과 설명서(종류 · 모양 · 회차 · 칸 · 신뢰 · 버전) · 새 결과 알림 |
| **공간 ③ 기관 자료** | 해류·바람 예보(바깥 제공처 — 누구인지 **확인 필요**) · 해안 관리 구간(도) · 수거 기록(도). 모두 광주전남 공간 안에서만 |
| **공간 ② 2차** | **해양쓰레기 예측 지도** — 1차의 100m 칸 합계(칸마다 개수 · 넓이 합 · 가장 많은 종류) × 해류·바람 격자 → 해안 구간마다 '앞으로 며칠 동안 얼마나 쌓일지'(많음 · 보통 · 적음). 해양 물리 계산은 LX 가 만들지 않는다(옛 자산 정의 그대로) |
| **누가 · 어떤 방식으로 올리나** | 광주전남이 맡긴 개발사(또는 도가 LX 에 맡기면 LX) → 우리 공간 → 서비스 올리기 → **코드 틀**(계산 코드 + 설정 한 장: 자원 · 바깥 주소 한 곳 · 자동 다시 계산). 해류 수치모델 프로그램을 통째로 돌려야 하면 **상자 통째**(점검 더 엄격 · 자원 더 큼 · 결재 둘) |
| **어디에 두나** | 계산 코드 = 광주전남 공간의 상자 하나(GPU 없음 · 처리 몫 2 · 메모리 4GB · 저장 50GB로 시작) · 해류 자료와 예측 결과 = 공간 저장 칸 · 화면 = 전남광주 AI 플랫폼 → 내 서비스 → **'우리 도가 만든 서비스'** 카드 |
| **승인** | LX 관리자 결재함 '우리 기관 서비스 올리기' — 자동 점검 다섯(권한 · 보안 약점 · 열린 문 · 자원 · 시험판 한 번) + 바깥 주소 한 곳 확인 → 승인 · 자원 배정 |
| **갱신** | ① LX 가 새 탐지 회차를 공개 → 공간 알림 → **자동 다시 계산**(도가 '자동'으로 고름) → 화면 '입력: 해양쓰레기 탐지 결과 ○월 ○일 기준'이 바뀜 ② 해류 예보가 새로 오면(제공처 주기 — **확인 필요**) 다시 계산 ③ 드론 회차처럼 **형식이 바뀌는 회차**(종류 1 → 8)는 미리 알림 → 개발사가 시험판에서 확인 → 공개 ④ 예측 코드 새 판은 같은 올리기 길, 이상하면 이전 판으로 되돌리기 |
| **폐기** | 사업이 끝나거나 바뀌면 기관 관리자가 '끄기' 요청 → 30일 내려받기 → 예측 지도 상자 · 예측 결과 · 해류 자료 지움. 탐지 서비스(1차)와 다른 기관은 그대로. 다른 해안 시도가 같은 예측을 원하면 — 전남 동의 + 관리자 승인으로 상자를 옮기거나, LX 가 1차로 다시 만들어 공개 |
| **책임** | 탐지(어디에 무엇이 얼마나) = LX · 예측(언제 어디에 쌓일지) = 광주전남 + 만든 개발사 · 서버(켜고 끄기 · 자원 · 보안) = LX 관리자. 가르는 열쇠 = 화면의 '입력 … 기준'(공간이 기록) |

## 2. 남원 영농 — 1차 경작 판정 → 2차 직불금 대상 검토 표
| | 무엇 · 누가 · 어디 |
|---|---|
| **1차(Land-XI 본체)** | 영농관리 행정서비스(서비스 2.1 — 2025 드론 · 경작/비경작). LX 프로젝트장 → LX 관리자 공개. 남원 카드 이전 순서 첫째(영농 → 도로안전 → 생활환경 — 7차 확정) |
| **공간 ① 받은 것** | 남원 관할 필지별 경작·비경작 판정 · 결과 설명서 · 새 결과 알림 |
| **공간 ③ 기관 자료** | 직불금 신청 명단(농정과 엑셀). **이름 등 개인정보가 있어** 공간 안에서만 두고, 표·보고서·내려받기에서는 가린다(원칙 59) |
| **공간 ② 2차** | **직불금 대상 검토 표** — 신청 필지 × AI 경작 판정 → '신청했는데 AI 가 비경작으로 본 필지' 목록(참고 자료). 대상인지 아닌지는 농정과가 정한다(Land-XI 는 보고서까지 — 원칙 40) |
| **누가 · 어떤 방식으로 올리나** | 농정과 담당자 → 우리 공간 → 서비스 올리기 → **설정만**: 공통 기능 '행정정보와 결합하여 비교 분석'에서 명단 올리기 → "엑셀의 어떤 열과 비교할까요?"(필지 번호 열 · 신청 여부 열) → 결과 모양 '표'. 일반 모드로 몇 번 누르면 끝(원칙 71). **코드도 상자도 없다** |
| **어디에 두나** | 명단과 표 = 남원 공간 저장 칸 · 화면 = 남원 플랫폼 → 내 서비스 → '우리 시가 만든 서비스'(농정과에만 보임 — 부서는 자기 서비스만, 원칙 38) |
| **승인** | 설정만이라 자동 점검은 '개인정보 칸이 결과로 나가는가' 하나. LX 관리자는 결재함 한 줄로 보고 승인(자원 배정 없음 — 저장 칸만) |
| **갱신** | ① 다음 해 드론 판정이 공개되면 알림 → 표 자동 다시 만듦 ② 농정과가 새 명단을 올리면 다시 만듦 ③ 표 위에 '입력: 영농관리 판정 ○년 드론 · 명단 ○월 ○일' 표시 |
| **폐기** | 그 해 검토가 끝나면 명단 지우기(보관 기간은 기관이 정함 — 개인정보라 짧게 권함) · 표는 보고서로 남김 · 서비스를 더 안 쓰면 끄기 → 칸 정리. 본체·다른 부서 영향 0 |
| **책임** | 판정(경작인가) = LX · 대상 여부 = 농정과 |

## 3. 두 예가 보여 주는 것
| | 광주전남 해양쓰레기 | 남원 영농 |
|---|---|---|
| 2차 방식 | 코드 틀(계산 코드가 꼭 필요) | 설정만(공통 비교 기능으로 충분) |
| 공간에 생기는 것 | 가벼운 칸 + **상자 하나** | 가벼운 칸만 |
| 바깥 연결 | 해류 예보처 한 곳 | 없음 |
| 만드는 사람 | 기관이 맡긴 개발사(또는 LX) | 기관 부서 담당자 |
| 이 서버 자원 | 처리 몫 2 · 메모리 4GB · 저장 50GB(제안) | 저장 조금 |
→ 대부분의 2차는 남원처럼 '설정만'으로 되고, 코드가 필요한 것만 상자를 쓴다 — 기술 방식 ⓒ(`tech.md`)를 추천하는 까닭.
