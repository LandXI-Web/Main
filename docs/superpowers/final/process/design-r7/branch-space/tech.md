## 0. 한 줄
**추천은 ⓒ — 모든 기관은 '가벼운 칸'(자료 칸 · 저장 폴더 · 서비스별 키)으로 나누고, 2차를 코드로 올리는 기관만 그 공간 안에 '상자'(컨테이너 — 도커)를 둔다.** 상자에는 GPU 를 주지 않는다(AI 분석은 LX 대기열로만). 2차는 기관이 맡긴 개발자(또는 LX)가 공간에 올리고, **LX 관리자가 자동 점검 결과를 보고 승인하면서 자원을 나눠 준다.** 폐기는 공간 이름 하나로 상자·칸·폴더·키를 한꺼번에 지운다.

## 1. 지금은 어떻게 나뉘어 있나(평가)
| 무엇 | 지금 | 2차를 올리기에 |
|---|---|---|
| 기관 사이 자료 | 한 데이터베이스 · 같은 표를 같이 쓰고, **줄마다 기관 표시 + 데이터베이스가 자기 기관 줄만 내주는 규칙**(화면 쪽 계정은 이 규칙을 넘을 수 없음). AI 결과 표는 기관별로 칸이 나뉘어 있다(새 기관은 공용 칸으로 감 — 앞 설계에서 지적) | 1차 결과 분리는 이미 됨. **기관 자료·2차 결과를 둘 기관 전용 칸은 없음** |
| 결과 파일 | 데이터 폴더 아래 기관 이름 폴더 | 기관 자료 폴더는 없음 |
| 기관 모습 | 기관마다 마크·이름·색·글 한 벌 | 그대로 씀 |
| 서비스별 키 | 없음(설계만 — 8차 확인 대기) | 공간 안 결과 받기에 같은 키 |
| 상자(컨테이너) | 이 PC 도커에서 Land-XI 묶음 둘(자료 저장 · 언어 모델)과 Land-XI 밖 묶음 둘이 **묶음 이름으로 나뉘어** 함께 돈다 — 묶음 단위로 켜고 끄는 방식은 이미 이 PC 의 일상 | 기관 묶음을 하나 더 두는 것은 같은 방식 |
| GPU 와 상자 | 이 PC 의 도커는 상자마다 GPU 를 나눠 주지 못한다(상자 안에 두 장이 다 보임 — 09-26 실측 기록) · 전력 규칙은 한 장씩 | **상자에 GPU 를 주면 전력 규칙이 깨질 수 있다** → 주지 않는다 |

## 2. 세 길 — 무엇으로 나누나
| | ⓐ 가벼운 칸만 | ⓑ 모든 기관에 상자 | **ⓒ 둘 다 — 상자는 필요한 기관만(추천)** |
|---|---|---|---|
| 한 줄 | 기관마다 자료 칸(데이터베이스 안 기관 전용 칸) · 저장 폴더 · 서비스별 키만 나눈다 | 기관마다 상자 묶음(자기 망 · 자기 저장 · 필요하면 자기 데이터베이스)을 통째로 둔다 | 모든 기관 = ⓐ. 2차를 **코드로** 올리는 기관만 그 공간 안에 상자 묶음을 더한다 |
| 2차 코드를 돌릴 수 있나 | **못 함** — 코드는 결국 본체 안에서 돌아야 하고, 그러면 잡동사니가 된다. '설정만' 2차(공통 비교 기능)는 됨 | 됨 | 됨(설정만 2차는 상자 없이, 코드 2차는 상자에서) |
| 이 서버 자원 | 거의 0(칸과 폴더뿐) | 기관마다 상자가 늘 떠 있음 — 기관이 늘수록 메모리·관리가 늘어남. 기관마다 데이터베이스까지 두면 더 큼 | 상자는 2차가 있는 기관만. 데이터베이스는 지금 것 하나에 기관 칸으로(따로 띄우지 않음) |
| 보안 | 데이터베이스 권한으로 기관 칸끼리 막음 — 지금 규칙의 연장 | 상자마다 망·저장이 따로라 가장 단단함 | 칸 = 데이터베이스 권한, 코드 = 상자로 막음(4절 다섯 장치) |
| 유지관리 | 쉬움 — 다만 기관 코드가 본체로 들어오면 본체가 무거워짐 | 상자 수만큼 손이 감 | 손이 가는 상자는 2차가 있는 곳만 |
| 폐기 | 칸 지우기 · 폴더 지우기 · 키 끊기 | 묶음 통째로 내리고 지우기 | **공간 이름 하나로** 상자 묶음 · 칸 · 폴더 · 키를 한꺼번에(5절) |
| 맞는 경우 | 남원 영농처럼 2차가 '설정만'인 기관 | 기관이 매우 많고 대부분 자기 코드를 돌릴 때 | 지금(기관 4곳 · 코드 2차는 광주전남 예측 지도가 첫 후보) |

**추천 ⓒ 의 까닭**: 남원 직불금 검토 표처럼 대부분의 2차는 공통 기능으로 '설정만' 하면 되고(상자 0), 해양쓰레기 예측 지도처럼 계산 코드가 꼭 필요한 것만 상자에 넣는다. 기관을 만들 때 생기는 것은 가벼운 칸뿐이라 기관이 늘어도 서버 부담이 거의 없다.

## 3. 2차는 누가 · 어떤 방식으로 올리나
| 방식 | 무엇을 올리나 | 누가 | 공간에 생기는 것 | 점검 |
|---|---|---|---|---|
| **설정만** | 화면에서 고르는 것뿐 — 어느 1차 결과 × 어느 기관 자료 · 공통 기능(행정정보와 결합하여 비교 분석 · 구간별 합계 · 보고서) · 결과 모양(표 · 지도 층 · 숫자 하나) | 기관 부서 담당자 · 기관 관리자 | 설정 한 장 + 결과 칸 | 개인정보 칸이 결과로 나가지 않는지만 |
| **코드 틀**(기본) | LX 가 주는 틀(입력 = 결과 받기 + 기관 자료 · 출력 = 지도 층 · 표 · 숫자 하나 · 끝났다는 신호)에 계산 코드를 넣은 묶음 파일 + 설정 한 장(필요한 자원 · 바깥 주소 · 다시 계산 방식) | 기관이 맡긴 개발자 · LX(기관이 맡기면) | LX 가 정해 둔 바탕 위에 상자 하나를 만들어 띄움 | 자동 점검 다섯(4절) + 시험판 한 번 |
| **상자 통째** | 이미 만들어진 프로그램을 상자 그대로(예: 해류 수치 계산 프로그램을 통째로 돌려야 할 때) | 기관이 맡긴 개발자 | 그 상자 | 자동 점검 다섯 + 관리자가 바탕·크기를 한 번 더 봄 · 자원이 크면 결재 둘 |

- **올리는 곳은 화면**: 기관 분기 플랫폼 → 우리 공간 → 우리 서비스 → '서비스 올리기'(묶음 파일 하나 + 설정 칸 몇 개). 명령줄로 서버에 들어가 올리는 길은 없다(원스톱 — 원칙 24 · 개발자에게 서버 계정을 주지 않는다).
- **화면은 기관 플랫폼 틀이 그린다**(갈림길 3 추천): 2차는 지도 층·표·숫자 하나·기준 시점만 내고, 카드·지도·목록 모양은 기관 플랫폼이 모든 기관에 같은 틀로 보여 준다(원칙 79). 2차 개발자는 화면을 만들지 않아도 된다.
- **새 판**: 같은 길(올리기 → 점검 → 승인)로 올리고, 바꾼 뒤 이상하면 **이전 판으로 되돌리기** 한 번.

## 4. LX 관리자 — 승인 · 자원 배정 · 감시(원칙 72 · 84)
**승인 한 건에서 보는 것**(결재함 종류 '우리 기관 서비스 올리기' 한 줄 → 서랍)
1. 무엇 · 누가 만들었나(기관 · 맡긴 개발사 · LX) · 어느 1차 결과와 어느 기관 자료를 쓰나
2. 자원 요청(처리 몫 · 메모리 · 저장)과 지금 이 서버의 '기관 공간 몫' 남은 양
3. 바깥 연결 주소(예: 해류 예보처 한 곳) — 적힌 곳만 열린다
4. **자동 점검 다섯** 결과: ① 상자 안 프로그램이 관리자 권한으로 돌지 않음 ② 알려진 보안 약점 검사 ③ 열어 두는 문 없음(바깥에서 상자로 들어올 길 0) ④ 크기·자원 요청이 배정 범위 안 ⑤ **시험판 한 번** — 1차 결과 한 회차로 돌려 출력이 틀(지도 층·표·숫자)에 맞고 개인정보 칸이 결과에 없음
5. 승인 / 반려(사유 필수 — 신청한 기관 관리자·개발자에게 그대로)

**상자에 주는 것 · 안 주는 것 — 다섯 장치**
| 장치 | 무엇 |
|---|---|
| 망 | 공간마다 자기 망. 상자가 닿는 곳은 **공간 안 결과 받기 한 곳 + 허용한 바깥 주소**뿐. 본체 데이터베이스 · 다른 공간 · 언어 모델 · 작업 대기열 · 이 PC 파일 = 0 |
| 자료 | 자기 기관 칸(데이터베이스 권한이 그 칸만) · 자기 저장 폴더 한 칸만 |
| GPU | **0.** AI 분석이 필요하면 '분석 맡기기'로 LX 대기열에(순번 · 관리자 승인 · 무상 — 원칙 60·83). 2차가 자기 AI 모델을 GPU 로 돌려야 한다면 그것은 LX 프로젝트로 1차가 될 후보 |
| 처리 몫 · 메모리 | 상자마다 배정한 만큼만(넘으면 느려지거나 멈추고, 관리자·기관에 알림) |
| 권한 | 관리자 권한 없음 · 바탕은 읽기만 · 비밀 값은 공간 키 하나뿐 |

**자원 배정 — 한도가 아니라 하드웨어 나눠 주기**(원칙 83 · 84 · 66): 기관의 1차 이용에는 한도를 두지 않는다. 상자는 LX 서버의 실제 처리기·메모리를 쓰므로 LX 관리자가 하드웨어를 나눠 준다 — 직원 자원 할당과 같은 '배정 → 더 필요하면 요청 → 승인' 모양.
| 값(초기 제안 · 설정 한 곳) | 이 PC(A6000) 지금 | A100 이 오면 |
|---|---|---|
| 기관 공간 전체 몫 | 처리 몫 16 · 메모리 64GB · 저장 500GB — 이 PC 의 1/8 쯤. 나머지는 AI 분석·학습·언어 모델·서버 몫 | 상자 묶음은 그대로 옮겨 감 — '어느 서버에서 돌리나' 한 줄만 바꿈 |
| 상자 하나 기본 | 처리 몫 2 · 메모리 4GB · 저장 50GB | 같은 값에서 시작 |
| 넘을 때 | 기관 관리자 요청 → LX 관리자 승인 | 같음 |
기관 화면에는 이 값을 '한도'로 보이지 않고 **사용 현황**(우리 서비스가 이번 달 얼마나 돌았나 · 저장 얼마)으로 보인다.

**감시**: LX 관리자 대시보드 → 기관 → **기관 공간** 목록(시안 `shots/new-admin-spaces.png`) — 공간마다 켜짐/꺼짐 · 올라간 2차 · 자원 사용(배정 대비) · 마지막 실행과 결과 · 바깥 연결 · 오류. 오류·자원 넘침·점검 실패는 경보 한 줄 + 기관 관리자·만든 개발자 알림. 같은 서랍에서 **끄기 · 다시 켜기 · 폐기**.

## 5. 폐기 — 공간 통째로 끄고 지우기
| 무엇을 | 어떻게 | 남는 것 |
|---|---|---|
| 2차 하나 | 끄기 → 내려받기 기간(제안 30일) → 그 상자 · 그 결과 · 그 키 지움 | 1차 · 다른 2차 · 기관 자료 |
| 공간 통째(기관 해지) | 모든 상자 끄기 → 내려받기 기간(제안 90일) → **공간 이름 하나로** 상자 묶음 · 기관 칸 · 저장 폴더 · 키 · 개발자 계정을 한꺼번에 지움(두 사람 결재) | 기록 한 줄 · LX 모델 · LX 영상 |
| 본체에서 지울 것 | **없음** — 본체에 기관 코드가 없으므로 | — |
지우는 일은 늘 **그 공간 이름으로만** 한다. 같은 도커에 다른 묶음(Land-XI 의 자료 저장·언어 모델과 Land-XI 밖 묶음)이 함께 돌기 때문에, 이름 없이 '안 쓰는 것 모두 지우기' 같은 명령은 쓰지 않는다(지금 Land-XI 묶음 설정 파일에도 같은 경고가 적혀 있다).

## 6. 유지관리 — 본체를 고쳐도 2차가 안 깨지게
- 2차는 결과 설명서의 칸과 공간 안 결과 받기로만 1차를 읽는다(본체 내부 표에 직접 붙지 않음).
- 형식이 바뀌는 회차는 형식 버전 + 미리 알림 + 시험판(`matching.md` 4절).
- 2차가 멈추면 그 공간만 멈춘다 — 본체·다른 공간 영향 0. 다시 켜기는 관리자 서랍에서 한 번.
- 백업은 공간 단위(기관 칸 · 저장 폴더). 지금 데이터베이스 백업이 아직 설정되지 않은 것(완전체 기준표의 '운영' 칸)과 함께 정해야 한다.

## 7. 확인 못 한 것(정직하게)
- 상자를 이 PC 에서 실제로 띄워 보지 않았다 — 처리 몫·메모리 제한은 도커의 기본 기능이라 될 것으로 보지만 실측 전이다.
- **저장 폴더 크기를 딱 막는 장치**는 이 PC(도커 데스크톱 · WSL2)에서 되는지 확인하지 못했다 → 우선 감시·경보로 다루는 것을 제안한다.
- 보안 약점 검사 도구는 아직 고르지 않았다(바깥 인터넷 없이 도는 것이어야 함).
- A100 서버의 운영체제·상자 실행 방식 — 장비가 와야 확정.
- 바깥 연결 허용(해류 예보처)의 실제 주소 · 공공기관 망 정책.
