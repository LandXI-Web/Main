# 1차 결과를 2차가 '알고 매칭'하는 곳 — 공간 안 결과 설명서 · 결과 받기 · 새 결과 알림

> 2026-10-01 · 설계 7차(오퍼스 5.5). 지위: **사용자 확인 전 설계**(코드 수정 0 · GPU 실행 0). 어느 플랫폼: **기관 분기**(보는 곳) — 내용은 Land-XI 의 1차 서비스에서 저절로 만들어진다. 종류: 결과 설명서 화면은 **[화면]**(시안 `shots/new-gj-guide.png`), 칸·규칙은 **[문서]**.
> 사용자 원문(10-01, 관계-1): "해류 모델이 중요한 게 아니라 해양쓰레기 예측 지도를 만들기 위해서는 **AI 분석 결과의 정보들을 알고 매칭해야 한다는 거지. 그걸 어디서 확인하느냐가 중요한데.**"
> 근거: 원칙 69(서비스별 키 · 내보내는 것은 AI 결과) · 59(내려받기는 정책과 함께) · 68(1차가 갱신되면 2차도) · 외부 연동 API 설계(내보내기 형식 · 결과 한 건에 붙는 것) · 실제 결과 파일 두 판(여수 해양쓰레기 2025 항공 · 2026 드론)을 이 PC 에서 직접 열어 잰 값.
> 그림: `shots/space-2-matching.png` · 시안 `shots/new-gj-guide.png`.

## 0. 한 줄
**2차를 만드는 사람은 기관 공간 안의 '결과 설명서' 한 장에서 1차 결과의 여섯 가지 — 무엇이 · 어디 · 언제 · 어떤 형식 · 믿을 만한 정도 · 버전 — 를 확인하고, 같은 공간 안의 '결과 받기'(서비스별 키)로 가져가며, 새 회차가 공개되면 공간 안에서 알림을 받는다.** 설명서는 사람이 따로 쓰는 문서가 아니라 1차 서비스를 공개할 때 저절로 만들어지고, 회차·형식이 바뀌면 같이 바뀐다.

## 1. 왜 '알고 매칭'이 어려운가 — 같은 서비스, 두 판(실측)
여수 해양쓰레기 결과 파일 두 판을 이 PC 에서 직접 열었다(2026-10-01). 같은 '해양쓰레기 탐지'인데 판마다 이만큼 다르다.

| | 2025 항공 판(지금 광주전남에 공개된 회차) | 2026 드론 판(LX 가 가진 다음 판 · 공개 전) |
|---|---|---|
| 조각 수 | 1,857 | 2,078 |
| 종류 | **1가지**(스티로폼) | **8가지**(스티로폼 · 병 모양 부표 · 플라스틱 상자 · 기타 쓰레기 · 로프 · 청색 부표 · 그물 · 적색 부표) |
| 종류 이름 표기 | 대문자로 시작(Styrofoam) | 소문자(styrofoam) — 그대로 합치면 '스티로폼'이 둘로 갈림 |
| 조각에 붙은 칸 | 5개 | 8개(색 · 겉모양 표시 등 3개 더) |
| 신뢰 값 가운데값 | **0.115**(0.05–0.72) | **0.71**(0.11–0.87) |
| 신뢰 값이 빈 조각 | 171 | 308 — 까닭은 확인 필요 |
| 조각 넓이 가운데값 | 7.2㎡ | 1.1㎡(영상이 더 촘촘해서) |
| '신뢰 0.5 이상만' 쓰면 | **53건(2.9%)만 남음** | 1,539건(74.1%) 남음 |

→ 설명서 없이 2차를 만들면: 2025 판에 없는 종류를 0 으로 세고, 스티로폼이 두 줄이 되고, '신뢰 0.5 이상'으로 자르면 2025 판은 거의 다 사라진다. 예측 지도는 이런 입력의 차이를 모른 채 계산하게 된다. **사용자가 짚은 "AI 분석 결과의 정보를 알고 매칭"이 바로 이것**이고, 그래서 확인하는 곳이 회차마다 정확해야 한다.

## 2. 확인하는 곳 — 기관 공간 안 '결과 설명서'
**어디**: 기관 분기 플랫폼 → 왼쪽 '우리 공간' → '결과 설명서' 탭 → 서비스 고르기(이 기관에 켜진 1차 서비스만). 기관 관리자와 기관이 맡긴 개발자 계정에만 보인다(부서 사용자 화면에는 없음). 바깥의 기관 자기 시스템을 만드는 개발자도 같은 설명서를 본다(API 와 한 벌).

**여섯 칸**(시안 `shots/new-gj-guide.png` 의 왼쪽)
| 칸 | 무엇을 적나 | 해양쓰레기 실태조사 서비스의 예 | 어디서 저절로 채워지나 |
|---|---|---|---|
| **무엇이** | 결과 종류 목록 — 한글 이름 · 개발용 코드 · 한 줄 뜻 · **이번 회차에 있는 종류 표시** | 스티로폼(styrofoam) — 부표·어구에서 떨어진 발포 조각 · 이번 회차에 있음. 나머지 7종은 '다음 회차부터' | 모델의 종류 목록 + 프로젝트장이 공개 때 쓴 한 줄 뜻 |
| **어디** | 모양(조각 폴리곤 · 100m 칸 합계) · 좌표계 · 범위(이 기관 관할 안만) · 필지·읍면동 연결 여부 | 조각 + 100m 칸 합계 둘 · 경위도 기본(국내 평면 고를 수 있음) · 광주전남 관할 해안 · 읍면동 이름 붙음 | 결과 형식 · 기관 관할 |
| **언제** | 회차마다 촬영 시기 · 분석한 날 · 공개한 날 — 2차가 '기준 시점'으로 쓰는 값 | 2025 항공 · 분석 2026.06.08 | 영상 기록 · 작업 기록 · 공개 결재 |
| **어떤 형식** | 받는 법(공간 안 결과 받기 · 파일) · 형식(GeoJSON · SHP · GeoPackage · 필지 CSV · 요약 숫자) · **칸 목록**(한국어 이름 · 개발용 이름 · 단위 · 예) | 결과 번호 · 종류 · 신뢰 · 넓이(㎡) · 읍면동 · 결과 확인 표시 · 회차 · 서비스 버전 / 100m 칸: 개수 · 넓이 합 · 평균 신뢰 · 가장 많은 종류 · 그 비율 | 표준 결과 형식(API 설계와 같은 칸) |
| **믿을 만한 정도** | 신뢰 값의 뜻(AI 가 붙인 점수 · 확률이 아님 · **회차·영상 종류마다 분포가 다름**) · 결과 확인 표시(확인 전 · 확인됨 · 고침) · 지운 조각은 '지운 목록'으로 | 2025 항공 판 가운데값 0.115 — "다른 회차와 같은 선으로 자르지 마십시오" | 결과 확인 기록 · 회차별 신뢰 분포(서버가 계산) |
| **버전** | 서비스 버전 · **형식 버전** · 바뀐 점 기록 · **다음 바뀜 예고**(적용 예정일) | 서비스 1.2 · 형식 1 · 예고(예시): 드론 회차부터 종류 1 → 8, 칸 3개 추가 | 서비스 버전 기록 · 공개 결재의 '형식이 바뀜' 표시 |

**오른쪽**(시안): 예시 한 건(조각 하나 · 100m 칸 하나의 실제 모양) · 받는 곳(공간 안 결과 받기 · 이 서비스 키 — 가려서 표시) · 새 결과 알림(켜짐 → 받는 우리 서비스: 해양쓰레기 예측 지도).

**누가 쓰나**: 사람이 손으로 쓰는 칸은 **종류마다 한 줄 뜻**과 **바뀐 점 한 줄**뿐이다 — LX 프로젝트장이 서비스 공개 요청 때 적고(입력 최소 — 원칙 49), LX 관리자가 공개 결재 때 빈칸 표시를 본다. 나머지는 서버 기록에서 저절로.

**AI 도우미로도 묻는다**: 공간 안에서 "드론 회차의 buoy_blue 는 뭐야?", "2025 판 신뢰 값은 어떻게 읽어?"를 물으면 도우미(vLLM)가 이 설명서를 근거로 답한다 — 숫자는 설명서·결과에서만(지어내지 않음), 다른 기관 것은 0.

## 3. 가져가는 곳 — 공간 안 결과 받기(서비스별 키)
- 2차는 1차를 **이 길로만** 읽는다. 본체의 내부 표에 직접 붙지 않는다 → 본체를 고쳐도 2차가 안 깨진다.
- 키는 **기관 × 서비스** 하나(원칙 69 · API 설계와 같은 키). 공간 안 2차에 쓰는 키는 공간 밖으로 나가지 않는 '공간용'으로 따로 발급 — 신청·승인은 2차 승인과 한 번에.
- 받을 수 있는 것: 그 서비스의 그 기관 관할 결과(지난 회차 포함) · 바뀐 것만(새로 · 바뀜 · 지움 세 묶음) · 100m 칸 합계 · 요약 숫자. 영상 · 학습 자료 · 다른 기관 · 다른 서비스 = 0.
- **종류 이름은 받을 때 하나로 맞춰 준다**(Styrofoam / styrofoam → 스티로폼 · styrofoam). 원래 파일의 표기 차이를 2차가 떠안지 않게.
- **어느 회차를 읽었는지 공간이 기록한다.** 2차 화면의 '입력: 해양쓰레기 탐지 결과 2026.06.08 기준'은 2차가 스스로 적는 글이 아니라, 2차가 실제로 받아 간 회차를 공간이 적어 붙이는 것이다 → 탐지가 틀렸는지(LX 몫) 예측이 틀렸는지(기관 몫)를 가르는 열쇠가 믿을 만해진다.

## 4. 새 결과가 나오면 — 공간 안 알림과 다시 계산
| 순서 | 무엇 | 누가 · 어디 |
|---|---|---|
| 1 | LX 관리자가 새 회차를 승인·공개 → 결과 버전이 올라감 | Land-XI 결재 |
| 2 | 그 결과를 받는 공간마다 알림 한 번 — ① 기관 화면 알림 한 줄("해양쓰레기 탐지 새 결과 · 2026.○○.○○ 기준") ② 그 결과를 쓰는 2차에 '다시 계산' 신호 ③ LX 관리자·프로젝트장 화면에 "이 결과를 쓰는 우리 기관 서비스 1곳에 알림 감" | 공간 · 본체 |
| 3 | 2차가 설명서의 **형식 버전**을 확인 — 같으면 바로, 다르면 멈추고 기관에 "형식이 바뀌어 확인 필요" | 2차(자동) |
| 4 | 결과 받기(바뀐 것만) → 다시 계산 → 화면의 '입력: ○○ 기준'과 계산 시각이 바뀜 | 2차 · 공간 |
| 5 | 자동으로 다시 돌지, 담당자가 '다시 계산'을 누를지는 **기관이 2차마다 고른다** | 기관 관리자 |

**형식이 바뀌는 회차는 미리 알린다**(드론 회차처럼 종류가 늘거나 칸이 바뀔 때): 공개 결재 화면에 '형식이 바뀜 · 이 결과를 쓰는 2차 1곳' 표시 → 공개 전에 설명서에 '다음 바뀜 예고'와 적용 예정일 → 2차 개발자는 공간의 **시험판**(새 형식 결과로 미리 돌려 보는 자리)에서 확인 → 공개. 시험판은 화면에 보이지 않고 결과도 남지 않는다.

## 5. 확인 못 한 것(정직하게)
- 2025 항공 판의 신뢰 값이 왜 낮고(가운데값 0.115) 빈 조각이 왜 있는지 — 학습·분석 기록에서 확인하지 못했다.
- 2026 드론 판을 언제 광주전남에 공개할지(지금 공개된 것은 2025 항공 1,857건 하나).
- 종류 여덟의 한글 이름은 코드 이름을 옮긴 것이다 — 정식 이름은 담당 프로젝트장이 정해야 한다.
- 결과 설명서·공간 안 결과 받기·알림은 **설계만** 했다(만들지 않음).
