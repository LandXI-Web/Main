## 0. 한 줄
**ECW 하나만 빼고 나머지 형식은 지금도 읽힌다.** 다만 서버 안에서 영상을 읽는 쪽(지도 · 분석)과 영상을 바꾸는 쪽(개요 만들기 · 변환 명령)이 서로 다른 GDAL 묶음을 써서, **JP2 는 읽히는데 바꾸지는 못하는** 어긋남이 있다. ECW 는 서버에서 읽으려면 **상용 서버 라이선스**가 필요하고, 무료 길은 **보내는 쪽 PC 에서 QGIS 로 TIF 로 바꿔 올리는 것**이다. 그런데 지금 화면은 ECW 를 받는다고 안내하고, 20GB 까지 다 올린 뒤에야 "읽을 수 없습니다"라고 알린다 — 먼저 고칠 곳이다.

**어긋남 둘 — 형식보다 먼저 고칠 것**
1. **읽는 쪽과 바꾸는 쪽이 다른 GDAL.** 서버 프로그램(파이썬)은 GDAL 3.10(JP2 읽기 들어 있음)을, 개요 · 변환 명령은 다른 묶음의 GDAL 3.12(기본 묶음 — JP2 읽기 빠짐)를 쓴다. 표준 변환은 **한 묶음만** 쓰게 한다 — 파이썬 쪽으로 바꾸기(이번 시험에서 JP2 → COG 변환을 파이썬 쪽만으로 해 봤다 · 됨) 또는 명령 쪽에 무료 JP2 구성요소 추가(conda-forge `libgdal-jp2openjpeg`). 두 묶음의 판(3.10 · 3.12)도 장비 대장처럼 한 곳에 적는다.
2. **ECW 를 '받는다'고 말하는 화면.** 분석 의뢰 화면의 안내 'TIF · JP2 · ECW · JPG(좌표 파일과 함께)'와 받는 형식 목록에 ECW 가 있다. 그래서 ECW 를 끝까지(한 파일 20GB 까지) 올린 다음에야 "ECW 파일은 이 서버에서 아직 바로 읽을 수 없습니다"가 뜬다. 결정(2절) 전까지는 **파일을 고르는 순간** 안내한다 — "ECW 는 TIF 로 바꿔 올려 주세요(바꾸는 법 보기)". 결정이 ⓒ(서버 라이선스)이면 그때 받는다.

**좌표계 — 지금은 '위치로 추정'이 잦다**
- 시험한 실제 영상 셋(25cm 항공 · 밀양 드론 · 본사 드론) 모두 **좌표계가 표준 번호로 읽히지 않았다.** 항공 도엽은 좌표계 기록이 아예 없고(TFW 만), 드론 둘은 이름만 다른 'TM 중부원점(127° · 38° · 200,000 · 600,000)'이다. 지금 서버는 이런 파일을 후보 좌표계로 옮겨 보아 관할 안에 떨어지는 것을 고른다(관할 안이면 맞을 가능성이 높지만, 원점이 비슷한 좌표계끼리는 헷갈릴 수 있다).
- 표준 변환 때는 **파일 안 좌표계의 원점 · 가산 값 · 타원체를 읽어 표준 번호를 붙인다**(예: 위 드론 둘 → GRS80 중부원점). 기록이 아예 없는 파일만 지금처럼 위치로 추정하고, 화면에 '위치로 확인'을 그대로 보인다.

## 2. ECW — 서버에서 바로 받을 수 있나
**결론: 지금은 못 받는다. 서버에서 받으려면 Hexagon(옛 ERDAS)의 서버용 라이선스를 사야 한다.**
- ECW 를 읽는 프로그램은 Hexagon 의 ECW/JP2 SDK 하나뿐이다(공개 구현 없음). GDAL 도 이 SDK 를 끼워서만 ECW 를 읽는다.
- **데스크톱에서 읽기는 무료**, **서버에서 읽기는 유료**다. GDAL 공식 설명: "For Desktop usage, decoding any sized ECW/JP2 image is made available free of charge. To compress, deploy on a Server platform, or decode unlimited sized files on Mobile platforms a license must be purchased from Hexagon Geospatial."
- 서버 라이선스는 두 가지(서버 읽기 전용 — 직접 쓰는 곳용 · 재배포용)가 있고, 값은 공개되어 있지 않다(영업 문의). 공개 설명상 **서버의 CPU 코어 수**에 따라 값이 달라진다 — 이 PC 는 64코어, A100 서버가 오면 그 서버 기준으로 다시 따져야 한다.
- 이 PC 의 QGIS 3.28 에는 ECW 읽기 구성요소(SDK 5.5)가 들어 있고, 실제 ECW(구미 3cm 드론 · 가로 41,812 · 세로 56,455칸)를 열고 바꾸는 데 성공했다. 이것은 **데스크톱 무료 범위**라 직원 · 기관 PC 에서 쓰는 것은 괜찮지만, 서버(Land-XI)가 이 구성요소를 가져다 쓰면 서버 사용이 된다 — **쓰지 않는다.**

**ECW 를 표준으로 바꾸면 오히려 커진다(실측)**
| 실제 ECW 1개(구미 · 3cm 드론) | 크기 | 걸린 시간(CPU 4개) |
|---|---|---|
| ECW 원본(가로 41,812 · 세로 56,455칸 · 그중 영상이 있는 곳 약 42%) | 260.5MB(색 3밴드 원래 크기 7.1GB 의 약 3.7%) | — |
| 표준(COG · JPEG 90) | 355.2MB(**ECW 의 1.36배**) | 약 6분 |
| (참고) COG · WEBP 80 | 192.4MB(ECW 의 0.74배) — 화질 기준 탈락(`diet.md` 4절) · 읽기 느림 | 약 8분 반 |
- 표준(JPEG 90)으로 바꾼 화질: ECW 를 풀어 놓은 그림과 비교해 PSNR 39.5~41.5dB · SSIM 0.987 이상(영상이 있는 곳 네 군데 2,048칸씩) — 다른 표본과 같은 수준이다.
- ECW 는 웨이블릿 압축이라 같은 화질에서 JPEG 보다 훨씬 작다. **ECW 로 오는 영상은 표준으로 바꾸면 저장이 늘어난다** — 보관 장부(`policy.md`)에서 ECW 출처는 '늘어남'으로 따로 센다. 대신 서버가 읽을 수 있게 되고, 지도 · 분석이 다른 영상과 같은 길로 간다.

## 3. 확인 못 한 것
- Hexagon 서버 라이선스의 실제 값 · 코어 셈법 · 공공기관 조건(견적 요청 필요 — 영업 문의).
- 기관 PC 에 깔린 QGIS 판마다 ECW 구성요소가 들어 있는지(이 PC 의 3.28 은 들어 있음). 안 열리면 LX 담당 직원이 대신 바꾸는 길(ⓐ 안)으로 받는다.
- 국토지리정보원 · 지자체 성과물의 형식 비율(ECW 가 얼마나 자주 오는지) — 운영하며 센다.
