## 0. 한 줄
**추천: 표준 한 벌 = COG · JPEG 품질 90 · 개요 포함 · 빈 칸은 마스크.** 25cm 항공 도엽은 원래 크기의 **9.0~13.3%**, 드론 정사 결과물(LZW)은 원래 파일의 **10.6~18.0%** 가 되고(개요까지 넣은 크기), 화질은 원본 대비 평균 차이 지표(PSNR) **39.8~44.4dB** · 구조 유사도(SSIM) **0.980 이상** 으로 눈으로는 원본과 구별이 어렵다. 무손실(ZSTD)은 22~42% 밖에 못 줄이고, 더 세게(JPEG 80 · WEBP 80) 줄이면 복잡한 항공 영상에서 나무 · 풀의 잔결이 뭉개진다. **분석용 · 보기용을 나누지 않는다** — 한 벌이 둘 다 맡는다.

## 3. 표준본이 빨라지는 것 — 크기만이 아니다
| 읽기(512칸 한 조각 / 16분의 1 축소 화면 한 장) | 원본 | 표준(JPEG 90) |
|---|---|---|
| 밀양 드론 한 장(1.8GB · LZW · 줄 단위 · 개요 없음 · 처음 읽을 때) | 0.22초 / **5.7초** | 0.004초 / 0.002초(드론 ② 표준본) |
| 25cm 항공 도엽(무압축 · 개요 없음 · 한 번 읽은 뒤) | 0.005초 / 0.007초 | 0.005초 / 0.006~0.014초 |
- 드론 정사 결과물은 대부분 '줄 단위 LZW · 개요 없음'으로 온다(이 PC 의 드론 원본 455장 가운데 454장이 줄 단위, 431장은 개요가 없다). 이런 파일은 지도를 축소할 때마다 파일 전체를 훑어 수 초가 걸리고, 지금 의뢰 화면은 개요 없는 큰 영상(4억 칸 넘음)의 미리 보기를 아예 만들지 않는다. **표준본은 같은 화면을 수천분의 1초에 연다** — 체감 성능(원칙 3 'Hyper Performance')에 바로 걸린다.
- 항공 도엽은 무압축이라 한 조각 읽기는 원래도 빠르지만, 크기가 10배라 디스크를 그만큼 더 쓴다.

## 4. AI 분석에 주는 영향 — 기준 제안(직접 분석은 하지 않음)
GPU 를 쓰지 않는 조건이라 분석을 돌려 비교하지 못했다. 대신 화질 기준을 제안하고, GPU 차례가 올 때 확인할 방법을 정해 둔다.
- **분석 입력 화질 기준(제안)**: 원본 대비 PSNR **38dB 이상** · SSIM **0.97 이상**. JPEG 90 은 네 표본 모두 통과(최저 39.8dB · 0.980), JPEG 80 과 WEBP 80 은 복잡한 항공 표본에서 탈락(37.4dB · 0.965 / 36.8dB · 0.952).
- 근거 셋: ① 우리가 이미 쓰는 학습 원천 일부가 JPEG 압축본이다 — 익산 1.36cm 드론(차량 라벨 원천)은 원래 크기의 8~11% 인 JPEG 타일 파일이다(라벨을 이 압축본 위에서 달았다). ② ECW 원본도 이미 손실 압축(원래 크기의 약 3.7%)이다. ③ 표준 변환은 해상도를 바꾸지 않는다 — 작은 물체(차 · 비닐하우스 모서리)에 가장 크게 걸리는 것은 해상도이고, 압축 잡음이 주는 영향은 아래 방법으로 직접 확인한다.
- **GPU 차례가 올 때 확인할 것(지금 하지 않음)**: 같은 도엽 10장(항공 5 · 드론 5)을 원본과 JPEG 90 으로 각각 분석해, 탐지 건수와 위치 일치율(겹침 50% 이상 짝)을 비교한다. 일치 98% 이상이면 확정, 못 미치면 JPEG 95 로 올린다. 분석 대기열의 한가한 때 한 장씩(전력 규칙).
- 새 영상은 **분석도 표준본으로** 한다 — 같은 영상으로 다시 분석하면 같은 결과가 나오게(원본은 정해진 기간 뒤 지워지므로).
