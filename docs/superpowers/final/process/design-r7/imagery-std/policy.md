## 0. 한 줄
**받은 영상은 서버가 표준본(COG · JPEG 90) 한 벌로 바꾸고, 지도 · AI 분석 · 기관 지도는 그 한 벌만 읽는다. 원본은 표준본 확인 뒤 30일 두고 정리 목록에 올려 LX 관리자가 지운다.** 규칙은 관리자 설정 한 곳. 지금 이 PC 에 쌓인 영상 5,907GB 에 적용하면 **568~881GB(85~90% 줄어듦 · 추정)** 이지만, 이미 쌓인 LX 원본을 지울지는 사용자가 정한다.

## 1. 표준 흐름 — 다섯 단계
| 단계 | 무엇 | 누가 · 언제 | 남는 것 | 지금과 다른 점 |
|---|---|---|---|---|
| ① 올리기 | 직원(데이터 올리기) · 기관(분석 의뢰)이 파일을 올림 | 사람 | 원본(임시 자리) · 파일 지문 | ECW 는 **고르는 순간** 안내(`formats.md` 2절) |
| ② 파일에서 읽기 | 해상도 · 촬영일 · 범위 · 좌표계 + **밴드 · 비트 깊이 · 빈 칸** | 서버 · 다 받자마자 | 읽은 값 | 좌표계는 원점 값으로 표준 번호(위치 추정은 기록 없는 파일만) |
| ③ 표준으로 바꾸기 | COG · JPEG 90(값이 중요한 영상은 무손실) · 개요 · 빈 칸 마스크 | 서버 CPU 작업기 · 새 영상은 바로 | **표준본** | 지금은 바꾸지 않고 원본을 바로 읽음(LX 영상 등록은 원본 옆에 개요 파일만) |
| ④ 확인 | 범위 · 좌표가 원본과 같은가 · 화질 수치가 기준 이상인가(표본 몇 곳) · 빈 칸 비율 | 서버 · 바꾼 직후 | 변환 기록(원본 크기 · 표준본 크기 · 화질 · 걸린 시간) | 새로 생김 — 어긋나면 한 번 다시, 또 어긋나면 관리자 알림 |
| ⑤ 원본 정리 | 보관 기간이 지난 원본을 정리 목록에 올림 | 시스템이 올리고 **LX 관리자가 한 번 눌러 지움** | 지운 기록 | 지금은 '보관'(기간 없음) |
- 지도 · AI 분석 · 기관 지도(LX 가 공유한 영상 포함 — 원칙 94)는 모두 **표준본 하나**를 읽는다. 같은 영상으로 다시 분석하면 같은 결과가 나온다(원본이 지워진 뒤에도).
- 화면에 생기는 것은 없다 — 직원 · 기관은 지금처럼 올리기만 한다. 다 바뀌기 전까지 미리 보기는 지금처럼 원본으로 보인다.

## 2. 표준 규칙
| 항목 | 규칙 | 이유 |
|---|---|---|
| 형식 | COG — 512칸 타일 · 개요(평균으로 줄임, 256칸까지) | 지도 한 칸 · 분석 한 조각을 파일 전체를 훑지 않고 읽음 |
| 압축 — 색 영상(8비트 3밴드) | **JPEG 90**(밝기 · 색차로 나눠 압축) | 크기 9~18% · 화질 기준 통과 · 가장 빠름(`diet.md`) |
| 압축 — 값이 중요한 영상 | ZSTD 무손실: 16비트 위성 · 다중분광(근적외선 등) · 높이 값(DSM) · 1밴드 · 분류 결과 | 값 자체를 분석 — 손실 압축 금지 |
| 이미 손실 압축된 영상 | JPEG 타일 파일 · ECW 를 바꾼 것 — JPEG 90 한 번만(이미 JPEG 이면 다시 압축하지 않고 타일 · 개요만 맞춤) | 손실을 두 번 겹치지 않음 |
| 밴드 | 색 4밴드(투명 칸 있음) → 색 3밴드 + 마스크 · 다중분광은 밴드 그대로 | 투명 칸이 크기 0 에 가깝게 |
| 비트 깊이 | 그대로(8비트는 8비트, 16비트는 16비트 — 화면용 밝기 늘이기는 보여 줄 때만) | 원래 값 보존 |
| 빈 칸 | 마스크 하나로 통일(투명 밴드 · 0 또는 255 테두리 · 빈 값 표시를 모두 마스크로) | JPEG 에서 테두리 잡음 없음 · 실측 어긋남 0칸 |
| 좌표계 | **번호만 정리하고 다시 그리지 않음**: 파일 속 원점 · 가산 값 · 타원체로 표준 번호(GRS80 중부 · 서부 · 동부 · 동해 · UTM-K, 해외는 UTM 등)를 붙인다. 옛 베셀 좌표계만 GRS80 으로 다시 그림 | 다시 그리면 화소가 섞여 화질이 떨어지고 시간이 든다. 지도는 화면에 그릴 때 바꿔 그린다(지금 방식) |
| 해상도 | 바꾸지 않음 | 작은 물체 분석에 해상도가 가장 중요 |

## 3. 설정 한 곳 — LX 관리자
설정 파일 하나('영상 표준')에 모으고, LX 관리자 화면 '장비 · 저장 설정' 칸(`design-r6/infra-data/infra-flex.md` 3절의 '저장 위치 한 장' 옆)에서 보고 바꾼다. 바꾸면 결재함에 기록된다. 지금 분석 의뢰 설정에 있는 받는 형식 · 보관 날 수도 이리로 옮겨 **LX 영상 등록과 기관 의뢰가 같은 값을 읽게** 한다.

| 칸 | 기본값(제안) | 고를 수 있는 것 |
|---|---|---|
| 받는 형식 | GeoTIFF · COG · IMG · JPG + 좌표 파일 · JP2 | ECW: 'PC 에서 바꿔 올리기 안내'(기본) / '서버에서 받기'(구성요소가 있을 때만 켜짐) |
| 표준 | COG · 512칸 · 개요 포함 · 빈 칸 마스크 | 바꾸지 않음(고정) |
| 색 영상 압축 | JPEG 90 | JPEG 95 · 90 · 80 · 무손실 |
| 값이 중요한 영상 | 무손실 | 바꾸지 않음 |
| 원본 보관 | 표준본 확인 뒤 30일 | 날 수 · '계속' |
| 끝내지 못한 올리기 | 7일(지금 값) | 날 수 |
| 변환 시간대 | 새 영상 바로 · 쌓인 영상 밤 22~06시 | 시간대 |
| CPU 몫 | 한 건 4개 · 동시 2건(밤 4건) — 64개 중 | 개수 |
| 한 파일 크기 | 20GB(지금 값) | 크기 |
- 관리자 화면에 보이는 숫자 셋(모두 변환 기록 한 곳에서 — 숫자 한 출처): **변환 기다림 n건 · 이번 달 줄인 용량(원본 − 표준본 합) · 정리 목록의 원본 n개(GB)**.
- 직원 · 기관 화면에는 칸이 늘지 않는다(원칙 49). 기관에는 올릴 때 한 줄만 — "올린 원본은 30일 뒤 지워집니다. 지도와 분석은 서버가 정리한 영상으로 합니다."

## 4. 지금 보관 영상에 적용하면 — 절약 추정
이 PC 에 쌓인 영상 원본 전체(서비스 저장소 밖 · D · E 드라이브)를 묶음별로 열어 압축 방식을 확인하고, `diet.md` 의 표본 비율(JPEG 90 · 개요 포함)을 묶음마다 곱했다. **추정**이다 — 표본이 넷뿐이라 범위로 적는다.

| 묶음 | 지금 | 저장 방식(실측) | 표준(JPEG 90) 뒤(추정) | 쓴 비율 |
|---|---|---|---|---|
| 2023 25cm 항공(전남 · 전북 · 충청 5,381장) | 1,787.8GB | 무압축 3밴드 · 좌표계 기록 없음 | **160~237GB** | 항공 두 표본 9.0~13.3% |
| 도로 드론(무압축 45장) | 1,961.9GB | 무압축 3밴드 970GB · 4밴드 992GB | **150~228GB** | 항공 · 드론 표본을 밴드 수로 맞춤 6.6~13.3% |
| 드론 LZW · DEFLATE(밀양 140 · 도로 254 · 용지 7 · 석면 5 · 본사 1) | 2,131.8GB | 줄 단위 LZW 대부분 · 용지 하나는 DEFLATE 타일 | **225~384GB** | 드론 두 표본 10.6~18.0% |
| 그대로 두는 것(이미 JPEG 인 익산 · 1밴드 3장) | 9.2GB | JPEG 타일 · 1밴드 | 9.2GB | 다시 압축하지 않음 |
| ECW(지적재조사 · 재난 15개) | 16.8GB | ECW | **22.9GB(늘어남)** | 실측 1.36배 |
| **합계** | **5,907.5GB** | | **568~881GB — 85~90% 줄어듦** | |

**다른 압축이면(같은 방식으로 추정)**: JPEG 95 → 788~1,231GB(79~87%) · JPEG 80 → 393~608GB(90~93%, 화질 기준 탈락) · ZSTD 무손실 → 3,408~5,237GB(11~42% — ECW 는 무손실로 바꾸면 10배 넘게 늘어 따로 셈).
- 이 숫자는 **원본을 지웠을 때**의 값이다. 이미 쌓인 LX 원본은 지우지 않는다(원칙 17 — 자산은 사용자가 정리). 표준본을 밤에 만들어 두고, 원본은 정리 목록에 '표준본 있음'으로 올려 **사용자가 묶음별로** 정한다(국토지리정보원 항공처럼 다시 받을 수 있는 원본 / LX 가 찍은 드론처럼 다시 못 구하는 원본을 나눠 표시).
- 앞으로 올라오는 영상은 처음부터 줄어든다: 기관이 드론 20GB(LZW)를 올리면 표준본 2.1~3.6GB 가 남고, 30일 동안만 원본과 둘 다 있다.
- 표준본을 먼저 만들고 원본을 나중에 지우므로, 바꾸는 동안 표준본 크기만큼(최대 0.9TB) 여유가 필요하다 — E 드라이브 여유 1,995GB 안에 든다.

## 5. 변환에 드는 CPU 시간과 대기열
| 무엇 | 시간(CPU 4개 작업 하나) | 근거 |
|---|---|---|
| 25cm 항공 도엽 한 장(328MB) | 5~8초 | 실측 |
| 드론 LZW 1GB 당 | 27~54초 → 20GB 한 장이면 9~18분 | 실측 비율로 추정 |
| ECW 한 개(260MB · 원래 7.1GB) | 약 6분 | 실측 — ECW 를 푸는 데 오래 걸림(서버 길 ⓒ 일 때만 서버 몫) |
| 쌓인 5.9TB 전부 | 작업 하나로 40~63시간 → **동시 4건(CPU 16개)이면 10~16시간 = 밤 이틀 안팎** | 추정 · 디스크 읽기(하드디스크라면 5.9TB 를 읽는 데만 8시간 넘음)가 실제 한계일 수 있음 |
- **새 영상은 바로** 바꾼다 — 올린 사람이 결과를 기다린다. 작업 하나에 CPU 4개, 동시 2건(64개 중 8개). 도엽 · 작은 드론은 1분 안, 20GB 드론도 20분 안(추정).
- **쌓인 영상은 밤(22~06시)에만**, 동시 4건(16개). 낮에 들어온 새 영상이 늘 먼저다(같은 줄에서 새 영상 우선).
- **GPU 는 쓰지 않는다** — GPU 두 장 동시 고부하 금지 규칙과 부딪히지 않는다. 다만 밤 변환이 디스크를 오래 쓰므로, 같은 시간에 도는 AI 분석이 영상을 읽기 느려지면 변환이 잠깐 쉬게 한다(설정 'CPU 몫'과 함께).
- 구조: 지금 영상 등록이 쓰는 CPU 작업기(둘)와 같은 줄에 '표준으로 바꾸기' 작업 종류 하나를 더한다. 새 작업기는 필요 없다. A100 서버가 오면 장비 대장(`infra-flex.md`)의 CPU 몫만 바꾼다.

## 6. 원본 보관 — 얼마나 두고 누가 지우나
| 어디서 온 원본 | 표준본 | 원본을 두는 기간(제안) | 지우는 사람 |
|---|---|---|---|
| 기관이 분석 의뢰로 올린 영상 | 기관 몫으로 계속(기관 해지 때 내려받기 기간 뒤 정리 — `data-governance.md`) | **표준본 확인 뒤 30일** | 정리 목록 → **LX 관리자**가 한 번 눌러 지움(기록) |
| 의뢰하지 않았거나 끝내지 못한 올리기 | 만들지 않음 | 7일(지금 그대로) | 시스템이 저절로 |
| LX 직원이 프로젝트로 올린 영상 | 계속 | **표준본 확인 뒤 30일** | 정리 목록 → LX 관리자 |
| 이미 쌓인 LX 보관 원본(항공 1,788GB · 드론 4,099GB 등) | 밤에 만들어 둠 | **지우지 않음** — 정리 목록에 '표준본 있음'으로만 | **사용자**가 묶음별로 결정 |
| 원본 보관 의무가 있는 사업(측량 성과로 쓰인 영상 등) | 계속 | 계속 — 프로젝트에 '원본 보관' 표시가 있으면 정리 목록에서 빠짐 | — |
| ECW(길 ⓐ) | — | 서버에 오지 않음 | — |
- **왜 30일**: 표준본 확인은 바로 끝나지만, 분석 결과를 직원 · 기관이 보고 이상을 알릴 시간(월 단위 업무 한 바퀴)을 둔다. 그 사이에는 원본으로 다시 바꿀 수 있다. 30일 동안은 원본과 표준본이 함께 있으므로, 서버가 따로 들고 있는 원본은 '최근 30일에 올라온 양'을 넘지 않는다.
- 기관에는 원본이 지워져도 잃는 것이 없다 — 원본은 기관이 이미 가지고 있고(원칙 88 — 이용자가 올린다), 서버에는 표준본과 결과가 남는다.
- 지금 설정은 '분석이 끝난 원본 = 보관(기간 없음)'이다. 확인되면 30 으로 바꾸고, 정리 목록(`data-governance.md` 5절 ③)에 '원본' 묶음을 더한다.

## 8. 만드는 순서(확인 뒤)
1. **화면 한 줄**: ECW 를 고르는 순간 안내(지금 다 올린 뒤 실패) — 작은 일.
2. 바꾸는 쪽 GDAL 을 한 묶음으로(JP2 를 읽게) — 무료 구성요소 하나.
3. '표준으로 바꾸기' 작업 종류 · 확인 · 변환 기록 — LX 영상 등록과 기관 의뢰 둘 다.
4. 관리자 설정 '영상 표준' · 정리 목록에 '원본' 묶음.
5. 쌓인 보관 영상 밤 변환(표준본만 — 원본은 사용자 결정).
6. GPU 차례가 올 때: 원본과 표준본으로 같은 도엽을 분석해 일치율 확인(`diet.md` 4절). 98% 아래면 JPEG 95 로 올린다.

## 9. 확인 못 한 것
- D · E 드라이브의 실제 읽기 속도(하드디스크인지) — 밤 변환 시간의 실제 한계.
- 원본 보관 의무가 있는 사업 목록(지적재조사 성과 등 — 담당 부서 확인).
- Hexagon 서버 라이선스 견적(갈림길 1 이 ⓒ 일 때).
- 표준본으로 한 AI 분석이 원본과 얼마나 같은지(GPU 차례에).
- 남원 드론 1.5cm 원본 4시점(시점당 0.3~2.1TB)은 이 PC 에 없어 절약 추정에 넣지 않았다.
