# XI ChatGEO 자리 — 검토 시안 셋 (10-18 · 원칙 287 · 구현 아님)

사용자 원문(10-18 now 답): "좀 더 고민이네. 지도를 너무 먹고 채팅이 되서.. 안좋아 보이긴 한데. 채팅도 무한정 화면에 채울수도 없고. 조금 영역을 놔눠야 될지. 아니면 채팅이 조금 지도안에서 보여져야 할지. 채팅을 내리고 올리고 자유도를 줘서 그렇게 해야 할지. 등 검토가 필요할 것 같다."
'채팅-덜겹침'은 '다시'가 두 번(바퀴 16 · 17). 그림을 더 고치기 전에 방향부터 묻는다(10-07 운영 규칙).

## 진단 — 왜 두 번 '다시'였나
- 지금 구조는 **지도 위에 떠 있는 채팅 창**이다. 답이 오면 창이 지도 가운데 아래에서 위로 자라고(최근 답 하나 · 최대 280px · 8초 뒤 접힘), 그 순간 지도의 핵심(현장 · 색 · 말풍선)을 덮는다. 높이를 줄이고 빈자리를 찾아 비켜 서게 해도 **'지도 위에 뜬다'는 성질은 그대로**라 사용자 눈에는 계속 겹쳐 보인다.
- 두 번의 고침(바퀴 16 높이 상한 · 바퀴 17 최근 답 하나 · 빈자리 찾기)은 모두 '떠 있는 채로 덜 가리기'였다. 다음 선택은 **구조**다: 자리를 나누거나(A), 아주 작게만 띄우거나(B), 사람이 높이를 정하게 하거나(C).

## 추천
**C(아래 시트)를 바탕으로, '반' 높이는 B 처럼 최근 답 한 장만 들어가는 낮은 높이로.**
- 이유 1 — 사용자 말 세 갈래("영역을 나눠야 할지 · 지도 안에서 보여야 할지 · 내리고 올리는 자유도") 중 자유도가 나머지 둘을 품는다: 접으면 B 와 같고, 전체로 올리면 A 처럼 대화 전부가 보인다.
- 이유 2 — 지도 폭이 그대로다. XI맵은 가로로 넓은 지도가 본체이고(1366 노트북에서도), A 는 채팅을 안 쓰는 순간에도 폭을 내준다.
- 이유 3 — 통계 판과 같은 문법(끌어서 · 사람마다 기억 · 원칙 280)이라 새 규칙을 만들지 않는다.
- 조건 — 시트가 올라온 동안 왼쪽 아래 분석 요청 칸 · 통계 판 아래 끝은 시트 위로 올라서야 한다(겹침 0 · 원칙 279). 1366×768 에서 '반'은 답 한 장(≤ 200px)으로 잡아 지도가 500px 이상 남게.
- A 는 큰 모니터(1920)에서는 가장 깔끔하므로, C 로 가더라도 '채팅 칸을 오른쪽에 붙이기' 단추 하나를 사람 설정으로 남기는 것을 함께 묻는다.
