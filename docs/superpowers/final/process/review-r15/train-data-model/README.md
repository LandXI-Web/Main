## 한 줄 결론
**학습 데이터 구축은 "이미 만든 라벨 묶음을 올려 확인하고 빼기"까지만 있고(라벨 그리기 · 학습 데이터 자산 · 공유 데이터셋 · 클래스 층과 조합은 화면에도 서버에도 없음), AI 모델 개발은 작은 표본 학습 → 결과 → 등록 → 배포가 한 번 이어지지만 같은 모델의 정확도가 화면마다 다르고, 기반 모델보다 낮은 모델도 경고 없이 공개되며, 기관 검토 요청과 결과 확인에서 나온 것이 다시 학습으로 돌아오지 않는다.**

## 4. 화면 평가 (원칙 기준)
- **왼쪽 쏠림 · 큰 빈 여백**(원칙 127): 프로젝트 안 학습 화면은 왼쪽에 카드 한 장, 가운데가 통째로 비고 모든 일이 오른쪽 서랍에 몰림.
- **단계마다 같은 서랍**: 학습데이터 구축 · 학습 · 배포 신청이 같은 서랍(1 올리기 · 2 라벨 확인 · 3 학습 · 4 결과 · 5 배포)이고 제목만 바뀜. '배포 신청'을 눌러도 검정 단추는 '학습 실행'이 먼저 보여 잘못 누를 수 있음.
- **사람 말 아님**(원칙 143): 기반 모델 목록 '2cm 드론 · IRG·수단그라스·옥수수·호밀 · 4번째', '비닐하우스 학습 2026.09.30 · 09.30 14:29'처럼 직원이 고를 수 없는 이름 15개. 정밀도가 '0.404'(소수)와 '89%'(퍼센트)로 섞임.
- **바깥에서 깨짐**: 바깥 주소에서 이 PC 주소를 부르는 곳 둘(라벨 도구 · 해양쓰레기 카드 그림) → 깨진 그림 · 막힌 요청.
- **흰 바탕 글만**(원칙 132): 재학습 칸 · 서랍이 글 위주. 라벨 그림이 작고 크게 볼 수 없음.
- **옛 모습 섞임**(원칙 157): 대시보드 4단계 · 결과 확인 서랍의 '정밀도 — · 임계 0.80' · 서비스 관리 빈 칸.
- 모바일은 이번 점검 범위 밖(PC 1440만).

## 5. LX 직원의 하루에서 막히는 곳
1. 새 영상을 받아 라벨을 그리려는데 **그릴 곳이 없다.** zip을 어떤 폴더 구조 · 어떤 클래스 이름 파일로 만들어야 하는지 안내도 없다.
2. 지난 묶음과 합쳐 더 큰 표본으로 학습하고 싶은데 **한 묶음 200장 이하만, 합치기 없음.** 항공 15만 장 원판 자료는 시스템 밖.
3. 학습이 끝나 0.404가 나왔는데 기반 모델 0.886보다 낮은데도 **다음 단추가 '등록'** → 낮은 모델이 그대로 서비스로 간다.
4. 기관에서 검토 요청 6건이 왔는데 **어느 사진인지 못 보고 표본에 못 넣는다** → 재학습 사유만 적고 같은 데이터로 다시 돌린다.
5. 관리자가 결재할 때 **새 판과 이전 판 비교 · 직접 돌려 보기**가 없어 숫자만 보고 승인한다.
