## 시스템 제안 규칙(위에서부터 · 코드만)
1. 서버 응답 없음 → 개발 요청('답 서버가 멈춘 까닭을 찾아 막기').
2. 세부 분류 말(단동 · 연동 · 다동) → 개발 요청('비닐하우스 단동이 모든 결과에서 나뉘도록 분류 더하기' · 근거 '결과 분류에 없음' 또는 '일부 결과에만 있는 분류').
3. 다른 이름 — 질문 낱말이 이름 표(온실 · 하우스 · 시설하우스 → 비닐하우스, 농경지 · 논밭 → 경작지, 영농 → 경작·휴경, 휴경지 · 묵밭 → 비경작지, 건축물 → 건물, 마시멜로 · 볏짚말이 → 곤포사일리지, 해양쓰레기 → 해안 쓰레기 등)에 있고, 바꿀 말이 실제 결과 분류 · 서비스 이름에 있을 때만. 사용자 말이 이미 플랫폼 말의 앞머리면(곤포 → 곤포사일리지) 겹쳐 바뀌므로 내지 않는다.
4. 이미 있는 도구(거르기 · 읍면동별 세기 · 보고서)가 알아듣는 말인데 막힘 → 답 문구('지도에 결과 층을 켠 뒤 물어보세요').
5. 질문 뜻 연결 — 도구가 할 수 있는데 그 말을 못 알아들을 때(동네별 · 몇 개씩 → '{분류} 읍면동별로 세어 줘', 레포트 · 한글 파일 → 'AI 분석 결과 보고서 만들어 줘', 만 남겨 · 빼고 지워 → '{분류}만 보여 줘') — 바꾼 질문이 실제로 그 도구로 가는지 확인한 것만.
6. 답 문구 — 이미 있는 기능(내려받기 → 지도 서비스 층마다 '내려받기') · 권한 밖(분석 실행 → 분석 요청 · 한도 → 요청하기 · 관할 밖 → 분석 요청) · 화면 밖(층 · 지적선) · 업무 밖 질문.
7. 그 밖 → 개발 요청(분류의 기본 방법).

## 제안 — 이런 것도 필요하지 않을까요?
1. **제안이 맞았는지 한 줄** — 누가 왜: LX 관리자. 이대로 반영한 줄마다 '그 뒤 같은 질문 막힘 n번'이 붙으면 시스템 제안을 믿고 눌러도 되는지 숫자로 안다.
2. **다른 이름 표를 관리자가 더하기** — 누가 왜: LX 관리자. 지금 이름 표는 코드에 있다. 현장에서 새 말(예: 지역 사투리)이 자주 막히면 표에 한 줄 더하는 칸이 있으면 개발 없이 늘린다.
3. **배포 신청서의 '학습 데이터 표본 n장'을 '학습 영상 n장'으로** — 누가 왜: LX 관리자. 결과 확인에서 '표본'을 뺐는데 신청서에 '표본'이 남아 둘을 같은 뜻으로 읽을 수 있다(이미 쓰던 화면이라 묻고 바꾼다).
