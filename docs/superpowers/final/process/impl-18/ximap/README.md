## 서버(새로)
- `server/landxi_api/ximap.py` (main.py 확장 목록에 한 줄 · 기동 때 미리 만듦)
  - `GET /ximap/board` — 한 번 호출: 시군구 × 서비스 → 수(봉투) · 끝난 시각 · 영상 · 그릴 결과 층 · 밀도(칠하기용). 출처 = 서비스 결과 장부(지금 줄 · 배포본 지금 결과 > 늦은 연도 · 분석) + 서비스가 붙지 않은 시군구 전역 분석(토지피복). 같은 분석(모델 · 영상 · 분류 같음)은 한 번만(여수 경작·휴경 = 토지피복 같은 결과가 두 번 세지던 것 막음). 1분 보관 · 지난 값을 바로 주고 뒤에서 새로(열자마자) · 고치면 바로 새로.
  - `GET /ximap/feature` — 객체 + 편집용 단순화 모양(ST_SimplifyPreserveTopology · 5186 · 1.5m) + 원래 꼭짓점 수 + 영상 · 모델 · 서비스 · 분류 목록 · 고치기 이력.
  - `POST /ximap/edits` · `POST /ximap/edits/{id}/undo` · `GET /ximap/edits?sets=` · `GET /ximap/edits/summary`(서비스별 고친 것 → 프로젝트).
- 마이그레이션 **0037_ximap_edits.sql**(되돌리기 down/0037) — `result_edits`(설계 17차 data-tables 1-1): 고치기 한 번 = 한 줄 · 원래 모양 · 분류 · 상태 · 신뢰도 · 누가 · 언제 · 결과 묶음 · 영상 · 모델 · 서비스 판 · 시군구 · 되돌림 · 시험 표시. 지우지 않고 쌓는다(학습 자료의 원천). `detections.edit_state` 에 'added'(새로 그림).
- 권한: 보기 = LX 영역 · 고치기 = LX 직원 · 관리자(영업 403) · 되돌리기 = 고친 사람 · 관리자 · 그 객체의 마지막 고치기부터.

## 제안 — 이런 것도 필요하지 않을까요?
1. **'최근 고친 곳' 한 줄(전국 칸)** — 누가 왜: 프로젝트장. 누가 어디를 고쳤는지 보이면 학습 자료가 쌓이는 것이 체감되고 다시 보기가 쉽다.
2. **서비스 색 칩에 '이 서비스만'** — 누가 왜: LX 직원. 여덟 개를 하나씩 끄지 않고 한 서비스만 보는 일이 잦다.
3. **기관 '틀렸어요' → XI맵 고칠 거리 핀** — 누가 왜: 기관 담당 · LX 직원. 기관 신고 중 AI 오류만 지도에 핀으로 띄우면 그 자리 고치기와 바로 이어진다(설계 17차 뒷면).
