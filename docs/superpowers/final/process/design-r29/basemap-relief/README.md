## 굽는 법 (CPU 만 · conda env gcs · GDAL · numpy · scipy)
스크립트는 `bake/` 에 있습니다.
1. 자료 받기: `fetch_vworld_buildings.py`(국내 건물) · `fetch_overture.py`(해외 건물, duckdb) · `fetch_osm.py`(도로 · 하천) · `fetch_dem.py`(표고) → `02. 데이터/basemap-relief/src/`
2. 굽기: `python bake.py namwon` / `bishkek` → `02. 데이터/basemap-relief/pub/tiles/{지역}/{z}/{x}/{y}.webp`
   - 해: 지도 관례대로 북서(315°) · 고도 35° 고정 → 그림자 길이 = 높이 × 1.43, 남동쪽으로.
   - 그림자: 화소마다 해 쪽으로 걸어가며 '가리는 높이'를 찾는 방식(높이 지도 행진) + 반그림자 살짝.
   - 둘레 음영: 건물 높이를 2.5 m · 8 m 폭으로 번지게 해 땅에만 얹음(AO 느낌).
   - 지형: 30 m 표고를 땅 45 m 폭으로 매끈하게 · 1.6배 과장 · 경사 2° 아래(시가지 평지)는 음영 0 → 10°까지 서서히.
   - 톤: 땅 #ECEEF1 · 지붕 #FDFDFE · 도로 #FAFBFC(아주 옅게) · 물 #DAE3EB · 그림자는 차가운 회청으로 끌림.
   - 넓은 판(z13–16)은 z16 해상도로 한 번, 가까운 판(z17–18)은 z18 해상도(0.5 m)로 가로 띠마다(띠 경계에 한 칸 여유).
3. AI 결과: `overlay.py` → `pub/overlay/*.geojson`(시안은 GeoJSON 을 바로 읽음 · 운영은 서버 결과 지도 조각을 그대로 얹으면 됨)
4. 공개: `02. 데이터/tiles/basemap-relief` → `basemap-relief/pub` 연결(디렉터리 연결). 관문의 기존 정적 조각 길(`/landxi/data/tiles/`)로 열리므로 **관문 코드 변경 없음**. 원본 자료(src)는 바깥에 열리지 않음.

## 전국 · 해외로 넓힐 때 (추정)
- **크기:** 실측 약 0.4 MB/km²(z13–18, 산 · 들 포함). 국내 전체 약 10만 km² → **약 40–60 GB.** 산지는 z17–18 을 건물 있는 곳만 구우면 더 줄어듦.
  해외는 대상국 단위: 키르기스스탄(20만 km², 대부분 산) — 전역 z13–16 + 사람 사는 곳만 z17–18 → **약 10–20 GB.**
- **굽는 시간:** 실측 약 6초/km²(한 프로세스). 국내 전체 = 한 프로세스 약 170시간 → 64코어에서 30개 병렬(한 개 약 10 GB 메모리 · 512 GB 안) → **약 6–8시간(하룻밤).** 키르기스스탄 약 2–3시간.
- **저장 상한 제안:** 입체 베이스 전체 **200 GB**(E 남은 약 1.7 TB 중 12%) — 국내 전체 + 해외 대상국 5곳 안팎. 넘으면 오래된 해외 지역부터 z18 을 지우고 z17 까지만.
- **자료 받기(전국):** 브이월드 API 를 칸칸이 부르지 않고 무료 내려받기를 씀 — 국가공간정보포털 'GIS건물통합정보'(시도별 파일 · 층수 · 높이) · OSM 한국 추출본(Geofabrik, 약 250 MB) · Copernicus DEM(국내 약 1 GB) 또는 국토지리정보원 5 m DEM. 해외: Overture 건물(범위로 잘라 읽기) · OSM · Copernicus DEM.
- **갱신:** 월 1회 — 건물 자료 새 판(브이월드 건물 · Overture 월간 판)과 지난 판의 차이에서 바뀐 건물이 있는 z16 칸(+ 그림자 여유 한 칸)만 다시 굽기. 지형은 거의 안 바뀜(해마다 1회 이하).
- **비용:** 자료 · 굽기 모두 0원(공개 자료 + 이 PC CPU). GPU 쓰지 않음.
