## 한 줄
**API = 분석 서비스 카드 하나의 바깥 창구.** 승인받은 다른 시스템(LX 내부 시스템 · 랜디에어 같은 LX의 다른 서비스 · 외부 기관 시스템)이 그 서비스의 ① **결과를 조회**하거나 ② **범위 + 영상 원천을 정해 분석을 호출**한다. 영상은 올리지 않는다 — 국토지리정보원 · 브이월드 영상을 그때 불러 분석하고, 결과만 쌓는다. 키는 **신청 → LX 관리자 승인**으로만, **신청 시스템 × 분석 서비스**마다 하나(범위 · 권한 · 원천 · 한도가 붙음). 기관 공유와는 떼어 낸다.

## 1. 개념 한 장

### 누가(부르는 쪽 셋 — 신청할 때 구분)
| 구분 | 예 | 무엇에 쓰나 | 다른 점 |
|---|---|---|---|
| **LX 내부 시스템** | LX 플랫폼(공간정보 · 지적 업무 시스템 등) | LX 업무 화면에 AI 결과를 겹쳐 보기 · 자기 업무 범위의 분석 호출 | 같은 기관. **LX 보유 영상 원천**까지 쓸 수 있음. 보안성 검토 부담이 가장 가벼움 |
| **LX의 다른 서비스** | 랜디에어(드론영상 분석 시스템) | 자기 서비스 화면에서 Land-XI 서비스(건축물 · 경작 등) 결과를 부르고, 드론 영상이 없는 곳은 공개 영상 원천으로 분석 호출 | LX가 운영하지만 시스템이 다름 → 키 · 기록 · 한도는 외부와 같은 규칙. 자기 드론 영상을 API로 올리지는 않음(아래 제안 2) |
| **외부 기관 시스템** | 부처 · 지자체 · 공공기관 업무 시스템, 해외 기관 시스템 | 결과 조회(자기 업무 범위) · 분석 호출 | 다른 기관 시스템 연동 → 국정원 보안성 검토 대상(review-r16 조건 1). **분석 호출은 검토 뒤 여는 것을 추천**(결정 API3-여는순서) |

기관(남원 · 전라남도) **화면에 배포된 서비스**는 이 API와 별개다. 그 기관의 다른 시스템이 API를 쓰려면 '외부 기관 시스템'으로 똑같이 신청한다.

### 무엇을(분석 서비스 카드마다 두 가지)
| | ① 결과 조회 | ② 분석 호출 |
|---|---|---|
| 하는 일 | 이미 만든 AI 결과(지난 결과 포함)를 범위 · 영상 원천 · 연도로 골라 받음 | 범위 + 영상 원천을 정해 분석을 맡기고, 끝나면 결과를 받음 |
| 범위 | 행정구역 코드(시군구 5자리 · 읍면동) · bbox · GeoJSON 도형 — 키의 범위 안에서만 | 같은 셋. 한 번에 넓이 한도(제안 25㎢) · 넘으면 나눠 달라는 답 |
| 영상 원천 | 결과에 붙은 원천 · 연도로 거름 | **국토지리정보원 항공(연도 · 2011–2025)** · **브이월드(최신)** · **LX 보유(LX 내부 키만)** |
| 흐름 | 요청 → 바로 답(쪽 나눠 받기) | 서비스 → **작업**(번호) → **상태**(차례 기다림 · 영상 부르는 중 · AI 분석 중 · 끝 · 실패 · 취소 · 한도 넘어 확인 대기 · 반려) → **결과**(+ 알림 주소로 알림) |
| 형식 | GeoJSON · SHP · 필지 엑셀(1차와 같음) · 요약 | 같음 |
| 영상 | 내보내지 않음 | **올리지 않음**(원칙 179 · 184). 영상은 그 자리만 불러 메모리에서 쓰고 버림(원칙 136) |

같은 서비스 · 같은 자리 · 같은 원천 · 같은 연도 · 같은 서비스 판의 결과가 이미 있으면 **다시 돌리지 않고 장부의 결과를 돌려준다**(결과를 쌓는 구조 — GPU 0).

### 어떻게(키 발급 · 승인)
- **신청**: 사이트 'API 안내' 페이지의 키 신청 창(로그인 없이) — 구분 · 기관 · 시스템 이름 · 담당자 · 전화 · 메일 주소 · 서비스(여럿) · 권한(조회 / 조회 + 분석 호출) · 범위 · 목적 · 호출 서버 주소.
- **승인**: LX 관리자 결재함에 'API 키 신청' 한 줄(원칙 178 — LX 기준 · 관리자 기능). 승인할 때 서비스마다 **범위 · 권한 · 원천 · 한도 · 끝나는 날**을 정하면 **서비스마다 키**가 만들어지고, 키 값은 한 번만 보임(1차 그대로). LX 관리자는 신청 없이 바로 만들 수도 있음(LX 내부용).
- **키 = 신청 시스템 × 분석 서비스**, 붙는 것 = 범위(전국 · 시도 · 시군구 목록 · 해외 나라) · 권한 · 원천 · 한도(호출 1분 · 하루 / 분석 넓이 한 번 · 하루 · 한 달) · 끝나는 날 · 허용 주소 · 알림 주소.
- 사람은 화면 로그인(OTP), 시스템은 키 — 섞지 않음(원칙 173 · 1차 그대로).

## 2. 분석 호출에 새로 필요한 것(지금 서버에 없는 길)
지금 분석은 **등록된 영상 파일**만 읽는다(`workers/imagery_src.py` — 영상 행 · 파일). 브이월드는 분석 입력으로 쓰지 않게 막혀 있고(`config/ladder.yaml vworld_analysis: allowed false · reason terms`), 국토지리정보원 연도별 호출 길은 저장소에 없다(10-09 실증은 임시 스크립트). 만들 것:
1. **영상 원천 장부** — '국토지리정보원 항공 2025 · 25cm · 전국', '브이월드 최신' 같은 원천을 영상 행 한 줄로(파일 없음 · 범위 = 전국 · 연도 · 가림 지역).
2. **원천에서 그 자리만 부르는 읽기기**(워커) — 작업 칸마다 타일을 불러 메모리에서 이어 붙이고 분석 뒤 버림. 원천별 호출 속도 조절 · 다시 받기 · 빈 타일(가림) 판정. **XI맵 다시 짜기(XI맵-1 ⓐ)와 같은 엔진** — 한 번 만들어 둘이 같이 씀.
3. **서비스 × 원천 적합도** — 10-09 실증: 같은 영상 API에서 경작지 95 · 건물 85 · 주차장 77 · **비닐하우스 46%**(압축 탓 · 재학습 필요). 서비스 카드에 '분석할 수 있는 원천'을 적고, 맞지 않는 조합은 호출 단계에서 거절.
4. **범위 입력 · 견적** — 행정구역 코드 · bbox · GeoJSON → 넓이 · 칸 수 · 예상 시간(영상 부르기가 대부분: 실측 약 50초/㎢) · 남은 한도.
5. **서비스 결과 장부** — 결과에 원천 · 연도 · 서비스 판을 붙여 쌓고, 같은 조건은 다시 쓰기. 결과 조회도 이 장부를 읽음.
6. **작업 · 상태 · 알림** — 지금 작업 대기열(GPU 한 장 · 화면 분석이 먼저 · API 분석은 Land-XI 전체에서 한 번에 1건) 위에 API 작업 번호 · 같은 요청 막는 열쇠 · 취소 · 알림(서명 · 다시 보냄).
7. **설정 바꾸기**: `vworld_analysis` 를 켜는 것은 사용자 결정(원칙 171 '저장 · 호출량 제한 없음' 확인 · 영상API-2 결정 대기)과 함께.

## 3. 보안(review-r16) — 영상 업로드가 없는 분석 호출은 어디에 걸리나
영상을 받지 않으므로 review-r16의 무거운 조건 — **업로드 서버와 AI 영역 분리(조건 3) · 넘기기 전 검사(4) · 군사시설 영상 받지 않기(6) · 영상 속 개인정보 위탁(7) · 받은 공개제한 영상 취급(5의 대부분)** — 은 걸리지 않는다. 들어오는 것은 범위(도형 · 코드)뿐이고, 분석 입력은 **이미 공개된 영상 원천**(국토지리정보원 · 브이월드 — 공공누리 제1유형, 보안 지역은 원천에서 가림 처리됨)이다. 남는 것은 셋이다. ① **보안성 검토(조건 1)** — 다른 기관 시스템과 잇는 AI 시스템이라 외부 기관 키는 여전히 국정원 검토 대상(LX 내부 · LX 다른 서비스는 LX 안 절차로 가벼움). ② **결과 반출 성격(질문 ⑤)** — 공개 영상에서 만든 결과는 공개 등급으로 볼 여지가 크지만, **LX 보유 영상(2023 25cm · '내부 분석용')에서 만든 결과는 '공개제한 정보를 활용해 생산한 공간정보'(국가공간정보 기본법 제35조의2)** 가 될 수 있어 외부 키에 열지 않는다(LX 보유 원천 = LX 내부 키만). 결과에는 영상 출처 · 연도를 늘 붙인다(공공누리 출처 표시). ③ **운영 조건(8 · 9 · 10)** — 호출 기록 1년 보관(지금 `api_calls` 에 보관 기간만 정하면 됨) · 해외 사업자 터널 경유는 결과만 오가므로 가벼우나 운영 전 LX 회선으로 · 범위 입력은 도형 검사(꼭짓점 수 · 넓이 · 나라 밖)로 막음. 남은 물음: 영상 API 원천을 받아 결과를 **저장하고 남에게 주는 것**이 브이월드 약관(저장 · 복제 제한)에 맞는지 — 영상API-2와 같은 정식 확인 대상.

## 4. 사용자 결정(5)
| id | 물음 | ⓐ | ⓑ | 추천 · 근거 |
|---|---|---|---|---|
| API3-키단위 | 키 하나가 무엇을 여나 | **신청 시스템 × 서비스 하나**(신청 한 건으로 여러 서비스를 고르면 서비스마다 키) | 신청 시스템마다 키 하나 + 서비스 여럿 권한 | **ⓐ** — 원칙 69 '서비스마다 키' · 184 '카드 중심 개별 API'. 서비스 하나만 멈추거나 폐기하기 쉬움. 신청 묶음으로 보여 관리 부담은 같음 |
| API3-분석승인 | 분석 호출은 언제 승인하나 | **키 승인 때 한 번** — 범위 · 넓이 한도 안은 바로 대기열, 넘으면 결재함 | 호출마다 결재함(지난 API-정기 ⓐ와 같음) | **ⓐ** — 지난 '매번 승인'은 영상을 올려 맡기는 길 기준이었음. 이번 길은 공개 영상 · 범위뿐이고 GPU는 대기열 · 한도가 지킴. 결정 기한이 없는 결재를 기계가 기다리면 API가 멈춤 |
| API3-여는순서 | 분석 호출을 누구에게 먼저 여나 | **LX 내부 · LX 다른 서비스(랜디에어) 먼저**, 외부 기관은 보안성 검토 뒤 — 외부 기관은 그때까지 결과 조회만 | 셋 모두 함께 | **ⓐ** — review-r16 조건 1(다른 기관 시스템 연동 = 국정원 검토). LX 안에서 실제 쓰임을 먼저 쌓음 |
| API3-결과장부 | API로 돌린 결과는 어디에 | **LX 서비스 결과 장부에 합침**(XI맵 · 같은 서비스 다른 키도 조회 · 같은 조건 다시 쓰기) — 부른 쪽의 범위 도형 · 요청 기록은 그쪽만 | 부른 쪽 전용 | **ⓐ** — 원칙 136 '결과를 쌓는다'. 공개 영상에서 나온 결과라 나눠도 됨. 같은 곳을 두 번 돌리지 않음 |
| API3-1차키 | 지금 1차(기관 공유 키)는 | **새 개념으로 바꿈** — 기관 공유 묶음을 떼고 키 = 신청 시스템 × 서비스. `/v1/results` 등 1차 주소는 새 주소로(켜진 키 0이라 옮길 것 없음) | 둘 다 둠(기관 공유 키 = 기관 결과판 · 새 키 = 서비스 장부) | **ⓐ** — 원칙 184 '기관 배포와 상관없이'. 표준 하나 · 안내 하나 |

## 6. 먼저 제안(원칙 57 — 이런 것도 필요하지 않을까요?)
1. **새 결과 알림 구독** — 키에 '이 범위에 새 연도 결과가 생기면 알림'. 누가: 랜디에어 · LX 플랫폼처럼 해마다 결과를 다시 가져가는 시스템 · 왜: 날짜를 맞춰 계속 묻지 않게(호출 수도 줄어듦).
2. **랜디에어 드론 영상을 'LX 보유' 원천으로 잇기** — API 업로드가 아니라 LX 안에서 랜디에어 영상 저장소를 영상 원천 장부에 한 줄로 등록(LX 직원 '영상 등록'과 같은 길). 누가: 랜디에어 · 왜: 공개 항공영상(25cm)보다 정밀한 드론 영상 위에서 같은 서비스를 돌림. 보안은 LX 내부 자료라 업로드 검토와 다름(먼저 보안 부서 확인).
3. **시험 키(모래 상자)** — 결과 조회만 · 작은 범위 · 30일. 누가: 외부 기관이 맡긴 개발사 · 왜: 실제 키를 개발 PC에 두지 않고 연동을 먼저 만듦.
4. **분석 호출 견적만 먼저 받는 주소** — 넓이 · 예상 시간 · 남은 한도만 답(GPU 0). 누가: 호출하는 시스템 · 왜: 큰 범위를 보내기 전에 나눌지 판단.
