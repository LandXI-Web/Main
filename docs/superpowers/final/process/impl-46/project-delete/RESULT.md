# 프로젝트 삭제 — 구현 결과

사용자 원문(10-23): "프로젝트 삭제하는 기능도 필요하다."
이번에 만든 것은 **프로젝트 삭제 하나**뿐입니다. 아래 '기본 규칙'에 적힌 것만 동작하고, 그 밖의 것은 '제안'에 올렸습니다(만들지 않음).

## 기본 규칙(이번에 정해서 만든 것)

| 무엇 | 정한 내용 |
|---|---|
| 누가 | 그 프로젝트의 **프로젝트장**과 **LX 관리자**만. 다른 사람(구성원 포함)에게는 단추가 보이지 않고, 서버도 거절합니다. |
| 어디서 | 프로젝트 한 장 오른쪽 아래, '끝난 프로젝트로 보관' 옆의 **프로젝트 삭제** |
| 확인 창 | 프로젝트 이름, 함께 정리되는 것(**영상 · 학습 자료 · 모델 · 결과** 수), '목록에서 바로 빠지고 30일 뒤 완전히 지워집니다'. 삭제 단추는 **프로젝트 이름을 똑같이 적어야** 켜집니다. |
| 막힘 | 이 프로젝트의 서비스나 모델이 **배포 신청 중**이면: "LX 관리자가 그 신청을 승인하거나 거절한 뒤 삭제할 수 있습니다". **기관에 공유된 서비스**가 있으면: "LX 관리자가 '배포' 메뉴의 기관 공유에서 공유를 거둔 뒤 삭제할 수 있습니다". 새로 만든 거두기 · 취소 기능은 없습니다. 지금 있는 길만 안내합니다. |
| 삭제하면 | 모든 프로젝트 목록(내 프로젝트 · 내가 만든 · 참여한 · 보관 · 전체), 알림, 내 저장 용량, 내 이력에서 **바로 빠집니다**. 한 장을 다시 열면 '삭제한 프로젝트입니다'가 나옵니다. |
| 돌던 작업 | 이 프로젝트의 대기 중 · 진행 중 작업은 사유 **'프로젝트 삭제'**로 멈춥니다. 작업 취소와 같은 길을 씁니다. |
| 파일 | 프로젝트 파일 · 이 프로젝트에만 쓰인 학습 자료 · 모델 폴더는 `02. 데이터/_trash/projects/{프로젝트}/` 로 **옮깁니다(지우지 않음)**. 학습 자료는 '지움', 모델은 '내림' 상태로 둡니다. 앞 상태는 기록해 둡니다. |
| 30일 뒤 | 기존 **보관 기한 정리**(하루 한 번 · `config/retention.yaml`)에 '삭제한 프로젝트'를 더했습니다(`deleted_project_days: 30`). 기한이 지나면 옮긴 폴더, 그 프로젝트 분석 결과의 파일 · 결과 줄, 프로젝트 줄(구성원 · 이은 것 · 메모)을 지웁니다. 작업 기록 · 감사 기록 · 내린 모델 줄은 남습니다. 새 예약 작업은 만들지 않았습니다. |
| 남는 것 | 다른 프로젝트와 함께 쓰는 학습 자료, 직원 공유 학습 자료, 서비스에 쓰인 모델, 공유 데이터의 영상 파일, 서비스 · 배포가 가리키는 결과는 그대로 남습니다. 남는 것이 있으면 창에 한 줄로 알려 줍니다. |
| 기록 | 감사 기록에 'project.delete' 한 줄이 남습니다(누가 · 프로젝트 이름 · 정리한 수). 기록 화면 말은 '프로젝트를 삭제'입니다. 감사 기록 줄은 고치거나 지우지 않습니다. |
| 되살리기 | **만들지 않았습니다.** 관리자 쪽에 삭제한 프로젝트를 보여 주는 목록이 없어서 '같은 목록에서 바로'가 아니기 때문입니다. 되살리기에 필요한 정보는 서버에 남겨 두었습니다(아래 제안 1). |

## 증거(시험 DB · 시험 게이트웨이 · 로그인 폼)
- 서버 시험 `server/tests/test_project_delete.py`: **4개 통과**. 누가 · 창의 수 · 이름 틀림 400 · 배포 신청 중 409 · 기관 공유 막힘과 거둔 뒤 풀림 · 삭제 뒤 목록 0 · 404 · 작업 멈춤 사유 · 학습 자료 지움 · 모델 내림 · 폴더 옮김 · 감사 기록 한 줄 · 30일 전 그대로 · 30일 뒤 지움. 기존 프로젝트 시험 21개도 통과했습니다.
- 화면(로그인 폼 · 버리는 프로젝트를 만들어 삭제): `test-pc-1-foot.png` 단추 · `test-pc-2-dialog.png` 창 · `test-pc-3-typed.png` 이름 적음 · `test-pc-4-list.png` 삭제 뒤 목록 · `test-pc-5-blocked.png` 막힘 · `test-mobile-*.png` 휴대폰 폭. 걸린 시간과 확인 결과는 `test-run.json`에 있습니다(창 열기 약 0.25초 · 삭제부터 목록까지 약 1.8초).
- 겹침: 삭제 창은 PC와 휴대폰 모두 0, 가로 스크롤 0입니다. 다만 PC 목록에서 **원래 있던** 겹침 1건이 나옵니다. 대화 단추가 오른쪽 아래 프로젝트 카드를 덮는 것으로, 목록 카드 수에 따라 생기며 이번 변경과는 무관합니다.
- **바깥 주소(app.land-xi.dev · 08:16 게이트웨이 재기동 뒤 · 로그인 폼)**: 버리는 프로젝트 둘(PC · 휴대폰)을 만들어 삭제했습니다. 단추 보임 → 창의 수 → 이름 적기 전 꺼짐 · 적은 뒤 켜짐 → 삭제 → 목록에서 빠짐 → 다시 열면 '삭제한 프로젝트입니다'. 겹침 0 · 가로 스크롤 0. 감사 기록 'project.delete' 두 줄. 그림 `public-*.png` · 기록 `public-run.json`.
- DB: 바꾸기 전 projects · project_members · project_links · schema_migrations 를 `02. 데이터/_backup/project-delete-20261023/` 에 떠 두고 `migrations/0128_project_delete.sql`(열 셋 더하기 · 되돌리기 down/0128) 적용(시험 DB → 운영 DB).
- 30일 정리는 CPU 작업기 안에서 돕니다 — 새 코드는 작업기를 다시 켠 뒤부터 적용됩니다(작업기 재기동은 오케스트레이터 몫).

## 제안(만들지 않음 · 채택은 사용자)
1. **LX 관리자 '삭제한 프로젝트' 목록 + 되살리기(30일 안).** 실수로 지운 프로젝트를 관리자가 되돌릴 수 있습니다. 서버에 앞 상태와 옮긴 폴더 기록이 있어 되돌리기 자체는 간단합니다.
2. **배포 신청을 낸 사람이 직접 '신청 거두기'.** 지금은 관리자 결정을 기다려야 해서, 직원이 삭제하려다 막히는 일이 생깁니다.
3. **삭제 뒤 구성원에게 알림 한 줄.** 구성원은 프로젝트가 갑자기 목록에서 사라진 이유를 모릅니다.
4. **승인됐지만 기관에 공유되지 않은 서비스 함께 정리.** 지금은 그런 서비스가 관리자 '배포' 목록에 남습니다.
