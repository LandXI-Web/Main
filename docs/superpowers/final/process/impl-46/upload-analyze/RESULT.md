- 시험 게이트웨이(:8712, 같은 DB · 같은 대기열)에서 API로 먼저 확인: 올리기 → 내 영상 → 판정 '이 서비스에 맞음' → `POST /cards/card-farm/analyze` → 작업 `done` 8.0초 · 모델 aerial25/best(카드 판의 정식 모델) · 9조각 · 경작지 142 · 건물 105.

## 2. 보관 — 올린 사람 것(공유 데이터에 넣지 않음)

- 영상 표 한 줄: `layer.role = 'own'` · `layer.owner = 올린 사람` · `staff_visible = false` · 이름 = 파일 이름.
- 파일 자리: 올리는 묶음 칸(`cog/uploads/drafts/…`)에서 `imagery/own/{주인}/{연-월}/{묶음}/` 으로 옮김(같은 디스크 이름 바꾸기 · 복사 없음). 결과 폴더 규칙(`results/{주인}/{연-월}/`)과 같은 모양.
- 빠지는 곳(다른 사람 · 서버가 고르지 않게): 영상 목록 · 지도 층(catalog) · 시군구 자동 고르기(deploys 2곳 · jobs) · 지역 영상 수(regions) · 공유 데이터 목록. 미리보기 그림은 올린 사람만.
- DB 표 바꿈 없음(이미 있는 칸만 씀) — 옮기기(migration) 없음.

## 3. 올리기 한 벌 — 고르기 전 안내 + 올리기 상태 창

**고르기 전 안내(서버가 실제로 받는 것만 · `GET /catalog/imagery/uploads/formats`)**

| 줄 | 화면 글 |
|---|---|
| 파일 형식 | GeoTIFF(COG 포함) · JPEG2000 · ECW · ERDAS IMG · JPG(위치 파일과 함께) — 지금 이 서버는 ECW 변환기가 있어 ECW 도 받음(없으면 목록에서 빠짐) |
| 위치 정보 | 공유 데이터: 좌표계가 든 파일 — 위치 파일(TFW · PRJ 등)이 따로 있으면 함께 · 내 영상: 좌표계가 든 파일만 |
| 크기 · 개수 | 한 파일 2,000GB까지 · 공유 데이터는 여러 장 한 번에 · 내 영상은 한 장 |
| 걸리는 시간 | 1GB 약 3분 · 10GB 약 30분 · 100GB 약 5시간(이 서버로 잰 초당 약 5.5MB 기준 · 회선에 따라 다름) |
| 올리는 동안 | 따로 열리는 올리기 창이 올립니다 — 그 창을 열어 두면 다른 화면에서 일해도 계속 올라가고, 어느 화면에서든 위쪽 '올리는 중' 표시로 진행을 봅니다 |

**올리기 창 + 상태 창** — 파일은 따로 열리는 올리기 창이 올린다(5절). 다른 화면은 머리줄 '올리는 중 42% · 약 1시간 20분'(접힘) ↔ 창(펼침): 쓰임(공유 데이터 / 내 영상 · 카드 이름) · 파일마다 진행 막대 · 'n / m 올림 · 남은 시간 약 …' · 멈춤 · 이어 올리기 · 취소. 다 올리면 쓰임대로 저절로 등록(공유 데이터 = 영상 등록 · 내 영상 = 판정)하고 결과 한 줄과 갈 곳('이 영상으로 분석하기' · '공유 데이터 보기'), 8초 뒤 창은 접힘.

**창 자리(겹침 0)**: 펼칠 때 네 귀퉁이(왼쪽 아래 → 왼쪽 위 → 오른쪽 아래 → 오른쪽 위) 가운데 떠 있는 것(지도 카드 · 범례 · 국토 변화 카드 · ChatGEO 단추 · 창 · 서랍 · 아래 대화 줄 — 겹침 검사기와 같은 목록)과 겹치지 않는 첫 자리. 빈 자리가 없으면 창을 접고 머리줄 표시만(사람이 누르면 가장 덜 가리는 자리에 연다). 휴대폰은 아래 메뉴 줄 · 지도 아래 대화 줄 위.

## 5. 화면을 옮기면 멈추나 — 고치기 전 답 · 첫 고침이 안 된 까닭 · 지금 방법

- **고치기 전:** 화면마다 따로 된 페이지라 다른 메뉴로 가면 그 화면의 올리기가 끝났다(브라우저 '나가시겠습니까' 창만). 탭을 바꾸는 것은 괜찮았다.
- **첫 고침(다음 화면에서 이어 받기)은 쓸모가 없었다** — 10-23 사용자가 관리자 공유 데이터에서 98.1GB를 올리며 다른 화면으로 가자 '나가시겠습니까' 창 뒤 멈춤: "이러면 무용지물이지". 화면을 옮길 때마다 끊기고 다시 잇는 방식은 일하는 동안 계속 올라가지 않는다.
- **지금 방법 — 올리기 창:** 파일을 고르면 '올리기 시작' → 작은 올리기 창(`/landxi/v3/upload/`)이 열려 파일을 쥐고 조각을 보낸다. **한 줄 이유: 화면을 옮겨도 살아 있는 것은 따로 열린 창뿐이라, 파일과 보내기를 그 창에 두면 사람이 어느 화면에서 무엇을 하든 끊기지 않는다.** 다른 모든 LX 화면은 BroadcastChannel 로 진행을 받아 머리줄 '올리는 중 n% · 약 n분' + 상태 창(접기 · 펼치기)을 보이고, 멈춤 · 이어 올리기 · 취소는 올리기 창으로 넘긴다. 보통 화면에는 '나가시겠습니까' 창이 없다(올리기 창을 닫을 때만 묻는다). 올리기 창은 하나만(Web Locks).
- **올리기 창을 실수로 닫으면:** 상태 창 · 머리줄이 '올리기 멈춤 · 올리기 창 열기'로 바뀌고, 누르면 다시 열려 서버가 받은 자리부터 이어 간다. 손잡이로 고른 파일은 그대로(허락이 풀렸으면 '이어 올리기' 한 번), 파일 칸으로 고른 파일은 '파일 다시 고르기' → 같은 이름 · 크기면 받은 자리부터.
- 팝업이 막힌 브라우저: '팝업이 막혀 올리기 창을 열지 못했습니다 — 주소창 오른쪽의 팝업 허용을 눌러 주세요'.

## 이런 것도 필요하지 않을까요? (만들지 않음)

1. **내 영상을 관리자 승인 뒤 공유 데이터로 보내기** — 누가: 좋은 드론 영상을 찍어 온 직원 · LX 관리자. 왜: 지금은 올린 사람만 쓴다. 다른 직원도 쓰게 하려면 관리자가 확인하고 공유 데이터로 넘기는 한 단추가 필요하다(지금은 관리자가 다시 올려야 함).
2. **내 영상 목록 · 지우기 · 보관 기한** — 누가: 직원 · 저장 공간을 보는 관리자. 왜: 내 영상은 올린 사람 칸에 쌓이기만 한다. 내 영상 목록과 지우기, 분석에 쓰지 않은 지 n일 지난 영상 정리 규칙이 있으면 디스크가 덜 찬다.
3. **'데이터 올리기 → 영상 등록' · '새 프로젝트' 창도 같은 올리기 한 벌로** — 누가: 직원. 왜: 지금 세 곳 가운데 두 곳(관리자 공유 데이터 · 내 영상)만 상태 창을 쓴다. 나머지 두 곳도 옮기면 어디서 올리든 화면을 옮겨도 이어 간다.
4. **올리기 진행을 LX 관리자 대시보드에서 보기**(P1 제안과 같음) — 수백 GB를 사무실 PC에서 밤새 올릴 때.
