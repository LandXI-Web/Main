## 두 장 사용 — 어떻게 돌아가나
- **설정** `server/config/pools.yaml`: `max_hot_gpus 2` · `job_max_gpus 1`(학습 · 사용자 분석은 그대로 한 장, 게이트웨이 접수 규칙) · `national.gpu [0, 1]` · `inflight_two 16`(장마다 8칩) · `read 8` · `secondary_mem_mib 5120` · `pipeline 2` · `tile_share` · `read_ahead` · `pair`(300W/10초 · 85℃ · 장비 응답 오류 3초 · 쉼 30분 · 기록 7일) · `start_gpus [0, 1]`.
- **첫 장(GPU0)**: 전국 · 해외 · 사용자 분석을 맡습니다. 두 장 모드에서 전국 칩은 다른 장의 열을 기다리지 않습니다. 사용자 분석은 예전 규칙 그대로입니다(다른 장이 고부하면 기다림). 단, 다른 장의 열이 우리 전국 작업에서 나온 것이면 세지 않습니다. 그 장은 사용자 작업 칸이 오면 칩 묶음 사이에서 비킵니다.
- **두 번째 장(GPU1 · XI ChatGEO 장)**: 국내 전국 칩만 받습니다. 사용자 분석 · 해외 · 모델 미리 올리기는 받지 않습니다. XI ChatGEO 호출 예고가 있거나 끝난 지 5초가 안 됐으면 칩을 받지 않습니다. 이미 받은 칩은 남은 칸을 스트림 끝으로 돌려놓습니다. 메모리 상한은 5GB 이고, 실제로는 3.6GB 를 썼습니다(vLLM · Ollama 와 함께).
- **XI ChatGEO 쪽** `bus.llm_power_request`: 두 장 모드에서는 GPU0 전국 작업을 기다리지 않습니다(예전에는 최대 12초를 기다렸습니다). GPU1 에서 돌던 칩 묶음이 끝날 때까지만 최대 3초 기다립니다.
- **안전 감시** `server/workers/pair_guard.py`: 워커 안에서 잠금을 쥔 하나만 돕니다. 1초마다 두 장의 전력 · 온도 · 사용률 · 합을 `02. 데이터/_logs/gpu-pair-YYYYMMDD.csv` 에 남깁니다. 이상이 생기면 `power:single` 을 걸어 바로 한 장으로 돌아가고, 30분 뒤 다시 두 장으로 돌아옵니다.
- **되돌림 실제 시험(15:59 · `fallback-test.json`)**: 가짜 신호로 한 장 모드를 걸었습니다. 15:59:24 에 걸자 GPU1 칩 처리가 15:59:26 에 멈췄고, GPU0 은 계속 돌았습니다. 관리자 줄은 '학습 장비 한 장으로 돌아감 · 두 장 합 전력 높음 15:59' 로 바뀌었습니다. 16:00:02 에 풀자 GPU1 이 16:00:08 에 다시 돌았습니다.
- **관리자 대시보드 장비 줄**(예전 '전력 예산 n/m GPU 고부하'): '**학습 장비 두 장 사용 · 고부하 0/2장**' / '학습 장비 한 장으로 돌아감 · 두 장 합 전력 높음 15:59' / '학습 장비 한 장 사용 · …'. 'GPU' 글자는 0곳입니다(`run.json gpu_word []`). PC 1440 · 모바일 390 모두 한 줄에 들어갑니다(`shots/equip-*`).

## 고친 고장(측정 중에 찾음)
1. **옛 nvidia-smi 스트림 29개가 부모 없이 돌고 있었습니다.** 워커를 다시 켤 때마다 1개씩 남았습니다. 부모가 없는 것만 PID 로 정리했고, 그러자 쉬는 동안 GPU0 전력이 약 100W 에서 약 20W 로 내려갔습니다. 이제 워커가 자식 스트림을 Windows 작업 개체(KILL_ON_JOB_CLOSE)에 묶어서, 워커가 끝나면 함께 끝납니다(따로 시험해 확인함).
2. **`localhost` → ::1(wslrelay) 경로가 30초 멈춤**(14:20–14:50 무렵): 데이터베이스 연결마다 30초가 걸렸습니다. 워커 · 스케줄러(`bus.pg`)와 영상 원천(`imagery_src`)은 127.0.0.1 로 붙게 했습니다. 상한 다시 읽기는 읽는 스레드 밖(뒤)에서 하게 했습니다. 다른 에이전트가 같은 원인으로 `.env` · `config.py` 를 127.0.0.1 로 바꿨지만, 워커 DSN 기본값(`PG_WORKER_DSN`)은 아직 `localhost` 입니다. 워커 로그(14:53 이후)에 WinError 64 · 연결 끊김 · db error 는 0건입니다. 14:20–14:45 로그는 재시작 때 덮여서 없습니다. 그때 증상은 30초 멈춤(읽기 대기 · 기록 30.2초)이었습니다.
3. 문지기가 요청마다 새 스레드에서 영상을 다시 열며 데이터베이스에 붙던 것을 고쳤습니다. 이제 프로세스 공용 캐시를 씁니다.
4. `start-landxi.ps1 -Restart workers` 가 `-Gpus` 를 `-File` 로 넘겨 배열이 한 값만 넘어가던 것을 고쳤습니다(두 장이면 1이 빠졌습니다).
