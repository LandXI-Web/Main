## 구현하려면 필요한 서버 기능
1. **기관 보고서**: `POST /agent/report/draft` 의 기관용 틀 — LX 'AI 분석 결과 보고서'(impl-14/b) 함수를 기관 범위(관할 · 열린 서비스)로 호출. 입력 = 서비스 · 읍면동, 출력 = 개요 · 지도 그림 · 읍면동별 표 · (대장 있으면) 다른 필지 칸. 규칙 입력 없음.
2. **대장 × 서비스 결과 맞춤**: 지금 `ledger` 는 2023 항공 실태조사 규칙(L1 · L2 · R1)으로만 대조. 결과 세트(서비스)를 골라 대장 필지와 잇는 길이 필요(detections.pnu × 대장 pnu · 분류 ≠ 지목 성격 두 줄 · 영상 범위 밖 수).
3. **'보고서에 넣기'**: 비교 결과(대장 이름 · 세 숫자 · 목록)를 보고서 ④ 칸으로 넘기는 저장.
4. `/survey/*` 의 '의심' 칸 이름은 그대로 두되 기관 화면에서는 호출하지 않음(금칙어 검사 `tools/check/words.mjs` 통과 유지).

## 이런 것도 필요하지 않을까요? (원칙 57)
1. **맞출 서비스가 여럿일 때** — 비닐하우스 · 건축물 결과도 열리면 '맞춘 서비스' 고르기가 바로 의미를 가짐(비닐하우스 1,153필지는 2023 항공으로 남원 전체). 농지대장 외 건축물대장 · 농업경영체 등록정보 같은 대장 종류별 '다른 필지' 정의가 필요.
2. **읍면동 보고서 묶음** — 읍면동 32곳을 한 번에 .docx 32장으로(읍면장 보고용).
3. **대장 올린 뒤 알림** — 새 결과(판)가 오면 '올린 대장과 다른 필지 수가 n → m'으로 바뀌었다는 한 줄(서비스 대시보드 새 결과 띠에 붙임).
