## 0. 판정 — 지금 이 화면군은 무엇으로 읽히는가

**잘 만든 그룹웨어 게시판.** 어느 공기업 인트라넷에나 있는 공지·FAQ·문의·사례·매뉴얼 다섯 탭을 법전(`design/system.md`)대로 곱게 재단했다. 동작은 흠이 없다 — 콘솔 0, 법전 위반 0, 딥링크·페이저·검색·빈 상태·Esc까지 원본 기능 1:1. **그러나 이 플랫폼에서 지도 · 정사영상 · AI 결과가 한 픽셀도 나오지 않는 유일한 화면군이다.** 활용사례 카드 두 장의 정사영상 크롭이 전부이고, 그마저 "해당 사업의 실제 장면이 아니다"라는 단서가 붙어 있다.

더 무거운 문제는 이 게시판이 **플랫폼의 일부가 아니라 별채**라는 점이다. 관리자가 쓴 공지·FAQ가 오지 않고(한쪽만 이어진 고리), 기관 사용자는 자기 CI의 서비스 지원 없이 LX 직원 셸로 넘어오고, 영업 계정은 이 게시판을 "활용 사례"라는 이름으로 빌려 쓴다. 이원화(기관) · 위계(역할) · 관리 연동(관리자) 세 축이 모두 끊긴 채 다섯 쪽이 정적 시드 위에 서 있다. 그래서 사용자 기준("딱딱한 업무 시스템 목업 거부")으로 보면 **동작하는 목업**이다 — 잘 움직이지만, Geo-AI 플랫폼임을 증명하는 순간이 없다.

한 줄 더. `01-faq-1440.png`의 첫 답변은 이렇게 적혀 있다: **"남원시가 운영하는 AI 기반 도로 안전관리 플랫폼입니다."** LX 직원이 로그인한 LX 플랫폼의 FAQ 1번이 자기를 남원시 도로 플랫폼이라고 소개한다. 원본(namwon3 계열) 시드를 바이트 그대로 옮긴 결과다. 기능 1:1은 맞지만 **정체성이 틀렸다.**

## 2. UX 문제 (심각도 순)

1. **끊긴 고리 — 관리자가 쓴 공지·FAQ가 여기 오지 않는다.** `support-data.js`는 `window.SP_NOTICES/SP_FAQS` 정적 시드만 읽고, `admin.js`는 `lx-admin-v1:notices/faqs`에 쓴다. 문의는 `lx.support.inquiries`로 양방향인데 공지·FAQ는 한 방향도 아니다. 공지 관리의 **팝업 설정**을 받는 화면도 없다. 관리자가 시연 중 공지를 등록하고 직원 화면으로 넘어가면 아무것도 바뀌지 않는다 — 시연이 거기서 깨진다.
2. **기관 사용자에게 제 서비스 지원이 없다.** `brand.js:27`은 서비스 지원을 골격 8부위로 선언(CI 칸 = 문의처)했는데 구현은 LX `notice.html` 하나다. 남원 포털 → LX 셸로 이탈. 기관 로그인이 `lx_role`을 쓰지 않아 역할이 남아 있지 않으면 admin으로 떨어져 포털 레일에서 서비스 지원이 사라진다.
3. **영업의 "활용 사례"가 서비스 지원을 빌려 쓴다.** 레일 활성 없음, 탭 5개 노출, 문의 등록 가능, 사례 2건, `DEPLOYS`(남원 5 + 광주전남 2)와 무관. 영업이 "해낸 것"을 보여 주는 자리가 비어 있다.
4. **정체성 오류 — 시드 문구가 남원시 도로 플랫폼을 말한다.** FAQ 1 "남원시가 운영하는 …", FAQ 2·10 "도로관리과 내선 102", 공지 8 "이력 관리 메뉴". LX 직원 셸에서 이 글이 뜬다. 콘티 원칙(지어낸 운영 서사·KPI 금지)과도 충돌: 12% 증가, mAP 0.83→0.87, 75% 단축, 8.4일→3.1일, 1억 7천만 원.
5. **관문 구멍.** `SCREEN_MENU`·`shell-gate.js MENU`에 notice/faq/contact/manual이 없어 관리자·영업이 주소로 열 수 있다. `roles.js` 주석("서비스 지원도 뺐다")과 어긋난다.
6. **문의에 "어디"가 없다.** 첨부는 파일만. 대상 서비스 카드 · 결과 좌표 · 지도 캡처를 붙일 칸이 없고, 유형(일반 / 오탐·누락 신고)이 없다. two-tier §3 **피드백** 고리("지도 결과 → 오류 신고 → 프로젝트")의 입구가 이곳인데 입구가 없다. 원본 인벤토리 §7의 **삭제**도 없다.
7. **매뉴얼은 자리 화면.** 본문 결손은 정직하지만, 결손 사유가 틀렸고(보고서 화면은 있다) 개발자 표기가 사용자 화면에 노출된다. 실제 화면으로 가는 딥링크가 없다.
8. **기준일 이중.** 서비스 지원 `2026-04-22` vs 셸 `2026-06-08`. 대시보드 공지 띠에서 들어오면 "오늘"이 7주 전으로 돌아간다.
9. **읽고 끝나는 판.** 공지·FAQ 열람 판에서 관련 화면(XI맵 카드 · 분석 서비스 · 보고서)으로 가는 길이 0개. 답변이 "지도 우측 도구 바"를 설명하는데 그 지도를 열어 주지 않는다.
10. **첨부의 정직성이 한 단계 늦다.** `.pdf`로 적힌 행을 누르면 `.txt`가 떨어진다(내용은 정직). 매뉴얼 행에만 `시연` 태그가 있고 공지·사례 첨부 행에는 없다.
11. **390px 가로 넘침**(5쪽 모두, contact 812px). `.ptabs` · `.sp-top` 줄바꿈 규칙 없음.

## 3. 인터랙티브 개선 제안 — 기존 기능만, 보여 주는 방식만 바꾼다

원칙: 새 기능을 발명하지 않는다. 아래 제안은 전부 (a) 원본 인벤토리 §7·§9에 있는 기능, (b) 9/20 스펙이 이미 요구한 고리, (c) XI맵·대장이 이미 가진 장치(`?card= ?result= ?epoch= ?sel=` URL 상태 · 비교 스와이프 모드 · 시점 스트립 · `CROPS` 실크롭 · `DEPLOYS`)를 서비스 지원 안에서 **켜는** 일이다. 법전 준수: 흰 바탕 · 잉크 · `#006DF7` · 라운드 0 · 그림자 0 · 유리 0 · Paperlogy+Pretendard · 이징 하나 · 유휴 움직임 화면당 1개(실데이터에 묶인 것).

### P-1 · 활용 사례 = 배포본 대장 위의 "전후 스와이프" (L)
- **무엇**: `usecase.html`을 `DEPLOYS` 7줄에 묶는다. 카드 한 장 = 배포본 한 줄(남원 23 생활환경 · 25 영농 · 25 변화탐지 · 26 도로 · 27 인파(예정) · 광주전남 25 해양 · 27 해양(예정)). 카드 그림은 `CROPS`의 실크롭(`namwon-farmland-2025` · `namwon-greenhouse-2025` · `namwon-epoch` · `kuksan-change` · `yeosu-marine-*`)이고, 모달 상단은 **XI맵 비교 모드의 스와이프(`map.js` `#swipe` · `cmp.baseE/cmpE`)를 그대로 재사용**해 2시점 정사영상을 좌우로 문지른다. 수치는 `RESULTS.stats`(2,098 필지 · 9,664 동 · 면적)만. `예정` 배포본은 점선 고스트 + `사업 시작 전`.
- **대응 기존 기능**: 인벤토리 §7 `usecase.html`(카드 · 모달 · 검색 · 페이저) + XI맵 비교(스와이프 · 시점 스트립) + `cards.js DEPLOYS` + `crops.js` + `results.js`.
- **왜 GeoAI**: 영업이 "해낸 것"을 말이 아니라 **실제 영상 두 시점과 실측 건수**로 증명한다. 원본 시드의 KPI 서사(mAP·75%)는 `원본 시드 · 시연` 표식을 달고 접힌 절로 내린다.
- **유휴 1개**: 스와이프 핸들이 6초 주기로 한 번 왕복(prefers-reduced-motion = 정지).

### P-2 · 문의하기 = "지도 위치를 첨부하는" 오탐·누락 신고 (L)
- **무엇**: 문의 등록 폼에 유형(일반 문의 / 오탐·누락 신고)과 **대상 서비스 카드** 선택을 두고, 신고 유형이면 첨부 칸에 `지도 위치 첨부` 버튼을 켠다. 누르면 XI맵을 **선택 모드**(`ximap.html?card=…&pick=1` — 기존 `?sel=` 결과 선택 상태를 돌려받는 것)로 열어 결과 폴리곤/점 하나를 고르고 돌아온다. 문의에는 좌표 · 결과 id · 카드 · 정사영상 시점 + 작은 크롭 미리보기가 붙는다. 열람 판에서는 그 크롭 위에 청록 폴리곤과 좌표(Inter tabular)를 보인다. 원본 **삭제** 버튼(답변 대기 상태만)을 되살린다.
- **대응 기존 기능**: 인벤토리 §7 `contact.html`(등록 폼 · 첨부 · 삭제) + two-tier §3 피드백 고리(스펙이 이미 "지도 결과 → 오류 신고 → 프로젝트"로 정의) + `portal-ui.js:597` 문구("오탐·누락은 서비스 지원으로 신고") + XI맵 결과 선택(`?sel=`) + 관리자 `문의 관리` 양방향 저장소(이미 동작).
- **왜 GeoAI**: 시드 문의 12건 중 6건이 위치 문제다. 글로 "인월면 동쪽 산간"을 쓰는 대신 그 자리를 찍어 보낸다. 관리자 `문의 관리` 열람에서 같은 크롭이 보이고, 답변 저장 시 `프로젝트 재학습 후보`로 표식만 남긴다(프로젝트 화면의 기존 역추적 링크에 걸린다 — 새 큐를 만들지 않는다).

### P-3 · 공지 열람 판의 "이 공지가 가리키는 곳" (M)
- **무엇**: 공지 데이터에 이미 있는 것(카테고리 · 본문의 모델/메뉴 언급)을 대장과 대조해 열람 판 하단에 **대상 카드 한 줄**을 붙인다. 예: 공지 7 "모델 v2.1 배포" → `card-road v2.1` · 배포본 `dp-nw-road-26` · `XI맵에서 이 카드 보기(ximap.html?card=card-road)` · `분석 서비스에서 보기(analysis-ai.html?svc=…)`. 카드 한 줄에는 그 배포본의 실크롭 1장(EVIDENCE-PAIR 축소형)이 선다. 대조가 안 되는 공지(정기점검 · 개인정보)는 줄이 서지 않는다 — 지어내지 않는다.
- **대응 기존 기능**: 인벤토리 §7 `notice.html` 열람 + `?notice=` 딥링크 + XI맵 `?card=` · 분석 서비스 `?svc=` URL 상태 + `cards.js` 버전 · `registry.js updateState()`(갱신 고리).
- **왜 GeoAI**: two-tier §3 **갱신** 고리("모델이 오르면 배포본에 알림")의 사람 쪽 입구가 공지다. 공지가 읽고 끝나는 글이 아니라 **카드로 건너가는 문**이 된다.

### P-4 · FAQ 답변의 "그 화면 열기" + 문의로 이어 쓰기 (S)
- **무엇**: FAQ 답변이 화면을 설명할 때(지도 도구 바 · 영상 관리 업로드 · 보고서 생성) 답변 아래에 코너 브래킷 2차 버튼 `그 화면 열기`를 세운다(`ximap.html` · `dataset.html` · `report-standard.html`). `찾는 답이 없으면 문의하기`는 지금 빈 폼으로 가는데, **그 FAQ의 카테고리와 질문을 문의 제목에 미리 채워** 간다(`contact.html?from=faq&id=7`).
- **대응 기존 기능**: 인벤토리 §7 `faq.html` + `contact.html` 등록 폼 + 기존 화면 URL.
- **왜 GeoAI**: 답을 읽는 것이 아니라 그 자리로 간다. 화면 코드는 대장(FAQ 카테고리 → 화면) 한 표만 읽는다.

### P-5 · 매뉴얼 = 지금 화면의 실캡처 + 단계 딥링크 (M)
- **무엇**: B5 원판 썸네일을 **지금 화면(9/22 기준)의 실캡처**로 바꾸고, 우측에는 `본문 미구성` 결손 상자를 유지하되 개발자 문구(`#manual-body` · `원본 manual.html`)를 걷고 사용자 말로 한 줄("본문은 준비 중 — 지금 있는 것은 카테고리 5와 파일 시드"). 05 결손 사유를 고치고(`report-standard.html` 실캡처) 각 카테고리에 `이 화면으로 가기` 브래킷 버튼을 단다. 캡처는 `clip-path inset(100% 0 0)→inset(0)` 1s로 현상(법전 §4).
- **대응 기존 기능**: 인벤토리 §7 `manual.html`(카테고리 5 · 파일) + 기존 화면들.
- **왜 GeoAI**: 매뉴얼이 실제 화면(XI맵 정사영상 · 데이터 관리 썸네일)을 보여 주면 그 자체가 플랫폼 소개가 된다. 본문은 여전히 지어내지 않는다.

### P-6 · 공지 팝업 수신 — 관리자 설정이 첫 진입에서 뜬다 (S)
- **무엇**: `admin-notice.js`의 팝업 설정(`popupOn · popupFrom · popupTo`)을 셸이 읽어, 기간 안이면 대시보드/포털 첫 진입에 잉크 헤어라인 판 하나를 띄운다(라운드 0 · 그림자 0 · 유리 0). 닫기 · `오늘 하루 보지 않기`(localStorage, 편의). 본문 안에 P-3의 대상 카드 한 줄이 함께 선다.
- **대응 기존 기능**: 인벤토리 §9 `admin-notice.html` 팝업 설정(원본에 있는 기능, 받는 쪽만 없었다) + 대시보드 공지 띠.
- **왜 GeoAI**: 관리자 → 직원 → 기관으로 흐르는 **한 벌의 공지**가 시연에서 보인다. S-01(저장소 통합)과 함께 간다.

### P-7 · 기관 서비스 지원 — CI 한 벌만 갈아 끼운 같은 골격 (M)
- **무엇**: 서비스 지원 다섯 쪽이 `brand.js THEMES[tenant]`를 읽어 레일 마크(`남원/GV`) · 상징색(`--accent/--tint` 덮어쓰기) · 마스트헤드 명칭 · 푸터 문의처(`contact`)를 갈아 끼우고, 레일은 `TENANTS.menus`(portal · analysis · map · support)만 세운다. 골격·CSS는 한 벌. 포털 로그인(`portal-login.js`)이 역할(`tenant`)을 남긴다.
- **대응 기존 기능**: production §3 골격 8부위(`SHELL_PARTS.support` · CI 칸 `문의처`) + `portal.js TENANTS.menus` + `brand.js cssVars()`(이미 shell.css 변수만 덮는다).
- **왜 GeoAI**: "손으로 하면 용역, 기능으로 하면 사업" — 기관 50곳이 되어도 서비스 지원 한 벌.

### P-8 · 영업 전용 "활용 사례" 셸 (S, P-1과 함께)
- **무엇**: `usecase.html boot()`가 역할을 읽어 영업이면 `active:'usecase'` · H1 `활용 사례` · 화면군 탭 없음. `SCREEN_MENU`·`shell-gate.js MENU`에 notice/faq/contact/manual → `support`를 넣어 관리자·영업의 URL 진입을 막는다(usecase만 열어 둔다 — 지금 주석이 말하는 대로).
- **대응 기존 기능**: `roles.js` 영업 메뉴 선언 + 관문.

### P-9 · 정직성 마감 (S)
- 기준일을 셸 정본 `AS_OF`(`shell.js:77`) 한 벌로. 첨부 행마다 `시연` 태그(파일명 `.pdf`와 실제 `.txt`의 차이를 누르기 전에 알린다). 시드 KPI 문장에는 `원본 시드 · 시연` 표식. FAQ 1의 "남원시가 운영하는 도로 안전관리 플랫폼"은 LX 셸용 문구로 바꾸되 원본 문구는 기관(남원) 서비스 지원에서만 뜨게 한다(P-7). `.ptabs` · `.sp-top` 줄바꿈.

## 4. 가장 먼저 고칠 것 (순서가 곧 의존 관계)

1. **S-01 저장소 통합** — 공지·FAQ를 `admin.js` 스토어와 같은 열쇠로 읽는다. 팝업 수신(P-6). 이것 없이는 아래 어떤 것도 시연에서 이어지지 않는다.
2. **S-03/S-04 관문과 영업 셸** — `SCREEN_MENU` 4쪽 추가, `usecase.html` 역할 분기(P-8). 30분짜리 일인데 신뢰를 좌우한다(영업 계정에 문의 폼이 열려 있다).
3. **S-02 기관 서비스 지원** — `brand.js` CI로 셸 교체 + 포털 로그인에서 역할 저장(P-7). 이원화 경계를 다시 세운다.
4. **정체성·정직성** — FAQ 1 문구, 기준일 한 벌, 첨부 `시연` 태그, 시드 KPI 표식, 매뉴얼 결손 문구·05 사유(P-9 · P-5의 문구 부분).
5. **그 다음에 몰입** — P-1(사례 = 배포본 + 스와이프) → P-2(문의 = 지도 위치 첨부) → P-3(공지 → 카드) → P-4/P-5.

## 5. 하지 말 것

- 게시판을 지도 위에 얹지 않는다. 대시보드가 "지도 없음"으로 확정된 것과 같은 이유 — 서비스 지원의 판은 **사례(P-1)와 문의 첨부(P-2)에만** 영상이 선다. 나머지는 잉크와 헤어라인.
- 사례를 늘리기 위해 서사를 쓰지 않는다. 배포본 7줄 · 실크롭 · `RESULTS.stats`가 전부다. `예정`은 고스트.
- 공지·FAQ 본문을 다시 쓰지 않는다(관리자가 쓰는 데이터다). LX 셸에 맞지 않는 시드는 기관 셸로 옮기고, LX 셸에는 표식을 단다.
- 유휴 움직임은 화면당 1개(P-1 스와이프 핸들)까지. 나머지는 진입 스태거와 클립패스 현상만.
