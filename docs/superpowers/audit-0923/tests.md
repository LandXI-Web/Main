### 2.1 무엇이 바뀌었나(근거)

2026-09-21 19:52 커밋 `cd03cb9`("위계를 세운다 — LX 관리자 · LX 직원 · 영업용 계정 3단 분리")에서 `landxi/assets/data/roles.js`가 새로 생겼다. 이 파일이 정의하는 것:

```js
export const DEFAULT_ROLE = 'admin';
ROLES = [
  { id: 'admin', menus: ['ops','media','publish','produce','admin','my'], home: 'admin-home.html' },   // 승인·사용자·공지·생산 공정만
  { id: 'staff', menus: ['dashboard','media','project','analysis','map','support','my'], home: 'ai-project.html' },
  { id: 'sales', menus: ['analysis','usecase','map','my'], home: 'ximap.html' },

```

같은 커밋이 `landxi/proto/shell-gate.js`(로그인 전 클래식 관문)와 `landxi/proto/shell.js`의 `gate()`(안전망)에 **역할별 화면 차단**을 심었다: `localStorage.lx_role`이 없으면 `admin`으로 간주하고, 그 역할이 `SCREEN_MENU`에 정의된 화면 키를 못 가지면 `location.replace(home?denied=...)`로 **그리기 전에** 쫓아낸다.

문제: **`admin` 역할은 2026-09-22 커밋 `2891fdb`("관리자에게 제 집을 준다")에서 대시보드·프로젝트·분석 서비스·지도 서비스·서비스 지원을 전부 잃었다** — 발주자 구술(코드 주석에 원문 인용): *"관리자는 프로젝트가 필요할까?" "관리자는 기존 사이트와 완전 다르게... 관리 기능만 있도록"*. 그 다섯 화면은 이제 `staff`(직원) 전용이다.

### 2.2 테스트는 왜 걸리나

`tests/e2e/proto-{map,project,analysis,dashboard,support}.spec.mjs`의 `boot()` 헬퍼는 전부 이렇게만 로그인한다(발췌, 5개 파일 공통 패턴):

```js
async function boot(page, url) {
  await page.addInitScript(() => localStorage.setItem('lx_logged_in', '1'));   // lx_role 은 세우지 않는다
  await page.goto(url);
  await page.waitForFunction(() => document.documentElement.dataset.shell === 'ready');
}
```

`grep -rl lx_role tests/e2e/*.spec.mjs` → **`proto-shell.spec.mjs` 단 한 파일만** `lx_role`을 세운다. 나머지는 전부 로그인 상태만 만들고 역할은 기본값(`admin`)에 맡긴다. 그 결과 `dashboard.html`(role key `dashboard`) · `ai-project*.html`(`project`) · `analysis-ai.html`(`analysis`) · `ximap.html`(`map`) · `notice/faq/contact/usecase/manual.html`(`support`)로 가는 모든 `boot()` 호출이 **관문에서 즉시 `admin-home.html?denied=...`로 튕겨 나간다.** 그 뒤 테스트가 기다리는 `dataset.dash/shell/map === 'ready'`는 영원히 오지 않거나(→ `Test timeout of 30000ms exceeded` / `waitForFunction Timeout`), 엉뚱한 페이지에서 `#rail .rail-i[aria-current="page"]` · `.pj-card` · `#map-a` 같은 셀렉터가 **0개**로 잡힌다(→ `toHaveCount(expected) failed` `Received: 0`).

증거 — 커밋 시각으로 확인: 위 5개 스펙 파일은 전부 `cd03cb9`(19:52) **이전**에 마지막으로 손이 갔다(`proto-map` 19:36 · `proto-support` 19:41 · `proto-project`/`proto-dashboard`는 전날). **3단 위계 커밋 이후로 이 스펙들을 고친 적이 없다** — 화면이 아니라 테스트 픽스처가 기능을 따라가지 못한 것이다.

같은 논리가 `proto-publish.spec.mjs`의 실패 1건과 `proto-login.spec.mjs`의 실패 1건, `smoke.spec.mjs`의 실패 1건에도 적용된다(레일에 없는 메뉴 키를 기대하거나, 옛 단일 계정 시절의 목적지 `dashboard.html`을 기대함). §3.3·§3.4 참고.

## 3. 위계 원인군이 아닌 나머지 4건 — proto-login.spec.mjs

`proto-login.spec.mjs`의 4개 실패는 전부 같은 파일이지만 원인이 서로 다르다. 넷 다 **2026-09-21~22 사흘간 로그인 화면에 "계정 종류(LX 관리자/직원/영업용 계정) 라디오 선택"이 새로 들어온 것**과 맞물려 있다 — 이 부분은 테스트가 낡은 것과 화면이 실제로 어긋난 것이 섞여 있다.

### 3.1 `224:1` — 시스템 법(액센트 정확히 3곳) — **화면 쪽 회귀로 보임**
```

Received: ['', 'lg-find__a','lg-find__a','lg-submit']   // 클래스명 없는 요소 하나가 액센트 블루로 추가 검출됨
```
`design/system.md` §2: "액센트 허용 자리 = KPI 큰 숫자·상태어·링크·포커스 링·선택 행/칩" 뿐이고 **"채운 파란 버튼은 여전히 없다"**. 새로 추가된 계정 종류 라디오(3종 `input[type=radio]`) 중 하나가 `:checked` 상태에서 클래스 없이 액센트 블루로 렌더되는 것으로 보인다 — 법전이 허용한 3자리 밖에 4번째 블루 요소가 생겼다. **원인 추정: 화면이 깨졌다**(3계정 라디오 UI 추가 시 법전 위반이 새로 생김). 소스 미수정 원칙상 정확한 요소는 스크린샷/DOM 스냅샷으로 별도 확인 필요 — `test-results/proto-login-시스템-법-.../error-context.md`에 있음.

### 3.2 `303:1`, `365:1` — 카드 높이 520px 안에 내용이 안 들어간다 — **화면 쪽 회귀로 보임**

## 4. 결론 — 권고(실행하지 않음, 읽기 전용 원칙)

1. **가장 값싼 수정으로 가장 큰 효과**: `tests/e2e/proto-{map,project,analysis,dashboard,support}.spec.mjs`의 `boot()`에 화면이 요구하는 역할(`localStorage.lx_role = 'staff'`, 필요하면 `'sales'`)을 한 줄 추가 — 추정 184건 중 대다수가 해소된다. `proto-shell.spec.mjs`가 이미 올바른 패턴을 갖고 있다(참고용).
