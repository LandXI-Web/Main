## 3. 발견 사항 (심각도순)

### P0
- **R1 레일이 계정 위계를 모른다 — 누르면 튕기는 메뉴가 절반.** `dataset.js:37-49`에 레일이 하드코딩되어 있다. 반면 관문 `shell-gate.js:15-19`은 역할별 메뉴를 막는다.
  - LX 관리자: `대시보드 · 프로젝트 · 분석 서비스 · 지도 서비스` 4개를 누르면 `admin-home.html?denied=…`로 간다. 관리자 홈(`admin-home`)으로 가는 항목은 레일에 없다.
  - LX 직원: `카드 발행 관리 · 생산 관리 · 서비스 관리` 3개를 누르면 `ai-project.html?denied=…`로 간다.
  - 증거: `results.json roles`, `40-role-admin.png`, `40-role-staff.png`.
  - "관리자는 별도 사이트"라는 전제와도 맞지 않는다. 관리자가 데이터 관리에 들어오면 직원용 레일을 보게 된다.

### P1
- **F1 파이프라인이 흐르지 않는다.** 이 화면의 존재 이유는 "4탭 = 파이프라인 단계"다(system.md §6). 그런데 업로드는 99→62로 되감는 루프이고(`dataset.js:428`), 대기 건은 시작하지 않는다. 발행은 단계가 오르지 않고, 끝난 발행이 아카이브로 들어오지 않는다. 업로드 → 완료 → 발행 → 아카이브 전이를 한 번도 볼 수 없다. 사용자 기준으로 가장 큰 결손이다.
- **F2 상태가 남지 않는다.** 업로드 · 발행 · 삭제 · 공유 · 표시 설정이 새로고침하면 전부 초기값으로 돌아간다(삭제 후 새로고침 → 아카이브 5, `results.json persist`). 메모만 localStorage에 남는다. 다른 화면(분석 · 프로젝트)도 같은 저장소를 읽지 않으므로 업로드 왕복이 반쪽이다.
- **F3 `내려받기`가 말만 한다.** `e62d7eb`가 "말만 하던 것을 실제로"라며 download.js를 세웠지만 dataset에는 적용하지 않았다. `dataset.js:888` → `say('내려받기 — … · 시연')`뿐이고 download 이벤트는 0건이다(`results.json download.file:null`). 완료 탭 6종 모두에 이 버튼이 뜬다. 같은 방식의 토스트 전용 액션: `필지에 붙이기`(`:889`), `풀기`(`:890`), `원본 다시 올리기`(`:565`), `필지 연결 안내`(`:566`), 공간 편집(`:620`).
- **F4 영업용 계정의 업로드 버튼이 막다른 길.** 분석 서비스(sales 허용)의 `영상 업로드`(`analysis-run.js:161-164`)가 sales에게 금지된 `dataset.html`로 보낸다. 결과는 `ximap.html?denied=dataset.html`이다. 버튼을 숨기거나 역할별 대체 경로가 필요하다.
- **F5 파괴 동작에 확인이 없다.** 아카이브 삭제, 업로드 취소, 발행 취소가 모두 즉시 실행되고 되돌릴 수 없다(S2 연장, `dataset.js:380,562,606`).
- **F6 타일 키보드 0 · 모달 포커스 트랩 0**(S1 · S4 미해결). "영상 썸네일이 1급 시민"인 화면에서 1급 시민이 키보드로 닿지 않는다.
- **F7 모바일(390) 붕괴.** 개요 가로 넘침 160px, 아카이브 241px, 발행 폼 275px. 제목 `데이터 관리`가 두 글자씩 쪼개지고 KPI 숫자가 겹친다(`50-overview-390x844.png`, `51-archive-a1-390x844.png`). 레일 72px가 그대로 남아 콘텐츠 폭이 318px뿐이다.
- **F8 9/20 스펙 연결 고리 부재.**
  - (a) 자산 등급 `ASSET_TIERS`(원본 정사영상 = LX 보관·반출 불가 / 타일만 공유 / 라벨·모델 사본)가 dataset에 없다. 공유 모달이 원본 정사영상에도 `남원시청 편집`을 허용한다. 이는 two-tier §3과 card-architecture §5.2 R7을 정면으로 위반한다.

- 좋은 점: 실제 정사영상 크롭 타일, 실좌표 GeoJSON 실루엣, 실제 MapLibre 판에 청록 성과 폴리곤이 올라간다. `왜 못 그리는지`를 스스로 밝힌다. 기능 밀도가 높다.
- 모자란 점:
  - 화면 문법이 여전히 **업무 시스템 대장**이다(KPI 4칸 + 150px 타일 격자 + 우측 속성표).
  - 파이프라인이라는 이야기가 움직임으로 보이지 않는다. 파일이 단계를 건너가는 전이 · 판으로 날아가는 레이어 · 발행 완료 순간이 없다.
  - 지도는 우표 크기다. 타일 위 글자는 겹치고 이름은 전부 말줄임이다.
- 사용자가 거부한 '딱딱한 목업'에서 벗어나지 못했다. 개요는 사진 4장을 나열한 정적 포스터다.

## 6. 권고 (구현 트랙용 · 우선순위)

1. **공용 셸로 이관**(`shell.js` + `roles.js`): R1 · C1이 한 번에 해소된다. 역할별 레일, 관리자는 `admin-home` 복귀.
2. **파이프라인 상태 기계 + 저장소**: 업로드 run → 100% → 완료 탭 전이, 발행 1→4단계 → 아카이브 편입, 대기열 자동 시작. 상태는 공용 store(localStorage 키 1개)에 두고 분석 · 프로젝트의 아카이브 픽커가 같은 store를 읽는다(왕복 완성). 값은 `시연` 표기를 유지한다.
3. **`내려받기` → `downloadNote`/`downloadFile` 적용.** 토스트 전용 액션 6곳은 실제 동작으로 바꾸거나 `준비 중`으로 비활성화한다.
4. **자산 등급 반영**: 원본 정사영상의 공유는 `타일 열람`만 허용한다. 공유 모달에 등급 한 줄을 넣는다(R7).
5. **삭제 · 취소 확인 대화상자 + 되돌리기 토스트, 타일 `<button>`화, 모달 포커스 트랩.**
6. **몰입감**: 선택 시 판을 우측 패널 전체(또는 PLATE-FULL 일탈 1회)로 키운다. 발행 완료 순간에 레이어가 판에 내려앉는 전이(750ms)를 넣는다. 개요는 4단계를 가로지르는 흐름 띠(실건수 기반)로 만든다.
7. 모바일 390: 레일을 하단 탭으로, 개요를 1열로, 우 패널을 시트로 바꾼다.
