# E0-8 발행 고리 배관 — 직원의 발행 요청이 관리자 큐에 도착한다

- 모델: Opus 5 · 난이도 S · 화면 변화 있음(요청 이력 표 · 링크 상태)
- 전제: `wave0/00-COMMON.md`(`switchTo` 픽스처) · `publish-produce.md` PP-1 · `project.md` B1 · B9 · `MASTER-PLAN.md §7.1`.

## 목표

직원의 카드 발행 요청이 **다른 저장소**(`project-data.js lx_project_v1`)에 써져 관리자 큐(`publish-data.js lx_publish_v1`)에 도착하지 않고(PP-1 P0), 요청 뒤 `admin-publish.html` 로 보내져 관문에 튕겨 목록으로 떨어진다(B1 P0). 저장소를 하나로 잇고, 직원은 자기 요청 이력에 착지한다. 승인 → 카드 생성(PP-2)은 **E1-3**.

## 단계별 할 일

1. **저장소 단일화**: `publish-data.js addRequest(item)` 가 정본. `project-data.js addRequest(pid, r)` 는 `publish-data.addRequest({ pid, card: r.card, train: r.train, modelName: r.modelName, kind: r.kind, status: '대기', requester: '<현재 역할명>', at: AS_OF })` 로 **위임**하고 자기 저장소에는 쓰지 않는다(옛 `lx_project_v1.requests` 는 읽기 호환만). `project-data.js requestsOf(pid)` = `publish-data.requests().filter(r => r.pid === pid)`. `hydrate` 가 `pid` · `requester` 를 살린다. 요청 id `pa-N` 규칙 유지.
2. **착지(B1)**: `project-deploy.js:152` → `location.href = 'ai-project.html?pid=' + p.id + '&tab=deploy&req=' + id`. 배포 탭 안에 **내 요청 이력 7열 표**(상태 · 과제명 · 학습결과 · 모델명 · 과제유형 · 요청자 · 요청일 — `requestsOf(pid)` · `bindRows` · `req` 파라미터 행 하이라이트 · 셸 `ST_CLASS` 상태 칩). `:122 go-publish` '카드 발행 관리에서 보기 ›' → `allowed('approve')` 면 링크 · 아니면 `disabled` + `<span class="mic">관리자 사이트에서 승인합니다</span>`.
3. **전역 요청 폼**: `publish-request.js:130` 착지 → `homeOf(ROLE)` 가 staff 면 `ai-project.html?pid=<pid>&tab=deploy&req=<id>` · admin 이면 `admin-publish.html?open=<id>`. `BACK`(목록 · 취소 링크) = `homeOf(ROLE)`(`import { ROLE } from './shell.js'` · `homeOf` from roles). `ai-publish-create.html` 의 정적 링크가 있으면 같은 규칙으로 JS 가 채운다.
4. **B9**: 모델 등록 폼(`project-deploy.js` 모달) `colgroup` 폭 합 = 표 폭 · 1440 에서 열 겹침 0.
