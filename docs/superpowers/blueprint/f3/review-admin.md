# F3 검토 · 관리자(LX 운영) — 관제에 남길 핵심

2026-09-27 · 정문 로그인과 :8702 로그인으로 직접 들어가 확인함 · 스크린샷 `shots/f3/review-admin/`

## 결론

관리자가 할 일은 **돌리기(인프라) · 나눠주기(기관 할당) · 내보내기(배포) · 승인하기(결재)** 네 가지뿐이다.
지금 관제(:8702)는 이 네 가지를 **다 갖추고 있지만** 설명 글, 출처 꼬리표, 코드 식별자, 중복 위젯에 묻혀 있다.
정문으로 들어온 관리자는 관제가 아니라 **구 시연 관리 사이트에 도착한다**.
해법은 기능을 더하는 것이 아니다. **메뉴 5개, 화면마다 질문 하나, 숫자 3~5개, 버튼 1개**로 줄이는 것이다.

| 발견 | 증거 |

| 구 사이트는 결재 **2·1·6건**, 관제는 결재 **0건**. 구 사이트 스토리지 13%, 관제 실측 D: **95%** | `00c` vs `02` `03-s1` |
| :8702 자체 로그인 카피가 "LX 전 직원이 Geo-AI 전문가 · NO-CODE"(폐기된 문구). 관리자 전용 문에 홍보 문구가 있고, 모토 3축이 없다 | `01` |

→ 관리 사이트는 **:8702 하나만 둔다**. 정문 관리자는 같은 출처의 `/ops`로 착지(F3-G). `proto/admin-*`는 폐기하고 아래 §4로 흡수한다.

## 2. 남길 핵심: 메뉴 5개

| 메뉴 | 답하는 질문 하나 | 숫자(≤5) | 동작 |
|---|---|---|---|
| **현황** | 지금 내가 할 일이 있나? | 결재 대기 · 경보 · GPU 부하 · 저장 여유 · 가동 기관 | 결재함 첫 건 열기 |
| **인프라** | 돌릴 힘이 충분한가? | GPU별 부하·VRAM·W · 전력 예산 1/1 · 대기열 · 디스크 | 재큐 · 모델 상주/해제 · 노드 추가 |
| **기관** | 누가 얼마나 쓰나? | 기관별 GPU 시간·저장·면적(사용/한도) | 한도 조정 → 결재 · 계정 승인 |
| **배포** | 어느 기관에 무슨 서비스가 몇 버전으로 돌고 있나? | 카드 × 기관 매트릭스 · 단계 | 승격 · 롤백 · 버전 고정 |
| **결재** | 무엇이 내 승인을 기다리나? | 유형별 대기 건수 | 승인 · 반려(사유 1줄) |

- **결재함은 하나로 합친다.** 지금은 카드 발행 승인(`admin-publish`), 가입 승인(`admin-users`), 쿼터 증액(tenants 하단), 배포 승격(deploys)이 네 곳에 흩어져 있다 → 결재함 하나의 목록에서 유형 칩으로 구분한다
- **현황 = 지도 한 장 + 할 일 목록.** 배포 지도(전국 + 글로브)는 Land-XI만의 장면이고, LX 직원이 묻는 "지자체에 어떻게 제공하지?"에 그림으로 답한다. 점 = 기관, 색 = 서비스 상태로 두고, 그 외 레이어는 모두 끈다
- 고객지원(공지·FAQ·문의)은 관리자의 핵심 업무가 아니다 → 결재함에는 `미답변 문의` 건수만 올리고, 편집은 설정 안 하위 화면에 둔다

## 3. 판정 기준(재구현 게이트)

- 화면당 글자 수 ≤ 현재의 40% · 코드 식별자 0 · 패널별 출처 꼬리표 0
- 같은 지표가 두 화면에서 다른 값 0(결재 건수·디스크 %)
- 경보는 **조치할 일**에만 켠다: 디스크 ≥ 90%는 켜고, LLM 상주로 VRAM이 차는 것은 끈다
- 정문 관리자 로그인 → :8702 현황 착지(e2e)
