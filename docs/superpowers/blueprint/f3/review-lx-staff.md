## 3. 제안 — LX 직원의 하루 = 한 화면 체계 "라인"

정문 하나 → 직원 착지는 **XI맵 위 '오늘' 띠**. 레일은 메뉴가 아니라 **하루의 순서 6단**이고, 모든 단은 같은 지도 위의 서랍이다(화면 전환 대신 카메라·서랍). 관제(:8702)는 6단 '운영'의 잉크 반전판 — 같은 로그인.

```
정문(모토 3축 · "실태조사 특화" 한 줄 · 계정 3택)
  └ 착지 = XI맵 + 오늘 띠 ── "검수 대기 3 · 재학습 1 · 이식 요청 1 · 기관 신고 4"
       레일 ① 반입   영상(LX 보관) + 대장(기관 업로드 CSV/XLSX/SHP → PNU 결합) + V-World 레이어
            ② 학습   라벨 → 학습 곡선 → 모델 (어느 실태조사 업무에 쓰이는지 배지)
            ③ 조립   업무 카탈로그 10 × [모델·대장·영상·규칙] 있음/없음 → 카드
            ④ 검수   의심 큐 · 표본 100 · 정밀도 → '검수 전' 꼬리표 떼기
            ⑤ 배포   기관 덱 미리보기 → 심기 / 이식(프로파일+배포본 한 줄) → CI 한 벌
            ⑥ 운영   기관별 사용·오탐 신고·모델 성능 → 재학습 트리거 (= 관제)
```

| 단 | 화면 하나 | 큰 숫자 하나 | 행동 하나 | 지도 위에 보이는 것 |
|---|---|---|---|---|
| 오늘 | XI맵 + 띠 | 할 일 n | 첫 항목 열기 | 할 일이 있는 곳에 핀 |
| ① 반입 | 자산 판 | 결합된 필지 n | 대장 올리기 | 영상 footprint · 대장 결합률 채색 |
| ② 학습 | 라벨·곡선 | mAP / IoU | 학습 실행 | 라벨 AOI · 칩 격자 |
| ③ 조립 | 카탈로그 매트릭스 | 만들 수 있는 업무 n/10 | 카드 만들기 | 규칙이 켜지는 필지 미리보기 |
| ④ 검수 | 의심 큐 | 정밀도 % | 확정/오탐 | R1–R6 필지 · 표본 |
| ⑤ 배포 | 기관 덱 | 깔린 기관 n | 심기·이식 | 배포 지도(전국) |
| ⑥ 운영 | 관제 | 성능·사용 | 재학습 | GPU·큐·기관 막대 |

규칙: 숫자는 `/registry · /survey/stats · /jobs · /ops` 한 출처. `시연`·`2026.06.08` 꼬리표 0. 지도가 없는 단은 없다(대시보드 폐지 → '오늘' 띠).

## 4. 예 — 남원 영농관리 카드를 여수에 심는 하루

| 단 | 직원이 하는 일 | 화면에서 보이는 것 | 근거 스펙 |
|---|---|---|---|
| 오늘 | 띠에 "이식 요청 · 여수시 농정과 · 영농관리" | 지도가 여수로 카메라 이동 | — |
| ① 반입 | 여수 항공 정사영상(LX 보관) 등록 · V-World 연속지적·농업진흥·용도지역 켜기 · 여수 농정과가 올린 **농지대장 XLSX** → PNU 결합 | 결합률 96% · 미결합 필지 붉게 | card-arch §5.2 ASSET_TIERS · V-World Data API |
| ② 학습 | 남원 라벨·모델 사본이 따라옴 → 여수 표본 AOI 200칩 미세조정 | 남원 v2.1 → 여수 fine-tune 곡선 | `transplantAssets()` |
| ③ 조립 | 카탈로그 '농지이용 실태조사' 행: 모델 ✓ 대장 ✓ 영상 ✓ 규칙 R1·R2·R5 ✓ → **카드 여수 배포본** | 프로파일 1벌 + 배포본 1줄(카드 복사 0) | `PROFILES` · `DEPLOYS` · R3 |
| ④ 검수 | 첫 스윕 → 의심 큐 → 표본 100 확인 → 정밀도 ≥ 기준이면 '검수 전' 꼬리표 제거 | 큐·정밀도 보드 | SURVEY-SPEC · production §1 |
| ⑤ 배포 | 여수 CI 9키 입력 → 포털 생성 → 덱 미리보기 → 심기 | 골격 한 벌 + `여수/XI` 마크 | brand.js · portal-gen |
| ⑥ 운영 | 여수 사용·오탐 신고 → 임계 미달 시 재학습 카드가 '오늘' 띠로 | 관제 기관 막대에 여수 행 | ops.js THRESHOLDS |

지금은 이 여덟 칸이 **모달 하나(19)** 에 글로 눌려 있다. 이것을 하루의 순서로 펼치는 것이 F3-U의 실체다.

## 5. 에이전트 — 업로드 행정데이터 융합(사용자 정정 반영)

- 입력은 API·기본정보가 아니라 **①에서 결합된 대장 × AI 결과 × V-World 필지**. 도구 셋: `ledger_join(file, key=PNU|지번)` · `parcel_lookup` · `survey_stats(by=emd|jimok|ledger_field)` · `draft_report`.
- 질문 예: "직불금 신청 필지 중 비경작 의심만" · "농지대장에 없는데 경작 중인 필지" · "작년 대비 신규 비닐하우스 상위 읍면". 답은 지도 하이라이트 + 표 + 초안 — 문장은 세 줄.
- 범위 가드: 반입된 대장·배포본 밖이면 "이 기관에 대장이 없습니다 → 반입" 한 줄로 ①단으로 보낸다.

## 7. 관리자 · 사용자 · 서비스 — 세 면 한 줄씩

- **관리자(LX/OPS)**: 6단 '운영'의 반전판. 승인·쿼터·배포 제어·GPU. 직원과 같은 로그인, 같은 숫자.
- **사용자(LX 직원)**: 6단 라인. 첫 화면에서 할 일·만들 수 있는 것·깔린 곳이 한눈.
- **서비스(기관)**: 카드 덱 → 작업공간 5탭. LX 메뉴 0. 오탐 신고가 직원 '오늘'로 되돌아온다.
