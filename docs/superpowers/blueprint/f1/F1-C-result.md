## 3. 세 사용자 점검

- **관리자(LX 운영자)**: 인프라에서 "누가 GPU를 쓰고 있나"가 한 줄로 보인다(외부 점유 띠 · 프로세스 이름 · 워커 예산 = 총 − 외부 − 2,048). 전력 예산 칩(`고부하 GPU 0/1 · 배정 1/1`)으로 두 장 동시 고부하가 스케줄러에서 막히는 것이 보인다. 취소/재큐/우선순위 · 가입 토큰 · 롤백 · 이식 · 쿼터 저장이 모두 실제 쓰기(사유 필수 · audit 이력). 부족: 알림 채널(메일/문자) 없음 · 노드 원격 재기동 없음(의도적 — 읽기 전용 폴러).
- **공무원(기관 담당, 관제 비접근)**: 관제에 들어오지 못한다(staff = `관제실은 관리자 전용입니다` · 4173 세션 불통). 기관 화면의 격리 표시(prefix · RLS · 서명 타일 · 원본 라우트 0)가 보고서용 근거가 된다.
- **일반인/시연 관람자**: 종이 무대 첫 화면이 플랫폼 소개 + 실측 요약 한 줄 + 실제 판독 미니맵이라 "살아 있는 시스템"임이 즉시 보인다. 공개 무대에 자체 원본 영상 없음(V-World 위성 + AI 결과만 · 사용자 결정 준수).

## 4. 계약 변경 요청(F1-CONTRACT)

1. §1 nvidia-smi 경로: 드라이버 597.16에서 `nv_dispwi.inf_…`로 바뀜 → 고정 경로 대신 "DriverStore 안 응답하는 최신 nvidia-smi · `LX_NVSMI` 우선"으로.
2. §5.3 `mem_used_mib`: 597.16 WDDM에서 `memory.used` 언더플로(17,592,186,044,414 MiB) 발생 → 대체 출처(PDH Dedicated Usage)와 `note` 필드를 계약에 명시.
3. §4.9 `external[].mem_mib`: WDDM에서도 PDH로 프로세스별 값을 얻을 수 있음 → `null | number` + `note`로 완화(현재 계약은 N/A 고정).
4. 예시값 `외부 점유 23,396 MiB`는 Ollama 상주량에 따라 변한다(녹화 시 31,982 / 33,374 MiB) → 계약 예시가 아니라 "실측값 표시"로 문구 변경.
5. F1-B 게이트웨이 `/ops/gpus` 가 현재 500 → 복구 전까지 관제는 브리지 사용(자동 전환 로직 있음, 복구 시 `lx_ops_src=gateway` 직결 검증 완료 · `logs/gw-probe.json`).
6. 전력 규칙(2026-09-26)을 스케줄러 계약에 추가: `claim` 응답에 `power_budget` 보류 사유 · 동시 고부하 GPU ≤ 1(`f1c-infra-live` 전력 규칙 테스트).
