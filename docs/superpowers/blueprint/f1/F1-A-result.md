## 3. 세 사용자 자기 점검 (첫 15초)

- **공무원(남원시)**
  - 보이는 것: 순백 글로브(어제 VIIRS)에서 남원 25cm 위로 내려온다. 하강 중 먹색·검은 칸은 제출 영상 실측 최대 0.05 %다(§2). HLS 궤도 밖은 검은 사각이 아니라 밑의 V-World가 보인다. `129,420` 폴리곤이 스윕을 따라 현상되고 `AI 추론 · 검수 전` 봉투가 숫자 옆에 있다. 운봉읍을 누르면 집계 카드가 뜨고, 드론 버튼은 `덕과면 드론 AOI로 이동 ›`이라 어디로 가는지 적혀 있다.
  - 약점: 필지(P8)는 off에서 로컬 PMTiles를 읽는다. V-World 검색은 `키 대기` 결손 칩이다.
- **일반 시민(게스트 · `?public=1`)**
  - 보이는 것: V-World 위성 위에 농지이용 2,098필지가 도착한다. 이제 on/off 모두 `AI 추론 · 검수 전`으로 표기한다(1차에는 off·공개에서 `실측`이었다). 마스트 `공개 · 위성 + AI 결과`.
  - 약점: 드론 AOI 장면이 없다. 사용자 결정대로 의도한 제한이다.
- **LX 직원**
  - 보이는 것: 프레임 → 견적 → 실행 → 제출 즉시 `접수 · 큐 대기` → `워커 배정` → 칸이 120 ms 간격으로 켜지고 빔이 지나간 뒤 걷힌다 → job.done → 스냅샷 교체. 작업 줄이 `shard 합 86 → 전역 NMS 후 71`로 큰 숫자와의 차이를 설명한다. GPU %는 '공유'로 적었고, 이 작업의 몫은 `0.56 GPU·s · 2.4 s`로 따로 적었다. 클래스 이름은 한글(건물·경작지).
  - 약점: 게이트웨이 CPU finalize 큐가 막히면 job.done이 늦는다. 그때는 `병합 대기 … n s`를 띄운다. 표시 큐 때문에 칸 도착 화면은 실제 shard 완료보다 최대 약 1.4 s(6칸 기준) 늦게 끝난다. 이벤트 순서와 개수는 같다.
