## 1. 발견된 설계 결함 (원인 수준)

### D1. 프로젝트 자산과 에이전트가 같은 장부를 보지 않음
- 현상: 프로젝트 생성 시 2019·2024 영상이 이미 확보돼 지도에 떠 있는데, ChatGEO는 "국토지리정보원 항공영상 확보 · 2019년·2024년"을 **다시 수행**.
- 원인(추정): 프로젝트 생성의 영상 확보 결과(타일 캐시·메타)가 프로젝트 자산으로 등록되지 않거나, 에이전트 도구가 프로젝트 자산을 조회하지 않고 자체 경로로 재확보.
- 영향: 중복 작업·시간 낭비, "방금 불러온 걸 왜 또 찾나"는 신뢰 저하.

### D2. 에이전트 추론이 6단계 파이프라인 밖의 그림자 경로로 돈다
- 현상: 플랫폼 정식 흐름(1 데이터 올리기 → 2 학습데이터 → 3 학습 → 4 추론 → 5 결과 확인 → 6 배포)과 무관하게 ChatGEO가 별도로 추론을 실행. 프로젝트 단계 표시·추론 작업 목록·결과 확인 화면 어디에도 기록되지 않음.
- 직원 관점의 혼란: "학습데이터 구축하고 학습해야 지도 서비스가 생기는 것 아닌가? 챗봇에 시키면 그냥 되는 건가?" — **둘 다 가능해야 하지만, 둘이 같은 장부에 기록돼야 한다.**
- 영향: 결과 추적 불가, 배포 단계로 연결 안 됨, 권한·감사 공백.

### D3. 장기 작업에 대한 예외 처리 부재
- 현상: "결과를 찾고 있습니다" + 점 세 개만 9분 이상. 진행률·대기열 위치·예상 소요·취소·시간초과·실패 사유·재시도 **전부 없음**.
- 원인(추정): 동기식 요청 대기 또는 폴링은 있으나 작업 상태 모델이 없음. GPU가 전국 분석·시험 학습과 공유돼 대기열에 밀린 것을 UI가 알 수 없음.
- 영향: 직원은 멈춘 건지 도는 건지 모름. 시연 중 발생하면 발표 중단.

### D4. "정식 모델 사용"과 "프로젝트 학습"의 분기가 UI에 없음
- 변화탐지는 정식 서비스의 기학습 토지피복 모델을 쓰므로 2·3단계(학습데이터·학습)가 **필요 없음**. 그런데 프로젝트 화면은 6단계를 항상 보여줘 직원이 "학습부터 해야 하나" 오해.

## 2. 수정 지시

### F1. 프로젝트 자산 장부 단일화 (D1)
- 프로젝트 생성 시 확보한 영상(연도별 타일 캐시·범위·해상도·출처)을 **프로젝트 자산**으로 등록. 데이터 올리기 화면 "영상" 목록에 "2019 NGII 항공 (API) · 2024 NGII 항공 (API)"로 표시.
- 모든 에이전트 도구는 실행 전 **프로젝트 자산을 먼저 조회**. 이미 있으면 "확보됨(프로젝트 자산 사용)"으로 즉시 통과, 없을 때만 확보. 채팅 단계 표시도 "✓ 영상 확보됨 — 프로젝트에 이미 있음"으로 구분.
- 영상·벡터·결과 모두 동일 원칙(한 장부).

### F2. 에이전트 실행 = 정식 추론 작업 (D2)
- ChatGEO가 분석을 시키면 **4단계 추론 작업(job)으로 생성**하고, 프로젝트 단계 표시가 "4 추론 · 진행 중"으로 바뀌며, 완료 결과는 **5단계 결과 확인**에 레이어로 등록. 배포(6단계)로 이어질 수 있어야 함.
- 추론 작업 레코드: 요청자(직원/에이전트) · 서비스·모델 버전 · 범위 · 연도 · 시작·종료 · 상태 · 결과 레이어 ID. 분석하기 화면에서 직접 실행한 것과 동일 스키마.
- 채팅 응답에 "추론 작업 #N 생성 — 프로젝트 4단계에서 진행 상황 확인 가능" 링크 포함.

### F3. 장기 작업 상태 모델과 예외 처리 (D3)
- 작업 상태: `대기(큐 위치 n/N)` → `실행 중(k/K 타일 · 경과 · 예상 잔여)` → `완료` / `실패(사유)` / `취소됨` / `시간초과`.
- 채팅·프로젝트·대시보드 어디서든 같은 상태 표시. 채팅 카드에 **진행률 바 + 예상 잔여 + 취소 버튼**.
- 규칙:
  - 큐 대기 30초 초과 → "GPU 대기열 n번째 · 예상 m분" 표시
  - 실행 10분 초과 → 사용자에게 "계속 기다리기 / 백그라운드로 보내고 알림 받기 / 취소" 선택지
  - 20분 초과 또는 워커 무응답 60초 → 시간초과로 종료, 사유와 재시도 버튼 제공
  - 실패 시 사유(모델 로드 실패·영상 누락·타일 오류 등)를 사람 말로 표시
- 백그라운드 전환 시: 요청함(inbox)에 알림, 대시보드 "진행 중 작업" 카드에 표시.
- GPU 스케줄링: 사용자 대화형 요청(소범위, 예: 2km² 이하)은 **전국 배치 작업보다 우선** 큐에 배치. 대화형 전용 슬롯 1개 확보.

### F4. 파이프라인 분기 표시 (D4)
- 프로젝트 생성 시 또는 분석 서비스 선택 시 **경로 선택**:
  - "정식 서비스 모델로 바로 분석" → 2·3단계를 "건너뜀(정식 모델 사용)"으로 회색 처리, 1 → 4 → 5 → 6
  - "이 프로젝트 데이터로 학습" → 6단계 전부
- 변화탐지 서비스는 기본값이 전자. 단계 바에 그 이유를 한 줄로 표시("토지피복 U‑Net v{버전} 사용 · 학습 불필요").

### F5. 에이전트 예외·거절 규칙
- 범위가 큰 요청(예: 시군구 전체 변화탐지) → 즉시 실행하지 않고 "예상 N분 · 배치로 보낼까요?" 확인.
- 프로젝트에 없는 연도 요청 → "프로젝트에 2019·2024만 있음. 2021을 추가로 확보할까요?(약 n초)" 선택지 제시 후 실행. 기존의 "한 시점뿐이라 할 수 없습니다"식 종료 금지.
- 권한 밖 요청(배포 승인 등) → 요청함으로 넘기는 버튼 제공.
- 동일 요청 재전송 → 진행 중 작업에 붙이고 새로 만들지 않음.

### F6. 사전 계산 의존 제거 검증
- §7 시나리오를 **사전 계산 없는 새 범위·새 계정**에서 통과시킬 것. 기준: 2단계 응답(작업 생성·진행률 표시)은 5초 이내, 추론 완료는 335필지·0.54km² 기준 **5분 이내**(대화형 우선 슬롯 사용 시). 녹화는 사전 계산 결과 사용 가능하되, 검수는 이 기준으로.
