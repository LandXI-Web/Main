# 겹친 결과에서 가장 나은 경계를 골라 배우기 — 장기 설계(문서만)

> 2026-10-22 · 원칙 315 · 사용자 원문(now 21 제안-농지하천한층): "결국 실제 하나의 농지이고 이게 추론 결과가 2개로 겹치되 서로 형태가 다르다는건 어쨋든 결과가 조금씩 차이나는 거고. 그 중 베스트가 있을건데. 단순 한층으로 한다기 보다는 베스트 폴리곤을 학습해서 추론 정확도를 보정하는 부분도 있어야만 장기적으로 훌륭한 GeoAI 서비스일텐데."
> 이 문서는 **설계만** 담았습니다. 이번 바퀴(22)에는 시스템 자동 정리(1단)까지만 했고, 사람이 고르는 화면과 학습은 만들지 않았습니다. 겹침 점검을 사람이 할지 시스템이 할지는 now 22 질문(Q2)입니다.
> 바탕: `recon-1021/OVERLAP-DESIGN.md`(겹침 진단) · 1단 결과 `final/process/impl-46/overlap-c22/RESULT.md`

## 한 줄 결론
겹친 두 경계는 **버릴 것과 남길 것이 아니라, 같은 땅을 두 번 본 '후보'**입니다. 후보마다 세 가지 근거(영상 경계와 맞는가 · 필지와 맞는가 · 사람이 확인했는가)로 점수를 매겨 가장 나은 경계를 고르고, 고른 결과와 그 까닭을 다음 학습 자료로 되돌립니다. 그러면 같은 실수를 다음 분석에서 덜 하게 됩니다.

---

## 1. 지금 무엇이 겹치나 — 후보가 생기는 다섯 자리

| 자리 | 예 | 지금(1단) 처리 | 장기 |
|---|---|---|---|
| ① 이웃 읍면동 · 조각이 같은 땅을 두 번 | 남원 2025 반 넘게 겹친 쌍 10,982 | 대표점이 속한 조각 것만 남김(규칙) | 둘을 견줘 나은 쪽 |
| ② 칸 경계에서 잘린 조각 | 남원 2023 칸 경계 쌍 1,071 | 붙여서 하나로(규칙) | 붙인 모양을 영상 경계로 다듬기 |
| ③ 같은 칸 안에서 붙은 두 경계 | 실제 두 논배미일 수도 | '합칠까요?' 후보 목록만 | 사람이 정한 결과로 배움 |
| ④ 농지 분석과 하천 분석이 같은 곳을 | 2025 농지 결과의 68% | 농지 층 하나로(하천 쪽 같은 것은 뺌) | 두 모양 중 나은 쪽 |
| ⑤ 해 · 모델 판이 다른 결과 | 판끼리 60~92%만 같음 | 곳마다 최신 하나 · 이전은 영상 비교에서만 | 해를 넘어 같은 땅을 잇고, 판끼리 다른 곳을 학습 후보로 |

1단 정리는 '규칙으로 하나 남기기'입니다. 빠르고 숫자가 한 번만 세어지지만, **남긴 쪽이 더 정확하다는 보장은 없습니다.** 예를 들어 ①에서 대표점이 속한 조각의 경계가 칸 가장자리에서 잘려 있고 이웃 조각의 경계가 더 온전할 수 있습니다. 그래서 1단은 버린 경계를 지우지 않고 원래 결과와 정리 기록(무엇을 왜 뺐는지 · 무엇을 붙였는지)에 남겨 두었습니다. 이것이 장기 설계의 재료입니다.

## 2. '가장 나은 경계'를 고르는 기준

같은 땅을 본 후보 묶음(서로 작은 쪽 절반 넘게 겹친 같은 분류의 경계들)마다 아래 점수를 매깁니다. 사람 확인이 있으면 그것이 언제나 이깁니다.

| 근거 | 무엇을 재나 | 어떻게 | 무게 | 주의 |
|---|---|---|---|---|
| **사람 확인** | 공무원 · LX 직원이 맞다고 한 모양 | 현장 확인 '맞음' · 고친 모양 · '합칠까요?'에서 고른 답 · 결과 확인에서 승인 | 결정(점수 무시) | 사람마다 다를 수 있음 — 두 사람이 다르면 후보로 남김 |
| **영상 경계와 맞음** | 경계선이 영상의 실제 논두렁 · 길 · 밭 가장자리를 따라가는가 | 경계선을 따라 영상 밝기 변화(가장자리 세기)의 평균 · 경계 안팎 색의 차이 · 칸 가장자리에 걸려 직선으로 잘린 길이의 비율(낮을수록 좋음) | 높음 | 그림자 · 구름 · 계절 차이 — 같은 해 영상으로만 견줌 |
| **필지와 맞음** | 경계가 필지 안에 얼마나 들어가는가 · 필지를 얼마나 채우는가 | 경계 넓이 중 한 필지 안 비율 · 필지 대비 덮음 | 낮음(보조) | 실제 논밭은 필지 선을 따르지 않음(남원 경계의 84%가 두 필지 이상에 걸침) — 필지는 '맞으면 가점'만, 안 맞는다고 감점하지 않음 |
| 모델 믿음 정도 | AI 가 낸 확신 | 경계마다 conf · 칩 가장자리 여부 | 낮음 | 판이 다르면 같은 잣대가 아님 |
| 시점 사이 한결같음 | 앞뒤 해 결과와 모양이 이어지는가 | 같은 땅의 지난해 · 다음 해 경계와 겹침 정도 | 중간 | 실제로 바뀐 땅(개간 · 전용)은 오히려 찾을 대상 — 감점이 아니라 '변화 후보'로 따로 |

- 점수는 **같은 묶음 안에서만** 견줍니다(지역 · 영상 · 모델이 다르면 절대값이 다름).
- 골라진 것과 함께 **왜 골랐는지(가장 큰 근거 한 줄)**를 남깁니다. 화면에는 '영상 경계가 더 잘 맞는 쪽' 같은 쉬운 말로만 보입니다.
- 점수 차가 작으면(예: 0.05 미만) 고르지 않고 사람 확인 후보로 둡니다. 이것이 now 22 Q2 와 이어지는 자리입니다.

## 3. 학습으로 되돌리는 고리

```
 분석 결과(원래 결과 보관)
      │  1단 정리(규칙) ─ 정리 기록: 뺀 것 · 붙인 것 · '합칠까요?' 후보
      ▼
 후보 묶음 만들기(같은 땅 · 같은 분류 · 반 넘게 겹침)
      │  점수 매기기(영상 경계 · 필지 · 믿음 정도 · 시점)
      ▼
 고르기 ── 점수 차 큼 → 시스템이 고름
      │   점수 차 작음 → 사람 확인 목록(결과 확인 화면 · 기관 필지 카드)
      ▼
 학습 자료로 ── 고른 경계 = 정답 후보 · 버린 경계 = '이렇게 그리지 말 것' 예시
      │   사람이 고른 것은 바로 학습 칸으로 · 시스템이 고른 것은 LX 직원 확인 뒤
      ▼
 다음 판 학습(GPU 한 장 · 전력 규칙 · 사용자 승인 뒤) → 같은 자리 다시 분석 → 견주기(좋아졌나)
```

### 3-1. 무엇을 학습 자료로 보내나
- **사람이 고친 모양 · 고른 모양**: 지금의 고치기 → 기억 → 학습 칸 흐름 그대로(고친 자리 기억 · 학습 칸 만들기). '합치기 · 나누기'를 고치기 종류에 더합니다(2단).
- **두 후보 중 점수 차가 큰 쌍**: 나은 쪽을 정답, 못한 쪽을 틀린 예로. 같은 영상 칸에서 두 모양을 함께 보여 주는 칸이라 모델이 경계를 어디에 그어야 하는지 배우기 좋습니다.
- **보내지 않는 것**: 칸 경계에서 잘린 것 · 조각 경계 중복처럼 **정리 과정이 만든 문제**는 학습으로 고치지 않고 정리 규칙을 고칩니다(잘림을 학습시키면 모델이 오히려 혼란스러워짐 — OVERLAP-DESIGN 3-4와 같은 원칙).

### 3-2. 스스로를 속이지 않게
- 시스템이 고른 것만으로 학습하면 모델이 자기 버릇을 더 굳힐 수 있습니다. 그래서 **시스템이 고른 자료는 사람 확인 자료보다 무게를 낮추고**, 한 번에 넣는 양을 사람 확인 자료의 몇 배 이하로 묶습니다.
- 학습 전후는 **사람이 확인한 고정 표본**(지역 · 지목 · 계절을 섞은 금 표본)으로만 견줍니다. 견주는 값: 경계가 몇 m 안으로 맞는가 · 겹침 비율 · 놓친 것 · 잘못 잡은 것.
- 좋아지지 않으면 새 판을 쓰지 않습니다(지금의 판 바꾸기 규칙 그대로 — 결과 확인 뒤 승인).

### 3-3. 해를 넘는 같은 땅
- 해마다 다시 분석하면 같은 땅에 경계가 하나씩 쌓입니다. 거의 같은 경계는 **같은 땅 번호**로 잇습니다(OVERLAP-DESIGN 3단). 그러면 신규 · 유지 · 사라짐이 저절로 나오고, 해마다 모양이 흔들리는 곳(모델이 불안한 곳)이 드러납니다. 흔들림이 큰 곳은 학습 후보 1순위입니다.

## 4. 단계(제안 · 확인 전에는 구현하지 않음)

| 단계 | 무엇을 | 사람 일 | 품 |
|---|---|---|---|

## 이런 것도 필요하지 않을까요?(원칙 57)
- **'어느 쪽이 맞나요?' 두 장 고르기** — 누가: 결과를 확인하는 LX 직원. 왜: 점수 차가 작은 두 경계를 영상 위에 나란히 보이고 하나를 누르면, 그 한 번이 정답 · 틀린 예 한 쌍이 됩니다. 사람 품이 가장 적게 드는 학습 자료입니다.
- **흔들리는 땅 지도** — 누가: 모델을 관리하는 LX 직원. 왜: 해마다 · 판마다 모양이 크게 바뀌는 곳을 색으로 보면 다음 학습에 넣을 지역을 바로 고를 수 있습니다.
- **기관의 현장 확인을 학습 근거로 쓰는 동의 한 줄** — 누가: 기관 담당자. 왜: 공무원의 현장 확인이 가장 믿을 만한 근거인데, 그것을 모델 학습에 써도 되는지 기관이 알고 동의하는 편이 운영에 안전합니다.

## 개발자 부록
- 1단이 남기는 재료: 결과 파일 옆 `{작업}-tidy.json`(raw 원래 파일 이름 · in · out · seam(merged_pieces · merged_into) · dropped(owner · dup · farm_layer) · candidates[{a, b, cls, gap_m, overlap}]) · 정리 결과 속성 `merged_from` · 원래 결과(옛 = `.geojson` 그대로 · 새 분석 = `.raw.fgb`).
- 후보 묶음 표(제안 · 마이그레이션 번호는 그때): `polygon_candidates(group_id, set_id, det_fid, cls, year, src(asset · 조각 · 판), score_edge, score_parcel, score_conf, score_time, chosen bool, chosen_by(system|person), reason, at)`.
- 영상 경계 점수: 경계선을 0.5 m 간격으로 표본 → 그 자리 영상(같은 해 COG · 표준본)의 가장자리 세기(Sobel) 평균 ÷ 경계 안쪽 2 m 띠의 평균 · 칩 가장자리 직선 길이 비율은 `chip_edge` 조각의 바깥선 중 칩 경계(타일 격자)와 0.3 m 안으로 평행한 길이.
- 학습 내보내기: `train_tiles.py` 의 칸 만들기에 `source='best_polygon'` · 무게 열 · 사람 확인 여부.
- GPU 는 4단에서만(학습 · 다시 분석) — 1~3단은 CPU 도형 · 영상 읽기만.
