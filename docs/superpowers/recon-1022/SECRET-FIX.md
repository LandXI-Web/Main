## 1. 쓰이던 곳

설정 파일에 적혀 있던 것은 `${PG_ADMIN_PASSWORD:-기본값}` 꼴의 **기본값**이었고, 그 기본값이 실제 최고 관리자 비밀번호와 같았다(지문 비교). 같은 개발용 기본값이 앱 · 작업 계정에도 쓰여, 세 계정 모두 저장소에 글자로 남아 있었다.

| 자리 | 무엇 | 고친 뒤 |
|---|---|---|
| `server/docker-compose.phase0.yml` | 최고 관리자 기본값 | 기본값 없음 · `.env` 에 없으면 멈추며 알림 |
| `server/.env.example` | 세 계정 비밀번호 · 접속 주소 | 비밀번호 빈칸 · 주소는 `<PG_…_PASSWORD>` 자리표시 |
| `server/landxi_api/config.py` | 세 접속 주소 기본값 | 비밀번호 뺀 주소(값은 `.env` 가 정본) |
| `server/ops/audit_read.py` | 최고 관리자 주소 기본값 | 없으면 멈추며 알림 |
| `server/ops/storage_poller.py` | 작업 계정 주소 기본값 | `server/.env` 에서 읽음(관제가 띄워 환경값이 없다) |
| `server/seed/seed_from_cards_js.py` | 앱 · 작업 계정 기본값 | `.env` 에 없으면 멈추며 알림 |
| `server/migrations/0001_init.sql` | 앱 · 작업 계정 첫 비밀번호 | 비밀번호 없이 역할만 만들고, seed 가 `.env` 값으로 넣음 |

- 같은 값을 쓰는 곳(바꾼 뒤 모두 새 값으로 붙음): 게이트웨이 · 작업자(설정 → `.env`), 마이그레이션 · 운영 스크립트 · 전국 분석 예약(15분마다 새로 읽음).
- **백업 · 되살리기 시험(`ops/db_backup.py`)과 그 예약 작업은 비밀번호를 쓰지 않는다**(컨테이너 안에서 바로 붙음). 백업 파일에도 역할 비밀번호는 빼고 저장한다.
- 저장소 밖(서버 기록 폴더 · 백업 폴더 · 실행 환경 폴더 · 검수 폴더)에서도 옛 값 0건. 저장소 안에서는 위 표의 7곳과 `server/.env`(올리지 않는 파일)뿐이었다.
- 첫 이력(0001) 글이 바뀌면 이력 적용기가 그 파일을 다시 돌리므로, 이력 기록의 지문만 새 글에 맞췄다(바뀐 곳은 이미 있는 역할을 만드는 줄뿐이라 다시 돌 필요 없음). 게이트웨이 재기동 때 다시 적용된 이력 0개 확인.

## 이런 것도 필요하지 않을까요?

1. **push 전 시크릿 검사를 자동으로** — 오늘 같은 일이 다시 생기지 않게, 커밋 전에 `server/.env` · `.env.local` 의 값이 커밋에 들어가는지 보는 검사(커밋 고리)를 둔다. 누가: 커밋하는 모든 에이전트. 왜: 지금은 사람이 기억해서 찾고 있다.
2. **비밀번호 바꾸기 순서를 스크립트 하나로** — 백업 → 바꾸기 → `.env` → 다시 띄우기 → 옛 값 거절 확인. 누가: 운영 담당. 왜: 정식 오픈 전과 사람이 바뀔 때마다 해야 하는 일이다.
3. **Redis 에도 비밀번호** — 지금은 문만 이 PC 안으로 닫았다. 같은 PC 의 다른 프로그램(다른 Docker 묶음 등)도 작업 대기열을 고칠 수 있다. 누가: 운영 담당. 왜: 작업 대기열 조작은 곧 AI 분석 결과 조작이다.
