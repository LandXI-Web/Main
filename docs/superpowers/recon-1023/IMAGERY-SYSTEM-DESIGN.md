## 0. 사용자 물음에 먼저 답

- **"개별로 올려도, 공유 데이터로 올려도 하나의 공간에 다 되나?"** — 그렇다. **영상 파일은 한 번만 저장**하고, 같은 줄에 **범위**(내 것 · 프로젝트 · 공유 데이터 · 기관)만 붙였다 뗀다. 직원이 올린 영상을 관리자가 승인하면 복사 없이 '공유' 범위가 더해지고, 프로젝트에 넣으면 '프로젝트' 범위가 더해진다. 화면은 역할마다 '영상' 한 곳이고, 필터가 범위다.
- **"프로젝트 영상을 따로 관리하는 개념도 검토됐나?"** — 됐다. 프로젝트 영상은 **별도 보관함이 아니라 같은 장부의 '프로젝트' 범위**다. 프로젝트 화면의 영상 칸은 그 범위로 거른 같은 목록이다. 프로젝트를 지워도 영상은 남고(범위만 빠짐), 다른 범위가 없는 영상만 올린 사람에게 '지울까요'를 묻는다.
- **"수백 GB 원본이 더 잦다"** — 맞다. 그래서 브라우저 올리기는 50GB 아래의 길로 두고, 그 위는 **업로드 전용 프로그램**(밤새 · 끊겨도 저절로 이어감)과 **서버 받는 폴더**(외장 디스크)를 정식 길로 설계했다(3절 · 속도표).

## 1. 지금 — 세 군데로 자란 영상 자리

| 자리 | 누가 올림 | 누가 봄 | 저장 자리 | 장부 | 빠진 것 |
|---|---|---|---|---|---|
| 공유 데이터 | LX 관리자(데이터 올리기 · 서버 경로 등록) | 모든 LX 직원 · 공유한 기관 | `cog/std` · `imagery/mosaics` · 보관 영상(D:) | 영상 표 role=imagery · 기관 공유 표 | 승인 대기 · 저장 현황이 표 밖 |
| 프로젝트 영상 | 직원(데이터 올리기 · 새 프로젝트) | 그 프로젝트 사람 | 같은 영상 표 + 프로젝트 연결 | 영상 표 + 프로젝트 영상 연결 | 목록 · 지우기 · 연도 고치기 없음(GAPS-STAFF 4) |
| 내 영상 | 직원(분석 서비스 카드) | 올린 사람만 | `imagery/own/{주인}/{연-월}/` | 영상 표 role=own | 목록 · 지우기 · 보관 기한 없음(GAPS-STAFF 14) · 100GB 한도에 쌓임 |
| (넷째) 기관이 맡긴 영상 | 기관(분석 요청) | 그 기관 · 담당 LX | `tenants/{기관}/requests/…` | 영상 표 role=request · 요청 표 | 기관이 자기 영상 목록을 한눈에 못 봄 |

좋은 점은 그대로 둔다: **기관 공유는 복사 0 · 권한 한 줄**, 표준본 한 벌(COG · JPEG 90 · 넷째 밴드 곁 파일), 원본 90일 정리, 같은 파일 두 번 올리면 막음, 조각 올리기 · 이어 올리기(64MB 조각 · 30분 저절로 다시 잇기), 올리기 창(화면을 옮겨도 계속). 문제는 **장부 하나에 '자리'가 역할 칸(role)으로 갈라져 있고, 화면이 자리마다 따로**라는 것뿐이다.

## 2. 한 저장소 · 한 장부

### 2-1. 장부 한 줄 = 영상 하나

| 칸 | 값 | 어디서 오나 |
|---|---|---|
| 지문 | 파일 내용 지문(올리기가 끝날 때 이미 잰다) | 같은 지문이면 새 줄을 만들지 않고 범위만 더한다 |
| 같은 영상 후보 | 범위(지도) 95% 이상 겹침 + 같은 촬영 연월 + 같은 해상도 | '같은 영상일 수 있음' 표시만(합치지 않음 · 5절) |
| 촬영 | 연월(일까지 있으면 일) | 파일 머리(EXIF · 메타) → 없으면 사람이 '확인 필요'에서 입력 |
| 해상도 · 종류 | cm · 드론 / 항공 / 위성 | 파일에서 · 종류는 해상도 · 센서 이름으로 추정 뒤 사람이 고침 |
| 센서 · 기체 | 있으면 | 파일 메타 |
| 좌표계 · 범위 | EPSG · 지도 도형 | 파일(없으면 등록 안 함 — 지금 규칙 그대로) |
| 크기 | 원본 · 표준본 · 곁 파일 | 장부에 적어 두고 더한다(폴더 훑지 않음 — P4 방식) |
| 출처 | 올린 사람 · 올린 길(브라우저 · 업로드 프로그램 · 받는 폴더 · 서버 경로 · 기관 요청 · 국토지리정보원) | 올리기가 적는다 |
| 개인정보 | 확인 필요 / 확인함(누가 · 언제) / 해당 없음 | 5cm 이하 드론 · 기관 요청 영상은 기본 '확인 필요' → 공유 전 관리자가 확인 |
| 상태 | 올리는 중 → 표준본 만드는 중 → 쓸 수 있음 · 확인 필요 · 비공개 · 휴지통 | 한 흐름 |
| 범위 | 내 것 · 프로젝트(n) · 공유 데이터 · 기관(n) · 기관이 올림 | **범위 표(영상 × 범위 × 누가 · 언제)** 한 벌 — 지금 role 칸 · 프로젝트 연결 · 기관 공유 표를 이 한 벌로 읽는다 |
| 쓰임 | 결과 n건 · 프로젝트 n개 · 분석 요청 n건 | 결과 · 작업 표가 영상 id 를 가리키는 것을 센다 |
| 파생물 | 표준본(COG) · 넷째 밴드 곁 파일 · 미리보기 그림 · 지도 조각(pmtiles 또는 서명 동적 타일) · 범위 도형 | 모두 영상 id 아래 한 벌 |

### 2-2. 파일 자리(새 것부터 · 옛 경로는 장부가 가리키는 대로)

```
02. 데이터/imagery/
├─ originals/{주인}/{연-월}/{영상id}/   원본 + 곁 파일(90일 뒤 정리 · 보관 영상은 예외)
├─ std/{주인}/{연-월}/{영상id}.tif      표준본(+ .b4.tif · 미리보기 .jpg)
├─ tiles/{영상id}.pmtiles              지도 조각(필요한 것만)
├─ inbox/{주인}/                        서버 받는 폴더(3-3)
└─ mosaics/ · overseas/ · sheets/       지금 그대로
```
주인 = `lx`(공유 · 직원) 또는 기관 id. 직원 '내 것'도 `lx` 아래이고 주인 구분은 장부 범위가 한다 — 승인돼 공유로 바뀌어도 **파일을 옮기지 않는다**(용량 몫만 직원 → LX 로 옮겨 센다). 지금의 `cog/std` · `imagery/own` · `tenants/…/requests` 는 그대로 읽힌다(5절).

## 3. 올리는 길 셋 — 같은 장부 · 같은 조각 올리기 약속

| 길 | 누가 · 언제 | 크기 | 어떻게 |
|---|---|---|---|
| ⓐ 브라우저 | 모든 LX 계정 · 기관 · 수 GB~수십 GB | **~50GB 까지 권장** | 지금 올리기 창(①/② 모양은 따로 시안 중 — 여기서 정하지 않음) · 64MB 조각 · 30분 저절로 다시 잇기 · 7일 안 이어 올리기 |
| ⓑ 업로드 전용 프로그램 | 사무실 PC 에서 밤새 · 수백 GB~TB | 50GB~2TB | 아래 3-2 |
| ⓒ 서버 받는 폴더 | LX 관리자(서버 앞 · 외장 디스크) · 같은 망 | 수백 GB~수 TB · 한 번에 많은 장 | 아래 3-3 |

### 3-1. 걸리는 시간 — 길마다(100GB · 500GB · 2TB)

| 길 | 속도 | 100GB | 500GB | 2TB | 근거 |
|---|---|---|---|---|---|
| 바깥 주소(Cloudflare) · 연결 1개 | 초당 5.5MB | 약 5시간 | 약 1일 1시간 | 약 4일 5시간 | 10-22 실측(3.2GB 9.8분) |
| 바깥 주소 · 조각 4개 동시(업로드 프로그램) | ~초당 15~20MB | ~1시간 30분~2시간 | ~7~9시간 | ~1일 5시간~1일 13시간 | **추정** — 1개 연결의 한계가 회선이 아니라 왕복이면 이만큼 · 시험 전엔 약속하지 않음 |
| 같은 망(사내 1Gbps · 터널 안 거침) | ~초당 100MB | ~17분 | ~1시간 25분 | ~5시간 40분 | 추정 · 서버 E: 디스크 쓰기 속도(SATA)가 상한 |
| 외장 디스크 → 서버(받는 폴더) | ~초당 150MB | ~11분 | ~56분 | ~3시간 40분 | 추정 · USB 3 · 디스크 쓰기 상한 |
| + 표준본 만들기(모든 길 공통 · CPU 4개) | 원본 크기에 따라 | 수십 분~ | 몇 시간 | 밤 하나 이상 | 재지 않음 · 큰 파일은 한 번에 하나씩(지금 규칙) |

**Cloudflare 가 정하는 것**: 한 요청 본문 100MB(그래서 조각 64MB) · 한 요청 100초(그래서 큰 파일 끝 확인은 뒤에서) · 전체 대역폭 상한은 공식에 없지만 연결 하나로 5.5MB 가 실측. 바깥에 여는 문은 Cloudflare 터널 하나뿐이므로(개발 서버 · 다른 포트는 열지 않음) 바깥에서 더 빠른 길은 **동시 조각**뿐이고, 진짜 빠른 길은 **같은 망**과 **디스크**다.

**권장**: 50GB 아래 → ⓐ · 50GB~1TB 사무실에서 → ⓑ(밤에 시작 · 아침에 확인) · 1TB 넘거나 여러 장 묶음 → ⓒ(외장 디스크 가져오기) · 서버 E: 남은 공간 1.3TB(200GB 는 늘 남김)는 길과 상관없이 먼저 본다.

### 3-2. 업로드 전용 프로그램 — 'Land-XI 업로더'

| 항목 | 설계 |
|---|---|
| 모양 | 1단계 **명령 한 줄 도구**(exe 한 개 · 설치 없음) → 2단계 **트레이 창**(끌어 놓기 · 진행 · 멈춤) — 둘 다 같은 속 |
| 로그인 | Land-XI 계정으로 한 번 로그인 → **기기 토큰**(90일 · 이름 있는 기기 · 계정 관리 화면에서 폐기 가능) · 비밀번호는 PC 에 저장하지 않음 |
| 받는 것 | 폴더째 끌어 놓기(곁 파일 자동 짝) · 형식 · 좌표계 · 중복을 **보내기 전에** PC 에서 검사해 안내(원칙 326) |
| 보내기 | 같은 조각 올리기 약속(64MB · 이어 올리기 · 지문) · 조각 2~4개 동시(시험 뒤 기본값 정함) · 끝나면 서버가 등록 → 장부 |
| 끊김 · 재부팅 · 절전 | 진행을 PC 파일에 적어 두고 **시작 프로그램**으로 다시 떠서 받은 자리부터 저절로 이어 감 · 절전은 올리는 동안 막음(PC 설정 바꾸지 않음) |
| 속도 제한 | 업무 시간(09~18시) 회선의 절반 · 밤은 전부 · 사용자가 바꿈 |
| 보이는 곳 | PC 창 + **웹 머리줄 '올리는 중 44% · 약 13시간 · 업로드 프로그램'**(시안 staff) + LX 관리자 대시보드 '올리는 중 n건' — 모두 서버 올리기 장부 한 출처 |
| 쓰임 지정 | 시작할 때 '내 것 / 프로젝트 ○○ / 공유 데이터(관리자만)' 고름 → 끝나면 그 범위로 등록 |
| 배포 | LX 관리자 화면 '인프라'에서 내려받기 · 코드 서명은 정식 오픈 전 |
| 안 하는 것 | 비밀번호 저장 · 서버에 직접 붙는 다른 포트 · 파일 변환(표준본은 서버가) |

### 3-3. 서버 받는 폴더

| 항목 | 설계 |
|---|---|
| 자리 | `imagery/inbox/{주인}/` — 외장 디스크를 서버에 꽂고 관리자 화면 '공유 데이터 → 영상 업로드 → 서버 폴더에서'를 눌러 폴더 고름 |
| 누가 | 1단계 **LX 관리자만**(서버 앞에 있는 사람) · 2단계 같은 망 직원 공유 폴더(`\\서버\landxi-inbox\{직원}`)는 질문 5 |
| 검사 | 서버가 훑어 형식 · 곁 파일 · 좌표계 · 지문 · 중복 · 남은 자리를 확인하고 **등록 전에 목록으로 보여 준다**(몇 장 · 몇 GB · 문제 n장) → 관리자가 '등록' |
| 옮기기 | 같은 디스크면 이름 바꾸기(복사 0) · 다른 디스크면 복사 뒤 지문 대조 · 끝나면 외장 디스크 쪽은 그대로(지우지 않음 · 사람이) |
| 그 뒤 | 표준본 · 장부 · 진행은 다른 길과 똑같이 머리줄 '받는 폴더 1' |
| 안 하는 것 | 폴더를 자동 감시해 저절로 등록(틀린 파일이 그대로 장부에 들어감 — 사람이 '등록'을 누른다) |

## 5. 옮기기 — 지금 세 자리를 깨지 않고

| 단계 | 무엇 | 깨지지 않는 이유 | 크기(추정) |
|---|---|---|---|
| 1 장부 | 범위 표 한 벌 만들고 지금 값으로 채움(role=imagery → 공유 · own → 내 것 · request → 기관이 올림 · 프로젝트 연결 → 프로젝트 · 기관 공유 표 → 기관). 옛 칸은 그대로 두고 **둘 다 쓰는 기간**(새 길은 둘 다 적음 · 읽는 쪽을 하나씩 옮김) | 영상 id 불변 · 결과 · 작업 · 서명 세트 이름이 가리키는 것이 그대로 | Opus 1~2일 |

**위험**: ① role 칸을 읽는 곳이 여럿(목록 · 지도 층 · 자동 고르기 · 지역 영상 수 · 카드 후보) — 둘 다 쓰는 기간 없이 바꾸면 내 영상이 공유 목록에 새거나 반대로 공유 영상이 사라진다 ② 지문이 같은 옛 영상 2건을 합치면 결과가 가리키던 id 하나가 없어진다 ③ 저장 현황 숫자가 폴더 훑기와 장부 합이 다를 수 있다 — 장부 한 출처로 정하고 주 1회 짝 맞추기(P4)로 확인 ④ 업로더의 동시 조각이 게이트웨이 프로세스 4개에서 같은 조각을 두 번 붙일 틈 — P1 의 파일 잠금이 막지만 동시 조각 시험으로 다시 확인.

**하지 말 것**: 파일 대량 이동 · 영상 id 바꾸기 · 옛 중복 자동 합치기 · '영상 보관함' 같은 **넷째 자리** 만들기 · 공유를 복사로 · 내 영상에 90일 원본 규칙을 바로 적용해 지우기(원본이 표준본 전이면 지우면 안 됨) · 바깥에 다른 포트 열기 · 업로더에 비밀번호 저장 · 받는 폴더 자동 등록 · 구현 전 확인 대장 번호 없이 만들기(원칙 323).

## 7. 이런 것도 필요하지 않을까요?

- **영상 올린 뒤 '범위 · 날짜 한 장'**(누가: 올린 직원 — 범위가 맞는지 지도에서 바로 보고 분석을 걸게 · P1 제안 3 과 같음).
- **촬영 연도 모름 영상의 '확인 필요' 칸**(누가: 직원 — 지금은 눌러도 아무 일 없음 · 두 해 비교가 막힘).
- **기관별 저장 사용량에 '영상' 줄 분리**(누가: LX 관리자 — 지금 표는 원본 · 표준본 · 결과 · 공간 합계. 범위별(공유 · 내 것 · 기관)로 보이면 한도 응대가 쉬움).
