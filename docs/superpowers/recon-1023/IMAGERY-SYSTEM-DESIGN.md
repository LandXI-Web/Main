## 1. 지금 — 세 군데로 자란 영상 자리(1판 그대로 · 요약)

| 자리 | 누가 올림 | 누가 봄 | 빠진 것 |
|---|---|---|---|
| 공유 데이터 | LX 관리자 | 모든 LX 직원 · 공유한 기관 | 승인 대기 · 저장 현황이 표 밖 |
| 프로젝트 영상 | 직원(새 프로젝트 창) | 그 프로젝트 사람 | 목록 · 지우기 · 연도 고치기 없음 |
| 내 영상 | 직원(분석 서비스 카드) | 올린 사람만 | 목록 · 지우기 없음 · 100GB 에 쌓임 · 올린 직후 자기 영상 미리보기가 403 |
| 기관이 맡긴 영상 | 기관(분석 요청) | 그 기관 · 담당 LX | 기관이 자기 영상 목록을 한눈에 못 봄 |

좋은 점은 그대로: 기관 공유는 복사 0 · 권한 한 줄, 표준본 한 벌, 같은 파일 두 번 올리면 막음, 조각 올리기 · 이어 올리기, 화면을 옮겨도 계속(원칙 330). 문제는 **장부 하나에 '자리'가 역할 칸으로 갈라져 있고 화면이 자리마다 따로**라는 것뿐이다.

## 2. 한 저장소 · 한 장부

### 2-1. 장부 한 줄 = 영상 하나(1판 그대로)

지문 · 같은 영상 후보 · 촬영 · 해상도 · 종류 · 센서 · 좌표계 · 범위 · 크기 · 출처(올린 사람 · 올린 길) · 개인정보 확인 · 상태 · **범위(내 것 · 프로젝트 n · 공유 데이터 · 기관 n · 기관이 올림)** · 쓰임(결과 n · 프로젝트 n · 요청 n) · 파생물(표준본 · 넷째 밴드 · 미리보기 · 지도 조각). 범위는 **범위 표(영상 × 범위 × 누가 · 언제) 한 벌**로 — 지금의 role 칸 · 프로젝트 연결 · 기관 공유 표를 이 한 벌로 읽는다.

### 2-2. 파일 자리(1판 그대로)

`imagery/originals/{주인}/{연-월}/{영상id}/` · `std/…` · `tiles/…` · `inbox/{주인}/`(받는 폴더 — 질문) · 옛 경로는 장부가 가리키는 대로. 승인돼 공유로 바뀌어도 **파일은 옮기지 않고** 용량 몫만 직원 → LX 로 옮겨 센다.

### 2-3. 흐름 · 권한 · 보관(답 2 · 3 반영)

| 흐름 | 누가 | 무엇이 일어나나 |
|---|---|---|
| 내 영상 → 공유 데이터 | 직원이 '공유 데이터로 보내기' → 관리자 승인 | 복사 0 · 범위에 '공유' 추가 · 개인정보 '확인 필요'면 승인 막힘 · 거절은 사유 한 줄 · 승인되면 그 영상은 직원 용량에서 빠짐 |
| 프로젝트에서 쓰기 | 구성원이 '영상 더하기' | 범위에 '프로젝트' 추가 · 프로젝트를 지우면 범위만 뺌(영상은 남음) |
| 기관에 공유 | 관리자(지금 그대로) | 범위에 '기관' 추가 · 그 기관 지도 서비스에 보임 · 관할 안만 · 보기 · 분석만(5절) |
| 기관이 올린 영상 | 기관(분석 요청에 붙여서) | 그 기관 + 그 요청의 담당 LX 직원 + 관리자만 봄 · LX 가 공유 데이터로 올리려면 기관 동의(5-5절) |
| 지우기 | 내 것 = 올린 사람 · 공유 = 관리자 · 프로젝트 = 범위만 뺌 · 기관이 올림 = 그 기관(요청이 끝난 뒤) | **휴지통 30일**(되살리기) → 완전히 지움 · 기록 한 줄 · 휴지통 안도 용량에 셈 |
| 결과가 쓰는 영상 | — | **지울 수 없음** — '결과 n건이 쓰는 영상'을 보여 주고, 결과를 먼저 보관 처리해야 지울 수 있다 |
| 원본 정리 | 서버(하루 한 번) | 표준본 확인 90일 뒤 원본만(원칙 94) · 보관 영상(서버 경로 등록)은 안 지움 |
| 안 쓰는 내 영상 | — | **기한 없음**(답 2). 용량 한도가 제약 · 안 쓴 지 오래된 영상은 용량 칸에서 '안 쓴 지 n개월'로 보여 줄 뿐 |

### 2-4. 용량 한도 — 유일한 제약(답 2)

| 어디 | 무엇을 보이나 |
|---|---|
| 막대 | 프로젝트 영상 탭 · 분석 서비스 영상 고르기 · 업로더 '보내기 전 확인' · 대시보드 내 정보 — **같은 값 한 출처**(`/me/storage`) · "62GB 씀 · 휴지통 9GB 포함 / 100GB" |
| 무엇이 차지하나 | 내 것 영상(원본 + 표준본) · 프로젝트에 내가 올린 영상 · 휴지통 · 프로젝트 파일. 공유로 승인된 영상은 빠짐. 공유 데이터에서 고른 영상은 **내 용량에 들지 않음**(복사 0) |
| 80% | 막대 아래 경고 글자 한 줄("80%를 넘었습니다") + 알림 1회 · 올리기는 계속 됨 · 업로더는 '보내기 전 확인'에서 "끝까지 받을 수 없습니다"를 미리 알림(시안 `uploader-2-check`) |
| 100%(올릴 자리 없음) | 새 업로드 **시작 안 됨**(지금의 '남은 자리' 검사 그대로 · 한 파일 크기 + 올리는 중인 것 합으로 판정) · 세 길 안내: 휴지통 비우기(바로 돌아옴) · 안 쓰는 영상 지우기 · 용량 늘리기 요청(관리자 승인 · 지금 있음) · 올리던 것이 한도에 닿으면 **멈춤 상태로 보존**(7일) — 자리가 나면 이어 올림 |
| 관리자 | 공유 데이터 '저장 현황' 탭(1판 admin 시안) — 서버 남은 공간 한 숫자 · 주인별 막대 · 늘리기 요청 대기 n |

### 3-1. 걸리는 시간(1판 그대로)

바깥 주소 연결 1개 초당 5.5MB(10-22 실측) → 100GB 약 5시간 · 500GB 약 1일 · 2TB 약 4일. 업로더 조각 4개 동시 ~초당 15~20MB(추정 · 시험 뒤 약속) → 100GB ~2시간 · 500GB ~8시간 · 2TB ~1일 반. 같은 망 ~초당 100MB · 외장 디스크 ~초당 150MB. 표준본 만들기는 모든 길 공통으로 따로 걸린다. **권장**: 50GB 아래 ⓐ · 50GB~1TB 사무실 ⓑ(밤에 시작 · 아침에 확인) · 1TB 넘거나 여러 장 ⓒ(쓰기로 하면).

### 3-3. 서버 받는 폴더 — 무엇인지(답 5 · 아직 질문)

**쉬운 말로**: 영상이 수 TB 짜리 외장 디스크에 담겨 사무실에 도착했을 때, 그 디스크를 **서버 본체에 직접 꽂고** 서버 안의 '받는 폴더'로 옮겨 넣는 길이다. 인터넷(바깥 주소)을 전혀 거치지 않아 가장 빠르고(2TB 가 서너 시간), 수십 장 묶음도 한 번에 들어간다. 쓰는 사람은 **서버 앞에 갈 수 있는 LX 관리자**뿐이고, 직원 · 기관은 쓰지 않는다. 옮겨 넣은 뒤 관리자 화면 '공유 데이터 → 영상 업로드 → 서버 폴더에서'를 눌러 서버가 폴더를 훑어 목록(몇 장 · 몇 GB · 문제 n장)을 보여 주면 관리자가 '등록'을 누른다 — 폴더를 자동 감시해 저절로 등록하지는 않는다(틀린 파일이 그대로 장부에 들어가는 것을 막기 위해). 이 길이 **꼭 필요한지는 사용자 결정**이다: 업로더(3-2)로도 2TB 를 하루 반이면 올릴 수 있으니, 외장 디스크로 영상을 받는 일이 실제로 잦은지에 달렸다.

```
 [촬영 업체 · 지자체]                [LX 사무실 · 서버실]                      [Land-XI]
  외장 디스크(2TB)  ──택배·방문──▶  관리자가 서버 본체에 꽂음  ──복사──▶  imagery/inbox/lx/  ──관리자 '등록'──▶  장부 한 줄 · 표준본 · 공유 데이터
                                   (인터넷 안 거침 · 초당 ~150MB)        서버가 훑어 목록 보여 줌          (다른 길과 똑같은 뒤처리)
```

## 5. 공유 · 보안 체계 — 공개제한 영상(답 6 · 원칙 331)

### 5-1. 한 줄 원칙

**영상은 공유해도 파일은 나가지 않는다.** 모든 화면은 지도 조각(256px · 로그인 · 서명 · 만료)으로만 보여 주고, 원본 · 표준본 파일을 내려받는 길은 **기본으로 없다**. 공유는 복사 0 · 범위 한 줄이고, 그 줄을 누가 언제 붙였는지 · 누가 언제 봤는지 · 분석에 썼는지가 기록에 남는다.

### 5-2. 범위 × 행동 표

| 범위 \ 행동 | 보기(지도 조각) | 분석에 쓰기 | 내려받기(원본 · 표준본) | 다시 공유 |

### 5-5. 기관이 올린 영상 — 동의 규칙

- 기관이 분석 요청에 붙여 올린 영상은 **기관 것**이다. 기본 범위 '기관이 올림'(그 기관 · 담당 LX 직원 · 관리자).
- LX 가 공유 데이터로 올리거나 다른 기관에 공유하려면 **기관 동의 한 번**이 필요하다 — 동의는 기관 담당자가 기관 화면에서 누르고(요청 상세에 '이 영상을 LX 공유 데이터로 올려도 됩니다' 한 줄 + 동의 · 거절), 기록에 남는다. 올릴 때 미리 '동의' 칸을 두느냐, 매번 묻느냐는 질문 Q4.
- 동의 뒤에도 기관은 언제든 **동의 철회**를 할 수 있고, 철회하면 새 분석에는 못 쓰되 이미 나온 결과 아래 조각은 그대로(10-14 규칙과 같음).
- 요청이 끝나면 기관이 지울 수 있다(휴지통 30일 · 결과가 쓰면 못 지움 — 2-3).

## 6. 옮기기 — 지금 세 자리를 깨지 않고(1판 + 답 반영)

| 단계 | 무엇 | 크기(추정) |

| 1 장부 | 범위 표 한 벌 · 지금 값으로 채움 · 둘 다 쓰는 기간 · 내 영상 403 풀림 · 관리자 응답에서 경로 뺌 | Opus 1~2일 |

**위험**: role 칸을 읽는 곳이 여럿 — 둘 다 쓰는 기간 없이 바꾸면 내 영상이 공유 목록에 새거나 공유 영상이 사라짐 · 지문 같은 옛 영상 2건을 합치면 결과가 가리키던 id 가 사라짐 · 열람 기록을 조각마다 적으면 DB 가 먼저 참(하루 한 줄로) · 업로더 동시 조각이 게이트웨이 4개에서 같은 조각을 두 번 붙일 틈(파일 잠금 시험).

**하지 말 것**: 파일 대량 이동 · 영상 id 바꾸기 · 옛 중복 자동 합치기 · '영상' 메뉴 · '영상 보관함' 같은 넷째 자리 · 공유를 복사로 · 어느 화면에도 원본 내려받기 단추 · 바깥에 다른 포트 · 업로더에 비밀번호 저장 · 받는 폴더 자동 등록 · 조각 워터마크를 기본으로 · 확인 대장 번호 없이 만들기(원칙 323).

## 8. 이런 것도 필요하지 않을까요?

- **영상 올린 뒤 '범위 · 날짜 한 장'**(누가: 올린 직원 — 범위가 맞는지 지도에서 바로 보고 분석을 걸게).
- **촬영 연도 모름 영상의 '확인 필요' 칸**(누가: 직원 — 지금은 눌러도 아무 일 없음 · 두 해 비교가 막힘).
- **용량 칸에 '안 쓴 지 n개월' 표시**(누가: 한도에 걸린 직원 — 기한은 없어도 무엇을 지울지 스스로 고를 수 있게 · 답 2 와 어긋나지 않음).
- **업로더 '이 PC' 목록을 계정 관리에**(누가: 직원 · 관리자 — 퇴직 · PC 교체 때 기기 토큰을 끊을 자리).
- **조각 긁기 알림 기준을 시험으로 정하기**(누가: 보안 담당 — 보통 열람이 한 시간에 조각 몇 개인지 재야 기준이 지어낸 숫자가 안 됨).
