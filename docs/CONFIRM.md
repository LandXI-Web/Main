# Land-XI 확인 대장 — 기록 → 사용자 확인 → 구현 → 구현 확인

> 2026-09-30 사용자: "방향성을 잃지 않도록 자주 기록해 놓고 기록에 대해 나에게 피드백을 점검받아. 제대로 된 부분만 구현을 진행하고, 구현에 대한 피드백도 점검받는다. 이러한 걸 다 기록화하고 컨펌 안 된 건 구현하지 않고. 오퍼스 5.5, 소넷 5.5 지시할 때도 기록을 공유하여 체계적인 지시·관리한다."

## 보는 곳
확인 요청 페이지(캡처·열어 볼 주소·계정·고르는 버튼): https://landxi-web.github.io/Main/landxi/proto/review/confirm/ — 생성 `python tools/review/build-confirm.py`

## 규칙
1. 새 기획·변경은 먼저 이 대장에 **확인 대기**로 적고, 확인 요청 페이지에 **지금 · 제안 · 보는 곳(캡처 + 열어 볼 주소·계정·누를 곳) · 고를 것**을 올려 사용자에게 보여 준다. "무엇을 보고 무엇을 고르는지" 없이 확인을 요청하지 않는다.
2. 사용자가 **확인**한 항목만 구현한다. **보류·반려**는 구현하지 않는다(이유를 적어 둔다).
3. 구현이 끝나면 **구현 확인 대기**로 올리고 화면(주소·캡처·영상)을 보여 준다. 사용자 피드백을 받아 **완료** 또는 **다시**.
4. 에이전트(Opus 5.5·Sonnet 5.5·Fable 5.1)에게 일을 줄 때는 이 대장의 항목 번호와 확인 내용을 그대로 넘긴다. 대장에 없는 일·확인 안 된 일은 지시하지 않는다.
5. 사용자가 준 지시 자체(USER-DIRECTIVES.md 원칙)는 확인된 것으로 본다. 그 지시를 **어떻게** 구현할지(방법·문구·주소 이름 등)가 새로 정해지면 여기서 확인받는다.

## 대장 비교의 기본 틀 — 초안(오케스트레이터 · 09-30) · 확인 대기
사용자: "부서 대장 표본이 너무 다양하다. 건건이 커스텀은 한계 — 커스텀 영역으로 보내고 기본 틀을 고민. 프로젝트 영역 안에서 이뤄져야 하나? 어디까지 AI 와 비교 가능한가?"

**1. 세 층**
| 층 | 무엇 | 기관이 할 일 | 누가 만드나 |
|---|---|---|---|
| ① 기본 비교 | AI 결과 × 나라가 이미 공개한 기준(지적도 지목·용도지역·개발제한구역 경계·건축물 정보·섬 목록 등) | 없음 | LX 가 한 번 만들면 전국 어디서나 |
| ② 표준 양식 비교 | AI 결과 × 기관 대장 — 대장에서 **위치 한 칸(필지 번호·지번 주소·좌표 중 하나) + 상태 한 칸 + 날짜 한 칸**만 뽑아 올리면 맞춰 줌(엑셀 양식 제공, 열은 자동 인식 후 사람이 확인) | 세 칸짜리 표 올리기 | LX 가 서비스마다 '무엇과 비교하나'만 정함 |
| ③ 커스텀 | 틀에 안 맞는 특수 대장·복잡한 규칙 | 사업 협의 | 연차 사업의 맞춤 개발(서비스 제공 체계 ⓒ) |

**2. 어디까지 AI 와 비교 가능한가 — 판별 질문 셋**
- 같은 곳인가: 대장에 위치 열쇠(필지 번호·지번·좌표·구역 이름)가 있는가
- 같은 것인가: 대장 항목이 영상에 보이는 성질인가(지붕·비닐·작물·쓰레기 더미 = 보임 / 소유자·허가 여부·임대 = 안 보임 — 안 보이는 것은 "AI 가 본 것과 대장에 적힌 것이 어긋난 곳" 표시까지만)
- 같은 때인가: 촬영일과 대장 기준일이 비교할 만큼 가까운가
→ 셋 다 예 = 비교 · 일부만 = 참고 표시 · 모두 아니오 = 비교하지 않음

**3. 어디서 하나** — 비교 기준을 **정하는 곳은 LX 프로젝트 안**(서비스 만들기 때 '이 서비스는 무엇과 비교 가능한가'를 카드에 담음) · 기관 대장을 **올리고 비교를 돌리는 곳은 기관 분기 플랫폼**(기관 데이터는 기관 안에서).

| # | 항목 | 상태 | 피드백 |
|---|---|---|---|
| 대장-틀 | 위 세 층 · 판별 질문 셋 · 정하는 곳(프로젝트)/돌리는 곳(기관) | 보류 → 다른 길 검토 | "아니면 매칭 기능 — 대조해야 할 것들을 사용자가 기능적으로 간단하게 매칭하도록 기능화해 비교한다든가, 아니면 LLM 서비스를 한다든가" |
