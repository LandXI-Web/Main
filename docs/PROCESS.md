# Land-XI 개발 공정 — 평가 → 기획 → 개발 → 실증 → 서비스 (원스톱)

> 2026-09-29 사용자: "백본도 중요하고, 플랫폼 안에서 구동하고 관리하고 작동하고 서비스하고 이 모든 체계가 원스톱으로 이뤄져야 한다. 이 과정에 대해서도 평가·기획·개발·실증·서비스 스텝을 그간 제대로 해야 했는데 제대로 안 된 아쉬움이 있다."

## 1. 원스톱 원칙
Land-XI 의 모든 일은 **플랫폼 화면 안에서** 끝나야 한다. 운영자가 명령줄·스크립트·파일 복사로 해야 하는 단계가 남아 있으면 그 기능은 '완성'이 아니다.

| 누가 | 플랫폼 안에서 끝나야 하는 일 |
|---|---|
| LX 직원 | 영상·데이터 올리기 → AI 모델 학습·결과 확인 → 서비스 만들기 → 지역에 적용 → 서비스 관리(오탐·재학습) |
| 지자체·해외 기관 | 로그인 → 우리 지역 AI 분석 결과 → 행정 데이터 올리기·융합 분석 → 말로 묻기 → 의심 필지 → 조치 → 보고서 |
| LX 관리자 | 계정·기관 승인 → GPU·작업 대기열·저장 공간 → 기관별 사용량·한도 → 서비스 배포·되돌리기 → 경보 |
| 게스트 | 플랫폼 소개 → 서비스·활용 사례 → 문의·로그인 |

## 2. 공정 5단계 — 코어·기능마다 이 순서를 지키고, 단계마다 기록을 남긴다
| 단계 | 하는 일 | 끝났다는 증거(기록 위치: docs/superpowers/final/process/<기능>/) |
|---|---|---|
| **① 평가** | 지금 무엇이 되고 안 되는지 실제로 써 보고 잰다(로그인부터, 두 지역 이상) | 평가표: 되는 것·안 되는 것·원스톱 끊기는 지점(명령줄이 필요한 단계) |
| **② 기획** | 사용자 규칙(USER-DIRECTIVES.md)에 맞춰 목표·범위·완료 기준을 정한다. 사소한 명칭은 기본값 | 기획서 1장: 목표 한 줄·흐름·완료 기준(측정 가능) |
| **③ 개발** | 백본(서버·데이터·AI) 먼저, 화면은 그 위에 | 코드·테스트 녹색·변경 목록 |
| **④ 실증** | 실제 데이터·실제 사용자 흐름으로 검증: 로그인부터, **서로 다른 시도 두 지역 이상 + 확인자가 무작위로 고른 한 지역**, 명령줄 없이 화면만으로, GPU 한 장 규칙 | 실증 기록: 시나리오·결과·영상·실패와 조치 |
| **⑤ 서비스** | 실제 쓰는 상태로 공개·운영: 배포(GitHub·운영 서버), 운영 지표·경보, 사용자 안내, 되돌리기 방법 | 서비스 기록: 배포 주소·운영 상태·알려진 한계 |

- 앞 단계의 증거 없이 다음 단계로 넘어가지 않는다. 판정은 각 단계의 증거로 한다.
- 화면·디자인(살)은 ③~⑤ 가 선 백본 위에서만 바꾼다.

## 3. 핵심 코어(백본) — 모두 이 공정을 거친다
1. XI맵 전역 AI 추론(전국 어느 시군구든)
2. 필지 실태조사(AI × 필지 × 대장 → 의심 → 결과 확인 → 조치 → 보고서)
3. 행정데이터 융합 + AI 도우미(올린 데이터 × AI, 말로 지도 제어·분석·즉시 시각화)
4. 관리-생산-서비스 한 흐름(같은 작업이 직원 → 기관 → 관리자 화면으로 이어짐)
