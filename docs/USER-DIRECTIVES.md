# Land-XI 사용자 지시·정정 기록 (하드 보관본)

> 2026-09-29 사용자: "나와 대화한 기록 중에서 중요하거나, 내가 지적해서 정정·보완하라는 부분은 대화 흐름이 끊겨도 다시 확인할 수 있게 프로젝트 경로에 하드로 저장해 놓고 관리하자."
>
> **관리 규칙** — Claude(오케스트레이터)는 사용자가 지시·정정·결정할 때마다 **그 턴 안에** 이 파일에 한 줄 이상 추가하고 커밋한다. 새 세션·새 에이전트는 작업 전에 이 파일과 `E:/Land-XI 플랫폼/CLAUDE.md`(필수 브리핑)를 읽는다. 같은 내용이 충돌하면 **날짜가 늦은 쪽이 이긴다.** 사용자 원문은 따옴표로 그대로 남긴다.

## A. 지금 유효한 원칙 (한 장 요약)
1. **정체성** — 공공기관 LX 가 제공하는 **유일한 GeoAI 실태조사 특화 플랫폼**. 정부 부처·지자체(전국) + 해외 기관 지원. (09-26)
2. **모토** — Hyper Performance · Hyper Solution · Hyper GeoAI 통합 플랫폼 서비스. (09-24)
3. **Hyper Performance** = AI 가 빠르게 전역을 추론 + vLLM 으로 말하면 지도 제어·융합 분석·바로 시각화. 숫자 나열이 아니라 체감. (09-27)
4. **판정 축** — 완성형 · 유일함 · Hyper Solution · Hyper Performance · 관리-생산-서비스 일원화 + 공무원·시민·LX 직원이 "우와". (09-26)
5. **사용자 3축** — LX 관리자 · LX 직원 · 서비스 사용자(지자체·해외). 기관 계정은 LX 와 완전 별도. 영업은 시연 없이 서비스·사례 중심. (09-24, 09-27)
6. **XI맵** = 플랫폼의 심장. 전국·해외 위성·항공·드론 영상을 실시간 분석하는 틀 + 결과 보기. 글로벌 버전 필요(대상국 키르기스스탄). (09-21, 09-24)
7. **전국 관점** — 남원은 예시일 뿐. 지역은 변수, 하드코딩 금지. 최소 두 지역으로 보여 준다. (09-27)
8. **행정데이터 융합** — vLLM 지도 제어·분석은 일반 API 가 아니라 **사용자가 올린 행정 데이터 × AI 결과** 융합. (09-27)
9. **LX 직원 관점** — "이게 뭐야? 우리는 뭘 해야 하지? 어떤 서비스를 만들 수 있지? 지자체에 어떻게 제공하지?"에 첫 화면이 답해야 한다. (09-27)
10. **깔끔·핵심만** — 어수선함·글 과다 금지, 불필요한 기능 지양. (09-27)
11. **개발 정보 노출 금지** — GPU명(예: 라데온 5700XT)·API 이름·파일 경로·작업 번호·좌표·ms. 출처 설명문 금지(신뢰는 작은 표시 + 호버 한 줄). (09-27)
12. **내부 지표 과장 금지** — 큰 숫자 자리엔 업무 결과만. (09-27)
13. **'시연'·'데모' 금지** — 실제 운영 서비스로 말한다. (09-27)
14. **용어** — 지어낸 말 금지. 관제→**LX 관리자 대시보드**, 생산 콘솔→**LX 직원 대시보드**, 정문→로그인, 반입→데이터 올리기, 조립→서비스 만들기, 검수→결과 확인, 이식→다른 지역에 적용, 판독→AI 분석. (09-29)
15. **디자인 톤** — 토스 분석을 반영한 밝은 톤. 관리자도 검정 톤 금지. (09-27)
16. **벤치마킹은 입력일 뿐** — 토스·카카오를 분석해 테마를 맞추는 것이지, 그 사이트·스펙시먼을 적용하거나 자산에 넣는 것이 아니다. (09-29)
17. **자산** — 자산 대장엔 **Land-XI 자산만**. Land-XI 자산은 지우지 않는다. **적용·검토·폐기는 사용자가 정리**한다. 정비는 불필요한 것만 최소로(스크롤 필름 등 보존). (09-29)
18. **공유 방식** — 사용자는 로컬 서버를 못 본다. 스크린샷·영상은 휴대폰으로, 결과는 GitHub(landxi-web.github.io/Main)에 정기 배포. 사용자에게 보이는 문서·허브도 사용자 말로, 모든 항목은 실제로 열려야 한다. (09-24, 09-27)
19. **우선순위** — 기능·퍼포먼스·서비스·UI/UX. 행정·조달 문서화(RFP·감리·인증)는 후순위. 현장 모바일 앱 제외. (09-26, 09-27)
20. **에이전트 운영** — 모든 에이전트는 투입 전에 기록(CLAUDE.md·이 파일·메모리)을 검토한다. Fable 5.1 = 기획·디자인 판단, Opus 5.5 = 구현·정비. 한도가 걸리면 Opus 가 할 수 있는 것부터. (09-23, 09-29)
22. **핵심 코어 우선** — 사소한 명칭·표기 문제로 멈추지 않는다. 기본값으로 진행하고 여기에 기록, 사용자가 나중에 정정. (09-29)
23. **백본 먼저** — 핵심 코어 4개(전역 AI 추론·필지 실태조사·행정데이터 융합과 AI 도우미·관리-생산-서비스 한 흐름)가 플랫폼에서 실제로 구현된 **백본**이 먼저다. 화면·디자인은 그 위에 붙였다 뗐다 하는 살. 백본 없이 살만 바꾸는 작업 금지. (09-29)
24. **원스톱 + 공정** — 구동·관리·작동·서비스가 모두 플랫폼 화면 안에서 끝나야 한다(명령줄 단계가 남으면 미완성). 모든 기능은 평가 → 기획 → 개발 → 실증 → 서비스 5단계를 거치고 증거를 남긴다(docs/PROCESS.md). (09-29)
25. **코어 목록은 CORE.md 가 기준** — C1 XI맵 전역 추론 · C2 vLLM 기반 GeoAI 서비스 · C3 필지 실태조사 · C4 행정데이터 융합 · C5 LX 생산 · C6 LX 관리자 인프라·기관·배포 · C7 한 흐름 · C8 글로벌 · C9 원스톱 공정. 단기 대화에 따라 코어를 빠뜨리지 않는다. (09-29)
26. **연결성** — 플랫폼은 이 PC 밖에서도 로그인·사용되어야 한다. 바깥 주소 https://app.land-xi.dev(공개 관문 tools/public-gate.mjs · server/start-public.ps1 · 로그온 자동 시작). 저장소 전체를 내주는 개발 서버(:4173)는 바깥에 열지 않는다. 계정 비밀번호는 저장소에 두지 않는다(server/.env). (09-30)
27. **입구 셋, 플랫폼 하나** — 로그인에 역할 탭 없음. LX 직원·영업은 한 로그인에서 아이디로 구분. LX 관리자 사이트와 기관 사이트는 입구를 따로 둔다. 셋 다 같은 Land-XI 서버·데이터·작업 흐름(관리-생산-서비스 한 흐름)의 분기다. (09-30)
28. **수시 피드백은 기록 먼저** — 사용자 피드백은 받은 턴에 이 파일에 적고 다음 차수에서 보완한다. (09-30)
29. **멘트 톤** — "~로 끝낸다", "유일한", "대체한다" 같은 단정·과장 구호 대신, 무엇으로 어떤 업무를 어떻게 돕는지 말하는 공공 서비스 말투("AI 기반 국토정보 통합조사", "현장조사 업무를 효율적으로 지원", "수요 맞춤형 행정서비스를 제공"). (09-30)
30. **시범 개발 검토 단계** — 정식 오픈 전. 계정은 사용자 혼자 쓰는 임시 계정 lxadmin(비밀번호는 server/.env). 정식 오픈 때 계정·비밀번호 체계를 다시 정한다. (09-30)
31. **줄바꿈·줄맞춤(모든 UI/UX)** — 의미 단위로 끊고, 글자 중간·한 단어 줄 금지, 제목 2줄 이내, 같은 왼쪽 선, PC·모바일 캡처로 확인. 세부는 design/system-v2.2-toss.md §2-1. (09-30)
32. **데모가 아니라 완전체** — 만드는 것은 실제 기관이 내일부터 쓸 수 있는 운영품이다. 판정은 CORE.md '완전체 기준' 표로. 가짜 데이터·고정 화면·명령줄 단계·"나중에 붙일" 자리는 미완성. (09-30)
33. **기능은 의도부터** — 모든 기능은 원래 의도(누가·왜)·목표(끝나면 무엇이 남나)가 먼저 서고 화면이 따른다. 화면이 사용자 대신 중요한 선택(지역 등)을 저절로 하지 않는다. 의도의 근거는 기존 GitHub 자산(대장·옛 화면·명세)의 기능과 역할 — 디자인은 참고하지 않음. (09-30)
34. **확인받고 만든다** — 기록 → 사용자 확인 → 구현 → 구현 확인. 확인 안 된 것은 구현하지 않는다. 에이전트 지시는 확인 대장(docs/CONFIRM.md) 항목과 기록을 그대로 넘겨서 한다. (09-30)
35. **역할별 점검 루프** — 차수마다 LX 직원·LX 관리자·지자체 관점으로 실제 로그인해 눌러 보고 돌려 보고, 작동 안 됨·부족함·있으면 좋을 것·도움될 것 네 칸으로 적어 기획 → (확인) → 구현 → 작동 → 보완. (CORE.md 역할별 점검 루프) (09-30)
36. **한국어로만** — 사용자에게 보이는 모든 글(작업 중 짧은 안내 포함)은 한국어. (09-30)
37. **확인 요청은 구체적으로** — 어디서(주소·계정·누를 곳) 무엇을 보고(캡처) 무엇을 고르는지(선택지) 함께 준다. 확인 요청 페이지로. 공개 페이지에 비밀번호는 적지 않는다. (09-30)
38. **플랫폼 위계** — Land-XI 플랫폼은 LX 직원·LX 관리자가 쓴다. 기관은 분기된 기관 플랫폼(예: 남원 GeoVision)을 그 기관 직원이 쓴다. 기관 안에도 기관 관리자와 부서 사용자가 있고, 부서는 자기 업무 서비스만 본다(예: 농정과 = 농지이용 전수조사). 기관 메인은 부서 공통으로 쓸 수 있는 기능만 — 자유도를 늘리면 복잡·통제가 어려워진다. (09-30)
39. **계정 범위 밖은 없다** — 계정의 대상지(관할) 밖 정보는 호출·표시·열람 모두 0. 화면에서 숨기는 게 아니라 서버가 내주지 않는다(검색 제안·지도·영상·AI 도우미 전부). 광역 기관은 광역 전체와 시군구 단위 둘 다. (09-30)
40. **보고서까지** — Land-XI 의 문서 기능은 보고서 생성이 범위다. 시정명령·공문처럼 행정 처분을 몰아붙이는 기능은 만들지 않는다. 현장 확인 배정도 지금은 없음. (09-30)
41. **데이터 올리기 = 영상과 행정 자산** — 올리는 대상은 위성·항공·드론 영상과 융복합할 수 있는 각종 행정 자산. 지역을 먼저 고르게 하지 않는다. 흐름은 기존 자산(옛 데이터 올리기 설계·구현)의 컨셉을 기준으로. (09-30)
42. **의미 없는 장식 금지** — 대기 화면의 드론 사진처럼 뜻 없는 그림·장식을 넣지 않는다. (09-30)
43. **UI/UX 통일성** — 모든 기능·화면에서 같은 일(올리기·승인/반려·목록/상세·상태 표시·빈 상태·오류 안내)은 같은 모양·같은 말. 새 기능은 공통 패턴부터 쓴다. (09-30, 2차 답 거의 전 항목)
44. **LX 직원의 일 단위 = 프로젝트·사업** — "오늘 할 일"이 아니라 프로젝트·사업에 따라 영상 올리기 → 라벨링 → 학습 → 모델 개발·보완 → 완성되면 서비스 카드 발행. 생산이 우선. (09-30)
45. **AI 분석이 먼저** — Land-XI(LX) 쪽은 AI 분석이 우선이고, 대장 매칭 행정서비스는 기관(지자체) 쪽 필요가 크다(LX 도 필요 없지는 않음). 대장 결합은 가이드 없이 한 형식으로 통일하지 않는다. (09-30)
46. **권한과 책임을 먼저 정한다** — 승인·반려·재학습 같은 판단은 누가(프로젝트장·LX 관리자·기관 관리자) 하는지와 그 기준·가이드를 먼저 정한다. 반려에는 사유가 남는다. 신고·요청 기능은 실제로 쓰는 사람(기관 이용자) 중심 화면으로. (09-30)
47. **모델은 일에 맞게** — 가벼운 일·반복 일은 소넷 5.5(페이지 생성·캡처 검증·여러 화면 같은 수정·배포 점검·문서 정리). 기획·디자인 판정은 페블 5.1, 새 구조·어려운 구현·실증은 오퍼스 5.5. 강제 할당이 아니라 잘할 수 있는 쪽으로. (09-30)
48. **기관 분기 플랫폼은 모습이 다르다** — 기관 플랫폼(예: 남원 GeoVision)은 Land-XI 와 스타일이 다르다. 지자체 기관 플랫폼끼리는 큰 틀의 UI/UX 를 통일해 분기하되, 기관 고유 CI 와 몇 가지 기능·이미지는 기관별로 바꿀 수 있게. (09-30)
49. **직원이 어려워하지 않게** — 입력 칸·조건·옵션은 최대한 줄이고, 시스템이 알아낼 수 있는 것(영상 해상도·촬영일·범위·좌표계 등)은 파일에서 자동 판독한다. 승인·반려도 꼭 필요한 것만. 쉬워야 활용도가 높다. (09-30)
50. **사용자에게 짐을 넘기지 않는다** — 서비스를 쓰는 기관 사용자에게 구조화된 입력을 요구하지 않는다. 오탐 알리기는 영상·지도에서 누르고 메모 한 줄. 정리는 LX 쪽이 한다. (09-30)
51. **소유와 관리** — 프로젝트는 만든 프로젝트장이 1차 소유·판단(재학습 포함). 서비스 카드 발행 뒤에는 LX 관리자가 갱신을 관리하고 필요하면 재학습을 지시한다. (09-30)
52. **확인 요청은 그림과 일상어로** — 무엇이 어떻게 바뀌는지 시안 그림(지금 / 바뀐 뒤)으로 보여 주고, 어느 플랫폼 화면(Land-XI / 기관 분기)인지 먼저 밝힌다. 규칙표·내부 용어로 묻지 않는다. 한 번에 적게. (09-30)
53. **서비스 제공 체계** — 기관 AI 서비스는 실제 사업(연차별: 남원 23 생활환경 · 25 영농 · 26 도로안전 · 27 관광인파, 전남 해양쓰레기 확대)을 기준으로 기획한다. Land-XI 가 100% 만들어 뿌리는 것이 아니므로 ① Land-XI 가 만들어 분기하는 것 ② 기존·외부 서비스를 연결하는 것 ③ 그 밖의 AI·분석 서비스 제공 방식을 나누고, 어디까지 뿌릴 수 있는지 역량(케파)을 정한다. 목표: 다른 지자체로 분기가 쉽고, 다른 지자체의 비슷한 신규 사업도 이 체계로 진행 가능. (09-30)

57. **먼저 제안한다** — 사용자가 말한 것만 묻지 않는다. 역할별 업무·완전체 기준·실제 사업·운영 경험에서 "이런 것도 필요하지 않을까요?"를 근거와 함께 먼저 꺼내고, 채택 여부는 사용자가 정한다. 확인 요청마다 제안 칸을 두고, 제안도 확인 요청처럼 **응답을 주고받는 페이지**(채택·보류·반려 버튼 + 메모 + 결정 복사)로 올린다. (09-30)
58. **대장은 기본 틀 + 커스텀** — 부서 대장은 너무 다양해 건건이 맞춤 기능을 만들지 않는다. 기본 틀(모든 서비스에 통하는 비교 방식·최소 양식)을 먼저 세우고, 틀에 안 맞는 특수 대장은 사업별 커스텀 영역으로 보낸다. (09-30)
59. **내려받기는 정책과 함께** — 결과·자료 내려받기는 개인정보가 있을 수 있으므로 사용자 동의 등 기본 정책(동의·범위·기록)을 먼저 두고 연다. (09-30)
60. **촬영은 수수료, 분석 의뢰는 무상** — LX 가 드론을 띄워 찍는 촬영 의뢰는 LX 수수료 체계에 따른다(09-30). 기관이 자기 영상으로 AI 분석을 맡기는 의뢰는 LX 관리자 승인/반려를 거치는 무상 체계다(10-01). LX 의 수익은 플랫폼 유지관리 수수료 — 기능·콘텐츠가 풍부하고 품질이 좋아야 기관이 매년 유지관리를 맡긴다. 기관의 LX AI 서버 자원 이용은 관리 대상. (09-30 · 10-01 고침)
61. **흐름 먼저, 화면은 그 칸** — 기능·화면은 역할별 원스톱 흐름(왜 하나 → 단계 → 결과 → 다음 단계, 단계마다 누가·무엇을·근거) 안의 한 칸으로 설계하고 보여 준다. 영상 올리기처럼 앞뒤 없이 떼어 낸 기능은 만들지 않는다. (09-30)
62. **판단에는 근거와 실물** — 승인·반려·미달 판정은 기준과 그 근거(무엇을 몇 건 확인해 얼마였나)를 보여 주고, 판단하는 사람이 분석 결과를 직접 보고 정한다. (09-30)
63. **받는 사람을 정한다** — 기관이 보낸 알림·신고·요청은 그 서비스를 담당하는 LX 직원(프로젝트장)에게 연결된다. 담당이 없으면 관리자에게. (09-30)
64. **기관 분기 흐름** — 기관별 메인(서비스 소개, 틀은 비슷하게) → 로그인 → 서비스 선택 → 대시보드 → 서비스별 기능. 기관 마크·이름·색은 기관 것으로. 기관 대장 맞추기는 요구사항을 들어 만드는 커스텀. (09-30)
65. **문서와 화면을 가른다** — 체계·생애·원칙 같은 것은 문서로 정하고, 플랫폼에 만들 화면·기능과 섞지 않는다. 확인 요청 항목마다 [화면] 인지 [문서] 인지 밝힌다. (10-01)
66. **데이터는 인프라와 함께 설계** — 영상·학습데이터의 보관(아카이브)·관리·공유는 저장 공간·GPU 와 바로 얽힌다. 누가 얼마나 쓰고 얼마나 두는지(할당·권한·보관 기간)를 먼저 정하고 기능을 만든다. 지금은 A6000 기준으로 세팅하되, A100 등 인프라가 바뀌어도 설정만 바꾸면 되는 구조로. (10-01)
67. **기관 만들기는 LX 관리자** — 기관을 만들고 그 기관의 기능·서비스를 정하는 것은 LX 관리자 역할이다. 서비스 체계는 거기서 정리된다. 기관 만들기가 어디까지(주소·도메인·마크·서비스)인지 범위를 분명히. (10-01)
68. **1차·2차 서비스** — Land-XI 가 만든 AI 결과(1차, 예: 해양쓰레기 탐지)를 기관이 다른 모델·자료(예: 해류 모델)와 결합해 만드는 2차 서비스(예: 해양쓰레기 예측 지도)가 있다. 2차는 기관 안에서 소화하되, 1차 결과가 갱신되면 2차도 갱신되는 관계를 설계한다. (10-01)
69. **API 는 서비스별 키 · 요청과 승인** — API 키는 분석 서비스마다 발급. 키로 접속 → 분석 맡기기 → 결과 가져오기(기존 결과 포함). 내보내는 것은 AI 분석 결과(폴리곤·SHP·GeoJSON 등)이고 영상은 아니다. 분석 맡기기는 관리자에게 요청하고 관리자가 승인·반려한다. (10-01)
70. **기준은 유연하게** — 공개 승인 기준은 합격선으로 고정하지 않는다. 현장 대조는 쉽지 않고, 기준은 서비스마다 다르며, 관리자 판단도 틀릴 수 있다. 기준 값은 판단을 돕는 참고 표시로 두고 관리자가 결과를 보고 정한다. (10-01)
71. **일반 모드 · 고급 모드** — 행정정보 비교처럼 복잡해지는 기능은 일반 모드는 최대한 쉽게(몇 번 누르면 끝), 세부 설정은 고급 모드로. 둘의 균형. (10-01)
72. **LX 관리자는 다 보고 돕는다** — 기관 알림·검토 요청·의뢰·메시지는 담당 프로젝트장과 함께 LX 관리자도 본다. LX 는 기관 가입 승인에는 관여하지 않지만 사용자 확인·통제·지원 기능을 가진다. (10-01)
73. **검토 요청 = 짧은 메시지** — "AI가 잘못 봤어요"가 아니라 "검토 요청". 짧은 메모로 AI 오류가 아닌 것도 전달할 수 있게. 주고받는 내용은 LX 관리자도 본다. (10-01)
74. **라벨링은 수동부터** — 학습데이터 구축 1차는 사람이 직접 그리는 수동 라벨링. 객체 단위 오토 라벨링은 2차이며, 그 성능을 보여 줘야 사용자가 쓸지 정한다. 보관된 학습데이터를 불러와 학습에 더하는 기능도 고려. (10-01)

89. **2차 인증은 정식 오픈 때** — 모든 역할에 한꺼번에 켠다. LX 직원은 회사 OTP 연동을 먼저 추진(사내 계정과 Land-XI 메일 아이디를 맞추는 방법 포함), 기관은 정부 OTP 를 녹일 수 있는지 검토. 메일·문자는 2차 인증이 아니라 알림에만. (10-01)
90. **서비스는 다채롭게 보여 준다** — 분석 서비스 고르기는 이름 목록이 아니라 서비스마다 대표 이미지·결과 예시·무엇을 찾나·어디서 쓰였나가 보이는 카드로. 지도로 보는 XI맵 방식도 살린다. 홈은 그 역할의 대시보드다. (10-01)
91. **"한도"는 하드웨어에만** — GPU·분석 시간·AI 도우미는 무상 정책이라 직원·기관 모두 막는 한도가 없다. 조정은 순번과 승인으로만. "한도"라는 말은 서버 저장 공간 같은 물리 하드웨어에만 쓴다. 사용 현황의 AI 도우미는 "질문"이 아니라 "요청 건수". (10-01)
92. **관리자는 팀** — LX 관리자 일은 5명 팀이 함께 한다(부재 드묾). 알림은 나중에 사내 메신저와 잇는 것을 검토한다. (10-01)
93. **서비스 카드는 한 벌** — 분석하기·서비스 카드 관리·기관 서비스 선택·기관 공간의 2차 서비스까지 같은 카드 부품을 쓰고, 종류별 배지·정보 칸만 다르게. 목업 수준이 아니라 실제 결과 이미지와 정보가 담긴 완성 디자인으로. (10-01)
94. **영상은 표준 하나로, 용량은 가볍게** — ECW·TIF·COG 등 들어오는 형식은 서버가 표준 한 가지로 바꿔 보관하고, 압축으로 용량을 최대한 줄인다. 형식·압축 규칙은 관리자 설정 한 곳. 기관에 공유한 영상은 그 기관 지도에도 보인다. 표준은 COG · JPEG 90 · 축소판 포함, 원본은 표준본 확인 뒤 90일 보관 후 지움. (10-01)
95. **이동은 바로, 글자는 잡히게** — 화면 안 이동 링크(서비스 보기·활용 사례·처음으로 등)는 스크롤 연출 없이 바로 그 자리로. 화면의 글자는 마우스로 선택·복사할 수 있어야 한다. 표기는 "LAND-XI PLATFORM". (10-01)
96. **이름은 XI ChatGEO** — 지도 오른쪽 아래 채팅으로 쓰는 vLLM 서비스의 이름은 "XI ChatGEO". 화면에서 "AI 도우미"·"물어보기"·"Land-XI 도우미"라고 부르지 않는다. 로그인한 화면에만 둔다. (10-01)
97. **말한 대로 보여 주고, 막다른 말은 없다** — XI ChatGEO 는 화면에 실제로 그려진 것만 "그렸습니다"라고 한다. 못 하는 요청에는 이유 한 줄 + 대신 할 수 있는 가장 가까운 일 + 할 수 있는 것 몇 개를 버튼으로. (10-01)
98. **못 한 것은 개선 재료** — 사용자가 하려다 못 한 일(XI ChatGEO 가 못 한 요청·막힌 동작·다시 물은 것)은 저절로 모아 묶고, LX 쪽에서 개선 후보로 보고 채택하면 만들고, 만들어지면 물었던 사용자에게 알린다. (10-01)
99. **메뉴와 지도 위 기능은 한 줄기** — 지도 위 카드에서 하는 일(프로젝트 만들기 등)도 왼쪽 메뉴와 같은 이름·같은 곳으로 이어진다. 메뉴판에 없는 길을 지도 위에 따로 내지 않는다. (10-01 구현 확인 2차 J-1)
100. **공무원은 전문가가 아니다** — 기관 화면은 "영상 넣기 → 분석 카드 고르기 → 요청" 처럼 쉬운 말·적은 단계로. 파일 형식·해상도·좌표 파일 같은 전문 기능·용어는 화면에 내지 않고 서버가 알아서 처리한다. 못 읽는 파일이면 쉬운 말 한 줄과 다음 할 일만. (10-01 J-9)
101. **뜻을 모를 버튼 이름 금지** — '영상 설명'처럼 누르면 무엇이 되는지 모를 이름은 쓰지 않는다. 버튼 이름은 눌렀을 때 일어나는 일 그대로. (10-01 J-3)
102. **기관 쪽 담당자도 보인다** — LX 직원이 기관의 요청·의뢰를 받을 때 그 기관 안의 담당자(부서·이름)를 알 수 있어야 한다. (10-01 J-4 · 세부는 확인 16차)
103. **기관 화면도 완성 디자인으로** — 기관 메인·서비스 선택·서비스 대시보드·기관 정보는 지금 목업 수준이다. 페블 디자인 → 확인 → 구현으로 완성도를 올린다. (10-01 J-6~8)
104. **체감되게 — 그림으로, 짧게** — 화면·시안은 지도·결과 사진 같은 그림이 있어야 체감된다. 글과 칸만 세로로 길게 늘어놓지 않는다(한눈에 들어오게). (10-01 제안 2 S-15~17)
105. **내 정보는 본인이 고친다** — 부서명 같은 계정 정보가 틀리면 관리자가 아니라 각 직원이 직접 고친다. LX 직원 계정을 강제로 사용 중지하는 기능은 지금 고려하지 않는다. 프로젝트장 넘기기는 의미 있다. (10-01 S-18)
106. **촬영 의뢰 수수료 기준** — 드론지적측량 수수료는 국토교통부 고시 제2025-896호: 기준면적 0.25㎢ 당 군 지역 3,471,000원 · 시 지역 3,551,000원 · 구 지역 3,656,000원(사용자 제공 10-01). 금액은 설정 한 곳에 두고 고시가 바뀌면 거기만 고친다. 바깥 주소 속도(접속 경로)는 정식 오픈 때 정한다. (10-01 S-6 · S-9)
107. **XI ChatGEO 의 소개 말** — 채팅창 머리는 "공간지식 추론 서비스(지도 제어 · 분석 · 보고서)", 입력 칸은 "더 똑똑한 공간지식 추론 서비스를 체험해 보세요". 답하는 법은 확인 16차 대화 규칙 일곱 가지(design-r7/chatgeo-talk/rules.md)를 따른다. (10-01 X-1 · 대화-1)
108. **카드 숫자는 의미 있는 것** — '비닐하우스 n동 발견' 같은 탐지 개수는 의미가 없다. AI 정확도처럼 그 서비스가 얼마나 믿을 만한지·무엇을 해 주는지 보여 주는 숫자를 찾는다. (10-01 구현 확인 3차 L-6)
109. **문제는 창으로 알린다** — 못 읽는 파일 같은 문제는 빨간 글 한 줄보다 창을 띄워 알린다. (10-01 M-2)
110. **지자체는 서비스와 지도로** — 기관 사용자는 서비스와 지도에서 분석 결과를 보고 확인하고, 필요하면 피드백을 주고받는다. '우리 공간'처럼 뜻이 안 와닿는 별도 메뉴를 만들지 않는다(공간은 안쪽 구조일 뿐). (10-01 N-1~3)
111. **프로젝트는 새 서비스를 만드는 일** — 새 프로젝트에서 이미 있는 서비스를 고르게 하거나 지역을 글로 적게 하지 않는다. 깃헙 옛 프로젝트 만들기 자산의 기능·흐름을 기준으로 한다. 생산 단계는 그림만 보고도 파악되게. (10-01 K-3 · K-4)
112. **영상은 보고 판단한다** — 영상 관리·판단 화면은 영상 그림(썸네일)을 보며 결정하게 하고, 판단에 필요한 순서로 놓는다. (10-01 M-4)
113. **기관 화면은 '분석 요청'** — 기관이 영상을 넣고 분석을 맡기는 일은 '분석 의뢰'가 아니라 '분석 요청'이라고 부른다. (10-01 기관-5)
114. **헬프데스크 담당은 LX 관리자가 지정** — LX 관리자가 기관 서비스마다(예: 남원시 영농관리 · 전라남도 영농관리) LX 헬프데스크 담당 직원을 배치한다. 기관의 막힌 일(못 읽는 파일 · 요청)은 그 담당에게, 없으면 LX 관리자에게. 기관 화면에 '서비스별 우리 담당자' 표는 두지 않는다 — 기관 대응은 LX 관리자가 지정·관리한다. (10-01 기관-6 · 7)
115. **서비스는 LX가 만든다** — 기관 화면에서 '우리 도가 만든 서비스'와 'LX가 만든 서비스'를 나누지 않는다. (10-01 기관-10)
116. **기관 메인 배경은 LX 관리자가** — 기관 메인(로그인 전)의 배경 사진·결과 장면은 LX 관리자가 최종으로 올리거나 고른다. (10-01 기관-2)
117. **기관 화면에 이력 · 결과 지도 탭 · 통계 리포팅** — 내 서비스에는 서비스 현황과 이력이 남고, 결과 지도는 탭으로 나오며, 통계 리포팅 자리가 있어야 한다. 분석 요청을 결과 지도 안에 넣을지·따로 둘지는 검토. 필지마다 담당자가 메모(확인 결과)를 남길 수 있어야 한다. '영상 설명'은 지금은 약하다. (10-01 기관-1 · 9)
118. **의미 있는 것만 담는다** — 화면 칸은 의미 없는 것을 빼고 의미 있는 것만. '막힌 곳'처럼 뜻이 바로 안 와닿는 표현은 다시 찾는다. (10-01 17차 P-2 · P-1)
119. **촬영 요청 금액은 비례 · 대략** — 0.25㎢ 기준 금액을 넓이 그대로 비례로 셈한다. 화면 금액은 '대략'일 뿐 확정이 아니다 — 조정(분석 대가 등)은 LX 담당자 몫이고 LX 답에서 정한다. (10-01 촬영-2 · 3)
120. **기관 '요청하기' 메뉴** — 기관 왼쪽 메뉴에 '요청하기'를 두고 그 안에 분석 요청 · 촬영 요청. 촬영 요청은 LX 관리자가 맡아 직접 하거나 담당자를 배정한다. (10-01 촬영-1 · 4)
121. **내 정보에 내 자원** — 내 정보에는 나에게 할당된 자원 현황(지금은 저장 용량)이 보인다. (10-01 P-5)
122. **분석 요청은 '결재'가 아니라 관리** — LX 관리자는 분석 요청을 승인 · 반려만 하는 것이 아니라 우선순위 등을 조정하며 관리한다. '결재'라는 말은 이 일에 쓰지 않는다. (10-01 18차 M-4-결재)
123. **필지 정보는 연속지적 · LX맵과 잇는다** — 필지 카드의 필지 정보는 **연속지적도**(V-World 데이터 API LP_PA_CBND_BUBUN — 지번 · 지목 · 공시지가 등 속성)와 **LX맵(편집지적도)**(V-World WMS 층 lt_c_landinfobasemap — 지도 그림)을 둘 다 잇는다. 둘은 서로 다른 것(사용자 10-01 정정). 서버는 연속지적을 이미 쓰고(parcels.py), WMS 는 프록시 /proxy/vworld/wms 로 받을 수 있다. (10-01 기관-9)
124. **2차 서비스도 LX가 만든다** — 기관 맞춤(2차) 서비스도 LX가 만들어 올린다. 변수가 많으니 미리 충분히 검토한다. (10-01 기관-10)
125. **LX 직원 화면은 단순하게** — 프로젝트 · 단계 화면이 "어지럽다 · 혼동스럽다"는 답이 반복됐다. 한 화면에 담는 것을 줄이고 깔끔하게. '결과 확인'처럼 뜻이 바로 안 와닿는 말은 풀어 쓴다. 홈은 대시보드 성격. (10-01 K-1 · K-3 · P-2 · K-4)
126. **단추 아이콘은 기본으로 넣지 않는다** — 로그인 · 문의하기처럼 단추 · 글자 옆에 붙는 아이콘은 기본으로 넣지 않고 시작한다. 경우에 따라 사용자가 정하면 넣는다(스크롤 안내의 마우스 그림 같은 안내 그림은 이 규칙과 별개). (10-07)
127. **한쪽으로 쏠린 배치 · 큰 빈 여백 금지** — 화면은 넓이 전체를 고르게 쓴다(1440에서 내용이 왼쪽에 몰리고 오른쪽이 비는 배치 금지). 시안을 넘기기 전에 빈 여백 비율을 재고 캡처로 확인한다. "이런 실수 반복되지 않도록." (10-07 대시보드 시안)
128. **사용자가 말한 것만 담지 말고, 그 사람이 정말 필요한 것을 고민한다** — 사용자가 든 항목은 예시일 뿐이다. 그 역할이 실제로 매일 보고 싶은 것(예: LX 직원 — 프로젝트별 용량 · 내 자원 · 돌고 있는 분석 · 결과 도착 · 요청 · 팀 소통 · 공지)을 스스로 찾아 근거와 함께 담는다. (10-07)
129. **기존 Land-XI 기능을 먼저 돌아본다** — 새 화면은 구 Land-XI 플랫폼(대시보드 · MY 작업공간 · 프로젝트 개요 · 마이페이지 디스크 증량 신청 · 분석 서비스 갤러리 등 — 화면 캡처 ref-old-landxi/)의 기능 · 정보 구성을 출발점으로 삼고, 그 위에 더하거나 다듬는다. 사용자가 실제로 쓰던 것에서 출발해야 공감된다. (10-07)
130. **확인 항목은 고를 가치가 있어야 한다** — 사용자 말을 되풀이해 '이대로 · 바꿔서 · 다시'만 묻지 않는다. 서로 실제로 다른 선택지(구성 · 비용 · 범위가 다른 것)와 그 차이를 보여 준다. (10-07)
131. **AI 학습 데이터는 자산으로 관리한다** — 시스템 안에 학습 데이터 자산 관리(목록 · 출처 · 라벨 · 수량 · 이용 조건 · 어느 모델에 쓰였나 · 버전)가 있어야 한다. (10-07)
