  • 고친 것 = 라벨과 같은 것(영상 조각 위에 클래스)인데 이름 · 세는 단위가 다름(건 ↔ 장)
  • XI맵에서 고친 것만 데이터하우스에 따로 셈 → "왜 고친 것만?" 질문의 원인

원천 기능 한 줄

영상 위에 라벨을 붙이거나 고친다→학습 데이터가 된다→재학습→새 판→결과를 보고 다시 고친다

이 고리에 꼭 필요한 화면은 셋. 나머지(데이터하우스 탭 셋 · 승인 대기 목록 · 비슷한 클래스 먼저 보여 주기 · '공유 데이터셋' 이름)는 고리 밖의 덧붙임이다.

① 라벨 붙이기 · 고치기프로젝트 학습데이터 구축 = XI맵 고치기와 같은 동작(영상 조각 위에 클래스 이름). 새 클래스 = 이름을 새로 쓰면 새 클래스 — 그뿐.
② 학습이 프로젝트의 학습 데이터(붙인 것 + 고친 것 한 묶음)로 학습 — 쉬는 시간에 자동.
③ 새 판 배포 신청 · 승인관리자는 여기서 한 번만 본다(새 클래스도 이때 함께). 승인되면 기관에 공유.

ⓐ 데이터하우스를 없앤다 — '프로젝트 안 학습 데이터' + '관리자 공유 데이터' 둘로추천

학습 데이터는 프로젝트 안에만. XI맵에서 고친 것은 그 서비스를 만든 프로젝트의 학습 데이터로 간다. 영상 · 행정 자료는 관리자가 관리하는 '공유 데이터' 한 이름.

  • 사라짐: 직원 메뉴 '데이터하우스' · 탭 셋 · 승인 대기 목록 · 데이터하우스 '고친 것' 탭 · '비슷한 클래스 먼저' · '공유 데이터셋' 이름
  • 바뀜: 새 프로젝트 창 · 추론 · 분석하기의 영상 고르기 → 모두 '공유 데이터에서 고르기' 하나
  • 새 클래스: 라벨 붙일 때 이름을 새로 쓰면 새 클래스. 관리자는 배포 신청 때 본다
  • 맞는 이유: 직원 일이 프로젝트 안에서 끝남(원칙 133 '관리자가 관리하는 공유 데이터'와 같음) · "왜 고친 것만?" 질문이 사라짐

ⓑ 데이터하우스 하나로 합친다 — 프로젝트는 거기서 고르기만

영상 · 행정 자료 · 학습 데이터 · 고친 것이 모두 데이터하우스 한 곳. 프로젝트의 데이터 올리기 · 학습데이터 구축 단계는 '데이터하우스에서 고르기'가 된다.

  • 사라짐: '공유 데이터셋' · '프로젝트 영상' 구분 · 학습 화면 데이터 블록의 세 선택지(→ 하나) · 데이터 올리기 서랍 · '비슷한 클래스 먼저'
  • 바뀜: 라벨 붙이기 · 고치기도 데이터하우스 안에서(프로젝트는 묶음을 가리키기만)
  • 새 클래스: 같은 방법 — 이름을 새로 쓰면 새 클래스
  • 무거운 점: 직원이 프로젝트와 데이터하우스를 오가야 함 · 학습 데이터가 프로젝트 밖에 있어 '내 것'이 흐려짐
