지난 확인 페이지입니다 — 그림이 지금 화면과 다를 수 있습니다. 답을 기다리는 것은 새 한 페이지에서 봅니다.

확인 요청 11차

구현 확인 1차에서 물으신 세 가지 — '내가 요청한 결재입니다'는 무슨 말인가, 한도는 무엇인가, 면적이 넓어 GPU가 못 받는 것인가 — 에 그림으로 답하고, 7차 답(기관은 한도 대신 사용 현황)에 맞춘 다시 설계입니다.

보는 법 — 항목마다 지금(무엇이 문제인지) · 제안(바뀐 뒤) · 보는 곳(캡처, 그리고 직접 열어 볼 주소·계정·누를 곳)이 있습니다. 캡처를 누르면 크게 열립니다.
고르는 법 — 버튼을 누르고, 고칠 점이 있으면 한 줄 적어 주세요. 고른 것은 이 브라우저에 저장됩니다. 다 고르시면 아래 결정 복사를 눌러 대화창에 붙여 넣어 주세요. 안 고른 항목은 그대로 두셔도 됩니다.

결재 규칙 — 요청한 사람과 결재하는 사람

구현 확인 1차 I-8 다시 "무슨 말인지 이해를 못했다. 규칙은 무엇이고? 등록 대장이 없으면 어떻게 할 것이고?"를 받아, 지금 구현된 결재를 한 장면으로 풀고, 결재할 관리자가 없을 때 지금 실제로 어떻게 되는지 따져 봤습니다.

결재-1

[문서][Land-XI] 요청한 사람은 스스로 승인하지 않는다

지금

사용자 10-01(I-8 다시): "'한도 조정도 결재 요청이 되며, 요청한 관리자가 열면 "내가 요청한 결재입니다"만 보입니다. 서버도 거절합니다' — 이 부분이 무슨 말인지 이해를 못했다. 그리고 규칙은 무엇이고?" 지금 결재함에는 서비스 공개 · 다른 지역 적용 · 모델 등록 · 규칙 기준값 · 한도 변경 · 배포 승인 여섯 가지가 들어오고, 결재는 LX 관리자만 합니다.

제안

규칙은 셋입니다: 결재는 LX 관리자만 · 요청한 계정은 자기 요청을 승인하지 못함 · 반려는 사유를 꼭 적고 그 사유가 요청한 사람 화면으로 돌아감. 장면: 관리자 A 가 광주전남 AI 도우미 한도를 1,800,000 → 2,400,000 으로 올리자고 '결재 요청'을 누르면 값은 그대로이고 결재함에 한 줄만 생깁니다. A 가 그 줄을 열면 승인 · 반려 버튼 없이 "내가 요청한 결재입니다"만 보이고, 다른 길로 승인을 보내도 서버가 거절합니다. 관리자 B 가 열어 승인하는 순간 바뀌고, 기록에 요청 A · 결재 B 가 남습니다. 한 사람이 요청과 승인을 다 하면 아무도 확인하지 않은 것과 같기 때문입니다. 7차 답으로 기관 한도가 없어져 '한도 변경' 결재는 없어지지만, 이 규칙은 새 '자원 요청' · 장비 설정 바꾸기 · 서비스 공개에 그대로 쓰입니다.

결재-2

[화면][Land-XI] 결재할 관리자가 한 명뿐이면

지금

사용자 10-01: "등록 대장이 없으면 어떻게 할 것이고?" — 결재할 사람 명단으로 이해했습니다. 지금 명단은 따로 없고 'LX 관리자' 역할 계정이면 모든 결재를 합니다. 관리자가 요청한 결재(한도 변경, 관리자 계정으로 만든 서비스 공개 · 지역 적용 · 모델 등록)는 다른 관리자가 없으면 기한 없이 대기하고, 거두기 · 대행 · 저절로 승인이 없습니다. 지금 관리자 계정 셋은 모두 시범 계정이라 옛 아이디를 정리하면 하나만 남습니다.

제안

ⓐ 관리자는 늘 두 명 이상 — 한 명이면 관리자가 요청하는 결재는 받지 않고 "결재할 관리자가 없습니다"로 안내. ⓑ 관리자 계정이 하나뿐일 때만 스스로 승인 — 결재 기록에 '혼자 결재'가 붙고, 두 번째 관리자가 생기면 그 목록을 한 번 확인. ⓒ 관리자마다 대행자를 정해 부재 때 대신 결재. 추천은 시범 기간 ⓑ, 정식 오픈 때 ⓐ(한 분이 휴가면 다른 분이 결재)이고 대행자는 두지 않습니다. 함께: 결재 대기가 5 업무일을 넘으면 모든 관리자에게 다시 알림(저절로 승인하지 않음) · 요청한 사람이 대기 중인 자기 요청을 거둘 수 있게.

자원 — 기관 한도 대신 사용 현황 · 순번 · 직원 몫

I-10 "한도는 무엇인지???" · Q-1 "면적이 넓어 GPU 용량이 못 받는 것? 타일링/스케줄링으로 처리해야 하지 않나?"와 같은 날 7차 답(기관에는 한도 대신 사용 현황, LX 관리자는 하드웨어와 순번 · 승인, 자원 할당 · 요청 · 승인은 LX 직원 개인 단위)을 받아, 지금 구현을 그 방향으로 바꾸는 구체안을 만들었습니다. 숫자는 9월 실제 기록과 서버 계획 값입니다.

자원-1

[화면][둘 다] 기관 한도는 없애고 사용 현황으로

지금

사용자 10-01: "한도는 무엇인지???" · "분석 면적이 넓어 GPU 용량이 수용을 못한다고 이해를 하면 되나??" 지금 한도는 LX 관리자가 기관마다 정한 한 달 허용량(분석 면적 · GPU 시간 · 저장 · AI 도우미)이고, 닿으면 새 분석 · 질문을 거절합니다. 9월 광주전남은 분석 면적 10,850 / 1,000㎢ 로 거절됐는데, 광주전남 계정이 낸 분석은 0건이었습니다. 10월 1일 0시에 장부가 새로 시작돼 지금은 0 입니다.

제안

GPU 용량 문제가 아닙니다 — 넓은 범위는 이미 조각(약 256m 네모)으로 나눠 차례로 돌아 오래 걸릴 뿐 거절하지 않습니다. 막은 것은 장부였고, 그 10,850㎢ 도 실제 광주전남 땅은 1,176㎢, 바다까지 잰 넓이 7,172㎢, 남원 · 하동이 잘못 적힌 2,501㎢ 였습니다(이 고장 둘은 따로 고침). 7차 답대로 기관에는 막는 한도를 두지 않고 거절 · 한도 고리 · '한도 조정' · '한도 변경' 결재 · '한도 임박'을 없앱니다. 대신 '사용 현황': LX 관리자는 기관별로, 기관 관리자는 '우리 기관 이용 현황'으로 같은 숫자를 봅니다 — AI 분석 넓이 · 분석 시간 · AI 도우미 질문 수 · 저장 · 서비스별, 그리고 '기관이 요청한 것'과 'LX 가 기관 서비스로 돌린 것' 두 칸. 예: 광주전남 9월 = AI 분석 1,176㎢ · 38분 · 질문 769건 · 저장 약 2.7GB, 전부 LX 가 영농관리 서비스로 돌린 것. 한도 · % · '초과'는 없습니다.

[화면][Land-XI] 자원은 순번 · 승인 · 직원 몫으로

지금

사용자 10-01: "이런 건 타일링/스케줄링 분석 기능으로 처리해야 되지 않나??" · 7차 답 "분석의 순번이나 승인/반려 정책은 있겠지" · "개인(LX 직원)에게 자원 할당-요청-승인, 프로젝트를 개설하더라도 개인의 허용된 정책에 한하여." 조각 나누기와 차례 정하기(화면 실시간 먼저 · 기관별 번갈아 · 기관마다 한 번에 1–2건 · 전력 규칙)는 이미 있고, 밤 예약과 직원 단위 몫은 없습니다. LX 는 제한이 없고 학습 시간은 사용 기록에도 남지 않습니다.

제안

순번 네 칸: ① 지금 화면에서 기다리는 분석 ② 승인된 분석(기관 의뢰 · API 요청 · 지역 적용 뒤 첫 분석) ③ 시군구 전역(예상 2시간 이하) ④ 큰 분석은 밤 예약(밤 10시–아침 7시) — 거절 없이 '예상 끝' 시각을 알려 줍니다. 예: 광주전남 전역 20곳 8,418㎢ 는 178,332조각, GPU 한 장 약 6시간 30분이라 밤 10시에 시작하면 새벽 4시 30분쯤 끝납니다. LX 직원은 사람마다 몫(제안: 저장 300GB · 분석 시간 한 달 10시간 · 학습은 처음엔 기록만) 안에서 자유롭게 쓰고, 프로젝트는 지금처럼 바로 만들되 쓴 자원은 쓴 사람 몫에서 셉니다. 넘으면 화면이 '자원 요청'을 띄우고, 한 줄 적어 보내면 LX 관리자가 그 사람의 사용 · 대기열 · 저장소 여유를 보고 승인(이번만 / 몫 늘리기)하거나 반려합니다. LX 관리자는 장비 · 저장소 여유 · 대기열 · 직원별 할당을 '인프라' 한 곳에서 보고, 규칙 값을 바꾸면 다른 관리자 결재입니다.
