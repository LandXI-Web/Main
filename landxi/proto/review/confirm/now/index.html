    외부 연동 API — 새 구조에 다시 붙임(정해진 것 요약 · 그림 한 장 · 시안)

    지금

    제안

    분석 서비스는 '무엇을 분석하나'(예: 영농관리)이고, API 키는 기관에 공유된 그 서비스를 기관의 다른 시스템(예: 남원 영농관리 시스템)이 화면 없이 쓰는 출입증입니다. 통장(공유된 서비스)과 거기 연결한 카드(키)처럼, 공유된 서비스마다 키가 하나 생기고, 카드를 잃어버리면 카드만 멈춥니다. 키로 하는 일은 셋 — 접속 확인 · 결과 가져오기(지난 결과까지 · GeoJSON 등) · 분석 맡기기(영상은 이용자가 올림 → 관리자 승인 → 분석). 분석 맡기기는 새 길을 만들지 않고 지금 있는 기관 '분석 요청'(요청 관리 한 줄 · 순번 · 보류 · 무상)에 '들어온 곳: API' 표시만 더합니다. API로 쓴 것도 '배포 → 사용 현황'과 기관 한도에 합산되고, 모든 호출이 기록됩니다. 사람은 화면 로그인(OTP), 시스템은 키 — 섞지 않습니다. 만드는 순서는 0단 키 · 관리자 화면 · 결과 가져오기(약 4.5일) → 1단 분석 맡기기 · 영상 올리기 · 알림(약 4일) → 2단 SHP · 개발자 안내(약 3.5일). 그림은 새로 그린 시안입니다(10-10). 그림 찍은 시각(시안) 10-10 23:13.

    지금은 개인 개발 PC 한 대에 바깥 관문 · AI · 원본 영상이 함께 있고, 해외 사업자(Cloudflare) 터널로 바깥에 열려 있습니다. 지침상 인터넷에 둘 수 있는 것은 공개 등급 시스템뿐이고, 한 시스템에 다른 등급을 섞지 않아야 하며, 접속 기록은 1년 이상 남겨야 합니다. 해외 사업자 망을 지나는 것이 공개제한 공간정보의 국외 반출에 해당하는지는 확인하지 못했습니다.

    제안

    ⓐ 실증 기간 동안 바깥 주소는 공개 자료(LX 보유 공개 자료 · 영상 API로 부르는 영상 · 기관이 공개로 분류해 준 자료)만 다룹니다. 기관 원본 영상(공개제한)을 받는 것은 국정원 보안성 검토와 운영 서버 이전 뒤로 미룹니다. 분석 요청 · API 설계와 화면은 그대로 만들되, 실제 기관 영상 받기 스위치만 닫아 둡니다. ⓑ 지금도 받되 기관 보안담당 서면 동의, 분석 끝 30일 뒤 삭제, 접속 · 삭제 기록을 남깁니다. 기관이 바로 쓸 수 있지만, 보안 사고가 나면 LX와 기관 모두 규정 위반을 다투게 됩니다. 추천은 ⓐ입니다.

    보안-올리기확인

    영상 올릴 때 받는 확인

    지금

    군사시설이 보이는 영상은 비공개라 받으면 안 되고, 민간 드론은 촬영 허가가 필요하며, 영상 속 사람 · 차량은 개인정보입니다. LX는 이를 영상만 보고 확인할 수 없어서 올리는 쪽의 확인이 필요합니다.

    제안

    ⓐ 영상을 올릴 때(화면 · API 모두) 세 가지를 확인받습니다 — 보안처리(보안시설 삭제)를 끝낸 영상인지 · 촬영 허가를 받았는지(민간 드론) · 개인정보 처리를 LX에 맡기는 데 동의하는지. 그리고 그 기관 관리자가 승인한 요청만 받습니다(이미 정한 '관리자 승인 뒤 받기'에 확인 칸만 더함). 확인 기록은 요청과 함께 남습니다. ⓑ 기관이 처음 서비스를 받을 때 약관에 한 번 동의합니다. 올리기는 편하지만 영상마다 책임이 흐려집니다. 추천은 ⓐ입니다.
