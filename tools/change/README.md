# 남원 4시점 변화 지수(비지도)

`tools/change/namwon_change.py` 가 만드는 산출물의 방법과 **한계**를 적는다.
결론부터: **이건 학습된 탐지 모델의 결과가 아니다.** 정사영상 두 장을 화소 단위로 비교해
"많이 달라진 곳"을 고른 **비지도 변화 지수**다. UI 는 반드시 `변화 지수(비지도)` 로 표기해야
하고, "AI 가 탐지했다"거나 "불법 건축물 N건" 같은 문구를 붙이면 안 된다.

## 입력

`build/namwon_{2504,2506,2508,2510}.tif` — `tools/prepare-assets.py --only namwon` 이
원본 정사영상(수백 GB)에서 잘라 낸 작업 GeoTIFF. EPSG:5186, 0.15m GSD, 5219×5270,
4밴드(RGB + 알파), 네 시점이 **같은 창·같은 격자**를 쓴다.

AOI = `127.3481, 35.5276, 127.3567, 35.5347` (≈780×790m, 남원 시청 북서 13km 계단식 논).
이 창을 고른 이유는 `tools/prepare-assets.py` 헤더에 있다 — 4시점이 모두 촬영된 유일한 구간이다.

## 파이프라인

1. **0.5m 리샘플** — 0.15m 원본을 `average` 로 0.5m(1566×1581)로 내린다. 잎사귀 한 장
   단위의 차이가 아니라 필지 단위의 변화를 보려는 것이고, 다운샘플 자체가 오정합 잡음을 줄인다.
2. **유효역** — 알파 밴드 > 192 인 화소. (원본 알파가 손실압축을 거쳐 249~254 로 흩어져
   있어 `>250` 같은 조건을 쓰면 멀쩡한 영역의 24%가 날아간다.) 네 시점 교집합을 disk(4)
   로 침식해 모자이크 경계 2m 를 잘라 낸다 → **공통 유효역 98.8%, 61.13ha**.
3. **기하 정합** — 밝기 영상에서 ±8화소(±4m)를 정수 격자로 훑어 평균절대차가 최소인
   평행이동을 찾는다. 네 시점 모두 (0,0) 이 나왔다 — 원본이 이미 정합돼 있다.
4. **복사 정합** — 밴드별 median/MAD 로 후영상을 전영상 노출·화이트밸런스에 맞춘다.
   **밝기·밴드 차분에만** 쓴다. ExG 는 이미 밴드합으로 나눈 색도 지수라 여기에 전역
   median 정합을 먹이면 "장면 중앙값 대비 녹색도"로 뜻이 바뀌고, 4월(맨땅 위주) 대비
   10월(전면 녹색) 비교에서 숲이 통째로 `veg_loss` 로 뒤집힌다.
5. **변화 지수**

   ```
   d_spec = mean(|B' − A|)                 # 밴드 절대차 (B' = 복사 정합한 후영상)
   d_exg  = ExG(B) − ExG(A),  ExG = 2g−r−b # 정규화 녹색도 차
   raw    = 0.55·(d_spec/0.25) + 0.45·(|d_exg|/0.20)
   idx    = Gauss( raw / (1 + 24·tex), σ=5px )   # tex = 5×5 국소 표준편차(두 시점 max)
   ```

   **질감 분모가 핵심이다.** 이게 없으면 나무 임관·이랑처럼 고주파가 센 곳이 몇 cm 오정합과
   태양각 차이만으로 최대값을 먹어, 결과가 온통 숲 가장자리 레이스 무늬가 된다(1차 시도가
   실제로 그랬다 — 폴리곤 282개가 전부 임관 테두리였다). σ=5화소(2.5m) 평활은 필지 규모의
   변화가 화소 잡음을 이기게 한다.
6. **임계** — `thr = max(Otsu, 91백분위)`. 이 장면에서는 항상 백분위가 이겼다
   (Otsu 0.39~0.44 vs p91 0.47~0.61). Otsu 만 쓰면 유효역의 20~30%가 변화로 잡혀
   "전부 변했다"는 쓸모없는 결과가 나온다. 백분위 하한은 **한 페어당 변화 면적을 8.8~8.9%
   로 고정하는 장치**이지, 실제 변화율이 9%라는 뜻이 아니다.
7. **형태학** — `opening(disk2) → closing(disk3) → 최소면적 25m² → 경계 가우시안 평활(σ1.6)
   → 다시 최소면적`. 마지막 평활은 0.5m 화소 계단을 눌러 폴리곤 정점 수를 줄인다.
8. **분류** — 연결성분 평균값 기준. 순서가 곧 우선순위다.

   | class | 조건 | 뜻 |
   |---|---|---|
   | `built_new` | Δ밝기 > 0.055 **및** ΔExG < −0.015 **및** 질감 ≥ 변화역 70백분위 | 밝아지고·녹색도 떨어지고·질감 생김 → **나지/정지작업/구조물 신설 후보** |
   | `veg_gain` | ΔExG > +0.03 **및** 후영상 ExG > 0 **및** 후영상 (g−b) > 0.03 | 식생 증가 |
   | `veg_loss` | ΔExG < −0.03 **및** 전영상 ExG > 0 **및** 전영상 (g−b) > 0.03 | 식생 감소 |
   | `other` | 나머지 | 분광은 변했으나 식생/구조물로 못 가름 |

   `g−b` 조건이 없으면 **청록색 비닐하우스 지붕이 '식생'이 된다**. 시안 지붕은
   ExG = 2g−r−b 가 크게 +로 나오기 때문이다(실제로 1차 결과에서 하우스 두 동이 통째로
   `veg_gain` 이었다). 식생은 g−b 가 뚜렷이 +, 청록 지붕은 −라서 이 조건이 갈라 준다.
9. **폴리곤** — `rasterio.features.shapes` → Douglas–Peucker → EPSG:4326(소수점 6자리,
   AOI 로 클램프). 허용오차는 **0.3m 부터 시작**하고 파일이 800KB 를 넘을 때만 0.35 → 0.4 →
   0.5 … 로 한 단계씩 올린다. 현재 4개 페어를 한 파일에 담아 **0.35m** 로 확정됐고,
   그 값은 GeoJSON `note` 에 적힌다(조용히 자르지 않는다).
10. **20m 격자** — 폴리곤 중심점을 20m 셀에 담아 `count / area_m2 / dominant`(셀 안 면적
    최대 클래스)를 낸다. 줌아웃 상태의 요약 표시용.
11. **히트 타일** — 대표 페어 2504→2510 만. 폴리곤 색(아래)에 알파 = `clip(70+150·idx, 55, 210)`,
    가장자리 σ=1 평활. 평활 전에 색을 최근접 화소로 채운다 — 안 그러면 RGB=0 인 바깥으로
    알파가 번져 **반투명 검정 후광**이 생긴다. GeoTIFF 는 `ALPHA=YES` 로 써야 한다
    (안 그러면 4번 밴드가 `ColorInterp=Undefined` 로 남아 gdal2tiles 가 투명도를 무시하고
    전면 불투명 타일을 만든다 — 실제로 한 번 그렇게 나왔다). `gdal2tiles --xyz -z 14-19`
    후 webp q80, 완전 투명 타일은 버린다.

## 검증한 것 — 실제 변화와 맞는가

2504/2510 두 시점에 **같은 폴리곤을 겹쳐 나란히 놓고 눈으로 대조**했다. 맞은 것들:

- 좌중앙·하단 계단식 논 — 4월 맨땅(회색) → 10월 작물(녹색). `veg_gain`. 맞다.
- 우측 사면 계단식 논 여러 필지 — 같은 패턴. 맞다.
- 상단·우상단 밝은 나지 패치 — 4월 이랑 있는 밭 → 10월 정지된 맨땅. `built_new`. 변화 자체는 맞다.
- 중앙 비닐하우스 옆 초지 — 10월에 갈변. `veg_loss`. 맞다.
- 임연부(숲 가장자리) — 4월 낙엽(회갈색) → 10월 만엽(짙은 녹). `veg_gain`. **실제 변화**다.

## 남은 오탐 — 솔직하게

1. **임연부·수관 경계 슬리버.** 질감 정규화로 크게 줄었지만 완전히 없애지는 못했다.
   숲 가장자리를 따라 가늘고 긴 폴리곤이 남는다. 그중 상당수는 진짜 낙엽↔만엽 변화지만,
   시차(parallax)·태양각 차이로 인한 순수 오탐도 섞여 있다. **둘을 구분하지 못한다.**
2. **`built_new` 는 준공 판정이 아니다.** 이 장면에서 잡힌 17건은 대부분 나지·정지작업된
   농지이고 실제 신축 구조물은 확인되지 않았다. 클래스 이름이 과하다 — UI 는
   "나지·구조물 신설 **후보**" 로 풀어 쓰는 편이 정직하다.
3. **계절 편이를 변화로 센다.** 4월→10월은 장면 전체가 변한다. 그래서 2504→2510 은
   `veg_gain` 128 / `veg_loss` 4 로 한쪽에 쏠린다. 이건 버그가 아니라 그 계절 비교의
   실제 모습이지만, "변화 128건"을 **위반·이상 128건으로 읽으면 안 된다.**
4. **변화 면적이 항상 8.8~8.9%.** 91백분위 하한 때문이다. 페어별 변화량 비교에
   이 면적을 쓰면 안 된다 — 비교해야 할 것은 `score` 분포와 클래스 구성이다.
5. **그림자·태양각.** 4월과 10월은 태양 고도가 다르다. 건물·수목 북측 그림자 이동이
   일부 폴리곤을 만든다. 밝기 항이 이를 부분적으로 흡수하지만 제거하지는 못한다.
6. **모자이크 이음선(seam).** 유효역 침식(2m)으로 대부분 걸렀지만, AOI 안쪽에서 시점별
   촬영 스트립이 갈리는 자리는 남을 수 있다.
7. **검증 데이터가 없다.** 정답 라벨이 없으므로 정밀도/재현율을 **계산하지 않았다.**
   위 판단은 전부 육안 대조다. 숫자를 붙이려면 현장 확인 또는 지적/건축물대장 대조가 필요하다.

## 다시 돌리기

```sh
"C:\Users\oem\anaconda3\envs\yolo\python.exe" tools/prepare-assets.py --only namwon   # build/*.tif
"C:\Users\oem\anaconda3\envs\yolo\python.exe" tools/change/namwon_change.py           # 전체
"C:\...\python.exe" tools/change/namwon_change.py --skip-tiles --skip-quicklook       # 벡터만(≈12초)
"C:\...\python.exe" tools/change/namwon_change.py --force                             # 타일 재생성
```

`skimage.segmentation`(SLIC) 과 `skimage.registration.phase_cross_correlation` 은 이 환경에서
프로세스를 죽인다(종료코드 127, 트레이스백 없음). 그래서 객체기반 분할 대신 평활+임계를,
위상상관 대신 정수 격자 탐색을 쓴다.
